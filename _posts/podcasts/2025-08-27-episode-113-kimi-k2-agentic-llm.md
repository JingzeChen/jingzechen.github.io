## 300 字摘要

杨植麟用《无穷的开始》描述 AI 研发：问题不可避免，但问题可以持续解决；AGI 更像没有峰顶的雪山，而非某一天跨过的终点。过去一年最重要的变化，是 Test-Time Scaling 从“缸中之脑”的长思考，扩展到与环境交互的多轮 Agent。Reasoning 增加内部思考 Token，Agent 增加工具调用和环境反馈轮次，两条路线最终汇合。

K2 的重点不是单纯堆规模，而是在数据墙下提高 Token Efficiency，并通过 MoE、MuonClip、数据改写和 Agentic 后训练获得更强基座与工具使用能力。真正瓶颈已经转向任务泛化、Benchmark 过拟合、长上下文、工具长尾和评价体系。

产品上，模型公司可先设计工具和运行环境，再在其中端到端训练，形成第一方 Agent 优势；垂直应用仍可依靠领域工具、专有入口和 Evaluation 生存。开源既是合作信念，也是竞争策略，并不承诺全部开放。组织管理被类比为 RL 与 SFT 的平衡：指标过强会 Reward Hacking，命令过多又会压制创造力。最终原则是继续攀登，但只决定当前有证据支持的下一步。

### 五个核心结论

1. **Test-Time Scaling 有两条轴。** 内部长思考扩展 Token，Agent 扩展工具调用和环境交互轮次。
2. **K2 的核心命题是数据效率和泛化。** 规模很重要，但同样 Token 学到更多能力更重要。
3. **Agent 的关键是行动闭环。** 写代码、运行工具、接收结果，再根据反馈决定下一步。
4. **模型与产品边界进入训练阶段。** 第一方产品可把工具、Context 和环境直接纳入模型训练。
5. **研发和组织都是可错的动态过程。** 解决旧问题会产生新问题，战略应随证据持续更新。

### Test-Time Scaling

```text
                 Test-Time Scaling
                 /               \
        Reasoning Scaling        Agent Scaling
        增加思考 Token           增加交互轮次
             ↓                       ↓
       猜想—验证—反思         工具—环境—反馈
             \                       /
              更复杂的任务完成能力
                       ↓
              延迟、成本、评估和泛化
```

更多计算不会自动带来更强能力。前提是模型经过相应 RL，学会有效利用新增预算。

- 其乐观主义是有条件的：新问题必然出现，重要的是形成猜想、批评、验证和修正能力。

### 00:10:25–00:24:58 缸中之脑、Agent 与 L1–L5

- “缸中之脑”指模型只在内部 Token 空间连续思考，不需要外界交互也能完成任务。
- Reasoning Scaling 通过更多串行思考、猜想、验证和反思提升上限；并行采样与串行探索也可组合。
- Agent Scaling 则调用搜索、浏览器、文件、代码和计算环境，外部结果改变下一轮动作。
- 二者都是 Test-Time Scaling 的不同维度，不要求先做完 Reasoning 才能做 Agent。
- 最高水平 Agent 最终仍需强 Reasoning；简单 Agent 也可以依赖环境反馈和测试先工作。
- L1–L5 可归纳为 Chatbot、Reasoner、Agent、Innovator、Organization。它们是技术里程碑，不是等距或严格串行等级。
- Innovator 的标志是模型参与研发：提出想法、运行实验、分析结果并改进下一代模型。
- Organization 指多个 Agent 分工、汇总和继续拆解任务。目前多 Agent 的端到端训练和跨角色泛化仍不成熟。
- Coding 是行动接口：代码能改变数字环境，并通过测试形成可观察反馈。
- 第一方 Agent 由模型公司设计工具和环境，再端到端训练；第三方则在已有模型上做 Context Engineering 和脚手架。

**回顾问题：** Agent 的能力来自模型、工具、环境，还是三者联合训练？

### 00:24:58–00:41:04 K2：Token Efficiency、Muon 与工程稳定性

- K1.5 被描述为强化学习路线验证，为 K2 积累 RL 基础设施和算法经验。
- K2 的两项目标是优秀基础模型，以及有泛化能力的 Agentic 模型。
- 数据墙指高质量公开文本增长慢，继续机械堆 Token 的边际收益下降。
- Token Efficiency 表示同样训练 Token 获得更低 Loss 或更强能力，不等于单纯训练吞吐更高。
- Muon 按矩阵整体处理更新，团队称在特定 Compute-Optimal 小实验中约有两倍 Token Efficiency。该结果需要同数据、算力和规模的独立复现。
- `30T≈60T` 是解释两倍效率的假设类比，不是 K2 实际 Token 披露。
- 大规模训练出现小实验看不到的 MaxLogit 爆炸等稳定性问题，团队通过 Clipping 等方式修复。
- 数据改写 Rephrase 旨在扩大表达分布和吸收效率，但若没有新增信息，也可能只产生冗余或污染。
- K2 使用 MoE 增加容量和效率；具体参数、专家数和路由应以模型卡为准。
- 官方模型卡口径为 1T 总参数、32B 激活参数、128K Context、15.5T 预训练 Token。厂商数字仍需独立评测。

**回顾问题：** Token Efficiency 应以 Loss、下游能力、训练 FLOPs 还是实际成本衡量？

### 00:41:04–00:54:08 Agent 泛化、工具与长上下文

- Agent 的最重要特征是多轮使用工具，而非一次生成长答案。
- Coding 是通用 Agent 的重要子集，但不等于所有 Agent。搜索、数据库、业务 API 和物理操作有不同反馈结构。
- 最大挑战是泛化：在少量训练工具和任务上提高分数，不保证新工具、新环境和分布外任务表现。
- Benchmark 容易饱和，也可能诱导模型学会特定框架而非通用能力。
- 训练任务需要隐式 Curriculum。任务过难会使有效奖励过少，浪费样本和算力。
- 128K/256K 对长任务仍可能不足，但扩大到百万 Context 不能牺牲短上下文智力和推理效率。
- 纯 Linear Attention 可能因结构 Bias 换取长度却损害能力。这是杨植麟的架构判断，不是对所有线性注意力的定论。
- 多模态不应建立隔离的“另一个脑子”，而应复用语言模型已学到的知识和推理能力。

**回顾问题：** 如何设计能测量 OOD Agent 泛化、而不是测量框架记忆的评估？

### 00:54:08–01:25:05 开源、模型级产品与商业边界

- Kimi 从闭源转向开放，既有社区合作和技术信念，也承认在未绝对领先时开放具有市场策略意义。
- 长期希望分享部分模型与技术，但不承诺所有权重、数据、训练管线和后训练能力都开放。
- 社区可贡献推理部署、微调和垂直 Agent；基座模型提升仍依赖集中算力、数据和原厂训练系统。
- 第一方产品的优势是模型、工具、Context 和运行环境在训练阶段共同优化，模型完成时产品主体也接近完成。
- 这并不消除产品工程：权限、安全、可观测性、支持、分发、工作流和合规仍需大量建设。
- 第三方 Agent 可依靠领域工具、专有入口、数据、Evaluation 和线下履约建立壁垒。
- 通用 Agent 可能在成熟后整合部分垂直服务，但短期合作可能大于竞争。
- 用户反馈噪声高，不适合直接作为训练 Reward；更适合抽象需求分布、失败模式和 Evaluation。
- 商业模式包括 API 和第一方 Agent 产品。杨植麟仍把模型能力放在首位。
- 对“能否盈利”没有给出财务数据或时间表，只表示取决于模型效果和市场增长。

**回顾问题：** 开放权重如何形成可持续收入，并让生态价值回流模型研发？

### 01:25:05–01:40:32 创始人、RL 管理与文明放大器

- 杨植麟用 RL 与 SFT 类比管理：只给指令容易降低主动性，只给奖励又会引发 Reward Hacking。
- 员工不是可交换训练样本，这个类比只能用于理解激励，不能替代公平、问责和劳动伦理。
- 复杂性有时由人主动叠加。创业者需要持续辨认哪些问题真实存在，哪些只是组织和叙事制造。
- “在自己的故事里面”指通过行动和反馈理解自己为何创业，而不是先获得完整、稳定的创始人身份。
- 他把 AI 称为人类文明的放大器和 Meta-Science：降低跨学科学习门槛，加速知识创造。
- 该立场承认毁灭性风险不能排除，但认为应通过对齐和社会机制管理，而不是停止技术发展。
- 人的体验、情感和爱被视为仍具独特价值。Kimi 的模型回答只是思想素材，不是独立权威。
- 面对批评和恐惧，行动原则是关注“当前这一步能做什么”，并保持可根据反馈修正。
- 最后的技术 Bet 是有泛化能力的 Agent，以及用 Innovator 能力推动下一层研发。
- 有效访谈约在 `01:40:32` 结束，之后为片尾。
