## 前言定位

*Hands-On Large Language Models* 希望在概念直觉与可运行实践之间建立桥梁。作者没有把大语言模型只当作文本生成器，而是从表示模型与生成模型两条路线展开，覆盖嵌入、分类、聚类、提示、检索、多模态以及训练和微调。

本书最鲜明的方法是大量使用图示解释数据流、模型结构和训练目标，再用 Notebook 把抽象概念落到实际模型。阅读时不必先掌握某个深度学习框架，但应具备 Python 和机器学习基础，并愿意通过实验观察 token、向量、logit、检索结果与生成输出。

## 全书结构

全书分为三个部分：

1. **理解语言模型**：第 1 至 3 章介绍语言模型全景、token 与嵌入，以及 Transformer 内部的注意力、前馈网络和生成循环。
2. **使用预训练模型**：第 4 至 9 章讨论分类、聚类、主题建模、提示工程、LLM 应用工具、语义搜索、RAG 与多模态模型。
3. **训练与微调模型**：第 10 至 12 章转向文本嵌入模型、表示模型分类微调和生成模型微调。

这些章节可以独立阅读，但前 3 章提供了后文反复使用的共同词汇。第一次阅读时，先建立 tokenization、embedding、attention 和自回归生成的因果链，再进入具体应用，会更容易判断不同技术究竟改变了哪一层。

## 表示模型与生成模型

前言特别区分两类模型：

- **表示模型**把文本、图像或其他对象映射为向量，适合分类、聚类、检索和相似度计算。
- **生成模型**根据上下文逐 token 产生新序列，适合问答、摘要、改写和开放式生成。

二者并不是互相替代。一个可靠的 LLM 系统往往同时使用表示模型做召回、路由或评估，再用生成模型组织答案。理解这种分工，比只会调用一个聊天接口更有迁移价值。

## 实践环境与版本边界

原书示例主要面向 Google Colab 和 NVIDIA T4 等写作时期常见的环境，并在部分章节使用开放权重模型与商业 API。实际复现时需要注意：

- 模型标识、API、依赖版本和价格会持续变化，应以当前模型卡和官方文档为准。
- API 密钥只从环境变量或秘密管理系统读取，不写入 Notebook 和仓库。
- 加载远程自定义代码前应审查来源并固定可信 revision。
- 显存需求不仅由参数量决定，还包括精度、激活、KV cache、批量和运行时缓冲区。
- 书中结果用于解释方法，不能直接当作今天的性能、成本或质量基准。

配套代码位于 <https://github.com/HandsOnLLM/Hands-On-Large-Language-Models>。Notebook 适合复现实验，生产系统仍需补充版本固定、数据治理、评测、可观测性、安全和失败处理。

## 推荐阅读方法

1. 先明确当前章节处理的是离散 token、连续向量、模型隐藏状态、检索结果还是生成文本。
2. 运行最小示例并打印中间张量或候选结果，不只观察最终回答。
3. 区分模型能力、训练目标、解码策略和应用编排，避免把系统效果全部归因于模型大小。
4. 对书中的具体模型和接口做版本核验，同时保留章节解释的长期原理。
5. 将准确率、延迟、显存、成本、隐私和可复现性放在同一张权衡表中。

## 核心结论

前言为全书设定的基调是“先建立可迁移的直觉，再学习具体工具”。表示、生成、检索和微调解决的是不同问题；真正可用的语言模型系统来自这些能力与数据、评测、运行约束的组合，而不是某个单独模型或一段提示词。
