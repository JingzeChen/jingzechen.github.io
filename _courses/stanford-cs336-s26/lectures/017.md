## 学习目标

- 理解本讲把多模态问题拆成哪两问：非文本模态如何输入 Transformer，非文本模态如何生成出来。
- 掌握从 CLIP、SigLIP 到 LLaVA/Qwen/Chameleon 的主线：先学视觉语义表示，再接入 LLM，最后讨论更统一的离散 token 路线。[代码: lecture_17.py p.2] [代码: lecture_17.py p.10]
- 能区分“语义理解需要什么表示”与“高保真生成需要什么表示”这两类需求。

## 需要的先修知识

- Transformer、tokenization、embedding、cross-entropy、RoPE。
- ViT/patch 表示、基本对比学习概念、简单的自回归语言模型训练流程。
- 对上下文长度、batch size、数据 mixture 的基本训练直觉。

## 老师的教学主线

1. 先定义多模态目标：从 `text => text` 走向 omni model。[代码: lecture_17.py p.2]
2. 再解决输入侧：CLIP/SigLIP 如何把图像编码成带语义的向量。[代码: lecture_17.py p.3] [代码: lecture_17.py p.4]
3. 然后搭标准 VLM：视觉编码器、projector、语言模型三段式，以 LLaVA 和 Qwen 为代表。[代码: lecture_17.py p.5] [代码: lecture_17.py p.6] [代码: lecture_17.py p.7] [代码: lecture_17.py p.8] [代码: lecture_17.py p.9]
4. 最后讨论更接近统一生成的路线：Chameleon 把图像也离散化成 token，再总结为什么当前最佳实践仍更偏连续编码器 + Transformer + diffusion。[代码: lecture_17.py p.10]

## 核心概念与依赖关系

- `omni model` 是全讲目标概念；其前提是先解决多模态 token 化问题。
- CLIP 提供图像到语义向量的基础；SigLIP 改进其损失和并行效率。[代码: lecture_17.py p.3] [代码: lecture_17.py p.4]
- LLaVA/Qwen 把视觉向量通过 projector 接到 LLM，因此能做图像理解，但大多仍是文本输出。[代码: lecture_17.py p.5] [代码: lecture_17.py p.7]
- 动态分辨率、MRoPE、DeepStack 等是把这条 VLM recipe 做长、做细、做稳的工程增强。[代码: lecture_17.py p.6] [代码: lecture_17.py p.8] [代码: lecture_17.py p.9]
- Chameleon 通过 VQ-VAE 把图像转成离散 token，换来统一输入输出接口，但损失了部分细节保真。[代码: lecture_17.py p.10]

## 关键推导、例子与结论边界

- 关键目标函数变化：CLIP 的 batch 内双向对比目标，SigLIP 的逐对二分类目标。[代码: lecture_17.py p.3] [代码: lecture_17.py p.4]
- 关键结构变化：LLaVA 的线性投影、Qwen 的 cross-attention adapter、Qwen3 的 DeepStack 跨层融合。[代码: lecture_17.py p.5] [代码: lecture_17.py p.7] [代码: lecture_17.py p.9]
- 关键例子：OCR 说明需要高分辨率；多图/视频说明需要控制视觉 token 长度；Chameleon 的图文交错说明统一 token 接口的吸引力。
- 结论边界：本讲主要覆盖“理解侧如何接入图像”，对图像/视频生成只给出路线对比和老师推测，没有系统讲 diffusion 细节。[需回听]

## 易错点与待核对项

- 不要把“把图像变成 token”误解成“随便离散化就行”；老师反复强调 token 必须保住语义，而 OCR/生成还要求保住细节。
- 不要把当前 VLM 当成真正 omni model；大多数例子仍是多模态输入、文本输出。
- 不要把 Qwen2/Qwen3 的进步理解成换了全新范式；老师强调更多是规模、数据、上下文和局部结构细化。
- `连续编码器 + Transformer + diffusion` 是老师的经验性判断，不是本讲公开验证的闭源系统细节。[需回听]

## 掌握标准

- 能用自己的话解释为什么 CLIP 能学到图像语义，以及为什么它不适合 OCR 这类细节任务。
- 能画出或口述标准 VLM 模板，并说明 projector 在其中的作用。
- 能说清动态分辨率、MRoPE、显式时间戳、DeepStack 分别在解决什么问题。
- 能比较 Chameleon 与 LLaVA/Qwen 路线的优缺点。

## 本段在整讲中的作用

这一段先把本讲从“语言模型课程”切到“多模态总览”，说明为什么即使原计划是继续讲强化学习，也要补一讲 multimodality：因为主流前沿模型几乎都在走向多模态。随后老师给出整讲主线：既然 Transformer 仍然是最好用的骨架，就必须先回答“如何把非文本输入变成 Transformer 能处理的 token”这一基础问题。[代码: lecture_17.py p.2]

## 教学展开

1. 老师先交代原本想继续讲强化学习，但只剩一讲时，如果完全不讲 multimodality，这门课会显得不完整。
2. 他回顾前面课程一直只讲 language model，并把语言模型概括为 `text => text`：输入可以是自然语言、代码、诗歌，甚至可以把 DNA 也当成文本串来处理。
3. 随后转到现实世界：真实世界不是纯文本，而是文本、图像、音频、视频并存，因此理想终点是 omni model，即输入端可以接收任意模态组合，输出端也可以生成任意模态组合。[代码: lecture_17.py p.2]
4. 但本讲不会直接搭完整 omni model，只会先讲“如何让模型吃进去图像”，重点放在理解侧而不是生成侧。
5. 老师给出一个很务实的动机：Transformer 在各模态上依然最好用，所以问题不是换掉 Transformer，而是想办法把所有模态都转换成它会说的 token。
6. 这里老师把 token 的概念放宽为离散 token 或连续 token，关键不是离散性，而是它要代表某种“语义单位”。文本里的 subword 大致算语义单位，但单个像素显然不是。
7. 因而真正困难变成：如何像文本 tokenization 那样，为图像、音频、视频构造可供 Transformer 消化的 token 化表示。
8. 在这个背景下，老师把问题拆成两问：第一，非文本数据如何输入 Transformer；第二，非文本数据如何从模型中生成出来；本讲主要回答第一问。[代码: lecture_17.py p.2]
9. 最后他把时间拨回 2021 年，引出 CLIP，作为现代 VLM 的基础出发点：借助大规模图文对学习图像的语义表示。

## 概念、符号与推导

- `omni model`：输入可接收任意模态组合，输出也可产生任意模态组合；这是老师给出的“North Star”。[代码: lecture_17.py p.2]
- `token`：本段里不局限于离散文本 token，也可指连续表示；判据是它是否承载某个近似语义单位。
- 文本 tokenization 的对照作用：文本已经有 BPE 这一相对可行的方案，但非文本模态没有这么直接的对应物。
- CLIP 训练目标的口头定义：给定一批图文对，把图像编码成向量 $I_1,\dots,I_N$，把文本编码成向量 $T_1,\dots,T_N$；对配对样本，希望 $I_i \cdot T_i$ 大于 $I_i$ 与其他文本的点积，也大于 $T_i$ 与其他图像的点积。
- 老师把这个目标概括为约 $2N$ 个 softmax 分类问题。

## 例子与课堂提示

- “文本已经很通用”这个提醒服务于动机铺垫：老师不是否定 LLM，而是说明它还没覆盖世界里的其他信息形态。
- “代码、诗歌、DNA 都可以当文本”这个例子用来强调 `text => text` 框架的宽泛性。
- “图像+视频提问、音频变图像”等例子服务于解释 omni model 的应用空间，而不是具体实现。
- “像素不是语义单位”是本段最重要的课堂提示之一，它解释了为什么不能把原始视觉信号直接类比成文本 token。
- 老师用“我们已经给文本做过 tokenization，只是对文本还不算太糟”来弱化文本 tokenization 的困难，并突出非文本 tokenization 才是真正棘手的地方。

## 本段掌握检查

1. 为什么老师认为这一讲必须补上 multimodality？
参考答案：因为主流前沿模型几乎都在走向多模态，如果整门课只讲纯语言模型，会缺少对当前模型形态的重要补充。

2. 老师说的 omni model 是什么？
参考答案：它能接收任意模态组合的输入，并输出任意模态组合的结果，不局限于文本输入或文本输出。[代码: lecture_17.py p.2]

参考答案：因为 token 需要代表某种语义单位，而单个像素本身几乎不承载独立语义。

### 00:10:04-00:20:03

## 本段在整讲中的作用

这一段把前面引出的 CLIP 具体化，补完“图像怎样被编码成语义向量”的第一套成熟方案。它既说明 CLIP 为什么有效，也暴露它对分类任务和大 batch softmax 的依赖，为后面转入 SigLIP 做铺垫。[代码: lecture_17.py p.3]

## 教学展开

1. 老师先从图像预处理讲起：由于模型希望输入尺寸固定，CLIP 会先把图像短边缩放到目标长度，再做中心裁剪得到正方形，这么做主要是为了工程便利和当时 ImageNet 分类场景下“主体多在中央”的假设。[代码: lecture_17.py p.3]
2. 接着回答学生问题：为什么用图文对而不是纯图像自监督？老师提到像 SimCLR 这样的增强式方法可以学到低层细节，但仅靠裁剪、旋转、扰动，学不到“不同狗都属于狗”这一类高层语义；文本恰好提供这种语义监督。
3. 然后进入 CLIP 的视觉编码器：他们试过 ResNet 和 Vision Transformer，最后发现 ViT 更好，所以后来大家提到 CLIP 往往默认说的是 ViT 版本。[代码: lecture_17.py p.3]
4. 老师解释 ViT 的基本流程：把图像切成 patch，每个 patch 作为视觉 token，加位置编码后送进标准 Transformer encoder。
5. 在把一串 patch 表示汇总成单向量时，CLIP 不是简单平均，而是做 attention pooling：先全局平均，再拿这个平均向量去和各位置的 key/value 做一轮注意力，得到更有信息的全局向量。[代码: lecture_17.py p.3]
6. 他随后解释最佳模型 `ViT-L/14@336px` 的含义：Large 规模的 ViT，patch 为 `14x14`，输入分辨率为 `336x336`；训练时前期可能用更低分辨率，后期再升高分辨率。[代码: lecture_17.py p.3]
7. 文本端则更简单：使用 GPT-2 风格 Transformer，在序列前后加 `BOS/EOS`，取最高层 `EOS` 激活作为整句表示。[代码: lecture_17.py p.3]
8. 训练时，把一个 batch 中所有图像和所有文本分别编码，形成两端嵌入，再对齐配对项并用两组 cross-entropy 优化。
9. 老师强调 CLIP 的 headline result：在 ImageNet 上，零样本 CLIP 超过了用 120 万张人工标注 ImageNet 图像训练的 ResNet-50，这意味着“网络噪声图文对 + 大模型”足以替代大量手工标注。[代码: lecture_17.py p.3]
10. 最后他补充两个 caveat：一是零样本预测本质上是“图像向量和候选文本标签做点积，取最大者”；二是训练数据本身非常 noisy，即使图里有狗、别的 caption 也可能也有狗，但平均下来模型仍能学到稳定语义。

## 概念、符号与推导

- 图像预处理：任意分辨率图像先 resize，使短边到目标长度，再 center crop 成方形输入；这是 CLIP 时代为固定尺寸视觉编码器服务的预处理。[代码: lecture_17.py p.3]
- `ViT`：把图像切成 patch 序列，每个 patch 视作 token，加位置编码后用标准 Transformer 编码。
- `attention pooling`：不是直接对 patch 表示求平均，而是先取激活的全局平均，再以其为 query 对整串 patch 表示做一轮 QKV 注意力，输出单个汇总向量。[代码: lecture_17.py p.3]
- `ViT-L/14@336px`：`L` 表示 large，`14` 表示 patch 边长 `14x14`，`336px` 表示训练时采用 `336x336` 分辨率。[代码: lecture_17.py p.3]
- 文本编码：输入 `[BOS] ... [EOS]`，取最高层 `EOS` 向量作为整段文本表征。[代码: lecture_17.py p.3]
- CLIP 对齐目标：对每个图像 $I_i$，让它和对应文本 $T_i$ 的相似度高于与其他文本 $T_j$ 的相似度；对每个文本 $T_i$ 同理，让它更接近对应图像 $I_i$；课堂上把它理解为双向的 batch 内分类任务。
- 零样本分类：把图像编码与一组候选文本标签编码做点积，取最大者作为预测类别。

## 例子与课堂提示

- `SimCLR` 被拿来做反例，说明“增强不等于语义”：它更适合逼近低层视觉一致性，而不是高层类别语义。
- “对象常在图片中间，所以裁剪损失不大”这一判断服务于解释当时预处理为何可接受，但也隐含它不适合 OCR 或细粒度任务。
- “很多网页图文对并不会逐字描述图像”提醒学生：CLIP 训练数据监督很脏，成功不来自精确标注，而来自规模与统计平均。

## 教学展开

1. 老师先补完 CLIP 的一个对照实验：如果不用 ranking/contrastive 风格目标，而让模型直接从图像预测文本，不管是 bag-of-words 还是语言模型式预测，计算效率都不如 CLIP 风格目标，至少在 ImageNet 分类语义上是这样。

## 概念、符号与推导

- `VQ-VAE`：
  - 编码器把图像映到连续表示。
  - 连续表示被量化到最近的 codebook 向量，得到离散 token。
  - 解码器根据离散 token 重建图像。
  - 训练主目标是重建损失最小化。[代码: lecture_17.py p.10]
- codebook：一组离散原型向量；课堂示例里规模约为 `8192`，每个视觉 token 选择最近的 code。
- 图像 token 化规模：`512x512` 图像压成 `1024` 个离散 token。[代码: lecture_17.py p.10]
- 训练稳定性问题：文本 token 低熵、图像 token 高熵，混合训练会造成 norm growth 和 logit drift。[代码: lecture_17.py p.10]
- 稳定化手段：`QK norm` 与 `z-loss regularization`，用于控制范数增长并缓和训练不稳定。[代码: lecture_17.py p.10]
- 理解/生成不对称：高层语义理解可接受较粗表示，但 OCR 与图像生成需要更高保真、更细粒度表示。

## 例子与课堂提示

- “最近的 codebook 向量”这个描述帮助学生把 VQ-VAE 理解成一种离散化近似，而不是神秘黑箱。
- 老师用“我很无聊，给我看一些鸟”对应文本和图像交错输出，说明 Chameleon 的美感在于接口统一。
- OCR 被反复拿来当反例，提醒学生：如果一个方法在离散化时丢失小字体信息，就说明它不适合细节保真场景。
- “视频信息密度低于文本”是课程收尾的重要工程提醒，说明不能按 token 数机械地平等对待各模态。
