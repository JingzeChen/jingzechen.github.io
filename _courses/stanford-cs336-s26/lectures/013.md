## 学习目标
理解老师为什么把数据视为语言模型训练里最关键的差异化因素；能说明训练数据从 live services 到可用语料之间经历的抓取、转换、过滤、去重与许可判断；能按时间顺序概括从 BERT、WebText、CCNet、C4 到 DCLM、Nemotron-CC、The Stack、CommonPile 的主要设计思路。

## 需要的先修知识
默认已经掌握前几讲关于语言模型训练、系统、扩展规律和评估的背景。尤其要知道“给定数据如何训练模型”和“如何判断模型是否好”这两层前提，因为本讲是在此基础上追问“究竟该训练什么数据”。

## 老师的教学主线
老师先用企业不公开数据来论证“数据最重要”，再拆解“训练在整个互联网上”这一误解，说明动态内容、认证、robots.txt、ToS 与版权会限制可获取数据。接着他建立版权、许可与 fair use 的法律框架，再从 Common Crawl、Wikipedia、GitHub、arXiv 等来源过渡到一系列代表性数据集，最后用 The Stack 与 CommonPile 讨论代码语料和只用宽松许可数据的上限。

## 核心概念与依赖关系
核心依赖链是：live service 不是语料，必须经过 crawler 或官方 dump 变成 raw data，再经过 transformation、filtering、deduplication 等步骤成为训练数据。法律层面还有 license、fair use、ToS 三层约束。数据集构造方法则大致分为三类：社区信号代理质量，如 WebText；参考分布过滤，如 CCNet；规则或模型评分过滤，如 C4、DCLM、Nemotron-CC。

## 关键推导、例子与结论边界
本讲没有公式推导，关键是论证链。代表性例子包括：Llama 3 几乎不公开数据；Wikipedia dump 可能被时间点攻击；GPT-2 用 Reddit 高 karma 外链做代理质量；CCNet 用 Wikipedia-like 得分筛语料；DCLM 用 OpenHermes 和 ELI5 定义高质量正例；CommonPile 说明只用宽松许可数据可以做到“还不错”，但要追平顶级模型仍困难。结论边界也很明确：训练在若干具体案件中得到 fair use 的有利判断，不等于所有训练都已合法定论。

## 易错点与待核对项
不要把“互联网”“公开网页”“合法可抓取语料”混为一谈。不要把 fair use 理解成一张通行证，也不要把数据集整体许可误认为内部每份作品都可宽松使用。阅读 token 数时要区分 unique token 与重复 epoch 后的训练消费 token。字幕中仍有少量需回听位置，如 00:01:59-00:02:11、00:11:45-00:11:51、00:30:52-00:31:18、01:09:41-01:09:45。

## 掌握标准
如果能够不看讲稿就解释清楚“为什么数据不是从天上掉下来”“为什么 Common Crawl 只是起点而不是终点”“为什么过滤和许可判断决定模型边界”，并能举出 5 个以上具体数据集说明其来源和过滤思路，就算掌握了本讲核心内容。

## 复习顺序
建议先复习开场论证与训练阶段，再复习数据来源和版权框架；之后按时间顺序复盘 BERT、GPT-2、CCNet、C4、GPT-3、The Pile、Gopher、LLaMA、RefinedWeb、Dolma、DCLM、Nemotron-CC；最后单独看 The Stack 与 CommonPile，把“代码数据”和“许可收紧下的数据工程”作为整讲收束。

### 00:00:05-00:10:03

## 本段在整讲中的作用
这一段是整讲的开场，先把课程位置从“已知如何在给定数据上训练模型、也知道如何评估模型”推进到“接下来真正要决定训练什么数据”。老师先论证“数据是语言模型里最重要、也最难做对的部分”，再把问题收束到本讲后半要回答的核心问题：数据从哪里来、为什么并不是“整个互联网”都能直接拿来训练。

## 教学展开
老师先回顾课程进度：此前已经讲过给定数据时如何训练模型，也讲过如何评估模型，因此接下来两讲要转向“该喂什么数据”。他明确提出自己的立场：对语言模型而言，最需要做对的是数据。第一个论据来自公司披露实践，像 Llama 3 这类开放权重模型会公开架构和训练流程，却几乎不公开训练数据，说明数据本身就是关键竞争壁垒。

随后老师解释数据保密的两类原因。第一是竞争层面，数据配方就是公司的“secret sauce”；第二是版权责任，公开承认某类训练数据可能直接带来诉讼风险。接着他把这个判断放回机器学习历史里：基础模型之前，数据工作更多是监督学习标注；现在预训练虽减少了手工标注，但数据清洗、筛选、整理并没有消失。数据始终是瓶颈，因为它是长尾问题，规模扩展仍然受人力约束。

在此基础上，老师给出训练流水线的三阶段框架：pre-training 用大量原始文本，mid-training 用更高质量数据强化能力和长上下文，post-training 则转向聊天记录、强化学习环境等更任务化的数据。实际边界会模糊，但总体趋势是不停地从“大量低质量数据”过渡到“少量高质量数据”。这也带出术语变化：传统上 base model 指预训练加中训练后的模型，instruct 或 chat model 指后训练后的模型，但现在很多大模型连中间 base checkpoint 都不公开了。

最后，老师进入“数据来源”问题，先纠正“模型训练在整个互联网上”这种说法。预训练不是让智能体在互联网上实时行动，而是先由 crawler 发现网页并下载。即使如此，也不能把所有网页都抓下来，因为有动态内容、需要登录或付费的内容，以及随后要详细讲的抓取限制与法律限制。

## 概念、符号与推导
- pre-training：在原始文本上训练基础语言能力的阶段，典型来源是网页文档。
- mid-training：在更高质量、更定向的数据上继续训练，以增强特定能力，如长上下文或更好的指令表现。
- post-training：在聊天记录、环境交互等更任务化的数据上训练，使模型更像可用助手。
- base model：老师此处给出的约定是“pre-training + mid-training 之后”的模型。
- instruct/chat model：post-training 之后的模型。
- crawler：从种子集合出发发现网页并下载网页的程序。
- live servers：互联网上真实运行的网站服务器；它们不是可直接“拿来训练”的静态语料。
- 本段无公式推导。

## 例子与课堂提示
- Llama 3 论文公开架构和训练程序，却不公开数据，用来支撑“数据是核心竞争要素”的判断。
- Qwen3.5-397B-A17B 被老师当作例子，说明越来越多模型只放最终 instruct 版本，不再提供中间 base model。
- OLMo 被提为开放研究对象，说明只有极少数开放模型能让外界看清 pre-training、mid-training、post-training 的全过程。
- Discord 这类站点被用来说明“动态内容”问题：不是顺着 URL 和超链接就能拿到全部内容。
- Facebook、X、LinkedIn、New York Times 被用来说明“围墙花园”问题：内容虽在网上，但登录、付费与平台控制会阻止一般抓取。

## 本段掌握检查
1. 老师为什么说数据比架构和系统更像长期瓶颈？
参考答案：因为数据是长尾问题，扩展更多依赖人工清洗、整理和判断，不能像系统或架构那样只靠少量专家持续放大。

2. 本讲给出的训练三阶段及总体数据质量趋势是什么？
参考答案：pre-training 用大量原始低质量文本，mid-training 用较少但更高质量的数据强化能力，post-training 用更任务化的数据；总体趋势是从大量低质量走向少量高质量。

3. 为什么“模型训练在整个互联网上”这个说法不准确？
参考答案：因为预训练不是在 live servers 上实时行动，而是先由 crawler 抓取静态内容；而且大量内容受动态页面、登录付费和抓取限制影响，根本拿不到。

4. 公司为什么往往不公开训练数据？
参考答案：一是数据本身构成竞争优势，二是公开数据来源会暴露版权责任与潜在诉讼风险。

### 00:10:03-00:20:00

## 本段在整讲中的作用
这一段承接开场对“互联网数据”神话的拆解，把问题从技术可得性继续推进到合规与版权边界。老师先说明技术限制和平台反制如何让“可抓到的数据”越来越少，再把课堂正式引入版权法框架，建立后续讨论数据集合法性的基础。

## 教学展开
老师先介绍 `Consent in Crisis` 这篇论文的观察：作者检查了常见语料数据集里 URL 对应站点的 robots.txt 和服务条款，发现对抓取和 AI 使用的限制在近几年显著上升。也就是说，就算 2020 年左右还能大规模抓网页，今天“能合法抓”的互联网实际上更小。

然后老师补充抓取实践中的现实问题。即使 robots.txt 和 ToS 只是“规则”而不是总能被自动执行的硬门槛，抓取者也可能有意无意越线。例如有站点抱怨 Anthropic 的 crawler 在一天内高频打爆服务器，Read the Docs 也曾遭遇类似压力。老师强调，这里甚至还没谈版权，仅从服务负载、成本转移、妨碍正常用户访问这些角度，就已经能看出爬虫行为本身带来的社会成本。

接着老师引入 shadow libraries。它们技术上属于 web 的一部分，但其典型作用就是绕过付费墙、集中传播受版权保护的书籍和论文。老师列举 LibGen、Anna's Archive 等例子，并指出支持者会说这让本应自由流通的知识被免费分享，但从法律角度看，这依然是盗版与侵权。这里的结论不是“网络很大，所以什么都能用”，而是互联网本身已经混杂了大量高风险来源。

在此背景下，老师转向“什么数据可合法训练”的法律框架。他先给出知识产权法的总目标：激励智力产品创作。接着指出与语言模型最相关的是版权法，并回顾其历史脉络：1709 年英国成文规制版权，1976 年美国版权法奠定现代框架。之后老师解释几个基础点：版权保护针对固定于某种表达媒介中的原创表达；目录式集合不一定可版权；版权保护表达而非思想，例如 quicksort 思想本身不能被版权保护，但具体实现可以。

随后老师强调 1976 年后版权门槛显著下降。如今不需要先正式注册，作品一经“固定”即可获得版权，因此“把东西放在自己的网站上”通常就已经自动受保护。注册主要关系到后续起诉资格，成本也不高。版权持续期结束后作品进入公有领域。基于这些规则，老师得出强结论：互联网上几乎所有东西默认都受版权保护。

最后，老师说明若想合法使用受版权保护的作品，最基本的路径有两条：获得许可，或之后会继续展开的 fair use。到本段结尾，他以 Creative Commons 为例解释许可机制的意义：它让创作者可以主动开放使用，而不必等待漫长的版权期限结束。

## 概念、符号与推导
- robots.txt：网站根目录下公布的抓取约束文件，更多是爬虫应遵守的自律规则而非自动法律执行机制。
- Terms of Service：访问和使用网站时需遵守的服务条款，可能额外限制 bot 抓取或 AI 训练用途。
- shadow library：绕过付费墙传播受版权保护内容的站点集合。
- intellectual property：老师列出版权、专利、商标、商业秘密四类。
- copyright：保护原创表达而不是抽象思想；关键条件是作品被固定在有形表达媒介中。
- public domain：版权期限届满后进入可自由使用的状态。
- Creative Commons：创作者主动授予开放使用权的一类许可体系。
- 本段无公式推导。

## 教学展开

## 教学展开

之后老师转向 RefinedWeb。该工作提出一个很强的口号：web data is all you need。与前面强调专门来源的路线不同，它试图证明只要把网页处理好，web 本身就足够。具体做法包括用 trafilatura 做 HTML 到文本的内容抽取、使用 Gopher 式规则过滤、避免模型型过滤以减少偏置，再配合 MinHash 去重。老师概括它的立场是：不要过早用模型把 web 压缩成过窄分布，而是先保留足够广的网页多样性。[代码: lecture_13.py p.22]

FineWeb 则是对 RefinedWeb 的复制与扩展。它覆盖了更多 Common Crawl dumps，做 URL 过滤、语言识别、手工规则过滤、去重和 PII 匿名化，最终达到 15T token。老师借此指出一个趋势：到 2024 年，语料规模已经从几百 GB 迈向数十万亿 token 级别。[代码: lecture_13.py p.22]

接下来是 AI2 的 Dolma。它不是“纯 web”路线，而是把自己处理的 Common Crawl、Reddit Pushshift、Semantic Scholar 导出的论文数据、C4、Project Gutenberg、Wikipedia/Wikibooks 等拼在一起。老师特别点出其 Common Crawl 处理的态度：语言识别可以用模型，但质量过滤仍尽量避免模型化，另加规则与分类器混合做毒性过滤，并用 Bloom filters 去重。其结果是 3T token。[代码: lecture_13.py p.23]

老师最后讲 Nemotron-CC，把它呈现成对 DCLM 的反拨。NVIDIA 认为 DCLM 和 FineWebEdu 过滤得太狠，牺牲了太多 token，于是想在质量不明显下降的前提下“要更多 token”。其策略有两层：一是分类器集成，用现有大模型给文档打“教育价值”分数再蒸馏成快模型，并结合 DCLM 分类器；二是大规模使用 synthetic data，对低质量文档进行改写，对高质量文档生成问答、摘要、关键信息抽取等任务。最后得到约 6.3T token，明显大于 DCLM。老师借这一节说明，预训练阶段已经不再只是“收集原文”，而开始主动重写和构造数据。[代码: lecture_13.py p.25]

## 本段在整讲中的作用
这一段是整讲末尾的专题收束，先把前面各种过滤方法提炼成统一权衡，再补讲代码语料 The Stack，最后用 CommonPile 回到“只用宽松许可数据能走多远”这一法律驱动的问题。它把技术设计、代码场景和许可风险三条线合并到了同一个收官论证里。

## 教学展开
老师先回头总结过滤方法的共性：无论是规则法还是模型法，核心都是从大规模 web crawl 里定义“什么叫好数据”，再对所有文档打分、筛选。这里的核心权衡在于数量和质量：你当然可以保留 240T token 的原始池，但大概率质量太低；也可以只留约 1T token 的高质量子集，问题则是可能删得过头。老师并没有给出公式化最优点，而是说现实中存在一个需要经验寻找的 sweet spot。

然后他把最后两个主题之一留给代码数据，也就是 The Stack。老师解释，到了 2022 年，社区已经很清楚 code 对模型很重要，所以 The Stack 的目标就是把代码做成“好数据集”。第一版做法是从 GitHub Archive 拿仓库名，大规模 clone 仓库，只保留宽松许可仓库，再用 minhash 与 Jaccard 去重，最终得到 3.1TB 代码。这里的关键不是数字本身，而是它系统地把许可过滤和去重放进代码语料构建主流程。[代码: lecture_13.py p.26]

接着老师讲 2024 年的 Stack v2。与初版相比，它不再只收仓库源码，而是大幅吸纳 issues、comments、PRs、Software Heritage 仓库和外部文档站点，还要去除二进制、恶意软件、bot 活动，做去重、PII 脱敏和 PR 子采样。老师特别喜欢它的一个设计：把低资源编程语言代码编译到共享的低层中间表示 LLVM，并把低资源语言与这一共享表示并排放进语料，以帮助模型把高资源语言中的模式迁移过去。[代码: lecture_13.py p.26]

他还强调 PR 数据不是天然线性文本。PR、diff、review 状态、评论事件本来是结构化对象，要喂给语言模型就必须做 linearization。此时设计问题包括：给模型多少上下文？只给改动行、周围几行，还是整个文件？老师用这一点提醒学生，数据处理不仅是“要什么数据”，还包括“把原始结构编码成什么 token 序列”。最终模型学到的也就不只是代码本身，而是围绕代码的软件开发流程。[代码: lecture_13.py p.26]

最后老师把话题带回许可最严格的一端，即 CommonPile。其研究问题非常直接：如果完全风险厌恶，只接受宽松许可或公有领域数据，还能不能训练出不错的模型？于是项目组在网上搜罗可合法使用的代码、政府文档、wiki、新闻、论文、论坛、教育资源等，最终整理出 8TB 数据。老师承认这已经相当可观，但也指出做这种项目远比看许可证字符串困难，因为存在 license laundering、集合许可不自动覆盖单个作品、以及 synthetic data 是否算“洗白”未授权来源等复杂问题。[代码: lecture_13.py p.27]

到结尾，老师对 CommonPile 的效果给出谨慎评价：和一些老模型相比并不差，说明只用宽松许可数据并非完全做不出东西；但若要跟顶级大模型竞争，单靠这类数据仍然很难，尤其在 token 总量上处于劣势。不过他也保留开放态度，认为这未必是终局，未来仍可能从公开宽松许可语料中挖出更多价值。[代码: lecture_13.py p.27]

- The Stack：以代码为中心、显式处理许可与去重的大规模代码数据集。[代码: lecture_13.py p.26]
- minhash / Jaccard：用于近重复代码去重的方法标签。[代码: lecture_13.py p.26]
- Stack v2：把源码、PR、评论和其他相关数据一起纳入的软件开发过程语料。[代码: lecture_13.py p.26]
- linearization：把结构化 PR/评论/事件对象转成线性 token 序列的过程。[代码: lecture_13.py p.26]
- CommonPile：只收宽松许可或公有领域数据的风险厌恶型语料项目。[代码: lecture_13.py p.27]
- license laundering：未经核实地给受版权保护作品贴上宽松许可标签。[代码: lecture_13.py p.27]

## 本段在整讲中的作用
这一段是全讲正式总结，把前面关于来源、抓取、过滤、许可和具体数据集的分散内容收束成一套统一认识，并为下一讲的 post-training data 与更细的 filtering 预告方向。

## 教学展开
老师首先强调，数据不是“从天上掉下来”的。它不是去 Hugging Face 随手下载一个现成数据集就结束的事，而是必须追问数据原本来自哪里、是谁生产的、通过什么技术路径和社会关系被整理出来。这个判断实际上回应了全讲的第一主张：数据工程是语言模型训练里不可替代的一环。

随后他把整个链条按层次重新串起来。最上层的互联网其实是许多 live services，因此总得有人先做原始数据采集，要么是网站自己提供 dump，要么是有人编写 crawler 把网页抓下来。再往下一层，原始数据不能直接训练，还必须经过 transformation、filtering、deduplication 等处理，才能变成可用语料。老师明确说，这些步骤会直接影响最终语言模型质量。

在所有处理中，老师特别突出 filtering。他用一个数量级对比来说明其重要性：从 200T token 缩到不到 3T token 是极大的压缩，因此“怎么筛”本身就是核心研究问题，而不是附属工程细节。紧接着他再次回到整讲的中心结论：很多语言模型在架构上都还是类似的 transformer，但不同团队在数据上的处理差异，会直接塑造模型差异化能力。

最后老师补上两个收尾判断。第一，数据天然带有法律和伦理问题，课堂里能讲到的只是其中一部分。第二，当前数据处理仍然非常 messy，很多步骤更像基于经验和“vibes”调阈值、定规则、训分类器，而不是像课程其他部分那样建立在清晰的一阶原理上。因此这也是未来最有改进空间的研究方向之一。老师由此自然引向作业四和下一讲：继续讨论过滤与 post-training 数据。

## 概念、符号与推导
- live service -> raw data -> usable corpus：本讲总结出的数据生产链条。
- transformation：把原始网页、PDF、结构化对象转成模型可消费形式。
- filtering：从超大候选池里保留被认为更适合训练的内容。
- deduplication：删除重复或近重复内容，避免浪费训练预算与污染分布。
- data differentiation：在架构相近的前提下，数据处理成为模型差异化的主要来源。
- heuristic pipeline：老师对当前数据处理状态的总概括，即大量依赖规则、阈值和经验判断。
- 本段无公式推导。

## 例子与课堂提示
- “不要只是去 Hugging Face 下载数据集”不是在否定数据平台，而是在提醒学生要向上追溯数据生产过程。
- 老师把 filtering 单独拿出来强调，是为了让学生意识到从 200T 到不到 3T 的压缩比本身就说明筛选策略决定了一切。
- “transformer 架构都差不多，但数据不同会带来大差异”是整讲最值得记住的工程判断之一。
- 把数据处理描述成 `vibes` 与阈值选择，意在提示研究机会：这个领域远没到理论封闭阶段。
