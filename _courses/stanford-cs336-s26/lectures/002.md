- 知道两种常用省显存策略：gradient accumulation 与 activation checkpointing。[代码: lecture_02.py p.28][代码: lecture_02.py p.29][代码: lecture_02.py p.30]

## 核心概念与依赖关系

- tensor 是统一载体：data、parameters、gradients、activations、optimizer state 都是 tensor。[代码: lecture_02.py p.4]
- dtype 决定单元素字节数与数值范围：fp32 稳但贵，fp16 省但危险，bf16 是训练常用折中，optimizer state 常保留 fp32。[代码: lecture_02.py p.5][代码: lecture_02.py p.25]
- 内存核算先于性能分析：装不下模型谈不上训练，搬运太慢也吃不满算力。
- einops 让维度语义显式化：一旦维度表达清楚，matmul、梯度、rearrange 的 FLOPs 和内存更容易核算。[代码: lecture_02.py p.9][代码: lecture_02.py p.10][代码: lecture_02.py p.11]
- MFU 依赖两层事实：
  - 逻辑层面先会数 FLOPs；
  - 系统层面再看算术强度是否足以越过硬件的 accelerator intensity。[代码: lecture_02.py p.12][代码: lecture_02.py p.19]
- training step 的 $6ND$ 依赖 backward = 2 × forward 这一层级结论；而 activation checkpointing、gradient accumulation 则是在这个训练框架上做 memory tradeoff。[代码: lecture_02.py p.21][代码: lecture_02.py p.28][代码: lecture_02.py p.29]

## 关键推导、例子与结论边界

- 关键推导 1：tensor memory = 元素数 × 单元素字节数；这是所有参数、梯度、activation、optimizer state 估算的基底。[代码: lecture_02.py p.5][代码: lecture_02.py p.25]
- 关键推导 2：线性层 forward FLOPs 约为 $2BDK$，换成参数量视角就是 $2 \times \text{数据点数} \times \text{参数量}$。[代码: lecture_02.py p.12]
- 关键推导 3：单层 backward 需要输入梯度和参数梯度两次 matmul，因此整层 backward ≈ 2 × forward；整步训练约为 $6ND$。[代码: lecture_02.py p.21]
- 关键推导 4：arithmetic intensity = FLOPs / bytes，accelerator intensity = 硬件 FLOP/s / bytes/s；前者低于后者则 memory-bound，高于后者则 compute-bound。[代码: lecture_02.py p.14][代码: lecture_02.py p.19]
- 关键例子：ReLU、GELU、dot product、matrix-vector、matmul 的强度比较，导出“matmul 常 compute-bound，许多别的操作常 memory-bound”。[代码: lecture_02.py p.14][代码: lecture_02.py p.15][代码: lecture_02.py p.16][代码: lecture_02.py p.17][代码: lecture_02.py p.18]
- 结论边界：$6ND$ 对长上下文 Transformer 会低估，因为注意力中的平方项会变重要；checkpoint “省一半”也是当前 block 划分下的直观说法，不是全局定律。[代码: lecture_02.py p.21][代码: lecture_02.py p.29]

## 易错点与待核对项

- 不要把 FLOPs 和 FLOP/s 混成一回事；一个是总量，一个是速度。
- 不要把“内存只影响能不能放下模型”理解得太窄；memory bandwidth 同时会限制吞吐。
- 不要以为“算子公式更复杂”就必然更慢；若都 memory-bound，复杂算子未必显著更慢。
- 不要把训练低比特与训练后量化低比特混成同一问题。
- 不要把 optimizer state 忽略掉；它常常不是主要算力瓶颈，但很可能是容量瓶颈。[代码: lecture_02.py p.25]

#### 概念、符号与推导

- 本段核心目标：在有限 compute、memory 下提升训练效率。
- 训练时长估算公式预告：总 FLOPs 约为 $6 \times \text{参数量} \times \text{token 数}$。

- tensor 存储公式：memory = 元素个数 × 单元素字节数。
- fp32：32 bits，由符号位、指数位、尾数组成；默认每个浮点数 4 bytes。
- 4×8 tensor 的存储：$4 \times 8 \times 4 = 128$ bytes。
- fp16：位数减半，内存更省，但指数位更少，动态范围差；1e-8 在老师示例里下溢为 0。

### 002 00:10:03-00:20:03

#### 本段在整讲中的作用

#### 教学展开

- [00:10:03-00:10:48] 先完成 bf16 的解释：总位数与 fp16 相同，但把部分 mantissa bits 挪给 exponent，因此动态范围接近 fp32、分辨率更差，不过对深度学习通常是值得的折中。

- [00:11:49-00:13:06] 引入 mixed precision training：通常参数、activation、gradient 用 bf16，optimizer state 用 fp32；PyTorch AMP 会在安全时自动降精度，例如 matmul 通常可降，而 exponentiation 会保留 fp32。
- [00:13:07-00:15:05] 继续扩展到 fp8 与 fp4：说明低比特正在继续下探，但很多机制依赖 NVIDIA 软件栈，用户未必能像创建普通 tensor 那样直接操控。

#### 概念、符号与推导

- 通信流程：从 memory 读入输入，执行计算，再把输出写回 memory。
- communication time = 搬运字节数 / memory bandwidth。
- computation time = FLOPs / FLOP/s。
- 重叠假设：总时间近似为 $\max(\text{communication time}, \text{computation time})$。
- ReLU 例子：
  - bytes = 读入 $2n$ + 写回 $2n = 4n$ bytes（bf16 每元素 2 bytes）。
  - FLOPs = $n$ 次比较。
  - arithmetic intensity = $n / 4n = 1/4$。
- accelerator intensity = 硬件 FLOP/s ÷ bytes/s；老师对 H100 给出的直觉值约为 295 FLOP/byte。
- bottleneck 判别：
  - 若 communication time > computation time，则 memory-bound。
  - 若 computation time > communication time，则 compute-bound。
  - 等价地，若 arithmetic intensity < accelerator intensity，则 memory-bound；反之 compute-bound。
- GELU 例子：
  - bytes 仍约为 $4n$。
  - FLOPs 粗估约为 $20n$。
  - arithmetic intensity 粗估约为 5，仍明显小于 295，因此仍是 memory-bound。

### 006 00:50:02-01:00:02

#### 本段在整讲中的作用

这段把 arithmetic intensity 的判断法从 elementwise 操作扩展到线性代数核心操作，并得出对 Transformer 训练/推理都很关键的结论：大矩阵乘法通常 compute-bound，而推理时常见的 matrix-vector 乘法往往 memory-bound。随后老师再把 roofline 图和一个深网络示例接上，为正式讲训练时的梯度与内存核算做铺垫。

#### 教学展开

- [00:50:02-00:50:27] 收束 dot product：读两个向量、写一个标量，FLOPs 大约是 $2n-1$，算术强度约 1/2，因此仍 memory-bound。
- [00:50:33-00:51:21] 讨论 matrix-vector product：读一个向量和一个矩阵、写一个向量，虽然比 dot product 大，但 arithmetic intensity 只略高一点，依旧 memory-bound。
- [00:51:22-00:52:48] 转到 matrix multiplication：因为只搬运 $O(n^2)$ 个元素，却做了 $O(n^3)$ 次计算，arithmetic intensity 大约是 $n/3$，当矩阵足够大时就会超过硬件阈值，变成 compute-bound。
- [00:52:53-00:54:48] 把这个结论映射到 Transformer：训练时本质上是大矩阵乘法夹杂少量别的操作，因此 arithmetic intensity 高；推理一次只生成一个 token，更接近 matrix-vector 乘法，所以偏 memory-bound。老师也顺便说明低 MFU 常常是 memory bottleneck 的结果。
- [00:54:49-00:56:57] 用 roofline plot 统一视觉化：横轴是 arithmetic intensity，纵轴是实际 FLOP/s；低强度算法落在斜坡段，高强度算法进入平台段，但永远不会超过峰值 FLOP/s。
- [00:57:11-00:59:10] 回到 training 场景，给出一个简化 deep network：输入是 $B\times D$，每层是 $D\times D$ 线性层加逐点 ReLU，层数为 $L$，参数量是 $D^2L$。
- [00:59:10-01:00:02] 用最简单的线性回归例子回顾 backward 的基本机械过程：`loss.backward()` 后，计算图里的可求导变量会得到相应梯度，`w.grad` 在例子中变成 `[1, 2, 3]`。

#### 概念、符号与推导

- dot product：
  - bytes = 读 $x$ 的 $2n$ + 读 $w$ 的 $2n$ + 写标量结果 2。
  - FLOPs = $n$ 次乘法 + $(n-1)$ 次加法 = $2n-1$。
  - arithmetic intensity 约为 1/2，memory-bound。
- matrix-vector product：
  - bytes = $2n + 2n^2 + 2n$。
  - FLOPs = $n(2n-1)$。
  - arithmetic intensity 只略高于 dot product，仍 memory-bound。
- matrix multiplication：
  - bytes 约为 $2n^2 + 2n^2 + 2n^2 = 6n^2$。
  - FLOPs 约为 $n^2(2n-1)$。
  - arithmetic intensity 近似 $n/3$，矩阵越大越有利。
- roofline 解释：低 arithmetic intensity 时性能受内存带宽限制；高到超过拐点后进入 compute-bound 区域。
- 深网络记号：输入批次大小为 $B$，隐藏维度为 $D$，层数为 $L$，参数量为 $D^2L$。
- 梯度基础例子：通过一次标量损失的 backward，可得到对参数向量的梯度。

#### 例子与课堂提示

- dot product、matrix-vector、matmul 三连比较：服务于把“memory-bound/compute-bound”变成可操作的层次判断，而不是抽象定义。
- “矩阵越大越容易 compute-bound”这一点：服务于理解为什么训练常喜欢较大的 batch 和较大的矩阵块。
- Transformer 训练 vs 推理的对比：服务于后续 inference lecture 的伏笔，也帮助区分两种 workload 的系统瓶颈。
- roofline 图：服务于把不同算法和不同硬件放到同一坐标系里比较。
- 简化 deep network 与 `w.grad = [1,2,3]`：服务于从系统核算切回训练 mechanics，确保后面讲 backward FLOPs 时不丢基础。

#### 本段掌握检查

### 007 01:00:02-01:10:01

#### 本段在整讲中的作用

这段把训练时最关键的计算量公式从“前向 matmul 很贵”推进到“完整 training step 为什么是 $6ND$ FLOPs”。老师通过两层线性网络把 backward 拆成两次和 matmul 同量级的计算，再把结果推广到整网，同时引入 optimizer state 的概念，为最后一段的内存核算做准备。

#### 教学展开

- [01:00:02-01:00:15] 先说明前面的 `w.grad` 例子只是 PyTorch backward 的基本机械过程，真正要回答的是“算梯度要多少计算”。
- [01:00:16-01:01:14] 构造一个简化两层线性网络：$x \rightarrow h_1 \rightarrow h_2 \rightarrow loss$，暂时忽略 ReLU，只保留两次 matmul，方便直接数 FLOPs。
- [01:01:14-01:02:08] 聚焦第二层 $h_2 = h_1 @ w_2$，先回顾 forward FLOPs 仍然是一个标准 matmul 的三维乘积乘 2。
- [01:02:08-01:04:04] 分解 backward：需要同时算输入侧的 backward message $\partial loss / \partial h_1$，以及参数梯度 $\partial loss / \partial w_2$；老师用 einsum 写出两式，强调命名维度能减少“到底谁该 transpose”的困惑。
- [01:04:07-01:05:05] 指出这两个梯度计算本质上也都是 matmul，虽然求和维度不同，但 FLOPs 仍是同一组三维大小的乘积级别。
- [01:05:05-01:06:19] 得出单层结论：backward 恰好是 forward 的两倍，因为要算两份梯度；推广到整网后，forward 为 $2ND$，backward 为 $4ND$，合起来就是训练一步 $6ND$。
- [01:06:24-01:06:47] 说明这个结论对 Transformer 也是不错的近似，但当 context length 很长、注意力的 $L^2$ 项变得显著时，就不能只靠这个简化式。
- [01:06:48-01:08:01] 切到 optimization：老师选 AdaGrad 作为示例，把它放在 SGD、momentum、RMSProp、Adam 的谱系中定位，重点不是优化器理论，而是“优化器会引入额外 state”。
- [01:08:01-01:10:01] 解释 optimizer state 的使用方式：读出历史状态、用当前梯度更新、再写回，并开始过渡到内存开销的分类：参数、activation、gradient、optimizer state。

#### 概念、符号与推导

- 简化网络：$x \in \mathbb{R}^{B\times D}$，$w_1,w_2 \in \mathbb{R}^{D\times D}$。
- 第二层 forward：$h_2 = h_1 w_2$，forward FLOPs 约为 $2BD^2$。
- backward 需要两项：
  - 输入梯度：$\partial loss / \partial h_1$，由上游梯度与 $w_2$ 相乘得到。
  - 参数梯度：$\partial loss / \partial w_2$，由上游梯度与 $h_1$ 相乘得到。
- 这两项各自仍是一个 matmul 量级，所以单层 backward FLOPs 约为 $2BD^2 + 2BD^2 = 4BD^2$。
- 因此单层结论：backward = 2 × forward。
- 推广到全网：
  - forward FLOPs = $2 \times \text{数据点数} \times \text{参数量}$。
  - backward FLOPs = $4 \times \text{数据点数} \times \text{参数量}$。
  - training step FLOPs = $6 \times \text{数据点数} \times \text{参数量}$。
- 适用边界：对 Transformer 是常用近似；若 context 太长，注意力中的平方项会让这套核算低估真实 FLOPs。
- AdaGrad：维护历史平方梯度和，用于按维度缩放更新步长；这说明优化器不仅有参数更新逻辑，也有持续存在的 optimizer state。

#### 例子与课堂提示

- 两层线性网络：服务于把 backprop 的计算量拆解成可直接复用 matmul 公式的形式。
- 老师说“我总搞不清 transpose 放哪边”：服务于强调 einsum 的一个现实好处不是炫技，而是减少推导和实现时的索引混乱。
- `retain_grad()` 与手工写出的梯度相比较：服务于做 sanity check，验证口头链式法则与 PyTorch 自动求导一致。
- AdaGrad 位于 SGD 和 Adam 之间：服务于说明优化器家族的直观关系，而非展开优化理论。

#### 本段掌握检查

- 问：为什么单层 backward 会比 forward 贵两倍？
  答：因为 backward 要额外算两份和 matmul 同量级的对象，一份是输入梯度，一份是参数梯度。
- 问：$6ND$ 里的 6 是怎么来的？
  答：forward 贡献 2，backward 贡献 4，加起来是 6。
- 问：什么时候 $6ND$ 会变成不够好的近似？
  答：当 context length 很长时，注意力里的平方项不能忽略。
- 问：老师为什么在梯度推导里坚持用 einsum？
  答：因为它直接写出命名维度，能减少 transpose 方向和求和维度的混乱。
- 问：optimizer state 是什么？
  答：是优化器在跨 step 持续保存的附加张量状态，例如 AdaGrad 的历史平方梯度和。
