## 学习目标

- 理解为什么大模型训练的基本计算单位已经从单张 GPU 变成整个数据中心，以及并行化首先要同时解决算力和显存两类瓶颈。[课件: lecture_08.pdf p.4][课件: lecture_08.pdf p.6][课件: lecture_08.pdf p.13]
- 能按老师的顺序解释数据并行路径：naive DDP -> ZeRO stage 1/2/3(FSDP)，并说清它们各自的通信账本、内存收益和适用边界。[课件: lecture_08.pdf p.15][课件: lecture_08.pdf p.21][课件: lecture_08.pdf p.27][课件: lecture_08.pdf p.28]
- 能区分三类模型并行与激活并行：pipeline parallel、tensor parallel、sequence/context parallel，以及它们为什么分别适合不同链路与不同瓶颈。[课件: lecture_08.pdf p.31][课件: lecture_08.pdf p.35][课件: lecture_08.pdf p.43][课件: lecture_08.pdf p.48][课件: lecture_08.pdf p.54]
- 理解 expert parallel 在 MoE 时代的角色，以及为什么 attention 与 MLP 往往需要解耦后的并行配置。[课件: lecture_08.pdf p.50][课件: lecture_08.pdf p.53]
- 能把整讲收束成可操作规则：先让模型 fit，再用 DP 吃剩余 GPU；机内优先 TP/EP，跨节点优先 PP，长序列补 CP，小模型可优先 FSDP。[课件: lecture_08.pdf p.57][课件: lecture_08.pdf p.58][课件: lecture_08.pdf p.72][课件: lecture_08.pdf p.73]

## 需要的先修知识

- 上一讲已经讲过的并行化基本概念，以及 collective communication 的基本术语，如 all-reduce、all-gather、reduce-scatter。[课件: lecture_08.pdf p.7][课件: lecture_08.pdf p.8]
- 训练态参数更新的基本心智模型，至少知道 batch、梯度累积、SGD/Adam 状态分别是什么。
- transformer 的主要结构块，包括 attention、MLP、LayerNorm、残差连接以及在 MoE 中的 expert/router。
- GPU/TPU 集群存在机内快互连与机间慢互连差异，通信模式会影响并行策略选择。[课件: lecture_08.pdf p.9][课件: lecture_08.pdf p.10]

## 老师的教学主线

- 先从“为什么必须多机多卡”和“collective 通信原语”讲起，把问题框成算力瓶颈、显存瓶颈与网络拓扑三者共同决定的系统问题。[课件: lecture_08.pdf p.4][课件: lecture_08.pdf p.7][课件: lecture_08.pdf p.13]
- 再走完数据并行路线：用 naive DDP 建立基线，解释 optimizer state 为什么让显存变得糟糕，再通过 ZeRO stage 1/2/3 逐步展示怎样分片状态、梯度和参数，并靠等价分解与 overlap 把成本压低。[课件: lecture_08.pdf p.15][课件: lecture_08.pdf p.17][课件: lecture_08.pdf p.23][课件: lecture_08.pdf p.26][课件: lecture_08.pdf p.27]
- 然后转入模型并行：先讲 pipeline parallel 的 bubble 与 microbatch，再讲 tensor parallel 的宽度切分和前后向对偶，顺手把 activation memory 公式推到需要 sequence parallel 的程度。[课件: lecture_08.pdf p.34][课件: lecture_08.pdf p.38][课件: lecture_08.pdf p.40][课件: lecture_08.pdf p.46][课件: lecture_08.pdf p.48]
- 接着用 expert parallel 把 MoE 带来的高带宽 token routing 复杂性说清，并解释为什么 attention 与 MLP 在 MoE 模型里会偏好不同的并行规模，需要解耦策略。[课件: lecture_08.pdf p.50][课件: lecture_08.pdf p.53]
- 最后用总表、定量扩展曲线和真实训练案例，把所有 parallelism primitives 收束成一套业界规则与经验模式。[课件: lecture_08.pdf p.55][课件: lecture_08.pdf p.57][课件: lecture_08.pdf p.59][课件: lecture_08.pdf p.72][课件: lecture_08.pdf p.73]

## 核心概念与依赖关系

- Collective 原语等价关系是理解 ZeRO/FSDP 的前提：all-reduce 与 reduce-scatter + all-gather 的等价使若干内存收益在带宽账本上近似“免费”。[课件: lecture_08.pdf p.8]
- 数据并行依赖 batch 这个资源；当 batch 不能再有效增大时，必须借助模型并行继续扩展。[课件: lecture_08.pdf p.15][课件: lecture_08.pdf p.29]
- 模型并行分成深度切分与宽度切分：pipeline parallel 沿层深度切，tensor parallel 沿矩阵宽度切；sequence/context parallel 则是对激活与长序列再做补充切分。[课件: lecture_08.pdf p.31][课件: lecture_08.pdf p.39][课件: lecture_08.pdf p.48][课件: lecture_08.pdf p.54]
- 激活内存账本是 TP/SP 之后仍要处理的问题，经验式 $34sbh + 5as^2/h$ 连接了显存估算、重计算与长上下文策略。[课件: lecture_08.pdf p.46][课件: lecture_08.pdf p.49]
- EP 与 TP/DP/PP 的组合并非自由交换，尤其在 MoE 中 attention 与 MLP 的并行需求不一致，这直接催生了解耦后的多维并行系统。[课件: lecture_08.pdf p.52][课件: lecture_08.pdf p.53]
- 最终的配置规则建立在链路层次之上：快链路优先 TP/EP，慢链路优先 PP，装得下后再回到 DP 扩展。[课件: lecture_08.pdf p.35][课件: lecture_08.pdf p.42][课件: lecture_08.pdf p.57][课件: lecture_08.pdf p.58]

## 关键推导、例子与结论边界

- Naive DDP 的核心更新式是 $\theta_{t+1}=\theta_t-\eta\sum_{i=1}^{B}\nabla f(x_i)$；它计算缩放理想，但通信要传 $2\times \#params$，内存几乎不缩放。[课件: lecture_08.pdf p.15]
- 训练态显存经验账本里，参数之外还要保存梯度、master weights 和 Adam 一二阶矩，因此 optimizer state 往往是显存大头。[课件: lecture_08.pdf p.17]
- ZeRO stage 1/2 与 naive DDP 在带宽账本上近似等价，而 stage 3/FSDP 额外多一次 all-gather，但可通过分层释放与 communication/computation overlap 将代价压到可接受。[课件: lecture_08.pdf p.21][课件: lecture_08.pdf p.23][课件: lecture_08.pdf p.26][课件: lecture_08.pdf p.27]
- Pipeline 的 bubble 比例大致随 $(n_{stages}-1)/n_{micro}$ 下降，所以必须有足够大的 batch 才能把 PP 用好。[课件: lecture_08.pdf p.34][课件: lecture_08.pdf p.36]
- Tensor parallel 没有 pipeline bubble，但通信更频繁、更依赖高速互连；激活内存里的 $10sbh$ 残差则推动了 sequence parallel 的引入。[课件: lecture_08.pdf p.43][课件: lecture_08.pdf p.47][课件: lecture_08.pdf p.48]
- 真实案例给出的结论边界很清楚：TP 通常不超过 8；小 dense 模型可偏向 FSDP；大 dense 模型使用 TP+PP+DP；MoE 倾向把 EP 做大并让 TP 保持较小；长上下文阶段会显著提高 CP。[课件: lecture_08.pdf p.61][课件: lecture_08.pdf p.63][课件: lecture_08.pdf p.66][课件: lecture_08.pdf p.72]

## 易错点与待核对项

- 不要把 ZeRO/FSDP 和 pipeline parallel 混为一谈：前者每卡仍走完整模型，只是按需拿参数；后者是真的把层放到不同卡上。[课件: lecture_08.pdf p.25][课件: lecture_08.pdf p.32]
- 不要把“通信成本差不多”误解为“实现完全免费”；老师的“free/almost free”是带宽账本口径，不是说没有工程调度、延迟或实现复杂度。[课件: lecture_08.pdf p.21][课件: lecture_08.pdf p.27]
- 不要把 sequence parallel 与 context parallel 当成严格同义词；老师明确说 sequence parallel 常是 TP 的附加件，而 context parallel 更像长上下文独立策略。[课件: lecture_08.pdf p.48][课件: lecture_08.pdf p.54]
- 不要以为 TP 越大越好；课上反复强调超过 8 往往收益变差，且 attention 与 MLP 在 MoE 中对 TP 的需求本就不同。[课件: lecture_08.pdf p.53][课件: lecture_08.pdf p.61]
- 若要按实现级精度复原 DeepSeek 的 DPP/Hybrid EP、TPU8i/TPU8t 或 loop transformer 问答，仍需回听若干口语化片段。[需回听]

## 概念、符号与推导

- 单卡扩展的两类根因：算力不够与显存不够。前者要求把 compute 扩展到多机多卡；后者要求把参数或相关状态切分存放。[课件: lecture_08.pdf p.4][课件: lecture_08.pdf p.6]
- intra-node parallelism 与 inter-node parallelism：前者依赖机内高速互连，允许更激进、更通信密集的策略；后者更慢，因此算法必须更加尊重通信成本。[课件: lecture_08.pdf p.6]
- collective communication primitives：本讲默认把通信抽象成 all-reduce、broadcast、reduce、all-gather、reduce-scatter，而不是网络包或链路级细节。[课件: lecture_08.pdf p.7]
- 关键等价：all-reduce 可以分解成 reduce-scatter 加 all-gather；老师强调在 bandwidth-limited regime 下，这已经是最优级别，因此后面若把一个 all-reduce 改写成这两步，通信账本未必更差。[课件: lecture_08.pdf p.8]
- TPU 网络心智模型：toroidal mesh，邻居通信、规则拓扑、易于随规模扩展保持固定度数。[课件: lecture_08.pdf p.9][课件: lecture_08.pdf p.10]
- GPU 网络心智模型：fat tree / all-to-all 分层网络，适合更不规则的通信模式，但规模增大时路径与代价更复杂。[课件: lecture_08.pdf p.9][课件: lecture_08.pdf p.10]
- 新的计算单位：不是单 GPU，而是整个数据中心；并行算法的目标是让模型参数容量和可用 FLOPs 都能随 GPU 数近似线性扩展。[课件: lecture_08.pdf p.13]
- 本段无公式推导。

## 例子与课堂提示

- [00:00:42-00:00:57] “4D parallelism” 的预告是课堂提示：老师从一开始就在强调真实系统不会只用一种并行，而是多种手段叠加。

## 教学展开

- [00:10:04-00:11:12] 老师先做第二部分总览：接下来是并行化 LLM 的算法主体，粗分成 data parallel 和 model parallel。前者移动的是数据，后者切的是模型；虽然边界不绝对，但这个分类足以组织接下来的讨论。[课件: lecture_08.pdf p.14]
- [00:12:01-00:13:21] 然后从最简单的 data parallel 讲起。为了不被 Adam 干扰，老师先假设 naive SGD：每一步取一个大小为 $B$ 的 batch，累加梯度后更新参数。最自然的并行法就是把 batch 沿样本维切给 $M$ 台机器，每台拿 $B/M$ 个样本，各自算完整梯度，再同步梯度求和。[课件: lecture_08.pdf p.15]
- [00:13:21-00:14:07] 老师马上评估这种 naive data parallel 的三项指标。算力扩展几乎完美，只要每卡仍有足够样本；通信上，每个 batch 需要来回传大约两倍参数量的梯度；内存上则完全没有缩放，因为每张卡都得保留完整模型和对应激活。[课件: lecture_08.pdf p.15]
- [00:14:07-00:15:05] 接着他把“显存坏消息”讲得更具体：真正贵的并不只是参数本身，而是训练时必须保留的多份副本。按经验法则，可能要到 5 份 weights、约 16 bytes per parameter，其中既有 BF16/FP16 参数，也有梯度、FP32 master weights，以及 Adam 的一阶和二阶矩。老师特别点名 optimizer state 才是大头。[课件: lecture_08.pdf p.16][课件: lecture_08.pdf p.17]

- [00:16:49-00:18:26] stage 1 的执行顺序被拆成四步：所有 worker 对各自 batch 子集算完整梯度；把梯度做 reduce-scatter，只把相关切片发给负责那片参数的 worker；各卡拿自己的参数切片、收到的梯度切片和本地 optimizer state 做更新；最后把更新后的参数切片 all-gather 回所有 worker。[课件: lecture_08.pdf p.20]
- [00:18:26-00:19:15] 老师此时利用前面铺垫的等价关系做关键比较：naive DDP 做一次 all-reduce，stage 1 做一次 reduce-scatter 加一次 all-gather，带宽账本仍然是 $2\times \#params$，所以 stage 1 在 bandwidth-limited 的视角下等价于“免费拿到”更好的内存缩放。[课件: lecture_08.pdf p.21]

## 概念、符号与推导

- Naive SGD 更新式：$\theta_{t+1}=\theta_t-\eta\sum_{i=1}^{B}\nabla f(x_i)$。老师用它说明 batch 维切分是最自然的数据并行起点。[课件: lecture_08.pdf p.15]
- $B$：全局 batch size；$M$：机器数。naive data parallel 中每台机器处理 $B/M$ 个样本。[课件: lecture_08.pdf p.15]
- Naive data parallel 的通信成本：每步约传输 $2\times \#params$，直观上是把完整梯度在多卡之间同步。[课件: lecture_08.pdf p.15]
- 训练态显存账本：参数、梯度、FP32 master weights、Adam 一阶矩、Adam 二阶矩。老师给出的经验法则是“大约 5 份权重、16 bytes/param”，并指出 optimizer state 是最主要部分。[课件: lecture_08.pdf p.17]
- ZeRO stage 1：只分片 optimizer state，参数和梯度仍全量复制；每个 worker 负责一片参数更新。[课件: lecture_08.pdf p.19]
- ZeRO stage 1 的通信分解：reduce-scatter 发送梯度切片，加 all-gather 回收更新后参数切片。[课件: lecture_08.pdf p.20]
- 关键推导：因为 all-reduce $\equiv$ reduce-scatter + all-gather，所以 stage 1 的通信总量仍是 $2\times \#params$，但内存从 $(4+K)\times \#params$ 下降到 $(4+K/N_{gpu})\times \#params$ 这一类分片形式。[课件: lecture_08.pdf p.21]
- ZeRO stage 2 的新约束：不再允许在某卡上完整实例化整个梯度向量，只能沿 backward 过程流式地产生并立刻散出去。[课件: lecture_08.pdf p.22][课件: lecture_08.pdf p.23]

## 教学展开

- [00:20:02-00:20:26] 老师先把 ZeRO stage 2 说完：既然梯度在 backward 图上只在局部时刻需要，那就每算完一层梯度，立刻 reduce 到负责该切片的 worker，并在不再需要后马上释放。这样“边算边发”和“一次算完再发”在通信账本上没有区别，但显存占用下降。[课件: lecture_08.pdf p.23]
- [00:20:26-00:21:08] 接着老师继续“得寸进尺”：既然 optimizer state 和 gradients 都几乎白捡地切开了，那就把 parameters 也一起分片。ZeRO stage 3，也就是 FSDP，目标是让任一时刻每张卡只看见参数、梯度和状态的一小片，并按需请求其余部分。[课件: lecture_08.pdf p.24]
- [00:21:08-00:22:19] 他先用一个单层 toy 过程解释 FSDP：开始时每卡只持有自己那一片参数；forward 某层前先 all-gather 该层完整参数，算完 forward 就释放；backward 到该层前再 all-gather 一次参数，算出梯度后立刻 reduce-scatter 发回各 owner，再释放参数。然后重复这一流程，最后每卡只更新自己负责的切片。[课件: lecture_08.pdf p.25]
- [00:22:19-00:24:57] 老师承认 stage 3 看起来通信更频繁，也多出一次 all-gather，但它依赖两条关键思想把代价压到实践上可接受。第一条是沿计算图顺序逐层通信、逐层释放；第二条是 communication/computation overlap。也就是说，在 forward 当前层时，就预取下一层参数；只要网络足够快而计算足够重，通信就可以被盖在计算下面，留下的只是少量 bubble。[课件: lecture_08.pdf p.26]

- [00:26:13-00:27:50] 问答部分里，老师澄清 FSDP 不是 pipeline parallel：每张卡仍然会跑完整模型的整个计算流程，只是任一时刻不会持有完整参数，而是“请求一层参数、算完就释放，再请求下一层”。他也确认参数、梯度和 optimizer state 都是按层或按切片 sharded 的。[课件: lecture_08.pdf p.24][课件: lecture_08.pdf p.25]

## 概念、符号与推导

- ZeRO stage 2：梯度分片版数据并行。核心不是先 materialize 全梯度，而是沿 backward graph 逐层计算并立即 reduce-scatter 到对应 worker，再在梯度离开 backward graph 后立刻释放。[课件: lecture_08.pdf p.23]
- ZeRO stage 3 / FSDP：参数、梯度、optimizer state 全部分片；forward 和 backward 都通过按需 all-gather 完整层参数，计算完立即 free，再用 reduce-scatter 送回梯度切片。[课件: lecture_08.pdf p.24][课件: lecture_08.pdf p.25]
- Stage 3 的通信账本：两次 all-gather 加一次 reduce-scatter，总体约为 $3\times \#params$。[课件: lecture_08.pdf p.25][课件: lecture_08.pdf p.27]
- overlap 思想：当第 $l$ 层正在计算时，后台同时发起第 $l+1$ 层参数 all-gather。若计算时间大于通信时间，则额外通信可被隐藏在计算中。[课件: lecture_08.pdf p.26]
- “free/almost free” 的口径：stage 1 和 stage 2 的总带宽账本与 DDP 一样，都是 $2\times \#params$；stage 3 更高，但不是灾难性增长。[课件: lecture_08.pdf p.27]
- critical batch size：老师给出的经验性概念，指 batch 大到某个阈值后，再加入样本带来的优化收益开始明显递减，不再等价于多做一步 SGD。[课件: lecture_08.pdf p.29]
- 数据并行的根本剩余问题：即便 stage 3 能线性缩放参数相关内存，也不减少 activation memory，因此“模型装进显存”和“激活装进显存”仍不是同一个问题。[课件: lecture_08.pdf p.30]

## 概念、符号与推导

- Model parallelism 的课堂定义：通过切参数结构来扩展内存与算力，但通信对象从“参数/梯度状态”为主转向“激活”为主。[课件: lecture_08.pdf p.31]
- Pipeline parallel：按深度切层，把一段段层放到不同 GPU，上下游之间传 activations 与 partial gradients。[课件: lecture_08.pdf p.32]
- Bubble：流水线中 GPU 空闲等待的时间片，朴素 layer-wise parallel 时几乎是常态。[课件: lecture_08.pdf p.33]
- Micro-batches：为了填流水线，把一个 batch 切成多个小块，令不同 stage 可以重叠处理不同 micro-batch。[课件: lecture_08.pdf p.34]
- 关键比例：bubble/useful compute 的比值大致是 $\frac{n_{stages}-1}{n_{micro}}$，因此增大 micro-batch 数有助于把 bubble 压小。[课件: lecture_08.pdf p.34]
- Pipeline 通信量的核心口径：按激活规模，约是 $b\times s\times h$，而且是 point-to-point，不是全局 collective。[课件: lecture_08.pdf p.35][课件: lecture_08.pdf p.43]
- Zero-bubble pipelining 的推理：backward 里同时包含“把梯度信号继续往前传”和“对当前权重求导”两类工作；前者阻塞下游，后者不阻塞，因此可以调度分离。[课件: lecture_08.pdf p.38]

## 教学展开

- [00:39:59-00:41:27] 老师先从一个最基本的 MLP/GELU 结构切入：输入 $x$ 先乘矩阵 $A$，经过 GeLU，再乘矩阵 $B$ 投影回输出 $z$。tensor parallel 的做法是把 $A$ 和 $B$ 切成子矩阵，分别放到不同 GPU 上并行算，最后再把结果汇总回来。老师说这本质上和 tiling 是同一类 primitive 的又一次出现。[课件: lecture_08.pdf p.39][课件: lecture_08.pdf p.40]

## 概念、符号与推导

- Tensor parallel：沿宽度轴切矩阵，把一次大 matmul 改成若干小 matmul 加一次汇总。[课件: lecture_08.pdf p.39][课件: lecture_08.pdf p.40]
- Forward/backward duality：forward 里 $f$ 是 identity、$g$ 是 all-reduce；backward 里二者互换。[课件: lecture_08.pdf p.40]
- Transformer 中的切分位置：
  - column-wise：QKV、up-projection
  - row-wise：attention output、down-projection
  - replicated：norms、routers、non-linearity 等小层。[课件: lecture_08.pdf p.41]
- Tensor parallel 的通信口径：每次 matmul 前后都伴随 activation-sized collective，因此高频、高带宽需求很强。[课件: lecture_08.pdf p.43]
- 激活内存经验式：$34sbh + 5as^2/h$。老师解释第二项来自 attention 的二次项和 dropout 存储。[课件: lecture_08.pdf p.46]
- 在 tensor parallel 下：MLP 的大块和 attention 二次项可按 $t$ 缩小，但 LayerNorm、dropout、MLP/attention 输入残差等约 $10sbh$ 不会随 $t$ 消失。[课件: lecture_08.pdf p.47]
- 结论推理：参数内存可以靠 TP/PP 线性降，但 activation memory 里仍有非分片残差，所以还需要额外手段处理激活。[课件: lecture_08.pdf p.45][课件: lecture_08.pdf p.47]

- [00:53:20-00:54:22] 之后进入 expert parallel。老师先定性地把它类比为“MoE 版 tensor parallel”：不是把一个大 matmul 切成多个子矩阵，而是把不同 experts 分散到不同设备，再把 token activations 路由过去，因此它同样是一种高带宽、同时还能减少激活/参数驻留的并行方式。[课件: lecture_08.pdf p.50][课件: lecture_08.pdf p.51]

- [00:55:44-00:57:58] 但他随即泼冷水：expert parallel 非常复杂。DeepSeek 有自己为专家路由做的 DPP 库，NVIDIA 也有 Hybrid EP；这些系统都在低层 GPU 网络原语上做了大量工程，甚至会用到 undocumented PTX 去继续压通信延迟。老师借此强调，MoE 的 all-to-all token dispatch 对延迟极敏感，因为算子必须等 token 到位才能继续。[课件: lecture_08.pdf p.51]

## 概念、符号与推导

- Sequence parallel：把 TP 下剩余的 pointwise activation 沿 sequence axis 分片存放，需要时 all-gather，之后再 reduce-scatter 回分片格式。[课件: lecture_08.pdf p.48]
- SP 的前后向对偶：forward 里 gather 后算，backward 里散回去的方向反转，这与 TP/FSDP 的“正反向角色互换”形成同一模式。[课件: lecture_08.pdf p.48]
- activation memory 下界口径：在 TP+SP 并配合可接受的 attention 重计算时，可记成近似 $34sbh/t$。[课件: lecture_08.pdf p.49]
- Expert parallel：把 experts 分散在不同设备上，token 根据 router 结果被 dispatch 到相应设备，本质上是 MoE 场景下以 token-routing 为中心的高带宽并行。[课件: lecture_08.pdf p.50]
- 为什么 MoE 下常 prefer EP over TP：TP 会把 matmul 切小、降低算子效率；EP 则直接利用 MoE 的稀疏路由结构，避免无谓地切 dense matmul。[课件: lecture_08.pdf p.51]
- EP 的系统难点：all-to-all token dispatch 延迟敏感，且 DP/EP 往往共享 replica 划分，因此 EP domain 常被 DP domain 限制。[课件: lecture_08.pdf p.52]
- 结构性不均衡：EP 只作用于 MLP，不作用于 attention，因此一个 MoE 模型里 attention 与 MLP 可能天然偏好不同的并行规模。[课件: lecture_08.pdf p.53]

## 例子与课堂提示

- [00:51:45-00:52:15] 记住 $34sbh/t$ 这个下界，是老师明确给出的手算经验值，适合做“这张卡能不能装下”的快速估算。[课件: lecture_08.pdf p.49]

- [00:54:46-00:55:21] “如果本来就是 MoE，尽量用 EP 而不是 TP” 是很强的工程经验，后面看 DeepSeek、Mixtral、Qwen 的配置时会不断印证。[课件: lecture_08.pdf p.51]

## 本段在整讲中的作用

本段把 MoE 时代的额外复杂性说清，并给出本讲最重要的“组合并行”操作手册。老师先处理 attention 与 expert parallel 之间的张力，再补充 context parallel，然后用一张总表和一组 compute/communication 视角下的规则，把前面所有并行法整合成可以真正拿来选型的框架。这一段是从“理解每个 primitive”过渡到“会组合它们”的关键节点。[课件: lecture_08.pdf p.53][课件: lecture_08.pdf p.54][课件: lecture_08.pdf p.55][课件: lecture_08.pdf p.56][课件: lecture_08.pdf p.57][课件: lecture_08.pdf p.58]

## 教学展开

- [00:59:57-01:00:58] 老师先讲一个只在 MoE 模型里才尖锐爆发的冲突：attention 不能用 expert parallel，因此想靠较高 tensor parallel 去切 attention；但 MLP 已经可以用 EP，如果再叠高 TP，就会把矩阵切得过碎、利用率很差。于是 attention 想要高 TP，MLP 想要低 TP，这构成了结构性矛盾。[课件: lecture_08.pdf p.53]
- [01:00:58-01:01:51] 针对这个矛盾，老师说近几年系统界给出的解法是“解耦”：让 attention 层和 MoE 层使用不同的张量/专家并行配置。于是 attention 侧有自己的一套 TP/CP/DP，MLP 侧有一套 ETP/EP/EDP，组合更复杂但也更有效。[课件: lecture_08.pdf p.53]
- [01:01:00-01:01:51] 随后老师简单带过 context parallel，也叫 ring attention：本质是把长序列的 activation 沿上下文维切到不同加速器，并沿环或 mesh 逐步传递。这在长上下文扩展和 serving 中常见，但由于概念上和前面 sequence/activation 切分相近，他不再展开细节。[课件: lecture_08.pdf p.54]
- [01:01:53-01:03:19] 进入全局总表后，老师刻意把不同方法的缺点标红，目的是强调“没有 strictly dominant parallelization strategy”。他逐项解释：FSDP 很好，但不减 activation，而且会消耗 global batch；tensor parallel 能减 activation 且不消耗 batch，但需要极快网络；pipeline 很省跨节点带宽，但要忍受 bubble 并依赖大 batch。换言之，每种方法都在不同资源上取舍。[课件: lecture_08.pdf p.55]
- [01:03:19-01:06:20] 接下来老师把问题提升到 roofline/利用率分析的语言：只要 compute time 长于 communication time，通信就能被掩盖在计算下方；一旦 batch 变小，FSDP-only 会先变成 communication bound，此时就要加入 model parallel，尤其是 tensor parallel，把曲线继续向可计算区推。把这些策略叠加起来，就形成老师口中的 3D 或 4D parallelism。[课件: lecture_08.pdf p.56][课件: lecture_08.pdf p.57]
- [01:06:20-01:07:58] 在操作规则上，老师给出非常简洁的 prescription：第一步先想办法让模型装得下，优先在机内快互连上使用 tensor 或 expert parallel；若还不够，再用 pipeline parallel 或 ZeRO-3/FSDP 去跨机器把模型塞进显存。第二步，当模型已经能装下后，再用 data parallel 吃掉剩余 GPU。若 batch 太小，再用 gradient accumulation 把更大有效 batch 换回来。[课件: lecture_08.pdf p.57][课件: lecture_08.pdf p.58]

## 概念、符号与推导

- Attention/MLP 的并行冲突：attention 不能靠 EP，只能靠 TP/CP 等切；MLP 在 MoE 中更愿意用 EP，因此两者偏好的 TP 规模不一致。[课件: lecture_08.pdf p.53]
- Context parallel / ring attention：把长上下文激活分散到不同设备，并沿环式或 mesh 拓扑交换所需上下文片段。[课件: lecture_08.pdf p.54]
- Parallelism table 的核心维度：同步方式、每 rank 参数内存、每 rank activation/KV 内存、主要带宽成本、是否扩大 global batch、是否易用。[课件: lecture_08.pdf p.55]
- Compute-bound vs communication-bound：只要单层或单步的计算时间大于通信时间，通信原则上可以被 overlap 掩盖；反之便会掉到效率差的区域。[课件: lecture_08.pdf p.57]
- 3D/4D parallelism：不是新的原语，而是把 DP、TP/SP、PP、EP/CP 这类维度叠加使用，以适应不同链路速度和内存压力。[课件: lecture_08.pdf p.57]
- 规则化 prescription：
  - 先为“装得下模型”服务：机内先用 TP/EP，机间再用 PP 或 ZeRO-3
  - 装下之后，为“吃满剩余 GPU”服务：尽量扩 DP
  - batch 小时，用 gradient accumulation 换有效 batch。[课件: lecture_08.pdf p.57][课件: lecture_08.pdf p.58]

## 概念、符号与推导

- Narayanan 风格扩展规则：TP 先升到约 8，随后 PP 上升，最末端 DP 反而可能下降，以把有限 GPU 预算让给“模型装得下”和“链路适配”。[课件: lecture_08.pdf p.59]
- Flat utilization：若并行组合与链路匹配得好，随着 GPU 数增加，利用率曲线可以近似持平，而不是线性崩塌。[课件: lecture_08.pdf p.60]
- TP=8 常见最优：这是老师从图中读出的经验边界，说明 TP 做大并非总是更好。[课件: lecture_08.pdf p.61]
- activation recomputation 的系统收益链：重算 -> 省显存 -> 扩 batch -> 提高利用率/吞吐，因此总收益不只看单次计算量。[课件: lecture_08.pdf p.62]
- 典型配置模式：
  - 小 dense 模型：FSDP 即可很好扩展
  - 大 dense 模型：TP + PP + DP，长上下文阶段再加 CP
  - 大 MoE 模型：EP 成为核心，再视 attention 需要叠加小规模 TP/PP。[课件: lecture_08.pdf p.63][课件: lecture_08.pdf p.64][课件: lecture_08.pdf p.66][课件: lecture_08.pdf p.72]
- 容错是大规模训练的隐含维度：GPU failure 不是边角问题，而是大规模训练配置的一部分背景约束。[课件: lecture_08.pdf p.67]
