## 核心概念与依赖关系
- Transformation 是入口：没有可靠的 HTML/PDF 到 text 转换，后续 filtering 的目标空间都不成立。[00:01:24-00:06:57]
- Filtering 依赖“target data / what good looks like”的定义。老师给出的统一模板是从小规模高质量目标集 T 学习打分函数，再把这个标准外推到海量 raw data R。[00:07:02-00:10:42] [代码: lecture_14.py p.4]
- Deduplication 依赖 filtering 之后的数据池，但目标从“判断单个样本好不好”转成“判断两个样本是否冗余”。因此它需要新的相似度定义与近似算法，而不是继续沿用分类器框架。[00:27:50-00:29:57][00:31:27-00:33:18]
- Jaccard 是 near duplicate 的定义层，MinHash 把相似度转成可哈希碰撞概率，LSH 再把随机碰撞锐化为接近阈值判别器；三者必须成套理解。[00:31:36-00:32:29][00:32:50-00:33:01][00:39:58-00:47:59] [代码: lecture_14.py p.8] [代码: lecture_14.py p.9]
- Mixing 依赖前面已经拿到的多个“相对可用”的 source，但它引入新的约束：source quality、source diversity、source finiteness 三者不能只看其一。[00:52:35-00:53:36]
- Regression-based mixing 与 simulated epoching 之间的关系是：前者回答“怎样找 mixture”，后者回答“怎样让小规模代理更像大规模训练”并防止优化被 epoching 偏差带歪。[01:00:26-01:09:47][01:09:47-01:10:23] [代码: lecture_14.py p.12]
- Post-training synthetic data 与 pre-training data 的本质区别是任务依赖性更强，数据构造不再只是“找好文本”，而是要联合设计环境、任务和 teacher 响应。[01:13:48-01:14:10] [代码: lecture_14.py p.13]

## 关键推导、例子与结论边界
- HTML to text 是 inherently lossy。这个结论来自老师对导航栏、图片、表格、嵌套表格和 PDF 版面语义缺失的展开，而不是某个形式化证明。[00:02:33-00:03:11][00:06:15-00:06:34]
- Filtering 的统一形式在代码页里写得很清楚：生成式打分可看作 $score(x)=p_T(x)$，分类式打分可看作 $score(x)=p(T\mid x)$；但老师明确提醒阈值不是常数，而依赖训练规模。[代码: lecture_14.py p.4] [00:17:26-00:18:10]
- OpenMathText 与 phi-1 是“先精确定义目标能力，再用过滤器放大规模”的两个代表。前者证明 task-specific corpus 可能胜过大而杂的语料，后者证明“昂贵教师标一小批 + 廉价过滤器扩大全量”是有效路线。[00:12:47-00:16:26] [代码: lecture_14.py p.4]
- Jaccard / MinHash / LSH 构成全讲最完整的一条算法推导链：

```text
Jaccard(A, B) = |A ∩ B| / |A ∪ B|
Pr[h(A) = h(B)] = Jaccard(A, B)
prob_match = sim^r
prob_collision = 1 - (1 - sim^r)^b
threshold = (1 / b)^(1 / r)
```

这些式子共同说明：先把 near duplicate 变成 Jaccard 阈值问题，再把相似度转成哈希碰撞，最后用 banding 结构把碰撞概率做成接近 phase transition 的函数。[00:31:36-00:47:59] [代码: lecture_14.py p.8] [代码: lecture_14.py p.9]
- 10T low / 10B high / 1T train / 50-50 mixture 的例子界定了 data mixing 最重要的失败模式：如果只按“高质量值得加权”思考，而不看 source size，就会无意中把高质 source 训练到 50 epochs。[00:53:45-00:57:07] [代码: lecture_14.py p.12]
- RegMix 的结论边界也被老师说得很清楚：它并非无条件可靠，而是依赖 surrogate 在 minimizer 附近仍然准、以及 small-scale 最优 mixture 能转到 large-scale，这两条都是 hope，不是 theorem。[01:04:50-01:09:47] [代码: lecture_14.py p.12]
- OpenThoughts 与 SWE-Zero 共同说明 post-training data 的边界：更强模型不一定是更好 teacher，no-exec 也可能足够强，但这些都建立在细致的数据构造、过滤与 scaffold 设计之上。[01:16:26-01:17:08][01:19:49-01:23:42] [代码: lecture_14.py p.13]

- 不要把 transformation 理解成“格式转换小问题”。老师明确把它讲成会影响内容定义、表格保真度和后续数据质量的大问题。[00:01:51-00:04:20]

## 本段在整讲中的作用
本段先把第 13 讲的数据来源问题接回到本讲的“数据管线”问题：老师先回顾数据不是自然掉下来的，而是要经过 live service -> dump/crawl -> processing 的链路，再说明本讲要进入四个预训练阶段环节：transformation、filtering、deduplication、mixing，最后再补 post-training data 的 synthetic data 用法。[00:00:13-00:01:12] 这一段还先把讨论范围限定在 pre-training，为后面所有技术细节定下语境。[00:01:12-00:01:15]

## 教学展开
老师先回顾上一讲：互联网数据来自在线服务，必须先抓取或导出，再经过处理，同时还要考虑 terms of service、copyright、license 或 fair use 等社会与法律约束。[00:00:13-00:00:46] 接着他给出本讲路线：数据转换、过滤、去重、混合，以及最后的 post-training synthetic data。[00:00:50-00:01:07]

随后老师转入 transformation 的复习。他强调 raw data 并不是天然文本；即便抓到了 Common Crawl，里面常见的原始形式也仍然是 HTML、PDF，或者 GitHub 这类目录结构。[00:01:18-00:01:39] 因为网页主体大多是 HTML，所以转换工作的重点通常是 HTML to text。[00:01:42-00:01:47]

在 HTML 转文本时，老师按问题顺序说明：先去除 boilerplate，例如导航栏、广告、页眉页脚、菜单，再尽量抽取页面主体内容。[00:01:51-00:02:20] 但他马上补充一个边界条件：什么算 content 并不总是清楚，因为某些导航元素也可能帮助模型学习网页结构。[00:02:20-00:02:31] 接着他提出图片与表格的处理难点，指出 HTML 线性化必然是有损过程；尤其表格常常只能近似处理，简单表格还能转成 markdown，嵌套表格则会很棘手，最后不得不放弃部分结构或做近似。[00:02:33-00:03:11]

老师再解释为什么工业上常见 rule-based HTML 处理：它速度快，而且此处任务并不要求太强的“智能”，所以经验规则通常够用。[00:03:11-00:03:31] 但他也保留一个开放判断：未来也许存在 model-based intervention 的空间，只是前提是足够快且能明显更智能。[00:03:34-00:03:41] 最后他提醒，任何 rule-based processing 都有失败率，因此数据里一定会留下瑕疵，而转换准确率会真实影响结果。[00:03:46-00:04:20]

后半段转到 PDF。老师先以 FinePDFs 为例说明：PDF 在互联网上也能从 Common Crawl 等来源拿到，但文件更大、常被截断，因此往往需要 recrawl。[00:04:20-00:05:20] 拿到 PDF 后，还要面对文本提取问题；有些 PDF 只是扫描件，本质上是图像，需要 OCR，通常还要借助 VLM，这比前面的纯文本处理昂贵得多。[00:05:20-00:05:47] 尽管 PDF 在整个互联网里占比小，老师仍强调它“值钱”，因为愿意做成 PDF 的内容平均质量往往高于普通 HTML 页面。[00:05:47-00:06:10] 最后他指出 PDF 清洗更难，因为它保留的是版面布局而不是 HTML 那样的语义标签，所以转换完成后虽然得到了 text，但距离可训练数据还“远未结束”，自然过渡到下一步 filtering。[00:06:15-00:06:57]

### 2. 00:10:03-00:20:00

## 本段在整讲中的作用
本段把 filtering 从抽象框架落到具体实例，完成“如何从 raw data 中筛出想要的数据”这件事的主要展开。它承接前一段“文本已经抽出来，但还远没结束”的结论，开始讲过滤器如何用目标数据定义“什么是好数据”，并给出 language identification、math filtering、GPT-3/LLaMA/phi-1、toxicity filtering 这些典型实现。[00:10:03-00:17:08] 最后又引入一个关键限制：过滤阈值是 scale-dependent 的，为后面关于训练时长与数据质量的讨论埋下伏笔。[00:17:26-00:20:00]

## 教学展开
老师先把抽象 filtering recipe 说完整：把目标集 T 当成正例、从 raw data R 中抽一些负例，训练一个足够快的分类器，最常用的是 fastText 这种 bag-of-words 线性分类器；然后对新文档打分，根据质量阈值决定保留，有时还会随机保留。[00:10:03-00:10:42] 他明确把这归为 model-based filtering，并说明近年趋势已从“担心偏差所以少用模型过滤”转向“算力紧张时必须聪明过滤，否则就是浪费 flops”。[00:10:42-00:11:21]

接着老师进入具体实例。第一类是 language identification：给定一段文本，判断它是不是某个目标语言。老师指出 Meta 的 fastText language ID 模型可直接拿来用，支持 176 种语言，训练源包括 Wikipedia 和多语翻译站点。[00:11:36-00:11:59] 他认为语言识别相对容易，因为少量词就足以区分西班牙语、日语等；但仍保留 code-switching、方言等边界复杂性，所以它不是绝对“彻底解决”的问题，只是通常不是训练好语言模型的主要瓶颈。[00:12:03-00:12:31] 最后仍要通过经验式阈值决定保留与否。[00:12:35-00:12:43]

第二类是按目标能力筛数据。老师以 OpenMathText 为例，目标是从大规模网页里提炼数学文本。[00:12:47-00:13:05] 这不是单一分类器，而是一条多阶段管线：先做规则过滤，例如是否包含 LaTeX 命令；再用在 ProofPile 上训练的 KenLM 按 perplexity 过滤；再训练 fastText 判断是否是 mathematical writing，并根据是否包含 LaTeX 采用不同阈值。[00:13:09-00:13:48] 他用结果强调 curated filtering 的威力：得到约 15B 级别数学 token 后，训练出的模型能胜过用 20 倍原始数据训练、但未做这种针对性过滤的模型。[00:13:51-00:14:07]

然后老师把 GPT-3、LLaMA、phi-1 都纳入同一个 filtering 框架。GPT-3 把 Wikipedia、WebText、books 之类当正例，把一般网页当负例，训练线性分类器后保留高分文档。[00:14:27-00:14:54] LLaMA 也类似，只是正例换成“被 Wikipedia 引用的页面”，而不是 Wikipedia 本身。[00:14:54-00:15:03] phi-1 的做法更值得注意：先从 The Stack 的 Python 子集出发，用一个关于“educational value”的 prompt 让 GPT-4 给 100K 子集打标签，把高质量样本当作 target，再训练更便宜的分类器（论文里是 Random Forest）扩展到全量数据。[00:15:06-00:16:17] 老师强调，这里 target 本身其实是“昂贵分类器的输出”，而便宜分类器只是拿来 scale-out。[00:15:55-00:16:17] 结果也是过滤后的数据集能在更少 steps 里达到更高性能。[00:16:17-00:16:26]

最后老师说明 toxicity filtering 也遵循同样套路：用 Jigsaw Toxic Comments 这类带标签数据，把 Wikipedia talk pages 上的评论按 toxic 与否做正负例，再训练分类器推广到大规模网页。[00:16:33-00:17:08]

在讲完这些实例后，老师抽象出“quality is task-defined”的观点：质量没有统一定义，如果你把“数学性”定义成质量，就能筛到数学数据，并在该能力上变强。[00:14:13-00:14:27] 随后他补充本段最重要的微妙点：不存在对所有训练方案都最优的固定阈值。分类器给出的 score 不是天然对应一个唯一最佳阈值，而是要看你准备训练多少 token。[00:17:26-00:17:54] 训练得更久时，可以接受更低质量、但数量更多的数据；训练得更短时，则应提高质量门槛。[00:17:54-00:18:10] 他再用一个 157M 模型在 100 websites 小数据池上的 preliminary experiment 解释：高质量过滤后的数据在早期 regime 表现更好，但随着多次 epoch，模型会先继续学习，最终也会过拟合；而过滤更少的数据虽然起步差，却在长程训练里可能反超。[00:18:24-00:20:00]

### 3. 00:20:00-00:30:00

## 本段在整讲中的作用
本段先收束 filtering，回答学生关于实验稳定性和高质量数据长训是否仍会收益的问题，然后正式切到 deduplication：为什么高质量数据里依然充满重复、为什么重复会伤害训练、以及去重问题的设计空间与算法约束。它承担从“筛什么数据”转向“避免重复样本浪费”的过渡作用。[00:20:00-00:29:57]

## 教学展开
老师先补完上一段的图。面对“每个点是否都要做多次训练取 confidence interval”的提问，他回答理想上应该这样做，但预训练实验昂贵，所以论文里常见不到太多重复实验；不过按他的经验，至少 pre-training 往往比较稳定。[00:20:16-00:21:08] 紧接着他回应“如果高质量数据继续长训是否仍有效”的问题：任何有限数据集最终都会出现 diminishing returns，只是高质量数据的收益曲线会整体更低、更久一些，但终究也会走向收益递减。[00:21:10-00:21:46]

在这两个问答后，老师对 filtering 下结论：只要算力不是无限，过滤就是构建好模型的关键；核心 recipe 仍然是先定义“好数据长什么样”，再训练一个轻量分类器，把这一标准外推到大规模网页。[00:21:56-00:22:50]

随后他切入 deduplication。前提是：即便数据已经经过过滤、只保留高质量内容，里面依旧会有大量 duplicates。[00:22:56-00:23:14] 他先区分两类重复：exact duplicates，例如 mirror sites 抓到的完全相同内容，以及代码仓库 fork 带来的大面积相同文件；near duplicates 则不是完全相同，而是仅差几个 token，可能来自复制、模板化生成或同一上游来源。[00:23:14-00:24:18]

接着老师用一组网页例子说明 near duplicates 的来源：许可证文本、网站共用页眉页脚、只差一个逗号的两篇文章、以及用模板把 Canada 替换成 USA 一类低质量广告式内容。[00:24:18-00:25:42] 他特别强调“看数据很重要”，并举出对 C4 的审计：某个 gas mask 商品描述竟然在 Common Crawl 中重复出现 61,000 次，这种异常现象说明网页数据的重复可能离谱到肉眼难以预想。[00:25:48-00:26:13]

在“为什么要 dedupe”上，老师给出两层理由。第一层是效率：去重能在几乎不损失信息的情况下减小数据集，避免把 GPU 算力花在重复样本上。[00:26:17-00:26:55] 第二层是泛化与合规：重复过多会加剧 memorization，因此也会放大 copyright 与 privacy 风险。[00:26:36-00:26:49] 他顺带提到相关但更重要的概念是 decontamination，即确保测试集没有泄漏进训练集。[00:26:58-00:27:07]

最后老师给出 deduplication 的设计空间，并指出真正的困难不在定义，而在规模。设计上要回答三件事：item 是句子、段落还是文档；match 是 exact、共享某个 subitem，还是用共同子项比例衡量近似重复；发现重复后是全删还是保留一个。[00:27:15-00:27:49] 算法难点在于 dedupe 本质上是 item-to-item 比较，朴素做法是 $n^2$，但网页规模完全不可行，因此必须发展近似线性时间算法；老师也据此自然引出后面的 hash-based 方法。[00:27:50-00:29:57]

## 概念、符号与推导
- Exact deduplication 的简单方案：item 取字符串，match 用 exact match，动作是 remove all but one。[代码: lecture_14.py p.7]
- Jaccard similarity 定义：

```text
Jaccard(A, B) = |A ∩ B| / |A ∪ B|
```

- MinHash 性质：

```text
Pr[h(A) = h(B)] = Jaccard(A, B)
```

其中 $h$ 是随机哈希函数。[00:32:50-00:33:01] [代码: lecture_14.py p.8]

- MinHash 构造：对集合中每个元素做哈希，取最小哈希值；等价于在随机排列下取最先出现的元素。[00:33:54-00:35:39] [代码: lecture_14.py p.8]

### 5. 00:39:58-00:49:53

## 本段在整讲中的作用
本段完成 near deduplication 的第二步：在 MinHash 基础上引入 locality-sensitive hashing，把“碰撞概率等于 Jaccard”改造成“在某个阈值附近出现相变”的近似判别器。它既是 dedupe 部分的高潮，也是后面 data mixing 的直接前置，因为老师最后顺着“跨数据集去重”自然转入“多数据源混合”。[00:39:58-00:49:53]

## 教学展开
老师先给出 LSH 的碰撞定义：把独立 hash functions 分成多个 band，只要存在某一个 band 内所有 hash 都匹配，就说 A 和 B collide。[00:39:58-00:40:53] 他强调关键不在“所有 hash 全部相同”，而在这个 and-or 结构：band 内是 AND，跨 band 是 OR，真正起作用的是这个组合逻辑。[00:40:42-00:40:57]

接着老师计算碰撞概率。若已知 Jaccard$(A,B)=0.8$，有 $b=5$ 个 band、每个 band 有 $r=10$ 个 hash，则固定一个 band 全部匹配的概率是 $0.8^r$，因为该 band 内每个 hash 都必须匹配。[00:41:16-00:41:58] 一个 band 不匹配的概率是 $1-0.8^r$，所有 $b$ 个 band 都不匹配的概率是 $(1-0.8^r)^b$，因此至少有一个 band 匹配、也就是整体 collide 的概率为 $1-(1-0.8^r)^b$。[00:42:04-00:42:32] 老师口头给出这个例子大约是 0.4，并提醒直觉上会比单次碰撞“更高”，因为你给了多个机会去撞上。[00:42:32-00:42:37] [代码: lecture_14.py p.9]

老师随后解释这条曲线的形状：横轴是相似度，纵轴是碰撞概率；在 0 处概率应为 0，在 1 处为 1，而中间会出现一个 S 型曲线。[00:42:46-00:43:45] 这正是 LSH 想要的效果，因为目标不是线性地反映相似度，而是制造接近 phase transition 的阈值行为：低于阈值时尽量不匹配，高于阈值时尽量匹配。[00:43:18-00:43:45]

然后老师比较参数变化的作用。先看 $b=10,r=10$ 时，不同相似度的碰撞概率大约从 0.25 到 1，说明低于阈值的样本仍可能 false positive，但高于阈值的样本大多会保留。[00:44:01-00:44:59] 增大 $r$ 会让曲线更陡、整体右移，因为一个 band 内要同时满足更多哈希匹配，低 Jaccard 的对象更难碰撞；老师举例说原先低相似度的概率约 0.25，增大 $r$ 后可降到 0.008。[00:45:04-00:45:49] 反过来，增大 $b$ 会让曲线左移，因为 band 更多意味着“总有一个 band 撞上”的机会更大，整体更容易匹配；例如相似度 0.9 的碰撞概率能从 0.72 提高到 0.92。[00:45:52-00:46:16] 但他也提醒，想把 phase transition 做得很尖锐，就得同时增大 $b$ 与 $r$，代价是更高计算成本。[00:46:24-00:46:33]

最后老师看一个更真实的参数规模：某去重论文用的是 $b=20, r=450$。[00:46:39-00:46:53] 他给出阈值近似公式：

```text
threshold = (1 / b)^(1 / r)
```

意思是，如果你想把相变中心放在某个目标 Jaccard，例如 0.9，就要反过来选合适的 $b,r$ 让这个式子接近该阈值。[00:46:59-00:47:25] 在这一阈值点上，固定 band 匹配的概率约为 $1/b$，整体碰撞概率则是常数，大约 $1-1/e \approx 0.64$；老师把它解释为 phase transition 的中心点：当 $b,r$ 足够大时，阈值下方趋向 0，阈值上方趋向 1，而中心就卡在约 0.64 的位置。[00:47:29-00:47:59] [代码: lecture_14.py p.9]

在收束时，老师点明这套方法叫 MinHash LSH，因为 LSH 本身可以搭配很多哈希族，而语言模型去重场景里这里选的是近似 Jaccard 的 MinHash。[00:48:15-00:48:30] 接着他补充一个工程提醒：去重不该只在单个数据集内部做，还应该跨整个训练集做，因为不同 data source 之间也会高度冗余。[00:48:55-00:49:15] 这句提醒之后，他自然转向“既然训练集来自多个 source，那它们怎么混合？”从而开启 data mixing。[00:49:21-00:49:53]

## 概念、符号与推导
- LSH 碰撞规则：把 $n$ 个哈希分成 $b$ 个 band、每个 band 含 $r$ 个哈希，若“存在某个 band 内所有哈希都匹配”，则判定 collide。[00:39:58-00:40:57] [代码: lecture_14.py p.9]
- 固定 band 匹配概率：

```text
prob_match = sim^r
```

其中 $sim=Jaccard(A,B)$。[00:41:19-00:41:58] [代码: lecture_14.py p.9]

- 整体碰撞概率：

```text
prob_collision = 1 - (1 - sim^r)^b
```

即“1 减去所有 band 都不匹配的概率”。[00:42:04-00:42:32] [代码: lecture_14.py p.9]

- 参数作用：增大 $r$ 让阈值更陡且右移，更难匹配；增大 $b$ 让曲线左移，更容易匹配。[00:45:04-00:46:16] [代码: lecture_14.py p.9]
- 相变阈值近似：

```text
threshold = (1 / b)^(1 / r)
```

在阈值点附近，整体碰撞概率约为 $1-1/e\approx0.64$。[00:46:59-00:47:59] [代码: lecture_14.py p.9]

### 7. 00:59:51-01:09:47

## 本段在整讲中的作用
本段从“如何防止 epoching 爆炸”进一步升级为“如何 principled 地求 mixture”。老师在这里系统引入 regression-based mixing / RegMix 框架，解释小规模代理实验、回归建模、优化求解及其两大 leaps of faith，是整讲 data mixing 的理论主线。[00:59:51-01:09:47]

## 教学展开
老师先承接上一段，说明即便加了 cap，仍要回答更根本的问题：如果有 50 个数据源，就有 50 个 mixture weight 要定，仅靠 proportional mixing 或基于某个 quality metric 的启发式采样都不够 principled。[00:59:51-01:00:24] 因此他提出 regression-based mixing，也就是 RegMix、Olmix 一类方法，认为这是当前最容易看清“发生了什么”的框架。[01:00:26-01:00:40] [代码: lecture_14.py p.12]

老师把流程拆成顺序明确的四步。第一步，目标是大模型训练，但先退回小规模，例如 300M 参数级别，试验许多不同 data mixtures。[01:00:46-01:01:06] 第二步，对每个 mixture 各训练一个 small proxy model，得到对应的 loss 或 downstream metric。[01:01:06-01:01:19] 第三步，用这些点拟合一个回归模型，让输入是 mixture weights，输出是预期 loss。[01:01:19-01:01:39] 第四步，对这个廉价 surrogate 直接做优化，找到预测最优的 mixture，再把它拿去训练大模型。[01:01:39-01:02:03] 老师指出这与 scaling laws 的精神相似：先用便宜计算逼近规律，再把结论放大到昂贵训练。[01:02:03-01:02:14]

接下来老师列出设计决策。首先，采样哪些 mixture？由于 mixture 本身是一个分布，所以这里需要“distribution over distributions”，常用 Dirichlet 来采样，也有其他分布。[01:02:17-01:02:35] 其次，回归模型可以是线性模型，也可以是 boosted decision trees。[01:02:35-01:02:42] 第三，target metric 往往来自 downstream evals，但这里危险最大：pre-training 本该学一般能力，如果 target 用太多 code evals，优化结果就会理所当然地把 code 数据大幅加权，结果可能导致模型泛化到诗歌等任务时表现变差。[01:02:42-01:03:19] 老师借此强调：uniform 与 proportional mixing 没有这个“看着评测调训练分布”的问题，因为它们根本不依赖 downstream evals。[01:03:21-01:03:27]

第四个设计点是 small-to-large discrepancy，也就是小规模代理与大规模训练的差异。[01:03:27-01:03:54] 老师说这是 cost/accuracy trade-off：代理模型太小会不具代表性，代理模型太大又失去做这种方法的意义，相当于把超参数搜索直接搬到最大规模做，太贵。[01:03:35-01:03:54] 他随后提到 Olmix paper 给了一个很好的对比表，展示不同方法采用的 proxy model size、采样 mixtures 的方式、回归模型，以及求解优化问题的方法。[01:03:54-01:04:50] 其中他提到 log-linear model 往往效果不错，mixture 采样可以用 Dirichlet 或 exponential family 之类的方法。[01:04:24-01:04:50] [代码: lecture_14.py p.12]

最后老师点明两个 leaps of faith。第一，回归模型是在若干小规模随机 mixture 上拟合出来的，但你真正关心的是它的 minimizer；优化过程可能把你带到训练数据覆盖不足的极端区域，因此“回归在 minimizer 附近仍然准确”只是希望，而不是自动保证。[01:04:50-01:05:43] 第二，即便在小模型上找到了好 mixture，也还希望它能转移到大模型上，这同样需要谨慎，因为 small proxy 与 large run 之间不必天然一致。[01:05:43-01:09:47] 他用这两点把 RegMix 的吸引力和风险同时摆出来，没有把它描述成无条件可靠的银弹。[代码: lecture_14.py p.12]

- 需要定义的对象：
  - mixture 的采样分布，例如 Dirichlet；
  - 回归器类型，例如线性模型、boosted trees；

- 关键风险 1：优化 minimizer 可能落在训练覆盖薄弱区域，导致 surrogate 在最优点附近不准。[01:04:50-01:05:43] [代码: lecture_14.py p.12]
- 关键风险 2：小规模最优 mixture 不一定可迁移到大规模训练。[01:05:43-01:09:47] [代码: lecture_14.py p.12]
