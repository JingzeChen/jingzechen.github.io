## 学习目标
本讲的目标是建立一套评估语言模型的完整框架：先回答“什么叫好模型”，再把抽象目标落成具体指标、题目或环境。老师依次讨论 perplexity、考试型 benchmark、开放式对话评估、agent benchmark、纯推理 benchmark、安全 benchmark、现实性与有效性，最后收束到“评估服务于什么目的”这一方法论问题。[代码: lecture_12.py p.2] [代码: lecture_12.py p.3] [代码: lecture_12.py p.4] [代码: lecture_12.py p.12]

## 需要的先修知识
需要承接前面课程已经讲过的语言模型训练主线，包括架构、优化、训练循环、系统、并行化、scaling laws 与少量推理加速内容。还需要熟悉概率分布 $P(x)$、few-shot prompting、chain-of-thought、ELO、agent scaffold、contamination、ecological validity 等基本术语，因为老师整讲都在用这些概念解释“分数到底代表什么”。[代码: lecture_12.py p.2] [代码: lecture_12.py p.4] [代码: lecture_12.py p.6] [代码: lecture_12.py p.10] [代码: lecture_12.py p.11]

## 老师的教学主线
老师先把 evaluation 定义为“给定一个模型，问它有多好”，并指出核心难点是把“擅长对话”“擅长推理”这类抽象构想变成具体 metric。[代码: lecture_12.py p.3] 接着他用多种 benchmark 展示不同评估如何各自引入局限：perplexity 自然却可能过宽，考试题可控却不真实，开放式评估贴近用户却容易受 judge bias 影响，agent 评估又把 scaffold 一并拉入被测对象。[代码: lecture_12.py p.4] [代码: lecture_12.py p.5] [代码: lecture_12.py p.6] [代码: lecture_12.py p.7] 最后老师强调，没有唯一正确评估，必须先声明目的和比赛规则，再接受难度、现实性、有效性之间的取舍。[代码: lecture_12.py p.11] [代码: lecture_12.py p.12]

## 核心概念与依赖关系
整讲最关键的依赖链是“抽象目标 -> 具体指标 -> 评测载体 -> 结果解释”。perplexity 站在语言模型概率分布 $p(x)$ 的底层视角上；LAMBADA、HellaSwag 可以看成更聚焦的 completion 评估；MMLU、GPQA、HLE 把问题组织成更易评分的考试题；Chatbot Arena、AlpacaEval、WildBench 则把真实 prompt 分布、judge 机制和 rubric 组织到一起。[代码: lecture_12.py p.4] [代码: lecture_12.py p.5] [代码: lecture_12.py p.6] 进一步到 agent benchmark，SWE-bench、Terminal-Bench、CyBench、MLEBench 让“模型 + scaffold”在环境中执行任务；再往后，ARC-AGI 试图把推理从知识中分离，安全与现实性 benchmark 则继续追问这些能力能否在社会上被接受、在真实世界中被信任。[代码: lecture_12.py p.7] [代码: lecture_12.py p.8] [代码: lecture_12.py p.9] [代码: lecture_12.py p.10]

## 关键推导、例子与结论边界
本讲最重要的推导是 perplexity 的论证：若真实分布是 $t$、模型分布是 $p$，最佳 perplexity 是 $H(t)$，并且仅当 $p=t$ 时达到，于是“持续压低 perplexity 最终逼近通用能力”才会成为长期有吸引力的研究信念。[代码: lecture_12.py p.4] 但老师也立即指出边界：普通 perplexity 会平均惩罚所有 token，未必对应真正关心的能力，所以才有 conditional perplexity 与更聚焦的 benchmark。[代码: lecture_12.py p.4] 在考试型 benchmark 上，MMLU -> MMLU-Pro -> GPQA -> HLE 展示的是“饱和后继续加难”的升级循环；在开放式评估上，Chatbot Arena、AlpacaEval、WildBench 展示的是“越来越真实，但越来越依赖 judge 设计”的另一条链；在 agent 评估上，CyBench、MLEBench 和 ARC-AGI 又共同说明分数并不只反映底层模型，而是同时反映 scaffold、任务环境与推理边界。[代码: lecture_12.py p.5] [代码: lecture_12.py p.6] [代码: lecture_12.py p.7] [代码: lecture_12.py p.8]

## 易错点与待核对项
最大的易错点，是把评估当成纯机械打分，而忽略它会反过来塑造模型优化方向。[代码: lecture_12.py p.3] 另一类易错点，是把某个 benchmark 高分直接解释成一般能力，而不追问 train-test overlap、judge bias、答案提取方式、agent scaffold、环境漏洞和数据集质量。[代码: lecture_12.py p.5] [代码: lecture_12.py p.6] [代码: lecture_12.py p.7] [代码: lecture_12.py p.11] 现有 section notes 里还明确保留了若干字幕疑点，包括 “top bottles”“remarkably slow perplexity”“another [INAUDIBLE] model”“La Marina”“authentic”“And no trade tests contamination”等，都应按 [需回听] 理解，不应当作确定事实。

## 掌握标准
掌握本讲，不是记住 benchmark 名字，而是能回答三类问题：第一，这种评估在测什么；第二，这个分数能不能直接信；第三，为什么在当前目的下选这种评估而不是别的评估。若能把采购决策、原始能力测量、收益与伤害分析、开发反馈四类目标，与 methods 或 models/systems 的规则区分联系起来，才算真正掌握老师最后的 takeaways。[代码: lecture_12.py p.12]

## 本段在整讲中的作用
这一段完成整讲开场，先把课程进度定位到“训练语言模型的主要环节几乎都讲完了，只差数据与评估”，再明确说明在讨论训练数据之前，必须先回答“我们到底希望模型表现成什么样”。老师因此把“评估”设成数据单元之前的前置问题，并把后面整讲的主线定为：把抽象的“好模型”翻译成可执行的具体指标。[代码: lecture_12.py p.1] [代码: lecture_12.py p.2] [代码: lecture_12.py p.3]

## 教学展开
老师先回顾本课此前已经覆盖的内容：架构、优化器、主训练循环、用 kernels 和并行化提速训练、scaling laws，以及一点推理加速；然后指出唯一还没系统展开的是训练数据，而这部分会在下周讲。[代码: lecture_12.py p.2]

接着他说明数据会塑造模型行为：如果训练在代码上，模型就更擅长代码；如果只训练 DNA 序列，模型大概率就不会说英语。正因为数据会决定行为，所以在谈“该喂什么数据”之前，必须先谈“想要什么行为”，这就是 evaluation 的位置。[代码: lecture_12.py p.2]

随后老师给出评估的基本问题：给定一个已经训练好的模型，它到底有多“好”。他故意追问“什么叫好”，并指出评估表面上看似机械，只要定义 prompts、喂给模型、取回响应、计算 accuracy 三步即可，但真正困难之处在于，评估实际上在为 AI 发展设定北极星。开发者会盯着评估结果当作进步尺度，因此你如何设计评估，就会反过来塑造模型会被优化成什么样。[代码: lecture_12.py p.3]

在这个基础上，老师提出本讲的核心困难：通常起点是一个抽象构想，例如“擅长对话”或“擅长推理”，而评估工作就是把这种抽象构想落到具体 metric 上，并由具体 prompts 或环境来承载。这条“抽象构想 -> 具体指标”的转化链条，是后面所有 benchmark 例子的总纲。[代码: lecture_12.py p.3]

然后他用几种不同的“好”来松动学生的直觉。第一种是 benchmark 表现好，例子是 Artificial Analysis 这样的模型排名网站，把多个数据集压成所谓 intelligence 指数。第二种是“强且便宜”，也就是把能力和推理成本一起纳入考虑。第三种是“人更喜欢它的回答”，对应 Arena AI 这类偏好排名。第四种是“用户愿意真的去用并付费”，对应 OpenRouter 统计到的真实使用量。老师强调这些都不是唯一正确答案，他的目标是迫使大家意识到“好”本身就有多个视角。[代码: lecture_12.py p.3]

最后，本段把话题收束到最基础的一类评估：既然语言模型本质上是 token 序列上的概率分布 $P(x)$，那最自然的评估就是看它给测试数据集分配了多少概率质量，也就是 perplexity / likelihood / log loss 这一类量。老师解释说，这和训练时最小化训练集 perplexity 是直接连着的，因此传统语言建模研究自然会在测试集上继续量 perplexity，为下一个片段的展开做铺垫。[代码: lecture_12.py p.4]

## 概念、符号与推导
- 评估的核心问题：给定已训练模型，问“它有多好”。[代码: lecture_12.py p.2]
- 三步机械流程：定义 prompts；向模型发送 prompts 并获得 responses；计算 accuracy。[代码: lecture_12.py p.3]
- 核心困难：把抽象构想（如“擅长对话”“擅长推理”）转成具体 metric，再由具体 prompts 或 environment 承载。[代码: lecture_12.py p.3]
- 语言模型视角：模型是 token 序列上的概率分布 $P(x)$。[代码: lecture_12.py p.4]
- 困惑度视角：对测试数据集 $D$，考察模型给 $D$ 分配多少概率质量；老师口头说会做归一化，让数值更可解释。[代码: lecture_12.py p.4]

接着老师正式切到 chat benchmarks。他给出一个贴近真实使用的示例 prompt：想做甜菜和山羊奶酪沙拉，哪些香草合适、哪些不合适。这类输入是开放式的，模型返回的也是开放式文本，因此不能再做 exact match，甚至不存在单一 ground truth。评估难点由此被明确提出：开放式回答到底怎么比优劣？[代码: lecture_12.py p.6]

第一种方案是 Chatbot Arena。老师解释其数据收集机制：任意互联网用户进入网站输入 prompt，系统从两个匿名模型返回两份回答，再让用户判断 A 更好、B 更好、两者都好或都差。这样就收集到大量 pairwise comparison。随后用 ELO 模型，把“模型 A 战胜模型 B 的概率”写成 ELO 分数差的平滑函数，再通过最大化观察到的两两比较概率来拟合每个模型的 ELO，从而得到排行榜。[代码: lecture_12.py p.6]

在评价 Chatbot Arena 时，老师先说优点：prompt 更接近真实世界，因为用户来这个网站的动机通常是免费用模型做事；同时 ELO 的一个大优点是，不必把同一批 prompt 送给所有模型，只要比较图是连通的，就能从稀疏两两比较中恢复整体排名，这对人类评审成本很关键。并且随着新模型和新 prompt 到来，体系也可以动态更新。[代码: lecture_12.py p.6]

但老师也强调多个问题。首先，你并不知道“来这个网站的人”到底代表什么分布，可能有偏差、刷子、甚至想给自己提交的模型刷分的人。其次，二元偏好把 style 和 correctness 混在一起，而“哪个回答更好”不像国际象棋胜负那样定义清楚。再者，发问者往往正因为不知道答案才来问模型，那他如何可靠地判断哪一个更正确？这里还会遇到 sycophancy：更讨喜、更顺着用户的话，未必更对。[代码: lecture_12.py p.6]

然后老师讲第二种方案 AlpacaEval。它取一组指令，对被测模型和基线模型都生成回答，再让 GPT-4 preview 之类的 judge 模型判谁更好，于是得到 against-baseline 的 win rate。这是典型的 LLM-as-a-judge。老师指出，这立刻带来 judge bias 的疑问；同时早期 AlpacaEval 还暴露出 LLM judge 偏爱长回答，导致 leaderboard gaming，于是后续版本用简单回归方法去偏。[代码: lecture_12.py p.6]
