## 学习目标
- 理解本讲的两条主线：一条是用 attention alternatives 控制长上下文成本，另一条是用 mixture of experts 在近似不增加 FLOPs 的前提下扩大参数容量。
- 能复述线性注意力的核心起点：先去掉 softmax，再利用矩阵乘法结合律把 attention 重排成线性依赖，并进一步写成递推状态形式。
- 能说明 Mamba-2、gated delta net、DSA 这几条 attention alternatives 路线分别在“表达力、推理效率、实现复杂度”上的取舍。
- 能说明主流 MoE 的结构、路由、训练和系统问题：TopK routing、shared/fine-grained experts、load balancing、expert parallel、router stability、fine-tuning 过拟合。
- 能用 DeepSeek v1/v2/v3 作为案例，理解现代大模型如何把架构设计与系统设计联合起来。

## 需要的先修知识
- 基础 transformer 结构：attention block、MLP/FFN block、residual、normalization。
- 自注意力常见记号：`Q`、`K`、`V`、softmax、上下文长度 `n`、隐藏维/键值维。
- 复杂度直觉：为什么 all-to-all attention 随序列长度增长会出现二次成本。
- RNN/LSTM 的基本概念：状态递推、遗忘/写入门、训练并行性差但推理状态固定。
- 系统侧基本概念：FLOPs、通信成本、KV cache、数据并行、模型并行。

## 老师的教学主线
- 先交代本讲范围：attention alternatives 改 attention，MoE 改 MLP。
- 再建立长上下文的成本动机，说明基础工具箱如 local/global hybrid 和 flash attention 虽重要，但可能不足以支撑超长上下文。
- 然后用“去掉 softmax + 结合律重排 + 递推 duality”构造出 linear attention 及其后继家族，再补充 DSA 作为另一条稀疏注意力路线。
- 在 attention alternatives 部分结束时，老师用问答澄清“损失到底来自哪里”，并强调 TopK 这种离散选择模式会在后面的 MoE 里再次出现。
- 进入 MoE 后，先讲工业动机和基础心智模型，再依次展开路由、共享专家、训练启发式、系统并行、稳定性和微调问题。
- 最后用 DeepSeek 系列把这些点串成一条演化线，并以 MLA、MTP 收束到“现代模型是整套系统设计”的结论。

## 核心概念与依赖关系
- `长上下文需求 -> attention 成本主导 -> 需要更激进的 attention alternatives`。
- `去掉 softmax -> linear attention 重排 -> RNN 递推 duality -> Mamba-2 / gated delta net 等门控状态模型`。
- `不走递推线 -> 用轻量 indexer 做 TopK 粗筛 -> DSA 在短子集上做 full attention`。
- `想要更多参数但不想同比增加 FLOPs -> 把单个 FFN 换成多个 experts + router -> 得到 MoE`。
- `离散 TopK 路由不可导且会 rich-get-richer -> 需要 balancing losses / bias tricks -> 才能稳定训练稀疏 MoE`。
- `MoE 不仅是建模技巧 -> 还牵涉 expert parallel、通信、稀疏矩阵乘法、router 数值稳定性、微调策略`。

## 关键推导、例子与结论边界
- 关键推导一：

```text
Attn(Q, K, V) = ρ(QK^T)V
若暂时把 ρ 视为恒等：
QK^TV = Q(K^TV)
```

- 关键推导二：线性注意力可以写成递推状态：

```text
S_t = S_{t-1} + k_t v_t^T
y_t = q_t^T S_t
```

- 关键推导三：门控后仍能维持 duality 的前提，是额外项只依赖输入而不依赖状态；这给出 Mamba-2 和 gated delta net 的课堂解释框架。
- 关键例子：Minimax M1、Nemotron-3、Qwen 3.5 / Qwen Next、DeepSeek v3.2、GLM5、Qwen MoE、DeepSeek MoE、MiniCPM。
- 结论边界：
  1. 纯线性 attention 尚未在大规模上被完全证明；现实里大多是 hybrid。
  2. DSA 并非严格线性时间，只是常数和子序列长度更可控。
  3. shared experts 有不少成功案例，但并非所有受控研究都证明它必然有效。
  4. MoE 训练依赖启发式均衡，不代表离散路由的理论难题已经彻底解决。

## 易错点与待核对项
- 易错点：把“linear attention 的并行形式与递推形式等价”误解成“full softmax attention 与 linear attention 等价”。真正有损的是去掉 softmax 的第一步。
- 易错点：把 experts 想成高层语义模块。老师明确说大多数 router 过于简单，专家分工通常只是输入模式偏好。
- 易错点：只看大 O 而忽略系统常数。flash attention、DSA indexer、expert communication 都说明常数项可能决定成败。
- 易错点：把 balancing loss 当成可有可无的装饰。OlMoE 消融说明删掉后可能直接出现 expert collapse。
- 待核对：字幕里有若干 `[INAUDIBLE]` 与术语误转写，尤其出现在问答、DSA 细节、shared expert 并行化、MoE 随机性与 MLA/KV cache 部分，详细项见各分段笔记中的 `[需回听]`。

## 掌握标准
- 能不用看讲义，口头解释为什么 attention 成本会随上下文变成瓶颈，以及 local/global hybrid、flash attention、linear attention、DSA 分别在解决什么层面的成本问题。
- 能写出线性注意力的重排式与递推式，并说明 duality 为何对训练和推理都有利。
- 能比较 Mamba-2 与 gated delta net 的门控思想，并说明为什么“只依赖输入的门”是关键条件。

- 能用 DeepSeek v1/v2/v3 的演化复述“现代 MoE 是建模与系统联合设计”的主张。

## 复习顺序
1. 先复习整讲总问题：为什么要同时讨论 attention alternatives 和 MoE。
2. 再复习线性注意力的三个台阶：去 softmax、结合律重排、递推 duality。

4. 再补 DSA，把它和 linear attention 区分开：一个靠递推，一个靠稀疏索引。
5. 最后复习 MoE：结构心智模型 -> TopK routing -> shared/fine-grained experts -> balancing losses -> 系统与稳定性 -> DeepSeek 家族复盘。

## 教学展开
- `[00:00:05-00:01:33]` 老师先说明本讲是“比基础 transformer 更高级、更复杂的架构想法”。前一讲讨论的是如何在基本 transformer 上做常规改造；这一讲则聚焦两类更激进的改造：attention alternatives 和 mixture of experts。前者改 attention block，后者改 MLP block。[课件: lecture_04.pdf p.1]
- `[00:01:33-00:02:49]` 进入 attention 部分后，老师先给出长上下文动机：大家都希望上下文更长，好把更多知识、工具和 agent 工作流塞进上下文里。问题在于，随着序列长度增长，attention 的 all-to-all 连接会比前馈层更快成为主导成本。[课件: lecture_04.pdf p.2]
- `[00:02:49-00:04:49]` 老师先回顾“基础工具箱”。第一类方法是把 local attention 和 global attention 混合，减少全局 attention 的出现频率；第二类方法是系统工程优化，典型代表是 flash attention。老师特别强调，这一类改进不改变大 O，但常数项很重要，flash attention 通过减少显存搬运和不显式物化大 attention 矩阵，能带来非常显著的吞吐提升。[课件: lecture_04.pdf p.3]
- `[00:04:49-00:05:47]` 老师随后收束问题：如果目标是 5M 到 10M token 级别的上下文，仅靠混合局部注意力和 flash attention 这类技巧可能还不够，因此需要更激进的线性时间依赖方案。
- `[00:05:47-00:07:54]` 线性注意力的起点是“先暂时忘掉 softmax”。老师把常见 attention 写成 `Attn(Q,K,V)=ρ(QK^T)V`，说明真正导致二次复杂度的是 `QK^T` 这一步；如果把 `ρ` 暂时当恒等映射，就可以利用乘法结合律把 `QK^TV` 改写成 `Q(K^TV)`，从而把对序列长度的依赖从 `n^2` 转成与 `d_k,d_v` 相关的线性项。[课件: lecture_04.pdf p.4]
- `[00:07:54-00:09:50]` 在完成重排后，老师继续指出另一个关键收获：右边的 `K^TV` 可以写成按时间步递推的状态更新，因此线性注意力还能写成 RNN 形式。这样训练时可以用并行的稠密形式，推理时可以用串行的递推形式，形成“训练高效 + 推理高效”的 duality。[课件: lecture_04.pdf p.5]
- `[00:09:50-00:10:01]` 这一段最后用一句话把后续案例引出来：已经有人把这种很朴素的 linear attention 用到实际模型里，下一段开始讲 Minimax M1 之类的混合方案。

## 概念、符号与推导
- 目标问题：长上下文下，attention 的成本会随着序列长度增长而迅速主导总成本；仅靠基础混合注意力和系统优化未必足够。[课件: lecture_04.pdf p.2][课件: lecture_04.pdf p.3]
- 常见 attention 写法：[课件: lecture_04.pdf p.4]

```text
Q ∈ R^{n×d_k}, K ∈ R^{n×d_k}, V ∈ R^{n×d_v}
Attn(Q, K, V) = ρ(QK^T)V
```

- 老师的关键前提：先“忘掉 softmax”，即把 `ρ` 暂时视为恒等映射。这样才能只讨论矩阵乘法结合律，而不处理按行归一化带来的非线性。
- 复杂度重排：[课件: lecture_04.pdf p.4]

```text
QK^TV = Q(K^TV)
```

- 推导含义：
  1. 原始形式的高成本来自 `QK^T` 的 all-to-all 交互，复杂度随 `n^2` 增长。
  2. 重排后，主要代价转移到 `K^TV` 与后续乘法上，依赖项从 `n^2` 变成和 `n d_k d_v` 同阶的线性项。
  3. 老师强调这一步“很傻，但很重要”，因为它是后续一系列线性时间 attention 方案的共同起点。[课件: lecture_04.pdf p.4]
- 递推形式与 duality：[课件: lecture_04.pdf p.5]

```text
S_t = S_{t-1} + k_t v_t^T
y_t = q_t^T S_t
```

- 这里的解释顺序是：先有并行的线性 attention 重排，再把 `K^TV` 写成从左到右的状态累计，最后得到“训练用并行形式、推理用递推形式”的双重视角。[课件: lecture_04.pdf p.5]

## 例子与课堂提示
- 长上下文需求的例子：老师提到 agent 场景需要把很多内容都放进上下文，说明“更长上下文”不是抽象追求，而是实际工作负载在推着模型演化。[课件: lecture_04.pdf p.2]
- `global attention 每八层才出现一次` 是老师用来解释“local + global 混合”如何控成本的课堂化例子，服务于“基础工具箱并非无效，但可能还不够激进”这个判断。
- flash attention 被老师用来提醒一个容易忽略的点：只盯着线性还是二次不够，系统实现和常数因子也能带来数量级上很重要的收益。[课件: lecture_04.pdf p.3]
- “没人把隐藏维做到一百万”这句口头判断服务于复杂度直觉：把依赖从 `n^2` 换到 `d_k,d_v` 相关项，通常是值得的，因为真正大的维度是上下文长度而不是隐藏维。
- 这一段的潜台词是：线性注意力的第一步本身就是有损的，因为 softmax 被先拿掉了；老师在本段还没展开这个代价，后面问答里才明确点出。

### 00:10:01-00:19:57

## 本段在整讲中的作用
- 这一段把上一段的“线性注意力起点”推进成几类已经在真实模型中落地的混合架构，核心目的是回答两个问题：线性 attention 是否真能用，以及怎样在保留线性推理优势的同时提升表达能力。[课件: lecture_04.pdf p.6][课件: lecture_04.pdf p.7][课件: lecture_04.pdf p.8][课件: lecture_04.pdf p.9][课件: lecture_04.pdf p.10][课件: lecture_04.pdf p.11]

## 教学展开
- `[00:10:01-00:11:12]` 老师先给第一个落地例子：Minimax M1 采用 `7:1` 混合，即七层 linear attention 配一层 full softmax attention。老师的判断是，这样的结构在性能上已经相当强，而且随着上下文增长，成本增长也比纯全注意力温和得多。但老师同时明确说，到目前为止，真正“纯线性时间” attention 在大规模上还没有被完全证明可行，所以接下来讲的都还是 hybrid。[课件: lecture_04.pdf p.6]
- `[00:11:12-00:13:18]` 接着老师把话题从“能不能用”转到“能不能更强”。他先回到 linear attention 的 RNN 递推式，再加一个只依赖当前输入 `x_t` 的门 `γ_t`，让状态是否保留由门控决定。这就是他用来解释 Mamba-2 的方式：从机制上看，它可以被看成线性注意力加输入依赖门控后的扩展。[课件: lecture_04.pdf p.7]
- `[00:13:18-00:14:16]` 老师强调，`γ_t` 不是状态依赖项，因此仍能维持 parallel form 和 recurrent form 之间的 duality。训练时可并行，推理时可递推，所以 Mamba-2 继承了线性注意力那套“训练/推理双视角”的好处。[课件: lecture_04.pdf p.7]
- `[00:13:26-00:14:16]` 紧接着给出第二个模型级例子：Nemotron-3 把 Mamba-2 当作轻量层，与偶尔出现的全 attention 层交替，用以平衡推理成本与表达能力。老师的总结是，它在开放模型里已经展示出不错性能和大上下文吞吐。[课件: lecture_04.pdf p.8]
- `[00:14:16-00:18:21]` 再往前一步，老师讨论 gated delta net。原则上，只要递推中的额外项都只依赖输入、不依赖状态，就还能保住 duality。gated delta net 在 Mamba-2 基础上再加入一个 `β_t`，既可以控制是否把当前输入写入状态，也可以通过 `I-β_t k_t k_t^T` 近似“擦除”当前 key 方向上的旧信息。老师把它类比为带遗忘/写入门的 LSTM 思路，并指出这种更新在 fast weight programming、test-time training、某些最小二乘型元学习问题里都被以不同形式“重新发明”过。[课件: lecture_04.pdf p.9]
- `[00:18:21-00:19:57]` 最后，老师用 Qwen 3.5 / Qwen Next 作为 gated delta net 的现实例子，并回到一个更经验化的判断：少量混合层时，性能损失很小；随着非 full-attention 层比例继续升高，长上下文任务和 QA 等评测会逐步下降；走到纯 RNN 端点时，性能退化会很明显。[课件: lecture_04.pdf p.10][课件: lecture_04.pdf p.11]

## 概念、符号与推导
- Minimax M1 的结构结论：`7 linear : 1 full attention`，属于明确的混合架构，而不是纯线性 attention。[课件: lecture_04.pdf p.6]
- Mamba-2 的老师版机制解释：[课件: lecture_04.pdf p.7]

```text
Linear attention:
S_t = S_{t-1} + k_t v_t^T
y_t = q_t^T S_t

Mamba-2:
S_t = γ_t S_{t-1} + k_t v_t^T
y_t = q_t^T S_t + v_t^T D
γ_t = f(x_t)
```

- 推导重点不是完整论文证明，而是三步直觉：
  1. 线性注意力的问题是状态总被无条件往后传。
  2. 引入 `γ_t` 后，可以控制“保留多少旧状态”。
  3. 因为 `γ_t` 只依赖 `x_t`，不是状态依赖项，所以并行/递推 duality 还在。
- 老师对 `v_t^T D` 的说明：它更像输出端的 residual 改造，不是状态更新机制的核心论证，但为完整起见被写进公式。[课件: lecture_04.pdf p.7]
- gated delta net：[课件: lecture_04.pdf p.9]

```text
S_t = γ_t (I - β_t k_t k_t^T) S_{t-1} + β_t k_t v_t^T
y_t = q_t^T S_t
γ_t = f(x_t), β_t = f(x_t)
```

- 这里的符号解释：
  1. `β_t=0` 时，可理解为“不写入当前输入”的 no-input gate。
  2. `I-β_t k_t k_t^T` 近似表示把状态中与当前 key 方向相近的内容投影掉，从而给新信息腾地方。
  3. 老师明确说“投影器”只是近似直觉，因为并没有做单位化等严格处理。
- 混合比例的经验结论：低 hybrid ratio 时损失不大，但随着 recurrent/SSM 层比例升高，性能下降越来越明显；尤其纯 RNN 端点会明显退化。[课件: lecture_04.pdf p.11]

  1. indexer 仍需看全体位置，严格说不是线性时间；

- `[00:42:34-00:43:20]` 接着老师点出 MoE 最难的地方：训练时也必须保持稀疏激活，否则计算就失去意义；但一旦训练时只看被激活的一个或几个专家，就出现“没被选中的专家到底会不会更好”这一 bandit/RL 味道很强的问题。

- `[00:44:31-00:45:33]` 老师再一次强调 DeepSeek 系列的重要性：它们不仅做出强模型，还在 earlier papers 里做了大量消融，把 dense layer、hash routing、switch router 等设计选择的差异讲清楚，因此很值得读。[课件: lecture_04.pdf p.22][课件: lecture_04.pdf p.23]
- `[00:45:33-00:47:23]` 接下来老师回答“为什么 MoE 没有更早普及”。核心原因有两类：第一，基础设施复杂，尤其多机并行和路由通信不容易做好；第二，训练目标带有很强启发式，而且可能不稳定。老师还顺手提到，用 MoE 去替换 attention heads 也有人试，但远没有替换 FFN 常见，难度也更高。[课件: lecture_04.pdf p.24][课件: lecture_04.pdf p.25]

## 概念、符号与推导
- 本段无公式推导。
- 关键概念一：expert parallel
  指把不同 expert 放在不同设备上，通过路由把 token 对应的 activation 送往专家所在设备，以获得额外并行维度。
- 关键概念二：训练时稀疏性
  MoE 的核心前提不是“推理时稀疏，训练时稠密”，而是训练时也要稀疏，否则 FLOPs 优势消失；这正是训练难点的来源。
- 关键概念三：token-level routing
  主流做法是每个 token 单独选专家，而不是句子级、批次级或任务级路由。
- 关键概念四：三维设计空间

```text
MoE design space:
1. Routing function
2. Expert sizes
3. Training objectives
```

- 老师在本段没有展开 expert size 和 training objectives 的细节，只是先用它们做后续章节的目录。

### 00:49:53-00:59:51

## 本段在整讲中的作用
- 这一段开始展开 MoE 设计空间中的第一项：routing function。老师从“有哪些路由思路”一路讲到“为什么 TopK 成为现实共识”，再补上 shared experts 与 fine-grained experts 这些近年的结构变体。

## 教学展开
- `[00:49:53-00:50:32]` 老师先讲最常见的路由器：给每个 expert 一个方向向量，对输入做一个很小的线性投影或内积打分，然后选得分最高的一个或若干个 expert。这就是 classic TopK router，也是 Switch Transformer、GShard、Grok、Mixtral、DBRX、DeepSeek 等模型的共同主线。
- `[00:50:36-00:51:04]` 然后老师提到一个看似反直觉的事实：并不一定非得学出路由器。很多论文表明，直接把输入哈希到不同专家也能有收益，虽然通常不如 TopK，但常被拿来当 baseline。
- `[00:51:05-00:52:57]` 接下来老师补两个“不太常用但概念上很自然”的方案。第一是 RL/bandit 路由：把选专家看成 bandit 或 policy learning 问题，这在理论上很顺，但训练开销和随机性太大。第二是全局线性分配：先算 token 到 expert 的成对分数，再整体求最优匹配。它在一些论文里有效，但规模代价太高，尚未成为大模型标准做法。
- `[00:52:57-00:54:21]` 于是老师回到现实共识：TopK routing。具体做法是，对输入做一个轻量前馈或线性映射，算出输入与专家权重之间的分数，再对这些分数做 softmax/TopK，选中的门值控制哪些 experts 被激活。老师特别提醒，这个模式和前面 DSA 的 TopK 选择非常像，因此要把它认成一种会反复出现的架构模式。
- `[00:54:21-00:57:01]` 接着讲 DeepSeekMoE 的 shared experts。老师的逻辑是：有些通用处理你希望所有 token 都做，不想完全交给条件路由；于是把原来一些大 experts 切成更细的 chunks，其中有少数 shared experts 始终开启、跳过路由，其余 routed experts 继续由 TopK 选择。这样通用能力与专门化能力可以更好分工。
- `[00:55:45-00:57:01]` 老师借 DeepSeek 的消融强调两点：更细粒度地分 expert 常常更好；加入 shared expert 在 DeepSeek 结果里通常也有收益，尤其在一些问答类任务上明显。
- `[00:57:01-00:58:00]` 但老师也补上边界：OlMoE 的受控研究并不完全认同 shared experts 一定有用，不过它同样支持“更多、更细粒度专家”通常有效。因此共享专家不是绝对定律，但 fine-grained experts 已经很 battle-tested。
- `[00:58:00-00:59:51]` 最后老师总结最近设计趋势：早期 Google、Mixtral、DBRX、Grok 是第一波，DeepSeek v1 引入 fine-grained + shared 设计后，Qwen、GLM 等很多现代模型都沿着这条线走；随后他把话题过渡到训练问题：既然训练时不能激活所有 experts，那不连续的稀疏门控该怎么学？

## 概念、符号与推导
- 本段没有完整微分推导，但给出了 TopK router 的结构化描述：

```text
输入 u
-> 轻量 router 计算每个 expert 的分数
-> 对分数做 softmax / TopK
-> 选中的 gates 控制 experts 激活
-> expert 输出与残差一起形成层输出
```

- TopK routing 的关键点：
  1. gate 的学习通常只是“输入与专家权重做内积”，非常轻量；
  2. `k` 的选择因模型而异，Switch 常见 `k=1`，GShard/Mixtral 常见 `k=2`，Qwen/DBRX/DeepSeek 则可更大；
  3. TopK 是 token choice，而不是 expert choice。
- Hash routing：不学习路由，直接通过哈希把输入送到专家，通常作为 baseline。
- RL routing：把选专家看成 bandit/policy 问题，但现实中不是主流。
- Linear assignment routing：全局最优匹配的思想上更干净，但求解昂贵。
- Shared experts：
  1. 部分专家永远激活，不经过 router；
  2. 其余专家仍由 TopK 条件选择；
  3. 设计目的之一是把“所有 token 都需要的通用处理”从 routed experts 中剥离出去。

## 例子与课堂提示
- 老师说 hash routing 也“居然能行”，是在提醒学生：MoE 的收益不全来自很聪明的语义路由，参数稀疏激活本身就很有价值。
- `这和 DSA 很像` 是一个重要课堂提示，说明 TopK 选择不是 MoE 独有 trick，而是通用的“先粗筛、再精算”模式。
- DeepSeek 的 shared experts 例子服务于理解“通用处理 + 条件专门化”的分工，而不是说所有 MoE 都必须有 shared experts。
- OlMoE 对 shared experts 的否定性结论，是老师主动给出的边界条件，防止学生把 DeepSeek 的经验误当成无条件定律。
- 关于 shared experts 的并行化问题，老师顺手提醒：shared expert 始终开启，所以它本身不会带来并行节省；如果想省通信，可以复制 shared experts，以显存换通信。

参考答案：因为它结构简单、实现轻量，而且配合一套经验性训练技巧后已经能在大规模模型上稳定工作。

### 00:59:51-01:09:48

## 本段在整讲中的作用
- 这一段对应 MoE 设计空间中的第三项：training objectives。老师的重点是说明，训练 MoE 的真正关键不在于“怎么精确求可微路由”，而在于“怎么靠启发式负载均衡避免 expert collapse”。[课件: lecture_04.pdf p.36][课件: lecture_04.pdf p.37][课件: lecture_04.pdf p.38][课件: lecture_04.pdf p.39][课件: lecture_04.pdf p.40][课件: lecture_04.pdf p.41][课件: lecture_04.pdf p.42][课件: lecture_04.pdf p.43]

## 教学展开
- `[00:59:51-01:00:33]` 老师先给出总判断：RL 和随机扰动这些方案“知道一下很有用”，但现实里不常用。真正让 MoE 工作起来的，是一串最后被验证有效的启发式。
- `[01:00:04-01:00:33]` 第一类方案是 RL。老师引用 Clark 2020 说明：REINFORCE 一类方法确实可行，但因为梯度方差和实现复杂度，效果并没有好到值得压过更简单的方法。[课件: lecture_04.pdf p.37]
- `[01:00:33-01:02:25]` 第二类方案是 stochastic approximation。老师回到 Shazeer 等人的早期做法：不在训练时直接做硬 TopK，而是在路由分数上注入与输入尺度相关的噪声，再配合 TopK 和 softmax。它的目的不是从第一性原理推导可微路由，而是给相近专家提供“打破平局、更多探索”的机会，让真正有用的专家逐步被强化。[课件: lecture_04.pdf p.38]
- `[01:02:25-01:03:13]` 老师再补一个相关变体：Fedus 2022 里做过均匀乘法扰动，希望让专家更 robust；但后续工作表明，很多随机探索技巧并非必需，甚至去掉以后稳定性和最终质量可能更好。[课件: lecture_04.pdf p.39]
- `[01:03:13-01:04:13]` 真正主角因此转向 heuristic balancing losses。老师指出，如果你只做普通梯度下降，早期被选中的 expert 会得到更多信号，于是更常被选，再得到更多信号，形成 rich-get-richer，最后出现 expert collapse 或 starvation。
- `[01:04:13-01:05:56]` Switch Transformer 的做法是加一个辅助平衡损失。老师没有从第一性原理推导它，而是建议直接看梯度：`F_i` 是分给 expert `i` 的 token 比例，`P_i` 是 router 分给它的概率质量，两者相乘后形成的项会让“越热门的 expert 受到越强的下压梯度”，从而抑制一路赢到头的专家。[课件: lecture_04.pdf p.40]
- `[01:06:00-01:07:12]` 老师据此“重建” DeepSeek v1/v2 的训练方式：主损失照常回传，把 TopK 的各种不可导和 counterfactual 问题基本先忽略掉；与此同时加入 per-expert balancing。更进一步，DeepSeek 还会做 per-device balancing，让不同设备上的专家负载也尽量均衡，以提高系统利用率。[课件: lecture_04.pdf p.41]
- `[01:07:12-01:07:53]` 对于 DeepSeek v3，老师补充了 per-expert bias 和 online learning 的变体，论文称之为“aux-loss-free balancing”，但老师提醒这并不是真的完全摆脱辅助损失，只是减少了丑陋程度。[课件: lecture_04.pdf p.42]
- `[01:07:53-01:09:48]` 最后老师用 OlMoE 的消融强调平衡损失不能轻易删：去掉 load balancing 后，训练曲线明显变坏，大部分 token 只落到极少数专家上，相当于白白浪费了大量参数。于是，本段最终结论是：MoE 训练之所以能工作，很大程度上就是“正强化”与“负载均衡抑制”两种力量互相抵消后的结果。[课件: lecture_04.pdf p.43]

## 概念、符号与推导
- RL 路由：理论上最像“正确解”，但不是实践主流。[课件: lecture_04.pdf p.37]
- 随机扰动路由：在路由分数 `H` 上加噪声，再走 TopK + softmax，目标是增加探索与鲁棒性。[课件: lecture_04.pdf p.38][课件: lecture_04.pdf p.39]
- 核心启发式是 load balancing loss。老师给出的符号解释：[课件: lecture_04.pdf p.40]
  1. `F_i`：分配给 expert `i` 的 token 比例。
  2. `P_i`：router 给 expert `i` 的概率质量。
  3. 将二者耦合进辅助损失后，热门专家会得到更强的负梯度，从而被“往下压”。
- 老师建议的理解方式不是死记公式，而是看梯度作用：

```text
被更多 token 使用的 expert
-> 对应更大的 dispatch fraction F_i
-> 在 balancing loss 下得到更强的下压
-> 减少继续垄断路由的趋势
```

- DeepSeek v1/v2 训练配方：
  1. 主损失正常回传；
  2. 加 per-expert balancing；
  3. 再加 per-device balancing 以优化设备利用率。[课件: lecture_04.pdf p.41]
- DeepSeek v3 变体：通过 per-expert bias 和 online update 做“更少辅助损失”的均衡，但极端不平衡时仍需要某些辅助约束。[课件: lecture_04.pdf p.42]

## 例子与课堂提示
- 老师说“如果只做普通梯度下降，会 rich gets richer”，这是本段最重要的课堂直觉，比记住公式本身更重要。
- `看梯度而不是看公式长相` 是老师给学生的明确学习方法：Switch 的平衡损失从第一眼看未必优雅，但从梯度方向看就很合理。
- DeepSeek v1/v2 的系统级平衡说明了一个容易忽略的点：MoE 的训练目标不仅服务于建模，也直接服务于多设备利用率。
- OlMoE 去掉 balancing loss 后只剩两个热门专家承担大部分 token，是老师用来证明“这些启发式不是装饰品”的关键例子。
- 本段的边界很明确：老师并没有说这些启发式是理论最优，只是说它们目前在实践中非常有效。

### 01:09:51-01:19:50

## 本段在整讲中的作用
- 这一段把 MoE 从“会训练”继续推进到“能在真实系统中部署”，依次讲 expert specialization 的边界、系统并行与稀疏矩阵乘法、通信优化、历史上的随机性问题，以及 router 稳定性和微调过拟合问题。

## 教学展开
- `[01:09:51-01:10:16]` 老师先做一个小结：TopK 加辅助损失这种 nondifferentiable routing trick，不只用在 MoE，也用在 DSA、H-Nets 等别的架构里，因此这类“离散选择 + 额外损失”的范式未来还会反复出现。
- `[01:10:20-01:11:03]` 有同学问 experts 是否会发展出明显的语义分工。老师回答得很克制：有些论文能可视化出不同 expert 更常接 punctuation、特殊符号、非英语字符等，但这离“医学专家”“法律专家”那种人类语义标签还很远，更多只是输入模式上的偏好而非高级语义模块。
- `[01:11:06-01:11:38]` 关于 per-expert 和 per-device balancing 的关系，老师说理论上前者若被强制到完全均匀，可能也会带来设备均衡；但实际不会把 per-expert loss 开得那么大，因为过度均匀会伤训练动态，所以设备级还要单独再扶一下。
- `[01:11:39-01:13:52]` 接着进入系统侧。老师回顾常规并行：data parallel 和 model parallel 各有极限；MoE 再额外提供一个 expert parallel 轴。更进一步，由于一个 GPU 上常常有多个 experts，与其做很多小矩阵乘法，不如利用 block-diagonal 和更一般的 structured sparsity，把多个 experts 的计算组织成对硬件更友好的稀疏矩阵乘法。
- `[01:13:55-01:15:02]` 然后老师回应前面提过的通信问题：如果 activation 要跨设备送专家，通信会贵。Nemotron-3 的一个想法是先把 residual stream 下投影到更低维，再传给 routed experts，这样能显著减少通信负担，同时不必把整个模型隐藏维都变小。
- `[01:15:08-01:16:28]` 老师接着讲一个历史上很有趣但近年已大幅缓解的问题：MoE 的额外随机性。旧式基础设施里，若某个 expert 过热、队列过长，系统会直接丢 token，返回零向量继续算。这样别人的请求可能把你的 token 从队列里挤掉，导致额外随机性。现在像 MegaBlocks 这样的框架已经基本解决这个问题。
- `[01:16:36-01:18:11]` 再往下是稳定性。老师提醒过“指数和除法都危险”，而 router 里又多引入了一次 softmax，所以 router 很容易成为数值稳定性的危险区。历史经验是：router 常用 Float32，必要时再加 z-loss 来抑制不稳定；OlMoE 的消融也显示 router z-loss 会让训练曲线更平稳。
- `[01:18:11-01:19:40]` 最后是 fine-tuning。老师指出 sparse MoE 在小数据微调时特别容易过拟合，因为专家参数太多、太容易记住数据。常见缓解方式是只微调 attention 或非-MoE MLP；如果数据很多，也可以靠“大量数据重训式微调”来压住泛化差距。

## 概念、符号与推导
- 本段无公式推导。
- expert specialization 的边界：路由器通常只是一次简单内积或线性打分，因此 experts 更多是对输入模式做粗分，而不是高层语义学科专家。
- MoE 的系统并行图景：

```text
已有并行轴：data parallel + model parallel
MoE 新增并行轴：expert parallel
硬件友好实现：structured sparse matrix multiply
```

- 通信优化思路：
  1. routed experts 需要跨设备通信；
  2. 若先下投影 activation，再通信，可减少带宽压力；
  3. 这是用更小的 routed 表示换取系统效率。
- 稳定性处理：
  1. router softmax 是数值风险点；
  2. 可仅把 router 提到 Float32；
  3. 必要时再加 z-loss。[课件: lecture_04.pdf p.48][课件: lecture_04.pdf p.49]
- 微调问题：稀疏 MoE 的高参数量会扩大 train/val gap，因此部分参数微调或超大数据微调更常见。[课件: lecture_04.pdf p.50]

## 例子与课堂提示
- punctuation、非英语字符更偏向某些 experts，是老师用来打破“专家一定对应清晰语义领域”这个直觉误解的例子。
- `不要把 per-expert loss 调到真均匀` 是很重要的课堂提示，说明“均衡”也是有度的，过强约束会损害学习动力学。
- structured sparse MM 的解释服务于一个系统侧判断：MoE 不是只靠建模技巧成功，而是与硬件支持形成了共设计关系。
- “别人请求把你的 token 挤出 expert 队列”是老师专门给的生动例子，用来说明历史上 MoE 服务为何会比 dense 模型多一层随机性。
- 微调部分的教训很直接：MoE 并不天然适合小数据 SFT，如果数据不够大，少动 experts 往往更稳。

1. 老师为什么说 experts 通常不是“医学专家”“法律专家”？
参考答案：因为主流 router 很简单，更多只是把不同输入模式分到不同 experts，而不是学出高层语义任务分工。

参考答案：因为如果只靠 per-expert balancing，未必愿意把它压到完全均匀；而设备利用率又足够重要，所以要额外施加设备级均衡。

参考答案：因为 router 里有 softmax，数值上容易不稳定；Float32 和 z-loss 都是为控制这一风险。

### 01:19:50-01:26:16

## 本段在整讲中的作用
- 这一段完成 MoE 收尾：先介绍 upcycling 这一类训练捷径，再用 DeepSeek v1/v2/v3 做整套 MoE 设计的纵向复盘，最后补上 MLA、MTP 这些与 DeepSeek v3 相伴的系统化技巧，并给出全讲总结。[课件: lecture_04.pdf p.51][课件: lecture_04.pdf p.52][课件: lecture_04.pdf p.53][课件: lecture_04.pdf p.54][课件: lecture_04.pdf p.55][课件: lecture_04.pdf p.56][课件: lecture_04.pdf p.57][课件: lecture_04.pdf p.58][课件: lecture_04.pdf p.59][课件: lecture_04.pdf p.60]

## 教学展开
- `[01:19:50-01:22:05]` 老师先讲 upcycling。核心想法是：如果已经训练好了一个 dense 模型，也许不必从零开始训 MoE，而是直接复制它的 MLP，扩成多个 experts，再随机初始化 router，继续训练，让专家在随机路由和继续训练中逐步分化。老师说这种方法在早期论文和一些中国模型上都验证过，例如 MiniCPM、Qwen MoE 都展示过“在已有 dense 底座上相对便宜地拿到额外收益”的结果；不过到了现在，这条路不再流行，因为大家更倾向直接从头训大型 MoE。[课件: lecture_04.pdf p.51][课件: lecture_04.pdf p.52][课件: lecture_04.pdf p.53]
- `[01:22:12-01:23:50]` 然后老师用 DeepSeek v1/v2/v3 做路线复盘。v1 已经具备现代 MoE 的原型：shared + fine-grained experts、标准 TopK routing、专家与设备级辅助平衡。v2 在此基础上大幅放大规模，并加入 device routing 与 communication balancing，体现“建模与系统要一起设计”的思想。v3 则继续保留 shared/fine-grained 结构，同时改用新的 balancing 方案与 `sigmoid + softmax` 权重方式。[课件: lecture_04.pdf p.54][课件: lecture_04.pdf p.55][课件: lecture_04.pdf p.56]
- `[01:23:55-01:24:59]` 老师接着介绍 DeepSeek v3 周边的 MLA。基本思路是，不直接把隐藏态投成 Q、K、V，而是先压成更低维的 latent `c`，再由 `c` 生成 Q、K、V。这样做的直接系统收益是 KV cache 不必存所有 K、V，只需存较小的 latent 表示，于是缓存开销更低。[课件: lecture_04.pdf p.57][课件: lecture_04.pdf p.58]
- `[01:24:42-01:25:05]` 但 MLA 不是没有代价。老师指出它和 RoPE 的缓存方式会冲突，因此需要保留一小部分非 latent 的 key 维度专门承载可旋转的位置编码，这个技巧老师点到为止，没有深入公式细节。[课件: lecture_04.pdf p.58]
- `[01:25:05-01:25:38]` 最后一个配套技巧是 MTP，多 token prediction。老师给了两层理由：统计上，预测多个未来 token 也许能帮助模型更好建模未来；系统上，它等价于把 speculative decoding 的某些能力直接内建进模型里，从而可能加速解码。不过老师也提醒 DeepSeek v3 里实际上只做了一步 ahead 的 MTP。[课件: lecture_04.pdf p.59]
- `[01:25:41-01:26:16]` 课程结束前，老师把全讲总结压成三点：MoE 利用稀疏性让“参数多于实际计算量”；离散路由听起来很难，但 TopK 加启发式已在大规模上有效；现在的经验已经足够充分，MoE 明显是会长期存在的主流设计。[课件: lecture_04.pdf p.60]

## 概念、符号与推导
- upcycling：
  1. 从已训练 dense 模型出发；
  2. 复制原有 MLP 形成多个 experts；
  3. router 随机初始化；
  4. 继续训练，让 experts 因路由随机性和梯度信号逐渐分化。[课件: lecture_04.pdf p.51]
- DeepSeek 三代路线：
  1. v1：shared + fine-grained experts，标准 TopK，aux-loss balancing。[课件: lecture_04.pdf p.54]
  2. v2：更多 experts、device routing、communication balancing。[课件: lecture_04.pdf p.55]
  3. v3：shared/fine-grained 继续保留，改进 balancing，并采用 `sigmoid + softmax` 路由权重。[课件: lecture_04.pdf p.56]
- MLA 的老师版公式直觉：[课件: lecture_04.pdf p.57][课件: lecture_04.pdf p.58]

```text
h
-> 先映射到低维 latent c
-> 再由 c 生成 Q, K, V

收益：KV cache 存 c，而不是完整 K/V
代价：需要处理与 RoPE 的兼容问题
```

- MTP：
  1. 不是只预测下一个 token；
  2. 而是让轻量模块预测多个未来 token；
  3. 统计上可能改善建模，系统上可内建 speculative decoding 优势。[课件: lecture_04.pdf p.59]

## 例子与课堂提示
- MiniCPM、Qwen MoE 被老师拿来证明 upcycling 不是空想，而是曾在真实模型上带来“近乎白赚”的提升。[课件: lecture_04.pdf p.52][课件: lecture_04.pdf p.53]
- 老师用 DeepSeek 三代纵向演化来教一种读论文的方法：不要只记单个 trick，而要看一个模型家族如何把路由、平衡、通信和缓存问题逐年拼起来。
- MLA 部分的课堂提示是：现代高性能模型设计往往不是单点技巧，而是“MoE + KV cache 优化 + 通信优化 + 推理解码技巧”一整套系统工程。
- 对 MTP，老师既给建模理由也给系统理由，提醒学生不要把架构技巧只看成统计建模或只看成部署优化，它经常同时服务两头。
- 全讲总结里“离散路由听起来很难，但简单方法已足够有效”是最终结论边界：不是说问题从理论上已被完全解决，而是工程上已经被驯服到足够可用。

## 本段掌握检查
1. upcycling 的基本做法是什么？
参考答案：把一个已训练的 dense 模型的 MLP 复制成多个 experts，随机初始化 router，再继续训练，让 experts 逐渐分化。

2. 为什么 upcycling 现在不如以前常见？
参考答案：因为如今大家更倾向直接从头训练大型 MoE，而不是先训练 dense 模型再转换。

3. DeepSeek v2 相比 v1 新增了哪些更偏系统侧的设计？
参考答案：新增了 device routing 和 communication balancing 等机制，更直接地把系统利用率纳入训练设计。

4. MLA 为什么能减小 KV cache？
参考答案：因为它先把隐藏态压成较低维 latent `c`，缓存时只需保存 `c`，而不必保存完整的 K、V。

5. MTP 除了统计建模理由，还有什么系统收益？
参考答案：它相当于把 speculative decoding 的一部分能力内建进模型，因此可能提升解码速度。
