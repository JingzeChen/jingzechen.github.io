## 学习目标
- 建立 GPU 的基础心智模型：SM、warp、shared/global memory、SIMT。
- 理解为什么现代 GPU 优化首先是 memory movement 问题，而不是单纯增加 FLOPs。
- 掌握第二部分的六类技巧及其共同目标：减少全局读写、提高局部复用、避免空转。
- 能用这些概念解释 FlashAttention 为什么快，而不是只记住“它是一个更快的 attention kernel”。

## 需要的先修知识
- 基本矩阵乘法与 attention 计算流程。
- 反向传播中 activation 与 gradient 的关系。
- 对并行执行、线程、缓存/内存层级有初步直觉即可；老师在本讲从头搭建术语。

## 老师的教学主线
- 先说明 compute 对 LLM scaling 的重要性，以及 Dennard scaling 失效后为什么必须转向 GPU 并行扩展。
- 再建立 GPU/TPU 的硬件与执行模型，尤其强调 memory hierarchy 才是后续优化的根。
- 然后用 roofline model 把“为什么会慢”概括成 memory-bound 与 compute-bound 的区分。
- 接着依次讲 control divergence、low precision、fusion、recomputation、coalescing、tiling，把所有技巧都压回“少搬数据、把数据搬对地方”。
- 最后用 FlashAttention 证明这些技巧不是零散 trivia，而是能系统性地产生重要算法收益。

## 核心概念与依赖关系
- GPU 心智模型依赖三组对象：计算组织、内存层级、执行约束。
- 计算组织包括 SM、thread、block、warp；内存层级包括 register、shared/L1、L2、global/HBM、host memory；执行约束核心是 SIMT。
- 性能分析依赖 roofline：先分清 memory-bound 还是 compute-bound，再决定该减少读写还是提升算子利用率。
- 六类技巧分别处理不同形式的浪费：control divergence 处理空转，low precision 处理位宽，fusion 处理来回搬运，recomputation 处理存储压力，coalescing 处理读模式，tiling 处理局部复用。
- FlashAttention 把 tiling、fusion、online softmax、recomputation 组合起来，目标始终是少访问 HBM。

## 关键推导、例子与结论边界
- ReLU 的 float32/float16 字节核算说明：减少位宽会直接减少 memory movement，但老师口头纠正这是 `bytes/FLOP`，不是正向的 arithmetic intensity。
- 三层 sigmoid 例子给出 recomputation 的直观收益：memory access 从 8 次降到 5 次，说明 GPU 上经常值得“多算少存”。
- tiling 的关键定量结论：naive matmul 每个输入从 global memory 读 `N` 次；tile 大小为 `T` 时降到 `N/T` 次，global memory 读写量减少 `T` 倍。[课件: lecture_05.pdf p.42]
- `1792 -> 1793` 的 wave quantization 例子说明：性能断崖可能来自 tile 数跨过 SM 数量边界，而不是数学定义发生变化。[课件: lecture_05.pdf p.48]
- FlashAttention 在本讲只讲 forward 核心思路和 backward 的重算直觉，不展开完整 backward 推导。

## 易错点与待核对项
- 不要把 shared memory、L1 cache、global memory 混成一个概念；它们在物理位置、可编程性和代价上不同。
- 不要把“32 的倍数更快”机械记成咒语；真正原因是 burst、warp、tile、alignment、SM 波次。
- 不要把“低精度更快”理解成“所有操作都该量化”；老师反复强调收益最大的还是 matmul。
- DRAM burst 图的电路级细节、某些字幕缺字的学生问题、以及 FlashAttention 图究竟来自第 2 版还是第 3 版，仍需结合视频/原论文核对。[需回听]

## 掌握标准
- 能自行解释 thread、block、warp、shared memory、coalesced access、tiling、wave quantization。
- 能遇到慢算子时先判断 memory-bound 还是 compute-bound，而不是只看 FLOPs。
- 能说明为什么 padding、alignment、tile size、SM 数量会共同影响 matmul 吞吐。
- 能口头重建 FlashAttention：tile 化 matmul、online softmax、尽量 fusion、backward 重算。

## 复习顺序
- 先复习第一部分的硬件模型，特别是 warp、shared memory、global memory 的边界。
- 再复习 roofline 与“memory 是主线”的总判断。
- 然后按“少分支 -> 少字节 -> 少往返 -> 少存储 -> 读对齐 -> 做 tiling”的顺序过六类技巧。
- 最后回看 FlashAttention，把每个技巧在 attention 里的落点一一对应起来。

### 00:10:03-00:20:02
## 本段在整讲中的作用
- 这一段从“GPU 为什么能扩展”进一步落到“GPU 到底由什么组成、怎么执行、怎么访存”，是整讲后半部分一切优化技巧的前置硬件模型。
- 老师在这里建立三层核心对象：SM/内存层级、thread/block/warp、寄存器到全局内存的访存边界；后面的 coalescing、tiling、FlashAttention 都依赖这套词汇。

## 教学展开
- [00:10:03-00:10:22] 先把 SM 近似看成“核心”：A100 上有大量 SM，每个都能独立执行不同 job，并共享外部 global memory。
- [00:10:22-00:12:35] 立刻强调真正重要的不只是 compute，而是 memory。老师依次区分 L1/shared、L2、register、global/HBM，并强调 L1/shared 约 20-30 cycles，global memory 约慢一个数量级；“显存 144GB”说的是 global memory，不是 shared memory。
- [00:11:40-00:12:35] 用物理位置解释速度：global memory 在芯片外，L2 在 die 上，L1/shared 在 SM 内部，因此距离近、延迟低；但 shared memory 非常昂贵、耗电，不能无限堆。
- [00:12:54-00:13:13] 回答学生：cache 是自动缓存最近访问数据，shared memory 是程序员可显式读写的可编程存储。
- [00:13:25-00:15:21] 进入执行模型：thread 是并行做工的轻量执行体；GPU 采用 SIMT，同一批线程执行同样指令、输入不同；block 是一组 thread，保证落在单个 SM 上并共享该 SM 的 shared memory；warp 是 32 个连续编号线程构成的调度单位。
- [00:15:22-00:15:41] 回答“到底是谁执行同样指令”：严格说是 warp 内线程一起执行，调度器决定下一个运行哪个 warp。
- [00:15:48-00:17:18] 进入 memory model：device code 可访问 register、local memory、shared memory、global memory、constant memory，以及必要时与 host memory 交换。老师反复强调，一旦跨出 shared memory，代价就会显著增加。
- [00:17:18-00:19:17] 用两页侧线讲 TPU：高层结构与 GPU 相似，都是轻控制、快 matmul 单元、快本地内存加慢大内存；区别在于 TPU 更简单、更偏机器学习专用，网络互联差异更大。

## 概念、符号与推导
- `SM`：streaming multiprocessor，可近似看成 GPU 上独立执行 blocks 的计算单元。
- `register / L1 / shared / L2 / global memory`：由近到远、由快到慢、由贵到便宜的层级；老师要学生从“物理位置 + 编程可见性”两方面理解它们。
- `SIMT`：single instruction, multiple threads；同一 warp 内线程执行相同指令，但输入不同。
- `thread`：执行工作最小单元。
- `block`：一组 threads，保证在单个 SM 上运行，因此能共享 shared memory。
- `warp`：32 个连续编号线程组成的调度单位；真正一起走指令的是 warp。
- `host memory`：CPU 侧内存；GPU 容量不够时可以交换，但代价高。
- 本段无公式推导。

## 例子与课堂提示
- 老师把 “H200 有 144GB memory” 拆开解释，是在纠正常见误解：工程里所谓 GPU memory 默认是 global memory，不是所有层级总和。
- 用“为什么不直接全做成 shared memory”提醒学生，快内存的代价是面积、功耗和成本，因此优化本质上是在尊重层级，而不是幻想消灭层级。
- 学生追问 shared memory 和 L1 cache 的区别时，老师把“自动缓存”和“可编程显式存储”分开，这是后面理解 tiling 的关键。

## 本段掌握检查
- 为什么 block 在 GPU 编程模型里是个重要对象？
参考答案：因为 block 保证运行在单个 SM 上，因而其中线程可以共享该 SM 的 shared memory。
- warp 和 block 的关系是什么？
参考答案：block 是线程组，warp 是其中按 32 个连续线程划分出来的调度单位；真正锁步执行相同指令的是 warp。
- 为什么老师说离开 shared memory 以后“事情就会慢下来”？
参考答案：因为访问会落到更远、更慢的层级，如 L2 或 global memory，延迟和带宽代价都更高。
- shared memory 和 L1 cache 的关键区别是什么？
参考答案：L1 cache 自动缓存最近访问数据；shared memory 由程序员显式放入、读出和复用。

### 00:20:02-00:30:02
## 本段在整讲中的作用
- 这一段承接 TPU 侧线，把 GPU 与 TPU 的相似和差异说清，然后回到“为什么 GPU 模型这么成功”，为后面所有性能技巧统一出一个结论：现代加速器都围绕 matmul 与 memory hierarchy 设计。
- 它也是第一部分的收尾：先比较芯片，再解释 tensor core、memory wall，最后收束成“GPU 的正确心智模型”。

## 教学展开
- [00:20:02-00:20:53] 先补一句：GPU 和 TPU 的矩阵乘法核心都可以看成 systolic array，因此高层架构相似；但老师对某个典型阵列尺寸问题没有当场给出答案。
- [00:20:24-00:22:23] 指出一个命名陷阱：TPU 把自己的处理器级单元叫 tensor core，GPU 把矩阵乘法专用单元也叫 tensor core，必须靠上下文区分。
- [00:20:53-00:22:23] 用数量对比说明两者风格不同：A100 约有 132 个 SM、528 个矩阵乘法单元；TPU 只有 2 个大单元、8 个矩阵乘法单元。GPU 依赖“更小但更多”的单元，因此更灵活；TPU 依赖“更大但更少”的单元，因此更锁定大 matmul。
- [00:21:47-00:22:03] 用论文中的 batch size sweep 举例：实验停在 64，是因为 TPU 的 tensor core 不接受更小维度的输入，直观说明 TPU 对“大矩阵乘法”的偏好。
- [00:22:42-00:23:51] 回到 GPU 成功的原因：想要更高吞吐就继续加 SM；SIMT 使得编程在概念上是“写一套指令，让很多输入同时跑”；线程又足够轻量，调度器可以快速停一个 warp、换另一个 warp，提高吞吐。
- [00:23:58-00:25:28] 回顾早期 GPU 被黑客化为科学计算设备：最初研究者用可编程 shader 绕出 matmul；而自 V100 起，NVIDIA 直接把矩阵乘法专用硬件做进芯片，matmul 从此成为机器学习里的“特权操作”。
- [00:25:32-00:26:43] 解释 memory wall：FLOPs 增长快于 memory bandwidth，设备互连速度也增长更慢，因此越往后做优化，越会被 memory 和 communication 卡住。
- [00:26:43-00:30:02] 给出第一部分总复盘：GPU 的正确心智模型是“大规模并行 + matmul 尤其快 + compute 比 memory 扩展更快，所以必须尊重 memory hierarchy”；随后回答 V100 之前没有 tensor core、shared memory 与 L1 cache 的区别、以及两者都可能是 SRAM 等问题。

## 概念、符号与推导

## 概念、符号与推导

- `control divergence`：同一 warp 内线程因条件分支走向不同逻辑时，硬件只能串行地把两个分支都走完，另一半线程在各自阶段空等。[课件: lecture_05.pdf p.23]

- `MXFP8`：更细粒度缩放的 FP8 方案；老师强调其核心不是“统一缩小到 8 bit”，而是“按块缩放 + 不同数制分工”。[课件: lecture_05.pdf p.27]

## 本段在整讲中的作用

## 教学展开
- [00:49:55-00:50:13] 先收束 fusion：简单的 pointwise fusion 往往能由编译器自动完成，复杂版才需要手工介入。[课件: lecture_05.pdf p.33]

- [00:54:14-00:54:55] 给出定义：如果一个 warp 中所有线程的访问都落在同一个 burst section 内，这次访问就叫 coalesced。[课件: lecture_05.pdf p.38]

- [00:55:58-00:57:44] 把 coalescing 拉回矩阵：对于 row-major 矩阵，如果线程按列去读，第一次迭代就会跨多个 burst window，等于为了拿一列把大块数据都扫了一遍；如果访问顺序与内存线性顺序对齐，就会快很多。[课件: lecture_05.pdf p.39]

## 概念、符号与推导
- `recomputation`：不保存所有中间激活，而是在需要时局部重算，以减少 memory accesses。[课件: lecture_05.pdf p.34] [课件: lecture_05.pdf p.36]
- 三层 sigmoid 例子中的 memory 计数：
  - 常规保存激活：总计约 8 次读写。[课件: lecture_05.pdf p.35]
  - 丢弃激活、反向重算：总计约 5 次读写，即原来的 5/8。[课件: lecture_05.pdf p.36]
- `burst mode`：DRAM 每次访问不是只给一个值，而是返回一整块连续 bytes。[课件: lecture_05.pdf p.37]
- `coalesced access`：warp 内线程访问落在同一 burst section 内的读取模式。[课件: lecture_05.pdf p.38]
- `tiling`：把大问题切成小 tile，先搬到 shared memory，再在本地反复使用，目的是减少 global memory 读取。[课件: lecture_05.pdf p.40] [课件: lecture_05.pdf p.41]

## 例子与课堂提示
- `sin^2(x) + cos^2(x)` 的 pointwise 图说明：如果不 fusion，会变成 5 次 CUDA kernel 往返；如果 fusion，一次 kernel 就能读一次、算完、写一次。[课件: lecture_05.pdf p.32] [课件: lecture_05.pdf p.33]
- 三层 sigmoid 例子告诉学生：在 compute 充裕而 memory 紧张的时代，丢掉“已经算过的结果”并不是反常识，而可能是最优。
- 4x4 row-major 矩阵按列读取的例子，用非常直观的方式说明“为什么对同一个数学对象，换个遍历方向就可能突然变慢”。
- 老师把 tiling 放在最后，是在暗示它会成为后面解释 matmul 怪图和 FlashAttention 的主武器。

## 本段掌握检查
- 为什么 recomputation 在 GPU 上可能是好主意？
参考答案：因为现代 GPU 常常是 compute 便宜、memory 贵；多算几步能换来更少的读写，总体更快。
- 什么叫 coalesced memory access？
参考答案：同一 warp 的线程访问落在同一个 DRAM burst section 内，从而能高效共享一次读取带来的整块数据。

- tiling 的一句话目标是什么？
参考答案：把数据先搬进 shared memory，在本地多次复用，尽量减少 global memory 访问。[课件: lecture_05.pdf p.40]

## 概念、符号与推导
- naive matmul：每个输入元素从 global memory 读取 `N` 次。[课件: lecture_05.pdf p.42]
- tiled matmul：tile 大小为 `T` 时，每个输入元素从 global memory 读取 `N/T` 次，在 tile 内共享访问 `T` 次。[课件: lecture_05.pdf p.42]
- 结论：global memory 访问量相对 naive 下降一个 `T` 倍因子。[课件: lecture_05.pdf p.42]
- `alignment`：tile 边界与 DRAM burst section 边界对齐时，读取更容易 coalesced；不对齐时需要 padding。[课件: lecture_05.pdf p.44]
- `wave quantization`：tile 总数超过 SM 数量后，多出来的 tile 必须等待下一轮调度，导致周期性吞吐下降。[课件: lecture_05.pdf p.48]
- 本段无额外公式推导。

## 例子与课堂提示
- `256 x 256` 配 `128 x 128` tile 是“整齐世界”，`257 x 257` 则是“多出瘦长边角”的世界；老师用这个对比提醒学生不要只看大 O，而要看边界形状。
- `max-autotune` 的例子说明：框架并不知道唯一正确 tile，大量性能来自搜索而不是单条固定规则。
- Karpathy 把词表从 `50257` pad 到 `50304` 获得 25% 加速，是本段最典型的“数学上只多几十个词，系统上却快很多”的案例。
- `1792 -> 1793` 的掉速展示了第二类非直观现象：问题不只在对齐，还在 tile 总数是否跨过 SM 数量门槛。

## 概念、符号与推导
- `attention` 的计算部件：K、Q、V 相关的矩阵乘法，以及中间的 softmax。[课件: lecture_05.pdf p.51]
- `online softmax`：不等看完整个向量再统一算，而是边扫描边维护当前最大值和累积归一化量；遇到更大元素时，对先前累积做修正。[课件: lecture_05.pdf p.53]
- `HBM`：这里被老师拿来指 global memory 侧的大容量慢内存，是 FlashAttention 想尽量少访问的对象。
- FlashAttention 的组合技巧：
  - matmul 用 tiling；
  - softmax 用 online 形式改写成可分 tile 更新；
  - 前向尽量 fusion；
  - 反向用 recomputation，避免保存 `N^2` 级激活。[课件: lecture_05.pdf p.54]
- 本段无独立公式推导，老师主要做的是算法步骤重组。

## 例子与课堂提示

- FlashAttention 被老师称为“all systems”，是在提醒学生：有些看似算法创新，其实核心收益来自 memory movement 的重写。
