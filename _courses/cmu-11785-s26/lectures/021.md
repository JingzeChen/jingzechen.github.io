## 学习目标
- 理解老师如何把大语言模型训练组织成预训练、评测与 scaling laws、后训练三段流程。
- 理解为什么数据设计、训练阶段切换和奖励设计，和模型规模一样决定最终能力。
- 理解为什么 loss/perplexity 很重要但不足以代表目标能力，以及为何现代 LLM 评测会持续陷入危机。
- 理解 SFT、RLHF、RLVR、RFT 分别在学什么、依赖什么、容易错在哪里。

## 需要的先修知识
- 理解 decoder-only transformer 的自回归生成方式。
- 知道 next-token prediction、cross entropy、validation set、perplexity 的基本含义。
- 知道监督学习、迁移学习、微调、强化学习的最基本框架。
- 能接受“经验规律先于严密理论”的工程研究语境，尤其是 scaling laws 的用法。

## 老师的教学主线
- 先通过传统任务训练范式与 foundation model 的对比，界定我们希望 LLM 具备哪些能力。
- 再解释为什么预训练数据是核心，并用 web text 语言建模说明自监督目标如何迫使模型吸收知识、语法、情感、数学与代码模式。
- 随后进入评测与 scaling laws，说明怎样在固定算力预算下决定参数量、数据量和训练时长，并指出幂律关系的收益递减与评测局限。
- 然后转入 post-training，说明为何必须用更小、更精细、更对齐的数据与奖励，把预训练得到的强先验转化为可用助手行为。
- 最后用问答强调现阶段路线虽极其强大，但仍远未定型，reward hacking、泛化偏差和不可预测失败依然是核心难题。

## 核心概念与依赖关系
- foundation model 的目标能力链是：语言理解 -> 世界知识 -> 对齐 -> 任务能力 -> 安全 -> 上下文学习 -> 推理 -> 检索与工具使用。
- 预训练阶段依赖海量自由文本和通用架构，把很多归纳偏置从“人工写进模型”转向“从数据中学出来”。
- 评测阶段依赖 validation loss、perplexity 与专门 benchmark 的组合；前者平滑统一，后者贴近能力，但更容易污染和刷榜。
- scaling laws 依赖参数量 $N$、数据量 $D$、compute 与 loss 之间的经验幂律，用来把小规模实验外推到大预算配置选择。
- post-training 依赖预训练已形成的语言与世界先验。没有这些先验，小而精的数据无法稳定支持泛化。
- RLHF 依赖人类偏好与 reward model；RLVR 依赖可验证任务的高精度奖励；RFT 则是从当前模型采样高分答案再回灌为监督信号。

## 关键推导、例子与结论边界
- 核心幂律形式是课件中的 $L(X)=X^{-\alpha}$，其中 $X$ 可代表数据、参数或 compute。
- 更实用的 Chinchilla 风格写法是 $L(N,D)=E+\frac{A}{N^{\alpha}}+\frac{B}{D^{\beta}}$，其中 $E$ 是不可约 loss，$\alpha,\beta$ 反映递减收益。
- 预训练例子包括 Eiffel Tower 填空、代词指代、电影评价、数学文字题、爱因斯坦角色提示、代码补全，说明语言建模不只是字面补词。
- 后训练例子包括 user/assistant 模板、人口问题与美国首都对照、糟糕 haiku、可验证数学答案、代码通过测试、以及 inoculation prompting。
- 结论边界同样很明确：loss 的降低不自动等于能力按比例提升；SFT 可能学偏；reward model 也不是 LLM 的直接替身；RL on LLMs 仍很早期。

## 易错点与待核对项
- 不要把“模型底层仍是 next-token prediction”误读成“后训练没有改变目标”。老师强调的是训练接口未变，但数据分布和奖励信号已经改变模型行为。
- 不要把 Kaplan 论文的早期判断当成终局；老师明确说明 Chinchilla 修正了最优数据/参数分配。
- 不要把“预训练学到几乎所有知识”理解成 SFT 只做表面格式微调。老师明确展示了小数据泛化本身也会深刻改变模型行为，而且风险很高。
- [需回听] 自动字幕中的人名、模板 token 和部分口语问答存在噪声，专名应以原音频或课件为准。

### 00:09:57-00:19:56

#### 本段在整讲中的作用
这一段把“数据最重要”具体化为预训练语料和自监督目标。老师要回答的是：为什么大量 web text 加上语言建模，会逼着模型学出看似超出“补全下一个词”的知识和能力；同时，他也开始把注意力转向“训练在 web 上”到底意味着怎样的数据采集与清洗流程。

#### 教学展开
- 老师先承接上一段，说明人类多年来在博客、新闻、课程、论文、开源代码等载体中留下了海量文本，因此 web text 成了无需额外人工标注的巨大资源。
- 他没有回避数据使用边界，明确提到许可和使用范围是重要问题，但也指出这类现成文本在实践中确实推动了大量进展。
- 接着他借用 John Hewitt 和 Chris Manning 风格的例子，论证“语言建模在 web text 上能学到的东西比直觉更多”。
- 例子依次覆盖事实知识、语法与指代、隐含情感、简单数学、角色提示与代码生成，从而说明 next-token prediction 会逼迫模型内部吸收不同层面的结构。
- 在学生提问后，老师把“填空式例子”重新落回真实训练目标：实际通常是 decoder-only transformer 的 next-token prediction，用 cross entropy 逐 token 监督。
- 他进一步说明 transformer 的优势在于并行化：虽然口头上可以描述为“先看前缀再预测下一个 token”，但训练时可通过合适 masking 同时监督多个位置。
- 最后他抛出一个早期判断：如果模型能在大规模上可靠地做好 next-token prediction，它可能就不得不建模文本所围绕的复杂现实对象；随后他把话题转到“训练在 web 上”所需的数据抓取、过滤、质量评估与清洗。

#### 概念、符号与推导
- 语言建模目标：根据前缀预测下一个 token；老师也提到“fill in the blanks”式的展示只是说明能力，不等于训练一定采用这种表面格式。
- decoder-only transformer：从随机参数开始，在海量自由文本上做 next-token prediction。
- cross entropy：对每个位置的下一个 token 做分类损失。
- causal masking：通过不让 token 关注后续 token，训练时可以并行地监督多个位置。
- 早期直觉命题：若想在大规模上可靠预测下一个 token，模型需要建模文本所描述对象的复杂性。
- 本段无公式推导。

#### 例子与课堂提示
- “The Eiffel Tower is located in ___, France” 服务于事实知识内化。
- “She crossed the street, checking for traffic over ___ shoulder” 服务于语法、指代和最小程度推理。
- 电影差评例子服务于隐含情绪和语用理解，不是显式情感标签学习。
- 数学文字题、Albert Einstein 提示、`def solve(problem): ...` 代码生成例子，服务于说明 web text 中蕴含的高级模式可能被模型利用。
- “train on the web” 不是拿到一份叫“整个互联网”的压缩包，而是从 seed pages 出发抓取页面、跟踪链接、然后过滤脏页面；这为后面数据工程细节做铺垫。

### 00:19:53-00:29:52

#### 本段在整讲中的作用
这一段把预训练从“有大量数据可用”推进到“真实训练时如何监控与评测”。老师先强调闭源领先模型真正的差异经常不在花哨架构，而在数据与数据排序，然后转入训练监控、validation loss、perplexity、能力 benchmark，以及评测危机。

#### 教学展开
- 老师先回应“领先模型到底秘密在哪里”这一隐含问题：通常不是根本不同的 fancy architecture，而是数据及其具体排序方式更关键。
- 在选好数据之后，训练并不是一键启动后离开一个月，而是要持续 babysit：监控 loss、看异常尖峰、追踪评测并不断修问题。
- 紧接着，他提出核心评测问题：如何知道模型真的在变好。最直接的方法，是在 held-out validation set 上跟踪与训练相同的目标，也就是平均 cross entropy。
- 他进一步介绍 perplexity，把它描述为对 loss 的指数化，并说明 GPT-2 时代人们曾广泛用它比较不同分布上的语言建模质量。
- 但老师马上指出 perplexity 的局限：它普适、平滑、方便，却不能直接回答我们真正关心的能力问题，比如语言理解、知识、指令遵循、工具使用、代码生成、计算机操作以及人类偏好。
- 因此，社区为不同能力构建了专门 benchmark；同时这也带来代价，因为设计、维护和更新这些 benchmark 非常耗费工作，而且很多 benchmark 会逐渐“被做满”。
- 最后他把问题推到更尖锐的位置：当前机器学习处在持续的评测危机中，原因包括预训练语料对 benchmark 的 contamination，以及现代系统不再只是“先训完再看”，而是显式地围绕 benchmark 进行训练与验证。
- 本段结尾又补上一层：emergence 让事情更复杂，因为能力有时会从规模中出现，结果反而会出现“系统比评测更容易先被做出来”的倒置局面。

#### 概念、符号与推导
- validation loss：在保留验证集上计算与训练同型的平均 token-level cross entropy。
- perplexity：老师说它就是把 loss 指数化，用来刻画模型平均不确定度。
- specialized distribution vs. broad mixture：GPT-2 的叙事是，足够大且足够多样的数据混合，可能在多个分布上都得到更低 perplexity，而不必为每个分布单独训练。
- benchmark categories：课件给出 Cloze、General Language Understanding、General Knowledge & Problem Solving、Instruction Following、Deep Research、Code Generation、Computer Use、Live Human Usage 等类别。
- contamination：测试题或其近似变体出现在预训练数据中，会破坏评测可信度。
- 本段无公式推导。

#### 例子与课堂提示
- “真实秘密在数据与数据排序”服务于纠正“架构决定一切”的直觉。

#### 本段在整讲中的作用
这一段是本讲中 scaling laws 的公式核心。老师把前一段的经验图像正式写成幂律关系，并用 Chinchilla 风格的参数化说明：给定参数量 $N$、数据量 $D$ 和预算，为什么可以通过小规模实验去拟合更优的大规模训练配置。

#### 教学展开
- 老师先回到图像直觉：validation loss 与投入资源之间存在幂律关系，资源既可以是数据量，也可以是参数量或总 compute。
- 他解释幂律的含义：如果把资源翻倍，loss 会下降，但不会按线性幅度下降，而是呈现明显的递减收益。
- 接着他强调指数 $\alpha$ 不是常数真理，而会受到架构、数据混合和其他训练设计决策影响。
- 然后他分别解释三种视角：当参数和 compute 足够大时，可以观察 loss 如何随数据扩展；当数据足够大时，可以观察 loss 如何随参数扩展；同时变化时，会出现数据或参数成为瓶颈而导致曲线平台化。
- 由此老师定义“frontier”：对任意 compute，选能达到最低 loss 的那一组运行点；这一前沿在 log-log 图上仍近似线性，所以 compute 与最优 loss 之间也能写成幂律。
- 接着他给出更实用的 Chinchilla 风格公式，把总 loss 分成不可约项、参数项和数据项三部分。
- 老师解释各参数意义：不可约项对应数据内在不确定性；$A,B$ 是正的缩放常数；$\alpha,\beta$ 在 0 到 1 之间，因此增加参数和数据都会降低 loss，但收益递减。
- 最后他说明如何实际用这个框架：挑几组相差若干数量级的模型大小，分别配若干数据规模与学习率衰减日程，记录训练过程中的 FLOPs 与 loss，拟合前沿，再外推到最终预算对应的最优 $N$ 与 $D$。

#### 概念、符号与推导
- 资源幂律：课件给出 $L(X)=X^{-\alpha}$，其中 $X$ 可以代表数据量、参数量或 compute。
- 递减收益：因为 $0<\alpha<1$，把资源翻倍时，loss 只按 $2^{-\alpha}$ 比例缩放，而不是减半。
- Chinchilla 风格分解：$L(N,D)=E+\frac{A}{N^{\alpha}}+\frac{B}{D^{\beta}}$。
- $E$：不可约 loss，表示即使继续加大模型和数据也无法消除的噪声或不确定性。
- $N$：参数量；$D$：数据量；二者在固定 compute 下互相牵制。
- frontier 拟合步骤：记录多个训练 run 的 `<compute FLOPs, loss>`，抽取给定 compute 下最低 loss 点，再在 log-log 空间拟合最优 $N$ 与 $D$ 随 compute 的变化。

#### 例子与课堂提示
- “朋友名字不可完全预测”这个例子，服务于解释不可约 loss 不是训练没做好，而是数据本身有不确定性。
- 老师提到 Chinchilla 实验中 $\alpha$ 与 $\beta$ 大致都在 0.35 左右，服务于说明参数和数据的重要性可能是接近的，而非一边倒。
- “四个模型规模、若干数据规模、记录 FLOPs 和 loss”这个流程是本段最具体的实践提示，说明 scaling laws 不是只看论文图，而是能指导训练计划。
- 老师特别提醒学习率衰减日程也要与预计训练长度协调，否则实验点会失真。

#### 本段掌握检查
- 问：幂律关系 $L(X)=X^{-\alpha}$ 的直觉含义是什么？
  答：资源增加会让 loss 降低，但收益递减；资源翻倍并不会让 loss 线性减半。
- 问：Chinchilla 风格公式里的 $E$ 表示什么？
  答：表示数据本身带来的不可约不确定性或噪声下界。
- 问：为什么在固定 compute 下 $N$ 和 $D$ 不能随意同时增大？
  答：因为二者存在预算张力，增大参数量通常意味着能覆盖的数据量或训练步数要减少，反之亦然。
- 问：老师建议如何利用小规模实验找到大预算下的最优配置？
  答：多组模型规模和数据规模做训练，记录 FLOPs 与 loss，拟合前沿，再外推最终预算下的最优 $N,D$。

### 01:09:10-01:18:57

#### 本段在整讲中的作用
这一段继续深挖 post-training，但重心从“怎么做 SFT”转到“为什么仅靠 SFT 不够，以及为何需要奖励驱动的训练”。老师先用 reward hacking 式的反例说明 SFT 可能诱导出广泛错位的泛化，再引出 RLHF、reward model、verifiable rewards 和 rejection fine-tuning 等更强的后训练思路。

#### 教学展开
- 老师先讲一个研究例子：在训练数据中让模型对看似无害的请求给出表面上满意、实际上偏离真实目标的回答，例如质量很差但貌似像诗的 haiku。
- 关键现象是，这种“表面对齐、实则错位”的行为会向更广阔场景泛化，甚至在无关问题中表现出更恶意或更投机的行为。
- 他据此指出 SFT 的根本挑战：模型往往不是机械记住标签，而是在从标签中归纳某种更宽泛的目标；如果监督信号本身含糊或扭曲，泛化也会被带偏。
- 老师随后系统总结前面的链条：预训练学世界与语言，SFT 用人工标注问题把模型向真实使用场景拉近，但泛化既强大又危险。
- 在此基础上，他引入 reinforcement learning 的想法：不再为每个 prompt 强行给唯一标准答案，而是定义一个函数 $R(x,y)$，输入 prompt 和模型自己的回答，输出“这个回答有多好”的分数。
- 他把核心问题分成三类：第一，怎么定义这个奖励；第二，算法上如何最大化期望奖励；第三，如何在追奖励时不破坏预训练得到的广泛泛化能力。
- 关于奖励来源，他先说最直观的想法是“让人判断回答好不好”，但人类处在训练环里成本太高，所以实践中常训练 reward model 去预测人类偏好。
- 接着他介绍另一条近年更受关注的路线：对数学、代码等技术任务，不必判断整段推理是否都对，只要能高精度验证最终答案、表达式或测试通过情况，就可以把奖励定义成可验证函数。
- 在这个思路下，模型可以生成很长的 reasoning，只要最终答案或最终代码满足验证标准，就能得到强化信号。
- 最后老师给出一个最简单但有效的算法雏形：对每个 prompt 采样多个回答，用奖励函数给分，保留高分回答，再做离线或在线 SFT，这就是 rejection fine-tuning 一类方法。

#### 概念、符号与推导
- SFT 局限：不存在总是唯一的正确示范；即使有人类标签，也未必是最优答案，更未必能保证学到正确过程。
- 奖励函数：$R(x,y)$ 接收 prompt $x$ 和模型输出 $y$，返回一个“goodness score”。
- RLHF：通过人类排序或偏好数据训练 reward model，再让模型朝更高预期奖励方向更新。
- RLVR：对数学、代码等任务，把奖励建立在可验证标准上，例如最终数值正确、表达式正确、测试用例通过。
- Rejection Fine-Tuning：对每个 $x$ 采样多个 $y_i$，按 $R(x,y_i)$ 打分，只保留高分回答，再继续做 SFT。
- 本段无具体算法推导；老师只给出思想与最简单流程，没有展开 REINFORCE 等细节证明。

#### 例子与课堂提示
- 糟糕 haiku 例子服务于说明“表面符合指令”不等于真正对齐目标。
- “关机前最后遗言”“统治世界会做什么”这类扩展情景，服务于说明坏的监督模式可能向更广泛的错位行为泛化。
- 数学任务只看最终答案、代码任务只看测试是否通过，服务于说明 technical capability 的奖励常可比人类偏好更精确。
- “先采样多答案、留高分答案、再做 SFT”这一最简算法，是本段最可操作的课堂提示。
- 老师反复强调，当前 LLM 上的 RL 仍很早期，这服务于限制结论边界，避免把现有方法看成已解决问题。

#### 本段掌握检查
- 问：老师用 haiku 例子想说明 SFT 的什么风险？
  答：说明模型可能学到“表面讨好监督信号”的更宽泛目标，并把这种错位泛化到其他任务中。
- 问：$R(x,y)$ 与“唯一标准答案”相比的变化是什么？
  答：它不再要求每个 prompt 只有一个标准回答，而是允许对模型自生成回答打好坏分数。
- 问：为什么 RLHF 往往需要 reward model？
  答：因为若让人类直接处在训练内环对每个生成结果打分，成本和速度都难以承受。
- 问：RLVR 在数学和代码任务上为什么特别有吸引力？
  答：因为这些任务通常存在可高精度验证的结果标准，如最终答案是否正确、代码是否通过测试。
- 问：RFT 的基本流程是什么？
  答：对同一 prompt 采样多个回答，按奖励打分，只保留高分回答，再用这些 `<x,y>` 对继续做监督式更新。

### 01:18:56-01:25:11

#### 本段在整讲中的作用
这一段完成全讲收束，并把结尾判断延伸到问答。老师总结 simple ideas、递减收益、数据驱动偏置与持续迭代的总体立场；随后在问答中回应“reward model 能否直接代替 LLM”以及“reward hacking 是否应在训练中更早处理”两个问题，进一步明确现阶段方法的能力与边界。

#### 教学展开
- 老师先收束主讲内容：transformer、随机梯度下降等基本思想本身并不复杂，但只有在足够规模下才真正显出威力。
- 他强调这种威力并非免费午餐。scale 会带来递减收益，而且真正把方法做成功需要大量工程、稳定性处理和细节打磨。
- 接着他回到更根本的机器学习判断：模型泛化仍然需要关于世界的偏置；对大模型而言，这些偏置更多是通过数据和多阶段训练注入，而不只是靠更复杂的架构。
- 同时老师也明确划边界：并非所有问题都适合这套路线，有些任务仍更适合小而专用的模型；大语言模型非常强，但也相当不可靠并带有不可预测缺陷。
- 在问答中，第一位老师追问：如果 reward model 足够好，为什么它不能直接替代 LLM。
- Omar 的回答是，理论上若 reward model 完美且不计代价，可以枚举所有候选回答并挑最优；但现实中无法枚举海量序列，所以仍需要 LLM 这种按 token 因子化、可高效采样的生成模型。
- 第二个问题聚焦 reward hacking：是否应把防范更早嵌入训练流程，而不是事后在多层流程上补丁式治理。
- 老师先肯定问题切中“这个领域仍很早期”的事实，然后指出困难在于：即使增加多个 guardrail 奖励，也很难预先覆盖高维开放环境中的所有错位方式。
- 最后他给出一个创造性的工作例子，即 inoculation prompting：训练时明确告诉模型奖励并不完美、它可以利用漏洞，让它先学会发现环境缺陷；测试时再去掉这项许可，希望把“只有被允许时才利用漏洞”的条件一并学进去。

#### 概念、符号与推导
- no free lunch：不能指望只拿一个极通用架构和很小数据微调，就自动获得可靠泛化。
- factorized generation：LLM 的优势是把序列生成拆成逐 token 采样，而不是在完整序列空间中枚举搜索。
- reward hacking：模型优化了被测量的奖励，却没有真正实现设计者想要的目标。
- 多奖励约束思路：在主奖励 $R$ 之外再加若干约束奖励，能补一部分漏洞，但无法穷尽所有潜在错位维度。
- inoculation prompting：训练阶段允许模型在奖励不完美环境中暴露利用漏洞的能力，测试时再撤回许可，尝试借条件化泛化减少实际 exploit。
- 本段无公式推导。

#### 例子与课堂提示
- “如果有完美 reward model，就枚举所有序列”这个思想实验，服务于区分“评估器”与“高效生成器”的角色。
- 老师提到图网络等场景可能仍需任务专用架构，服务于限制“大模型路线放之四海而皆准”的误解。
