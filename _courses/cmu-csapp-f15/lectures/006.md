## 学习目标

- 能把 x86-64 控制流所依赖的机器状态分成通用寄存器、`%rsp`、`%rip` 与 `CF/ZF/SF/OF`，并说明各自作用。[课件: 06-machine-control.pptx p.3]
- 能从算术、`cmpq`、`testq` 追踪条件码，再用 `SetX`、条件跳转或条件传送读取这些状态。[课件: 06-machine-control.pptx p.4-p.17]
- 能按 AT&T 操作数顺序解释 `cmpq Src2, Src1` 与 `testq Src2, Src1`，避免把书写顺序误当成概念运算顺序。
- 能从汇编和 goto 形态识别 `if/else`、条件表达式、`do-while`、`while` 与 `for` 的标准控制流骨架。
- 能比较 conditional jump 与 conditional move：前者只执行被选中的路径，后者先算两个候选值再选择，并能判断条件传送何时不安全或不划算。
- 能沿 `switch_eg` 的入口检查、间接跳转、跳转表与目标代码块恢复每个 `case`、hole、共享标签、fall-through 和 `default` 的语义。
- 能说明本讲三类底层控制机制：conditional jump、conditional move、通过 jump table 完成的 indirect jump；并说明编译器怎样用它们组合出 C 控制结构。[课件: 06-machine-control.pptx p.41]
- 能把上述模式用于 Bomb Lab 的早期机器代码阅读，同时明确本讲尚未展开 stack、call/return 与完整 procedure call discipline。[课件: 06-machine-control.pptx p.42]

## 先修知识

- 上一讲的 x86-64 通用寄存器、内存、数据传送、算术指令和 AT&T 汇编二操作数记法。
- Data Lab 中的 fixed-width unsigned arithmetic、two's-complement signed arithmetic、最高位、carry 与 signed overflow。
- 位运算与移位，特别是 `&`、`>>`、`x & 1` 和 `x & x == x`。
- C 的 `if/else`、条件表达式 `?:`、`goto`/label、`do-while`、`while`、`for`、`switch/case/default/break`。
- 本讲只临时使用“前两个参数位于 `%rdi/%rsi`、第三个参数位于 `%rdx`、返回值位于 `%rax`”这些例子中明确出现的约定；完整 procedures 属于下一讲。

## 教学主线

1. **`00:00:01-00:03:05`：动机与范围。** Machine-level programming 是理解系统状态、程序 crash 和 Bomb Lab 的核心工具；本讲处理 conditionals、loops、switch，procedures 留到下一讲。
2. **`00:03:05-00:12:14`：建立条件码数据源。** 先加入 `%rip` 与 `CF/ZF/SF/OF`，再说明算术隐式设置 flags，`cmpq` 与 `testq` 显式设置 flags。
3. **`00:12:15-00:19:58`：读取为布尔值。** `SetX` 把条件码组合物化到低位字节；`gt(x,y)` 串起 `cmpq`、`setg`、`movzbl` 和 32 位写入清高位规则。
4. **`00:19:58-00:31:23`：读取为控制转移。** 用 `jX`、label 和 goto 形式实现 `absdiff` 的 `if/else`，再归纳一般条件表达式的 then/else/Done 模板。
5. **`00:31:24-00:38:16`：不用分支的条件选择。** 解释 branch prediction 与错误预测代价，展示 `cmovle` 版 `absdiff`，再限定条件传送必须面对简单、安全、无副作用的候选计算。
6. **`00:38:17-00:49:49`：循环。** 从最直接的 `do-while` 回跳开始，推出 `while` 的 jump-to-middle 与入口保护两种翻译，再把 `for` 先改写成 `while`。
7. **`00:49:50-01:09:42`：`switch`。** 从源级 fall-through 与多标签出发，建立范围检查、jump table、indirect jump、目标代码块和共享后缀；再讨论偏置与稀疏 case。
8. **`01:09:42-01:13:39`：性能与总结。** 稠密范围可用常数步数的跳转表，稀疏集合可用对数级 decision tree；所有高级控制结构都由少量底层机制组合而成。

## 概念依赖

```text
fixed-width 位级表示 + AT&T 操作数顺序
                  |
                  v
算术 / cmp / test 产生 CF、ZF、SF、OF
                  |
                  +--> SetX --> 低位字节 0/1 --> movzbl --> 完整布尔返回值
                  |
                  +--> jX --> taken / fall through
                  |              +--> if/else
                  |              +--> do-while / while / for
                  |              +--> 稀疏 switch 的 decision tree
                  |
                  +--> cmovX --> 已算好的两个候选值中选择一个

case 常量 + 值域/密度分析
                  |
                  +--> 范围检查 --> jump table --> indirect jump --> case 代码块
```

这条依赖链的阅读原则是：先找**谁最后写了条件码**，再看后继指令怎样消费它们；对于 `switch`，先找**索引是否合法**，再看表项保存的**目标地址**，最后追目标代码块。`%rip` 表示代码控制点，jump 最终改变的是接下来从哪里取指；`SetX` 和 `cmovX` 则不必改变控制点。

## 源材料关键推导和例子

### 1. Processor state 与 condition codes

课件只画出本讲需要的部分状态：[课件: 06-machine-control.pptx p.3]

| 状态 | 本讲作用 |
| --- | --- |
| `%rax` 等 16 个整数寄存器 | 保存参数、临时值与结果 |
| `%rsp` | 指向 runtime stack top；完整用途下一讲展开 |
| `%rip` | 标识当前代码控制点/指令位置 |
| `CF/ZF/SF/OF` | 概括最近相关运算或测试的性质 |

对 `addq Src, Dest`，令 `a` 为 `Dest` 旧值、`b` 为 `Src`、`t=a+b`：[课件: 06-machine-control.pptx p.4]

- `CF`：最高位产生 carry，服务 unsigned interpretation。
- `ZF`：`t == 0`。
- `SF`：`t` 按有符号解释为负。
- `OF`：two's-complement signed overflow；课件给出

$$
OF=(a>0\land b>0\land t<0)\lor(a<0\land b<0\land t\ge 0)
$$

因此 `CF` 与 `OF` 回答的是不同问题，同一 bit pattern 上可以不同。多数算术指令把 flags 当作副作用更新；`leaq` 是课堂明确指出的例外，它不设置条件码。

### 2. `cmpq`：丢弃差值，只留下条件码

AT&T 语法：[课件: 06-machine-control.pptx p.5]

```asm
cmpq Src2, Src1          # 按 Src1 - Src2 设置 flags，不保存差值
```

阅读 `cmpq b, a` 时必须在脑中写成 `a-b`。例如：

```asm
cmpq %rsi, %rdi          # Compare x:y，即按 x-y 设置 flags
```

`%rdi` 与 `%rsi` 都不被改写。教师实际建议是在汇编旁手写反转后的比较注释，避免混淆 AT&T 与 Intel/Microsoft dialect 的操作数顺序。

### 3. `testq`：丢弃按位与结果，只留下条件码

课件定义：[课件: 06-machine-control.pptx p.6]

```asm
testq Src2, Src1         # 按 Src1 & Src2 设置 flags，不保存结果
```

典型自测：

```asm
testq %rax, %rax         # 因 x & x == x，检查 %rax 自身
```

由此 `ZF=1` 表示 `%rax==0`，`SF=1` 表示它按有符号数解释为负。课件还允许一个操作数充当 mask，但本讲没有口述具体 mask 数值例子。

### 4. `SetX`：把条件码物化为 0/1

`SetX` 只写目的寄存器的低位字节，其余 7 字节保持原值。[课件: 06-machine-control.pptx p.7-p.9]

| 指令 | 条件 | 含义 |
| --- | --- | --- |
| `sete` / `setne` | `ZF` / `~ZF` | 相等/不等 |
| `sets` / `setns` | `SF` / `~SF` | 负/非负 |
| `setg` | `~(SF^OF) & ~ZF` | 有符号大于 |
| `setge` | `~(SF^OF)` | 有符号大于等于 |
| `setl` | `SF^OF` | 有符号小于 |
| `setle` | `(SF^OF) | ZF` | 有符号小于等于 |
| `seta` | `~CF & ~ZF` | 无符号高于 |
| `setb` | `CF` | 无符号低于 |

`gt(x,y)` 的完整链条是：[课件: 06-machine-control.pptx p.9]

```asm
cmpq   %rsi, %rdi        # x:y
setg   %al               # 只写 %rax 的最低字节
movzbl %al, %eax         # 零扩展到 %eax；32 位写入同时清 %rax 高 32 位
ret
```

推导顺序：`cmpq` 令 flags 描述 `x-y`；`setg` 用 `~(SF^OF)&~ZF` 判断 signed `x>y`；`movzbl` 清理尚未定义的其余 7 字节，最终整个 `%rax` 为规范的 0 或 1。

### 5. `jump`：把条件码变成控制路径

`jX` 与 `SetX` 使用相同类型的条件组合，但它选择 taken 或 fall through，而不是写一个布尔字节。[课件: 06-machine-control.pptx p.11]

`absdiff` 的传统分支版：[课件: 06-machine-control.pptx p.12]

```asm
absdiff:
    cmpq %rsi, %rdi      # x:y
    jle   .L4            # x <= y 时 taken
    movq  %rdi, %rax
    subq  %rsi, %rax     # x-y
    ret
.L4:
    movq  %rsi, %rax
    subq  %rdi, %rax     # y-x
    ret
```

一般条件表达式：

```c
val = Test ? Then_Expr : Else_Expr;
```

按课堂 goto 模板翻译为：[课件: 06-machine-control.pptx p.14]

```c
ntest = !Test;
if (ntest) goto Else;
val = Then_Expr;
goto Done;
Else:
val = Else_Expr;
Done:
/* 后续代码 */
```

每次只执行一个候选表达式；两条路径在 `Done` 汇合。`absdiff` 只是控制流示例，教师明确暂不处理 `TMin` 边界问题。

### 6. `conditional move`：先算两边，再选择结果

一般模板：[课件: 06-machine-control.pptx p.15]

```c
result = Then_Expr;
eval = Else_Expr;
nt = !Test;
if (nt) result = eval;
return result;
```

`absdiff` 的实际 `cmovle` 版本：[课件: 06-machine-control.pptx p.16]

```asm
movq   %rdi, %rax
subq   %rsi, %rax        # result = x-y
movq   %rsi, %rdx
subq   %rdi, %rdx        # eval = y-x
cmpq   %rsi, %rdi        # x:y
cmovle %rdx, %rax        # x<=y 时 result = eval
ret
```

课堂动机是直线指令流有利于流水线；条件分支需要预测，错猜时要撤回错误方向的工作。教师口述的约 98% 正确率、糟糕时约 40 clock cycles 都只是课堂概略量级，不是所有处理器的固定常数。

条件传送不能无条件替代分支，因为两个候选值都会被计算：[课件: 06-machine-control.pptx p.17]

- `Test(x) ? Hard1(x) : Hard2(x)`：两边昂贵，全部计算不划算。
- `p ? *p : 0`：原条件保护潜在空指针，先算两边不安全。
- `x > 0 ? x*=7 : x+=3`：两边都有副作用，全部执行会改变语义。

采用标准是：候选计算相对简单、执行安全、没有副作用。

### 7. `loops`：测试与回跳的组合

#### `do-while`

```c
do {
    Body;
} while (Test);
```

等价 goto 骨架：[课件: 06-machine-control.pptx p.21]

```c
loop:
    Body;
    if (Test) goto loop;
```

第一次进入时先执行 `Body`，所以至少执行一次。`pcount_do` 每轮执行：

$$
result_{k+1}=result_k+(x_k\mathbin{\&}1),\qquad x_{k+1}=x_k\mathbin{\texttt{>>}}1
$$

再以移位后的 `x` 是否非零决定 `jne .L2` 回跳。[课件: 06-machine-control.pptx p.19-p.20]

#### `while` 的两种翻译

`-Og` 下课堂称为 jump-to-middle：[课件: 06-machine-control.pptx p.22]

```c
goto test;
loop:
    Body;
test:
    if (Test) goto loop;
done:
```

入口保护式 do-while conversion（课件标为 `-O1`）：[课件: 06-machine-control.pptx p.24]

```c
if (!Test) goto done;
loop:
    Body;
    if (Test) goto loop;
done:
```

两种形状都保证初始 `Test` 为假时 `Body` 执行 0 次；不能把普通 `while` 与 `do-while` 一般化为等价。

#### `for`

课堂先做语义等价变换：[课件: 06-machine-control.pptx p.27]

```c
for (Init; Test; Update)
    Body;
```

变为：

```c
Init;
while (Test) {
    Body;
    Update;
}
```

顺序固定为 `Init` 一次、每轮 `Test -> Body -> Update`。`pcount_for` 中 `i=0` 且 `WSIZE` 通常为 32，编译器可证明首次 `i<WSIZE` 为真，从而在该具体例子中删除入口保护测试；这不是所有 `for` 的固定规则。[课件: 06-machine-control.pptx p.29]

### 8. `switch`：范围检查、跳转表与间接跳转

`switch_eg` 的源级关键结构：[课件: 06-machine-control.pptx p.31]

```c
long w = 1;
switch (x) {
case 1:
    w = y*z;
    break;
case 2:
    w = y/z;
    /* Fall Through */
case 3:
    w += z;
    break;
case 5:
case 6:
    w -= z;
    break;
default:
    w = 2;
}
```

入口先排除查表范围之外的值，再间接跳转：[课件: 06-machine-control.pptx p.33-p.35]

```asm
cmpq $6, %rdi
ja   .L8                 # unsigned above：x<0 或 x>6 都去 default
jmp  *.L4(,%rdi,8)       # 取 JTab[x] 中的 8-byte 目标地址并跳转
```

有效表项地址是：

$$
\operatorname{entryAddress}(x)=\mathrm{L4}+8x,\qquad 0\le x\le 6
$$

表项内容：[课件: 06-machine-control.pptx p.36]

| `x` | 目标 | 含义 |
| ---: | --- | --- |
| 0 | `.L8` | hole，走 `default` |
| 1 | `.L3` | `case 1` |
| 2 | `.L5` | `case 2` |
| 3 | `.L9` | `case 3` |
| 4 | `.L8` | hole，走 `default` |
| 5 | `.L7` | `case 5` |
| 6 | `.L7` | `case 6`，与 5 共用代码 |

逐路径结果：[课件: 06-machine-control.pptx p.37-p.40]

- `x==1`：`.L3` 返回 `y*z`。
- `x==2`：`.L5` 计算 `y/z`，跳到 `.L6` 加 `z`，返回 `(y/z)+z`。
- `x==3`：`.L9` 设置 `w=1`，自然落入 `.L6` 加 `z`，返回 `1+z`。
- `x==5` 或 `x==6`：`.L7` 设置 `w=1` 后减 `z`，返回 `1-z`。
- `x==0`、`x==4` 或范围外：`.L8` 返回 `2`。

这说明 fall-through 可表现为不同入口汇入共享后缀；表内 hole 直接填 default target；多个 case 可重复同一目标地址。源代码的 `w=1` 没在统一入口执行，是因为编译器把初始化推迟到真正需要它的路径。

若最小 case 不是 0，教师说明可加减 bias，使最小值映射到索引 0；若 case 极稀疏，例如只有 0 与 1,000,000，不应建巨大表，编译器可对已知常量排序并生成类似 binary search 的 balanced decision tree。课堂总结的分派量级是：跳转表 constant、线性条件链 linear、平衡条件树 logarithmic；材料没有给出 GCC 的密度阈值。[课件: 06-machine-control.pptx p.41]

## 易错点

1. **把 `CF` 与 `OF` 当成同一个 overflow。** `CF` 服务 unsigned，`OF` 服务 signed two's-complement；必须先确定解释域。
2. **只看 `SF` 判断 signed 小于。** 减法可能发生 signed overflow，`setl/jl` 使用 `SF^OF` 修正。
3. **把 `cmpq a,b` 读成 `a-b`。** 本讲采用 AT&T syntax，应按第二操作数减第一操作数，即 `b-a`。
4. **以为 `cmpq/testq` 会写回概念结果。** 二者只写 flags，不保存差值或按位与结果。
5. **以为 `leaq` 后 flags 描述刚算出的值。** 课件明确说 `leaq` 不设置条件码。
6. **以为 `setg %al` 已把整个 `%rax` 变成 0/1。** 它只写 8 位；示例需要 `movzbl %al,%eax` 清理其余位。
7. **忽略 flags 的“最近写入者”。** `jX`/`SetX`/`cmovX` 读取的是最近相关指令留下的条件码；中间若有改 flags 的指令，判断来源就变了。
8. **把 conditional move 理解成只计算被选中一边。** 它先算两边；昂贵、危险或有副作用的候选表达式都不适用。
9. **把 `cmovle` 的 `le` 读成数据宽度。** 这里是 less or equal 条件。
10. **混淆 `do-while` 与 `while` 的首次测试。** 前者先执行一次 body，后者可以执行 0 次；两种 `while` 翻译都必须保护入口语义。
11. **把某一种循环汇编形状当成唯一模板。** `-Og` 与 `-O1` 可产生不同而等价的控制流，具体优化还可能删除可证明恒真的测试。
12. **把 `switch` 当成必然的线性 `if-else` 链或必然的跳转表。** 稠密范围适合 jump table，稀疏集合可能使用 decision tree。
13. **把 `ja` 当成 signed greater-than。** 本例故意用 unsigned above，使负数和大于 6 的值一次都被送到 default。
14. **把 `.L4+8x` 当成最终代码地址。** 它是表项地址；需要先读取其中保存的 target，再间接跳转。
15. **认为范围内 hole 会被入口越界检查捕获。** `x=0`、`x=4` 通过范围检查，靠对应表项指向 `.L8` 才走 default。
16. **认为 C `break` 一般都翻译成 `ret`。** 本例 switch 后立刻 `return w`，所以部分代码块可直接返回；这不是一般规则。
17. **把课件或字幕不确定处擅自修正成确定事实。** 后附 001–008 中所有 `[需回听]` 均须保留，表示现有材料的证据边界。

### 参考答案

1. `%rip` 标识当前代码控制点；`%rsp` 指向 runtime stack top；四个 flags 概括最近相关运算的 carry、zero、sign、signed overflow 状态。
2. `01111111+00000001=10000000` 没有第 9 位 carry，但两个 signed 正数得到 signed 负数，所以无 unsigned carry 而有 signed overflow。
3. 按 `%rdi-%rsi`，即 `x-y` 设置 flags；`cmpq` 不写回差值，两个输入寄存器都不改。
4. 因 `x&x=x`，概念结果就是 `%rax` 自身；`ZF/SF` 可反映零/负，`testq` 不保存按位与结果，所以不覆盖 `%rax`。
5. `ZF` 先排除相等；signed 减法可能 overflow，表面符号 `SF` 需与 `OF` 组合修正，故严格大于为 `~(SF^OF)&~ZF`。
6. `setg` 只写最低 8 位，其余 56 位仍是旧值；`movzbl` 零扩展到 `%eax`，而写 32 位结果又清 `%rax` 高 32 位，最终整个返回寄存器为 0/1。
7. taken 表示 `x<=y`，在 `.L4` 计算 `y-x`；fall-through 表示 `x>y`，计算 `x-y`。
8. 先测试 `!Test` 并跳到 `Else`；then 路径结束后无条件跳到 `Done`，else 路径自然落到 `Done`，所以每次只走一边。
9. 它把两边候选值都算好后只做条件复制，不改变控制点；两边计算昂贵、执行有风险、存在副作用时不适用。
10. `do-while` 在第一次 body 之后测试；jump-to-middle 在入口先跳到尾部 test；入口保护式在进入 do-while 骨架前先测 `!Test`。
11. `Init` 一次，然后每轮 `Test -> Body -> Update`；本例 `i=0` 且 `WSIZE` 通常为 32，首次测试可证明恒真，所以具体入口保护可删。
12. `ja` 按 unsigned above 判断；signed 负数按 unsigned 解释为很大，一条分支同时把 `x<0` 与 `x>6` 送到 default。
13. 计算表项地址 `.L4+8*x`，从该位置读取 8-byte target address，再间接跳转；8 是每个地址表项的字节数。
14. 0、4 是范围内 hole，应走 default `.L8`；5、6 共享 `w-=z`，所以重复保存 `.L7` 地址。
15. `x==2` 在 `.L5` 先算 `y/z` 再跳 `.L6` 加 `z`，返回 `(y/z)+z`；`x==3` 在 `.L9` 设 `w=1` 后落入 `.L6`，返回 `1+z`。
16. 加减固定 bias，使最小 case 映射到索引 0；值域过大且稀疏时可用 binary-search 式 balanced decision tree。
17. conditional jump 支撑 `if/else`、循环和 decision tree；conditional move 支撑适合先算两边的条件选择；jump table 的 indirect jump 支撑适合建表的 `switch`。

### 2. 从可见机器状态过渡到“下一步执行哪里”（`00:02:12-00:03:05`）

上一讲已经看到通用寄存器和内存。教师回应课后问题：寄存器既不是内存，也不是 cache；它们是处理器内部、C 源程序不能直接命名的一类特殊状态。今天要在这些状态之上讨论 machine-level control，并依次把它映射回：

1. conditional statements；
2. loops；
3. switch statements。

Procedures 需要 stack、call/return 与调用约定，因此留到下一讲。[课件: 06-machine-control.pptx p.2]

### 3. x86-64 的部分 processor state（`00:03:05-00:05:13`）

课件只画出与当前主题相关的部分状态：[课件: 06-machine-control.pptx p.3]

| 状态 | 本段角色 | 可否像普通 C 变量一样使用 |
| --- | --- | --- |
| `%rax` 等 16 个整数寄存器 | 保存临时数据 | C 代码通常看不到具体分配 |
| `%rsp` | 指向当前 runtime stack top | 有特殊约束，不能任意改动 |
| `%rip` | 保存当前/下一控制点所需的 instruction address | 不能像普通通用寄存器那样直接读写 |
| `CF/ZF/SF/OF` | 保存最近一次相关测试或运算的状态 | 由专门的读取/控制指令消费 |

16 个整数寄存器中，8 个沿用历史名称，另外 8 个命名为 `%r8` 到 `%r15`。教师说“多数寄存器大体可由指令自由使用”，同时明确给这句话加了 qualifications；下一讲的 calling convention 会进一步限制各寄存器的责任。

`IP` 是 instruction pointer；32-bit IA-32 中叫 `%eip`，x86-64 中叫 `%rip`。它标识程序当前执行到哪里，是顺序执行、jump 和 call/return 最终都要改变或推进的控制点。

### 4. 四个条件码不是一个多位数，而是四个一位状态（`00:05:13-00:07:14`）

课件列出本讲所需的四个 single-bit condition codes；处理器还有其他 flags，但本讲不使用。[课件: 06-machine-control.pptx p.4]

| 条件码 | 名称 | 对结果 `t` 的含义 | 主要解释域 |
| --- | --- | --- | --- |
| `CF` | Carry Flag | 最高位产生 carry；用于判断 fixed-width unsigned overflow/ordering | unsigned |
| `ZF` | Zero Flag | `t == 0` | 两者皆可 |
| `SF` | Sign Flag | `t` 的最高位为 1，即按 two's-complement 解释为负 | signed |
| `OF` | Overflow Flag | signed 结果超出当前位宽可表示范围 | signed |

对 `addq Src, Dest`，令 `a = Dest` 的旧值、`b = Src`、`t = a + b`。课件给出的 signed overflow 判定为：[课件: 06-machine-control.pptx p.4]

$$
OF = (a>0 \land b>0 \land t<0) \lor (a<0 \land b<0 \land t\ge 0)
$$

其逻辑是：相反符号相加不会产生 signed overflow；同号相加却得到异号结果时，有限位宽表示已经越界。`CF` 与 `OF` 可以对同一 bit pattern 给出不同答案，因为前者按 unsigned arithmetic 解释，后者按 signed two's-complement arithmetic 解释。

### 5. 算术指令把条件码作为副作用写入（`00:07:14-00:07:48`）

多数相关算术指令在写 destination 的同时也更新 flags。可以把它理解成两份输出：显式输出是 destination 中的结果，隐式输出是对该结果性质的四个摘要位。大多数时候后续代码并不读取它们，于是这些副作用被覆盖；当程序需要比较或改变控制流时，紧随其后的指令才会消费它们。

`leaq` 是课堂明确指出的例外：它可以完成类似算术的地址计算，却**不设置条件码**。[课件: 06-machine-control.pptx p.4] 因此不能看到 `leaq` 后就假定 flags 描述它刚算出的值。

### 6. `cmpq`：只保留减法的 flags，不保留差值（`00:07:48-00:10:01`）

`cmpq` 的唯一目的就是显式设置条件码。AT&T 语法为：[课件: 06-machine-control.pptx p.5]

```asm
cmpq Src2, Src1          # flags <- properties of Src1 - Src2
```

若写成 `cmpq b, a`，应在脑中重排为 `a - b`。它与 `subq b, a` 使用相同的差值关系来设置 flags，但不覆盖 `a`，也没有其他 destination。教师建议阅读 assembly 时主动写成 `# Compare a:b`，避免被源操作数在前、目的操作数在后的 AT&T 顺序误导。

Linux/GNU 工具链常见的是 AT&T dialect；Intel/Microsoft 常见另一种 dialect，两者的操作数顺序等约定不同。本讲所有代码都按 AT&T syntax 解释，不能混用另一种记法的直觉。

## 条件码追踪

### 追踪 A：有符号溢出与无符号 carry 是不同问题

假设为便于展示只看 8-bit pattern，执行 `0x7f + 0x01`：

```text
0111 1111   (127)
+0000 0001   (1)
-----------
1000 0000   (-128 if signed; 128 if unsigned)
```

- 没有第 9 位 carry，所以 `CF = 0`。
- 结果不为 0，所以 `ZF = 0`。
- 最高位为 1，所以 `SF = 1`。
- 两个正数得到负的 signed result，所以 `OF = 1`。

这个小位宽例子只是把 p.4 的规则可视化；课堂实际示例指令后缀 `q` 表示 64-bit，不能把 8-bit 数值范围套到 `addq`。

### 追踪 B：`cmpq %rsi, %rdi` 不改两个输入

设 `%rdi = 7`、`%rsi = 4`：

```asm
cmpq %rsi, %rdi          # internally reason about 7 - 4
```

逻辑差值为 3，因此 `ZF = 0`、`SF = 0`，且这里没有 signed overflow；`%rdi` 仍为 7，`%rsi` 仍为 4。下一节才会说明 `setcc` 如何把这些 flags 组合成布尔结果。

## 关键概念与依赖关系

```text
arithmetic / cmp / test
          |
          v
     CF ZF SF OF
          |
          +--> setcc：物化为 0/1（第 2 节）
          +--> jcc：选择下一控制点（第 3 节）
          +--> cmovcc：选择是否覆盖结果（第 4 节）
```

`%rip` 给出当前 control point；condition codes 概括最近相关运算；后续控制指令读取这些 bits，决定 `%rip` 是顺序推进还是转到其他代码位置。

## 常见误解

- **误解：寄存器是很小很快的 cache。** 本讲明确把 registers 与 cache/memory 区分为不同机器状态。
- **误解：`CF` 和 `OF` 都叫 overflow，所以总是相同。** `CF` 服务 unsigned interpretation，`OF` 服务 signed two's-complement interpretation。
- **误解：`SF = 1` 就足以判定任何 signed comparison 的“小于”。** 减法可能 signed overflow；后续 `setl/jl` 必须组合 `SF` 与 `OF`。
- **误解：每条看起来像算术的指令都会更新 flags。** `leaq` 是本讲明确给出的反例。
- **误解：`cmpq a, b` 计算 `a-b`。** 在本讲的 AT&T syntax 中，它按 `b-a` 设置条件码。
- **误解：`cmpq` 会把差值写回第二个操作数。** 它只写 flags，不保存差值。

   **答：** 同一 bit pattern 可按 unsigned 或 signed 解释；`CF` 检查 unsigned carry，`OF` 检查 two's-complement signed range 是否越界。

3. **问：两个负数相加在什么课堂条件下设置 `OF`？**  
   **答：** 结果按 signed 解释为非负，即 `a<0 && b<0 && t>=0`。[课件: 06-machine-control.pptx p.4]

4. **问：执行 `cmpq %rsi, %rdi` 时，逻辑上比较的差值和被改写的寄存器是什么？**  
   **答：** 按 `%rdi - %rsi` 设置 flags；两个输入寄存器都不被 `cmpq` 改写。[课件: 06-machine-control.pptx p.5]

5. **问：为什么不能用紧随 `leaq` 的条件分支判断该地址计算结果？**  
   **答：** `leaq` 不设置条件码，分支看到的是更早一条会写 flags 的指令所留下的状态。[课件: 06-machine-control.pptx p.4]

# 第 2 节：显式设置与读取条件码

> 时间范围：`00:10:01-00:19:58`  
> 课件范围：[课件: 06-machine-control.pptx p.5] [课件: 06-machine-control.pptx p.6] [课件: 06-machine-control.pptx p.7] [课件: 06-machine-control.pptx p.8] [课件: 06-machine-control.pptx p.9]

## 本段在整讲中的作用

上一段已经建立了 `CF`、`ZF`、`SF`、`OF` 四个条件码，并说明算术指令会隐式设置它们、`cmpq` 会像减法一样显式设置它们。本段承接两个问题：除了 `cmpq`，怎样只考察一个值的零/负性质；条件码设置后，又怎样把它们变成 C 程序可使用的 `0` 或 `1`。[课件: 06-machine-control.pptx p.5] [课件: 06-machine-control.pptx p.6]

教师先补完减法语境下条件码的提醒，再讲 `testq`，随后从“怎样读取条件码”转到 `SetX` 指令。最后用 `gt(x, y)` 把调用约定、`cmpq`、`setg`、低位字节寄存器和零扩展串成一条完整的数据通路。下一段会把条件码用于改变控制流，而不只是生成一位布尔结果。

## 教学展开

### 1. 从 `cmpq` 的减法语义收尾（`00:10:01-00:10:18`）

教师提醒：`cmpq b, a` 按 `a-b` 设置条件码，因此分析 `CF` 和 `OF` 时必须按“减法”而不是“加法”理解；虽然仍然是在判断最高位进位/有符号溢出一类现象，但判断方向需要随运算改变。[课件: 06-machine-control.pptx p.5]

课件把 `cmpq b, a` 的结果概括为：

- 不写回差值，只写条件码；
- `ZF=1` 当且仅当 `a==b`；
- `SF=1` 当 `a-b` 按有符号数解释为负；
- `CF` 用于无符号比较；
- `OF` 记录 `a-b` 的补码有符号溢出。

### 2. `testq`：用按位与的结果设置条件码（`00:10:19-00:11:32`）

接着引入另一条“存在的唯一目的就是设置条件码”的指令 `testq`。教师先对比使用意图：

- `cmpq` 常用于比较两个值之间的关系；
- `testq` 常用于考察一个值本身，例如它是否为零、是否为负。

课件给出的精确定义是：[课件: 06-machine-control.pptx p.6]

```asm
testq Src2, Src1          # 按 Src1 & Src2 的结果设置条件码，不保存结果
```

写成 `testq b, a` 时，概念上计算 `a & b`，但没有目的寄存器被改写。由此：

$$
ZF = 1 \iff (a \mathbin{\&} b)=0
$$

$$
SF = 1 \iff (a \mathbin{\&} b)<0 \quad\text{（按有符号数解释）}
$$

课件还指出其中一个操作数可以是 mask。课堂重点讲的是两个操作数相同的常见写法：

```asm
testq %rax, %rax
```

因为按位与具有幂等性，`x & x == x`，所以它不需要保存任何新值，就能让 `ZF`、`SF` 反映 `%rax` 本身是否为零、是否为负（`00:11:03-00:11:31`）。

### 3. 从“设置”过渡到“读取”条件码（`00:11:34-00:12:14`）

至此，最近的算术、`cmpq` 或 `testq` 已经留下条件码。教师提出新的问题：怎样使用它们？理论上可以直接从特殊状态寄存器取出条件码，但课堂说这种做法很少见。通常有两条路径：

1. 根据条件码在普通寄存器中物化一个 `0/1` 结果；
2. 根据条件码执行条件跳转。

本段先讲第一条路径，即 `SetX`；第二条路径留给下一段。

### 4. `SetX`：把条件码组合物化为单字节 `0/1`（`00:12:15-00:13:57`）

`SetX` 不是一条单独的指令名，而是一族只在“采用什么条件”上不同的指令。它们读取最近一次相关指令留下的条件码组合，把某个可寻址寄存器的低位字节写为 `1`（条件成立）或 `0`（条件不成立）；其余七个字节保持原值。[课件: 06-machine-control.pptx p.7]

课件列出的条件关系如下，其中 `^` 表示异或，`~` 表示逻辑取反：[课件: 06-machine-control.pptx p.7]

| 指令 | 条件码组合 | 含义 |
| --- | --- | --- |
| `sete` | `ZF` | 相等 / 结果为零 |
| `setne` | `~ZF` | 不相等 / 结果非零 |
| `sets` | `SF` | 结果为负 |
| `setns` | `~SF` | 结果非负 |
| `setg` | `~(SF^OF) & ~ZF` | 有符号大于 |
| `setge` | `~(SF^OF)` | 有符号大于等于 |
| `setl` | `SF^OF` | 有符号小于 |
| `setle` | `(SF^OF) | ZF` | 有符号小于等于 |
| `seta` | `~CF & ~ZF` | 无符号高于 |
| `setb` | `CF` | 无符号低于 |

教师以 `sets` 为最直接的例子：若最近结果的 `SF=1`，即结果按有符号数解释为负，则写入 `1`。而 `setl`、`setle` 等有符号比较不能只看符号位，还要考虑最近的减法是否发生 `OF`；这正是前面学习补码和位级行为的用途（`00:13:10-00:13:49`）。

### 5. 为什么目的只能是低位字节（`00:13:58-00:14:35`）

x86-64 的 16 个整数寄存器都可单独引用最低字节。课件列出 `%al`、`%bl`、`%cl`、`%dl`、`%sil`、`%dil`、`%spl`、`%bpl` 以及 `%r8b` 到 `%r15b`。[课件: 06-machine-control.pptx p.8]

`SetX` 写其中一个低位字节时，只改变这 8 位，不清除同一个 64 位寄存器的其他 56 位。因此，“已经得到布尔字节”不等于“整个返回寄存器已经是规范的整数 0 或 1”。这个差别直接引出后面的 `movzbl`。

### 6. `gt(x, y)`：从比较到完整返回值（`00:14:35-00:19:50`）

目标 C 函数为：[课件: 06-machine-control.pptx p.9]

```c
int gt(long x, long y)
{
    return x > y;
}
```

课堂给出的汇编为：

```asm
cmpq   %rsi, %rdi   # Compare x:y
setg   %al          # Set when >
movzbl %al, %eax    # Zero rest of %rax
ret
```

教师按下面的顺序追踪数据：

1. 按课堂介绍的调用约定，`x` 在 `%rdi`，`y` 在 `%rsi`；返回值放在 `%rax`（`00:16:06-00:16:25`）。
2. `cmpq %rsi, %rdi` 按 `%rdi-%rsi`，也就是 `x-y` 设置四个条件码。教师把注释写成 `x:y`，是为了按实际比较关系阅读，而不是照抄 AT&T 语法中出现操作数的顺序（`00:16:29-00:16:49`）。
3. `setg %al` 根据有符号“大于”的条件 `~(SF^OF) & ~ZF`，把 `%rax` 的最低字节设为 `1` 或 `0`（`00:16:49-00:17:20`）。
4. 此时只确定了 `%al`；其余七个字节仍是进入函数前的旧内容，不能直接把整个 `%rax` 当作干净的返回值（`00:17:20-00:17:35`）。
5. `movzbl %al, %eax` 把该字节零扩展到 `%eax` 的 32 位。课堂随后强调 x86-64 的规则：产生 32 位寄存器结果时，硬件同时把对应 64 位寄存器的高 32 位清零（`00:17:44-00:18:53`）。于是 `%rax` 的其余七个字节最终全部为零。
6. `ret` 返回时，调用者从 `%rax` 取得规范的 `0` 或 `1`。

教师将它总结为一个常见模式：`SetX` 先得到单字节布尔值，`movzbl` 再完成整个返回寄存器的零扩展。[课件: 06-machine-control.pptx p.9]

课堂还顺带说明汇编排版惯例：指令通常缩进，标签通常靠左；汇编器对空白较宽容，但规范排版更便于人阅读（`00:14:54-00:16:00`）。

## 概念、符号与推导

### `cmpq` 与 `testq` 的共同点和差异

| 指令 | 概念运算 | 是否保存运算结果 | 典型用途 |
| --- | --- | --- | --- |
| `cmpq b, a` | `a-b` | 否，只设置条件码 | 比较两个值 |
| `testq b, a` | `a&b` | 否，只设置条件码 | 检查零、符号或 mask 后的位 |

### 从 `x-y` 推出有符号 `x>y`

`cmpq %rsi, %rdi` 先令条件码描述 `x-y`。课件给出的 `setg` 条件为：[课件: 06-machine-control.pptx p.7]

$$
x>y \iff \neg(SF\oplus OF) \land \neg ZF
$$

推导链按课堂材料可读为：

1. `ZF=1` 表示差为零，即 `x==y`，所以严格大于要求 `ZF=0`。
2. 对有符号减法，`SF` 所见的结果符号可能受 `OF` 影响，因此用 `SF^OF` 表示经溢出修正后的“小于”判断。
3. `SF^OF` 为假且 `ZF` 为假时，得到严格有符号“大于”。

### 零扩展链

```text
条件码
  -> setg %al：仅 %al = 0 或 1
  -> movzbl %al, %eax：%eax = zero_extend(%al)
  -> 32 位写入规则：%rax[63:32] = 0
  -> 整个 %rax = 0 或 1
```

字节操作只影响一个字节，两字节操作只影响两个字节，而课堂特别指出四字节结果会把同一 64 位寄存器的高四字节清零（`00:18:38-00:19:24`）。

## 例子与课堂提示

- **同一寄存器自测**（`00:11:03-00:11:31`）：`testq %rax, %rax` 利用 `x&x=x`，服务于“不破坏值而检查它是否为零/负”的知识点。
- **mask 操作数**：[课件: 06-machine-control.pptx p.6] 指出 `testq` 的一个操作数可用作 mask；它服务于“先筛选位，再根据结果设置 `ZF/SF`”。本片段没有口述具体 mask 数值，不补造示例。
- **低位字节的旧高位陷阱**（`00:17:20-00:17:35`）：`setg %al` 后不能假设 `%rax` 的其余 56 位为零；这是理解 `movzbl` 必要性的核心易错点。
- **32 位写入的特殊规则**（`00:18:17-00:19:30`）：写 `%eax` 会清 `%rax` 高 32 位，但字节和两字节操作不会照此清除其余位。教师明确说这条规则容易混淆，需要记住。
- **反转 `cmpq` 的阅读注释**（`00:16:29-00:16:49`）：看到 `cmpq %rsi, %rdi` 时写 `# x:y`，用于避免误读成 `y-x`。
- **汇编格式不等于语义**（`00:14:54-00:16:00`）：缩进错误令课件看起来不规范，但汇编器仍可接受；标签和指令的视觉层次主要帮助阅读。

## 本段掌握检查

1. **问：`testq %rax, %rax` 会不会改写 `%rax`？它能检查什么？**  
   **答：** 不会；它按 `%rax & %rax` 设置条件码。因 `x&x=x`，可由 `ZF` 判断是否为零、由 `SF` 判断按有符号数看是否为负。[课件: 06-machine-control.pptx p.6]

2. **问：为什么有符号“小于/大于”不能只看 `SF`？**  
   **答：** 最近的减法可能发生补码有符号溢出，表面的结果符号会受 `OF` 影响；因此课件中的 `setl/setg` 都组合了 `SF` 与 `OF`。[课件: 06-machine-control.pptx p.7]

3. **问：执行 `cmpq %rsi, %rdi; setg %al` 时，比较的关系是什么，写了多少位？**  
   **答：** 比较 `%rdi-%rsi`，即 `x-y`，判断有符号 `x>y`；`setg` 只把 `%al` 这一个字节写为 `0` 或 `1`。

4. **问：为什么 `setg %al` 后还要执行 `movzbl %al, %eax`？**  
   **答：** `setg` 不改 `%rax` 的其他七个字节；`movzbl` 先把 `%al` 零扩展到 `%eax`，再借助 32 位写入会清高 32 位的规则，使整个 `%rax` 成为 0 或 1。[课件: 06-machine-control.pptx p.9]

5. **问：本段给出的两种常见条件码使用方式是什么？**  
   **答：** 用 `SetX` 把条件物化为普通寄存器中的 `0/1`，或用条件跳转改变控制流；本段展开前者，后者在下一段展开（`00:11:41-00:12:14`）。

# 第 3 节：用条件跳转实现分支

> 时间范围：`00:19:58-00:29:52`  
> 课件范围：[课件: 06-machine-control.pptx p.10] [课件: 06-machine-control.pptx p.11] [课件: 06-machine-control.pptx p.12] [课件: 06-machine-control.pptx p.13] [课件: 06-machine-control.pptx p.14]

## 本段在整讲中的作用

上一段用 `SetX` 把一次比较压缩成 `0/1`。本段把同一组条件码用于更一般的问题：不是只返回一位，而是决定接下来执行哪一片代码，从而实现 C 的 `if/else`。[课件: 06-machine-control.pptx p.10] [课件: 06-machine-control.pptx p.11]

教师先讲传统、通用的条件跳转，再用 `absdiff` 逐行映射 C 与汇编；随后把低层汇编提升为带标签和 `goto` 的 C 形态，最后开始归纳编译器翻译任意条件表达式的模板。更专门的新方法“条件传送”只在本段开头预告，下一段才展开比较。

## 教学展开

### 1. 为什么一位结果还不够（`00:19:58-00:20:35`）

教师从上一段的布尔结果出发：有时只要比较得到的一个 bit，但更常见的需求是根据比较结果“做不同的事”，最简单的高级语言形式就是 `if`，以及可能存在的 `else`。

课堂预告有两种实现路线：

1. 传统且最通用的 jump；
2. 较新、适用范围更窄的 conditional move。

本段先处理第一种。

### 2. jump 改变顺序执行路径（`00:20:36-00:21:32`）

普通情况下，指令按顺序一条接一条执行。jump 可以把控制点从当前位置转到另一位置，因此既可以跳过一段指令，也可以跳回先前位置。[课件: 06-machine-control.pptx p.11]

教师在口述中区分：

- **无条件跳转**：执行到 jump 就一定跳；
- **条件跳转**：只有条件码满足相应组合才跳，否则继续执行下一条指令。

`jX` 的后缀条件与前一段 `SetX` 的条件命名相呼应；程序因而可以读取同一批条件码，选择“taken（跳转）”或“fall through（顺序落下）”。

### 3. 用 `absdiff` 构造两个互斥分支（`00:21:33-00:22:45`）

示例函数计算两个 `long` 的差的非负版本：[课件: 06-machine-control.pptx p.12]

```c
long absdiff(long x, long y)
{
    long result;
    if (x > y)
        result = x-y;
    else
        result = y-x;
    return result;
}
```

逻辑分解为：

$$
result =
\begin{cases}
x-y, & x>y \\
y-x, & x\le y
\end{cases}
$$

教师同时给出证据边界：这个示例用于说明控制流，并没有解决涉及 `TMin` 时的绝对值问题；课堂明确说这里暂不处理（`00:22:13-00:22:21`）。因此不能把它无条件当成所有机器整数上的数学绝对值实现。

### 4. 逐行追踪传统分支汇编（`00:22:46-00:25:02`）

课件中的汇编是：[课件: 06-machine-control.pptx p.12]

```asm
absdiff:
    cmpq    %rsi, %rdi  # x:y
    jle     .L4
    movq    %rdi, %rax
    subq    %rsi, %rax
    ret
.L4:                    # x <= y
    movq    %rsi, %rax
    subq    %rdi, %rax
    ret
```

按实际控制路径解释：

1. `x` 位于 `%rdi`，`y` 位于 `%rsi`。`cmpq %rsi, %rdi` 按 `x-y` 设置条件码；注释 `x:y` 是教师用于反转 AT&T 操作数阅读顺序的提示（`00:22:46-00:23:00`）。
2. `jle .L4` 检查有符号 `x<=y`。成立时跳到 `.L4`；不成立时顺序执行紧随其后的 `x-y` 分支。
3. 当 `x>y` 时，先把 `x` 复制到返回寄存器 `%rax`，再执行 `subq %rsi, %rax`，得到 `%rax=x-y`，随后直接 `ret`。
4. 当 `x<=y` 时，`.L4` 分支先把 `y` 复制到 `%rax`，再减 `x`，得到 `%rax=y-x`，随后直接 `ret`。
5. 两条路径都在返回前把结果放进 `%rax`，调用者由约定从这里取得函数返回值（`00:24:25-00:24:47`）。

这段代码把 then 与 else 编译成两个独立区域，每次调用只执行其中一个区域。[课件: 06-machine-control.pptx p.14]

### 5. 标签是面向汇编阅读者的跳转名字（`00:23:01-00:23:50`）

名字后加冒号形成 label，例如 `.L4:`。教师解释：标签是汇编表示中的 tag，帮助读者直接看出跳转落点；它不会以这个名字原样留在最终 object code，而是在后续过程中用于确定并编码目标地址。与只看裸地址相比，标签让控制流结构更容易辨认。

因此阅读时应把：

```asm
jle .L4
```

理解为“若当前条件码表示 `x<=y`，则把下一控制点改到 `.L4` 对应的位置”。

### 6. 为什么先 `movq` 再 `subq`（`00:25:03-00:26:13`）

学生提问后，教师给出两个相互关联的原因：

1. 函数结果最终必须位于 `%rax`；
2. 本例中的 `subq` 是二操作数指令，第二个操作数既是输入也是被覆盖的目的。

所以常见模式是先把一个操作数移入 `%rax`，再把 `%rax` 作为算术目的更新：

```asm
movq %rdi, %rax          # %rax = x
subq %rsi, %rax          # %rax = %rax - y
```

教师把这种受二操作数形式约束的写法类比为 C 中总要写 `x += something`、`x -= something`，而不是任意三操作数表达式（`00:25:55-00:26:08`）。

### 7. 用 `goto` C 代码抽象汇编控制流（`00:26:15-00:28:45`）

教师认为长时间逐条看汇编会妨碍抓住结构，因此采用“仍是 C、但看起来像汇编”的中间表示。C 的 `goto` 和 label 正好对应 jump 与汇编 label：[课件: 06-machine-control.pptx p.13]

```c
long absdiff_j(long x, long y)
{
    long result;
    int ntest = x <= y;
    if (ntest) goto Else;
    result = x-y;
    goto Done;
Else:
    result = y-x;
Done:
    return result;
}
```

这里 `ntest` 是原始条件 `x>y` 的否定。若 `ntest` 成立，就跳过 then 区域进入 `Else`；否则先算 `x-y`，再用无条件 `goto Done` 跳过 else 区域。`Else` 和 `Done` 是标签名，不是 C 的 `else` 关键字。

教师说明编译器可能生成“各分支直接返回”或“跳到公共返回点”这两种形态；具体选择在这个例子中不承载新的语义。本课程后续会多用 goto 形式展示控制结构，以便识别模式，而不必每次陷入寄存器和单条指令细节（`00:27:33-00:28:09`）。

### 8. 从特例归纳一般条件表达式翻译（`00:28:46-00:29:52`）

教师要求从“假设自己在写编译器”的角度，把 `absdiff` 推广为一般规则。高级语言表达式为：[课件: 06-machine-control.pptx p.14]

```c
val = Test ? Then_Expr : Else_Expr;
```

课件给出的分支翻译模板为：

```c
ntest = !Test;
if (ntest) goto Else;
val = Then_Expr;
goto Done;
Else:
val = Else_Expr;
Done:
/* 后续代码 */
```

本段口述在“取反测试并准备跳往 else”处截断；其余 then/else 区域及重新汇合由课件完整给出，并在下一片段开头继续口述。

## 概念、符号与推导

### 条件跳转的抽象语义

```text
先前的 cmp/test/算术指令
          |
          v
      CF/ZF/SF/OF
          |
          v
      jX target
       /      \
条件真       条件假
跳到 target   fall through
```

`jle .L4` 不是重新比较寄存器；它读取此前 `cmpq` 留下的条件码。若中间插入会改写条件码的指令，`jle` 所依据的就不再是原来的比较。这一点来自本讲“条件指令读取最近相关结果”的整体链条，本例通过让 `cmpq` 与 `jle` 相邻来保证关系明确。

### `absdiff` 的控制流推导

```text
cmp x:y
  |
  +-- x <= y --跳到 .L4--> %rax = y - x --> ret
  |
  +-- x > y ---顺序落下--> %rax = x - y --> ret
```

它把一个 C `if/else` 翻译成两个互斥代码区域。两个区域都写同一个返回位置 `%rax`，因而无需在返回后再合并数据。

### 一般翻译规则

本段没有独立的数值公式推导；核心是控制流等价变换：[课件: 06-machine-control.pptx p.14]

1. 令 `ntest = !Test`。
2. `ntest` 为真时跳往 `Else`，于是不会求值 `Then_Expr`。
3. `ntest` 为假时顺序求值 `Then_Expr`，随后无条件跳过 else 区域。
4. `Else` 区域只在原 `Test` 为假时执行。
5. 两条路径在 `Done` 汇合，再继续后续程序。

这个结构保证每次只执行 `Then_Expr` 与 `Else_Expr` 中的一个。

5. **问：一般的 `Test ? Then_Expr : Else_Expr` 怎样翻译成 goto 结构？**

# 第 4 节：条件传送与 do-while 循环引入

> 时间范围：`00:29:52-00:39:52`  
> 课件范围：[课件: 06-machine-control.pptx p.15] [课件: 06-machine-control.pptx p.16] [课件: 06-machine-control.pptx p.17] [课件: 06-machine-control.pptx p.18] [课件: 06-machine-control.pptx p.19] [课件: 06-machine-control.pptx p.20]

## 本段在整讲中的作用

本段先完成上一片段尚未说完的分支翻译：then 与 else 是分离的代码区，执行其中一边后在 `Done` 汇合。然后教师引入实现条件表达式的第二条路线 conditional move，并回答两个核心问题：为什么“把两边都算出来”有时反而更快，以及为什么它不能用于所有条件表达式。[课件: 06-machine-control.pptx p.15] [课件: 06-machine-control.pptx p.17]

条件结构结束后，课程进入更高一层控制结构 loops。片段末尾以 `do-while` 为最容易翻译的循环，并用 `pcount_do` 展示“执行 body -> 测试 -> 条件跳回”的骨架。[课件: 06-machine-control.pptx p.18] [课件: 06-machine-control.pptx p.19]

## 教学展开

### 1. 补完基于 jump 的一般条件翻译（`00:29:52-00:31:23`）

承接上一片段的 `ntest=!Test`：

1. 若 `ntest` 为真，即原始 `Test` 为假，就跳到编译好的 else 表达式区域（`00:29:52-00:30:06`）。
2. 若 `ntest` 为假，即原始 `Test` 成立，就顺序执行 then 表达式区域（`00:30:06-00:30:18`）。
3. 若整个条件结构只是一个小函数，各分支可以直接返回；若后面还有代码，两条路径通常要重新汇合并继续（`00:30:18-00:30:38`）。
4. 学生确认：执行完 `Else` 后可直接 fall through 到 `Done`；教师回答是（`00:31:03-00:31:18`）。

教师强调，课程虽然不要求编写编译器，但用“一般翻译规则”思考有助于看到汇编时识别模式，而不是把每条 jump 当成孤立指令（`00:30:42-00:31:01`）。

### 2. 条件传送看似浪费，却可能更高效（`00:31:24-00:32:08`）

传统 jump 是最一般、过去一直使用的做法。conditional move 是另一种常见优化，其基本策略与 `if/else` 的直觉相反：

1. 先计算 `Then_Expr` 的值；
2. 再计算 `Else_Expr` 的值；
3. 最后根据条件只选择其中一个。

这样看似多算了一边，但当两边都很简单时，课堂指出它可能比控制转移更高效。[课件: 06-machine-control.pptx p.15]

### 3. 为什么 branch 会打断处理器流水（`00:32:09-00:34:39`）

教师用“海上油轮”作类比：现代处理器沿一条直线指令流前进时很高效，但突然停下或转向代价较大。这里的技术解释是 pipelining：处理器在前一批指令尚未全部完成时，已经取入并处理后续指令；课堂说这种前瞻深度可达 20 条以上（`00:32:36-00:32:59`）。

遇到条件 branch 时，处理器必须猜测它会：

- taken：跳到目标；或
- fall through：继续下一条。

这个过程叫 branch prediction。教师给出的课堂估计是通常可达到约 98% 的正确率；猜对时流水继续高效前进，猜错时则要撤回错误方向并从另一方向重新开始，糟糕情况下可付出约 40 个 clock cycles（`00:33:06-00:33:54`）。这些数字是本次口述中的概略量级，不应脱离课堂语境解释为所有处理器的固定常数。

绝对值是难预测的例子：若输入正负近似不可预测，无论固定猜哪边，都可能约一半时间猜错（`00:33:55-00:34:09`）。conditional move 不转移控制，只在最后决定是否把一个值复制进寄存器，因而能保持直线指令流（`00:34:09-00:34:27`）。结论不是“永远更快”，而是教师的限定说法：它**有时**是好主意。

### 4. 一般条件传送模板（`00:34:40-00:35:38`）

课件把条件表达式改写为：[课件: 06-machine-control.pptx p.15]

```c
result = Then_Expr;
eval = Else_Expr;
nt = !Test;
if (nt) result = eval;
return result;
```

其中 `result` 先保存 then 值，`eval` 保存 else 值。测试完成后，一条条件传送指令实现抽象操作：

```text
if (Test) Dest <- Src
```

也就是说，源值和目的旧值都已准备好；条件成立才覆盖目的，不成立则保留目的原值。课件说明 conditional move 在 1995 年后的 x86 处理器中得到支持，GCC 会尝试使用，但只在编译器能够确定安全时采用。[课件: 06-machine-control.pptx p.15]

为展示传统 jump 版本，前一页示例编译时显式使用了 `-fno-if-conversion`，阻止 GCC 改用它倾向生成的条件传送。[课件: 06-machine-control.pptx p.12] 教师在此回看并说明了这个选项的目的（`00:35:15-00:35:37`）。

### 5. `absdiff` 的 `cmovle` 版本（`00:35:38-00:36:43`）

课件给出的实际汇编为：[课件: 06-machine-control.pptx p.16]

```asm
absdiff:
    movq    %rdi, %rax  # x
    subq    %rsi, %rax  # result = x-y
    movq    %rsi, %rdx
    subq    %rdi, %rdx  # eval = y-x
    cmpq    %rsi, %rdi  # x:y
    cmovle  %rdx, %rax  # if <=, result = eval
    ret
```

按教师讲解顺序追踪：

1. 前两条指令无条件计算 `result=x-y`，放在 `%rax`。
2. 接着两条指令无条件计算 `eval=y-x`，放在 `%rdx`。
3. `cmpq %rsi, %rdi` 设置描述 `x-y` 的条件码。
4. `cmovle %rdx, %rax` 中的 `le` 表示“less than or equal”，不是数据宽度后缀（`00:36:01-00:36:09`）。
5. 若 `x<=y`，把红色 else 值 `%rdx` 复制到结果 `%rax`；若 `x>y`，不复制，原先的 `%rax=x-y` 保持不变。
6. 最后 `ret`。整个序列同时算了两个候选值，但没有条件 jump。

### 6. 为什么不能总用 conditional move（`00:36:43-00:38:16`）

关键限制来自“两个候选表达式都会被求值”。教师依次给出三类坏情况：[课件: 06-machine-control.pptx p.17]

#### 6.1 计算昂贵

```c
val = Test(x) ? Hard1(x) : Hard2(x);
```

若一边要破解密码、另一边要寻找第 n 个素数，把两边都算完的浪费会远大于避免 branch 的收益（`00:36:50-00:37:07`）。所以课堂说只有两边都相对简单时才有意义。

#### 6.2 计算有风险

```c
val = p ? *p : 0;
```

原条件表达式用 `p` 保护指针解引用；当 `p` 可能为空时，传统分支不会求值 `*p`。若强行先算两边，就会执行原本应被跳过的潜在空指针解引用（`00:37:21-00:37:44`）。

#### 6.3 计算有副作用

```c
val = x > 0 ? x*=7 : x+=3;
```

两个表达式都会改变程序状态。若两边都执行，就不再等价于原来只选择一个分支的程序（`00:37:45-00:37:58`）。

因此课堂归纳的采用条件是：两个候选计算都比较容易、执行安全、没有副作用（`00:37:58-00:38:13`）。

### 7. 从条件结构进入循环（`00:38:17-00:39:17`）

完成 conditionals 后，教师转向控制结构的下一层 loops。[课件: 06-machine-control.pptx p.18] C 有 `while`、`for` 和 `do-while` 三种循环。教师说自己很少在实际 C 代码中使用 `do-while`，但它最容易实现，所以从它开始。

`do-while` 的关键顺序是：

```text
先执行 body -> 再执行末尾 test -> test 成立则返回 body
```

它与普通 `while` 的直观差别是测试位置：`while` 把测试放在前面，而 `do-while` 把测试放在末尾（`00:38:50-00:39:12`）。因此用 goto 表示时，只需在 body 后测试，成立就跳回刚才的 label，控制流形成环。

### 8. `pcount_do` 示例及课件中的编译结果（`00:39:18-00:39:52`）

课件用 popcount 示例展示该结构：[课件: 06-machine-control.pptx p.19]

```c
long pcount_do(unsigned long x)
{
    long result = 0;
    do {
        result += x & 0x1;
        x >>= 1;
    } while (x);
    return result;
}
```

对应 goto 形态为：

```c
long pcount_goto(unsigned long x)
{
    long result = 0;
loop:
    result += x & 0x1;
    x >>= 1;
    if (x) goto loop;
    return result;
}
```

每轮先用 `x & 0x1` 取得最低位并累加，再把 `x` 右移一位；只要移位后的 `x` 非零就跳回 `loop`。课件把函数目的写为统计参数 `x` 中 `1` 的个数，即 popcount。[课件: 06-machine-control.pptx p.19]

对应汇编也已列在课件中：[课件: 06-machine-control.pptx p.20]

```asm
movl    $0, %eax        # result = 0
.L2:                    # loop:
    movq    %rdi, %rdx
    andl    $1, %edx    # t = x & 0x1
    addq    %rdx, %rax  # result += t
    shrq    %rdi        # x >>= 1
    jne     .L2         # if (x) goto loop
    rep; ret
```

这段汇编保持了 goto 版本的顺序：初始化一次，进入 `.L2` 执行 body，`shrq` 后由 `jne .L2` 决定是否回到循环头。需要注意，本片段在教师刚说出函数名 “pop count” 时结束；对 p.20 汇编的逐行口述发生在下一片段，因此这里的映射只依据课件注释和本段已经讲清的 do-while/goto 规则。

## 概念、符号与推导

### 分支版与条件传送版的求值差异

对：

```c
val = Test ? Then_Expr : Else_Expr;
```

两种翻译的核心差异是：

| 路线 | 候选表达式求值 | 控制是否转移 | 主要约束 |
| --- | --- | --- | --- |
| 条件 jump | 只求值被选中的一边 | 是 | 最通用 |
| conditional move | 先求值两边，再选择结果 | 否 | 两边需简单、安全、无副作用 |

条件传送的状态推导为：[课件: 06-machine-control.pptx p.15]

```text
result <- Then_Expr
eval   <- Else_Expr
nt     <- !Test
if nt:
    result <- eval
return result
```

- `Test=true` 时，`nt=false`，不覆盖 `result`，返回 then 值。
- `Test=false` 时，`nt=true`，以 `eval` 覆盖 `result`，返回 else 值。

### `absdiff` 的寄存器推导

$$
RAX_0 = x-y
$$

$$
RDX = y-x
$$

执行 `cmpq %rsi,%rdi` 后：

$$
RAX_{final} =
\begin{cases}
RDX=y-x, & x\le y \\
RAX_0=x-y, & x>y
\end{cases}
$$

`cmovle` 只选择是否覆盖 `%rax`，不会跳到另一代码位置。[课件: 06-machine-control.pptx p.16]

### do-while 到 goto 的结构推导

```c
do {
    Body;
} while (Test);
```

在本段给出的规则下改写为：

```c
loop:
    Body;
    if (Test) goto loop;
```

推导关键不是数值公式，而是执行顺序保持一致：第一次到达时不做入口测试，先执行 `Body`；每轮末尾测试，真则回边，假则 fall through。

### `pcount_do` 的单轮状态变化

令本轮开始时的值为 `x_k`、累计值为 `result_k`，课件代码对应：

$$
result_{k+1}=result_k+(x_k\mathbin{\&}1)
$$

$$
x_{k+1}=x_k \mathbin{\texttt{>>}} 1
$$

随后以 `x_{k+1}` 是否非零决定是否跳回。这里仅把 p.19 代码逐句符号化，没有补充课件和 transcript 之外的复杂度或位宽结论。

## 本段掌握检查

1. **问：为什么 conditional move 可能比条件 jump 快，即使它计算了两个候选值？**  
   **答：** 当两边计算很简单时，避免控制转移可保持流水线沿直线指令流推进；错误 branch prediction 可能需要撤回并重启，而 conditional move 最后只决定是否复制一个寄存器值（`00:31:45-00:34:27`）。

2. **问：`cmovle %rdx, %rax` 在 `absdiff` 中何时覆盖 `%rax`，覆盖成什么？**  
   **答：** `cmpq` 表明 `x<=y` 时覆盖，把 `%rdx` 中的 `y-x` 复制到 `%rax`；否则保留原先的 `%rax=x-y`。[课件: 06-machine-control.pptx p.16]

3. **问：conditional move 的三个课堂限制是什么？**  
   **答：** 两边应当计算简单、执行安全、没有副作用；否则会分别造成无谓成本、执行原本被 guard 的危险操作，或改变程序状态。[课件: 06-machine-control.pptx p.17]

4. **问：为什么 `val = p ? *p : 0` 不适合先算两边再条件传送？**  
   **答：** 当 `p` 为空时，原条件表达式不会执行 `*p`；先算两边却会尝试空指针解引用，破坏原程序的安全语义。

5. **问：`do-while` 的 goto 版本为什么保证 body 至少走到一次？**  
   **答：** 控制直接进入 `loop:` 后的 `Body`，测试位于 body 末尾；只有完成第一次 body 后才决定是否跳回。[课件: 06-machine-control.pptx p.19]

# 第 5 节：循环的机器级翻译

> 时间范围：`00:39:52-00:49:49`

## 本段在整讲中的作用

本段把前文已经建立的“测试条件 + 条件跳转”机制扩展到循环。片段开头仍在收束前一页的 `popcount` 示例：目标是统计一个数据字中有多少个二进制 `1`，关键机器级动作是执行循环体、测试继续条件，再用一条回跳指令回到先前的代码位置（`00:39:52-00:40:51`）。随后老师依次处理 `do-while`、`while` 和 `for`，说明高级语言中看似不同的循环，最终都可改写成少量标签、测试和 `goto`。[课件: 06-machine-control.pptx p.21] [课件: 06-machine-control.pptx p.22] [课件: 06-machine-control.pptx p.27]

与前文的具体连接是：前文已经讲过条件码与条件跳转，本段不再重新解释条件码，而是把条件跳转用于“向后跳”，由此形成重复执行。片段末尾则明确表示循环的低级实现大体符合直觉，下一段将转向更不直观的 `switch`（`00:49:40-00:49:49`）。

## 教学展开

### 1. 从 `popcount` 的回跳抽象出 `do-while`（`00:39:52-00:41:14`）

老师先回到“一个数据字里有多少个 `1`”的问题；本例讨论的是 64-bit word（`00:39:52-00:39:58`）。他提到过去某些 Data Lab 作业会要求只用有限数量的基本运算完成该函数，但本节目的不是做这种运算数约束练习，而是观察循环怎样降到低级控制流（`00:39:58-00:40:17`）。

在实际汇编中，最值得看的不是逐条指令，而是末尾一条“若不等则跳到 `.L2`”的跳转：它把执行位置带回循环体开头（`00:40:34-00:40:51`）。老师据此抽象出 `do-while` 的一般结构：[课件: 06-machine-control.pptx p.21]

```c
do
    Body
while (Test);
```

可写成只含标签和跳转的形式：

```c
loop:
    Body
    if (Test)
        goto loop;
```

执行链严格是 **先执行 `Body` -> 再计算 `Test` -> 若测试成立则回到 `loop`**。因此 `do-while` 无论初始条件如何，循环体都至少执行一次（`00:40:57-00:41:14`）。

### 2. 比较 `do-while` 与 `while` 的首次测试（`00:41:14-00:41:45`）

`while` 与 `do-while` 的核心差异不是后续回跳，而是第一次执行循环体之前是否测试：

- `do-while` 第一次不先测试，保证执行一次 `Body`；
- `while` 在入口处就测试；若初始条件为假，直接越过整个循环，执行零次 `Body`。

因此，把 `while` 翻译为低级控制流时，必须额外解决“怎样在第一次迭代前先做测试”的问题。

### 3. `while` 翻译一：jump-to-middle（`00:41:45-00:44:51`）

老师说明生成 `while` 代码并不只有一种方法，GCC 在课堂涉及的设置下会出现两种。本课程主要使用 `-Og`：它会做一些简单优化，同时仍便于把机器代码与 C 代码对应起来；更高优化级别可能大幅重写程序。老师补充，实践中公司常见 `-O2`，但课程有意降低优化程度以利于阅读（`00:41:45-00:43:08`）。

在 `-Og` 下，课件给出的第一种形式叫 **jump-to-middle translation**；老师特别说明这是他自己的命名，不应预期在其他资料中必然见到（`00:43:08-00:43:23`）：[课件: 06-machine-control.pptx p.22]

```c
goto test;
loop:
    Body
test:
    if (Test)
        goto loop;
done:
```

推导顺序如下：

1. 先保留 `do-while` 式的 `loop -> Body -> test -> 回跳` 骨架。
2. 在进入循环时执行一次无条件 `goto test`，直接跳到原循环结构中部的测试位置。
3. 若第一次 `Test` 为真，再跳回 `loop` 执行第一次循环体；若为假，则落到 `done`。
4. 一旦进入循环，后续迭代就与 `do-while` 相同：执行体、测试、成立则回跳（`00:43:23-00:44:42`）。

课件用 `pcount_while` 展示这一改写：[课件: 06-machine-control.pptx p.23]

```c
long pcount_while(unsigned long x) {
    long result = 0;
    while (x) {
        result += x & 0x1;
        x >>= 1;
    }
    return result;
}
```

对应的 jump-to-middle 版本先 `goto test`；测试 `x` 后才决定是否进入 `loop`。循环体把最低位 `x & 0x1` 加到 `result`，再将 `x` 右移一位。老师指出，对这个特定函数而言，写成 `do-while` 或 `while` 会得到相同结果（`00:44:00-00:44:21`）；这里是对该函数结果的判断，不是说两类循环一般都语义相同。

### 4. `while` 翻译二：先用条件保护入口（`00:44:51-00:46:10`）

第二种方法在 `-O1` 下会出现。思路是先把 `while` 看成 `do-while`，再在它前面加一个入口保护条件（`00:44:51-00:45:30`）：[课件: 06-machine-control.pptx p.24]

```c
if (!Test)
    goto done;
loop:
    Body
    if (Test)
        goto loop;
done:
```

这里的控制链是：

1. 入口先测 `!Test`；若原条件为假，立即跳到 `done`。
2. 否则进入 `loop`，至少完成这一轮 `Body`。
3. 循环尾部重新测试原条件，成立则回跳。

`pcount_while` 的对应版本把入口保护具体化为 `if (!x) goto done;`，之后的循环体与尾部 `if (x) goto loop;` 都保持不变。[课件: 06-machine-control.pptx p.25] 因而它与 jump-to-middle 的控制流形状不同，却保持相同的 `while` 入口语义。老师没有在本段展示这两种版本的完整汇编，只说明课程目录中的代码会按所述方式对应（`00:45:51-00:46:10`）。

### 5. 拆解 `for` 的四个组成部分（`00:46:10-00:47:30`）

第三类循环是 C 中常用而且很一般的 `for`。老师把它拆为四部分（`00:46:16-00:46:40`）：[课件: 06-machine-control.pptx p.26]

```c
for (Init; Test; Update)
    Body
```

在 `pcount_for` 中，四部分分别是：

| 组成部分 | 本例代码 | 作用 |
| --- | --- | --- |
| `Init` | `i = 0` | 从第 0 位开始 |
| `Test` | `i < WSIZE` | 只在索引仍处于检查范围时继续 |
| `Update` | `i++` | 每轮转到下一位 |
| `Body` | `bit = (x >> i) & 0x1; result += bit;` | 取出第 `i` 位并累加 |

课件定义 `WSIZE` 为 `8 * sizeof(int)`；老师口述解释为“一个 `int` 有多少字节，再乘 8 得到位数”（`00:47:05-00:47:22`）。本例不再通过不断修改 `x` 来终止，而是让索引 `i` 依次检查固定数量的位。

### 6. 用 `while` 给出 `for` 的行为语义（`00:47:30-00:48:40`）

老师把下面的改写称为理解 C `for` 行为的一条一般规则：[课件: 06-machine-control.pptx p.27]

```c
Init;
while (Test) {
    Body
    Update;
}
```

顺序不能交换：`Init` 只在进入循环前执行一次；每轮先检查 `Test`；成立后执行 `Body`，然后执行 `Update`；接着回到下一次 `Test`（`00:47:47-00:48:08`）。把 `pcount_for` 的四块代入后，就得到课件中的 `pcount_for_while`：[课件: 06-machine-control.pptx p.28]

```c
i = 0;
while (i < WSIZE) {
    unsigned bit = (x >> i) & 0x1;
    result += bit;
    i++;
}
```

老师指出，实际编写 C 时选 `for` 还是 `while` 有时只是风格偏好；对机器级分析而言，可以先按此规则统一成 `while`，再套用前面的翻译（`00:48:08-00:48:40`）。

### 7. `-O1` 为什么可能消掉初始保护测试（`00:48:43-00:49:40`）

把 `for` 先改成 `while`、再改成入口受保护的 `do-while`，一般会得到：[课件: 06-machine-control.pptx p.29]

```c
i = 0;
if (!(i < WSIZE))
    goto done;
loop:
    Body
    i++;
    if (i < WSIZE)
        goto loop;
done:
```

本例中，初始化后 `i = 0`，而 `WSIZE` 通常为 32，所以第一次 `i < WSIZE` 必然为真（`00:48:52-00:49:12`）。编译器能证明这一点，便可删除入口处本来用于保护循环的初始测试，直接进入循环体。[课件: 06-machine-control.pptx p.29] 老师认为，这正是 `-O1` 常采用这种转换的重要原因：很多具体循环的初始测试可以被证明为恒真（`00:49:12-00:49:35`）。

## 概念、符号与推导

### 1. 三种循环的统一控制流元素

- `Body`：每轮要执行的循环体。
- `Test`：决定是否执行或继续执行循环的条件。
- `Init`：`for` 在第一次测试前执行一次的初始化。
- `Update`：`for` 在每轮循环体之后、下一次测试之前执行的更新。
- `loop`、`test`、`done`：低级改写中的代码标签，分别表示循环体入口、测试位置和循环结束位置。

这些标签不是 C 循环额外产生的数据，而是用于描述控制可以跳到哪里。[课件: 06-machine-control.pptx p.21] [课件: 06-machine-control.pptx p.22]

### 2. 首次执行次数的语义条件

设初始测试结果为 `Test_0`：

| 源循环 | `Test_0 == false` 时 `Body` 执行次数 | 保持语义所需的低级结构 |
| --- | ---: | --- |
| `do-while` | 至少 1 次 | 先执行 `Body`，尾部再测 |
| `while` | 0 次 | 首轮前必须到达 `Test` |
| `for` | 0 次 | `Init` 后、首轮 `Body` 前必须测 `Test` |

这就是两种 `while` 改写都必须增加入口控制的原因：jump-to-middle 用 `goto test`，do-while conversion 用 `if (!Test) goto done`。

### 3. `for -> while -> goto` 的逐步推导

第一步，按 C `for` 的行为规则改写：[课件: 06-machine-control.pptx p.27]

```text
for (Init; Test; Update) Body
=> Init; while (Test) { Body; Update; }
```

第二步，选择入口保护式 `while` 翻译：[课件: 06-machine-control.pptx p.24]

```text
Init;
if (!Test) goto done;
loop:
    Body;
    Update;
    if (Test) goto loop;
done:
```

第三步，若编译器能证明初始化后的第一次 `Test` 恒真，则删除 `if (!Test) goto done`；`Body -> Update -> Test -> 回跳` 的循环核心保持不变。[课件: 06-machine-control.pptx p.29]

### 4. `pcount_for` 的位提取与累加

第 `i` 轮执行：

```c
unsigned bit = (x >> i) & 0x1;
result += bit;
```

`x >> i` 把要检查的位移到最低位，`& 0x1` 只保留该最低位，得到 `0` 或 `1`，再把它加入 `result`。[课件: 06-machine-control.pptx p.26] 依次令 `i = 0, 1, ...` 并在 `i < WSIZE` 时继续，便完成课件所定义范围内的逐位计数。这里没有超出上述代码的额外公式推导。

## 例子与课堂提示

- **只抓住回跳而不是逐条展开汇编**（`00:40:34-00:40:51`）：老师略过 `popcount` 汇编的大部分细节，要求先识别“条件成立就跳回 `.L2`”这一循环骨架；它服务于从具体汇编抽象出一般 `do-while` 翻译。
- **不要把 `while` 与 `do-while` 一般化为等价**（`00:41:14-00:41:41`）：二者在初始条件为假时分别执行 0 次和至少 1 次。老师只说本例 `pcount` 的结果相同。[课件: 06-machine-control.pptx p.23]
- **jump-to-middle 是课堂命名**（`00:43:12-00:43:23`）：该名称有助于理解 `goto test` 的位置，但老师明确说这是自己的叫法。
- **优化级别影响代码形状**（`00:41:54-00:43:08`）：`-Og` 的目标在本课程中是兼顾简单优化与可读性；`-O1` 可能生成另一种循环形状；老师口述实践中 `-O2` 很常见。不能仅凭源代码循环类型断言汇编一定只有一种模板。
- **`for` 更新的位置易放错**（`00:47:47-00:48:08`）：`Update` 在 `Body` 之后、下一次 `Test` 之前。若把它放到循环体前，或忘记在回测前执行，就不再是课件给出的 `for` 语义。[课件: 06-machine-control.pptx p.27]
- **初始测试只能在可证明时删除**（`00:48:52-00:49:35`）：本例由 `i = 0` 和通常为 32 的 `WSIZE` 得出首次测试恒真；不能把“删除入口保护”当作所有 `for` 循环都成立的固定规则。

## 本段掌握检查

1. **问：`do-while` 的一般 goto 版本按什么顺序执行？为什么循环体至少执行一次？**  
   **答：** 从 `loop` 开始先执行 `Body`，再计算 `Test`，成立才 `goto loop`。第一次测试发生在第一次循环体之后，所以循环体至少执行一次。[课件: 06-machine-control.pptx p.21]

2. **问：jump-to-middle 怎样保持 `while` 在首轮前测试的语义？**  
   **答：** 入口先执行 `goto test`，越过循环体到达测试位置；只有 `Test` 成立才跳回 `loop`，否则落到 `done`。[课件: 06-machine-control.pptx p.22]

3. **问：入口保护式 `while` 翻译中的第一条条件跳转是什么，作用是什么？**  
   **答：** `if (!Test) goto done;`。它在原条件初始为假时跳过整个 `do-while` 式循环核心，使循环体执行零次。[课件: 06-machine-control.pptx p.24]

4. **问：`for (Init; Test; Update) Body` 改成 `while` 后，各部分顺序是什么？**  
   **答：** 先执行一次 `Init`；每轮先测 `Test`，成立后执行 `Body`，随后执行 `Update`，再回到下一次测试。[课件: 06-machine-control.pptx p.27]

# 第 6 节：`switch` 与跳转表入口

> 时间范围：`00:49:50-00:59:47`  
> 课件范围：[课件: 06-machine-control.pptx p.31] 至 [课件: 06-machine-control.pptx p.35]  
> 证据范围：本时间段 transcript 与上述课件页面。

## 本段在整讲中的作用

上一段已把 `do-while`、`while` 和 `for` 规约为测试与回跳；老师认为，如果被迫只用低级的 jump 和 test 来实现循环，这种翻译大体还能凭直觉推出（`00:49:50-00:50:03`）。本段转向更不直观的 `switch`：它通常不是一条很长的 `if-else-if` 链，而可由编译器生成代码块、地址表、范围检查和一次间接跳转。老师强调这类机器代码更难辨认，而且 Bomb Lab 会要求学生读懂它（`00:50:04-00:50:23`）。

本段先建立完整入口机制：复习 C `switch` 的 fall-through、多标签、缺失标签与 `default`，再抽象 jump table，最后分析示例函数怎样通过 `cmpq`、`ja` 和 `jmp *.L4(,%rdi,8)` 选择目标。各个目标代码块如何计算 `w`，留到下一段继续展开。

## 教学展开

### 1. 用一个纯教学示例列出 `switch` 的语义特征（`00:50:24-00:53:16`）

老师说明 `switch_eg` 本身没有实用目的，只用来展示 `switch` 如何翻译成汇编（`00:50:24-00:50:37`）。源程序为：[课件: 06-machine-control.pptx p.31]

```c
long switch_eg(long x, long y, long z)
{
    long w = 1;
    switch (x) {
    case 1:
        w = y * z;
        break;
    case 2:
        w = y / z;
        /* Fall Through */
    case 3:
        w += z;
        break;
    case 5:
    case 6:
        w -= z;
        break;
    default:
        w = 2;
    }
    return w;
}
```

老师按出现顺序强调四个特征：

1. **选择值与标签。** `switch` 检查某个整数值；每个 `case` 标签必须是常量整数值（`00:50:37-00:50:54`）。
2. **fall-through。** `case 2` 没有 `break`，所以先执行 `w = y / z`，随后直接继续执行 `case 3` 的 `w += z`（`00:51:00-00:51:20`）。
3. **多个标签共享代码。** `case 5` 后没有语句，直接进入 `case 6` 对应的 `w -= z`。老师把它解释为 fall-through 的一种特殊情况；这种并列标签本身很自然（`00:52:26-00:52:47`）。
4. **缺失标签与 `default`。** 若没有标签匹配，就走 `default`。本例包括 `x = 0`、负数、很大的数和内部缺口 `x = 4`；标签在源程序中也不要求按数值排序（`00:52:49-00:53:16`）。

老师对有实际语句的故意 fall-through 给出强烈编程建议：必须像示例一样加注释，明确说明这是有意行为，否则遗漏 `break` 很容易成为难查 bug（`00:51:22-00:52:20`）。这条建议针对 `case 2 -> case 3`；空的 `case 5` 与 `case 6` 共用代码不需要同样的警示注释。

### 2. 放弃“线性 `if-else-if`”直觉，建立跳转表模型（`00:53:18-00:55:54`）

若不能使用 `switch`，程序员很可能手写一条很长的 `if-else-if-...-else` 链，并猜测编译器也会如此实现；老师立即指出，本例的机器代码不是这样（`00:53:18-00:53:42`）。

跳转表方案分为三部分：[课件: 06-machine-control.pptx p.32]

1. 为各个 `case` 编译出独立代码块，每个代码块有一个入口地址 `Targ0`、`Targ1`、……。
2. 在内存中建立表 `JTab`；表项保存相应代码块的起始地址，并按 case 值覆盖的数值范围排列。
3. 用 `x` 像数组下标一样取出一个表项，再跳到该表项保存的地址：

```c
goto *JTab[x];
```

老师用 array indexing 类比：数组下标允许直接取中间元素，而不必从头逐项走过；跳转表同样能根据 `x` 直接定位代码块，不必依次测试许多条件（`00:54:52-00:55:35`）。在此处老师把收益表述为“一步知道该去哪里”，相对线性条件链平均要走过约一半条件（`00:55:35-00:55:54`）。

### 3. 确认参数寄存器并观察编译器延迟初始化（`00:55:57-00:56:31`，`00:58:45-00:59:09`）

本例三个参数与寄存器的对应关系为：[课件: 06-machine-control.pptx p.33]

| 源级值 | 寄存器 |
| --- | --- |
| `x` | `%rdi` |
| `y` | `%rsi` |
| `z` | `%rdx` |
| 返回值 | `%rax` |

入口第一条指令 `movq %rdx, %rcx` 把 `z` 复制到 `%rcx`。老师此时只说“出于某种原因”先做这份复制，后续代码块才显示 `%rcx` 会被用作 `z`（`00:56:21-00:56:31`）。

源代码虽写了 `long w = 1`，但入口汇编没有立即初始化 `w`。老师提醒先记住这一点：GCC 检查整个函数后，决定把所需初始化推迟到各目标代码块内部（`00:58:45-00:59:09`）。因此，入口处看不到 `w = 1` 不表示编译器遗漏了源程序语义；是否、在哪里需要值 `1`，要沿每条 case 路径继续追踪。[课件: 06-machine-control.pptx p.33]

### 4. 用一次无符号范围检查同时排除上界外和负值（`00:56:31-00:58:04`）

入口先执行：[课件: 06-machine-control.pptx p.33]

```asm
cmpq $6, %rdi        # compare x with 6
ja   .L8             # use default
```

数字 `6` 是本例最大的 case 值（`00:56:31-00:56:44`）。`.L8` 是 `default` 代码块，所以在查表前必须把不属于可查表范围的值送到 `.L8`。

这里使用 `ja`（jump above，无符号比较），而不是 `jg`（有符号 greater-than）。其效果是：

- 若有符号 `x > 6`，它按无符号解释也在 6 之上，跳到 `.L8`；
- 若有符号 `x < 0`，同一位模式按无符号解释会成为很大的正数，也在 6 之上，同样跳到 `.L8`；
- 只有 `0 <= x <= 6` 才继续执行间接跳转。

老师把这称为利用 signed/unsigned 表示关系的巧妙技巧：一条 unsigned “above” 检查同时覆盖上下两个越界方向（`00:57:07-00:58:04`）。

### 5. 间接跳转完成按表分派（`00:58:05-00:58:45`）

范围检查通过后执行：[课件: 06-machine-control.pptx p.34]

```asm
jmp *.L4(,%rdi,8)    # goto *JTab[x]
```

这条指令不是跳到写死的标签，而是：

1. 以 `.L4` 为跳转表首地址；
2. 用 `%rdi` 中的 `x` 作索引；
3. 每个表项是 8-byte 地址，所以索引乘 8；
4. 从有效地址 `.L4 + x * 8` 处取出目标地址；
5. 跳到取出的地址。

因此本例为 `x = 0` 到 `x = 6` 准备七个表项；只有已通过范围检查的值才允许执行该索引操作（`00:58:05-00:58:38`）。课件用两种语法作对比：[课件: 06-machine-control.pptx p.35]

```asm
jmp .L8              # direct jump：目标就是标签 .L8
jmp *.L4(,%rdi,8)    # indirect jump：从表中取出目标
```

### 6. 跳转表由汇编声明，地址由后续工具填定（`00:59:09-00:59:47`）

课件展示的表位于只读数据段，并按 8 字节对齐：[课件: 06-machine-control.pptx p.34]

```asm
.section .rodata
.align 8
.L4:
    .quad .L8        # x = 0
    .quad .L3        # x = 1
    .quad .L5        # x = 2
    .quad .L9        # x = 3
    .quad .L8        # x = 4
    .quad .L7        # x = 5
    .quad .L7        # x = 6
```

`.quad` 声明一个 8-byte 值；这里每个值最终是相应标签的地址。老师说明，汇编文本给出“需要一个指向某标签的 8-byte 值”这一框架，实际地址由 assembler 在确定标签位置后填入（`00:59:09-00:59:47`）。本段结束时这句话尚未完整收束，表项与源级 case 的逐项对应在下一段继续解释。

## 概念、符号与推导

### 1. 跳转表的抽象

设 case 覆盖可索引区间 `0` 到 `n - 1`，每个 `JTab[i]` 保存处理值 `i` 的代码入口，则扩展 C 形式为：[课件: 06-machine-control.pptx p.32]

```c
goto *JTab[x];
```

其中 `*` 表示跳转目标来自表项保存的地址，而不是语句中写死的标签。代码块在汇编文件中的物理排列顺序不决定分派关系；表项中的地址才决定每个索引去哪里。

### 2. 本例的有效地址推导

每个目标地址占 8 bytes，基址为 `.L4`，索引为 `x`，所以：[课件: 06-machine-control.pptx p.35]

$$
\text{entryAddress}(x) = \mathrm{L4} + 8x, \qquad 0 \le x \le 6
$$

然后从该内存位置读取 8-byte target，再令控制流跳到 target。注意 `.L4 + 8x` 是**表项自身的地址**；该表项中存的值才是代码块地址。

### 3. 一次 `ja` 完成双侧边界排除

逻辑目标是只让下面条件成立的 `x` 查表：

$$
0 \le x \le 6
$$

对其他值走 `default`：

$$
x < 0 \quad \lor \quad x > 6
$$

`cmpq $6, %rdi` 后采用无符号 `ja`。负的 signed `x` 重新按 unsigned 解释时是很大的值，因而与真正的 `x > 6` 一样满足 unsigned above。这样无需另加一条 signed lower-bound 分支（`00:57:07-00:57:57`）。

### 4. 七个索引与目标标签

| `x` | 表项 | 目标标签 | 源级含义 |
| ---: | --- | --- | --- |
| 0 | `.quad .L8` | `.L8` | 没有 `case 0`，走 `default` |
| 1 | `.quad .L3` | `.L3` | `case 1` |
| 2 | `.quad .L5` | `.L5` | `case 2` |
| 3 | `.quad .L9` | `.L9` | `case 3` |
| 4 | `.quad .L8` | `.L8` | 没有 `case 4`，走 `default` |
| 5 | `.quad .L7` | `.L7` | `case 5` |
| 6 | `.quad .L7` | `.L7` | `case 6` |

表项内容来自课件 p.34；本段只建立映射，重复标签与缺口如何体现源级结构由下一段详细分析。

## 例子与课堂提示

- **故意 fall-through 要写注释**（`00:51:51-00:52:20`）：`case 2` 既做除法又继续做 `case 3` 的加法。老师以自己忘写 `break` 导致 bug 的经验说明，注释是在告诉读者这里不是疏漏。[课件: 06-machine-control.pptx p.31]
- **多个空标签共享一段代码不等于危险的隐式行为**（`00:52:26-00:52:47`）：`case 5:` 紧接 `case 6:`，两者都执行 `w -= z`；老师认为这种并列写法无需额外 fall-through 警告注释。
- **`default` 不只处理“大于最大标签”**（`00:52:49-00:53:03`）：它还处理负值、最小标签以下的值以及区间内部的 hole，例如本例的 0 和 4。
- **不要把 jump table 当作代码块数组**（`00:54:02-00:55:29`）：表中存的是各代码块的**起始地址**；间接跳转先读地址，再转移控制。
- **查表之前必须保证索引范围**（`00:56:31-00:58:38`）：`jmp *.L4(,%rdi,8)` 只适用于 `0 <= x <= 6`。若跳过 `cmpq/ja` 而让负值或大值参与索引，就不符合本例控制流。[课件: 06-machine-control.pptx p.35]
- **入口没写 `w = 1` 不是源变量未初始化**（`00:58:45-00:59:09`）：这是编译器把初始化推迟到真正需要它的路径；分析时要逐路径寻找定义，不能只看函数开头。[课件: 06-machine-control.pptx p.33]
- **直接跳转与间接跳转易混**：`jmp .L8` 的目标由指令直接给出；`jmp *.L4(,%rdi,8)` 的目标值来自内存表项。[课件: 06-machine-control.pptx p.35]

# 第 7 节：跳转表、case 代码块与 fall-through 合流

> 时间范围：`00:59:47-01:09:42`  
> 课件范围：[课件: 06-machine-control.pptx p.36] 至 [课件: 06-machine-control.pptx p.40]  
> 证据范围：本时间段 transcript 与上述课件页面。

## 本段在整讲中的作用

上一段已经得到 `switch_eg` 的入口：先用 `ja .L8` 排除 `x < 0` 与 `x > 6`，再通过 `jmp *.L4(,%rdi,8)` 从七项跳转表中取出目标。本段继续回答两个尚未闭合的问题：表中的标签怎样编码缺失 case 与多标签共享，以及每个目标代码块怎样恢复源程序对 `w` 的计算。

老师先从 `.quad` 表项逐项读回 C 逻辑，再沿 `.L3`、`.L5`、`.L9`、`.L6`、`.L7` 和 `.L8` 追踪各条路径，重点解释 `case 2` 到 `case 3` 的 fall-through 如何变成共享后缀。最后借学生提问把单一示例推广到一般情况：负 case 值可加偏置，case 过于稀疏时不建巨大表，而改用经过组织的条件判断树（`01:06:32-01:09:02`）。

## 教学展开

### 1. `.quad` 表项按 `x = 0...6` 排列（`00:59:47-01:00:22`）

本段从上一句中途继续：`.quad` 声明的 8-byte 值最终要成为某个标签的地址；表项依次对应 `x = 0` 到 `x = 6`（`00:59:47-00:59:55`）。完整表为：[课件: 06-machine-control.pptx p.36]

```asm
.section .rodata
.align 8
.L4:
    .quad .L8        # x = 0
    .quad .L3        # x = 1
    .quad .L5        # x = 2
    .quad .L9        # x = 3
    .quad .L8        # x = 4
    .quad .L7        # x = 5
    .quad .L7        # x = 6
```

这些条目的顺序由索引值决定，而标签编号本身没有数值递增规律；`.L8`、`.L3`、`.L5` 等只是编译器生成的代码标签。

### 2. 表中的 hole 指向 `default`，多个 case 可重复同一地址（`01:00:22-01:01:37`）

源程序没有 `case 0` 和 `case 4`，所以索引 0 与 4 的表项都填 `.L8`；前一段入口的越界分支 `ja .L8` 也已表明 `.L8` 是 `default` 代码块（`01:00:22-01:00:46`）。这说明跳转表不会为区间内部的“洞”留一个不可用空位，而是让这些位置直接保存 default target。

另一方面，`case 5` 和 `case 6` 共用 `w -= z`，所以索引 5 与 6 都保存 `.L7`（`01:01:04-01:01:28`）。因此：

- 一个源级 case 值对应一个表项；
- 不同表项可以保存同一个目标地址；
- 缺失 case 与多标签共享都能只靠表项内容表达，不需要在查表后再做额外比较。[课件: 06-machine-control.pptx p.36]

### 3. 代码块可按任意物理顺序出现（`01:01:38-01:01:56`）

老师说明课件是从完整汇编 listing 中抽取小片段逐页展示；实际查看 `.s` 文件时，这些表和代码块会出现在同一份较长文本中（`01:01:38-01:01:52`）。各代码块无须按照 case 的数字顺序排列，因为跳转表已经保存其入口地址。分析时应从表项追标签，而不是把汇编文本从上到下的排列误认成 case 顺序。

### 4. `case 1`：乘法后直接返回（`01:01:57-01:02:43`）

`x == 1` 时跳到 `.L3`：[课件: 06-machine-control.pptx p.37]

```asm
.L3:
    movq  %rsi, %rax     # y
    imulq %rdx, %rax     # y * z
    ret
```

`%rsi` 保存 `y`，`%rdx` 保存 `z`，`%rax` 是返回值寄存器。先把 `y` 复制到 `%rax`，再乘 `z`，就得到源级 `w = y * z`。

源代码中 `break` 后只剩 `return w`；因此编译器没有让所有 case 汇合到唯一的公共 return 点，而直接在本代码块末尾放 `ret`（`01:02:01-01:02:42`）。这里的结论只适用于该函数布局：不能把“C 的 `break` 总会翻译成 `ret`”当作一般规则。

### 5. `case 2` 与 `case 3` 通过共享后缀实现 fall-through（`01:02:47-01:04:30`）

这两条路径必须区分 `w` 的来源：

- 从 `case 2` 进入时，先令 `w = y / z`，然后 fall through，再执行 `w += z`；
- 从 `case 3` 直接进入时，没有前面的除法，`w` 应保持源代码初始化值 `1`，然后执行 `w += z`。

课件先把逻辑重排为共享后缀：[课件: 06-machine-control.pptx p.38]

```c
case_3:
    w = 1;
case_2:
    w = y / z;
    goto merge;
merge:
    w += z;
```

这段示意的关键不是标签在文本中的先后，而是两条入口最终都到达 `merge`：`case 2` 带着 `y / z` 到达，`case 3` 带着 `1` 到达。实际汇编更清楚：[课件: 06-machine-control.pptx p.39]

```asm
.L5:                       # case 2
    movq  %rsi, %rax
    cqto
    idivq %rcx             # y / z
    jmp   .L6              # goto merge

.L9:                       # case 3
    movl  $1, %eax         # w = 1

.L6:                       # merge
    addq  %rcx, %rax       # w += z
    ret
```

路径追踪如下：

1. **`x == 2`：** `.L5` 计算 `y / z` 到 `%rax`，显式 `jmp .L6`，再加 `%rcx` 中的 `z`，返回 `(y / z) + z`。
2. **`x == 3`：** `.L9` 把 `%eax` 设为 1，随后自然落入紧接的 `.L6`，加 `z`，返回 `1 + z`。

老师称除法的指令写法很“quirky”，说明书中有讲，但本段不展开 `cqto/idivq` 的细节（`01:03:50-01:04:04`）。他还指出，写 `%eax` 的 32-bit `movl` 会把 `%rax` 高 32 位清零，所以装入正数 1 后可直接作为后续 64-bit 值使用（`01:04:12-01:04:30`）。

这个结构也解释了为何函数入口没有统一执行 `w = 1`：只有直接进入 `case 3`、`case 5/6` 等确实需要初值的路径才设置它；`case 2` 会完全覆盖 `w`，无需先写 1（`01:02:47-01:03:43`）。

### 6. 编译器生成表框架，汇编器填定地址（`01:04:30-01:05:11`）

一位学生就 jump table 提问，问题本身在 transcript 中不完整。老师回答时说明：课件展示的内容都可在编译器输出的 `.s` assembly file 中找到；编译器生成表的框架和标签引用，assembler 再把实际地址细节填入（`01:04:37-01:05:11`）。

这与 `.quad .L8` 的含义一致：编译器先声明该位置应保存 `.L8` 的地址，待各标签地址确定后再落实为具体值。老师一度想现场展示文件，随后放弃，改为口头确认该表确实由编译过程产生。

### 7. `case 5/6` 与 `default` 各自形成短代码块（`01:05:18-01:05:53`）

剩余路径为：[课件: 06-machine-control.pptx p.40]

```asm
.L7:                       # case 5, case 6
    movl $1, %eax          # w = 1
    subq %rdx, %rax        # w -= z
    ret

.L8:                       # default
    movl $2, %eax          # w = 2
    ret
```

- `.L7` 需要源级初值 `w = 1`，然后计算 `1 - z`。表中 `x = 5` 与 `x = 6` 都指向这里。
- `.L8` 直接把返回值设为 2，不需要先设置 `w = 1`。内部 hole `x = 0, 4` 与范围外值都可到达这里。

至此，所有源级 case 路径都已有对应代码块。老师再次提醒，它们在 `.s` 文件里可以按任意顺序串列，顺序不影响表驱动的控制流（`01:05:41-01:05:53`）。

### 8. 一般范围策略：先找最小值和最大值（`01:06:02-01:06:49`）

老师回应范围问题，再次指向入口的 `ja .L8`：若 `x < 0` 或 `x > 6`，直接走 default；只有 `0 <= x <= 6` 才使用索引（`01:06:02-01:06:31`）。

他把本例推广为一般过程：

1. 找出 case 值的最小值和最大值；
2. 对范围外的输入安排 default 路径；
3. 为范围内的值建立表，缺失值也填成 default target（`01:06:32-01:06:49`）。

### 9. 负 case 值：加偏置后从 0 开始索引（`01:06:50-01:07:21`，`01:08:17-01:08:44`）

学生问 case 可以是负数时如何索引。老师回答，编译器通常会有效地加一个 bias，让最低 case 值映射为 0，从而避免负下标（`01:06:50-01:07:19`）。

若最小 case 值为 `m`，口述策略可表示为：

```text
index = x - m
```

当 `x = m` 时，`index = 0`。老师稍后又用“最低值可能是 5700”重述同一原则：加或减一个固定偏置，使第一项落在索引 0（`01:08:17-01:08:44`）。本段没有给出对应汇编，只说明一般策略。

### 10. case 范围过于稀疏时，改用条件判断树（`01:07:23-01:09:02`）

另一位学生提出 case 可以相距很远，例如只有 `0` 和 `1,000,000`。老师指出，为两个 case 建一百万项的表并不合理；编译器会退回 `if-else` 式代码（`01:07:23-01:07:43`）。

但它不必按源代码顺序线性检查。因为所有 case 值在编译时都已知，编译器可以像 binary search 一样组织一棵条件判断树，使所需测试数量从线性级别降为对数级别（`01:07:43-01:08:02`）。究竟何时判定“太稀疏”由编译器自己的规则决定；老师建议可通过实验观察和 reverse engineer，但本段没有给出固定阈值（`01:08:45-01:09:02`）。

## 概念、符号与推导

### 1. 从源级 case 到结果的完整路径表

| `x` 的类别 | 入口目标 | 关键指令路径 | 返回结果 |
| --- | --- | --- | --- |
| `x == 1` | `.L3` | `y -> %rax; %rax *= z; ret` | `y * z` |
| `x == 2` | `.L5` | `y / z -> %rax; jmp .L6; %rax += z; ret` | `(y / z) + z` |
| `x == 3` | `.L9` | `%rax = 1;` fall through `.L6; %rax += z; ret` | `1 + z` |
| `x == 5` 或 `x == 6` | `.L7` | `%rax = 1; %rax -= z; ret` | `1 - z` |
| `x == 0` 或 `x == 4` | 表项指向 `.L8` | `%rax = 2; ret` | `2` |
| `x < 0` 或 `x > 6` | `ja .L8` | `%rax = 2; ret` | `2` |

表中计算均直接来自课件 p.36-p.40；没有引入源程序之外的 case。

### 2. fall-through 的共享后缀

设 `merge` 对应 `.L6`，则两条路径可写成：[课件: 06-machine-control.pptx p.39]

```text
x == 2:  w <- y / z  -> merge
x == 3:  w <- 1      -> merge
merge:   w <- w + z  -> return
```

共享的是 `w += z` 及其后的 `ret`，不是要求两条路径共享前置赋值。这个控制流把源程序的 fall-through 表达成“不同入口汇入同一后缀”。

### 3. hole 与共享标签在表中的编码

设 `D` 为 default target，`S` 为共享 target：

```text
JTab[0] = D, JTab[4] = D       // range 内缺失 case
JTab[5] = S, JTab[6] = S       // 多个 case 共用代码
```

所以跳转表是从整数索引到代码地址的映射，不要求一项对应一个独有代码块。[课件: 06-machine-control.pptx p.36]

### 4. 非零最小标签的偏置

若 case 范围为 `[m, M]`，老师口述的标准化思路是令：

$$
i = x - m
$$

则最小 case `x = m` 映射到 `i = 0`，最大 case 映射到 `i = M - m`。本段只给出这一概念性推导，没有展示具体边界检查指令或固定编译器模板（`01:06:50-01:07:19`）。

### 5. 稠密与稀疏选择的课堂复杂度结论

- 对适合跳转表的范围：索引后直接取得目标地址，分派使用常数数量的步骤。
- 对很稀疏的 case 集合：编译器可把已知常量排序并建立类似 binary search 的条件树，测试数为对数级，而不是线性逐项检查（`01:07:37-01:08:02`）。

老师没有给出密度公式、内存成本公式或 GCC 的阈值；这些都不能从本段材料自行补出。

## 例子与课堂提示

- **读表时先看索引，不看标签编号大小**（`00:59:55-01:01:09`）：`.L8, .L3, .L5...` 的排列看似无序，但表项位置严格对应 `x = 0...6`。[课件: 06-machine-control.pptx p.36]
- **hole 要填 default target**（`01:00:22-01:00:54`）：`x = 0` 与 `x = 4` 都在可索引范围内，不能靠入口越界检查捕获，所以对应表项必须显式写 `.L8`。
- **`break -> ret` 只由本函数后续结构造成**（`01:02:01-01:02:42`）：因为 switch 后马上 `return w`，编译器可直接返回；若函数后面还有代码，`break` 应转到后续代码而非必然 `ret`。
- **延迟初始化要逐路径验证**（`01:02:47-01:03:43`）：`case 2` 覆盖 `w`，不需初值；`case 3` 直接使用 `w += z`，所以 `.L9` 必须先恢复 `w = 1`。这服务于理解编译器为什么没有在统一入口初始化 `w`。
- **fall-through 不要求代码块按源代码排布**（`01:03:37-01:04:12`）：显式 `jmp .L6` 与自然落入 `.L6` 都可形成共享后缀，关键是控制流边，而非文本邻接看起来像哪个 case。
- **不要为极稀疏标签想当然地构造巨表**（`01:07:25-01:07:56`）：老师用 0 与 1,000,000 两个 case 说明空间浪费，编译器会选择条件代码。
- **编译器策略没有课堂固定阈值**（`01:08:45-01:09:02`）：可以做实验反推，但不能仅凭本例断言所有 GCC 版本在某一密度下必然选择同一种实现。

## 本段在整讲中的作用

本段先补完上一段被截断的结论：`switch` 的机器级实现虽然不如循环翻译直观，却能通过跳转表或条件判断树获得比朴素线性 `if-else` 链更好的分派效率（`01:09:42-01:10:32`）。老师随后回答“编译器怎样建树”，说明 C 的 case 标签是编译期常量，因此编译器能排序、划分并选择实现。

最后，老师把整讲从条件码到 `switch` 的内容收束为三类汇编级机制：conditional jump、conditional move、indirect jump。C 的 `if-then-else`、各种循环和 `switch` 并不是处理器各有一条同名指令，而是由编译器把少量低级原语拼成代码序列。[课件: 06-machine-control.pptx p.41] 下一讲将加入 stack、call/return 和 procedure call discipline。[课件: 06-machine-control.pptx p.42]

## 教学展开

### 1. 三种 `switch` 分派策略的性能比较（`01:09:42-01:10:32`）

老师从上一段的评价接着说：jump table 做法乍看不明显，但理解后可以看到它带来的性能收益（`01:09:42-01:09:56`）。他按算法级别比较三种路径选择方式：

1. **跳转表：** 经过范围检查后，以 case 值索引目标地址，用常数数量的步骤到达所需代码块，所以是 constant time。
2. **线性条件链：** 若按 `if-else-if` 从头逐项比较，case 数增加时比较次数线性增加；若各 case 均匀出现，平均大约检查到列表中部。
3. **稀疏 case 的条件树：** case 不适合建表时，可组织成树，使分派使用 logarithmic time，而不是线性逐项测试（`01:09:56-01:10:30`）。

老师在本段的结论是：无论采用适合稠密范围的 jump table，还是采用适合稀疏集合的条件树，编译器都在避免最直接的线性 `if-else` 形式（`01:10:19-01:10:32`）。课件的对应总结是：“Large switch statements use jump tables；Sparse switch statements may use decision trees”。[课件: 06-machine-control.pptx p.41]

### 2. “好消息是：树由编译器建立”（`01:10:36-01:10:50`）

学生追问怎样设置这棵树。老师先澄清程序员通常不手工建立它：编译器负责生成相应控制流（`01:10:36-01:10:45`）。随后他把问题改述为“如果我是编译器，应怎样建树”，开始用 binary search 解释生成方法。

这里的要点是区分职责：源程序员提供一组常量 case 及各自代码；编译器考察这些值的数量与范围，决定用表还是树，并产生实际汇编。[课件: 06-machine-control.pptx p.41]

### 3. 用 binary search 思路构造平衡条件树（`01:10:50-01:11:36`）

老师给出的构造过程是：

1. 取一组已知 case 值，并选择中间值。
2. 把输入与中间值比较。
3. 若小于中间值，递归处理较小的那一组；否则处理较大的那一组。
4. 重复划分，形成 balanced binary tree（`01:10:52-01:11:10`）。

这种方法能够成立，关键依赖 C 的语言约束：所有 case 条件都是常量，且在编译器执行编译时已经确定；老师特别指出，不是所有语言都具有同样前提（`01:11:10-01:11:27`）。因此编译器可以在运行前完成：

- 对 case 值排序；
- 统计 case 数量；
- 确定最小值到最大值的范围；
- 决定采用哪种实现；
- 生成相应代码（`01:11:23-01:11:36`）。

### 4. 从单一示例追问边界，是计算机科学式思考（`01:11:37-01:12:08`）

老师肯定学生围绕负 case、非零起点、极稀疏范围和建树方法提出的问题。他认为，看到一个具体例子后继续问“条件 X 或条件 Y 怎么处理”“如果情况变化会怎样”，正是计算机科学家应有的思考方式（`01:11:37-01:11:58`）。

他的标准不是停在一句简化解释，而是继续追问：如果必须把它真正实现成程序，具体该怎样做（`01:11:58-01:12:08`）。这也解释了前两段为何既分析一张具体 jump table，又进一步讨论 bias 与 decision tree。

### 5. 高级控制结构由有限的低级机制拼成（`01:12:09-01:13:22`）

老师总结，本讲用于实现条件控制的“bag of tricks”其实相当有限（`01:12:09-01:12:28`）：

1. **conditional jump：** 根据条件码跳到代码的不同位置；
2. **conditional move：** 根据条件决定是否把候选值移入目标；
3. **indirect jump via jump table：** 从表中读取目标地址，再跳到该地址（`01:12:28-01:12:44`）。

课件把 C 控制结构与标准翻译并列总结：[课件: 06-machine-control.pptx p.41]

| C 控制结构 | 课堂总结的机器级实现方式 |
| --- | --- |
| `if-then-else` | conditional jump，部分情形可用 conditional move |
| `do-while` | 循环体后测试并条件回跳 |
| `while`、`for` | 转成 do-while 式入口保护，或 jump-to-middle 形式 |
| 较大、适合建表的 `switch` | jump table + indirect jump |
| 稀疏 `switch` | decision tree，即组织过的 `if-elseif-...-else` |

由此得到整讲的总原则：编译器生成一段指令序列，用少量 assembler control primitives 实现更复杂的 C control constructs。高级语言中所有改变执行流、决定“哪些语句会执行”的结构，都需要这样由低级指令组合出来（`01:12:44-01:13:22`）。

### 6. 本讲结束，下一讲进入 procedures（`01:13:22-01:13:39`）

课件回顾本讲四项内容：[课件: 06-machine-control.pptx p.42]

- condition codes；
- conditional branches 与 conditional moves；
- loops；
- switch statements。

下一讲主题是 procedures，包括 stack、call/return 和 procedure call discipline。老师说 procedures 是一个足以占据完整一讲的重要主题，随后结束课堂（`01:13:22-01:13:39`）。本段不提前补写这些机制。

## 概念、符号与推导

### 1. 三种分派方式的课堂复杂度

设有 `n` 个需要区分的 case：

| 分派方式 | 课堂描述 | 复杂度记法 | 适用情形 |
| --- | --- | --- | --- |
| 跳转表索引 | 常数数量的步骤直接取得目标 | $O(1)$ | case 范围适合建表 |
| 线性 `if-else` 链 | 最坏逐项测试；均匀时平均约到中部 | $O(n)$ | 老师用作朴素对照 |
| 平衡条件树 | 每次比较排除约一侧值集合 | $O(\log n)$ | case 稀疏，不宜建大表 |

`O(1)`、`O(n)` 与 `O(\log n)` 是对老师所说 constant、linear、logarithmic time 的记法整理；本段没有给出常数开销、精确平均比较次数或表/树切换阈值（`01:09:51-01:10:30`）。

### 2. 平衡条件树的递归划分

若已排序的 case 常量为：

$$
v_1 < v_2 < \cdots < v_n
$$

老师给出的 binary-search 式步骤可整理为：选择中间 case `v_m`，比较输入 `x` 与 `v_m`；然后只在较小值集合或较大值集合中继续（`01:10:52-01:11:10`）。反复二分形成 balanced binary tree，所以路径长度随 case 数按对数级增长。

本段没有给出：中间下标的精确定义、相等分支的具体汇编排列、叶节点布局或编译器启发式。上述推导只保留口述的“中间值、左右递归、平衡树”链条。

### 3. 编译期常量是预先组织分派结构的前提

推理链为：

```text
case 标签在编译时已知
    -> 编译器可排序、计数并计算值域
    -> 可评估 jump table 与 decision tree
    -> 在运行前生成选定的代码结构
```

运行时输入 `x` 只负责沿已生成的表或树选择路径，不负责动态创建这些结构（`01:11:10-01:11:36`）。

### 4. 从 C 控制到 assembler control 的依赖关系

```text
condition codes
    +-> conditional jump -----> if/else、循环回跳、decision tree
    +-> conditional move -----> 适合同时计算候选值的条件表达式

jump-table address
    +-> indirect jump --------> switch 的表驱动分派
```

循环和 `switch` 不是新的底层原语；它们分别复用条件跳转或间接跳转。课件据此说，compiler generates code sequence to implement more complex control。[课件: 06-machine-control.pptx p.41]

## 例子与课堂提示

- **性能结论必须区分稠密与稀疏输入集合**（`01:09:51-01:10:30`）：jump table 给出 constant-time 分派，但稀疏 case 可能改用 logarithmic 条件树；不能把“所有 `switch` 都一定是跳转表”当成结论。
- **平均检查到中部带有分布前提**（`01:10:06-01:10:19`）：老师明确加了“如果各情况均匀”的条件；不能无条件声称线性链平均总是 `n/2`。
- **程序员写 `switch`，编译器建表或建树**（`01:10:36-01:10:50`）：理解构造过程用于阅读和分析机器代码，不表示源程序员必须手工维护这棵树。
- **case 必须是编译期常量**（`01:11:10-01:11:28`）：这是编译器能预排序并生成 balanced tree 的关键前提；老师提醒这项性质并非所有语言都有。
- **从一个例子主动追问范围变化**（`01:11:37-01:12:08`）：负值、远距离标签和稀疏集合等课堂问题服务于检验解释是否足以真正实现，而非偏离主题。
- **不要寻找与每个 C 关键字一一对应的机器指令**（`01:12:09-01:13:22`）：机器层只有少量控制原语，编译器通过组合代码区、条件码和跳转实现高级结构。[课件: 06-machine-control.pptx p.41]
- **procedures 属于下一讲证据边界**（`01:13:22-01:13:39`）：本段只记录将讲 stack、call/return、calling discipline，不自行展开。[课件: 06-machine-control.pptx p.42]
