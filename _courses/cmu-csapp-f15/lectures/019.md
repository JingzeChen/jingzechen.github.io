## 教师教学主线

### 1. 从 VM 资源到 allocator API（`00:00:02-00:10:00`）

虚拟内存给出连续字节数组，allocator 负责把 heap 管成不同大小、allocated/free 的连续 blocks。C 的显式 allocator 要求应用既申请又释放；Java、ML、Lisp 一类 implicit allocator 则由 garbage collection 释放。[00:01:06-00:03:35] 老师介绍 `malloc`、`free`、`calloc`、`realloc`、`sbrk`，再用 `n * sizeof(int)` 和一串按字计数的请求建立后续统一图示。[课件: 19-malloc-basic.pptx p.4] [课件: 19-malloc-basic.pptx p.5] [课件: 19-malloc-basic.pptx p.6] [课件: 19-malloc-basic.pptx p.8]

### 2. 在硬约束下定义速度、空间与碎片（`00:10:00-00:21:25`）

应用请求不可预测，allocator 必须立即响应、只从 free memory 分配、满足对齐、不能移动已交给应用的块。[00:10:00-00:12:18] 因此它同时追求 throughput 与 peak utilization，而两者经常冲突。[00:12:18-00:17:22] 低利用率随后被分成块内的 internal fragmentation 与空闲块之间布局导致的 external fragmentation。[00:17:22-00:21:25]

### 3. 把抽象问题变成块元数据和空闲结构（`00:21:35-00:31:39`）

老师提出五个实现问题：怎样知道释放长度、怎样跟踪空闲块、怎样处理 leftover、怎样选候选块、怎样重新插入释放块。[课件: 19-malloc-basic.pptx p.15] payload 前的 header 保存总块长，先解决第一个问题；implicit list、explicit list、segregated list 与按大小排序的树则给出不同空闲块组织。[课件: 19-malloc-basic.pptx p.16] [课件: 19-malloc-basic.pptx p.17]

### 4. 用对齐低位完成 implicit-list header（`00:31:42-00:40:22`）

总块长按 8/16 字节对齐，size 的最低 3/4 位恒为 0，因此最低位可保存 `a`：1 表示 allocated，0 表示 free；读 size 时用 mask 清掉状态位。[00:31:42-00:33:37] 详细布局加入 unused word 保证 payload 对齐，并以 `0/1` epilogue 终止遍历和消除末端合并特例。[00:33:52-00:36:40] 在这一布局上，老师比较 first fit、next fit 与 best fit。[00:36:41-00:40:22]

### 5. 从 splitting 推到 boundary-tag coalescing（`00:40:22-00:59:24`）

选中 6 字空闲块服务 4 字总块请求时，可整块交付，也可 split 成 4 字 allocated 与 2 字 free。[00:40:22-00:42:24] 若随后只清 4 字块的 allocation bit，就留下相邻的 4 字和 2 字 free blocks，仍无法满足 5 字请求，形成 false fragmentation。[00:42:24-00:44:16] 为维持“不存在相邻 free blocks”的 invariant，`free` 必须 coalesce；向后继跳转容易，找前驱却会迫使全堆扫描。[00:44:16-00:46:09]

Knuth 的 boundary tag 在块尾复制 size/allocated word，使当前 header 前一个字可提供前驱状态与大小，从而常数时间处理四种前后邻接组合。[00:46:11-00:52:24] footer 会增加内部碎片，所以老师再利用另一个空闲低位保存 previous-block allocation status：前块 allocated 时不需要它的 size，也就不需要 footer；前块 free 时才读取其 footer。[00:52:24-00:59:24]

### 6. 用 policy 和复杂度收束（`00:59:51-01:06:13.120`）

placement 决定选哪块，splitting 决定是否拆出 leftover，coalescing 决定立即还是延迟合并。[课件: 19-malloc-basic.pptx p.32] implicit list 的 allocate 最坏线性，free 即使含合并仍为常数时间，memory usage 取决于 placement policy。[课件: 19-malloc-basic.pptx p.33] 整体结构通常不用于通用 `malloc/free`，但 splitting 与 boundary-tag coalescing 对其他 allocator 仍具一般性。[01:04:28-01:05:54]

## 核心接口、模型与计算

### Allocator API

```c
#include <stdlib.h>

void *malloc(size_t size);
void free(void *p);
```

- `malloc(size)` 成功时返回一个至少含 `size` 字节 payload 的块；课件给出的对齐为 x86 8 字节、x86-64 16 字节。[课件: 19-malloc-basic.pptx p.5]
- 课件写明 `size == 0` 时返回 `NULL`；失败时返回 `NULL (0)` 并设置 `errno`。[课件: 19-malloc-basic.pptx p.5]
- `free(p)` 把 `p` 指向的块归还可用池；课件要求 `p` 来自先前一次 `malloc` 或 `realloc`。[课件: 19-malloc-basic.pptx p.5]
- `calloc` 返回初始化为 0 的块；`realloc` 改变已分配块大小；`sbrk` 供 allocator 内部增大或缩小 heap。[00:04:55-00:05:33] [课件: 19-malloc-basic.pptx p.5]

整数数组例把对象数换成 API 所需字节数：

$$
\text{requested bytes}=n\times\operatorname{sizeof}(int).
$$

[00:05:40-00:06:08] [课件: 19-malloc-basic.pptx p.6]

### Heap/block 模型

allocator 把 heap 维护为一系列 variable-sized blocks；每块要么 allocated，要么 free。[00:01:56-00:02:18] [课件: 19-malloc-basic.pptx p.4] 本讲为图示假设 memory word-addressed、word 为 int-sized，并以白色字表示 free、有色字表示 allocated；真实内存按字节寻址，这只是课堂简化。[00:07:13-00:08:33] [课件: 19-malloc-basic.pptx p.7]

### Throughput 与 peak utilization

给定请求序列 $R_0,R_1,\ldots,R_{n-1}$，throughput 为：

$$
\text{throughput}=\frac{\text{completed requests}}{\text{time}}.
$$

5,000 次 `malloc` 加 5,000 次 `free` 在 10 秒完成：

$$
\frac{5{,}000+5{,}000}{10}=1{,}000\ \text{operations/s}.
$$

[课件: 19-malloc-basic.pptx p.10]

执行完 $R_k$ 后，$P_k$ 是当前 allocated payload 总和，$H_k$ 是当前 heap size；本讲假设 $H_k$ 单调不减。执行前 $k+1$ 个请求后的 peak utilization 为：

$$
U_k=\frac{\max_{0\le i\le k}P_i}{H_k}.
$$

[课件: 19-malloc-basic.pptx p.11]

### Fragmentation 的两次课堂计算

- Internal fragmentation：单块中 block size 超过 payload 的部分，来源包括 allocator metadata、alignment padding 与主动返回较大块的 policy；只依赖过去请求，容易测量。[00:17:22-00:18:50] [课件: 19-malloc-basic.pptx p.13]
- External fragmentation：总空闲量足够，却没有足够大的单个 free block；是否造成失败依赖未来请求，难以测量。[00:18:50-00:21:25] [课件: 19-malloc-basic.pptx p.14]

5 字与 2 字两个 free blocks 面对 6 字请求时：

$$
5+2=7\ge6,\qquad \max(5,2)=5<6.
$$

总量够但单块不够，只能扩堆。[00:19:23-00:20:42]

6 字块 split 为 4 字 allocated 与 2 字 free，随后释放 4 字块但不合并；面对 5 字请求时：

$$
4+2=6\ge5,\qquad \max(4,2)=4<5.
$$

两块实际上相邻却仍被 header 分开，这就是 false fragmentation；合并为单个 6 字块才能满足请求。[00:41:14-00:44:16]

## 概念依赖与实现不变量

1. **对齐先于位编码**：只有先保证总块长为 8/16 的倍数，size 低 3/4 位才恒为 0，才能复用低位保存状态。[00:31:56-00:33:37] [00:57:51-00:59:12]
2. **header 先于 implicit traversal**：header 保存总块长；当前 header 加上屏蔽状态位后的 size，才得到下一 header。[课件: 19-malloc-basic.pptx p.16] [课件: 19-malloc-basic.pptx p.21]
3. **splitting 先于 false fragmentation**：split 会创建相邻的小 free block；后来释放邻块而只清状态位，才显出逻辑边界阻碍复用。[课件: 19-malloc-basic.pptx p.22] [课件: 19-malloc-basic.pptx p.23]
4. **“无相邻 free blocks”先于 coalescing**：为了维持这一 invariant，释放时必须检查两侧，而不是只把当前块标为 free。[00:43:51-00:44:52]
5. **反向定位需求先于 boundary tag**：后继地址可由当前 size 算出，前驱地址不能；footer 把前驱 size 放到当前 header 前一个字，才消除全堆扫描。[00:44:56-00:47:32]
6. **footer 开销先于 prev-allocated 优化**：allocated block 不会参与合并，只需知道它“已分配”，不需知道其 size；所以可在后继 header 记一位前块状态，只给 free block 保留 footer。[00:52:24-00:57:49]

释放当前 $n$ 字块时，设前块为 $m_1$、后块为 $m_2$，四种结果是：

| 前块 | 后块 | 新空闲块大小 | 新块起点 |
| --- | --- | --- | --- |
| allocated | allocated | $n$ | 当前块原 header |
| allocated | free | $n+m_2$ | 当前块原 header |
| free | allocated | $m_1+n$ | 前块原 header |
| free | free | $m_1+n+m_2$ | 前块原 header |

[课件: 19-malloc-basic.pptx p.26] [课件: 19-malloc-basic.pptx p.27] [课件: 19-malloc-basic.pptx p.28] [课件: 19-malloc-basic.pptx p.29] [课件: 19-malloc-basic.pptx p.30]

## 策略总表与复杂度

| 策略面 | 课堂选项 | 主要权衡 |
| --- | --- | --- |
| Placement | first fit、next fit、best fit、good fit、segregated lists | 搜索 throughput 与 fragmentation/utilization |
| Splitting | 整块交付、split、按最小 leftover threshold 决定 | allocated block 内部浪费与过小 free block |
| Coalescing | immediate、deferred | `free` 时立即恢复大块，或把工作推迟到扫描/阈值时 |

[00:59:51-01:04:28] [课件: 19-malloc-basic.pptx p.32]

若堆中有 $B$ 个隐式串接的块：

$$
T_{\mathrm{alloc}}(B)=O(B),\qquad T_{\mathrm{free}}(B)=O(1).
$$

前者来自最坏情况下扫描全堆；后者来自 boundary tags 使 `free` 只处理固定数量邻接字段，即使 coalescing 也保持常数时间。[01:04:28-01:04:57] [课件: 19-malloc-basic.pptx p.33]

## 全讲易错点

- 不要把实际 `malloc` 的字节参数与课堂图中的按字计数混同；word-addressed 是讲解简化。[00:07:13-00:08:49]
- 不要把 $U_k$ 写成当前 $P_k/H_k$；课件分子是截至 $k$ 的最大 aggregate payload。[课件: 19-malloc-basic.pptx p.11]
- 不要把“总 free memory 足够”当作请求必能成功；单个请求需要一块足够大的连续 free block。[课件: 19-malloc-basic.pptx p.14]
- header 保存本讲模型中的总 block size，不只保存 payload；4 字 payload 需要 1 字 header，示例总长为 5。[00:23:15-00:24:06] [课件: 19-malloc-basic.pptx p.16]
- implicit free list 不是只链接 free blocks；它遍历全部 blocks，再跳过 allocated blocks。[00:24:21-00:25:21]
- `0/1` epilogue 是 size 0、allocated bit 1 的哨兵，不是 1 字节 payload。[课件: 19-malloc-basic.pptx p.20]
- next fit 避免重扫不代表整体一定更好；老师引用的研究显示其 fragmentation 可能更差。[00:37:34-00:38:17]
- splitting、coalescing 与 placement 都是 policy，不存在不看 workload 就总正确的单一选择。[00:39:59-00:42:24] [00:59:51-01:04:28]
- boundary tag 是 size/allocated word 的副本，不是前驱指针；优化后也不是所有 footer 都删除，只删除 allocated-block footer。[00:46:30-00:47:50] [00:55:07-00:57:49]
- implicit list 整体不常用于通用 `malloc/free`，不等于 splitting 与 boundary-tag coalescing 没有一般价值。[01:05:04-01:05:48]

# 第 1 节：从虚拟内存到动态内存分配

> 时间范围：`00:00:02-00:10:00`  
> 主要课件：[课件: 19-malloc-basic.pptx p.1] [课件: 19-malloc-basic.pptx p.2] [课件: 19-malloc-basic.pptx p.3] [课件: 19-malloc-basic.pptx p.4] [课件: 19-malloc-basic.pptx p.5] [课件: 19-malloc-basic.pptx p.6] [课件: 19-malloc-basic.pptx p.7] [课件: 19-malloc-basic.pptx p.8]

## 本段在整讲中的作用

本段把上周的虚拟内存主题接到本周的存储分配主题。虚拟内存先向程序提供“一个很大的、连续的字节数组”这一抽象；接下来的问题是怎样管理这项资源，使应用能够按需取得和归还其中的一段内存（`00:00:09-00:01:06`）。老师先定义动态内存分配器及堆上的块，再区分显式与隐式分配器，介绍 C 的 `malloc` 包接口，最后用简化的按字寻址模型演示一串分配与释放，为下一段讨论分配器约束和性能目标建立共同模型。本讲标题与日期见 [课件: 19-malloc-basic.pptx p.1]。

## 教学展开

1. **从虚拟内存抽象提出管理问题（`00:00:09-00:01:06`）**
   - 上周已经看到虚拟内存机制及其多种系统功能，并得到“大型连续字节数组”的抽象。
   - 仅有这片地址空间还不够，系统需要一种机制管理和使用它。因此本周主题是 storage allocation，即存储分配器如何工作，以及程序如何借助它管理虚拟内存。

2. **定义动态内存分配器、堆与块（`00:01:06-00:02:18`）**
   - 应用通过动态内存分配器取得和释放程序所需的虚拟内存片段。
   - 这部分动态内存位于虚拟地址空间中的 **heap（堆）**。
   - 分配器把堆维护为一组连续的 **block（块）**。每个块只有两种状态：
     - **allocated（已分配）**：正在被某个应用使用；
     - **free（空闲）**：尚未被应用占用，可供后续请求使用。
   - 不同语言都提供某种取得和管理动态内存的机制；C 使用 `malloc` 包，Java 一类语言使用 `new`。
   - 课件把 heap 放在进程虚拟地址空间中，并把 application、dynamic memory allocator 与 heap 的关系画出。[课件: 19-malloc-basic.pptx p.3]

3. **区分显式与隐式分配器（`00:02:18-00:03:35`）**
   - **显式分配器**：应用既显式申请，也必须在用完后显式释放。C 的 `malloc` 包属于此类；若程序不调用 `free`，系统不会替它释放该块。
   - **隐式分配器**：程序显式申请，系统在幕后借助 **garbage collection（垃圾收集）** 负责释放。老师列举 Java、ML、Lisp。
   - 本节课只讨论显式分配器；老师预告周四再讲隐式分配器。
   - 这一分类和本讲只讲简单显式分配器的范围见 [课件: 19-malloc-basic.pptx p.4]。

4. **介绍 C 的 `malloc` 包（`00:03:35-00:05:33`）**
   - 标准 C 库提供这一组函数。
   - `malloc(size)`：参数 `size` 以字节为单位；返回一个指针，所指块至少包含 `size` 字节。老师说明 x86 上按 8 字节对齐，x86-64 上按 16 字节对齐（`00:03:46-00:04:12`）。
   - `free(ptr)`：`ptr` 必须是先前某次 `malloc` 返回的指针；函数没有返回值。它释放该地址处的块，并把块归还给可用内存池（`00:04:21-00:04:46`）。
   - `calloc`：取得一个内容初始化为 0 的块（`00:04:55-00:05:05`）。
   - `realloc`：改变一个先前已分配块的大小（`00:05:05-00:05:13`）。
   - `sbrk`：由分配器内部使用，用于增大或缩小堆；分配器需要更多内存时调用它，把新增虚拟内存并入自己管理的堆（`00:05:13-00:05:33`）。
   - 接口签名、对齐要求和这些辅助函数列于 [课件: 19-malloc-basic.pptx p.5]。

5. **用整数数组说明 `malloc`/`free` 的调用过程（`00:05:40-00:07:13`）**
   - 程序声明 `int *p`，要取得含 `n` 个整数的数组，就调用 `malloc(n * sizeof(int))`；相乘是因为 `malloc` 的参数单位是字节。
   - `malloc` 返回通用的 `void *` 指针。课堂代码把它转换为 `int *` 后赋给 `p`。
   - 程序检查返回值是否为 null；若为 null，就报告错误。
   - 成功后可像普通数组一样用 `p[i]` 访问并初始化元素。
   - 用完后调用 `free(p)` 归还整个块。
   - 完整 `foo(int n)` 示例见 [课件: 19-malloc-basic.pptx p.6]。

6. **建立本讲的简化堆模型（`00:07:13-00:08:33`）**
   - 接下来要研究 `malloc` 和 `free` 如何实现。
   - 虽然实际内存按字节寻址，本讲图示改为按 **word（字）** 寻址，并暂定一个字为 4 字节，以减少图中的单位数量。
   - 块是若干连续的字，并处于 allocated 或 free 状态。图中有一个 4 字已分配块、一个 2 字空闲块、一个 4 字已分配块和一个 3 字空闲块；白色表示空闲，有色表示已分配。
   - “memory is word addressed、words are int-sized”以及块的图例是本讲的显式简化假设。[课件: 19-malloc-basic.pptx p.7]

7. **按字演示分配、释放与复用（`00:08:33-00:10:00`）**
   - 为简化图示，这里的 `malloc` 参数暂以字而非字节表示。
   - `p1 = malloc(4)`：取得 4 字块。
   - `p2 = malloc(5)`：取得 5 字块。
   - `p3 = malloc(6)`：取得 6 字块。
   - `free(p2)`：原来由 `p2` 指向的 5 字块变为空闲。
   - `p4 = malloc(2)`：分配器寻找足够大的空闲块，在刚释放的 5 字空闲块中放入 2 字请求；该例由此引出“如何从可用块中满足请求”的实现问题。
   - 请求序列与图示顺序见 [课件: 19-malloc-basic.pptx p.8]。

## 概念、符号与推导

### 核心对象

| 对象 | 本段定义或约定 | 依据 |
| --- | --- | --- |
| 虚拟内存 | 对程序呈现为大型连续字节数组 | `00:00:09-00:00:34` |
| heap | 分配器维护动态内存的虚拟内存区域 | `00:01:06-00:01:44` |
| block | 堆中连续的一段；状态为 allocated 或 free | `00:01:56-00:02:08` |
| 显式分配器 | 应用显式申请且显式释放 | `00:02:18-00:02:47` |
| 隐式分配器 | 应用申请，系统通过垃圾收集隐式释放 | `00:02:47-00:03:26` |
| `size` | `malloc` 的字节数参数 | `00:03:46-00:04:04` |
| word | 本讲图示中的简化单位，暂按 4 字节处理 | `00:07:24-00:08:02` |

### 接口约束

```c
void *malloc(size_t size);
void free(void *ptr);
```

- `malloc(size)` 返回的块含有至少 `size` 字节（`00:03:46-00:04:04`）。
- `free(ptr)` 的参数必须来自先前一次 `malloc` 的返回值（`00:04:21-00:04:46`）。
- 本段口述的对齐要求为：x86 8 字节、x86-64 16 字节（`00:04:04-00:04:12`）。

### 数组申请中的唯一计算

申请 `n` 个 `int` 时，传给 `malloc` 的字节数为：

$$
n \times \operatorname{sizeof}(int)
$$

推导链条是：请求对象数为 `n`，每个对象占 `sizeof(int)` 字节，而 `malloc` 接收字节数，因此二者相乘（`00:05:40-00:06:08`）。除这一步外，本段无公式推导。

## 例子与课堂提示

### 整数数组例子

老师用以下调用链说明 API 的完整生命周期（`00:05:40-00:07:13`）：

```c
int *p = (int *)malloc(n * sizeof(int));
if (p == NULL) {
    /* 报告分配失败 */
}
/* 逐项使用 p[i] */
free(p);
```

这个例子服务于三个知识点：请求单位是字节；成功后返回的连续内存可当作数组使用；显式分配器要求程序最终显式释放。

### 块序列例子

`malloc(4) -> malloc(5) -> malloc(6) -> free(p2) -> malloc(2)`（`00:08:33-00:10:00`）展示了：释放不会让这段地址消失，而是把块重新标为空闲；后续较小请求可以复用足够大的空闲块。老师在本段只展示结果，尚未解释剩余空间的具体表示与策略。

### 易错点与边界

- 不要把实际 API 的字节参数与课堂后半段图示的“字”参数混为一谈；按字计数只是本讲为画图采用的简化（`00:07:24-00:08:49`）。
- allocated/free 描述的是整个块的状态，不是单个字节的状态（`00:01:56-00:02:08`）。
- 在显式分配器中，仅让指针变量离开作用域并不等同于调用 `free`；本段明确说系统不会自动释放（`00:02:18-00:02:40`）。
- `sbrk` 是分配器向系统扩展或收缩堆时使用的内部机制，不是本例中应用直接取得数组的接口（`00:05:13-00:05:33`）。
- `p4 = malloc(2)` 被放入 5 字空闲块，并不代表本段已经规定了“总要选择该块”或“剩余 3 字如何处理”；这些都是后续实现策略问题。

## 本段掌握检查

1. **问：虚拟内存抽象为什么自然引出动态内存分配器？**  
   **答：** 虚拟内存提供大型连续字节数组，但程序还需要机制按需取得和归还其中的片段；分配器承担这项管理工作（`00:00:09-00:01:06`）。

2. **问：显式分配器和隐式分配器的责任边界有何不同？**  
   **答：** 两者都允许程序申请内存；显式分配器还要求程序调用 `free`，隐式分配器则由系统通过垃圾收集释放（`00:02:18-00:03:26`）。

3. **问：为什么申请 `n` 个整数要传入 `n * sizeof(int)`？**  
   **答：** 因为程序需要 `n` 个整数，而 `malloc` 参数的单位是字节，所以要把元素数乘以每个整数的字节数（`00:05:40-00:06:08`）。

4. **问：本讲的图示模型相对真实机器做了什么简化？**  
   **答：** 把实际的按字节寻址改画成按字寻址，并暂按每字 4 字节处理；图中块由连续的字组成（`00:07:24-00:08:11`）。

5. **问：释放 `p2` 后，为什么 `malloc(2)` 能复用原 5 字块？**  
   **答：** `free(p2)` 把该 5 字块归还为空闲块，它足以容纳 2 字请求，所以演示中的分配器把新块放在其中（`00:09:18-00:09:51`）。

# 第 2 节：分配器约束、性能目标与碎片

> 时间范围：`00:10:00-00:19:59`  
> 主要课件：[课件: 19-malloc-basic.pptx p.9] [课件: 19-malloc-basic.pptx p.10] [课件: 19-malloc-basic.pptx p.11] [课件: 19-malloc-basic.pptx p.12] [课件: 19-malloc-basic.pptx p.13] [课件: 19-malloc-basic.pptx p.14]

## 本段在整讲中的作用

上一段只展示了分配与释放的结果，本段解释为什么实现一个好的分配器很难：应用给出不可预测的请求，分配器又必须立即响应、不能移动已分配块。在这些硬约束下，分配器同时追求吞吐率和峰值内存利用率，而二者往往冲突。[00:10:00-00:13:28] 老师随后把低利用率具体分为内部碎片和外部碎片，并沿用上一段的块序列给出“总空闲量够、单块却不够”的计算。[课件: 19-malloc-basic.pptx p.9] [课件: 19-malloc-basic.pptx p.12]

## 教学展开

### 1. 先列应用和分配器各自受到的约束

应用可以发出任意次序、任意组合的 `malloc` 和 `free` 请求，分配器无法预测下一次请求；应用释放块时，传入的指针必须来自先前的 `malloc`。[00:10:00-00:10:40] [课件: 19-malloc-basic.pptx p.9]

分配器受到更多约束：[00:10:41-00:12:18]

1. 不能控制已分配块的数量和大小，因为这些由应用决定。
2. 收到 `malloc` 后必须立即完成并返回，不能重排或缓存一批请求后统一处理。
3. 只能从空闲内存中放置新块。
4. 块一旦交给应用，分配器就不能修改它，也不能把已分配块挪到一起做 compaction（压紧）。
5. 块必须满足可存放最大对象所需的对齐；本讲口述和课件给出的 Linux 对齐为 x86 8 字节、x86-64 16 字节。[课件: 19-malloc-basic.pptx p.9]

### 2. 把设计目标分成速度与空间两项

分配器同时优化运行速度和堆空间效率；这两项会互相牵制。[00:12:18-00:13:28]

给定请求序列

$$
R_0,R_1,\ldots,R_k,\ldots,R_{n-1},
$$

其中每个 $R_i$ 是一次 `malloc` 或 `free`，两个目标是最大化 **throughput（吞吐率）** 和 **peak memory utilization（峰值内存利用率）**。[课件: 19-malloc-basic.pptx p.10]

### 3. 定义并计算吞吐率

吞吐率是单位时间完成的请求数：[00:13:36-00:13:58]

$$
\text{throughput}=\frac{\text{completed requests}}{\text{time}}.
$$

老师的例子是在 10 秒内完成 5,000 次 `malloc` 和 5,000 次 `free`，所以

$$
\frac{5{,}000+5{,}000}{10\ \mathrm{s}}
=1{,}000\ \text{operations/s}.
$$

[课件: 19-malloc-basic.pptx p.10]

### 4. 从 payload 推导峰值内存利用率

应用调用 `malloc(p)` 时请求的是 $p$ 字节 **payload（有效载荷）**；分配器返回的块至少容纳这 $p$ 字节。块内除 payload 之外的内容都是开销。[00:14:26-00:14:57]

执行完请求 $R_k$ 后，**aggregate payload** $P_k$ 是当时仍处于已分配状态的所有 payload 之和。[00:14:57-00:15:25] 当前堆大小记为 $H_k$；本讲作简化假设，$H_k$ 单调不减，即分配器通过 `sbrk` 扩堆，但不缩堆。[00:15:33-00:15:52] [课件: 19-malloc-basic.pptx p.11]

执行完前 $k+1$ 个请求后的峰值内存利用率定义为：

$$
U_k=\frac{\max_{0\le i\le k}P_i}{H_k}.
$$

[课件: 19-malloc-basic.pptx p.11]

分子保留截至 $R_k$ 的 aggregate-payload 峰值，分母是此刻的堆大小。若每个块都只有 payload、没有任何开销，最佳利用率为 1；实际块包含分配器数据结构与对齐填充，所以达不到这个理想状态。[00:16:04-00:16:46]

### 5. 用 2 字节请求引出内部碎片

若块要求 16 字节对齐，块起点在 16 字节边界上，块也至少达到相应粒度。此时只请求 2 字节 payload，会有大量非 payload 字节，降低利用率。[00:16:46-00:17:16]

当一个块的 payload 小于整个块的大小时，差额构成 **internal fragmentation（内部碎片）**。成因包括：[00:17:22-00:18:03]

- 维护堆数据结构的开销；
- 满足对齐所需的 padding；
- 显式策略决定，例如以较大块满足较小请求，避免产生过小碎片或维持最小块大小。

内部碎片只取决于已经发生的请求。任一时刻冻结堆，查看当前各 payload 与对应块大小，就能计算，因此容易度量。[00:18:13-00:18:50] [课件: 19-malloc-basic.pptx p.13]

### 6. 用 7 个空闲字无法满足 6 字请求解释外部碎片

**external fragmentation（外部碎片）** 是：堆中的总空闲空间足够，但没有任何一个空闲块大到足以满足当前请求。[00:18:50-00:19:23]

老师沿用前例：堆中有一个 5 字空闲块和一个 2 字空闲块，总空闲量为

$$
5+2=7\ \text{words}.
$$

随后请求 6 字。虽然 $7\ge6$，但

$$
\max(5,2)=5<6,
$$

所以没有单个块可以满足它。[00:19:23-00:19:59] 课件把请求序列写为 `p1 = malloc(4)`、`p2 = malloc(5)`、`p3 = malloc(6)`、`free(p2)`、`p4 = malloc(6)`。[课件: 19-malloc-basic.pptx p.14]

## 概念、符号与推导

| 概念或符号 | 定义 | 关键性质 |
| --- | --- | --- |
| $R_i$ | 第 $i$ 个 `malloc`/`free` 请求 | 请求次序不能被分配器重排 |
| throughput | 单位时间完成的请求数 | 越高越好 |
| payload | 应用实际请求并使用的字节 | `malloc(p)` 的 payload 为 $p$ 字节 |
| $P_k$ | $R_k$ 完成后仍已分配的 payload 总和 | 会随 `malloc`/`free` 增减 |
| $H_k$ | $R_k$ 完成后的堆大小 | 本讲假设单调不减 |
| $U_k$ | $\max_{0\le i\le k}P_i/H_k$ | 理想上限为 1 |
| 内部碎片 | 单个块大小超过其 payload 的部分 | 仅依赖过去请求，易测量 |
| 外部碎片 | 总空闲量够但没有足够大的单个空闲块 | 是否成为问题取决于请求大小 |

本段的两项数值推导是吞吐率 $10{,}000/10=1{,}000$ 次/秒，以及外部碎片例中的总量 $5+2=7$ 但最大单块仅为 5。[课件: 19-malloc-basic.pptx p.10] [课件: 19-malloc-basic.pptx p.14]

## 例子与课堂提示

- **不能压紧堆**：即使把所有已分配块挪到一起可制造更大的连续空闲区，C 分配器也不能这么做，因为交给应用的块已经不归分配器修改。[00:11:15-00:11:58]
- **速度与空间冲突**：老师指出，写出很快但利用率很差的 `malloc` 很容易；评估实现不能只看一种指标。[00:12:18-00:13:28]
- **2 字节 payload**：用于说明对齐粒度如何在块内部形成不可供其他请求使用的浪费。[00:16:46-00:17:16]
- **5+2 对 6**：用于区分“空闲总量”和“最大连续空闲块”；只有后者能直接满足一个 6 字请求。[00:19:23-00:19:59]

## 易错点与辨析

- **误解：峰值利用率就是当前 $P_k/H_k$。** 课件定义的分子是截至当前的最大 aggregate payload，必须写成 $\max_{0\le i\le k}P_i$。[课件: 19-malloc-basic.pptx p.11]
- **误解：总空闲空间足够就一定能分配。** 5 字和 2 字分散在两个块中，不能直接拼成一个 6 字块；这正是外部碎片。[00:19:23-00:19:59]
- **误解：分配器可以暂缓请求以找到全局最优布局。** 本段明确要求收到请求后立即响应，不能缓存和重排。[00:10:55-00:11:11]
- **误解：内部碎片只有对齐填充。** 块内元数据以及故意返回较大块的策略也会造成内部碎片。[00:17:22-00:18:03]

## 本段掌握检查

1. **问：C 分配器为什么不能通过移动已分配块来压紧空闲空间？**  
   **答：** 块交给应用后属于应用，分配器只能修改空闲内存，不能改动或移动该块。[00:11:15-00:11:58]

2. **问：5,000 次 `malloc` 加 5,000 次 `free` 在 10 秒内完成，吞吐率是多少？**  
   **答：** $(5{,}000+5{,}000)/10=1{,}000$ operations/s。[课件: 19-malloc-basic.pptx p.10]

3. **问：$U_k$ 的完整定义是什么？**  
   **答：** $U_k=\max_{0\le i\le k}P_i/H_k$，其中 $P_i$ 是请求 $R_i$ 后的 aggregate payload，$H_k$ 是当前堆大小。[课件: 19-malloc-basic.pptx p.11]

4. **问：内部碎片和外部碎片在位置上有什么区别？**  
   **答：** 内部碎片位于已分配块内部、但不属于 payload；外部碎片表现为块之间有空闲空间，却没有足够大的单一空闲块。[课件: 19-malloc-basic.pptx p.13] [课件: 19-malloc-basic.pptx p.14]

5. **问：为什么 7 个空闲字仍可能无法满足 6 字请求？**  
   **答：** 7 个字分成 5 字和 2 字两个块，最大单块只有 5 字，无法放入连续的 6 字块。[00:19:23-00:19:59]

# 第 3 节：实现问题、块头与空闲块组织

> 时间范围：`00:20:01-00:29:59`  
> 主要课件：[课件: 19-malloc-basic.pptx p.15] [课件: 19-malloc-basic.pptx p.16] [课件: 19-malloc-basic.pptx p.17] [课件: 19-malloc-basic.pptx p.18]

## 本段在整讲中的作用

本段先收束外部碎片：5 字与 2 字的空闲总量虽然足够，但 6 字请求会迫使分配器扩堆，而且是否构成外部碎片要看未来请求。[00:20:01-00:21:25] 随后老师把前面的抽象模型转成五个实现问题，先用 header 解决“`free` 只收到指针，怎样知道块大小”，再比较隐式链表、显式链表、分离链表和平衡树四类空闲块组织方式，最终选定本讲要深入的 implicit free list。[课件: 19-malloc-basic.pptx p.15] [课件: 19-malloc-basic.pptx p.17]

## 教学展开

### 1. 完成外部碎片的判断逻辑

在 5 字和 2 字两个空闲块之间，没有单个块能容纳 6 字请求，分配器只能取得更多虚拟内存并扩展堆。[00:20:01-00:20:42]

内部碎片由过去请求造成，冻结当前堆即可测量；外部碎片则与未来请求有关。面对同一个当前布局：若下一次请求为 6 字，它已经外部碎片化；若未来都只是小请求，现有小空闲块可能全部可用，就未必造成问题。[00:20:42-00:21:25] [课件: 19-malloc-basic.pptx p.14]

### 2. 提出五个实现问题

老师指出简单图示略去了真正实现必须回答的问题：[00:21:35-00:23:02]

1. `free` 只接收指针，不接收长度，怎样知道应释放多少内存？
2. 怎样跟踪所有空闲块？
3. 找到比请求更大的空闲块后，剩余空间留在原块造成内部碎片，还是切成另一个空闲块？
4. 多个空闲块都能容纳请求时，选哪一个？
5. `free` 一个块后，怎样把它重新纳入可用结构？

这些问题与 [课件: 19-malloc-basic.pptx p.15] 的五项 Implementation Issues 一一对应。

### 3. 在 payload 前保存块长度

标准方法是在每个块开头放一个字，保存该块的总长度；这个字叫 **header field（头字段）** 或 **header（块头）**。[00:23:02-00:23:33] [课件: 19-malloc-basic.pptx p.16]

若应用请求 4 字 payload，分配器必须找到至少 5 字的块：

$$
\underbrace{1}_{\text{header}}+
\underbrace{4}_{\text{payload}}=5\ \text{words}.
$$

header 记录总块长 5，分配器向应用返回的 `p0` 指向 payload 起点，而不是 header。[00:23:33-00:24:06] 因此 `free(p0)` 可以从 payload 指针前一个字找到 header，恢复整块长度；代价是每个块至少多一个字的开销。

### 4. 方法一：用长度隐式链接所有块

**Implicit list（隐式链表）** 在每个块前都放 header，无论该块已分配还是空闲。[00:24:21-00:24:39]

从堆首开始，读取当前块大小即可跳到下一个 header。例如当前块长 5，则下一个块从当前 header 偏移 5 个字处开始；下一个块若长 4，再偏移 4 个字继续。[00:24:39-00:25:03]

它叫“隐式空闲链表”，因为并不存在只链接空闲块的指针链。要遍历所有空闲块，只能遍历堆中的全部块并忽略已分配块。[00:25:03-00:25:21] [课件: 19-malloc-basic.pptx p.17]

### 5. 方法二：只在空闲块之间放显式指针

另一方法是在空闲块内取出若干字，组成单向或双向链表，只把空闲块链接起来。[00:25:26-00:25:49]

- 隐式链表遍历成本与堆中 **全部块数** 成线性关系。
- 显式链表遍历成本与 **空闲块数** 成线性关系；大量已分配块不再进入搜索。[00:25:55-00:26:17]

学生问是否还需要 free bit。老师确认需要，并说这正是下一步要解决的问题。[00:26:24-00:26:33]

### 6. 方法三和四：按大小分类或排序

更复杂的两种组织方式是：[00:26:45-00:27:17]

- **Segregated free list（分离空闲链表）**：为不同大小或大小范围分别维护空闲链表。
- **按大小排序的块结构**：例如用平衡树（老师举 Red-Black tree），在空闲块内存指针，以块长度为键。

本讲选择最简单的隐式链表，因为其中会出现更复杂组织方式也要使用的基础概念。[00:27:10-00:27:24] 本讲路线再次显示于 [课件: 19-malloc-basic.pptx p.18]。

### 7. 用大小类回答课堂提问

老师用三个范围解释 size class：一个链表保存 0-8 大小的块，另一个保存 9-16，再一个保存 17-32。进入某条链表时，就已知道其中块的大小范围。[00:27:29-00:28:13]

理想化地，若每个可能大小都有一条链表，请求就能取得大小恰好的块，碎片最少；现实不能维护无限多条链表，但 size class 越多，越接近这个理想。[00:28:20-00:28:51]

学生追问能否为每个实际出现的大小动态建立 class。老师认为可以思考这种策略，但段末还没有给出统一结论，只指出它要结合请求大小的分布来评价。[00:29:02-00:29:59]

## 概念、符号与推导

### 块头模型

```text
低地址                                      高地址
+----------------+----------------------------+
| header: size=5 | payload: 4 words            |
+----------------+----------------------------+
                 ^
                 p0
```

总块长包含 header 与 payload。对本段的 4 字 payload 例子，总长是 $1+4=5$ 字；`p0` 指向 payload。[00:23:15-00:24:06]

### 四种空闲块组织

| 方法 | 被直接链接/索引的对象 | 本段指出的搜索尺度 |
| --- | --- | --- |
| 隐式链表 | 所有块由长度隐式串接 | 堆中全部块数 |
| 显式链表 | 只链接空闲块 | 空闲块数 |
| 分离空闲链表 | 每个大小类一条空闲链 | 先由大小缩小候选范围 |
| 按大小排序 | 以块大小为键的平衡树等结构 | 本段未给复杂度公式 |

除 $1+4=5$ 的块长计算外，本段无其他公式推导。

## 例子与课堂提示

- **未来请求决定外部碎片**：同一组 5 字、2 字空闲块，对 6 字请求无效，对多个小请求却可能够用；用于说明不能只看当前布局下结论。[00:20:42-00:21:25]
- **header 跳转**：长度 5 后跳 5，长度 4 后跳 4；用于说明没有显式 `next` 指针仍可遍历整个堆。[00:24:39-00:25:03]

- **无限 size class 思想实验**：每种大小一条链可取得恰好匹配的块，用于解释增加分类为何可能减少碎片，而不是建议真实实现无限结构。[00:28:20-00:28:51]

## 易错点与辨析

- **误解：header 只保存 payload 大小。** 课堂 4 字 payload 的 header 写 5，说明这里保存的是包含 header 的总块长。[00:23:33-00:24:06]
- **误解：`malloc` 返回 header 地址。** 返回指针指向 payload 开头；header 位于它前一个字。[课件: 19-malloc-basic.pptx p.16]
- **误解：隐式链表只遍历空闲块。** 它由所有块的长度隐式串起，搜索时必须经过已分配块并忽略它们。[00:25:03-00:25:21]
- **误解：size class 越多必然无代价。** 老师只说更接近精确匹配；为很多不同大小维护大量链表是否划算取决于 workload，并在下一节继续讨论。[00:28:20-00:29:59]

1. **问：`free(p)` 没有长度参数，分配器怎样找到块大小？**  
   **答：** 在 payload 前的 header 中保存总块长，`p` 指向 payload，因此向前一个字即可读取 header。[00:23:02-00:24:06]

2. **问：4 字 payload 为什么需要 5 字块？**

3. **问：隐式链表为什么是“隐式”的？**

# 第 4 节：隐式链表的头部编码、堆布局与放置策略

> 时间范围：`00:29:59-00:39:59`  
> 主要课件：[课件: 19-malloc-basic.pptx p.19] [课件: 19-malloc-basic.pptx p.20] [课件: 19-malloc-basic.pptx p.21]

## 本段在整讲中的作用

本段先完成上一节关于 size class 的课堂问答，再正式实现隐式空闲链表。老师依次解决三个问题：如何把块大小和分配状态压进同一个 header 字，如何布置堆使每个 payload 对齐并可靠终止遍历，以及如何在空闲块中选择放置位置。由此把 first fit、next fit、best fit 的搜索成本与碎片权衡摆到同一个模型中。[00:31:42-00:39:59]

## 教学展开

### 1. size class 的收益取决于 workload

为每种实际大小建立链表是否有效，取决于大小范围和请求频率。若请求均匀覆盖许多不同大小，可能留下很多很少使用的空闲链表；若某些大小特别常见，可以为这些热点大小建立专用链表，其余链表覆盖较宽范围。[00:29:59-00:31:03]

若某条链表中的块全部同样大，管理还能更简单：老师举例说可用 bit vector，每个潜在块一位表示 allocated/free，不必遍历链表。[00:31:03-00:31:23] 这说明 `malloc` 实现存在很大的设计空间，也是 malloc lab 要探索的内容。[00:31:23-00:31:39]

### 2. 利用对齐留下的低位编码 allocation status

隐式链表的每个块既要保存 size，也要保存 allocated/free 状态。用两个字分别保存很浪费。[00:31:42-00:31:56]

对齐提供了标准技巧：若块大小是 8 的倍数，size 的最低 3 位必为 0；若是 16 的倍数，最低 4 位必为 0。[00:31:56-00:33:04] 因而可把最低位改作 allocation flag `a`：

- `a = 1`：allocated；
- `a = 0`：free；
- 其余高位：block size。

读取 size 时必须屏蔽状态位，把最低位清零。[00:33:04-00:33:37] [课件: 19-malloc-basic.pptx p.19]

若 header 值记为 $h$，本讲图示中可写成：

$$
a=h\mathbin{\&}1,
$$

$$
\text{size}=h\mathbin{\&}(-2).
$$

第二式正是课件遍历代码采用的 low-bit mask。[课件: 19-malloc-basic.pptx p.21]

### 3. 构造 4 字节 word、8 字节对齐的隐式堆

详细图例假设每字 4 字节、payload 必须按 8 字节边界对齐。[00:33:52-00:34:16]

堆起点先放一个 unused word。第一个块的 header 因而位于距对齐起点 4 字节处，它后面的 payload 正好从 8 字节边界开始；只要后续每个总块长都是 8 的倍数，每个后续 payload 也继续对齐。[00:34:16-00:35:36]

课件示例把 header 标为“总字节数/分配位”，依次出现 `8/0`、`16/1`、`16/1`、`32/0`，阴影为已分配块，非阴影为空闲块。[课件: 19-malloc-basic.pptx p.20] 老师特别指出一个 16 字节已分配块只有 2 字 payload，还需 padding 使总块长满足 8 字节倍数；这段 padding 是内部碎片。[00:34:54-00:35:36]

堆末放一个特殊 **epilogue block（结尾块）**，header 为 `0/1`，即“大小 0、状态 allocated”。它既可作为遍历停止标记，也会在后续合并相邻空闲块时消除末端特殊情况。[00:35:45-00:36:40] [课件: 19-malloc-basic.pptx p.20]

### 4. First fit：遇到第一个够大的空闲块就停止

**First fit** 每次从堆首开始，返回第一个能容纳请求的空闲块。[00:36:41-00:37:30]

若请求 10 字节，搜索必须考虑块头以及对齐后的实际总块长，不能只拿 payload 数与 header 的总 size 直接混比。[00:37:07-00:37:30] 最坏情况下，它对堆中全部块作线性扫描；课件还指出实践中容易在链表前部产生小 splinters。[课件: 19-malloc-basic.pptx p.21]

课件给出的按字寻址遍历骨架为：

```c
p = start;
while ((p < end) &&
       ((*p & 1) ||
        (*p <= len)))
    p = p + (*p & -2);
```

循环继续的原因是：尚未越过末尾，并且当前块已分配或太小；跳转量 `*p & -2` 是屏蔽 allocation bit 后的块长。[课件: 19-malloc-basic.pptx p.21]

### 5. Next fit：从上次停止处继续

**Next fit** 不在每次请求时回到堆首，而是记住上次找到块的位置，下次从那里继续扫描。[00:37:34-00:38:03]

直觉上它避免反复扫描无用的前缀，应当更快；但老师引用经验研究指出，它会造成更差的碎片，因此通常可能不是最佳选择。[00:38:03-00:38:17] [课件: 19-malloc-basic.pptx p.21]

### 6. Best fit：扫描候选并选择剩余最少者

**Best fit** 查看堆中的空闲块，选择能容纳请求且剩余字节最少的块；若请求 10 字节，就找大小最接近且不少于所需大小的空闲块。[00:38:21-00:38:50]

它通常必须扫描所有空闲候选后才能确认“最佳”，所以比遇到首个匹配就停止的 first fit 慢；优点是留下的差额更小，通常改善内存利用率。这是明确的 time-space tradeoff。[00:38:52-00:39:13] [课件: 19-malloc-basic.pptx p.21]

### 7. 用多个 size class 逼近 best fit

若理想化地每个大小都有一个空闲链表，就能立即定位精确大小，以常数时间搜索实现 best fit；问题是这种组织自身占用多少内存。[00:39:24-00:39:54] size class 越多，越接近真正 best fit，但下一节还要讨论分类数量与范围的边际收益。

## 概念、符号与推导

### Header 编码

```text
高位                                         最低位
+---------------------------------------------+-+
| block size                                  |a|
+---------------------------------------------+-+
                                               1 allocated
                                               0 free
```

8 字节对齐意味着 size 是 8 的倍数，二进制低 3 位为 0；占用其中 1 位保存 `a` 后，仍能通过 mask 恢复 size。[00:32:14-00:33:37]

示例：若总块长为 16 字节，则 size 编码为 `0b10000`；allocated header 可把低位设为 1，形成 `0b10001`。读取时：

$$
0b10001\mathbin{\&}(-2)=0b10000=16.
$$

这里的位运算规则来自老师和课件；本段没有引入其他 header 位。[课件: 19-malloc-basic.pptx p.19]

### 放置策略比较

| 策略 | 搜索起点与停止条件 | 老师强调的权衡 |
| --- | --- | --- |
| first fit | 每次从堆首；第一个够大块即停 | 搜索较早停止，但前部可能产生 splinters |
| next fit | 从上次停止处继续；第一个够大块即停 | 避免重扫，但研究显示碎片可能更差 |
| best fit | 比较所有候选，取剩余最少者 | 更慢，通常提高利用率 |

## 例子与课堂提示

- **8、16、24 的二进制低位**：老师口头列举这些 8 的倍数，说明最低 3 位恒为 0，服务于 header 复用低位的技巧。[00:32:14-00:33:04]
- **unused word**：它不是 payload，而是为了让“header 后一个字”落到双字边界；服务于每块 payload 的 8 字节对齐。[00:34:16-00:34:48]
- **16 字节块的 padding**：payload 只有 2 字，剩余字用于保持下一块 payload 对齐，明确展示内部碎片。[00:35:04-00:35:36]
- **`0/1` epilogue**：大小 0 负责终止，allocated 位防止后续把堆外当作空闲邻居。[00:35:45-00:36:40]
- **请求 10 字节**：first fit 找首个足够块；best fit 找最接近 10 的足够块，用来比较提前停止与完整扫描。[00:37:07-00:38:50]

## 易错点与辨析

- **误解：header 的低位本来就是 size 的有效信息。** 对齐保证这些位恒为 0，才允许借其中一位保存状态。[00:31:56-00:33:25]
- **误解：只要 header 对齐即可。** 老师要求的是 payload 对齐；unused word 用来调整 header 与 payload 的相对位置。[00:34:00-00:34:48]
- **误解：`0/1` 表示一个 1 字节块。** 斜线左侧是 size 0，右侧是 allocated bit 1；它是哨兵，不提供 payload。[课件: 19-malloc-basic.pptx p.20]
- **误解：next fit 因少重扫就一定更好。** 老师明确说经验研究显示其碎片通常更差。[00:38:03-00:38:17]
- **误解：best fit 同时更快且更省空间。** 在隐式链表中，它通常要扫描更多候选，以较低吞吐率换取更好的利用率。[00:38:52-00:39:13]

## 本段掌握检查

1. **问：为什么 8 字节对齐时可把 header 的最低位用作 allocated flag？**  
   **答：** 块大小是 8 的倍数，最低 3 位原本恒为 0；借用其中一位后仍可用 mask 恢复大小。[00:31:56-00:33:37]

2. **问：如何从 header `h` 分别取出状态和大小？**  
   **答：** 状态为 `h & 1`，本讲单状态位格式中的大小为 `h & -2`。[课件: 19-malloc-basic.pptx p.21]

3. **问：epilogue 为什么编码为 `0/1`？**  
   **答：** size 0 可终止遍历，allocated 状态可在合并时避免把堆末当成空闲块。[00:35:45-00:36:40]

4. **问：first fit、next fit、best fit 的核心区别是什么？**  
   **答：** first fit 每次从头找首个匹配；next fit 从上次位置继续找首个匹配；best fit 比较候选后取剩余空间最小者。[00:36:50-00:38:50]

5. **问：为什么 best fit 体现时间与空间权衡？**  
   **答：** 它通常需扫描全部候选而更慢，但因选择最接近请求的块，通常提高内存利用率。[00:38:52-00:39:13]

# 第 5 节：块分割、释放、合并与边界标记

> 时间范围：`00:39:59-00:49:56`  
> 主要课件：[课件: 19-malloc-basic.pptx p.21] [课件: 19-malloc-basic.pptx p.22] [课件: 19-malloc-basic.pptx p.23] [课件: 19-malloc-basic.pptx p.24] [课件: 19-malloc-basic.pptx p.25] [课件: 19-malloc-basic.pptx p.26]

## 本段在整讲中的作用

上一段解决了“怎样找一个能容纳请求的空闲块”，本段继续回答“找到以后怎样真正放进去”和“释放以后怎样恢复可用空间”。老师先完成分离空闲链表逼近 best fit 的讨论，再用一个 6 字空闲块容纳 4 字块的例子引出 splitting。随后他指出，仅把 allocated bit 清零会留下相邻但彼此独立的空闲块，形成 false fragmentation；为了让 `free` 同时与前后邻块合并且仍保持常数时间，他引入 Knuth 的 boundary tag（footer）。[00:39:59-00:49:56]

## 教学展开

### 1. 分离链表只能逼近 best fit，分类存在边际收益

size class 越多，每条链表中的块大小越接近，请求就越接近真正的 best fit；但分类增加到一定程度后会出现 diminishing returns。因此实现者要选择空闲链表数量及每个 size range，而不是无条件增加分类。[00:39:59-00:40:22] 这承接上一段“精确大小类可常数时间得到 best fit”的思想实验。[课件: 19-malloc-basic.pptx p.21]

### 2. 找到空闲块后，在整块分配与 splitting 之间选择

应用发出 `malloc`，放置策略已经找到一个足够大的空闲块；接下来的问题是：把整个空闲块交给应用，还是只取所需部分，并把剩余部分保留为空闲块。[00:40:22-00:41:12]

老师的例子是：分配器已经算出所需 **总块长为 4 字，且这 4 字包含 header**；它选中一个 6 字空闲块。两种处理是：[00:41:14-00:42:24]

1. 整个 6 字块都标为已分配，应用只需要其中 4 字，剩余 2 字留在已分配块内部；
2. **split（分割）** 为一个 4 字已分配块和紧随其后的 2 字空闲块。

课件用如下玩具代码表达第二种处理：[课件: 19-malloc-basic.pptx p.22]

```c
void addblock(ptr p, int len) {
  int newsize = ((len + 1) >> 1) << 1;  // round up to even
  int oldsize = *p & -2;                // mask out low bit
  *p = newsize | 1;                     // set new length
  if (newsize < oldsize)
    *(p+newsize) = oldsize - newsize;   // set length in remaining
}                                       //   part of block
```

按本讲的按字寻址模型，步骤是：把 `len` 向上取到偶数以满足双字对齐；用 `& -2` 清掉旧 header 的状态位并得到 `oldsize`；把新块大小和 allocated bit 写回；若确有剩余，就在 `p + newsize` 处写入剩余空闲块的大小。课件例为 `addblock(p, 4)`，把 6 字空闲块变成 4 字已分配块与 2 字空闲块。[课件: 19-malloc-basic.pptx p.22]

### 3. 最简单的 `free` 只清 allocated bit

若 `p` 指向要释放块的 header，最简单的释放只需把最低位清零：[00:42:24-00:42:59]

```c
void free_block(ptr p) { *p = *p & -2; }
```

[课件: 19-malloc-basic.pptx p.23]

块大小保持不变，只把状态从 allocated 改为 free，因此这一步本身是常数时间。

### 4. 只清标志会造成 false fragmentation

前面刚把一个 6 字块分成 4 字已分配块和 2 字空闲块。若随后释放该 4 字块，简单实现会得到两个物理上连续、逻辑上却仍是两个 header 分隔的空闲块：4 字和 2 字。[00:43:01-00:43:51]

若下一次请求需要 5 字，分配器看不到任何单块达到 5 字，尽管这 6 个空闲字不仅总量足够，而且地址也连续。这就是老师所说的 **false fragmentation（假碎片）**。[课件: 19-malloc-basic.pptx p.23]

由此得到一个分配器应维持的 invariant：**不应留下相邻的空闲块**；释放后要把所有相邻空闲块合成尽可能大的单块。[00:43:51-00:44:52]

### 5. 向后看容易，向前看昂贵

释放当前块时，检查内存中后继块很容易。当前 header 给出当前总块长，因此在 `p + size` 处就是下一块 header；读取其 allocated bit 即可决定是否合并。[00:44:56-00:45:28]

课件给出的“只与下一块合并”代码为：[课件: 19-malloc-basic.pptx p.24]

```c
void free_block(ptr p) {
    *p = *p & -2;          // clear allocated flag
    next = p + *p;         // find next block
    if ((*next & 1) == 0)
      *p = *p + *next;     // add to this block if
}                          //    not allocated
```

如果下一块空闲，就把两个 size 相加；下一块原 header 在逻辑上消失。课件图中的 4 字块与后继 2 字块因此合成 6 字块。[课件: 19-malloc-basic.pptx p.24]

困难在前驱块：当前 header 只知道自己的大小，不能直接得知前一个 header 在哪里。按目前的隐式链表格式，只能从堆首重新遍历，并一直记住前一块；这会让 `free` 的成本变成与堆中块数线性相关。[00:45:28-00:46:09]

### 6. 用 boundary tag 支持反向定位

老师介绍 Donald Knuth 1973 年提出的技巧：把 header 中的 size/allocated word 复制到块末尾，得到与 header 相同的 **footer**；Knuth 称它为 **boundary tag（边界标记）**。[00:46:11-00:47:50] [课件: 19-malloc-basic.pptx p.25]

```text
低地址                                                   高地址
+----------------+--------------------------+----------------+
| header: size/a | payload and padding      | footer: size/a |
+----------------+--------------------------+----------------+
```

给定当前块的 header，向低地址方向看前一个字，恰好就是前驱块的 footer。由 footer 可先读出前驱是否 allocated；若需要合并，还可读出前驱总长度并反向定位其 header。因为“向前一个字”是固定偏移，这一检查不再需要从堆首扫描，可在常数时间完成。[00:46:46-00:47:32]

课件把这一结构描述为在空闲块底部复制 size/allocated word，使隐式链表可以向后走；代价是额外空间。[课件: 19-malloc-basic.pptx p.25]

### 7. footer、对齐与块开销共同进入所需块长

学生追问：分配块时是否必须为 boundary tag 留空间。老师回答“是”，并预告稍后会给一个优化。[00:47:55-00:48:21]

因此搜索可容纳请求的块时，所需总块长不能只看 payload，还要计入 header、boundary tag，并加入满足对齐要求的 padding。[00:48:49-00:49:23] footer 对小 payload 的相对开销很大，会明显降低利用率；payload 较大时，同样的固定元数据占比没那么严重。[00:49:25-00:49:48]

在有了前后邻块状态和大小后，老师于段末提出：释放一个块时共有四种邻接情况，下一节逐案处理。[00:49:48-00:49:56] [课件: 19-malloc-basic.pptx p.26]

## 概念、符号与推导

### 分割计算

设选中的空闲块总长为 `oldsize`，对齐后的新已分配块总长为 `newsize`，则剩余空闲块为：

$$
\text{remainder}=\text{oldsize}-\text{newsize}.
$$

课堂数值是：

$$
6-4=2\ \text{words}.
$$

因此 6 字空闲块可分为 4 字已分配块和 2 字空闲块。[00:41:14-00:42:24] [课件: 19-malloc-basic.pptx p.22]

### 假碎片计算

释放刚才的 4 字块后，若不合并，空闲块大小为 4 和 2。对 5 字请求：

$$
4+2=6\ge5,
$$

但

$$
\max(4,2)=4<5.
$$

总空闲空间和连续地址都足够，逻辑块边界却阻止请求成功；合并后得到单个 6 字块即可满足。[00:43:01-00:44:16]

### Boundary tag 的反向定位

若当前 header 地址为 $p$，前一个字 $p-1$ 是前驱 footer。设 footer 给出的前驱总长为 $m$，则前驱 header 位于：

$$
p-m.
$$

老师口述的关键不是推广一套地址公式，而是“footer 固定在当前 header 前一字，先由它取得前驱大小和状态”，从而避免全堆扫描。[00:46:30-00:47:32]

## 例子与课堂提示

- **6 分成 4+2**：用于对比整块分配造成的内部浪费与 splitting 留下新空闲块。[00:41:14-00:42:24]
- **释放后 4+2 无法服务 5**：用于说明只清状态位会制造 false fragmentation，并推导出“不能保留相邻空闲块”的 invariant。[00:43:01-00:44:16]
- **只向后继合并**：当前 size 可直接跳到下一 header；用于显示隐式链表天然支持向高地址遍历。[课件: 19-malloc-basic.pptx p.24]
- **寻找前驱**：没有 footer 时只能从堆首走到当前块；用于说明为什么简单 `free` 会从常数时间退化为线性时间。[00:45:28-00:46:09]
- **小 payload 与大 payload**：用于说明 header/footer 是固定开销，其内部碎片影响取决于请求模式。[00:49:25-00:49:48]

## 易错点与辨析

- **误解：找到够大的空闲块后一定要 split。** 老师把“整块交付还是分割”明确作为策略选择；分割减少当前块内部浪费，但可能产生很小的剩余块。[00:40:22-00:42:24]
- **误解：相邻两个 free header 已经等价于一个大空闲块。** 搜索按 header 把它们视为两块；不修改边界就不能满足跨越两块的请求。[00:43:01-00:44:16]
- **误解：coalescing 只需检查下一块。** 为维持不存在相邻空闲块的 invariant，还必须检查前驱；boundary tag 正是为高效检查前驱而引入。[00:44:23-00:47:32]
- **误解：footer 是指向前驱的显式指针。** 它只是 header 的 size/allocated 副本；前驱位置由 size 推出。[课件: 19-malloc-basic.pptx p.25]
- **误解：footer 没有空间代价。** 它不是 payload，会增加块开销和内部碎片，尤其影响大量小请求。[00:48:06-00:49:48]

## 本段掌握检查

1. **问：6 字空闲块满足 4 字总块请求时，splitting 得到什么？**  
   **答：** 一个 4 字已分配块和一个 2 字空闲块；剩余量是 $6-4=2$。[00:41:14-00:42:24]

3. **问：为什么检查下一块是常数时间，而原格式下检查前一块是线性时间？**

5. **问：计算一个可分配块所需大小时，本段要求考虑哪些部分？**

# 第 6 节：四种常数时间合并与 boundary tag 优化

> 时间范围：`00:49:56-00:59:51`  
> 主要课件：[课件: 19-malloc-basic.pptx p.26] [课件: 19-malloc-basic.pptx p.27] [课件: 19-malloc-basic.pptx p.28] [课件: 19-malloc-basic.pptx p.29] [课件: 19-malloc-basic.pptx p.30] [课件: 19-malloc-basic.pptx p.31]

## 本段在整讲中的作用

上一段已经用 footer 解决了“怎样在常数时间找到前一块”，本段把这一能力落实为完整的双向 coalescing。老师按前后邻块各自 allocated/free 的组合逐一处理四种情况，说明只需检查相邻 header/footer 并改写边界，不必扫描整条隐式链表。接着他正面处理 footer 引入的内部碎片：allocated block 不参与合并，可以省去 footer；为了仍能判断前一块是否空闲，再利用对齐留下的另一个低位，在当前 header 中记录 previous-block allocation status。[00:49:56-00:59:24]

## 教学展开

### 1. 两个邻块的状态产生四种情况

设正在释放的当前块大小为 $n$，前一块大小为 $m_1$，后一块大小为 $m_2$。前、后邻块各有 allocated/free 两种状态，因此共有四种组合：[00:49:56-00:50:23] [课件: 19-malloc-basic.pptx p.26]

| 情况 | 前一块 | 后一块 | 释放后的动作 |
| --- | --- | --- | --- |
| Case 1 | allocated | allocated | 只把当前块改为 free |
| Case 2 | allocated | free | 当前块与后一块合并 |
| Case 3 | free | allocated | 前一块与当前块合并 |
| Case 4 | free | free | 三块全部合并 |

课件 p.26 先并列四种布局，随后 p.27-p.30 分别展示各案的边界字段变化。[课件: 19-malloc-basic.pptx p.26] [课件: 19-malloc-basic.pptx p.27] [课件: 19-malloc-basic.pptx p.28] [课件: 19-malloc-basic.pptx p.29] [课件: 19-malloc-basic.pptx p.30]

### 2. Case 1：前后都 allocated，不发生合并

当前块被两个 allocated block 包围，没有相邻空闲空间可并入。当前块 header/footer 的 size 仍为 $n$，只把 allocation status 从 1 改为 0。[00:50:23-00:50:45]

$$
n\longrightarrow n.
$$

也就是说，块边界和大小都不变，变化的只有当前块状态。[课件: 19-malloc-basic.pptx p.27]

### 3. Case 2：前 allocated、后 free，与后块合并

先看当前 header 前一个字处的 boundary tag，确认前块 allocated，因此左侧不用处理。再用当前大小 $n$ 跳到后块 header，读到后块为 free，于是把当前块和大小为 $m_2$ 的后块合并。[00:50:45-00:51:33]

新空闲块从当前块原 header 开始，总长为：

$$
n+m_2.
$$

新 header/footer 都应表示总长 $n+m_2$ 且 allocation status 为 0；原来位于两块之间的后块 header 不再是逻辑边界。[课件: 19-malloc-basic.pptx p.28]

### 4. Case 3：前 free、后 allocated，与前块合并

当前 header 前一字的 footer 表明前块 free，并给出前块大小 $m_1$；后块 header 表明后块 allocated。因此只合并前块与当前块。[00:51:33-00:52:02]

新空闲块沿用前块原 header 作为起点，总长为：

$$
m_1+n.
$$

老师强调要更新旧前块的 header，并相应更新合并块末端的 boundary-tag footer。[00:51:47-00:52:02] [课件: 19-malloc-basic.pptx p.29]

### 5. Case 4：前后都 free，三块合并

前块 footer 表明左侧 free，后块 header 表明右侧也 free，因而新块覆盖三块，从前块原 header 一直到后块原 footer。[00:52:02-00:52:24]

总长为：

$$
m_1+n+m_2.
$$

新 header/footer 记录这一总长且状态为 free；原先两条内部边界在逻辑上消失。[课件: 19-malloc-basic.pptx p.30]

以上四案只查看固定位置的前驱 footer、当前 header 与后继 header，再做固定次数的字段更新，所以 boundary-tag coalescing 是常数时间，而不是随堆中块数增长。[课件: 19-malloc-basic.pptx p.26]

### 6. Boundary tag 的代价是内部碎片

footer 不属于应用 payload，而是分配器元数据，因此会扩大块并形成内部碎片。[00:52:24-00:52:53] 老师于是追问：哪些块真的需要 footer，allocated block 是否可以没有 footer？这正是课件“Disadvantages of Boundary Tags”提出的优化问题。[课件: 19-malloc-basic.pptx p.31]

关键观察是：只有 free block 才可能与刚释放的邻块 coalesce；allocated block 不参与合并，所以无需通过它的 footer取得其 size。[00:53:48-00:54:18]

### 7. 难点：没有 allocated footer，怎样知道前块状态

若 allocated block 不带 footer，查看当前 header 前一个字时，无法仅凭该字判断它究竟是前驱 footer 还是前驱 payload。可是在决定是否向前合并之前，分配器仍必须知道前一块是 allocated 还是 free。[00:54:18-00:55:07]

老师引导学生回到对齐留下的低位：8 字节对齐使 size 的最低 3 位恒为 0，16 字节对齐使最低 4 位恒为 0；目前只用其中 1 位保存当前块的 allocation status，因此还可借用另一个低位保存 **前一块的 allocation status**。[00:55:07-00:55:31]

可把优化后的 header 概念化为：

```text
高位                                  低位
+--------------------------------------+---+---+
| size                                 |pa | a |
+--------------------------------------+---+---+
                                         |   +-- 当前块：1 allocated / 0 free
                                         +------ 前一块：1 allocated / 0 free
```

这里的 `pa` 只是便于笔记说明的名字；老师口述为“用另一个 spare bit 表示 previous block 的 allocation status”，没有在本段给它规定变量名。[00:55:19-00:56:32]

### 8. 只给 free block 保留 footer

有了 previous-allocation bit 后，判断流程是：[00:55:32-00:57:49]

1. 若当前 header 记录前块 allocated，则不向前合并，也不需要知道前块大小；因此 allocated block 可以没有 footer。
2. 若当前 header 记录前块 free，则需要向前合并；free block 保留 footer，可从当前 header 前一个字读取其 size，再定位并更新前块 header。

这样，footer 只存在于 free blocks：它在真正需要反向取得 size 时可用，又不再占用 allocated blocks 的空间。[00:56:40-00:57:49]

### 9. 再次解释为什么低位可复用

学生追问这些位为什么必为 0。老师重新从对齐推导：payload 要按 8 或 16 字节边界对齐，为使后继 payload 仍正确对齐，每个总块长也必须是 8 或 16 的倍数；于是 size 二进制的最低 3 或 4 位恒为 0。[00:57:51-00:59:12]

这一事实既支持当前块的 allocated bit，也支持 previous-block allocated bit。老师在确认没有其他问题后，于 `00:59:24` 转入分配器关键策略的总结。[00:59:12-00:59:51]

### 四种合并结果

| 情况 | 邻接状态（前/后） | 新空闲块大小 | 新块起点 |
| --- | --- | --- | --- |
| Case 1 | allocated / allocated | $n$ | 当前块原 header |
| Case 2 | allocated / free | $n+m_2$ | 当前块原 header |

### 优化后的判断逻辑

设当前 header 的 previous-allocation bit 为 $pa$：

- $pa=1$：前块 allocated，不向前合并，也不读取前驱 size；
- $pa=0$：前块 free，前一个字是有效 footer，由它取得前驱 size 后向前合并。

### 对齐与可复用位数

## 易错点与辨析

# 第 7 节：分配器策略与隐式链表总结

> 时间范围：`00:59:51-01:06:13.120`  
> 主要课件：[课件: 19-malloc-basic.pptx p.32] [课件: 19-malloc-basic.pptx p.33]

## 本段在整讲中的作用

本段是全讲收束。老师不再增加新的块格式，而是把此前的设计选择归纳为三类 policy：placement 决定“选哪块”，splitting 决定“剩余空间怎样处理”，coalescing 决定“何时合并相邻空闲块”。他随后总结隐式链表的复杂度和用途：实现简单、分配最坏线性、释放即使含合并仍为常数时间，因此不适合作为通用 `malloc/free` 的常见组织；但 splitting 与 boundary-tag coalescing 是可迁移到其他分配器的重要技术。[00:59:51-01:05:54] 最后预告下一讲的 explicit list 与 multiple free lists，并在 `01:06:13.120` 结束。[01:05:54-01:06:13.120]

## 教学展开

### 1. Placement policy：速度与碎片之间取舍

第一个决策是把已分配块放进空闲链表中的哪一个空闲块，即采用 first fit、next fit、best fit 或其他策略。[00:59:51-01:00:10] [课件: 19-malloc-basic.pptx p.32]

老师再次强调一般权衡：更充分地搜索候选会降低 throughput，却可能减少 fragmentation、提高 memory utilization。best fit 需要为更接近请求大小的块付出更长搜索；较快策略则可能留下更不利的空闲布局。[01:00:10-01:00:34]

### 2. Good fit：只在有限搜索范围内取最佳

为了改善 best fit 的性能，可以采用老师称为 **good fit** 的折中：不扫描整个堆，只搜索其中一部分；到达截止位置后，在已经看过的候选中选最合适者。[01:00:34-01:01:08]

其教学逻辑是：

1. first fit 很快停止，但不比较后续候选；
2. best fit 比较全体候选，内存利用率通常更好但搜索慢；
3. good fit 限制搜索区间，在局部候选中取 best，因而近似 best fit 而避免完整扫描。

老师没有在本段给出 good fit 的固定扫描长度、复杂度公式或质量保证，因此它只是一个可调策略示例。[01:00:44-01:01:08]

### 3. Multiple/segregated free lists 同时缩短搜索并逼近 best fit

另一种近似 best fit 的办法是按 size class 维护多条空闲链表。目标大小会把搜索导向一条只含相近大小块的链表，所以候选更可能匹配请求；全部空闲块被分散到多条链表后，每条链表也更短。[01:01:08-01:02:05]

因此老师指出它可能同时改善两方面：

- 块大小更接近请求，提高 memory utilization；
- 搜索链更短，提高查找性能。

课件把这一观察写成：segregated free lists 不必搜索整条 free list，也可近似 best-fit placement；具体结构留到下一讲。[课件: 19-malloc-basic.pptx p.32]

### 4. Splitting policy：如何处理选中块的 leftover

第二类决策发生在已找到足够大的空闲块之后：是把整块交给应用，让 leftover 留在已分配块内，还是分割出恰好所需的已分配部分并创建较小空闲块。[01:02:05-01:02:52]

这不是“总要分割”的机械规则。老师举出一种阈值策略：小请求时可能不 split，或不允许产生小于某个 threshold 的新空闲块；只在剩余部分足够大时才分割。[01:02:54-01:03:19]

这一策略直接表达内部碎片与外部可用性的取舍：不 split 会把 leftover 留作已分配块内部的浪费；split 过度则可能制造很小、难以使用的 free block。[课件: 19-malloc-basic.pptx p.32]

### 5. Coalescing policy：立即合并或延迟合并

第三类决策是何时 coalesce。借助 boundary-tag footer，课堂实现即使在 `free` 时合并，仍是常数时间。[01:03:19-01:03:31]

两种策略是：[01:03:31-01:04:28]

- **Immediate coalescing**：每次调用 `free` 都立即合并相邻空闲块；这是前面四案所采用的策略。
- **Deferred coalescing**：先只释放，推迟到以后再合并。例如响应 `malloc`、扫描 free list 寻找放置位置时顺便合并。

老师没有宣布某种策略普遍更好；他认为在 boundary-tag coalescing 已是常数时间的条件下，很难为延迟合并给出强理由，但它仍是设计空间中的选项。[01:04:10-01:04:28]

课件还列出另一种 deferred 触发条件：当 external fragmentation 达到某个 threshold 时再合并。该项只见于课件，本段口述没有展开其度量或阈值算法。[课件: 19-malloc-basic.pptx p.32]

### 6. 隐式链表的成本总结

老师把 implicit list 定位为非常简单的 allocator，并给出三项结论：[01:04:28-01:05:04] [课件: 19-malloc-basic.pptx p.33]

1. **Allocate cost**：最坏情况下与堆中块数线性相关，因为搜索可能遍历整个 heap。
2. **Free cost**：最坏仍为常数时间，即使进行 boundary-tag coalescing。
3. **Memory usage**：取决于 placement policy，例如 first fit、next fit 或 best fit 产生的布局不同。

课件用“linear time worst case”概括 allocate；口述说“linear in the size of the heap”。结合本讲的隐式遍历模型，可确定其含义是搜索成本随必须经过的堆块增长，而不是给出按字节逐字扫描的新算法。[01:04:34-01:04:57]

### 7. 实际适用边界与可迁移概念

由于 allocation 的线性搜索成本，implicit list 通常不用于实践中的通用 `malloc/free`。[01:05:04-01:05:12] 在特殊用途下仍可能适用，例如可确定 free list 很小，或相关 size class 数量很少。[01:05:12-01:05:24]

本讲学习 implicit list 的价值不在于照搬其整体结构，而在于它清楚引出了两个通用概念：[01:05:24-01:05:54]

- splitting；
- boundary-tag-based coalescing。

老师明确说，boundary-tag coalescing 可用于不同结构的 free list，不依赖整体是否是 implicit list。[01:05:31-01:05:41] [课件: 19-malloc-basic.pptx p.33]

## 本段掌握检查

1. **问：good fit 怎样折中 first fit 与 best fit？**  
   **答：** 它只搜索堆的一部分，然后在已搜索候选中选择最合适的块，避免 best fit 的完整扫描。[01:00:34-01:01:08]

2. **问：segregated free lists 为什么可能同时改善速度和利用率？**  
   **答：** 目标链中的块大小更接近请求，且全部空闲块被分散后单链更短，所以匹配概率提高、搜索量下降。[01:01:08-01:02:05]

3. **问：splitting policy 要决定什么？**  
   **答：** 决定是否把选中空闲块的 leftover 拆成新空闲块；可用最小剩余块阈值避免制造过小块。[01:02:05-01:03:19]

4. **问：immediate 与 deferred coalescing 有何区别？**  
   **答：** immediate 在每次 `free` 时合并；deferred 推迟到以后，例如 `malloc` 扫描 free list 时再合并。[01:03:19-01:04:28]

5. **问：隐式链表的 allocate/free 最坏成本分别是什么，哪些概念仍具一般性？**  
   **答：** allocate 为线性时间，free 即使合并仍为常数时间；splitting 与 boundary-tag coalescing 可用于其他 allocator。[01:04:28-01:05:48]
