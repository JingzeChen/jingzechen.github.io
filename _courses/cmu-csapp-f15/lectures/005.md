## 需要的先修知识与课堂假设

### 先修知识

- 能读基本 C function、pointer dereference、`long`、local temporary 和 expression。
- 理解 bit、byte、hexadecimal 与 left/right shift；本讲沿用此前 data-representation lectures 的 bit-level model。
- 知道 compiler 将 source language 转为低层 code，但不要求预先掌握 assembler、linker 或 ABI。
- 能做基础代数化简，例如 $x+2x=3x$、$v\ll k=v\cdot2^k$，并能手算简单 hexadecimal addition。

### 本讲明确采用的假设

- 目标是 **x86-64**，不再以 IA32 为主线；IA32 仅作为 history/web aside。[课件: 05-machine-basics.pptx p.9]
- Assembly 采用 AT&T syntax：register 前缀 `%`，immediate 前缀 `$`，source 在前、destination 在后。
- 课堂示例的 `long` 与 `movq` 都按 8 bytes 处理；`q` 是 quad word。[课件: 05-machine-basics.pptx p.18]
- `sumstore`/`swap`/`arith` 的 register mapping 来自课件展示的特定 compiler output，不是变量与 register 的永久绑定。
- `swap` 中 `0x120`、`0x100` 是为了手算而选的非典型小地址。
- 本讲解释 ISA-visible semantics，不展开 instruction bit-field encoding、full calling convention、condition-code details、cache organization、virtual-memory translation 或 processor pipeline。

## 老师的教学主线与依赖关系

### 1. 先说明为什么要读 machine code（`00:00:01-00:04:40`）

Object-code bytes 是 processor 真正执行的 program，assembly 是其可读文本表示。课程把 machine code 当作 C intent 与 machine execution 之间的 gateway：学生不以汇编重写应用，而是从 GCC output 反推 expression、procedure 和 data structure 怎样落到机器上。[课件: 05-machine-basics.pptx p.1] [课件: 05-machine-basics.pptx p.2]

### 2. 用 x86 历史解释后续不规则（`00:04:40-00:19:56`）

8086 的 compatibility lineage、386/IA32 的 32-bit flat addressing、power wall 后的 multicore、Intel IA64 的激进路线与 AMD x86-64 的渐进路线，共同说明 architecture 不只由“最整齐的设计”决定，也由 backward compatibility、software ecosystem、power 与市场约束决定。[课件: 05-machine-basics.pptx p.3] [课件: 05-machine-basics.pptx p.4] [课件: 05-machine-basics.pptx p.6] [课件: 05-machine-basics.pptx p.8]

### 3. 建立 ISA 与 machine state（`00:19:56-00:24:48`）

ISA 定义 compiler 和 machine-code programmer 必须依赖的行为；microarchitecture 决定内部实现。ISA view 暴露 PC/RIP、registers、condition codes 与 byte-addressed memory，同时抽象掉 cache 和 virtual-memory mechanism。[课件: 05-machine-basics.pptx p.11] [课件: 05-machine-basics.pptx p.12]

### 4. 沿 toolchain 把 C 降到 bytes，再反向观察（`00:24:48-00:47:47`）

`sumstore` 依次经过 compiler、assembler、linker，六条 instructions 编成 14 bytes。`objdump` 与 GDB 从 bytes 恢复 approximate assembly，但不能恢复 C variable names、types 与原始 intent。这个双向流程建立后，学生才有工具证据支撑后续逐条分析。[课件: 05-machine-basics.pptx p.13] [课件: 05-machine-basics.pptx p.14] [课件: 05-machine-basics.pptx p.17] [课件: 05-machine-basics.pptx p.19]

### 5. 从 storage locations 进入 data movement（`00:47:49-00:59:44`）

先认识 16 个 integer registers 和 aliases，再定义 immediate/register/memory operands；随后用 `movq` 的五种合法组合区分 temporary copy、load、store。`(R)` 与 `D(R)` 把 register-held address 连接到 C pointer dereference，`swap` 则把四个 dereferences 落成 four moves。[课件: 05-machine-basics.pptx p.23] [课件: 05-machine-basics.pptx p.26] [课件: 05-machine-basics.pptx p.27] [课件: 05-machine-basics.pptx p.28]

### 6. 从简单 dereference 扩展到 address arithmetic（`00:59:44-01:08:41`）

老师先逐条模拟 `swap`，再推广到 $D(R_b,R_i,S)$。Scale 1/2/4/8 对应常见 element size；同一 address expression 放在 `movq` 中表示 memory access，放在 `leaq` 中只表示 arithmetic result。`m12` 用 `leaq` 与 shift 展示 compiler 不必逐字复刻 C operator。[课件: 05-machine-basics.pptx p.34] [课件: 05-machine-basics.pptx p.36] [课件: 05-machine-basics.pptx p.39]

### 7. 最后用 `arith` 验证“语义等价，不是文本对应”（`01:08:41-01:13:16`）

Two-operand instructions 覆盖 destination，one-operand instructions 直接修改单一 operand。`arith` 把 `leaq`、`addq`、`salq`、`imulq` 组合起来：`y*48` 变为 `3y<<4`，`x+4` 融入后续 `leaq`，旧 `%rdx` 在 `z` 被消费后复用。逐条 symbolic execution 最终证明 `%rax=(x+y+z)(x+4+48y)`。[课件: 05-machine-basics.pptx p.40] [课件: 05-machine-basics.pptx p.41] [课件: 05-machine-basics.pptx p.43]

### 2. Programmer-visible state

| State | x86-64 name/view | 本讲作用 |
| --- | --- | --- |
| Program counter | `%rip` | 保存下一条 instruction 的 address |
| Integer register file | 16 个 64-bit registers 及 aliases | 保存 integers、pointers、temporaries |
| Condition codes | 若干 status bits | 记录近期 arithmetic/logical result，供 conditional branch 使用 |
| Memory | Byte-addressable array | 保存 code、data、stack；通过 computed address load/store |

[课件: 05-machine-basics.pptx p.12]

### 3. x86-64 integer registers

```text
64-bit legacy names:
%rax %rbx %rcx %rdx %rsi %rdi %rsp %rbp

64-bit added names:
%r8  %r9  %r10 %r11 %r12 %r13 %r14 %r15

low 32-bit views:
%eax %ebx %ecx %edx %esi %edi %esp %ebp
%r8d %r9d %r10d %r11d %r12d %r13d %r14d %r15d
```

- `%rsp` 是 stack pointer，不能作为普通 temporary 随意使用。
- `%eax` 是 `%rax` 的 low-order 32-bit view，不是独立 register。
- `%ax/%al/%ah` 等更低位 aliases 是 backward-compatibility legacy；本讲不要求完整背诵所有 byte aliases。[课件: 05-machine-basics.pptx p.23] [课件: 05-machine-basics.pptx p.24]

### 4. Operand syntax

| Syntax | Type | Meaning in `movq` context |
| --- | --- | --- |
| `$Imm` | Immediate | Constant value `Imm` |
| `%rX` | Register | `Reg[%rX]` |
| `(%rX)` | Memory | 以 `Reg[%rX]` 为 address 的 8 bytes |
| `D(%rX)` | Memory | 以 `Reg[%rX]+D` 为 address 的 8 bytes |
| `D(Rb,Ri,S)` | Memory/address expression | $EA=Reg[R_b]+S\cdot Reg[R_i]+D$ |

[课件: 05-machine-basics.pptx p.25] [课件: 05-machine-basics.pptx p.27] [课件: 05-machine-basics.pptx p.36]

### 5. `movq` 五种合法组合

| Source -> Destination | Example | C analogy |
| --- | --- | --- |
| Immediate -> Register | `movq $0x4,%rax` | `temp = 0x4;` |
| Immediate -> Memory | `movq $-147,(%rax)` | `*p = -147;` |
| Register -> Register | `movq %rax,%rdx` | `temp2 = temp1;` |
| Register -> Memory | `movq %rax,(%rdx)` | `*p = temp;` |
| Memory -> Register | `movq (%rax),%rdx` | `temp = *p;` |

不存在 destination immediate，也不能用单条 `movq` 直接 memory-to-memory；后者必须先 load 到 register，再 store。[课件: 05-machine-basics.pptx p.26]

### 6. Addressing 与 `leaq`

$$
D(R_b,R_i,S) \Longrightarrow EA=Reg[R_b]+S\cdot Reg[R_i]+D
$$

| Field | Constraint |
| --- | --- |
| `D` | 1/2/4-byte constant displacement |
| `Rb` | 任一 integer register |
| `Ri` | 任一 integer register，except `%rsp` |
| `S` | 1、2、4、8 |

```asm
movq D(Rb,Ri,S), %rax   # %rax <- M[EA]，访问 memory
leaq D(Rb,Ri,S), %rax   # %rax <- EA，不访问 memory
```

[课件: 05-machine-basics.pptx p.36] [课件: 05-machine-basics.pptx p.39]

### 7. Arithmetic/logical instructions

Two-operand general form：

```text
opq Src, Dest   ->   Dest <- Dest op Src
```

| Instruction | Computation/meaning |
| --- | --- |
| `addq Src,Dest` | `Dest = Dest + Src` |
| `subq Src,Dest` | `Dest = Dest - Src` |
| `imulq Src,Dest` | `Dest = Dest * Src` |
| `salq Src,Dest` / `shlq` | Left shift |
| `sarq Src,Dest` | Arithmetic right shift |
| `shrq Src,Dest` | Logical right shift |
| `xorq Src,Dest` | Bitwise XOR |
| `andq Src,Dest` | Bitwise AND |
| `orq Src,Dest` | Bitwise OR |

One-operand forms：

| Instruction | Computation |
| --- | --- |
| `incq Dest` | `Dest = Dest + 1` |
| `decq Dest` | `Dest = Dest - 1` |
| `negq Dest` | `Dest = -Dest` |
| `notq Dest` | `Dest = ~Dest`，不是 logical `!` |

[课件: 05-machine-basics.pptx p.40] [课件: 05-machine-basics.pptx p.41]

## 易错点与推理陷阱

### 表示与工具

- 把 assembly text 当成 CPU 直接执行的 bytes；实际还需 assembler 编码。
- 把 `gcc` 当作单一转换；它可驱动 compiler、assembler、linker 多阶段。
- 看到真实 `.s` 中以 `.` 开头的 directives 就当成未知 instructions；它们服务 assembler/debugger/linker。
- 假设同一 C source 在 Mac、其他 GCC version、不同 optimization 下必须生成相同 assembly；本讲输出以 shark environment 为准。[课件: 05-machine-basics.pptx p.14]
- 认为 disassembler 能恢复 C variable names、types 或 exact source structure；ordinary bytes 不保存这些信息。
- 忽略 executable 中 startup/runtime/library code，误以为每个 function 都来自自己的 `.c`。
- 把“可反汇编”误认为“license 允许 reverse engineering”；技术与许可边界分开。[课件: 05-machine-basics.pptx p.21]

### Registers 与 operands

- 把 `%rax` 与 `%eax` 当成独立 registers；后者是前者 low 32-bit view。
- 因 legacy name 猜固定用途；多数 registers 的当前角色由 data flow 决定，`%rsp` 是明确特殊例外。
- 混淆 `$0x400`、`%rax`、`(%rax)`：分别是 immediate、register value、memory dereference。
- 忘记 AT&T syntax 是 source first、destination last，导致 `subq` 方向读反。
- 认为 `movq` 可以 memory-to-memory；必须经 register 分两条 instructions。
- 认为 “move” 会清空 source；它复制 value。

### Addressing 与 arithmetic

- 把括号出现等同于必然访问 memory；`leaq` 只计算 expression，不 dereference。
- 忘记 scale 限制为 1/2/4/8，或把 `%rsp` 用作 index register。
- 将 effective address 与 address 内的 memory value 混为一谈。
- 把 `q` 错解为 4 bytes；quad word 是 64 bits/8 bytes。
- 把 `notq` 当 logical `!`；它对应 bitwise `~`。
- 认为 signed/unsigned 在所有 instructions 上都完全相同；本讲已明确 `sarq` 与 `shrq` 的区别，comparisons 等尚未覆盖。
- 强迫每个 C temporary 对应一个永久 register；compiler 可融合 temporary、重用 dead register、重排 independent operations。
- 只靠 assembly 与 C 的文本相似度判断正确性；应逐条维护 symbolic state/invariant。

## 全讲快速自测

1. **问：为什么 assembly 是 gateway，却不是本课主要编程语言？**  
   **答：** 它直接表示 compiler 选择的 machine instructions，能解释 C 如何执行；但完整低层 sequence 冗长，生成工作更适合 compiler。

2. **问：ISA abstraction 同时服务 compiler writer 和 hardware designer 的方式是什么？**  
   **答：** Compiler 只依赖规定的 instructions/register behavior；hardware designer 可在不改变 contract 的前提下选择不同 microarchitecture implementation。

3. **问：看到 `leaq 4(%rdi,%rdx),%rcx` 时，最先应问什么？**  
   **答：** 这是 `lea`，所以只计算 `4 + %rdi + %rdx` 并写 `%rcx`，不读取该 address 的 memory。

4. **问：为什么 `arith` 中 `%rdx` 可先是 `z`，后又是 `48y`？**  
   **答：** `z` 已被加到 `%rax`，其独立 lifetime 结束；compiler 可重用 register 保存新的 intermediate。

5. **问：读 compiler-generated assembly 的可靠证明方法是什么？**  
   **答：** 从 argument/register assumptions 出发，按每条 instruction 的精确定义维护 symbolic state，最终比较 observable result 与 C semantics。

## 教学展开

### 1. 从高级语言跨入“逐条指令”的视角（`00:00:01-00:00:26`）

老师把 machine-level programming 称为课程真正的核心：不再只从 C statement 看程序，而是考虑程序触发机器执行的每一条 instruction。这里的切换不是换一种语法写同一程序，而是把问题改为：高级语言构造最终被分解成哪些机器动作，机器可见状态如何随每条指令改变。[课件: 05-machine-basics.pptx p.1] [课件: 05-machine-basics.pptx p.2]

### 2. 同一机器程序的两种表示（`00:00:26-00:01:23`）

老师先给出两种 code form：

1. **Object code**：实际运行在计算机上的 byte sequence；每段 bytes 编码处理器执行的 instructions。
2. **Assembly code**：为了让人能够阅读这些 instructions 而使用的 text representation。

他说两者之间有紧密、近似逐指令的对应，因此课堂上有时会宽泛地把二者都称为 machine code。学习时仍应保持表示层次清晰：

```text
assembly text  --assembler-->  object-code bytes  --processor-->  state changes
```

“一一对应”在本节的教学含义是每条文本指令会得到机器编码，不能据此推断 source-level variable name、类型或控制结构会完整保留；后面反汇编时会看到这些高层信息已经丢失。

### 3. 本课不是传统的“手写汇编课”（`00:01:25-00:03:44`）

老师对比了两种教学方式：

- 传统 assembly programming course 让学生用汇编完成排序、数据结构等完整任务。
- 15-213/15-513 只会在极小范围内手写汇编，主要分析 **GCC 从 C 生成的代码**。

教学目标是建立如下双向理解：

```text
C 中写出的意图
    -> compiler 选择的低层指令序列
    -> machine 的实际执行
    -> 从汇编反推 procedure、expression、array、struct 等高层构造
```

这条路径解释了为什么汇编仍重要：它是 source language 与执行机器之间的 gateway。学生需要问“compiler 的输出怎样实现输入”，而不是与 compiler 比赛手写大型程序。后续若干讲会分别解释 procedure/function 与 array/struct 的机器级实现；本节只列出路线，尚未展开。

### 4. 限定研究对象与本讲路线（`00:03:53-00:04:40`）

机器指令集很多，本课程只选择 Intel 64-bit instruction set，即 **x86-64**。本讲按以下顺序推进：[课件: 05-machine-basics.pptx p.2]

1. Intel processors/architectures 的历史。
2. C、assembly、machine code 的关系。
3. Registers、operands、move 等 assembly basics。
4. Arithmetic 与 logical operations，并开始读真实 compiler output。

这是一条依赖链：若不先知道机器状态和 operand 怎样表示，就无法逐条模拟 arithmetic instruction；若不先知道 compiler/assembler 的角色，就容易把汇编文本误当成 CPU 直接读取的文件。

### 5. “x86”名称与历史累积式设计（`00:04:40-00:06:07`）

“x86”来自早期 8086 及后续处理器名称中共同的 “86”。老师用 **English 与 Esperanto** 作类比：x86 像自然演化的英语，不是从零开始、追求整体规则整齐的设计；许多局部决策在当时合理，长期叠加后却留下 irregular cases。

这个类比服务于后续阅读策略：

- 遇到不规则命名或特殊约束时，先考虑 backward compatibility 和历史遗留。
- 不应期待所有语法都能从一个优雅原则推出。
- “不够整齐”不等于“不值得学”；它因现实市场和软件生态而非常有用。

课件将这一性质概括为 **evolutionary design**，并明确说明兼容性可一直追溯到 1978 年的 8086。[课件: 05-machine-basics.pptx p.3]

### 6. CISC、RISC 与课程的取舍（`00:06:07-00:08:00`）

老师纠正并定义两类术语：

- **RISC**：Reduced Instruction Set Computer。
- **CISC**：Complex Instruction Set Computer；x86 是经典例子。

x86 有大量 instructions 和 formats，完整手册规模很大。课程不会覆盖整个 ISA，而是聚焦 Linux 上 GCC 为常见 C program 生成的小子集。[课件: 05-machine-basics.pptx p.3]

老师的判断包含两个维度：复杂 x86 理论上很难与较简洁的 RISC 在实现效率上竞争，但 Intel 依靠市场力量和 semiconductor technology 达到了很高的 speed；课件同时保留边界：在 low power 方面优势较弱。[课件: 05-machine-basics.pptx p.3]

因此学习策略不是背“500 多条指令”，而是先掌握 compiler output 中反复出现的核心形式。

### 7. 8086：兼容链的起点（`00:08:04-00:08:35`）

8086 于 1978 年推出，是早期 single-chip 16-bit Intel processor；其一个变体成为 original IBM PC 的基础。课件补充其规模为 29K transistors、5-10 MHz、1 MB address space。[课件: 05-machine-basics.pptx p.4]

本讲引用这些数字不是为了硬件考古，而是说明今日 x86-64 仍背负一个从 16-bit 时代开始的 compatibility lineage。

### 8. 386/IA32：从 16-bit PC 到可运行 Unix 的 32-bit 平台（`00:08:35-00:09:34`）

386 于 1985 年把架构推进到 32 bits，并采用课件所称的 “flat addressing”，使其能够运行 Unix；这一 32-bit architecture 称为 **IA32**。[课件: 05-machine-basics.pptx p.4]

老师的因果链是：

```text
32-bit extension + 更平坦的 addressing model
    -> 更像通用 processor
    -> 能支撑 Unix/Linux 一类系统
    -> IA32 长期成为主流 code target
```

Fall 2015 是课程首次完全转向 x86-64；此前最近一个 summer 仍教 IA32。这个时间点解释了为何课件和教材仍会讨论 IA32 legacy，但本课程主线不再以它为目标。

### 9. 64-bit 过渡的开端：兼容性先于断裂（`00:09:34-00:10:00`）

老师先点出 Pentium 4E 代表 Intel x86 进入 64-bit 的 milestone，完整的 Intel/AMD 历史放到下一节。此处最重要的设计选择是：能运行 64-bit code 的机器仍能运行 32-bit code，因此硬件推出时不要求整个软件生态同时迁移。[课件: 05-machine-basics.pptx p.4]

这再次印证 evolutionary design 的主线：x86 的成功与不规则性，都和维持旧软件可运行密切相关。

## 常见误解

- **误解：Assembly code 就是 CPU 直接读取的字符文本。** CPU 执行 object-code bytes；assembly 是相应的可读文本表示。
- **误解：学 machine-level programming 就要用汇编写完整应用。** 本课主要分析 compiler-generated code，只在很小范围手写。
- **误解：C 的 procedure、array、struct 会作为同名对象直接存在于机器码。** 它们要由 compiler 组合低层指令和 bytes 来实现，具体映射将在后续讲解。
- **误解：CISC 意味着每个程序会用到数百条 x86 指令。** 课程和常见 Linux compiler output 只涉及较小子集。[课件: 05-machine-basics.pptx p.3]
- **误解：x86 的所有不规则都是任意错误。** 很多 artifact 来自局部演化和 backward compatibility；理解历史能解释其来源，但不等于所有规则都可忽略。
- **误解：从 IA32 到 x86-64 是一次完全断裂。** 64-bit processors 仍可运行 32-bit code，迁移因而可以渐进发生。

1. **问：Object code 与 assembly code 的核心差别是什么？**

2. **问：为什么本课仍把汇编放在核心，却不要求大量手写汇编？**

3. **问：English/Esperanto 类比试图解释 x86 的什么性质？**  
   **答：** x86 是长期演化和功能叠加的结果，实用且普及，但包含不规则和历史 artifact，并非从零统一设计。

4. **问：8086 与 386 各自代表什么 milestone？**

   **答：** x86-64 machines 保留运行 32-bit code 的能力，不要求所有既有软件同时重写或重编译。

## 本段在整讲中的作用

上一节用 evolutionary design 解释 x86 的历史包袱，本节继续追问这种演化为什么最终产生今天课程所学的 x86-64。老师先从兼容迁移讲到 power budget 和 multicore，再讲 AMD 对 64-bit extension 的关键作用以及 Intel IA64 的失败路线，最后明确课程只覆盖 x86-64。ARM 被用作另一条现实主流路线的对照，但不是本课程的教学目标。[课件: 05-machine-basics.pptx p.8] [课件: 05-machine-basics.pptx p.9]

## 学习目标

- 解释 backward compatibility 如何使 32-bit 软件逐步迁移到 64-bit。
- 从 power budget 推出 frequency scaling 停滞与 multicore 转向的课堂逻辑。
- 区分 core、cache 与 integrated I/O 在本节中的角色，不提前混入后续微架构细节。
- 按顺序复述 Intel IA64/Itanium 与 AMD x86-64 两条路线及最终结果。
- 说明 Fall 2015 课程为何只讲 x86-64，以及 IA32/ARM 被放在什么边界之外。

## 前置知识与边界

- 依赖第 1 节的 8086→386/IA32→64-bit milestone。
- 本节数据反映 2015 年课堂状态，不代表当前处理器规格或市场格局。
- 老师用 cache 作直观预告，只说它保存近期访问数据以加速复用；cache organization 留到后续课程。
- 本节讨论 architecture history，不要求由 transistor count 推导性能，也不把 clock frequency 当作完整性能指标。

## 教学展开

### 1. 兼容性让 64-bit 迁移不必“一夜完成”（`00:10:00-00:10:23`）

老师承接上一节：64-bit x86 processors 仍能运行 32-bit code。因而硬件厂商可以先部署新机器，用户无需同时替换全部软件；随后约十年中，软件生态才逐渐从 IA32 迁移到 64-bit。[课件: 05-machine-basics.pptx p.4] [课件: 05-machine-basics.pptx p.8]

这体现 evolutionary solution 的价值：兼容旧代码降低迁移阻力，但也让旧模式长期存在。

### 2. 频率增长遇到 power wall（`00:10:23-00:11:18`）

老师回顾 single-processor speed 曾持续上升，但约在 2004 年遇到严重功耗问题。芯片逼近约 100 W 时，热量必须在有限机箱内排出；继续提高 clock frequency 会突破可接受的 power budget。因此单核频率此后长期停留在数 GHz 量级。

推理链是：

```text
提高频率 -> 功耗/散热压力增大 -> 接近可接受功耗上限
        -> 不能继续依靠频率让单个 processor 持续变快
```

这里是课堂的定性解释，不是功耗公式或某一 processor 的精确上限。

### 3. 从“更快单核”转向“同芯片更多 cores”（`00:11:18-00:12:15`）

既然不能持续提高单个 processor 的频率，厂商便把多个 independent processors 放在一块 chip 上，称为 cores/multicore。老师以当时设备举例：laptop 常见 2 cores，server 可到 16 cores，课程 shark machines 是 2008 年的 4-core systems。课件把 Core 2（2006）列为首个 multi-core Intel milestone，把 shark machines 的 Core i7（2008）列为 4 cores。[课件: 05-machine-basics.pptx p.4]

老师强调旧 shark machines 仍“相当不错”，同时说明 2008 到 2015 单个 core 并未像更早年代那样持续大幅变快。不能从这里推出所有 workload 都会自动因多核加速；本节尚未讲 parallel software。

### 4. Shared cache 与 2015 Broadwell 集成趋势（`00:12:15-00:14:11`）

老师先展示与 shark era 相近的 4-core chip：四个 cores 位于同一 chip，并共享底部的一块 cache。此处 cache 只作功能性定义：暂存最近访问的数据，使再次访问可能更快。

随后转到 2015 Broadwell：[课件: 05-machine-basics.pptx p.6]

| Model | Cores | Clock | Power | 课堂强调的集成 |
| --- | ---: | --- | ---: | --- |
| Desktop | 4 | 3.3-3.8 GHz | 65 W | Integrated graphics |
| Server | 8 | 2-2.6 GHz | 45 W | Integrated I/O |

老师按芯片外围连接逐项说明：DDR 连接 DRAM/main memory，PCI 连接 peripherals，SATA 连接 disks，USB 连接外设，Ethernet 连接 network。结论是现代 chip 不只包含 processor cores，也集成把 processor 接入更大系统的逻辑。

最后比较 65 W desktop 与 45 W server，指出大规模机房中 power 是首要工程约束之一。课件数字只描述这两个 2015 model，不能泛化为所有 server 一定比 desktop 省电。[课件: 05-machine-basics.pptx p.6]

### 5. AMD 从追随者到 x86-64 提案者（`00:14:21-00:15:25`）

老师先把 AMD 描述为 Intel 的长期竞争者：历史上通常稍慢但便宜；后来招募 circuit designers，推出 Opteron，并发展出自己的 64-bit x86 extension。[课件: 05-machine-basics.pptx p.7]

AMD 能制造 x86-compatible processors，与过去 patent disputes 后形成的 cross-licensing arrangement 有关。这个背景随后解释 Intel 为什么可以采用几乎相同的 64-bit extension。

本段对 2015 市场优劣的评价是时代性材料；应保留为当时课堂叙述，不升级为当前结论。[课件: 05-machine-basics.pptx p.7]

### 6. Intel IA64/Itanium：激进断裂路线（`00:15:25-00:16:20`）

Intel 在 2001 年试图从 IA32 转向完全不同的 **IA64** architecture，即 Itanium。老师的解释是：该方案技术上有趣、纸面结果有吸引力，但过度依赖 compiler 展现近乎“奇迹般”的 optimization capability，最终 performance 和市场表现不理想。IA32 code 只能作为 legacy mode 执行。[课件: 05-machine-basics.pptx p.8]

与前面的 evolutionary design 相比，这是一条 radical shift：它不只是把现有寄存器和地址空间扩宽，而是要求软件/编译器面对不同 architecture。

### 7. AMD64/x86-64：渐进扩宽路线胜出（`00:16:20-00:16:47`）

AMD 在 2003 年采用更渐进的做法：扩宽 registers，把体系从 32 bits 延伸到 64 bits，同时延续 x86 生态。这一 architecture 称 x86-64，也称 AMD64。方案成功后，Intel 在 2004 年推出 EM64T，课件称其与 x86-64 “almost identical”。[课件: 05-machine-basics.pptx p.8]

核心对比是：

```text
IA64/Itanium：新 architecture，激进断裂，高度依赖 compiler
x86-64/AMD64：在 IA32 上渐进扩展，保留 compatibility
```

老师用这段历史支持前面的总论：现实 software ecosystem 与 compatibility 往往能左右 architecture 的成败。

### 8. 明确课程 coverage：只学 x86-64（`00:16:47-00:17:37`）

老师宣布 Fall 2015 是课程第一次完全跳过 IA32，只采用 Linux 语境中的 **x86-64** 名称。课件给出：[课件: 05-machine-basics.pptx p.9]

```bash
gcc hello.c
gcc -m64 hello.c
```

在目标 shark environment 中，默认就是 x86-64；第二条显式要求 64-bit。教材主线覆盖 x86-64，IA32 只放在 book web aside，而且阅读 aside 仍假设先懂 64-bit 主线。[课件: 05-machine-basics.pptx p.9]

### 9. ARM 作为另一条主流路线的对照（`00:17:41-00:19:43`）

老师最后介绍 ARM：其起点与英国 Acorn 的 processor design 有关，instruction set 较简单，通常有较低 power requirement，并采用授权 design/IP 而不是只销售成品 processor 的商业模式。授权方可把小型 ARM processor core 与 graphics、communications 等其他 logic 集成到一块 chip。

这段的教学目的有二：

1. 提醒学生现实世界不只有 x86。
2. 解释为何课程仍不扩展到 ARM：要公正覆盖它需要重写近乎整套教材/课程，而不是附加几页即可。

课件 p.11 只把 ARM 列为另一类 ISA，并说明其广泛用于 mobile phones；本讲不教授 ARM syntax 或 encoding。[课件: 05-machine-basics.pptx p.11]

### 10. 转入 architecture 术语（`00:19:43-00:19:56`）

老师以“x86 与 ARM 是两个 dominant worlds”结束历史背景，开始定义 instruction set 是 compiler 的 target；完整 ISA 与 microarchitecture 区分在下一节展开。[课件: 05-machine-basics.pptx p.11]

## 概念、符号与推导

### 历史决策图

```text
IA32 软件生态
├─ Intel: IA64 / Itanium（新 architecture）-> performance/market disappointing
└─ AMD: x86-64 / AMD64（渐进扩展）-> 成功
                                      -> Intel EM64T（近似兼容）
```

### Power-to-multicore 推理

本节没有给出功耗公式，只给出定性链：

`frequency growth` -> `power/heat pressure` -> `power budget` -> `frequency plateau` -> `more cores per chip`

### 术语边界

| 术语 | 本节含义 |
| --- | --- |
| Core | 同一 chip 上可独立执行指令的 processor instance |
| Multicore | 单一 chip 集成多个 cores |
| Cache | 暂存近期访问数据、使复用更快的 memory；机制未展开 |
| IA32 | Intel 32-bit x86 architecture |
| IA64 | Intel 的不同 architecture，产品线称 Itanium；不是“64-bit IA32”的同义词 |
| x86-64 / AMD64 | AMD 提出的 evolutionary 64-bit x86 extension |

## 常见误解

- **误解：64-bit processor 出现后，32-bit code 立即失效。** x86-64 保留兼容执行能力，软件迁移持续多年。
- **误解：频率停止快速增长等于计算能力停止增长。** 厂商转向更多 cores；但本节也没有承诺任何单线程程序自动加速。
- **误解：Core 与 chip 是同义词。** 一块 chip 可集成多个 cores、shared cache 与 I/O logic。
- **误解：IA64 是 x86-64 的另一个名字。** IA64/Itanium 是不同 architecture；x86-64 是 AMD 的渐进 x86 extension。[课件: 05-machine-basics.pptx p.8]
- **误解：Intel 首先设计了今天使用的 x86-64。** 本讲明确把该 extension 归于 AMD；Intel 后来推出几乎相同的 EM64T。
- **误解：课程提到 ARM 就会教授 ARM assembly。** ARM 只作为主流 alternative 和范围边界出现。

# 第 3 节：ISA、程序员可见状态与 C 到 executable 的路径

> 时间范围：`00:19:56-00:29:52`  
> 对应主题：architecture/ISA 与 microarchitecture；PC、registers、condition codes、memory；virtual memory/cache 的抽象边界；compiler、assembler、linker；`sumstore` 初见。  
> 证据范围：本节 transcript、metadata、`05-machine-basics.pptx` p.11-p.14；不确定处保留 `[需回听 HH:MM:SS]`。

## 本段在整讲中的作用

前两节回答“为什么是 x86-64”，本节开始回答“从机器级程序员视角到底能看见什么”。老师先用 ISA 把 compiler target 与 hardware implementation 分开，再列出 processor-visible state 和 byte-addressed memory，最后把 C program 沿 compiler、assembler、linker 逐层降到 executable。`sumstore` 是贯穿后续 object code 与 disassembly 的首个具体锚点。[课件: 05-machine-basics.pptx p.11] [课件: 05-machine-basics.pptx p.13]

## 学习目标

- 区分 architecture/ISA 与 microarchitecture，并说明 compiler 面向哪一层。
- 画出 PC/RIP、register file、condition codes 与 memory 构成的 programmer-visible model。
- 解释 memory 为何在 machine-code view 中像 byte array，同时仍隐藏 virtual memory 和 cache。
- 按顺序说明 compiler、assembler、linker 与 dynamic linking 的职责。
- 初步逐行解释 `sumstore` 汇编中的 `pushq`、`movq`、`call`、`popq`、`ret` 各属于什么动作。

## 前置知识与边界

- 依赖第 2 节对 IA32、Itanium、x86-64、ARM 的历史区分。
- 本节只定义 condition codes 的用途，不讲 flags 的具体名称或 branch encoding。
- 本节把 memory 描述为逻辑 byte array，不等于物理 DRAM 真的是单一平坦数组。
- `sumstore` 中 calling convention、stack discipline 与 `%rax/%rbx/%rdx` 的精确角色将在后续 lecture 展开；本节只认出可见指令类别。

## 教学展开

### 1. ISA 是 compiler 与 hardware 之间的契约（`00:19:56-00:20:54`）

Compiler 的目标是生成一系列 instructions，规定 machine 应完成什么。Hardware designer 可以用不同速度、面积和复杂度的实现去完成同一 instructions。为了把“应表现成什么”与“内部怎样做到”分开，系统采用 **instruction set architecture (ISA)** abstraction。[课件: 05-machine-basics.pptx p.11]

- **Architecture/ISA**：编写或理解 assembly/machine code 必须知道的 processor specification，例如 instruction set 和 registers。
- **Microarchitecture**：architecture 的具体 implementation，例如 cache sizes、core frequency。

因此同一 ISA 可有多种 microarchitectures；compiler 无需为每种 transistor-level implementation 重新定义语言。本课程主要研究 architecture，几乎不深入 microarchitecture。

### 2. Machine code 与 ISA 实例（`00:21:04-00:21:50`）

老师再次将 machine code 宽泛用于 executable bits 与 assembly-level representation。IA32、x86-64、Itanium 是不同 Intel ISA；ARM 也经历多个 instruction-set generations。[课件: 05-machine-basics.pptx p.11]

这一步把历史名称重新分类：它们不只是产品品牌，而是 compiler 必须面向的行为接口。

### 3. Program counter：下一条 instruction 在哪里（`00:21:50-00:22:24`）

Machine-level view 暴露 C source 中通常看不到的状态。第一项是 **program counter (PC)**：保存下一条待执行 instruction 的 address；在 x86-64 中称 **RIP**。[课件: 05-machine-basics.pptx p.12]

此处只定义“地址指向下一条 instruction”，尚未讨论 jump、call 或 return 如何修改 RIP。

### 4. Register file：少量按名称访问的高速工作位置（`00:22:24-00:22:48`）

Registers 可暂时类比为极少量 storage locations，但与 memory 不同：程序通过 `%rax` 等特定名字引用，而不是计算普通 byte address。它们保存 machine code 频繁使用的 program data。[课件: 05-machine-basics.pptx p.12]

“像 memory location”只帮助理解读写状态；register 并不是 memory array 中的一段地址。

### 5. Condition codes：近期算术/逻辑结果的摘要（`00:22:48-00:23:10`）

Processor 还保存少量 status bits，记录最近 arithmetic/logical operation 是否产生 zero、negative 等性质。这些 **condition codes** 用于实现 conditional branching。[课件: 05-machine-basics.pptx p.12]

本节尚不要求判断具体 instruction 设置哪些 bits；只需知道它们是 machine-visible state，后续 control lecture 会消费这些状态。

### 6. Memory：机器级视角下的 byte-addressable array（`00:23:10-00:24:48`）

Machine-level programmer 把 memory 看成按 address 访问的 byte array，其中容纳 code、user data 与支持 procedures 的 stack。[课件: 05-machine-basics.pptx p.12]

老师马上指出这是一种有用但不完整的 fiction：

1. **Virtual memory** 由 OS 与 hardware 协作，让每个 program 看似拥有独立 byte array，即使 programs 共享 physical memory。
2. **Cache** 自动保存近期内容；程序通常没有本讲意义上的普通 instruction 去直接操作/寻址 cache，但重访数据的速度会变化。

所以 ISA view 有意隐藏部分 microarchitecture/system implementation。隐藏不等于不存在：cache 会影响 timing，virtual memory 决定“独立地址空间”如何实现；只是当前 instruction-level model 不直接展示这些内部结构。

### 7. 多文件 C program 不是一步变成 executable（`00:24:48-00:26:19`）

大型 C program 往往含多个 `.c` files 并调用 libraries。老师按顺序拆解转换：[课件: 05-machine-basics.pptx p.13]

```text
p1.c, p2.c
   --compiler (gcc -Og -S)--> p1.s, p2.s
   --assembler (gcc/as)-----> p1.o, p2.o
   --linker (gcc/ld)--------> executable p
                                 + static libraries (.a)
   --program startup--------> possible dynamic-library loading
```

- **Compiler**：把 C text 转成 assembly text。
- **Assembler**：把 assembly instructions 编码成 object-code bytes。
- **Linker**：合并各 object files，解析跨文件 references，并结合需要的 library code。
- **Dynamic linking/loading**：某些 libraries 在 program 开始执行时才被引入；本节只点到为止。

命令 `gcc -Og p1.c p2.c -o p` 驱动整条 pipeline，并把最终 binary 写入 `p`。[课件: 05-machine-basics.pptx p.13]

### 8. `sumstore`：从 C function 初看指令序列（`00:26:19-00:27:31`）

课件给出：[课件: 05-machine-basics.pptx p.14]

```c
long plus(long x, long y);

void sumstore(long x, long y, long *dest)
{
    long t = plus(x, y);
    *dest = t;
}
```

GCC 生成的 x86-64 assembly 是：

```asm
sumstore:
    pushq   %rbx
    movq    %rdx, %rbx
    call    plus
    movq    %rax, (%rbx)
    popq    %rbx
    ret
```

老师先做动作级预览：`pushq` 把值压入 stack，`movq` 在位置之间传值，`call` 调用 procedure，`popq` 与 push 对应，`ret` 返回 caller。每一行 assembly instruction 最终对应一条 object-code instruction；此时还不要求解释每个 register 的 calling-convention 责任。

### 9. 课件代码是清理版，真实 `.s` 还有 directives（`00:27:31-00:28:26`）

## 教学展开

### 1. `-S` 停在 assembly，`-Og` 选择可读优化级别（`00:29:52-00:31:55`）

完整命令为：[课件: 05-machine-basics.pptx p.14]

```bash
gcc -Og -S sum.c
```

- `-S`：完成 C-to-assembly 后停止，不继续 assemble/link。
- `-Og`：选择面向 debugging 的 basic optimization level；`O` 是大写字母 O，表示 optimize，不是数字 0。
- 输出：`sum.s`。

老师解释选择 `-Og` 的教学理由：完全不优化的 code 冗长且难读；更强 optimization 会大幅重写 program，使 C 与 assembly 的初学映射更难追踪。`-Og` 做明显简化，同时尽量保留可调试、可理解的结构。它在当时只存在于较新 GCC，也不是所有 compiler 的通用 option。

### 2. 真实 `.s` 中为何有“课件没有的行”（`00:31:55-00:33:45`）

打开 `sum.s` 后，核心 `sumstore` instructions 与 slide 相同，但周围有以 `.` 开头的 directives。这些行不是 CPU 执行的 instructions；它们携带 debugger 定位、linker 识别 global function 等 metadata。

教材和 slide 为了先突出 instruction semantics 而删除这些 directives。阅读真实 output 时应先分类：

```text
sumstore:            label
    pushq ...        instruction
    .cfi_...         directive（示意；本节未逐项解释具体名称）
```

本节只确认“`.` 开头的若干行属于其他工具信息”，不补造屏幕上未在 transcript/课件记录的 directive 列表。

### 3. Environment 会改变 compiler output（`00:33:49-00:34:29`）

老师指出 shark 与 non-shark environment 会产生差异。即使 Mac 也使用 Intel processor，OS conventions、compiler version/settings 仍可使 output 与 Linux shark code 不直接兼容或明显不同。因此课程要求在 shark machines 上完成分析。[课件: 05-machine-basics.pptx p.14]

边界是：输出不同不自动表示某一方错误；要比较的是是否遵循目标 platform/ABI 并实现同一 C semantics。

### 4. Assembly 的 data model 比 C 更扁平（`00:34:29-00:35:48`）

老师按 data category 比较 C 与 assembly：[课件: 05-machine-basics.pptx p.15]

- “Integer” data 有 1、2、4、8 bytes。
- 普通 data values 与 addresses 都可作为这些 machine words；pointer 在机器里是数值，不自带 C pointee type。
- Floating point 有 4、8、10-byte forms，并使用不同 register/instruction 体系；本讲不展开。
- Code 本身也是编码 instructions 的 byte sequences。
- Array、struct 等 aggregate type 不在 ISA 中作为整体 type 存在；它们表现为 memory 中连续分配的 bytes，由 compiler 生成 addressing/operation sequence 来实现。

所以 machine code 不知道一个地址“是 `long *` 还是 struct field”；这些高层意义来自 source、compiler decisions 和程序使用方式。

### 5. 每条 instruction 只完成有限动作（`00:35:50-00:36:48`）

Assembly operation 大体分为：[课件: 05-machine-basics.pptx p.16]

1. 对 register 或 memory data 做 arithmetic/logical operation。
2. 在 memory 与 register 间 transfer：load 或 store。
3. Transfer control：procedure jump/return 或 conditional branch。

一条 instruction 通常只做一个有限动作；C loop、conditional、switch、procedure 需要由多条低层 instructions 组合。这正是让 compiler 生成 sequence 比手写更合理的原因。

### 6. `sumstore` 的六条 instructions 编成 14 bytes（`00:36:48-00:37:18`）

Assembler 把 `.s` 转成 `.o`，为每条 instruction 生成 binary encoding。`sumstore` 的 object code 共 14 bytes，从课件地址 `0x400595` 开始；六条 instruction 分别占 1、3 或 5 bytes。[课件: 05-machine-basics.pptx p.17]

```text
53
48 89 d3
e8 f2 ff ff ff
48 89 03
5b
c3
```

Object file 已接近 executable image，但跨文件 linkage 尚未解析。Linker 随后解析 references，结合 `malloc`、`printf` 等 static runtime libraries；某些 libraries 则在程序启动时动态链接。[课件: 05-machine-basics.pptx p.17]

### 7. 三层追踪 `*dest = t`（`00:37:18-00:38:53`）

C statement：[课件: 05-machine-basics.pptx p.18]

```c
*dest = t;
```

在当前 compiler output 中：

- `t` 位于 `%rax`。
- `dest` pointer value 位于 `%rbx`。
- `*dest` 是 address `%rbx` 指向的 memory，写作 `(%rbx)`，也可抽象记作 $M[\mathrm{%rbx}]$。

因此 assembly 是：

```asm
movq %rax, (%rbx)
```

`q` 表示传送 8-byte quad word。该 instruction 在 `0x40059e` 处编码成 3 bytes：

```text
48 89 03
```

逐步语义是：

1. 读取 source register `%rax` 的 8-byte value。
2. 把 `%rbx` 的 value 解释为 memory address。
3. 向从该 address 开始的 8 bytes 写入 value。

这里的 “move” 是复制，不会清空 `%rax`。

### 8. 从 assembler 正向转换到 disassembler 反向转换（`00:38:53-00:39:48`）

老师提出实际问题：若没有 C source，甚至没有原 assembly，怎样检查 binary？答案是 **disassembler**。[课件: 05-machine-basics.pptx p.19]

```text
assembler:    assembly text -> object-code bytes
disassembler: object-code bytes -> approximate assembly text
```

Disassembler 根据 byte patterns 识别 opcode/operands，并打印近似 assembly rendition。说“approximate”是因为 source-level names、types 和某些 intent 已不在 bytes 中；下一节会观察这一信息损失。

## 概念、符号与推导

### `sumstore` 的表示链

```text
C:       *dest = t;
ASM:     movq %rax, (%rbx)
Object:  48 89 03
Meaning: M[Reg[%rbx] ... +7] <- Reg[%rax]
```

最后一行表示从 `%rbx` 给出的 address 起写 8 bytes；本讲此处不展开 byte order。

### Assembly data boundary

| C-level notion | Machine-level representation in this section |
| --- | --- |
| Signed/unsigned integer | 相同宽度的 bit pattern；解释/operation 决定语义 |
| Pointer type | Address value，不带 source-level pointee type |
| Array/struct | Contiguous bytes + compiler-generated addressing |
| Statement | 一条或多条 limited instructions |

### Tool directions

| Tool | Direction | 是否恢复原 C intent |
| --- | --- | --- |
| Compiler | C -> assembly | 生成低层 implementation |
| Assembler | assembly -> bytes | 编码 instruction |
| Disassembler | bytes -> approximate assembly | 否，只恢复可由 encoding 推断的 instruction form |

## 常见误解

## 教学展开

### 1. 降到 machine level 后，变量名已经消失（`00:39:48-00:40:32`）

老师先收紧上一节“反向转换”的含义：C 中的 `t`、`dest` 等名字不会作为名字保存在 ordinary machine code 中。低层只剩 register values、memory locations、instructions 和可能保留的 symbol/debug metadata；disassembler 不能凭 bytes 知道 `%rax` 原先叫 `t`。

因此反汇编是从 encoding 恢复 instruction form，而不是 compiler 的完全逆函数：

```text

bytes --disassembler--> approximate assembly --X--> original C names/types/intent
```

### 2. 编译完整 executable 并运行 `objdump -d`（`00:40:40-00:42:49`）

```bash
objdump -d sum
```

`-d` 请求 disassemble。完整 executable 不只含学生写的 functions，也含 startup/runtime code，所以输出中会看到未在 source 中直接编写的 functions。老师在大量输出中定位到 `sumstore`。

这里建立一个重要边界：在 executable 中看到“额外代码”通常来自 startup、linking 或 libraries，不应先断定 compiler 擅自改变程序功能。

### 3. 对齐 address、bytes 与 instruction（`00:42:49-00:44:03`）

`objdump` 输出如下：[课件: 05-machine-basics.pptx p.19]

```text
0000000000400595 <sumstore>:
  400595:  53               push   %rbx
  400596:  48 89 d3         mov    %rdx,%rbx
  400599:  e8 f2 ff ff ff   callq  400590 <plus>
  40059e:  48 89 03         mov    %rax,(%rbx)
  4005a1:  5b               pop    %rbx
  4005a2:  c3               retq
```

每行可按三层读：

1. 左侧是 instruction 起始 address。
2. 中间是组成 instruction 的 bytes。
3. 右侧是 disassembler 重建的 mnemonic 与 operands。

长度由相邻 address 或 byte 数可见：`push` 1 byte，第一条 `mov` 3 bytes，`callq` 5 bytes，第二条 `mov` 3 bytes，`pop`/`retq` 各 1 byte，共 14 bytes。Disassembler 没有读取原 `.c` 或 `.s`，仅依据 executable 中的 bytes；可见 x86 instructions 是 variable-length。[课件: 05-machine-basics.pptx p.17] [课件: 05-machine-basics.pptx p.19]

### 4. GDB 可在没有 source 时反汇编 procedure（`00:44:03-00:45:22`）

GDB 不只用于 source-level debugging，也能检查 binary。课件操作是：[课件: 05-machine-basics.pptx p.20]

```gdb
gdb sum
(gdb) disassemble sumstore
```

输出列出 function 内各 instruction address 与 text，形式与 `objdump` 接近，但该视图不直接显示每条 byte encoding。即使 source 不可用，只要 GDB 能定位 function/address，仍可在 instruction level 观察和 single-step。

### 5. 用 GDB 直接检查 14 bytes（`00:45:44-00:46:29`）

若要在 GDB 中看原始 object bytes，可执行：[课件: 05-machine-basics.pptx p.20]

```gdb
(gdb) x/14xb sumstore
```

课堂语义分解：

- `x`：examine memory。
- `/14`：显示 14 个 units。
- `x`：以 hexadecimal 格式显示。
- `b`：每个 unit 是 byte。
- `sumstore`：从该 function 的 address 开始。

这使学生可以在同一 debugger 中交叉核对 bytes 与 disassembled instructions。

### 6. 什么可以被反汇编：任何可解释为 code 的 bytes（`00:46:29-00:47:47`）

老师用旧版 Microsoft Word executable 作例子：application 最终也是 executable file，其中包含编码 instructions 的 bytes，因此 `objdump` 可以尝试 disassemble。[课件: 05-machine-basics.pptx p.21]

但技术能力不自动授予法律许可。课件明确写出 Microsoft EULA 禁止 reverse engineering；老师因收到相关提醒而遮去演示内容。正确结论是：

```text
技术上可解析 bytes != license/法律上允许进行 reverse engineering
```

此外，任意 bytes 都可被 disassembler 按某一 ISA 解释，不保证这些 bytes 实际是可达、有效或有意义的 program instructions；本讲此处只说“anything that can be interpreted as executable code”。

### 7. 转入 registers：16 个 integer/pointer storage locations（`00:47:49-00:48:25`）

x86-64 有 16 个用于保存 integers 和 pointers 的 integer registers：[课件: 05-machine-basics.pptx p.23]

```text
%rax %rbx %rcx %rdx %rsi %rdi %rsp %rbp
%r8  %r9  %r10 %r11 %r12 %r13 %r14 %r15
```

前八个保留 alphabetic legacy names，新增八个使用 numeric names。老师再次把这种不整齐归因于 architecture 的 evolutionary history。

### 8. 同一 register 的不同宽度名字（`00:48:25-00:49:20`）

使用 `%r...` name 访问 64 bits；使用对应 `%e...` 或 `%r8d` 等 name 访问 low-order 32 bits。课程中操作 `long` 时常见 64-bit names，操作 32-bit `int` 时常见 32-bit names。[课件: 05-machine-basics.pptx p.23]

| 64-bit | Low 32-bit | 更低位视图（本节只确认存在） |
| --- | --- | --- |
| `%rax` | `%eax` | low 16 bits、low 8 bits |
| `%rbx` | `%ebx` | low 16 bits、low 8 bits |
| `%r8` | `%r8d` | low 16 bits、low 8 bits |

关键模型是 aliasing：`%eax` 不是另一枚独立 register，而是 `%rax` 的低 32-bit view。本节没有讲写 32-bit alias 对高 32 bits 的具体效果，不能自行补入。

### 9. Register 按名字选取，不靠普通 address arithmetic（`00:49:20-00:49:46`）

老师把 registers 称为 named locations：instruction 必须直接指定 `%rax`、`%r13` 等名字，不能像 memory 那样先计算一个普通 byte address再选 register。这一差别将在下一节 operand syntax 中变成 `%rax` 与 `(%rax)` 的关键区别。

# 第 6 节：寄存器历史、`movq` operands 与简单寻址

> 时间范围：`00:49:46-00:59:44`  
> 对应主题：IA32 到 x86-64 的 register 扩展；legacy names 与 `%rsp`；immediate/register/memory operands；`movq` 五种组合；`(R)`、`D(R)`；`swap` 与前两个 argument registers。  
> 证据范围：本节 transcript、metadata、`05-machine-basics.pptx` p.23-p.29；不确定处保留 `[需回听 HH:MM:SS]`。

## 本段在整讲中的作用

上一节只把 registers 当作 named storage，本节给它们补上历史来源和操作语法。老师先解释为什么一半 register 有名字、一半有编号，再以 `movq Source, Dest` 建立三类 operand、五种合法传送和两种简单 memory addressing。最后用 `swap(long *xp, long *yp)` 把 pointer dereference、argument registers 与四条 move instructions 对齐，下一节将逐条模拟其状态变化。[课件: 05-machine-basics.pptx p.24] [课件: 05-machine-basics.pptx p.28]

## 学习目标

- 解释 IA32 的 8 registers 如何扩展为 x86-64 的 16 registers，以及 legacy names 的来源。
- 识别 `%rsp` 的特殊 stack-pointer role，并理解其他 legacy names 多数不再固定用途。
- 精确识别 immediate、register、memory 三类 operands 的 AT&T syntax。
- 列出 `movq` 五种合法 source/destination combinations，并说明为何没有 memory-to-memory 单指令传送。
- 将 `(R)`、`D(R)` 翻译为 address calculation，并把 `swap` 四条 `movq` 还原成 C dereferences。

## 前置知识与边界

- 依赖第 5 节的 16 integer registers 与 width aliases。
- 这里使用 AT&T syntax：source 在前、destination 在后；Intel syntax 的顺序不在本讲范围。
- `movq` 中 `q` 表示 8-byte quad word；更小宽度的 move variants 未在本节展开。
- 本节只引入 `%rdi`/`%rsi` 为前两个 arguments；完整六参数 calling convention 与 caller/callee obligations 后续再讲。

## 教学展开

### 1. IA32 只有 8 个主要 integer registers（`00:49:46-00:50:32`）

IA32 使用八个 32-bit `%e...` registers；转向 x86-64 时，register width 扩为 64 bits，并新增 `%r8`-`%r15`，总数翻倍为 16。老师评价新增 registers 很有帮助，因为旧架构的八个 registers 很紧张。[课件: 05-machine-basics.pptx p.23]

这解释了现代命名为何分两组：

```text
历史扩宽：%eax ... %ebp/%esp -> %rax ... %rbp/%rsp
新增编号：%r8 ... %r15
```

### 2. 16/8-bit aliases 是 backward compatibility 的遗产（`00:50:32-00:51:30`）

旧 IA32 registers 还能引用 low-order 16-bit names `%ax/%cx/%dx/%bx/%si/%di/%sp/%bp`；前四个又保留高低 byte names，如 `%ah/%al`。[课件: 05-machine-basics.pptx p.24]

这些层叠 aliases 来自更早的 8086/8080 lineage。老师的目的不是要求本讲背完每个 byte alias，而是让学生明白 register spelling 的不规则来自 backward compatibility。

### 3. Legacy names 大多不再规定固定用途，但 `%rsp` 例外（`00:51:30-00:53:10`）

`rax/rbx/rcx/rdx/rsi/rdi` 等名字最初反映 accumulate、base、counter、data、source index、destination index 等用途；现代 compiler 通常可把多数 registers 用作 general program data，不能只凭名字断言它当前保存什么。[课件: 05-machine-basics.pptx p.24]

明确例外是 `%rsp`：它是 **stack pointer**，不能任意当普通 temporary。老师还说 IA32 中常用作 procedure base pointer 的 `%rbp` 在现代 code 中通常不再固定承担该角色，但“通常”保留 compiler/settings 依赖边界。

因此读 assembly 要根据 data flow 和 calling convention 判断实际角色，而不是按古老名称猜变量。

### 4. `movq Source, Dest` 与三类 operands（`00:53:11-00:54:19`）

`movq` 把 8-byte value 从 source 复制到 destination。三类 operand 是：[课件: 05-machine-basics.pptx p.25]

1. **Immediate**：编码在 instruction 中的 constant integer，以 `$` 开头，如 `$0x400`、`$-533`。
2. **Register**：16 个 integer registers 之一，以 `%` 开头，如 `%rax`、`%r13`。
3. **Memory**：由 address expression 指定的连续 8 bytes，最简单如 `(%rax)`。

语法标记不可互换：`%rax` 表示 register value；`(%rax)` 把该 value 当 address 并访问 memory；`$0x400` 表示 constant 0x400，而不是 address 0x400 处的内容。

### 5. 为什么不是 $3\times3=9$ 种组合（`00:54:19-00:55:25`）

Immediate 不能作为 destination，因为 constant 不是可写 location。x86 `movq` 也不允许一条 instruction 同时以 memory 为 source 和 destination；memory-to-memory copy 必须经 register 分两步。[课件: 05-machine-basics.pptx p.26]

因此有五种合法组合：

| Source -> Dest | Example | C-like meaning |
| --- | --- | --- |
| Immediate -> Register | `movq $0x4, %rax` | `temp = 0x4;` |
| Immediate -> Memory | `movq $-147, (%rax)` | `*p = -147;` |
| Register -> Register | `movq %rax, %rdx` | `temp2 = temp1;` |
| Register -> Memory | `movq %rax, (%rdx)` | `*p = temp;` |
| Memory -> Register | `movq (%rax), %rdx` | `temp = *p;` |

Memory-to-memory 必须写成类似：

```asm
movq (%rax), %rdx
movq %rdx, (%rcx)
```

第一条 load，第二条 store。

### 6. 用 C analogy 理解 load/store（`00:55:25-00:56:37`）

老师把 register 当作当前计算的 temporary storage：

- Immediate→register 类似给 temporary 赋 constant。
- Register→register 类似复制 temporary。
- Register→memory 类似 pointer 在 assignment 左侧，即 store。
- Memory→register 类似 dereference pointer 读取 value，即 load。

这些 analogy 用于恢复 data flow，不表示 machine code 保留 C temporary names。

### 7. 简单 addressing：`(R)` 与 `D(R)`（`00:56:37-00:57:45`）

Normal form：[课件: 05-machine-basics.pptx p.27]

$$
(R) \quad\Longrightarrow\quad M[\operatorname{Reg}[R]]
$$

例如：

```asm
movq (%rcx), %rax
```

把 `%rcx` 中的 value 当 address，从该 address 读取 8 bytes 到 `%rax`，对应 C pointer dereference。

Displacement form：[课件: 05-machine-basics.pptx p.27]

$$
D(R) \quad\Longrightarrow\quad M[\operatorname{Reg}[R] + D]
$$

例如：

```asm
movq 8(%rbp), %rdx
```

先计算 `%rbp + 8`，再从该 effective address load。$D$ 可为正或负 constant，适合访问某个 region/object 内的固定 offset；本节尚未绑定到具体 stack frame layout。

### 8. `swap`：四次 dereference 对应四条 moves（`00:57:45-00:58:48`）

C code：[课件: 05-machine-basics.pptx p.28]

```c
void swap(long *xp, long *yp)
{
    long t0 = *xp;
    long t1 = *yp;
    *xp = t1;
    *yp = t0;
}
```

Assembly：

```asm
swap:
    movq (%rdi), %rax
    movq (%rsi), %rdx
    movq %rdx, (%rdi)
    movq %rax, (%rsi)
    ret
```

前两条是 memory→register loads，后两条是 register→memory stores；交换必须先把两个旧值都保存在 registers 中，避免第一次 store 覆盖第二个仍需读取的 value。

### 9. Arguments 到达 `%rdi`、`%rsi`（`00:58:48-00:59:44`）

在本课使用的 x86-64 convention 中，caller 在 function 开始前把第一个 argument `xp` 放入 `%rdi`，第二个 `yp` 放入 `%rsi`。两者保存的是 addresses，不是 `*xp`/`*yp` 的 values。[课件: 05-machine-basics.pptx p.29]

Compiler 自行分配 `%rax` 保存 `t0`、`%rdx` 保存 `t1`。老师提到最多六个 arguments 可通过指定 registers 传入，但本节只要求记住前两个；完整规则后续讲授。

## 概念、符号与推导

### Operand syntax reference

| Syntax | Category | Value obtained |
| --- | --- | --- |
| `$Imm` | Immediate | constant `Imm` |
| `%rX` | Register | `Reg[%rX]` |
| `(%rX)` | Memory | `M[Reg[%rX]]`，8 bytes for `movq` |
| `D(%rX)` | Memory | `M[Reg[%rX] + D]`，8 bytes for `movq` |

### `swap` data-flow invariant

在任何 store 前先完成两次 load：

```text
%rax <- M[xp]   (t0)
%rdx <- M[yp]   (t1)
M[xp] <- %rdx
M[yp] <- %rax
```

若先执行 `M[xp] <- M[yp]` 而没有保存旧 `M[xp]`，原 `*xp` 会丢失；这也是 memory-to-memory 单指令缺失时 register temporary 的实际作用。

## 例子与课堂提示

- **8 named + 8 numbered**（`00:53:11-00:53:20`）：是 IA32 扩展到 x86-64 的可见痕迹，不是两类速度不同的 registers。
- **`%rsp` 粉色标记**（`00:52:08-00:52:30`）：强调 stack pointer 的特殊用途。[课件: 05-machine-basics.pptx p.23]
- **“为什么不是九种组合”**（`00:54:44-00:55:20`）：通过排除 immediate destination 和 memory-memory 得到五种合法 `movq`。
- **括号就是 dereference**（`00:56:48-00:57:13`）：建立 `%rcx` 与 `(%rcx)` 的关键语义差别。
- **`swap` 四次 memory references**（`00:57:45-00:58:33`）：把 C pointer code 精确映射成 two loads + two stores。

## 常见误解

- **误解：`%rax` 的名字保证它永远是 accumulator。** 这些名称大多是 legacy；实际角色由当前 code/data flow 决定。
- **误解：所有 16 registers 都能任意使用。** `%rsp` 是 stack pointer，具有特殊约束。
- **误解：`$0x400` 与 `(%rax)` 都表示 memory address。** 前者是 immediate constant，后者才 dereference register-held address。
- **误解：AT&T syntax 的 destination 在前。** 本讲统一是 `Source, Dest`。
- **误解：一条 `movq` 可以直接 memory→memory。** 必须先 load 到 register，再 store。
- **误解：`%rdi` 中已经是 `*xp`。** 它保存 `xp` address；`(%rdi)` 才是 memory value。

## 本段掌握检查

1. **问：为什么 x86-64 registers 一半有 legacy names、一半有数字？**  
   **答：** x86-64 扩宽 IA32 原有八个 registers，并新增 `%r8`-`%r15` 八个；命名反映演化历史。

2. **问：`%rax`、`(%rax)`、`$0x400` 分别是什么？**

## 教学展开

### 1. Compiler 选择 temporary registers，读者追踪 data flow（`00:59:44-01:00:14`）

Compiler 的 register-allocation algorithm 决定把 C temporaries 放在哪些 registers；读者不必猜它为何选 `%rax/%rdx`，而应从 instruction data flow 证明当前映射：[课件: 05-machine-basics.pptx p.29]

```text
%rdi = xp address
%rsi = yp address
%rax = t0
%rdx = t1
```

重点是角色可随 function 改变，不能把 `%rax` 永久命名为 `t0`。

### 2. 设置 `swap` 的具体初态（`01:00:14-01:01:02`）

老师要求学生达到能手工 simulate instructions 的熟练度。课堂假设：

```text
%rdi = 0x120      M[0x120] = 123
%rsi = 0x100      M[0x100] = 456
```

`0x120`、`0x100` 远小于典型运行时 address，仅为图示。每次 `movq` 处理连续 8 bytes，但表中以一个 `long` value 简写。[课件: 05-machine-basics.pptx p.30]

### 3. 前两条 load 保存旧值（`01:01:02-01:02:12`）

```asm
movq (%rdi), %rax   # t0 = *xp
movq (%rsi), %rdx   # t1 = *yp
```

逐步：

1. `%rdi=0x120`，所以第一条读取 $M[0x120]=123$，得到 `%rax=123`。
2. `%rsi=0x100`，所以第二条读取 $M[0x100]=456$，得到 `%rdx=456`。
3. Memory 尚未改变；两个原值已安全保存在 registers。[课件: 05-machine-basics.pptx p.31] [课件: 05-machine-basics.pptx p.32]

### 4. 后两条 store 完成交换（`01:02:12-01:02:49`）

```asm
movq %rdx, (%rdi)   # *xp = t1
movq %rax, (%rsi)   # *yp = t0
```

1. 第三条把 `%rdx=456` 写到 `%rdi` 指向的 `0x120`，此时 memory 暂时是 `456,456`。[课件: 05-machine-basics.pptx p.33]
2. 第四条把 `%rax=123` 写到 `%rsi` 指向的 `0x100`，最终得到 $M[0x120]=456$、$M[0x100]=123$。[课件: 05-machine-basics.pptx p.34]

`ret` 返回 caller；procedure mechanism 后续再讲。四条 `movq` 完成全部数据工作：two loads + two stores。

### 5. `q` 与历史 word sizes（`01:01:23-01:01:57`，课堂在模拟中插入说明）

老师在第一条 load 后解释 Intel terminology：

| Name | Size |
| --- | --- |
| Word | 16 bits = 2 bytes |
| Long word | 32 bits = 4 bytes |
| Quad word | 64 bits = 8 bytes |

因此 `movq` 的 `q` 表示 quad word/8 bytes。这里的 “word” 不等于当前 x86-64 natural register width；名称来自 8086 history。

### 6. 从简单括号扩展到通用 address form（`01:02:55-01:04:31`）

最一般 memory addressing syntax 是：[课件: 05-machine-basics.pptx p.36]

$$
D(R_b,R_i,S)
$$

其 effective address 为：

$$
EA = \operatorname{Reg}[R_b] + S\cdot\operatorname{Reg}[R_i] + D
$$

字段约束：

- $D$：constant displacement，编码为 1、2 或 4 bytes。
- $R_b$：base register，可为 16 个 integer registers 之一。
- $R_i$：index register，可用任一 integer register，但不能是 `%rsp`。
- $S$：scale，只能为 1、2、4、8。

省略不用的字段可得到 special cases：

```text
(Rb,Ri)       -> Reg[Rb] + Reg[Ri]
D(Rb,Ri)      -> Reg[Rb] + Reg[Ri] + D
(Rb,Ri,S)     -> Reg[Rb] + S*Reg[Ri]
(Rb)          -> Reg[Rb]
```

Scale 1/2/4/8 与常见 element byte size 对应：`int` index 常乘 4，`long` index 常乘 8。老师明确说完整 array mapping 会在后续讲授；这里仅建立动机。

### 7. 十六进制 address computation（`01:04:47-01:06:08`）

课堂设：

```text
%rdx = 0xf000
%rcx = 0x0100
```

逐项计算：[课件: 05-machine-basics.pptx p.37]

| Address expression | Calculation | Effective address |
| --- | --- | --- |
| `8(%rdx)` | `0xf000 + 0x8` | `0xf008` |
| `(%rdx,%rcx)` | `0xf000 + 0x0100` | `0xf100` |
| `(%rdx,%rcx,4)` | `0xf000 + 4*0x0100` | `0xf400` |
| `0x80(,%rdx,2)` | `2*0xf000 + 0x80` | `0x1e080` by direct arithmetic/transcript |

最后一项的 materials notes 写成 `0x1d080`，与 $2\times0xf000=0x1e000$ 以及口述 “I get 1E with three zeros” 冲突；本笔记不静默合并，见待核对项。

这些 expression 本身只计算 address。若作为 `movq` operand，才用该 address load/store memory。

### 8. `leaq`：看起来像 memory，实际不 dereference（`01:06:17-01:07:45`）

`leaq Src, Dst` 称 load effective address：[课件: 05-machine-basics.pptx p.39]

- `Src` 写成 address-mode expression。
- `Dst` 必须是 register。
- CPU 计算 `Src` 所表示的 effective address，把数值写入 `Dst`。
- **不从该 address 读取 memory。**

它可实现 C address-of，例如 `p = &x[i]`；也可被 compiler 当作受限的 arithmetic unit，计算 $x+k y$，其中 $k\in\{1,2,4,8\}$。

最常见误读是把 `leaq (%rdi,%rdi,2),%rax` 当作 load：括号长得像 memory operand，但 `lea` 只取算出的数值。

### 9. `x*12`：`3x` 再乘 4（`01:07:45-01:08:41`）

C code：[课件: 05-machine-basics.pptx p.39]

```c
long m12(long x)
{
    return x * 12;
}
```

Compiler output：

```asm
leaq (%rdi,%rdi,2), %rax  # x + 2*x = 3*x
salq $2, %rax             # (3*x) << 2 = 12*x
```

推导：

$$
\operatorname{Reg}[\%rax] = x + 2x = 3x
$$

$$
(3x) \ll 2 = (3x)\cdot 4 = 12x
$$

这说明 compiler 实现 C multiplication 时不必逐字使用一条 multiply instruction；只要最终 bit-level computation 实现相同语义即可。

### 10. Two-operand arithmetic：destination 也是输入（`01:08:41-01:09:41`）

大多数本节 arithmetic/logical instructions 使用：[课件: 05-machine-basics.pptx p.40]

```text
opq Src, Dest
Dest <- Dest op Src
```

类似 C 的 compound assignment，例如 `x += y`。AT&T syntax source 在前、destination 在后，顺序尤其影响 subtraction。

| Instruction | Computation |
| --- | --- |
| `addq Src,Dest` | `Dest = Dest + Src` |
| `subq Src,Dest` | `Dest = Dest - Src` |
| `imulq Src,Dest` | `Dest = Dest * Src` |
| `salq Src,Dest` / `shlq` | `Dest = Dest << Src` |
| `sarq Src,Dest` | arithmetic right shift |
| `shrq Src,Dest` | logical right shift |
| `xorq Src,Dest` | `Dest = Dest ^ Src` |
| `andq Src,Dest` | `Dest = Dest & Src` |
| `orq Src,Dest` | `Dest = Dest | Src` |

老师在边界处强调 add/sub 等 bit-level behavior 不因把 operands 称为 signed/unsigned 就改变；right shift 则明确分 arithmetic (`sarq`) 与 logical (`shrq`)。更精确的 signed/unsigned interpretation 留在既有 bit-level knowledge 与后续 context 中。

## 概念、符号与推导

### Effective-address checklist

对 `D(Rb,Ri,S)`：

1. 读取 `Reg[Rb]`。
2. 读取 `Reg[Ri]` 并乘 $S$。
3. 加 displacement $D$。
4. 得到 $EA$。
5. 若 instruction 是 `movq`，在 $EA$ 读/写 8 bytes；若是 `leaq`，直接把 $EA$ 数值写入 destination register。

### `movq` vs `leaq`

| Form | Result |
| --- | --- |
| `movq D(Rb,Ri,S), Dst` | `Dst <- M[EA]` |
| `leaq D(Rb,Ri,S), Dst` | `Dst <- EA` |

### Destructive destination

执行 `subq %rax,%rdx` 前：`%rax=a, %rdx=b`。执行后：

```text
%rax = a       # source unchanged by this instruction
%rdx = b - a   # old destination consumed and overwritten
```

## 常见误解

- **误解：Compiler 选了 `%rax`，所以 `%rax` 永远表示 `t0`。** 这是当前 function 的 allocation，角色随 code 改变。
- **误解：`q` 表示 4 bytes，因为 quad 看起来像 four。** x86 terminology 中 quad word 是四个 16-bit words，即 8 bytes。
- **误解：Address expression 一定访问 memory。** 它先定义 effective address；`leaq` 只保存该数值。
- **误解：`leaq` 名字含 load，所以会读取 `M[EA]`。** 它不 dereference。
- **误解：Scale 可取任意 integer。** 只能是 1、2、4、8，且 index 不能用 `%rsp`。[课件: 05-machine-basics.pptx p.36]
- **误解：`subq Src,Dest` 计算 `Src-Dest`。** AT&T syntax 计算 `Dest-Src`。

## 教学展开

### 1. Signed/unsigned 不是每条 instruction 都有两个版本（`01:09:41-01:09:49`）

老师完成上一节末句：对 add、subtract、multiply 和 bitwise logic 这类操作，底层 instruction 处理同一 bit pattern，不因 source-level type 被称为 signed 或 unsigned 就自动换一套基础 opcode；结果如何解释取决于 context。明显需要区分的是 right shift：[课件: 05-machine-basics.pptx p.40]

- `sarq`：arithmetic right shift。
- `shrq`：logical right shift。

本节不展开 flags 或 signed/unsigned comparison；不能把“没有区分”泛化到所有 x86 instructions。

### 2. One-operand instructions 直接读写同一 destination（`01:09:49-01:10:09`）

课件列出：[课件: 05-machine-basics.pptx p.41]

| Instruction | Computation | C-like reading |
| --- | --- | --- |
| `incq Dest` | `Dest = Dest + 1` | increment |
| `decq Dest` | `Dest = Dest - 1` | decrement |
| `negq Dest` | `Dest = -Dest` | arithmetic negation |
| `notq Dest` | `Dest = ~Dest` | bitwise complement |

老师特别强调 `notq` 对应 C 的 tilde `~`，不是 exclamation mark `!`。前者逐 bit 取反；本讲未在此定义后者的 logical semantics，只要求不要混淆符号。

### 3. 建立综合 C expression（`01:10:11-01:10:24`）

课件 C code：[课件: 05-machine-basics.pptx p.42]

```c
long arith(long x, long y, long z)
{
    long t1 = x + y;
    long t2 = z + t1;
    long t3 = x + 4;
    long t4 = y * 48;
    long t5 = t3 + t4;
    long rval = t2 * t5;
    return rval;
}
```

若先在代数层压缩：

$$
t2 = x+y+z
$$

$$
t5 = x+4+48y
$$

$$
rval = (x+y+z)(x+4+48y)
$$

Assembly 使用多次 `leaq`、一次 `salq` 和一次 `imulq`；source 中有两处 multiplication（`y*48` 与最终 product），但 machine code 只需一次 `imulq`。

### 4. 前两条建立 $t2=x+y+z$（`01:10:24-01:11:25`）

```asm
leaq (%rdi,%rsi), %rax   # t1
addq %rdx, %rax          # t2
```

初始 mapping：`%rdi=x`、`%rsi=y`、`%rdx=z`。

第一条不访问 memory，计算：

$$
\%rax \leftarrow \%rdi + \%rsi = x+y = t1
$$

第二条采用 `Dest <- Dest + Src`：

$$
\%rax \leftarrow (x+y)+z = t2
$$

从此 `%rax` 保持最终 product 的左因子，直到最后 `imulq`。

### 5. 用 `3y << 4` 构造 $48y$（`01:11:25-01:11:50`）

```asm
leaq (%rsi,%rsi,2), %rdx
salq $4, %rdx            # t4
```

第三条覆盖原本保存 `z` 的 `%rdx`。这是安全的，因为 `z` 已在上一条加入 `%rax`，后续不再单独需要。

$$
\%rdx \leftarrow y+2y=3y
$$

左移 4 positions 等于乘 $2^4=16$：

$$
\%rdx \leftarrow 3y\cdot16=48y=t4
$$

这解释为什么 C 中的 `y * 48` 没有对应 `imulq`：compiler 将 $48=3\times16$ 分解为 scaled addition 与 shift。[课件: 05-machine-basics.pptx p.43]

### 6. 把 `x+4` 融入 $t5$，而不单独保存 $t3$（`01:11:20-01:12:02`）

```asm
leaq 4(%rdi,%rdx), %rcx  # t5
```

此时 `%rdi=x`、`%rdx=48y`。Displacement `4` 直接并入 effective-address arithmetic：

$$
\%rcx \leftarrow 4+x+48y=t5
$$

C 中先有 `t3=x+4`，再有 `t5=t3+t4`；assembly 不创建单独的 `t3` register value，而把两步融合为一条 `leaq`。这是 source operation order 与 machine operation order 不一一对应的直接例子。

### 7. 一次真正的 multiply 得到返回值（`01:12:02-01:12:10`）

```asm
imulq %rcx, %rax          # rval
ret
```

执行前：

```text
%rax = t2 = x+y+z
%rcx = t5 = x+4+48y
```

所以：

$$
\%rax \leftarrow \%rax\cdot\%rcx
= (x+y+z)(x+4+48y)
= rval
$$

Function result 位于 `%rax`，`ret` 返回 caller。课件将每条 instruction 注释到 `t1/t2/t4/t5/rval`，但这些 labels 是人对 data flow 的解释，不是 object code 内保存的 C variable names。[课件: 05-machine-basics.pptx p.43]

### 8. 验证方法：维护每条 instruction 后的 invariant（`01:12:10-01:12:27`）

老师要求学生回去逐条确认 comments 正确，而不是只接受 compiler 输出。可使用如下表格验证：

| 执行后 | `%rax` | `%rdx` | `%rcx` |
| --- | --- | --- | --- |
| Entry | 未限定 | `z` | 未限定 |
| First `leaq` | `x+y` | `z` | 未限定 |
| `addq` | `x+y+z` | `z` | 未限定 |
| Second `leaq` | `x+y+z` | `3y` | 未限定 |
| `salq` | `x+y+z` | `48y` | 未限定 |
| Third `leaq` | `x+y+z` | `48y` | `x+4+48y` |
| `imulq` | `(x+y+z)(x+4+48y)` | `48y` | `x+4+48y` |

这类 invariant table 是读 compiler-generated assembly 的核心方法：只依赖 instruction semantics，不依赖 source 顺序表面相似。

### 9. Compiler 保语义，不保逐句形状（`01:12:27-01:12:43`）

老师明确总结：generated code 会正确实现 C function，但不必在低层精确复刻 source 指定的 operation sequence。Compiler 可以：

- 重用已经“死亡”的 register，如在消费 `z` 后重用 `%rdx`。
- 用 `leaq` 做 arithmetic。
- 用 shift 替换 constant multiplication。
- 合并 source temporaries/expressions，如不单独形成 `t3`。

读者的责任不是按行寻找文本相似，而是证明 input-to-output semantics 等价。

### 10. 全讲总结：接受 x86 的历史性，再掌握核心子集（`01:12:43-01:13:16`）

老师回顾本讲路线：[课件: 05-machine-basics.pptx p.44]

1. x86 evolutionary design 产生 quirks/artifacts。
2. C 经 compiler 转成 low-level instruction sequences，再由 assembler 编码成 machine bytes。
3. Machine-level view 新增 PC、registers、condition codes、byte-addressed memory 等 visible state。
4. Registers、operands、`movq` 支持多种 data movement。
5. Effective-address syntax 同时服务 memory access 和 arithmetic。
6. Compiler 会组合 `leaq`、shift、multiply 等 instructions 来实现 C computation。

老师再次用 English 而非规则统一语言作类比：x86 不够整齐，但课程目标是建立能工作的 mental model，而不是等待它变得优雅。

## 概念、符号与推导

### One-operand vs two-operand

```text
incq Dest       -> Dest <- Dest + 1
addq Src, Dest  -> Dest <- Dest + Src
```

两者都覆盖 destination；差别是 second input 是否显式编码。

### `arith` 的 dependency graph

```text
x ----+--> t1=x+y --+--> t2=x+y+z --------+
      |             z                     |
      +--> t3=x+4 --+                      +--> rval=t2*t5
y --> t4=48y -------+--> t5=x+4+48y ------+
```

Assembly 将该 graph 调度为：先完成 `t2`，重用 `%rdx` 构造 `t4`，融合 `t3+t4` 为 `t5`，最后 multiply。

### Algebraic proof target

$$
\texttt{arith}(x,y,z)=(x+y+z)(x+4+48y)
$$

逐条 symbolic execution 得到同一 expression，即证明本例 machine sequence 实现 source semantics。

## 例子与课堂提示

- **`notq` 是 `~` 不是 `!`**（`01:10:03-01:10:09`）：防止把 bitwise complement 与 logical negation 混淆。[课件: 05-machine-basics.pptx p.41]
- **C 中两次 multiplication，assembly 只有一次 `imulq`**（`01:10:36-01:10:57`）：说明 constant multiply 可分解为更简单 operations。
- **消费 `z` 后重用 `%rdx`**：展示 register lifetime，而不是“一变量永久绑定一 register”。
- **Displacement `4` 吸收 `x+4`**（`01:11:50-01:12:02`）：展示 `leaq` 可融合 source expressions。[课件: 05-machine-basics.pptx p.43]
- **逐条相信 comments 前先验证**（`01:12:10-01:12:19`）：老师要求建立 symbolic simulation 能力，而非背 mapping。

## 常见误解

- **误解：Signed 与 unsigned 在所有 instructions 上完全没有差别。** 本讲只说许多基本 bit-level operations 共用形式；right shift 已明确分 arithmetic/logical，其他 signed-sensitive operations 未在此覆盖。
- **误解：`notq` 等于 C 的 `!`。** 它对应 `~`，执行 bitwise complement。
- **误解：每个 C temporary 都必须占一个独立 register。** Compiler 可消除、融合或重用 storage。
- **误解：`y*48` 必须出现 `imulq $48,...`。** 本例用 `3y` 左移 4 位实现。
- **误解：Assembly 必须按 C statement 顺序逐行排列。** 只要 dependencies 和 observable result 正确，compiler 可重新调度或融合。
- **误解：`leaq` 只用于 pointer。** 它也常用于 $x+k y+D$ arithmetic；本例出现三次。

## 本段掌握检查

1. **问：`notq %rax` 与 C 中哪个 operator 对应？**  
   **答：** Bitwise complement `~`，不是 logical NOT `!`。[课件: 05-machine-basics.pptx p.41]

2. **问：为什么第三条 instruction 可以覆盖 `%rdx` 中的 `z`？**  
   **答：** 前一条 `addq %rdx,%rax` 已把 `z` 合入 `t2`，后续不再单独需要 `z`，所以 register 可重用。

3. **问：两条 instructions 怎样计算 `y*48`？**  
   **答：** `leaq (%rsi,%rsi,2),%rdx` 得 `3y`，`salq $4,%rdx` 再乘 16，得到 `48y`。

4. **问：`t3=x+4` 为什么没有单独的 assembly line？**  
   **答：** `leaq 4(%rdi,%rdx),%rcx` 把 `x`、constant 4 与已算出的 `48y` 一次合并成 `t5`。

5. **问：怎样证明这段 assembly 实现 `arith`，而不是只凭相似度判断？**  
   **答：** 从 argument-register mapping 开始，逐条维护 symbolic register invariant，最终证明 `%rax=(x+y+z)(x+4+48y)`，与 C 返回表达式相同。
