## 关键假设与边界

- 所有 B2U/B2T/T2U/U2T 公式都以**固定 word width $w$**为前提；省略 width 会把 `-1→31` 之类的例子误当成普遍常数。
- 老师列出的 `char=1 byte`、`short=16 bits`、`int=32 bits`、`long=64 bits` 是课程 x86-64 工作环境；C 类型精确宽度具有平台依赖性。[00:06:08–00:07:30]
- 本讲使用 two’s-complement machine model 解释 signed values；老师称这种 representation 极其普遍。[00:30:54–00:31:07]
- 课件明确说 unsigned arithmetic 具有 C 保证的 modulo behavior；对 signed `-TMin`，本讲只记录老师展示的 fixed-width result，不外推到未讲语义。[00:51:34–00:52:08] [课件: 02-03-bits-ints.pptx p.49]
- 老师对 mixed signed/unsigned 的简化规则对应课件给出的 32-bit `int`/`unsigned int` 表；其他 type width 的组合不在本讲证据范围内。[课件: 02-03-bits-ints.pptx p.28]
- 课件 p.34 以后大多是后续课次内容；本视频明确在 truncation 后结束。总笔记不把 addition、multiplication、memory organization 等未讲内容混入本讲。[01:10:34–01:10:52]

## 常见误区与陷阱

1. **认为 bits 自带类型。** 实际上同一 `10110₂` 可是 unsigned 22 或 signed -10，type/operation 决定 decoder。
2. **把 `&`/`|`/`~` 与 `&&`/`||`/`!` 混用。** 前者逐 bit，后者把整个 operand 规范成 truth value 0/1，并可 short-circuit。[课件: 02-03-bits-ints.pptx p.13]
3. **假设大于等于 word width 的 shift 有固定结果。** C 将其列为 undefined behavior；硬件 modulo count 只是某实现现象。[课件: 02-03-bits-ints.pptx p.14]
4. **把 sign bit 当 sign-magnitude 的“负号”。** two’s complement 的 MSB 是权重 $-2^{w-1}$。
5. **先按纸面 decimal 比 mixed expression。** 必须先确定 types 和 implicit conversion；`-1 > 0U` 就是反例。
6. **认为 `TMin=-TMax`。** 正确是 `TMin=-TMax-1`；`abs(TMin)` 没有同宽 signed 正值可返回。
7. **认为 array index 应无符号，所以 countdown 更安全。** `i>=0` 对 unsigned 永真，`0-1` wrap 到 `UMax`。
8. **只看变量声明，不看 subexpression。** signed `i` 与 unsigned `sizeof` 混合后，condition 仍可能按 unsigned 解释。
9. **把 widening 当 left shift。** extension 在左侧增加 bits，原 bit positions 不动；left shift 会改变值。
10. **认为 truncation 是 saturation 或 rounding。** 它只保留 low bits；目标 sign bit 变化时可使正负翻转。

# 第 1 节：为什么一切都是位——二进制、十六进制与布尔代数

> 时间范围：00:00:01–00:10:00

## 本段在整讲中的作用

本段先给整讲建立问题意识：上一讲出现过“两个正数相乘却得到负数”一类反直觉结果，本讲不把它当作算术偶然，而是追问**有限位表示（finite-width representation）怎样改变运算性质**，尤其是 overflow 等边界情况。[00:00:13–00:00:55] 之后老师沿着“为什么用 bit → 怎样给 bit 串赋予数值 → 为什么需要 hexadecimal → C 中对象有多宽 → 怎样用 Boolean algebra 操作 bit”的路径，从物理实现一直走到后续位运算的数学语言。[课件: 02-03-bits-ints.pptx p.2]

## 教学展开

### 1. 从反直觉运算回到表示层

- 老师先说明接下来几讲研究 data representation，重点是同一类“数”如何以不同形式表示，以及表示形式带来的运算性质。[00:00:13–00:00:27]
- 动机来自上一讲的现象：有限机器字中，正数相乘也可能出现负结果。真正要理解的是数的 bit-level representation、运算怎样作用于这些 bits，以及 overflow 时为什么不再符合数学整数的直觉。[00:00:31–00:00:49]
- 因而教学从最基础的整数位表示开始，而不是直接背 overflow 规则。[00:00:55–00:01:01]

### 2. 为什么数字系统选择 binary

- 人类习惯 decimal 与十根手指有关；早期电子计算机 ENIAC 也用 base 10，每一位需要在十种状态中选一种，老师用“每个十进制位配置十个 vacuum tubes”来说明其硬件代价。[00:01:07–00:01:52] 老师紧接着说“that’s 1948”，其指代或年份在字幕中不够清楚，且当前课件文字不能确认：[需回听 00:01:52]。
- binary 的关键不是“0 和 1 更容易算”，而是它把连续的 analog signal 划成两个允许范围：低电压解释为 0，高电压解释为 1。只要噪声没有跨过判决阈值，接收端仍能恢复干净的离散值。[00:02:04–00:02:44]
- 因此 bit 适合用 bistable element 保存，也能在有噪声、不精确的线路上可靠传输；同一组 bits 再由不同 encoding/interpretation 表示 instruction、number、set、string 等对象。[课件: 02-03-bits-ints.pptx p.3]

**结论：**计算机里“everything is bits”不等于所有对象都具有同一种意义；bits 是统一载体，**解释规则**决定意义。[00:03:10–00:03:15]

### 3. 位权：从整数顺带过渡到 binary fraction

- 对 binary integer，从 binary point 向左，第 $i$ 位的权重是 $2^i$；值等于所有为 1 的位的权重之和。[00:03:19–00:03:29]
- binary point 右侧的权重依次是 $2^{-1},2^{-2},\ldots$，即 $1/2,1/4,\ldots$。老师借此说明 binary fraction 与 decimal fraction 的构造方式相同，floating-point representation 会在一周后展开，本节只建立直觉。[00:03:29–00:04:17]
- 课件给出三种层次的示例：整数 $15213_{10}=11101101101101_2$；分数 $1.20_{10}=1.001100110011\ldots_2$，其中 `0011` 循环；科学计数形式 $1.5213\times10^4=1.1101101101101_2\times2^{13}$。[课件: 02-03-bits-ints.pptx p.4]

这里的目的不是讲完 floating point，而是说明**一套位权规则既可放在 binary point 左边，也可延伸到右边**。

### 4. 用 hexadecimal 压缩 bit 串

- 32 或 64 个 `0/1` 很难人工读写，所以把 bit 串从右向左每 4 bits 分一组；因为 $2^4=16$，每组恰好对应一个 hexadecimal digit。[00:04:22–00:04:53]
- hex 使用 `0`–`9` 表示 0–9，`A`–`F` 表示 10–15；C literal 使用前缀 `0x`，大小写均可，例如 `0xFA1D37B` 与 `0xfa1d37b`。[课件: 02-03-bits-ints.pptx p.5]
- 老师建议先记几个锚点，再插值得到其余值：$1010_2=A_{16}$、$1100_2=C_{16}$、$1111_2=F_{16}$。[00:05:06–00:05:45] 原字幕把第一项识别为 “101 is A”，这里依据课件的 `A=10` 和四位一组规则校正为 `1010`。[课件: 02-03-bits-ints.pptx p.5]
- 一个 byte 是 8 bits，所以有 $2^8=256$ 种 bit pattern，范围可写成 `00000000₂`–`11111111₂`、`0`–`255` 或 `00₁₆`–`FF₁₆`。[00:06:08–00:06:21] [课件: 02-03-bits-ints.pptx p.5]

**实用要求：**看到一个 hex digit，应能立即展开成 4 bits；看到按四位分组的 binary，也应能逐组写成 hex。[00:04:56–00:06:04]

### 5. C 类型宽度与本讲的平台假设

- C 的 `char`、`short`、`int`、`long` 没有在语言设计之初被固定成跨平台完全相同的 byte 数；程序员必须意识到宽度会随 machine/platform 变化。[00:06:08–00:07:05]
- **本课程当时的 x86-64 环境假设**是：`char` 1 byte，`short` 16 bits，`int` 32 bits，`long` 64 bits；老师还提到 32-bit 与 64-bit floating point。[00:07:10–00:07:40] 这些是本讲工作环境中的具体 data representation，不应误记成所有 C 实现无条件保证的精确宽度。[课件: 02-03-bits-ints.pptx p.6]
- 老师补充 x86 的 80-bit extended-precision floating-point 格式，并继续谈到 64-bit 环境中的 padding/alignment；但字幕把关键数量和 machine width 识别成“extra 6 bits/604-bit machines”，课件文字也未给出这些细节，因此不校正其具体数值：[需回听 00:07:55]、[需回听 00:08:03]。
- 老师用 address 宽度解释“64-bit machine”：本讲语境下地址为 64-bit/8-byte value，而较老的 32-bit machine 使用 32-bit address。[00:08:09–00:08:30] 这是课程用来建立 word size 直觉的表述，不要由此推出每一种数据类型都必然是 64 bits。

### 6. Boolean algebra：给 bit 运算一套代数

- George Boole 在 19 世纪提出 Boolean algebra，把 logic 写成 algebraic operations：约定 `1=True`、`0=False`。[00:08:34–00:09:19] [课件: 02-03-bits-ints.pptx p.8]
- 四个基本操作按老师顺序为：
  - AND：`A & B` 仅在二者都为 1 时为 1；
  - OR：`A | B` 在至少一个为 1 时为 1；
  - NOT：`~A` 翻转该 bit；
  - XOR（exclusive-or）：`A ^ B` 在恰有一个输入为 1 时为 1。[00:09:19–00:09:49] [课件: 02-03-bits-ints.pptx p.8]
- 本节最后转入历史连接：Claude Shannon 把 Boolean algebra 用于 digital systems 与 electromechanical relay network；这一说明在下一节继续。[00:09:52–00:10:00] [课件: 02-03-bits-ints.pptx p.65]

# 第 2 节：从 Boolean bit vector 到 C 位运算与移位

> 时间范围：00:10:00–00:19:58

## 本段在整讲中的作用

上一节定义了单个 bit 上的 AND、OR、NOT、XOR。本段按老师的实际路径完成三次推广：先把 Boolean operation 逐位施加到整个 word，再把 bit vector 解释成 set，最后落到 C 的 `& | ~ ^`、`&& || !` 和 shift operators。核心目标是让“bits 是表示”变成可操作的编程模型，同时提前暴露两个高频错误：混淆 bitwise 与 logical operator，以及忽视 right shift 的两种填充规则。[00:10:57–00:11:57] [课件: 02-03-bits-ints.pptx p.9]

## 教学展开

### 1. Shannon：Boolean algebra 如何进入数字系统

- 老师接续上一节的历史线索：Claude Shannon 在 University of Michigan 学过 logic，之后在 MIT 的 master’s thesis 中把当时偏抽象的 Boolean algebra 用到 digital systems。[00:10:00–00:10:28]
- 当时系统由 electromechanical relays 构成，可以把 closed switch 编成 1、open switch 编成 0，再用 Boolean expression 推理网络是否连通。课件给出的连接条件是 `A & ~B | ~A & B`，也就是 `A ^ B`。[课件: 02-03-bits-ints.pptx p.65]
- 老师借此强调：用 Boolean algebra 系统地设计数字电路是现代形成的方法，并非“自古就自然存在”的常识。[00:10:28–00:10:54]

### 2. 从单 bit 运算推广到 bit vector

- 对两个同宽 bit vectors，Boolean operator 在每一对对应位置上独立执行；位置之间没有 carry，也不互相影响。[00:10:57–00:11:41]
- C 使用 `&`（ampersand）、`|`（vertical bar）、`^`（caret）和 `~`（tilde）表示这四种 bit-level operations。原字幕中的 “bullion”“carrot”“tilda”均可由课件符号与上下文校正为 Boolean、caret、tilde。[00:11:05–00:11:41] [课件: 02-03-bits-ints.pptx p.9]
- 老师强调 C 的吸引力之一，是程序能直接进行这种 low-level bit manipulation；后续课程会反复使用。[00:11:41–00:11:57]

课件同步给出 8-bit 逐位计算：[课件: 02-03-bits-ints.pptx p.9]

```text
  01101001          01101001          01101001
& 01010101        | 01010101        ^ 01010101
  --------          --------          --------
  01000001          01111101          00111100

~01010101 = 10101010
```

例如 AND 结果的最高两位是 `01`，不是对两个 binary numbers 做普通乘法；每一列只查单 bit 的 AND truth table。

### 3. bit vector 作为 set 的 characteristic vector

- 老师把抽象位运算解释成集合运算：一个宽度为 $w$ 的 vector 表示全集 $\{0,\ldots,w-1\}$ 的某个子集；从右到左编号，bit 0 对应元素 0，bit $j=1$ 表示 $j$ 在集合中。[00:12:06–00:12:41] [课件: 02-03-bits-ints.pptx p.10]
- 对 8-bit 例子：
  - `01101001₂` 表示 $A=\{0,3,5,6\}$；
  - `01010101₂` 表示 $B=\{0,2,4,6\}$。[课件: 02-03-bits-ints.pptx p.10]
- 逐位运算因此精确对应：
  - `A & B = 01000001₂`：intersection $\{0,6\}$；
  - `A | B = 01111101₂`：union $\{0,2,3,4,5,6\}$；
  - `A ^ B = 00111100₂`：symmetric difference $\{2,3,4,5\}$；
  - `~B = 10101010₂`：相对于 $\{0,\ldots,7\}$ 的 complement $\{1,3,5,7\}$。[00:12:49–00:13:15] [课件: 02-03-bits-ints.pptx p.10]
- 实际用途是用一串 bits 跟踪“哪些候选项当前成立”。老师举后续 file/network I/O 的例子：一个隐藏在 C library calls 背后的数据结构用约一千个 bits 表示一组连接，并快速判断哪些输入已 ready to read。[00:13:17–00:13:59]

**关键边界：**`~` 得到的 set complement 依赖固定 universe/word width。这里是 8 bits，因此只讨论 0–7；若宽度改变，complement 也改变。

### 4. C 的 bit-level operators

- `& | ~ ^` 可用于 C 的 integral data types，如 `long`、`int`、`short`、`char` 及 unsigned variants；操作时把参数视作固定宽度 bit vectors，再逐位应用。[00:14:05–00:14:16] [课件: 02-03-bits-ints.pptx p.11]
- 课件以 8-bit `char` 展示：

```text
~0x41        = 0xBE
~0x00        = 0xFF
0x69 & 0x55  = 0x41
0x69 | 0x55  = 0x7D
```

这些结果正是上一小节 binary 逐位计算的 hex 写法。[课件: 02-03-bits-ints.pptx p.11]

### 5. bitwise 与 logical operators 不是一回事

- 老师把这是非判断列为非常常见的 C 错误：`&` 与 `&&`、`|` 与 `||`、`~` 与 `!`（bang）外形和语义都有一点相似，却执行不同操作；新手常犯，熟练程序员也会偶尔写错。[00:14:17–00:14:58] [课件: 02-03-bits-ints.pptx p.13]
- `&& || !` 先把整个 operand 解释成 truth value：数值 0 为 false，任何 nonzero bit pattern 为 true；结果始终规范化成整数 0 或 1，而不是保留 operand 的某些 bits。[00:15:03–00:16:36] [课件: 02-03-bits-ints.pptx p.12]
- 因而：

```text
!0x41          = 0x00
!0x00          = 0x01
!!0x41         = 0x01
0x69 && 0x55   = 0x01
0x69 || 0x55   = 0x01
```

这里 `0x69 && 0x55` 不等于 bitwise AND 的 `0x41`；两个 operand 都 nonzero，所以 logical result 是 1。[00:15:33–00:16:36] [课件: 02-03-bits-ints.pptx p.12]
- logical AND/OR 还有 early termination（short-circuit evaluation）。`p && *p` 会先判断 `p`；若 `p==NULL`，右侧 `*p` 不执行，因而避免 null pointer dereference。[00:16:51–00:17:11] 原字幕说“then it will do the dereferencing”，与整句意图冲突；课件明确写 `avoids null pointer access`，据此校正。[课件: 02-03-bits-ints.pptx p.12]

### 6. shift operations

- 移位形式为 `x << y` 或 `x >> y`，即把 bit vector `x` 移动 `y` 个位置。[00:17:25–00:18:07]
- **left shift**：老师以左移 3 位说明，保留原 word 中尚未越界的低位，把它们移到左边；左端越界 bits 丢弃，右端空位填 0。[00:18:08–00:18:29] [课件: 02-03-bits-ints.pptx p.14]
- **logical right shift**：老师以右移 2 位说明，右端被移出的 bits 丢弃，左端空位填 0。[00:18:29–00:18:43] [课件: 02-03-bits-ints.pptx p.14]
- **arithmetic right shift**：左端不固定填 0，而是复制原 most significant bit（MSB）。若 MSB 为 0，结果看起来与 logical shift 相同；若 MSB 为 1，就用 1 填充。为什么这能服务于 signed arithmetic，要等 two’s-complement negative number 引入后再解释。[00:18:43–00:19:27] [课件: 02-03-bits-ints.pptx p.14]
- 本段最后提出边界问题：对一个 8-bit value 左移 8 位，直觉上会得到什么？老师把回答留到下一段。[00:19:32–00:19:58]

## 概念、符号与推导

### bit vector 运算

对同宽 vectors $a=[a_{w-1},\ldots,a_0]$、$b=[b_{w-1},\ldots,b_0]$，逐位 AND 可写为：

$$a\mathbin{\&}b=[a_{w-1}\land b_{w-1},\ldots,a_0\land b_0]$$

OR、XOR 同理；NOT 对每个 $a_j$ 取反。这里是对老师“operations applied bitwise”的符号化整理，没有加入跨位 carry。[00:10:57–00:11:41] [课件: 02-03-bits-ints.pptx p.9]

### set encoding

老师给出的定义是：[课件: 02-03-bits-ints.pptx p.10]

$$a_j=1\iff j\in A,\qquad A\subseteq\{0,\ldots,w-1\}$$

由单 bit truth table 逐位置判断可得：

$$A\cap B\leftrightarrow a\mathbin{\&}b,
\quad A\cup B\leftrightarrow a\mathbin{|}b,
\quad A\triangle B\leftrightarrow a\mathbin{\char94}b$$

NOT 对应相对于这 $w$ 个候选元素的 complement。[00:12:49–00:13:15]

### shift 的结构规则

- `x << y`：丢弃左侧越界 bits，右侧补 $y$ 个 0。
- logical `x >> y`：丢弃右侧越界 bits，左侧补 $y$ 个 0。
- arithmetic `x >> y`：丢弃右侧越界 bits，左侧复制 $y$ 个原 MSB。[课件: 02-03-bits-ints.pptx p.14]

本段尚未把 shift 推导成乘除 $2^y$，也尚未决定 8-bit value 移 8 位的结果；不要提前套用后续算术结论。

## 例子、边界与易错点

- **逐位不等于逻辑判断：**`0x69 & 0x55 = 0x41`，但 `0x69 && 0x55 = 1`。[00:15:33–00:16:36] [课件: 02-03-bits-ints.pptx p.11] [课件: 02-03-bits-ints.pptx p.12]
- **NOT 的宽度不可省略：**课件把 `~0x41=0xBE` 明确限定为 8-bit `char` 示例；本段没有讨论其他 operand width 的求值规则，因此不能把这个两位 hex 结果无条件外推。[课件: 02-03-bits-ints.pptx p.11]
- **set complement 不是无限集合补集：**`~01010101₂=10101010₂` 只在固定的 8-element universe 下表示 $\{1,3,5,7\}$。[课件: 02-03-bits-ints.pptx p.10]
- **short-circuit 是控制流语义：**`p && *p` 安全的原因不是 bit manipulation，而是左侧 false 时不求值右侧。[00:16:51–00:17:11]
- **arithmetic 与 logical right shift 的差别只在左侧填充值：**当原 MSB 为 0 时两者结果相同，不能据单个非负例子误认为根本没有两种 right shift。[00:18:43–00:19:27]
- **非法/过大 shift count 的答案尚未给出：**本段只提出 8-bit 左移 8 位的问题；下一段说明 C 不保证直觉结果。[00:19:32–00:19:58]

# 第 3 节：移位边界与整数编码公式

> 时间范围：00:19:58–00:29:48

## 本段在整讲中的作用

本段先回答上一节留下的 shift-count 边界问题，借此建立“机器常见行为不等于 C 语言保证”的意识；随后进入全讲最核心的两个 decoding equations：同一 $w$-bit pattern 分别怎样解释成 unsigned integer 与 two’s-complement integer。老师没有停在公式，而是刻意选用 5-bit 小模型，把位权、同一 bits 的两种数值和三个范围端点逐一算出来。[00:19:58–00:22:30]

## 教学展开

### 1. 移位量达到字长时，不能依赖直觉结果

- 问题承接上一段：如果把一个概念上的 8-bit value 左移 8 位，直觉会认为所有原 bits 都被移出、右边全补 0，结果应为 0。[00:19:58–00:20:08]
- 老师说明在许多机器上会观察到原值 `x`：硬件只读取 shift amount 的低 3 bits，因此有效移位量像是 $8\bmod 8=0$，实际没有移动。[00:20:08–00:20:38]
- 但不同机器可能产生不同结果；C 对 shift amount `< 0` 或 `>= word size` 定义为 undefined behavior。负移位量也不能当成“自动反向移位”。[00:20:38–00:21:02] [课件: 02-03-bits-ints.pptx p.14]

**结论：**“某硬件通常取 shift count modulo word size”只是观察到的实现方式，不是可移植 C 程序可以依赖的语义。

### 2. 两个核心 decoding equations

- 老师把 number representation 称为必须真正内化的核心，并说后续讨论都从两个式子出发。[00:21:02–00:21:34]
- 设 bit vector 为 $\vec{x}=[x_{w-1},\ldots,x_0]$，每个 $x_i\in\{0,1\}$。
- **Unsigned decoding（B2U）**：每一位使用正的 power-of-two weight，所有置 1 位的权重相加。[00:21:34–00:22:05]

  $$\operatorname{B2U}_w(\vec{x})=\sum_{i=0}^{w-1}x_i2^i$$

- **Two’s-complement decoding（B2T）**：低 $w-1$ 位仍用正权重，唯一变化是 most significant bit 使用负权重 $-2^{w-1}$。[00:22:05–00:22:24]

  $$\operatorname{B2T}_w(\vec{x})=-x_{w-1}2^{w-1}+\sum_{i=0}^{w-2}x_i2^i$$

- MSB 因而称为 sign bit：在 two’s-complement interpretation 下，MSB 为 0 时数值非负，为 1 时数值为负。[00:25:33–00:25:44] [课件: 02-03-bits-ints.pptx p.16]

### 3. 5-bit 例子一：`01101₂` 只使用正权重

- 老师选择 $w=5$，bit positions 为 0–4，权重依次为 $1,2,4,8,16$。小规模例子的目的，是让公式的每一项都能直接看见。[00:22:24–00:22:36]
- 第一个板书 pattern 的置 1 位权重为 8、4、1，因此从口述可恢复为 `01101₂`：[00:23:05–00:23:37]

  $$\operatorname{B2U}_5(01101_2)=0\cdot16+1\cdot8+1\cdot4+0\cdot2+1\cdot1=13$$

- 因为 MSB 为 0，two’s-complement interpretation 也得到 13；老师用它说明两种编码在 MSB=0 的区域共享相同权重。[00:24:43–00:24:55]

### 4. 5-bit 例子二：`10110₂` 的两种解释

- 先按 unsigned 解释：[00:23:50–00:24:12]

  $$\operatorname{B2U}_5(10110_2)=16+4+2=22$$

- 再按 two’s complement 解释，MSB 的 $+16$ 改成 $-16$，其余位不变：[00:24:15–00:25:13]

  $$\operatorname{B2T}_5(10110_2)=-16+4+2=-10$$

- 所以 bits 完全相同，数值却可为 22 或 -10；决定数值的是 interpretation，而不是 bits 自己携带的“类型标签”。[00:25:14–00:25:33]
- 两值相差 $22-(-10)=32=2^5$。老师稍后会把这个差值推广成 signed/unsigned conversion 的规则，本段先保留这个观察。

### 5. 从 bit patterns 推出范围端点

老师继续使用 5-bit 模型，不靠死记端点：[00:25:51–00:27:45]

1. **Unsigned minimum**：`00000₂` 没有置 1 位，所以 $\mathrm{UMin}=0$。
2. **Unsigned maximum**：`11111₂=16+8+4+2+1=31$，所以 $\mathrm{UMax}=31$。
3. **Two’s-complement minimum**：要尽量小，就让唯一的负权重位为 1、所有正权重位为 0，即 `10000₂=-16`，所以 $\mathrm{TMin}=-16$。
4. **Two’s-complement maximum**：要尽量大，就让负权重位为 0、所有正权重位为 1，即 `01111₂=8+4+2+1=15`，所以 $\mathrm{TMax}=15$。

一般化到 $w$ bits：[00:27:45–00:29:37] [课件: 02-03-bits-ints.pptx p.18]

$$\mathrm{UMin}_w=0$$

$$\mathrm{UMax}_w=2^w-1$$

$$\mathrm{TMin}_w=-2^{w-1}$$

$$\mathrm{TMax}_w=2^{w-1}-1$$

原字幕在 00:28:31–00:28:47 把指数和 “minus 1” 的位置打乱；这里依据老师的 5-bit 板书数值与课件范围公式校正。[课件: 02-03-bits-ints.pptx p.18]

### 6. 为什么一串低位 1 比下一位权重少 1

- 对 `01111₂`，低四位和为 $8+4+2+1=15$，正好比下一位权重 16 少 1。[00:28:52–00:29:12]
- 老师给出 binary increment 直觉：给 `01111₂` 加 1 时，最右边连续的 1 全部变 0，并逐位传播 carry，最终得到 `10000₂`。因此原值必为 $16-1$。[00:29:12–00:29:37]
- 一般地：[课件: 02-03-bits-ints.pptx p.66]

  $$1+2+4+\cdots+2^{w-1}=2^w-1$$

  等价地，

  $$1+\sum_{i=0}^{w-1}2^i=2^w$$

这正是 `UMax` 和 `TMax` 公式中 “$-1$” 的来源。

## 概念、符号与推导

### 约定

- $w$：word width，单位为 bits。
- $x_i$：bit position $i$ 的值，只能是 0 或 1；$i=0$ 为 least significant bit（LSB）。
- $x_{w-1}$：most significant bit（MSB）；在 B2T 中也是 sign bit。
- B2U：bit vector to unsigned。
- B2T：bit vector to two’s complement。

### B2U 与 B2T 的唯一差异

将两个定义相减：[00:24:15–00:25:28]

$$
\operatorname{B2U}_w(\vec{x})-\operatorname{B2T}_w(\vec{x})
=x_{w-1}2^{w-1}-(-x_{w-1}2^{w-1})
=x_{w-1}2^w
$$

因此 MSB=0 时两值相同；MSB=1 时 unsigned value 比 two’s-complement value 大 $2^w$。这是由老师对 `10110₂` 的 $22/-10$ 计算直接得到的整理，不改变课堂推导顺序。

### 范围推导的前提

- word width 固定为 $w$；一共有 $2^w$ 个 patterns。
- unsigned 所有权重非负，所以全 0/全 1 分别给出 min/max。
- two’s complement 只有 MSB 权重为负，所以 `100...0` 给出 min，`011...1` 给出 max。[00:25:51–00:27:27] [课件: 02-03-bits-ints.pptx p.18]

## 例子、边界与易错点

- **undefined behavior 不是“随机值”定义：**对非法 shift count，C 没有规定结果；某机器得到 `x` 不能形成可移植规则。[00:20:08–00:21:02] [课件: 02-03-bits-ints.pptx p.14]
- **负 shift count 不会自动改变方向：**`x << -1` 不能当作 `x >> 1`。[00:20:50–00:21:02]
- **sign bit 不是 sign-magnitude 的独立正负号：**在 two’s complement 中它本身贡献权重 $-2^{w-1}$；其余 bits 仍是正权重。把 `10110₂` 读成“负的 6”是错误的，正确值是 $-16+6=-10$。[00:24:15–00:25:28]
- **同一 pattern 不含 signedness：**`10110₂` 是 22 还是 -10，取决于程序如何解释它；硬件存储的五个 bits 没变。[00:25:14–00:25:33]
- **端点不对称已露出但尚未解释：**5-bit two’s complement 是 -16 到 15，不是 -15 到 15；下一节会继续分析这种不对称。[课件: 02-03-bits-ints.pptx p.18]
- **small-model 方法：**老师明确建议遇到公式时先用 5-bit 等小规模 pattern 逐项计算，不要让符号遮蔽直觉。[00:22:24–00:22:36]

# 第 4 节：数值范围与 signed/unsigned 映射

> 时间范围：00:29:48–00:39:37

## 本段在整讲中的作用

上一节已经给出 B2U/B2T 和范围端点。本段不再引入新的底层 bit pattern，而是建立三层更强的直觉：第一，全 1 在 two’s complement 中为什么恒为 `-1`；第二，同一组 $2^w$ 个 patterns 怎样被 unsigned 与 signed 范围重新分配；第三，C 中 signed/unsigned conversion 为什么可以理解为“bit pattern 不动，只更换 decoding function”。[00:29:48–00:30:48] [课件: 02-03-bits-ints.pptx p.20]

## 教学展开

### 1. 先用小规模 pattern 理解公式

- 老师提醒，教材会给出较长的 formulas 和 derivations，但这组概念的直觉并不复杂；看到抽象公式迷失时，应先把它代入小 word size，逐位算出含义。[00:29:48–00:30:21]
- 这不是否定公式，而是建议先建立可检查的模型：每个 bit 对应什么 weight、哪些位置是 1、总和是多少。

配套课件还给出 16-bit `short` 的 concrete representation：`15213` 为 `00111011 01101101₂`，`-15213` 为 `11000100 10010011₂`；MSB 分别为 0 和 1。[课件: 02-03-bits-ints.pptx p.16] [课件: 02-03-bits-ints.pptx p.17] 课堂口述在这一段仍以 5-bit 板书为主，没有逐位重算这对 16-bit patterns。[00:29:48–00:30:21]

### 2. two’s complement 的全 1 pattern 恒为 `-1`

- 对 5 bits，老师直接计算：[00:30:21–00:30:48]

  $$11111_2=-16+8+4+2+1=-1$$

- 一般化到 $w$ bits，MSB 的负权重是 $-2^{w-1}$，其余全 1 的正权重和是 $2^{w-1}-1$，所以：[课件: 02-03-bits-ints.pptx p.18]

  $$
  \operatorname{B2T}_w(11\ldots1)
  =-2^{w-1}+\left(2^{w-1}-1\right)
  =-1
  $$

- 因此 `111...111` 不是“最大的 signed number”；它在 unsigned 中是 `UMax`，在 two’s complement 中却是 `-1`。

### 3. two’s complement 的地位与不同 word sizes 的范围

- 老师说明，表示正负数不只 two’s complement 一种方案，但它极其普遍；实际系统中掌握它就能覆盖几乎所有会遇到的 signed integer representation。[00:30:54–00:31:07]
- 重新命名三个端点：`UMax` 是最大 unsigned value，`TMin` 是最负 two’s-complement value，`TMax` 是最大正 two’s-complement value。[00:31:14–00:31:38]
- $w$ bits 总共只有 $2^w$ 个 patterns。若按 unsigned 解释，全部用于 $0$ 到 $2^w-1$；若按 two’s complement 解释，一半用于 negative，另一半用于 zero 与 positive。[00:31:38–00:32:16] [课件: 02-03-bits-ints.pptx p.18]

| $w$ | unsigned range | two’s-complement range |
| ---: | ---: | ---: |
| 8 | 0 … 255 | -128 … 127 |
| 16 | 0 … 65,535 | -32,768 … 32,767 |
| 32 | 0 … 4,294,967,295 | -2,147,483,648 … 2,147,483,647 |
| 64 | 0 … 18,446,744,073,709,551,615 | -9,223,372,036,854,775,808 … 9,223,372,036,854,775,807 |

这些值由上一节三个端点公式直接代入得到；老师现场重点评论：8-bit 只有 256 种可能；16-bit 时代维持数值不越界很麻烦；32-bit 对日常数值已相当宽；64-bit 在当时看起来极大。[00:31:42–00:32:58] [课件: 02-03-bits-ints.pptx p.19]

- 老师以“Microsoft 需要 64-bit 才能表示 Bill Gates 的 net worth”作为范围增长的幽默类比，不是严谨的架构迁移动因。[00:32:30–00:32:48]
- C 的这些极值是 platform specific；课件提示通过 `<limits.h>` 中的 `ULONG_MAX`、`LONG_MAX`、`LONG_MIN` 等 constants 获取，不应在可移植程序里手写假设。[课件: 02-03-bits-ints.pptx p.19]

### 4. 同一 pattern 的两个值相差 $2^w$

- 老师把 5-bit 板书中的两组结果重新并排：`11111₂` 是 unsigned 31、two’s-complement -1；`10110₂` 是 unsigned 22、two’s-complement -10。[00:33:05–00:34:31]
- 两组都相差 32，即 $2^5$。原因是 MSB=1 时，该位权从 signed interpretation 的 $-16$ 切换成 unsigned interpretation 的 $+16$；单这一位的权重变化是 $16-(-16)=32$。[00:34:10–00:34:40]
- 这种 $2^w$ 的跳变正是 C 在 signed/unsigned 之间 reinterpret 时会出现“大 unsigned 突然成为 negative”或反向变化的根源。[00:34:40–00:35:24]

### 5. 4-bit 全表：低半区不变，高半区平移

- 老师再用 4-bit numbers 枚举全部 patterns。MSB=0 的 `0000₂`–`0111₂` 在两种解释下都是 0–7；MSB=1 的 `1000₂`–`1111₂` 在 unsigned 下是 8–15，在 two’s complement 下是 -8–-1，两值相差 $2^4=16$。[00:35:24–00:35:59]
- 因而映射可以分成两段：

  $$
  \operatorname{T2U}_w(x)=
  \begin{cases}
  x, & x\ge 0\\
  x+2^w, & x<0
  \end{cases}
  $$

  反向为：

  $$
  \operatorname{U2T}_w(u)=
  \begin{cases}
  u, & 0\le u\le \mathrm{TMax}_w\\
  u-2^w, & \mathrm{TMax}_w<u\le \mathrm{UMax}_w
  \end{cases}
  $$

老师现场用“MSB=0 不变，MSB=1 相差 $2^w$”解释这些分段关系，而不是要求先记 piecewise formula。[00:35:44–00:38:14] [课件: 02-03-bits-ints.pptx p.25]

### 6. uniqueness 使映射可以反向

- 对固定宽度和固定 interpretation，每个 bit pattern 都对应唯一 integer；范围内每个 representable integer 也有唯一 bit encoding。因此 B2U/B2T 都是一一对应，可定义 inverse functions U2B/T2B。[00:35:59–00:36:17] [课件: 02-03-bits-ints.pptx p.20]

  $$\operatorname{U2B}_w=\operatorname{B2U}_w^{-1},\qquad
  \operatorname{T2B}_w=\operatorname{B2T}_w^{-1}$$

- T2U 是 `T2B` 后接 `B2U`；U2T 是 `U2B` 后接 `B2T`。中间 bit pattern 原封不动，变化的是最后使用哪种 decoder。[00:36:17–00:38:03] [课件: 02-03-bits-ints.pptx p.22]
- 例：`T2U₅(-1)=31`，因为 `T2B₅(-1)=11111₂`，再由 `B2U₅` 得 31。[00:36:43–00:37:11]
- 老师强调机器本身只持有 bits，并不知道这些 bits 是“negative unsigned number”还是 two’s-complement number；signedness 来自程序和操作所采用的 interpretation。原字幕里的 “negative unsigned number” 语义矛盾，应理解为“negative signed number or unsigned number”；此处仅按上下文释义，不把它当成新术语。[00:37:20–00:37:44]

### 7. 为 conversion graph 铺设 5-bit 数轴

- 本段结尾，老师开始画 5-bit two’s-complement 数轴：从 `TMin=-16` 经 `-1`、`0` 到 `TMax=15`，准备在下一段把它与 unsigned 的 0–31 对齐。[00:38:23–00:39:24]
- 因为板书空间不够，老师停下来调整两块黑板；映射图的完整结论属于下一节。[00:39:24–00:39:37]

## 概念、符号与推导

### 三组函数不要混淆

| 函数 | 输入 | 输出 | bits 是否改变 |
| --- | --- | --- | --- |
| B2U / B2T | bit vector | integer value | 只是解释，不谈改变 |
| U2B / T2B | integer value | bit vector | 生成该 interpretation 下的唯一 encoding |
| T2U / U2T | integer value | 另一 interpretation 下的 integer value | 中间 encoding 保持完全相同 |

[00:35:59–00:38:03] [课件: 02-03-bits-ints.pptx p.20] [课件: 02-03-bits-ints.pptx p.22]

### $2^w$ 差值的推导

对 MSB=1 的 pattern，其余位贡献记为 $r$：

$$u=2^{w-1}+r$$

$$t=-2^{w-1}+r$$

所以：

$$u-t=2^{w-1}-(-2^{w-1})=2^w$$

这解释 `31-(-1)=32` 与 `22-(-10)=32`。[00:34:10–00:34:40]

### 全 1 为 `-1` 与 range asymmetry

全 1 的低位正权重之和比 $2^{w-1}$ 少 1，恰好抵消 sign bit 后剩 `-1`。同时，two’s-complement range 含 $2^{w-1}$ 个 negative values，却只含 $2^{w-1}-1$ 个 positive values，另一个 pattern 给 0；这种不对称将在后面用 `TMin` corner case 展开。[课件: 02-03-bits-ints.pptx p.18] [课件: 02-03-bits-ints.pptx p.19]

## 例子、边界与易错点

- **全 1 的含义取决于 interpretation：**unsigned 是 `UMax`，two’s complement 是 `-1`。[00:30:21–00:30:48] [课件: 02-03-bits-ints.pptx p.18]
- **“sign bit=1”不是再额外加负号：**它把最高位权重从 $+2^{w-1}$ 换成 $-2^{w-1}$；其余位保持不变。[00:34:10–00:34:40]
- **cast/reinterpret 不等于转换 bit pattern：**T2U/U2T 的核心是 maintain same bit pattern；数值可加减 $2^w$。[00:36:17–00:38:14] [课件: 02-03-bits-ints.pptx p.22]
- **映射不保持 ordering：**negative half 会移到 unsigned range 的高端；因此 signed 中较小的负数会成为很大的 unsigned 数。完整 visualization 下一节继续。[课件: 02-03-bits-ints.pptx p.26]
- **固定宽度是所有公式的前提：**`-1 → 31` 只针对 5 bits；32 bits 下同一规则得到 `4294967295U`，不是仍为 31。
- **平台极值应查 `<limits.h>`：**不要把课堂某一 word size 的 decimal endpoint 当作所有 C implementation 的固定值。[课件: 02-03-bits-ints.pptx p.19]

# 第 5 节：C 的 signed/unsigned conversion 与比较陷阱

> 时间范围：00:39:37–00:49:33

## 本段在整讲中的作用

上一节把 T2U/U2T 定义为“保持 bit pattern、切换 interpretation”，并开始画 5-bit 数轴。本段先完成这张图，再解释它为什么会直接影响 C 程序：C 有显式 unsigned types，赋值、函数调用和 mixed-type expressions 都可能触发 conversion。老师用一整张 comparison table 把抽象的 $\pm2^w$ 跳变变成可见的真假反转。[00:40:16–00:41:15] [课件: 02-03-bits-ints.pptx p.26]

## 教学展开

### 1. 完成 5-bit T2U 图

- 调整好两块黑板后，老师把 two’s-complement 区间 `-16..15` 映到 unsigned 区间 `0..31`。[00:39:37–00:40:16]
- 非负半区 `0..15` 的 MSB 为 0，T2U 后数值原样保留；negative half `-16..-1` 的 MSB 为 1，分别加 $2^5=32$，变成 `16..31`。[00:40:16–00:40:37]
- 特别地，`TMin=-16 → 16=TMax+1`，全 1 的 `-1 → 31=UMax`。[00:40:16–00:40:37]
- 图中绿色部分是 MSB=0、数值不变的区域；粉色部分是由 negative signed values 翻到 unsigned 高端的区域。因此 conversion 会打乱原 signed ordering：negative values 不再位于数轴左侧，而成为最大的一批 unsigned values。[00:40:51–00:41:06] [课件: 02-03-bits-ints.pptx p.26]

### 2. 为什么这个映射在 C 中尤其重要

- 老师对比 Python/Java 的学习经验：C 是少数把 unsigned 作为显式整数类型暴露给程序员的语言之一，因此这种 reinterpretation 会频繁进入表达式。[00:41:15–00:41:32]
- `unsigned` 是 `unsigned int` 的简写，也可声明 `unsigned char`、`unsigned short`、`unsigned long`。[00:41:32–00:41:50]
- 显式 cast 与 T2U/U2T 对应；赋值和 procedure/function call 也会发生 implicit conversion。例如：[00:42:00–00:42:35] [课件: 02-03-bits-ints.pptx p.27]

```c
int tx, ty;
unsigned ux, uy;

tx = (int) ux;       /* explicit U2T */
uy = (unsigned) ty;  /* explicit T2U */

tx = ux;             /* implicit conversion */
uy = ty;             /* implicit conversion */
```

在本讲固定-width two’s-complement 模型中，conversion 保留低 $w$ 位 pattern，再按目标 signedness 解释；数值可能不变，也可能加减 $2^w$。[课件: 02-03-bits-ints.pptx p.29]

### 3. mixed expression 的课堂规则

- 老师把规则推广到 comparison、addition、division 等运算：参与同一个 expression 的 operands 需要统一类型；若课件中的一对同宽 `int`/`unsigned int` 中有一个 unsigned，signed operand 会先转成 unsigned，然后执行运算。[00:42:35–00:43:12] [课件: 02-03-bits-ints.pptx p.28]
- 判断比较题时，第一步不是直接比较纸面十进制值，而是先问“这是 signed comparison 还是 unsigned comparison？”[00:43:16–00:43:43]
- integer constant 默认按 signed 类型处理；后缀 `U` 或 `u` 明确产生 unsigned constant，例如 `0U`。[00:43:45–00:43:57] [课件: 02-03-bits-ints.pptx p.27]

**适用范围说明：**课堂规则和课件表格针对本页列出的 32-bit `int`/`unsigned int` 例子。讲者没有在本段展开其他 type width 的组合，因此这里不把该简化规则外推到未讲情形。[课件: 02-03-bits-ints.pptx p.28]

### 4. Casting Surprises：逐行判断

### 5. 三个重点反转怎样由 bits 看出来

1. **`-1 > 0U`**：`-1` 是全 1；T2U 后是 `UMax`，所以反而最大。[00:44:31–00:45:22]
2. **`TMaxU < TMin`**：一旦 unsigned comparison，`TMin` 的 leading 1 不再有负权重，而成为 unsigned 的 $2^{31}$；它比 `TMax=2^{31}-1` 大。[00:46:04–00:47:33]
3. **`(unsigned)-1 > -2`**：`-1` 与 `-2` 分别是 `...1111₂`、`...1110₂`；按 unsigned 仍保持前者大 1。[00:47:36–00:48:00]

## 概念、符号与推导

### conversion 的分段模型

对本讲的固定 $w$-bit 模型：[00:40:16–00:41:06] [课件: 02-03-bits-ints.pptx p.26]

$$
\operatorname{T2U}_w(x)=
\begin{cases}
x,&x\ge0\\
x+2^w,&x<0
\end{cases}
$$

例如 $\operatorname{T2U}_{32}(-1)=-1+2^{32}=4{,}294{,}967{,}295$。

### 比较题的固定流程

1. 标出每个 operand 的 C type，包括 literal 的 `U/u` suffix 和 explicit cast。
2. 在课件的同宽 `int`/`unsigned int` 场景下，只要一边是 unsigned，就对另一边做 T2U。
3. bit pattern 保持不变，必要时按 $x+2^w$ 求 negative value 的 unsigned 数值。
4. 最后才应用 `< > ==`。[00:43:16–00:43:57] [课件: 02-03-bits-ints.pptx p.28]

### 关键端点关系

$$\operatorname{T2U}_w(-1)=\mathrm{UMax}_w=2^w-1$$

$$\operatorname{T2U}_w(\mathrm{TMin}_w)=2^{w-1}=\mathrm{TMax}_w+1$$

# 第 6 节：范围不对称、`TMin` corner case 与 unsigned 循环

> 时间范围：00:49:33–00:59:33

## 本段在整讲中的作用

上一节最后指出 `TMin` 的绝对值比 `TMax` 大 1。本段先解释这一个 pattern 的差异从何而来，再展示它怎样破坏看似正确的 `abs`；随后推导 `UMax = 2*TMax + 1`，并把 signed/unsigned conversion 落到两个 loop failures。教学重点从“会算 conversion”转向“能主动寻找 endpoint 和 implicit unsigned conversion”。[00:49:33–00:51:07] [课件: 02-03-bits-ints.pptx p.19]

## 教学展开

### 1. 为什么 two’s-complement range 不对称

- 对 $w$ bits，MSB=1 的 $2^{w-1}$ 个 patterns 全部表示 negative values；MSB=0 的另 $2^{w-1}$ 个 patterns 要同时容纳 zero 和 positive values。[00:49:33–00:50:47]
- 因为 `000...0` 必须留给 0，positive values 只有 $2^{w-1}-1$ 个，而 negative values 有 $2^{w-1}$ 个。因此最负值比最大正值多出一个量级单位：[00:50:47–00:51:01] [课件: 02-03-bits-ints.pptx p.19]

  $$|\mathrm{TMin}_w|=2^{w-1}=\mathrm{TMax}_w+1$$

- 5-bit 例子即 `TMin=-16`、`TMax=15`；32-bit 例子为 `-2147483648` 与 `2147483647`。

### 2. `abs(TMin)` 为什么是必须测试的 corner case

- 老师写出经典 absolute-value 逻辑：若 `x<0` 返回 `-x`，否则返回 `x`，然后问输入 `TMin` 会怎样。[00:51:01–00:51:44]

```c
int abs_like(int x) {
    return x < 0 ? -x : x;
}
```

- 数学上 $-\mathrm{TMin}=2^{w-1}$，但它比 `TMax` 大 1，无法由同宽 signed integer 表示。在课堂采用的 wraparound/two’s-complement machine model 中，bit pattern 回到 `TMin`，所以函数返回的仍是负的 `TMin`。[00:51:45–00:52:08]
- 老师把 `TMin` 称为测试中专门用来“break things”的 endpoint：任何包含 negation、absolute value 或边界比较的代码，都应主动加入该输入。[00:52:08–00:52:15]

**证据边界：**老师在课堂 two’s-complement machine model 中观察到结果回到 `TMin`；本段 transcript 与课件没有继续讨论其他 C implementation 或语言标准层面的处理，因此这里不作外推。

### 3. `TMin` 常量为何写成 `-TMax-1`

- 学生追问上一节 `-2147483647-1` 的写法是否会引发奇怪问题。老师回答这是 C limits constants 有意采用的形式，并用 parentheses 避免 precedence 问题。[00:52:15–00:52:53]
- 其数值关系就是：[00:52:53–00:53:05]

  $$\mathrm{TMin}=-\mathrm{TMax}-1$$

- `<limits.h>` 提供 `LONG_MIN`、`LONG_MAX`、`ULONG_MAX` 等 platform-specific constants；使用它们比手写十进制端点可靠。[课件: 02-03-bits-ints.pptx p.19]

### 4. mixed signed/unsigned 规则不仅影响 comparison

- 回答课堂提问时，老师说明 comparison 只是一般 expression conversion 的特例；addition、subtraction 等同样先统一 operand types。若本节同宽例子中任一 operand 是 unsigned，另一个会按 unsigned 解释。[00:53:05–00:53:34]
- 老师预告：从低 $w$ 位 bit patterns 看，addition、subtraction、甚至 multiplication 的底层结果对 unsigned 与 two’s complement 相同；具体算术证明留到下一次课，本讲不展开。[00:53:34–00:53:52]
- 因此本段只应记住“conversion 会先发生”，不应把未讲的 overflow arithmetic derivation 提前当成本节结论。

### 5. 推导 `UMax = 2*TMax + 1`

- 老师重新观察另一个端点关系：[00:54:00–00:54:31] [课件: 02-03-bits-ints.pptx p.19]

  $$\mathrm{UMax}_w=2\mathrm{TMax}_w+1$$

- bit-level 推导按课堂顺序是：[00:54:33–00:55:19]
  1. `TMax` 是 `0` 后跟 $w-1$ 个 `1`，数值 $2^{w-1}-1$；
  2. 左移一位得到末位为 0 的 `111...110₂`，数值 $2^w-2=2*TMax`；
  3. 再加 1，把最后一位设为 1，得到全 1 的 `UMax=2^w-1`。
- 以 5 bits 为例：`TMax=01111₂=15`，`2*TMax=11110₂=30`，再加 1 得 `UMax=11111₂=31`。

### 6. unsigned 倒序 loop 不会在 0 停止

- 老师先写一个常见的反向遍历模式：从末尾逐个递减，条件是 `i >= 0`。[00:55:22–00:56:57]

```c
for (i = n - 1; i >= 0; i--)
    use(a[i]);
```

- 若 `i` 被声明成 unsigned，条件 `i >= 0` 对它的每个可表示值都为 true。[00:56:57–00:57:48]
- 当 `i` 从 0 执行 `i--`，unsigned arithmetic 按 modulo $2^w$ wrap 到 `UMax`。循环继续，并很可能访问极大的 out-of-bounds index，最终触发 memory fault；问题不是“多跑一次”，而是 termination condition 永远失效。[00:57:15–00:57:43]
- 因此“array index 不会是负数，所以用 unsigned 总更合理”是危险的半真命题：还必须检查算法是否把负值用作 loop termination sentinel。

### 7. `int i` 也可能被 `sizeof` 暗中拉到 unsigned

- 老师接着把例子变得更隐蔽：即使 `i` 声明为 signed `int`，只要 loop condition 的 arithmetic 混入 `sizeof(...)` 的结果，仍可能变成 unsigned comparison。[00:57:53–00:59:23]
- `sizeof` 是 C operator/built-in，不是普通 function；其 result type 是 unsigned `size_t`。[00:58:46–00:59:31]
- 与现场板书对应的课件形式是：[课件: 02-03-bits-ints.pptx p.48]

```c
#define DELTA sizeof(int)
int i;

for (i = CNT; i - DELTA >= 0; i -= DELTA)
    /* ... */
```

- 在 condition `i - DELTA >= 0` 中，`DELTA` 的 unsigned type 触发 usual arithmetic conversion；负的数学结果可能先变成巨大 unsigned value，再与 0 比较，于是条件仍为 true。代码表面上有 signed `i`，却仍会越界。[00:58:00–00:59:31]
- 这一例的后果和最终总结跨到下一节开头；本节停在“`sizeof` 的结果 considered unsigned”。

## 概念、符号与推导

### range asymmetry 的计数证明

固定 $w$ bits：

- MSB=1：$2^{w-1}$ 个 negative patterns，值域 $[-2^{w-1},-1]$；
- MSB=0：$2^{w-1}$ 个 nonnegative patterns，其中一个是 0，只剩 $2^{w-1}-1$ 个 positive values。[00:49:56–00:50:57]

所以：

$$-\mathrm{TMin}=2^{w-1},\qquad \mathrm{TMax}=2^{w-1}-1$$

$$|\mathrm{TMin}|=\mathrm{TMax}+1$$

[课件: 02-03-bits-ints.pptx p.19]

### `TMin` negation 的固定宽度解释

在 modulo-$2^w$ 的 bit-level 模型中：

$$-(-2^{w-1})=2^{w-1}\equiv -2^{w-1}\pmod{2^w}$$

因此同一 pattern `100...0` 回到自身。这解释老师在本讲模型中观察到的 `abs_like(TMin)==TMin`；其他语义不在本段材料范围内。[00:51:34–00:52:08]

### unsigned decrement

$$0-1\equiv 2^w-1=\mathrm{UMax}\pmod{2^w}$$

这一步让 `i >= 0` 永真，并把下一次访问送到数组范围之外。[00:57:15–00:57:48]

## 例子、边界与易错点

- **zero 消耗的是 nonnegative half 的一个 pattern：**这正是 positive side 少一个值的原因，不是硬件随意决定 `TMin` 更大。[00:49:56–00:51:01]
- **`abs(x)` 的返回类型不够宽时无法表示 `abs(TMin)`：**判断分支本身没错，range assumption 错了。[00:51:07–00:52:08]
- **不要扩大课堂结论：**课件明确保证的是 unsigned modulo arithmetic；对 signed `-TMin`，本段只记录老师展示的 fixed-width result。[00:51:34–00:52:08] [课件: 02-03-bits-ints.pptx p.49]
- **`i >= 0` 对 unsigned 是 tautology：**编译器不需要等到 runtime 才“发现”它，逻辑上对类型范围内所有值都成立。[00:57:44–00:57:53]

# 第 7 节：Sign extension 与 truncation

> 时间范围：00:59:33–01:09:29

## 本段在整讲中的作用

本段先用一句结论收束 `sizeof` 引发的 mixed signed/unsigned bug，然后进入本讲最后一类 representation operation：改变 integer width。老师先证明 widening signed value 时为何复制 sign bit 能保持数值，再对比 unsigned zero extension；随后反向讨论 truncation，说明“保留低位”对 unsigned 是 modulo arithmetic，对 two’s complement 则必须截断后重新解释。[00:59:33–01:00:37] [课件: 02-03-bits-ints.pptx p.31]

## 教学展开

### 1. `sizeof` bug 的最终后果

- `sizeof` 产生 unsigned `size_t`；当 signed `i` 与它参与 subtraction/comparison 时，组合会按 unsigned 处理。在老师的例子中，这使 loop condition 成为几乎肯定不是程序员本意的 unsigned comparison。[00:59:33–00:59:46]
- 程序可能越界并 crash，而源码表面又写着 `int i`，因此很难从直觉看出原因。老师把它归为必须记住的 C signed/unsigned subtlety，也认为若能重新设计语言，大概不会继续采用这套约定。[00:59:46–01:00:28]
- 对应模式仍是上一节的 `i - DELTA >= 0`，其中 `DELTA` 来自 `sizeof(int)`。[课件: 02-03-bits-ints.pptx p.48]

### 2. widening 的任务不是移动数值

- 新任务：给定一个较窄的 signed integer，例如 8 bits，把它扩成 16 bits，同时**保持同一个数学值**。[01:00:37–01:01:00]
- two’s complement 的规则是 sign extension：在左侧添加所需数量的 bits，每一位都复制原 sign bit/MSB。[01:01:00–01:01:15] [课件: 02-03-bits-ints.pptx p.31]
- 老师一度脱口说成 left shift，立即停下来纠正：widening 不是把所有原 bits 左移，也不是乘 2；原 bit positions 和权重应保持，新增 bits 放在更高位。[01:01:30–01:02:12]

### 3. 非负例子：leading zero 继续补 zero

- 对 4-bit `0110₂`，two’s-complement value 为 $4+2=6$。[01:02:08–01:02:16]
- 扩到 5 bits 时复制 sign bit 0，得到 `00110₂`；原来的 4、2 权重位置不变，新高位为 0，因此仍为 6。
- 对 MSB=0 的 signed value，sign extension 表面上与 unsigned zero extension 相同，但理由不同：前者复制 sign bit，而后者按 unsigned widening rule 固定补 0。[课件: 02-03-bits-ints.pptx p.33]

### 4. 负数例子：`1110₂ → 11110₂` 仍为 -2

- 原 4-bit pattern：[01:02:22–01:02:37]

  $$\operatorname{B2T}_4(1110_2)=-8+4+2=-2$$

- 扩成 5 bits 时复制原 sign bit 1，得到 `11110₂`。新解释为：[01:02:38–01:03:11]

  $$\operatorname{B2T}_5(11110_2)=-16+8+4+2=-2$$

- 数值保持的机制是：原 sign bit 所在位置在扩宽后从负权重 $-8$ 变成普通正权重 $+8$，新复制出的 sign bit 贡献 $-16$；二者之和仍为 $-8$。[01:03:13–01:03:38]

  $$-16+8=-8$$

- 每多扩一位都会重复同样的抵消，所以可以复制 sign bit 任意多次，而不改变 two’s-complement value。[01:03:38–01:04:14]

### 5. 一般 sign-extension 证明

设原值宽 $w$，只先扩 1 位。若 sign bit $x_{w-1}=0$，新增 0 显然贡献 0；若 $x_{w-1}=1$，与 sign bit 相关的贡献由：

$$-2^{w-1}$$

变成：

$$-2^w+2^{w-1}=-2^{w-1}$$

其余低位权重完全不变，所以总值不变。重复 $k$ 次得到：[01:03:38–01:04:14] [课件: 02-03-bits-ints.pptx p.31]

$$
[x_{w-1},\ldots,x_0]
\longrightarrow
[\underbrace{x_{w-1},\ldots,x_{w-1}}_{k\text{ copies}},x_{w-1},\ldots,x_0]
$$

### 6. 从 leading `F` 识别 sign-extended negative value

- 一个 hex digit `F` 是 `1111₂`。因此较窄 negative value 扩成更宽 two’s-complement integer 后，常会看到很多 leading `F`，例如 `0xFFFF...`。[01:04:14–01:04:59]
- 老师的识别口诀是：看到一串 leading `F`，先想到这是 sign extension 后的 negative number。它常表示靠近 0 的小负数，而不是巨大的正 unsigned value；最终数值仍取决于 width 与 interpretation。[01:04:39–01:05:02]

### 7. `short` 扩成 `int` 的课件例子

- C 在从较小 signed integer type 转到较大 signed type 时自动执行 sign extension。[01:05:07–01:05:17] [课件: 02-03-bits-ints.pptx p.32]
- 配套例子沿用 `±15213`：[课件: 02-03-bits-ints.pptx p.17] [课件: 02-03-bits-ints.pptx p.32]

```c
short int x =  15213;  /* 0x3B6D */
int      ix = (int)x;  /* 0x00003B6D */

short int y = -15213;  /* 0xC493 */
int      iy = (int)y;  /* 0xFFFFC493 */
```

- `x` 的 sign bit 为 0，新增高位全是 0；`y` 的 sign bit 为 1，新增高位全是 1。两者扩宽后数值都不变。[课件: 02-03-bits-ints.pptx p.33]
- unsigned widening 更直接：无论原 MSB 是什么，左侧都添加 0。[01:05:25–01:05:29] [课件: 02-03-bits-ints.pptx p.33]

### 8. truncation：只保留低位

- 老师转向反问题：若把一个 number 变短，硬件/转换会丢弃高位，只保留目标宽度能容纳的 low-order bits。[01:05:32–01:06:36]
- 现场 5-bit unsigned 例子经老师自我纠正后是：[01:05:54–01:07:35]

  $$11011_2=16+8+2+1=27$$

  截成 4 bits 丢掉最高的 `1`：

  $$1011_2=8+2+1=11$$

  二者相差 16，所以：

  $$27\bmod 16=11$$

- 老师最初口算说出 17、9 等不一致结果，随后由学生提醒并明确改为 27 和 11；正文采用最终修正值，不保留中间算术错误。[01:06:00–01:07:35]
- 一般地，截到 $k$ bits 等价于保留低 $k$ 位；对 unsigned value $u$：[01:07:38–01:07:54] [课件: 02-03-bits-ints.pptx p.33]

  $$u'=u\bmod 2^k$$

### 9. two’s-complement truncation：先丢 bits，再重解释

- 对 signed value，机械动作仍是丢掉高 bits；困难在于剩余 pattern 要按新的 $k$-bit sign weight 重新解释，因此结果不总是直觉上的 remainder。[01:07:54–01:08:24] [课件: 02-03-bits-ints.pptx p.33]
- 第一个 pattern `11011₂` 若按 5-bit two’s complement 是：

  $$-16+8+2+1=-5$$

  截成 4-bit `1011₂` 后是：

  $$-8+2+1=-5$$

  数值没有变化，因为原 pattern 正好是 4-bit `1011` 的 sign extension；老师指出这个例子因此“不够有趣”。[01:08:24–01:09:05]
- 老师随后把 5-bit pattern 改成 `10011₂`，其值是 $-16+2+1=-13$；截断后剩 `0011₂`，结果在下一节开头揭晓。[01:09:12–01:09:29]

## 概念、符号与推导

### widening rules

| source interpretation | 扩宽规则 | 数值 |
| --- | --- | --- |
| unsigned | 左侧补 0（zero extension） | 保持 |
| two’s complement | 左侧复制 sign bit（sign extension） | 保持 |

[课件: 02-03-bits-ints.pptx p.33]

### sign extension 的代数不变量

扩一位时，旧 sign contribution $-x_{w-1}2^{w-1}$ 被：

$$-x_{w-1}2^w+x_{w-1}2^{w-1}$$

替代，而：

$$-x_{w-1}2^w+x_{w-1}2^{w-1}=-x_{w-1}2^{w-1}$$

所以总和不变。[01:03:13–01:03:54]

### truncation rule

从 $w$ bits 截到 $k<w$ bits：

1. 保留 $x_{k-1},\ldots,x_0$；
2. 丢弃 $x_{w-1},\ldots,x_k$；
3. 按目标 signedness 重新解释剩余 pattern。[01:05:42–01:07:54] [课件: 02-03-bits-ints.pptx p.33]

对 unsigned，这直接是 modulo $2^k$；对 signed，bit truncation 相同，但 numerical result 还取决于新 sign bit $x_{k-1}$。

## 例子、边界与易错点

- **widening 不是 left shift：**left shift 会改变原位权并近似乘 2；extension 在左边添加 bits，原位置不动。[01:01:30–01:02:12]
- **negative widening 不能补 0：**`1110₂=-2` 若补 0 成 `01110₂` 会变成 +14；必须复制 1 成 `11110₂`。[01:02:22–01:03:54] [课件: 02-03-bits-ints.pptx p.31]
- **leading `F` 的含义依赖 signed interpretation：**把 `0xFFFFC493` 当 unsigned 读会是大正数；把它当 sign-extended `int` 才是 -15213。[课件: 02-03-bits-ints.pptx p.32]
- **truncation 不做 rounding：**它只丢 high-order bits；unsigned `27→11` 是 modulo 16，不是把 27 限制到 4-bit maximum 15。[01:06:34–01:07:54]
- **signed truncation 可能偶然保持值：**若被丢掉的 bits 只是合法 sign extension copies，如 `11011₂→1011₂`，值不变；不能据此认为所有 signed truncation 都安全。[01:08:24–01:09:12]
- **源值可表示性是关键：**只有原值落在目标 signed range 内时，sign-extension 的逆过程才必然恢复同一数值；超出后必须重新解释 low bits。[课件: 02-03-bits-ints.pptx p.33]

# 第 8 节：Signed truncation 的最终例子与本讲收束

> 时间范围：01:09:29–01:10:54

## 本段在整讲中的作用

本段完成上一节留下的 5-bit-to-4-bit signed truncation：一个原本为 -13 的 two’s-complement value，在只保留低 4 bits 后变成 +3。老师用它说明 truncation 的危险并非只在“数值变小”，而在于新的 sign bit 可能改变，导致正负号翻转；随后明确把 addition、multiplication 等 integer arithmetic 留到下一次课。[01:09:29–01:10:52] [课件: 02-03-bits-ints.pptx p.33]

## 教学展开

### 1. 完成 `-13 → +3` 的截断

- 上一节末尾的 source pattern 是 5-bit `10011₂`。按 5-bit two’s complement 解释：[01:09:12–01:09:29]

  $$\operatorname{B2T}_5(10011_2)=-16+2+1=-13$$

- 截成 4 bits 时机械地丢掉最高位，留下 `0011₂`。新的 4-bit MSB 是 0，所以：[01:09:29–01:10:05]

  $$\operatorname{B2T}_4(0011_2)=2+1=3$$

- 这与上一例 `-5 → -5` 不同：`10011₂` 不是 `0011₂` 的 sign extension；被丢掉的 `1` 承担了原 source 的 negative weight，丢掉后目标 pattern 已是 nonnegative。

### 2. 用 unsigned 中间值理解 modulo 路径

- 老师先随口把该 pattern 对应的 unsigned value 说成 27，马上意识到“我们已经改了 number”，并修正为 19。[01:09:42–01:09:59]
- 正确链条是：同一 5-bit pattern `10011₂` 若按 unsigned 解释为 19；保留低 4 bits 等价于 modulo 16；结果为 3：[01:09:49–01:10:05]

  $$\operatorname{T2U}_5(-13)=19$$

  $$19\bmod 2^4=19\bmod16=3$$

  $$\operatorname{U2T}_4(3)=3$$

- 因而 signed truncation 可以统一写成“先保留 low bits，再按目标 two’s-complement width 解释”：[课件: 02-03-bits-ints.pptx p.33]

  $$
  x'=
  \operatorname{U2T}_k\left(\operatorname{T2U}_w(x)\bmod2^k\right),
  \qquad k<w
  $$

老师没有要求背这个组合公式，而是强调它不像 unsigned modulo 那样一眼直观；最稳妥的办法仍是写出 bits、截断、再重新赋权。[01:10:05–01:10:18]

### 3. truncation 的一般风险

- 老师只说明 truncation 在程序中经常发生，但没有在本段枚举具体来源；这里不补造场景。[01:10:18–01:10:26]
- 丢弃高位后，新的 top retained bit 成为 sign bit。因此：
  - negative source 可能变成 positive，如本例 `-13 → 3`；
  - positive source 也可能变成 negative；
  - 若丢掉的只是冗余 sign-extension bits，数值也可能保持不变，如上一节 `-5 → -5`。[01:10:20–01:10:34]
- 不能仅凭 source signedness 或 source sign 预测结果；必须检查目标宽度的 low-bit pattern。[课件: 02-03-bits-ints.pptx p.33]

- 老师至此结束本次内容，并说明下一次（Tuesday）继续 integer arithmetic，包括前面预告但尚未推导的 addition、negation、multiplication、shifting arithmetic。[01:10:34–01:10:52] [课件: 02-03-bits-ints.pptx p.2]

## 概念、符号与推导

### signed truncation 的三步算法

给定 $w$-bit two’s-complement source，截到 $k<w$ bits：[01:09:29–01:10:18]

1. 写出 source 的 $w$-bit pattern。
2. 丢弃最高的 $w-k$ bits，只保留 low $k$ bits。
3. 把保留 pattern 的 bit $k-1$ 当作新 sign bit，用 B2T$_k$ 重新解释。

这三步比直接在 signed decimal 上猜 modulo 更可靠。

### 为什么 `-13` 的 unsigned 中间值是 19

source width 为 5，且 -13 为 negative，所以：[01:09:42–01:09:59]

$$\operatorname{T2U}_5(-13)=-13+2^5=19$$

之后：

$$19\bmod2^4=3$$

目标 3 落在 4-bit nonnegative range 0–7，U2T 不再减 16，最终仍为 3。

### sign flip 的条件

- source 的 sign 由 source bit $x_{w-1}$ 决定；
- target 的 sign 由 retained bit $x_{k-1}$ 决定。

两者不是同一位置。若它们不同，truncation 后正负号就可能翻转；若高位只是 $x_{k-1}$ 的 sign-extension copies，值才可能保持。[课件: 02-03-bits-ints.pptx p.31] [课件: 02-03-bits-ints.pptx p.33]

## 例子、边界与易错点

- **采用老师修正后的数值：**本例 unsigned intermediate 是 `10011₂=19`，不是老师最初沿用上一 pattern 说出的 27。[01:09:42–01:09:59]
- **signed truncation 不是直接把负数做日常“余数”运算：**应先固定 bit width，再保留 low bits 并按新 width 解释。[01:10:05–01:10:18]
- **丢掉一个 leading 1 不必仍为负：**目标 sign bit 是截断后 pattern 的 MSB；本例目标为 `0011`，所以是 +3。[01:09:29–01:10:05]
- **“小数值通常安全”必须带目标范围前提：**课件只说 small numbers yield expected behavior，实际含义是 source value 能由目标类型表示；不能只凭主观上的“看起来不大”判断。[课件: 02-03-bits-ints.pptx p.33]

1. **问：5-bit `10011₂` 为什么是 -13，截成 4 bits 后为什么是 +3？**  
   **答：**source 为 $-16+2+1=-13$；截断保留 `0011₂`，新 sign bit 为 0，目标为 $2+1=3$。[01:09:12–01:10:05]

2. **问：怎样用 modulo 路径复核 `-13 → 3`？**  
   **答：**先在 5 bits 中做 T2U：$-13+32=19$；再算 $19\bmod16=3$；最后按 4-bit two’s complement 解释 3，仍为 3。[01:09:42–01:10:05]

3. **问：为什么 signed truncation 可能改变正负号？**  
   **答：**source sign bit 是 bit $w-1$，target sign bit 是保留下来的 bit $k-1$；二者可能不同，丢高位后 target 会按新的负权重重新解释。[01:10:18–01:10:34] [课件: 02-03-bits-ints.pptx p.33]

4. **问：判断 truncation 是否保持数值，最可靠的步骤是什么？**
