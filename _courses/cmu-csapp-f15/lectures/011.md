## 本讲概览

### 学习目标

完成本讲后，应能：

1. 从“线性字节数组”抽象下钻到 SRAM、DRAM、nonvolatile memory、rotating disk、SSD 及总线/I/O controller，说明速度、容量、成本和功耗为何互相制约。[00:00:26–00:07:07] [课件: 11-memory-hierarchy.pptx p.1–6]
2. 追踪 CPU–main-memory 的 load/store transaction，以及 CPU 发起 disk read 后 controller、DMA、main memory、interrupt 的协作路径。[00:07:07–00:11:57] [00:25:08–00:31:42] [课件: 11-memory-hierarchy.pptx p.6–12, p.33–37]
3. 从 disk geometry 推导 capacity，并把一次 sector access 拆为 seek、rotational latency、transfer time，完成 `7,200 RPM` 例题。[00:13:25–00:25:08] [课件: 11-memory-hierarchy.pptx p.14–32]
4. 解释 SSD 的 page/block、先擦后写、FTL、顺序/随机性能与 wear leveling，并识别课堂数字的型号和 2015 年语境边界。[00:31:53–00:37:39] [课件: 11-memory-hierarchy.pptx p.38–40]
5. 从 power wall 和 CPU–storage speed gap 说明 locality 的必要性，区分 temporal/spatial locality，并从 C 数组的 loop order 判断 stride-1、stride-`N` 和三维访问顺序。[00:37:39–00:53:58] [课件: 11-memory-hierarchy.pptx p.41–48]
6. 由硬件成本/速度性质与程序 locality 导出 memory hierarchy，解释相邻层缓存关系、block transfer、hit/miss、placement/replacement，以及 compulsory、capacity、conflict misses。[00:53:58–01:11:25] [课件: 11-memory-hierarchy.pptx p.49–56]
7. 用“缓存什么、存在哪里、latency、由谁管理”统一比较 registers、TLB、L1/L2、virtual memory、OS/file、disk、network 与 browser caches。[01:11:25–01:14:44] [课件: 11-memory-hierarchy.pptx p.57]

### 需要的先修知识

- 能把内存视为按 byte 编址的线性数组，理解 address、word、register file、ALU，以及 x86-64 `movq` 的 load/store 方向。
- 熟悉 C 的 scalar、array、nested loop 和下标表达式；row-major 的具体性能含义由本讲建立。
- 能在 bit/byte、ns/μs/ms、Hz/RPM、十进制 `GB` 之间按题目给定单位换算，并理解对数纵轴表示数量级。
- 理解基本除法、乘积、平均值与取模；不要求预先掌握 cache organization，硬件 cache 的细节留到下一讲。[01:01:37–01:01:50] [01:11:19–01:11:25]

### 老师的教学主线

1. **先拆抽象**：内存不是一块均匀设备，而是对复杂存储系统提供的线性地址抽象。[00:00:33–00:02:15]
2. **再建立器件约束**：SRAM 快而贵，DRAM 大而慢；disk 容量大但机械延迟高；SSD 去掉机械部件却保留擦除、寿命和成本权衡。[00:02:18–00:37:39]
3. **把约束画成鸿沟**：CPU 曾快速提频，2003 年撞上 power wall 后转向多核；SRAM 大体跟随 CPU，DRAM/SSD/disk 访问时间却远落后。[00:37:39–00:44:05]
4. **转向程序性质**：程序倾向于近期重用同一地址或邻近地址；一维和多维数组把 locality 变成可从代码检查的具体访问顺序。[00:44:05–00:53:58]
5. **合成设计**：快设备贵且小、速度 gap 扩大、程序有 locality，三者共同导出 memory hierarchy。[00:53:58–00:55:02]
6. **抽象成 cache**：每个较快的 `L_k` 缓存较慢的 `L_{k+1}`；数据按 block 搬运，请求产生 hit 或 miss，miss 再按原因分类。[00:55:02–01:11:25]
7. **证明其普适性**：从 compiler 管理的 registers 到 browser 管理的 local-disk cache，管理者和 transfer unit 会变，但 locality、staging、reuse 的原则不变。[01:11:25–01:15:34.100]

### 核心概念与依赖关系

```text
存储技术的速度/容量/成本/功耗约束
                    +
CPU 与 DRAM/SSD/disk 的速度鸿沟
                    +
程序的 temporal / spatial locality
                    ↓
             Memory hierarchy
                    ↓
L_k 缓存 L_{k+1} 的数据子集，按 block 搬运
                    ↓
hit：由快层服务；miss：访问慢层并 placement/replacement
                    ↓
cold / capacity / conflict miss 与具体管理机制
```

- Device geometry 决定 raw latency；logical blocks、FTL、bus interface、DMA 等 abstraction/indirection 隐藏物理细节，但不会消除底层延迟。[00:20:31–00:31:42] [00:31:53–00:36:36]
- Locality 是 cache 有效的前提；working set 与 cache capacity 决定能否保留重用对象，placement restriction 又可能在总容量足够时制造 conflict。[01:00:14–01:11:19]
- “上层更快”与“下层更大、更便宜”必须同时成立，层次结构才有机会接近顶层速度与底层成本/容量；这是总体效果，不是每次请求必然 hit 的保证。[00:55:02–01:01:37]

### 关键推导、例子与结论边界

1. **Disk capacity**：[课件: 11-memory-hierarchy.pptx p.18]

   $$
   \text{Capacity}=(\text{bytes/sector})(\text{avg sectors/track})
   (\text{tracks/surface})(\text{surfaces/platter})(\text{platters/disk}).
   $$

   课堂例子得到 `30,720,000,000 bytes = 30.72 GB`，其中厂商单位严格采用 `1 GB = 10^9 bytes`。

2. **Disk access time**：[课件: 11-memory-hierarchy.pptx p.31–32]

   $$
   T_{access}=T_{avg\ seek}+T_{avg\ rotation}+T_{avg\ transfer}.
   $$

   `7,200 RPM`、`9 ms` seek、`400 sectors/track` 给出课件取整值 `4 ms + 0.02 ms + 9 ms = 13.02 ms`；结论是 seek 与 rotation 主导，不是 transfer 真正为零。

3. **CPU effective cycle trend**：[课件: 11-memory-hierarchy.pptx p.66]

   $$
   T_{effective}=\frac{T_{cycle}}{N_{cores}}.
   $$

   这是老师用于历史趋势图的有效工作量指标，不保证任意程序随 core 数线性加速。

4. **Locality examples**：一维 `a[i]` 是 stride-1；C row-major 二维数组中，inner `j` 得 stride-1，inner `i` 得 stride-`N`；对 `a[k][i][j]`，从 outer 到 inner 应排 `k–i–j`。[00:46:27–00:53:58] [课件: 11-memory-hierarchy.pptx p.45–48]

5. **Miss boundaries**：`|working set| > cache capacity` 是 capacity miss 的条件；4-slot cache 用 `slot(i)=i mod 4` 时，0、4、8 都争 slot 0，`|W|=3≤4` 仍反复 miss，因此属于 conflict。[01:07:16–01:11:19] [课件: 11-memory-hierarchy.pptx p.56]

6. **模型边界**：总线图是信息流 abstraction，不是现代芯片的字面布线；disk 例题暂设 logical block 与 sector 的简单关系；SSD 性能来自 Intel SSD 730；L1/L2 latency 来自课堂 Core i7 示例；课件 p.59–66 是 supplemental，不属于 01:15:34.100 前的逐页口述主线。

### 易错点与待复核

- SRAM/DRAM 的 refresh 与 EDC 不可按有歧义的 ASR 互换，应以课件 p.4 表格为准。[需回听 00:03:21]
- Disk 厂商 `GB` 是十进制；sector 是 `512 bytes` 而非老师口误后更正前的 `512 bits`。[00:13:51–00:15:28]
- “First bit 最贵，rest free”是数量级概括；transfer time 仍为非零。[00:23:48–00:24:26]
- DMA 是 controller 直接把数据送入 main memory，CPU 不逐 word 搬运；interrupt 负责完成通知。[00:29:58–00:31:42]
- Flash page、flash block、logical disk block 是不同单位；课件/口述中的 page size 范围本身有疑点，不能用外部常识静默修正。[需回听 00:33:04]
- Temporal locality、spatial locality 要分别检查 data 与 instructions；多维数组必须把 row-major layout 与 inner-loop index 一起判断。[00:44:41–00:53:58]
- `L0` 在层次最上方；cache warming、capacity miss、conflict miss 分别来自初始为空、working set 装不下、受限映射冲突。[01:00:00–01:11:19]
- 全讲所有未决 ASR/材料差异均保留为 `[需回听 HH:MM:SS]`，逐项列在各段“待核对项”中，没有以外部资料替换课堂证据。

- 给定 block trace、cache capacity 与 placement rule，能逐项判断 hit/miss，并区分 compulsory、capacity、conflict 原因。
- 能任选 register、L1、OS buffer、browser cache，按 what/where/latency/manager 四维解释为何它属于同一个 caching abstraction。

# 第 1 段：从内存抽象到总线读事务

> 时间范围：00:00:00–00:10:00  
> 对应课件：11-memory-hierarchy.pptx p.1–9

## 本段在整讲中的作用

老师先把此前汇编课中的“内存是可按地址索引的巨大字节数组”定位为程序员看到的抽象，再揭示实现这个抽象的其实是一组复杂、分层的设备。本讲要解释两件事：内存层次如何构成，以及为什么必须这样构成。老师给出的整讲路线是先看存储技术及其性能限制，再看程序的局部性，最后说明两者如何共同导出 memory hierarchy；本段完成第一步的开场，并从 RAM、非易失存储一路讲到 CPU 发起一次内存读所经过的总线结构。[00:00:26–00:02:15] [课件: 11-memory-hierarchy.pptx p.1–2]

## 教学展开

### 1. 从“字节数组”抽象转向真实存储系统

- 此前分析汇编程序时，可以把内存当成一个大字节数组，地址就是数组索引；老师现在追问：这个大而线性的地址空间在机器里究竟怎样实现？答案不是单一设备，而是复杂的设备层次。[00:00:33–00:01:05]
- 设计动机来自两组性质的汇合：一组是存储设备在速度、容量、成本上的物理/技术性质，另一组是程序访问数据与指令的规律。老师把这种汇合称为 memory hierarchy 的设计基础。[00:01:08–00:01:28]
- 教学顺序因此是：高层巡览 storage technologies and trends，理解限制性能与速度的基本因素；随后引入 locality of reference；最后把两者合在一起解释层次化存储。[00:01:28–00:02:15] [课件: 11-memory-hierarchy.pptx p.2]

### 2. RAM 的组织单位与两种实现

- RAM（random-access memory）通常封装为芯片，多个 RAM 芯片组合成一套内存；基本存储单位是 cell，每个 cell 存 1 bit。[00:02:18–00:02:37] [课件: 11-memory-hierarchy.pptx p.3]
- RAM 分 SRAM（static RAM）和 DRAM（dynamic RAM），区分点是 cell 的实现。老师先从复杂度推成本：SRAM 每 bit 约需 4 或 6 个晶体管，DRAM 每 bit 约需 1 个，因此 SRAM cell 更复杂、成本更高。[00:02:37–00:03:13] [课件: 11-memory-hierarchy.pptx p.4]
- 再从实现推性能与用途：课件把 SRAM 访问时间记为基准 `1X`，DRAM 为 `10X`；SRAM 成本约为 DRAM 的 `100X`。SRAM 更快、更贵、可做得较小，所以用于 cache memories；DRAM 较慢、较便宜、容量可更大，所以用于 main memories 和 graphics frame buffers。[00:03:13–00:04:18] [课件: 11-memory-hierarchy.pptx p.4]
- 可靠性与维护方面，课件明确列出 SRAM 不需要 refresh、可能需要 EDC（error detection and correction），DRAM 需要 refresh 且需要 EDC。口述字幕在此发生自相矛盾，不能用字幕静默覆盖表格结论。[需回听 00:03:21] [课件: 11-memory-hierarchy.pptx p.4]

### 3. 从易失 RAM 转到非易失存储

- SRAM 与 DRAM 都是 volatile：掉电即丢失内容。因此关机后内存内容消失，重新开机时必须从磁盘重新装入程序与数据。[00:04:24–00:04:44] [课件: 11-memory-hierarchy.pptx p.5]
- Nonvolatile memory 在断电后仍保留值。老师以 ROM 家族的演变说明“可编程、可擦除”的能力逐步增强：最初的 ROM 在生产时一次写定；课件还依次列出 PROM（可编程一次）、EPROM（可用 UV/X-Ray 整体擦除）、EEPROM（电擦除），以及可按 block 局部擦除的 flash memory。[00:04:44–00:05:42] [课件: 11-memory-hierarchy.pptx p.5]
- Flash 的限制是擦除寿命：约 `100,000` 次擦除后会磨损。老师用“erase and reprogram 100,000 times”强调它不是无限可写。[00:05:34–00:05:59] [课件: 11-memory-hierarchy.pptx p.5]
- 非易失存储的用途按老师顺序展开：固件是写在 ROM 中的软件；计算机上电后最先执行的 BIOS 指令来自 ROM，随后启动过程才逐步把更多指令和数据装入内存；I/O 设备中的 controller 也带有存于 ROM 的指令和数据；SSD 则以 flash 构成、对系统呈现为旋转磁盘，应用于 U 盘、手机、平板、笔记本，并开始进入服务器。[00:05:59–00:07:07] [课件: 11-memory-hierarchy.pptx p.5]

### 4. CPU、内存与总线抽象

- Memory 与 CPU 通过统称为 bus 的导线连接。课件定义 bus 为一组并行导线，承载 address、data 和 control signals，且通常由多个设备共享。[00:07:07–00:07:22] [课件: 11-memory-hierarchy.pptx p.6]
- CPU chip 内，register file 保存 `%rax`、`%rdi` 等通用寄存器；ALU 从寄存器文件读写数据并执行算术或逻辑操作。若 `mov` 指令需要访问内存，则经 bus interface 进入 system bus，再经 I/O bridge 进入 memory bus，最后到 main memory。[00:07:22–00:08:36] [课件: 11-memory-hierarchy.pptx p.6]
- 老师明确警告这只是信息流抽象，不应把图当成现代系统的字面布线。Intel 把此处抽象为 I/O bridge 的芯片集合称为 chipset；真实现代专有总线设计更复杂，本课暂用简化模型。[00:08:16–00:08:57] [课件: 11-memory-hierarchy.pptx p.6]

### 5. `movq A, %rax` 的读事务

- 老师把“从 CPU 的视角把内存数据装入 CPU”称为 load。例子 `movq A, %rax` 要把地址 `A` 处的 8 bytes 装入 `%rax`。[00:09:05–00:09:25] [课件: 11-memory-hierarchy.pptx p.7]
- 第一步：CPU 把地址 `A` 放到总线上，main memory 感知并读取这个地址。[00:09:25–00:09:40] [课件: 11-memory-hierarchy.pptx p.7]
- 第二步：main memory 取出地址 `A` 处的 8-byte word `x`，把 `x` 放回总线；这些 bit 经 I/O bridge 到达 bus interface。[00:09:40–00:09:53] [课件: 11-memory-hierarchy.pptx p.8]
- 第三步“CPU 从总线读取 `x` 并复制到 `%rax`”在课件 p.9 给出，但口述落在下一段开头 00:10:00，本段在这里留下事务边界，下一段接续。[课件: 11-memory-hierarchy.pptx p.9]

## 概念、符号与推导

### 存储技术对照

| 项目 | SRAM | DRAM |
|---|---:|---:|
| 每 bit 晶体管数 | 4 或 6 | 1 |
| 相对访问时间 | `1X` | `10X` |
| 是否 refresh | No | Yes |
| 是否需要 EDC | Maybe | Yes |
| 相对成本 | `100X` | `1X` |
| 主要用途 | cache memories | main memories、frame buffers |

表中数量均来自课件 p.4；老师据此建立的因果链是：cell 更复杂 → 每 bit 成本更高，但访问更快 → SRAM 适合小而快的 cache；DRAM 适合容量较大的主存。[00:02:41–00:04:18] [课件: 11-memory-hierarchy.pptx p.4]

### 读事务中的符号

- `A`：要读取的主存地址。
- `x`：主存从 `A` 取出的 8-byte word。
- `%rax`：load 的目标寄存器。
- 数据路径：`CPU/address A → system bus → I/O bridge → memory bus → main memory`，返回时 `main memory/word x → memory bus → I/O bridge → system bus/bus interface → %rax`。[00:07:52–00:09:53] [课件: 11-memory-hierarchy.pptx p.6–9]

本段没有代数公式推导；数量关系是 SRAM/DRAM 的相对时间、成本、晶体管数，以及 flash 约 `100,000` 次擦除寿命。

## 例子与课堂提示

- **上电启动例子**：老师问“第一条指令从哪里来”，用 BIOS 固件存在 ROM 中解释掉电后仍可启动；它服务于 volatile 与 nonvolatile 的区别。[00:05:59–00:06:30] [课件: 11-memory-hierarchy.pptx p.5]

## 易错点

# 第 2 段：主存访问代价与磁盘容量

> 时间范围：00:10:00–00:19:58  
> 对应课件：11-memory-hierarchy.pptx p.9–20

## 本段在整讲中的作用

本段先补完上一段的 load，并用 store 对称地展示一次主存写事务，由总线上的多步传输推出第一个性能结论：片上寄存器操作与片外主存访问之间已有一到两个数量级的差距。老师随后沿“设备构造 → 几何组织 → 容量因素 → 容量公式 → 机械动作”的顺序引入旋转磁盘，为下一段计算其访问时间做准备。[00:10:00–00:12:04] [课件: 11-memory-hierarchy.pptx p.9–13]

## 教学展开

### 1. 补完主存读，并对称讲解主存写

- 上一段的 `movq A, %rax` 在这里完成最后一步：CPU 从总线读出 data word `x`，复制到 `%rax`。[00:10:00–00:10:06] [课件: 11-memory-hierarchy.pptx p.9]
- 写事务例子是 `movq %rax, A`，即把 `%rax` 中的 8-byte word `y` 写到主存地址 `A`。[00:10:07–00:10:21] [课件: 11-memory-hierarchy.pptx p.10–12]
- 第一步，CPU 把地址 `A` 放到总线上；main memory 读到地址后等待对应数据到来。[00:10:22–00:10:32] [课件: 11-memory-hierarchy.pptx p.10]
- 第二步，CPU 把 `%rax` 的内容 `y` 放到总线上。[00:10:32–00:10:37] [课件: 11-memory-hierarchy.pptx p.11]
- 第三步，`y` 沿总线到达 main memory，主存读出该 word 并存到地址 `A`。[00:10:37–00:10:45] [课件: 11-memory-hierarchy.pptx p.12]

### 2. 由事务步骤推出片上/片外延迟差距

- Register file 紧邻 ALU，寄存器读写只需若干 cycle；主存却是相对远离 CPU 的芯片集合，读写要经历多个 bus operation，还要等待信号在总线上传播。[00:10:45–00:11:31]
- 老师给出的数量级是：memory read/write 约 `50–100 ns`，register 之间的操作低于 `1 ns`，因此 off-chip 取数会带来约 `1–2` 个数量级的差距。这是本讲关于内存系统的第一个“大结论”。[00:11:31–00:12:04]

### 3. 旋转磁盘为何天然更慢

- 磁盘由若干 platter 构成，表面有磁性材料，以磁场变化编码 bit。Arm 绕支点移动并悬浮在盘片上方的薄空气层上，末端的 read/write head 感知磁场变化；盘片旋转、arm 径向来回移动。[00:12:04–00:12:53] [课件: 11-memory-hierarchy.pptx p.13]
- 这些动作是机械动作，所以老师直接预告 rotating disk 会比 SRAM、DRAM 慢。与此同时，磁盘内部也有 electronics，包括 processor 和 memory；其中 firmware/controller 控制 arm 移动和数据读取，磁盘本身可视作一台小计算机。[00:12:53–00:13:25] [课件: 11-memory-hierarchy.pptx p.13]

### 4. 从盘片到柱面的几何组织

- 每个 platter 有上下两个 surface；每个 surface 是一组同心 track；每条 track 再分为存数据的 sector，sector 之间由不存数据的 gap 隔开。[00:13:25–00:14:09] [课件: 11-memory-hierarchy.pptx p.14]
- 老师先口误说 sector 通常为 `512 bits`，随即更正为 `512 bytes`。[00:13:51–00:14:00] [课件: 11-memory-hierarchy.pptx p.18]
- 多张 platter 沿 spindle 叠放；不同 surface 上径向位置对齐的一组 track 形成一个 cylinder，因为这些 track 在空间中构成圆柱形。[00:14:09–00:14:31] [课件: 11-memory-hierarchy.pptx p.15]

### 5. 容量、密度与厂商 GB

- Capacity 是能存储的最大 bit 数。磁盘厂商使用十进制单位：`1 GB = 10^9 bytes`。老师提醒这会让标称数值看起来更大，是使用磁盘规格时必须适应的单位约定。[00:14:31–00:15:28] [课件: 11-memory-hierarchy.pptx p.16]
- Recording density，单位 `bits/in`：一英寸 track 片段中能挤入多少 bit；track density，单位 `tracks/in`：一英寸径向片段中能挤入多少 track。[00:15:28–00:15:58] [课件: 11-memory-hierarchy.pptx p.16]
- Areal density，单位 `bits/in²`，是 recording density 与 track density 的乘积；面密度越高，同一 surface 能容纳的 bit 越多。[00:15:58–00:16:07] [课件: 11-memory-hierarchy.pptx p.16]

### 6. Recording zones 解决外圈空间浪费

- 早期面密度较低时，每条 track 可使用相同 sector 数；但越靠外的 track 周长越大，若 sector 数仍相同，sector 间空隙会越来越大，外圈空间被浪费。[00:16:07–00:17:01]
- 现代磁盘把 tracks 分成互不相交的 recording zones。一个 zone 内每条 track 的 sector 数相同，由该 zone 最内侧 track 的周长决定；切换到更外层 zone 时，sectors/track 增加，因此 outer zones 比 inner zones 每轨容纳更多 sector。[00:17:01–00:17:54] [课件: 11-memory-hierarchy.pptx p.17]
- 因为整个盘面的 sectors/track 不再是常数，估算总容量时使用跨 zones 的平均 sectors/track。[00:17:54–00:18:11] [课件: 11-memory-hierarchy.pptx p.17]

### 7. 容量公式与示例

老师按物理组织逐层相乘：[00:18:11–00:18:32] [课件: 11-memory-hierarchy.pptx p.18]

$$
\text{Capacity}=
(\text{bytes/sector})
(\text{avg sectors/track})
(\text{tracks/surface})
(\text{surfaces/platter})
(\text{platters/disk})
$$

这里相邻括号表示乘法。课件示例代入：

$$
512\times 300\times 20{,}000\times 2\times 5
=30{,}720{,}000{,}000\ \text{bytes}
=30.72\ \text{GB}.
$$

逐层看：每轨 `512×300 = 153,600 bytes`；每面 `153,600×20,000 = 3,072,000,000 bytes`；每盘片双面为 `6,144,000,000 bytes`；5 张盘片共 `30,720,000,000 bytes`。最后用厂商定义 `10^9 bytes/GB` 得 `30.72 GB`。[课件: 11-memory-hierarchy.pptx p.16, p.18]

### 8. 磁盘运行的两个机械自由度

- Surface 以固定 rotational rate 转动，老师给出的常见值为 `7,200 RPM`；动画展示盘片逆时针旋转，arm 沿半径移动到任意 track。[00:18:36–00:19:15] [课件: 11-memory-hierarchy.pptx p.19]
- 多盘片磁盘在每个已用 surface 上有 read/write head，多个 arm/head 相连并一起从 cylinder 移到 cylinder。老师开始比较早期固定 head 与现代高 track density 下的精细对齐，本段结束时尚未讲完，下一段接续。[00:19:21–00:19:58] [课件: 11-memory-hierarchy.pptx p.20]

## 概念、符号与推导

- **Load**：从 CPU 视角把主存数据装入寄存器；例为 `movq A, %rax`。
- **Store**：从 CPU 视角把寄存器数据写入主存；例为 `movq %rax, A`。
- **Platter / surface / track / sector / gap / cylinder**：容量公式所依赖的逐层几何单位；cylinder 是跨 surface 对齐的 tracks 集合。[课件: 11-memory-hierarchy.pptx p.13–15]
- **Recording density** 与 **track density** 是两个独立技术因素，`areal density = recording density × track density`。[00:15:28–00:16:07] [课件: 11-memory-hierarchy.pptx p.16]
- **Capacity** 由每 sector 字节数、平均每 track sector 数、每 surface track 数、每 platter surface 数、每 disk platter 数连乘；示例推到 `30.72 GB`。[课件: 11-memory-hierarchy.pptx p.18]

## 例子与课堂提示

- **地址和数据分两步走**：store 先发送 `A`、再发送 `y`，用来解释一次“内存写”为什么不是寄存器文件内部那样的单一快速动作。[00:10:22–00:10:45]
- **空气层上的磁头**：read/write head 不直接摩擦盘面，而是浮在薄空气层上；该细节服务于理解磁盘依赖精密机械运动。[00:12:25–00:12:46]
- **老师现场更正单位**：sector 是 `512 bytes`，不是 `512 bits`；容量计算若错 8 倍，通常就是漏听了这个更正。[00:13:51–00:14:00]
- **Recording-zone 反例**：所有 track 固定相同 sector 数会让外圈 gap 变大，说明容量不能只按“轨道数量”推，还要考虑周长利用率。[00:16:16–00:17:54]
- **动画提示**：固定转速与径向移动是下一段 seek、rotational latency、transfer time 三项延迟的物理来源。[00:18:36–00:19:21]

## 易错点

- `50–100 ns` 是老师对主存操作的典型量级描述，不是本段某一型号的严格常数；结论重点是相对 sub-nanosecond 寄存器操作的 `1–2` 个数量级差距。[00:11:31–00:11:57]
- 厂商 `GB` 在本段严格按 `10^9 bytes`，不能在 `30.72 GB` 这道课件例题中改用二进制除数。[课件: 11-memory-hierarchy.pptx p.16, p.18]
- Cylinder 不是一条 track，也不是整张 platter；它是多个 surface 上对齐 tracks 的集合。[00:14:09–00:14:29]
- Recording zone 内 sectors/track 相同，但不同 zone 之间不同；容量式因此用平均 sectors/track。[课件: 11-memory-hierarchy.pptx p.17–18]

# 第 3 段：磁盘访问时间、逻辑块与 I/O 读请求

> 时间范围：00:19:58–00:29:58  
> 对应课件：11-memory-hierarchy.pptx p.20–36

## 本段在整讲中的作用

上一段已给出磁盘几何与机械动作，本段把动作转换成可计算的性能模型：用蓝、红 sector 的读取动画拆出 seek、rotational latency、data transfer，再用 `7,200 RPM` 的实例算出总访问时间并与 SRAM/DRAM 对比。随后老师从复杂物理几何抽象到 logical blocks，再把磁盘接入 I/O bus，开始追踪“CPU 请求一个 sector”在系统中的控制与数据路径。[00:19:58–00:29:58] [课件: 11-memory-hierarchy.pptx p.20–36]

## 教学展开

### 1. 高密度磁盘上的磁头对齐

- 早期 track density 较低，即便不同 surfaces 上的 tracks 不完全对齐，刚性连接的 heads 仍能覆盖它们；现代密度更高，controller 可对 read/write heads 做细微移动，使其与各 surface 的 tracks 对齐。[00:19:58–00:20:26] [课件: 11-memory-hierarchy.pptx p.20]

### 2. 从蓝 sector 到红 sector：三段服务时间

- 动画先把 head 放在某 track 上，盘片逆时针旋转；蓝 sector 即将经过 head。蓝 sector 转到 head 下方时，head 感知 bits，交给 controller，再向 CPU 返回。[00:20:31–00:21:03] [课件: 11-memory-hierarchy.pptx p.21–25]
- CPU 随后请求红 sector。Controller 先把 head 移到红 sector 所在 track，这一步是 **seek**；再等待红 sector 随盘片转到 head 下方，这一步是 **rotational latency**；最后让整个红 sector 经过 head 并读出 bits，这一步是 **data transfer**。[00:21:03–00:22:16] [课件: 11-memory-hierarchy.pptx p.26–30]
- 三项相加得到访问目标 sector 的平均时间。Seek 涉及 servo 和真实机械移动，典型平均值约 `3–9 ms`，且数十年来很难下降；老师把这归因于基本机械限制。[00:22:16–00:23:04] [课件: 11-memory-hierarchy.pptx p.31]

### 3. 平均访问时间模型

总式为：[00:22:16–00:23:29] [课件: 11-memory-hierarchy.pptx p.31]

$$
T_{access}=T_{avg\ seek}+T_{avg\ rotation}+T_{avg\ transfer}.
$$

- `T_avg seek`：把 heads 定位到目标 sector 所在 cylinder 的平均时间。
- `T_avg rotation`：等待目标 sector 第一 bit 转到 read/write head 下方的平均时间。若起始相位随机，平均等待半圈：

$$
T_{avg\ rotation}=\frac{1}{2}\times\frac{60}{RPM}\ \text{seconds}.
$$

- `T_avg transfer`：读完一个 sector 的 bits 所需时间；若平均每轨有 `S` 个 sectors：

$$
T_{avg\ transfer}=\frac{60}{RPM}\times\frac{1}{S}\ \text{seconds}.
$$

### 4. `7,200 RPM` 示例逐步推导

已知 rotational rate `7,200 RPM`、average seek time `9 ms`、平均 `400 sectors/track`。[00:23:29–00:24:00] [课件: 11-memory-hierarchy.pptx p.32]

1. 一整圈时间：

   $$
   \frac{60\ \text{s}}{7200}=\frac{1}{120}\ \text{s}=8.333\ldots\ \text{ms}.
   $$

2. 平均旋转等待是半圈：

   $$
   T_{avg\ rotation}=\frac{1}{2}\times 8.333\ldots=4.166\ldots\ \text{ms}
   \approx 4\ \text{ms}.
   $$

3. 一个 sector 占一圈的 `1/400`：

   $$
   T_{avg\ transfer}=\frac{8.333\ldots}{400}=0.020833\ldots\ \text{ms}
   \approx 0.02\ \text{ms}.
   $$

4. 按课件先取整后的数字：

   $$
   T_{access}=9+4+0.02=13.02\ \text{ms}.
   $$

   若直到最后才取整，则为约 `13.19 ms`；课堂课件采用前一种早取整表达 `9 ms + 4 ms + 0.02 ms`。[课件: 11-memory-hierarchy.pptx p.32]

- 结论不是 transfer 完全为零，而是 `0.02 ms` 相比 seek 与 rotation 小得多，所以访问时间由 seek 和 rotational latency 主导。“First bit in a sector is the most expensive, the rest are free”是这种数量级关系的口语化总结。[00:23:48–00:24:26] [课件: 11-memory-hierarchy.pptx p.32]
- 老师给出粗略估算规则：把 seek time 乘 2，通常可估出磁盘读的量级；这是经验近似，不替代三项公式。[00:24:00–00:24:20]

### 5. 与 SRAM、DRAM 的性能鸿沟

- 课件列出 SRAM 约 `4 ns/doubleword`、DRAM 约 `60 ns`，并直接给出“disk about `40,000×` slower than SRAM、`2,500×` slower than DRAM”的结论。[00:24:26–00:25:08] [课件: 11-memory-hierarchy.pptx p.32]
- 老师借此强调：SRAM 与 DRAM 已相差约一个数量级，而 disk 与两种 memory 之间还有更巨大的断层。课件没有在该页展开两个倍数采用何种单位归一化，因此应把它们视为课件给定的比较结论，不能仅拿整 sector 的 `13.02 ms` 直接除以一个 doubleword 延迟。[课件: 11-memory-hierarchy.pptx p.32]

### 6. 用 logical blocks 隐藏物理几何

- 现代磁盘不把 track/cylinder/sector 的复杂布局直接暴露给 CPU，而把可用 sectors 建模成编号 `0,1,2,...`、每个大小为 `b` 的 logical blocks；最简单模型可把一个 logical block 看成一个 sector。[00:25:08–00:25:53] [课件: 11-memory-hierarchy.pptx p.33]
- Disk controller 维护 logical block 到物理 `(surface, track, sector)` triple 的映射。老师把这称为 indirection：上层只用线性编号，controller 负责实际位置。[00:25:53–00:26:17] [课件: 11-memory-hierarchy.pptx p.33]
- 这层间接映射允许 controller 为每个 zone 留出 spare cylinders；若 sector 损坏，可把内容迁到 spare cylinder 并更新映射。预留空间也解释了 formatted capacity 小于按全部物理位置计算的 maximum capacity。[00:26:17–00:26:53] [课件: 11-memory-hierarchy.pptx p.33]

### 7. I/O bus：从旧 PCI 抽象到 PCI Express

- Disk controller、graphics adapter、USB controller 等经 I/O bridge 接到 I/O bus；mouse/keyboard 接 USB controller，monitor 接 graphics adapter，expansion slots 可接 network adapter。[00:26:53–00:29:10] [课件: 11-memory-hierarchy.pptx p.34]
- 图示更接近当时较早的 PCI broadcast bus：一组共享导线中任一设备改变值，所有设备都能看到。老师明确说现代系统用 PCI Express，它虽沿用 PCI 名称，却是经 switch 仲裁的 point-to-point connections；实现更高效、更快，但在本课抽象中仍承担“把设备接到 CPU”的同一功能。[00:27:07–00:28:20] [课件: 11-memory-hierarchy.pptx p.34]

### 8. CPU 发起 disk read

- CPU 向 disk controller 对应的 port/address 写入三个值：`command`（如 read）、`logical block number`、`destination memory address`。[00:29:10–00:29:43] [课件: 11-memory-hierarchy.pptx p.35]
- Controller 找出该 logical block 对应的 sector 并读取它；课堂暂设一个 logical block 等于一个 sector。随后 controller 将执行一种“有意思”的传输，具体 DMA 动作在下一段从 00:29:58 继续。[00:29:43–00:29:58] [课件: 11-memory-hierarchy.pptx p.36]

## 概念、符号与推导

- **Seek**：head 跨 track/cylinder 定位；典型平均 `3–9 ms`。
- **Rotational latency**：等待目标第一 bit 转到 head；平均半圈。
- **Transfer time**：sector 本身经过 head 的时间；一轨平均 `S` 个 sectors 时是一圈时间的 `1/S`。
- **Logical block**：CPU 所见的线性磁盘单位；disk controller 映射到 `(surface, track, sector)`。
- **Broadcast bus / point-to-point bus**：旧 PCI 抽象为所有设备共享一组导线；PCI Express 使用 switch 仲裁的点到点连接。[00:27:20–00:28:14]
- 本段完整数量推导为 `7,200 RPM, 9 ms seek, 400 sectors/track → 4 ms rotation, 0.02 ms transfer, 13.02 ms access`（按课件取整）。[课件: 11-memory-hierarchy.pptx p.32]

## 例子与课堂提示

- **蓝/红 sector 动画**：把“磁盘很慢”拆成可观察动作，服务于三项时间模型，而不是只背一个总延迟。[00:20:31–00:22:16] [课件: 11-memory-hierarchy.pptx p.21–30]
- **First bit 最贵**：一旦 seek 和 rotation 已完成，连续读完 sector 的增量成本很小；它为后面“顺序访问通常更好”埋下伏笔。[00:23:48–00:24:26] [课件: 11-memory-hierarchy.pptx p.32]
- **Indirection 的用途**：logical block 不只是让接口好看，还使坏 sector 可重映射到 spare cylinder。[00:25:53–00:26:49]
- **总线图不是现代机器的字面图**：老师主动区分 PCI 与 PCI Express，要求把图理解为功能模型。[00:27:07–00:28:20]

## 易错点

- Rotational latency 是“等目标第一 bit 到达”的时间；transfer time 才是“读完 sector”的时间。[课件: 11-memory-hierarchy.pptx p.31]
- 平均 rotation 乘 `1/2`，transfer 则乘 `1/(sectors/track)`；二者不能共用同一个分母。[课件: 11-memory-hierarchy.pptx p.31]
- `13.02 ms` 使用课件已经取整的 `4 ms` 和 `0.02 ms`；保留原始小数会得到约 `13.19 ms`，两者差异来自取整时点，不是两个模型。
- Logical block 与物理 sector 不是天然一一固定；映射由 controller 维护，课堂只为简化暂设一 block 一 sector。[00:25:32–00:26:17]
- PCI Express 不是课件图中 broadcast PCI 的简单提速版；老师明确说其连接结构“completely different”。[00:27:20–00:28:07]

1. **问：读取红 sector 的三项服务时间分别对应什么机械/数据动作？**  
   **答：** 移 head 到目标 track 是 seek；等红 sector 转到 head 是 rotational latency；红 sector 经过 head并读出是 data transfer。[00:21:03–00:22:16]
2. **问：`7,200 RPM` 时平均 rotational latency 如何得到约 `4 ms`？**  
   **答：** 一圈 `60/7200 s = 8.333 ms`，随机位置平均等半圈，所以 `8.333/2 ≈ 4.167 ms`，课件取整为 `4 ms`。[课件: 11-memory-hierarchy.pptx p.31–32]
3. **问：给定 `400 sectors/track`，为什么 transfer time 约为 `0.02 ms`？**  
   **答：** 一个 sector 占一圈的 `1/400`，所以 `8.333 ms/400 ≈ 0.0208 ms`，课件取 `0.02 ms`。[课件: 11-memory-hierarchy.pptx p.32]
4. **问：logical block 这层 indirection 带来哪两个直接好处？**  
   **答：** 对 CPU 隐藏物理 `(surface,track,sector)` 几何；允许 controller 预留 spare cylinders 并重映射坏 sector，也导致 formatted capacity 低于 maximum capacity。[00:25:08–00:26:49]
5. **问：CPU 发起磁盘读时写给 controller 的 triple 是什么？**  
   **答：** Command、logical block number、destination memory address。[00:29:10–00:29:43] [课件: 11-memory-hierarchy.pptx p.35]

# 第 4 段：DMA、SSD 与 CPU–存储差距的形成

> 时间范围：00:29:58–00:39:54  
> 对应课件：11-memory-hierarchy.pptx p.36–41；趋势数据补充见 p.65–66

## 本段在整讲中的作用

本段先补完“读取一个磁盘 sector”的系统路径：disk controller 用 DMA 绕过 CPU 把数据直接送入主存，再以 interrupt 通知完成，从而让 CPU 不必同步等待毫秒级磁盘。随后老师引入位于 DRAM 与旋转磁盘之间的 SSD，沿物理组织、写入限制、性能数字与成本/寿命权衡完整展开。最后把 SRAM、DRAM、SSD、disk 与 CPU 放到 1985–2015 的对数时间图上，开始说明为什么单靠改进器件不能消除 CPU–memory gap。[00:29:58–00:39:54] [课件: 11-memory-hierarchy.pptx p.36–41]

## 教学展开

### 1. DMA：controller 直接把 sector 搬到主存

- 上一段中 CPU 已把 `command + logical block number + destination memory address` 写给 disk controller。Controller 读到 sector 后取得 I/O bus 的控制权，把数据经 I/O bus、I/O bridge 直接复制到 main memory；传输过程中不需要 CPU 搬运每个 word，CPU 对该数据传送本身“完全不知情”。[00:29:58–00:30:12] [课件: 11-memory-hierarchy.pptx p.36]
- 这就是 direct memory access（DMA）：设备 controller 直接与主存交换数据。DMA 完成后，controller 才以 interrupt 通知 CPU；老师用硬件动作解释 interrupt：controller 改变 CPU 芯片上专用 interrupt pin 的值，例如从 `0` 拉到 `1`。[00:30:23–00:30:45] [课件: 11-memory-hierarchy.pptx p.37]
- 收到通知后，CPU 才恢复/调度等待这批数据的程序，让程序处理已在主存中的内容。[00:30:45–00:31:02]
- 为什么要异步：一次约 `10 ms` 的磁盘操作期间，CPU 可以执行数百万条指令。若 CPU 原地等待，会浪费大量计算；发出请求后去做其他工作、完成时再由 interrupt 唤回，是避免慢磁盘拖住整机的关键机制。[00:31:02–00:31:42]

### 2. SSD 的接口像磁盘，内部却是 flash

- SSD 在系统中的位置大致介于 rotating disk 与 DRAM。对 CPU 而言，它与 rotating disk 有相同 socket、physical interface 和 packaging，呈现同样的 logical disk block 接口；内部没有盘片和磁头，而由 flash memory 与 firmware/controller 构成。[00:31:53–00:32:37] [课件: 11-memory-hierarchy.pptx p.38]
- Firmware 中的 **flash translation layer（FTL）** 扮演类似 rotating-disk controller 的角色：接收 logical disk block 请求，并在 flash 的物理组织上定位、搬移数据。[00:32:37–00:32:57] [课件: 11-memory-hierarchy.pptx p.38]

### 3. Page、flash block 与“先擦后写”

- Flash 以 **page** 为读写单位，若干 page 构成一个 **flash block**。老师特别提醒：这里的 flash block 与 CPU 请求的 logical disk block 是两种不同单位，只是术语碰巧重叠。[00:32:57–00:33:23] [课件: 11-memory-hierarchy.pptx p.38]
- 课件原文写 `Pages: 512KB to 4KB, Blocks: 32 to 128 pages`，口述字幕也给出“512K bytes to 4K bytes”；这个范围顺序/单位可疑，必须原样保留并标记回听，不能按外部常识修正。[需回听 00:33:04] [课件: 11-memory-hierarchy.pptx p.38]
- 核心限制：数据可按 page 读写，但一个 page 只有在它所属的整个 block 已擦除后才能写。若只修改目标 block 的一个 page，FTL 必须找到另一个已擦除 block，把目标 block 中其余 pages 复制过去，再写入新 page；原 block 随后擦除以供将来写入。[00:33:23–00:34:32] [课件: 11-memory-hierarchy.pptx p.38–39]
- 因此 read 可直接进行，而 write 尤其是随机修改可能触发“整块搬家 + 擦除”。Flash block 约经 `100,000` 次反复写入/擦除会磨损。现代 FTL 用 caching 和其他专有算法延长寿命，老师判断实际使用中通常不构成问题。[00:34:07–00:34:58] [课件: 11-memory-hierarchy.pptx p.38, p.40]

### 4. SSD 性能数字与顺序访问优势

- 老师以自己测得的典型 hard drive `40–50 MB/s` 为参照，称课件中的 SSD 约快 `10×`；Intel SSD 730 规格给出的 sequential read throughput 是 `550 MB/s`。[00:35:00–00:35:22] [课件: 11-memory-hierarchy.pptx p.39]
- 课件完整数字如下，老师据此按顺序说明：sequential write 略慢于 sequential read；random read/write 又略慢于 sequential；random write 受 block erase 约 `1 ms` 及其他 pages 搬移影响。[00:35:22–00:36:08] [课件: 11-memory-hierarchy.pptx p.39]

| Intel SSD 730 指标 | 数值 |
|---|---:|
| Sequential read throughput | `550 MB/s` |
| Sequential write throughput | `470 MB/s` |
| Random read throughput | `365 MB/s` |
| Random write throughput | `303 MB/s` |
| Average sequential read time | `50 μs` |
| Average sequential write time | `60 μs` |
| Block erase time | 约 `1 ms` |

- 由表中数值可直接比较：顺序读比顺序写高 `80 MB/s`，约为后者的 `550/470 ≈ 1.17×`；随机读比随机写高 `62 MB/s`，约为后者的 `365/303 ≈ 1.20×`。这些比值只是对课件数字的算术展开，不添加新性能模型。[课件: 11-memory-hierarchy.pptx p.39]
- 老师把“sequential 优于 random”提升为 memory hierarchy 中反复出现的主题：顺着地址处理通常优于到处跳转。早期 SSD 的 read/write 差距更大；FTL 改进已使数字接近，因此本讲建立 SSD 高层模型时“不再需要明显区分 read 与 write”，尽管 write 仍稍慢。[00:35:28–00:36:36] [课件: 11-memory-hierarchy.pptx p.39]

### 5. SSD 相对旋转磁盘的权衡

- **优点**：无 moving parts，所以更快、耗电更少、更抗冲击；这解释了它为何适合 U 盘、便携播放器等移动设备。[00:36:36–00:36:58] [课件: 11-memory-hierarchy.pptx p.40]
- **寿命代价**：有磨损潜力，但 FTL 的 wear leveling logic 缓解它。老师举 Intel 保证值：总写入量达到 `128 PB = 128×10^15 bytes` 前仍在保证范围，并让学生从“要写多少年”理解其实际量级。[00:36:58–00:37:22] [课件: 11-memory-hierarchy.pptx p.40]
- **成本/容量代价**：2015 年 SSD 每 byte 约比 rotating disk 贵 `30×`。所以老师概括为 rotating disk 更大、更慢；SSD 更小、更快。[00:37:22–00:37:39] [课件: 11-memory-hierarchy.pptx p.40]

### 6. CPU–memory gap 图：先看 CPU 到 2003 年的轨迹

- 图的纵轴是 access/cycle time，单位 nanoseconds，使用 log scale；相邻十倍刻度（如 `1,000` 到 `10,000`）代表一个数量级。横轴是年份 `1985–2015`，曲线包括 CPU cycle time、SRAM、DRAM、SSD 与 disk access time。[00:37:39–00:38:38] [课件: 11-memory-hierarchy.pptx p.41]
- CPU cycle time 在 1985–2003 年近似指数下降：clock frequency 约每 `18 个月–2 年` 翻倍，cycle time 相应减半。制造商通过缩小 feature size，使元件更靠近并同比提高 clock frequency。[00:38:38–00:39:37] [课件: 11-memory-hierarchy.pptx p.41, p.66]
- 补充数据页给出该轨迹的代表点：1985 年 80286 为 `6 MHz / 166 ns`；1995 年 Pentium 为 `150 MHz / 6 ns`；2003 年 Pentium 4 为 `3,300 MHz / 0.30 ns`。这些是 p.41 趋势图背后的课件表值。[课件: 11-memory-hierarchy.pptx p.66]
- 这一增长方式在 2003 年结束。老师在本段末提出原因：功耗与 frequency 成正比，frequency 越高，耗电越多；具体 power wall 例子和多核应对留到下一段。[00:39:37–00:39:54]

## 概念、符号与推导

### Disk read 的控制/数据路径

1. CPU 写 `command + logical block number + destination address`。[上一段；课件 p.35]
2. Disk controller 读 sector。[课件 p.36]
3. Controller 取得 bus 控制，以 DMA 把 sector 直接写入 main memory，CPU 不逐 word 参与。[00:29:58–00:30:12]
4. DMA 完成，controller 以 interrupt pin 通知 CPU。[00:30:23–00:30:45]
5. CPU 继续等待该数据的程序。[00:30:45–00:31:02]

### SSD 写放大路径（课堂定性模型）

`修改一个 page → 找已擦除 block → 复制其他 pages → 写目标 page → 擦除旧 block`。[00:33:35–00:34:32]

本段没有给出 SSD 延迟的统一公式；数量推导包括吞吐差值/比值以及 CPU `frequency` 翻倍时 `cycle time` 减半的倒数关系。若以频率 `f` 表示，课上关系可写作：

$$
T_{cycle}=\frac{1}{f};\qquad 2f\Rightarrow \frac{T_{cycle}}{2}.
$$

## 例子与课堂提示

- **`10 ms` 内可执行数百万指令**：服务于 DMA/interrupt 的动机，不是给出固定 IPC；重点是 CPU 与 disk 延迟相差巨大。[00:31:02–00:31:42]
- **“SSD 外表像磁盘”**：强调接口抽象与内部技术可分离；同样的 logical block API 可由机械盘或 flash 实现。[00:31:53–00:32:37]
- **修改一个 page 却搬其他 pages**：直观解释 random write 为什么比 read/sequential access 复杂。[00:33:35–00:34:32]
- **Intel SSD 730**：所有 `550/470/365/303 MB/s`、`50/60 μs` 数字都属于该课件规格示例，不应泛化为所有 SSD。[课件: 11-memory-hierarchy.pptx p.39]
- **移动设备例子**：无 moving parts 同时带来速度、功耗与抗冲击优势，解释技术为何进入 thumb drive、便携播放器和 laptop。[00:36:36–00:36:58]

## 易错点

- DMA 不是“CPU 把数据循环复制到内存”；恰恰是 controller 直接传输，CPU 只发起并在完成时收 interrupt。[课件: 11-memory-hierarchy.pptx p.35–37]
- Flash 的 page、flash block、logical disk block 不同；老师明确说两个 “block” 是不幸的术语重叠。[00:33:11–00:33:23]
- “Page 可写”有前提：其整个 flash block 已擦除；读取则没有这项先擦限制。[00:33:23–00:34:15]
- “高层模型不必明显区分 read/write”不等于两者性能完全相同；课件仍显示 write 较慢。[00:36:19–00:36:36] [课件: 11-memory-hierarchy.pptx p.39]
- CPU 趋势图纵轴是 log scale；图上相同距离不代表相同纳秒差，而代表相同比例/数量级变化。[00:37:53–00:38:14]

## 本段掌握检查

1. **问：DMA 与 interrupt 在一次磁盘读中分别解决什么问题？**  
   **答：** DMA 让 controller 不经 CPU 逐 word 介入就把 sector 写入主存；interrupt 在传输完成后通知 CPU，使其此前可执行其他工作。[00:29:58–00:31:42]
2. **问：为什么 SSD 修改一个 page 可能需要复制许多 pages？**  
   **答：** Page 只有在所属整个 flash block 已擦除后才能写，因此 FTL 找已擦除 block，复制未修改 pages，再写目标 page。[00:33:23–00:34:32]
3. **问：课件数字如何支持 sequential access 优于 random access？**  
   **答：** Intel SSD 730 顺序读/写为 `550/470 MB/s`，随机读/写为 `365/303 MB/s`；随机值均低，且 erase 约 `1 ms` 会拖慢随机写。[课件: 11-memory-hierarchy.pptx p.39]
4. **问：2015 年课堂语境中，SSD 相对 rotating disk 的主要权衡是什么？**  
   **答：** SSD 无 moving parts，因而更快、省电、坚固，但有磨损潜力且每 byte 约贵 `30×`；wear leveling 与 `128 PB` 保证值缓解寿命担忧。[00:36:36–00:37:39]
5. **问：1985–2003 年 CPU cycle time 为什么持续下降，趋势为何将在下一段转折？**

# 第 5 段：CPU–存储鸿沟与局部性原则

> 时间范围：00:39:54–00:49:43  
> 对应课件：11-memory-hierarchy.pptx p.41–46；CPU 历史数据补充见 p.66

## 本段在整讲中的作用

上一段在 CPU 趋势图上讲到 2003 年前依靠提高时钟频率缩短 cycle time，本段先解释这条路线为何撞上 **power wall**，以及多核为何只能改变有效吞吐趋势、不能消除单次数据访问的延迟。老师随后比较 SRAM、DRAM、SSD、disk 与 CPU 的速度轨迹，提出本讲的核心矛盾：程序需要的数据位于明显更慢的存储设备中，CPU 再快也可能被取数时间限制。解决线索不是假定器件突然变快，而是利用程序本身的 **locality**；本段完成局部性定义、时空两类局部性的区分，并用一维数组求和建立从源代码判断局部性的第一套方法。[00:39:54–00:49:43] [课件: 11-memory-hierarchy.pptx p.41–46]

## 教学展开

### 1. 2003 年的 power wall 终止了单纯提频路线

- 本段从上一段末尾“频率越高、功耗越大”的因果关系接起。老师说 Intel 当时准备推出的处理器若继续按原路线发展，功耗将约为 `800 W`；他用“把 800 W 灯泡放进笔记本”以及自己见过的巨大散热器原型，强调这种热量无法在普通系统中合理处理。[00:39:54–00:40:31]
- 因此，老师把 2003 年称为处理器设计撞上 **power wall** 的转折点：设计者不能再只靠持续提高 clock frequency 来制造更快的计算机。[00:40:31–00:40:47] [课件: 11-memory-hierarchy.pptx p.41, p.66]

### 2. 多核延续有效工作量，但单核周期不再快速下降

- 2003 年以后，设计者不再把主要增长押在成倍提高频率上，而是在一块 CPU chip 中放入多个 processor cores；每个 core 可执行自己的 instruction stream，多条独立执行流并行时，单位时间内可完成更多工作。[00:40:47–00:41:17]
- 趋势图底部画的是老师定义的 **effective cycle time**：实际 cycle time 除以 core 数。2005 年的双核可以同时运行两个 independent threads 或 programs；课堂所述当时常见约 4 核，server-class 系统可有 8 核，甚至已有 12 核。[00:41:17–00:41:46] [课件: 11-memory-hierarchy.pptx p.66]
- 老师的预测是 clock frequency 大体趋平：cycle time 一度反而增加，之后虽缓慢下降，但总体接近平坦。因而继续提升总性能的主要办法是增加能够并行工作的独立 cores，而不是等待单核频率再次按旧速度增长。[00:41:46–00:42:06]

### 3. 趋势图揭示 CPU 与各级存储之间的鸿沟

- SRAM 的 access time 与 CPU 趋势跟得较紧，虽约慢一个数量级，仍能随 CPU 一同改善；DRAM 与 CPU 之间则相隔数个数量级，近年来虽有改善，却很难显著提速。[00:42:15–00:42:51] [课件: 11-memory-hierarchy.pptx p.41]
- SSD 位于 DRAM 与 rotating disk 之间；disk 的 access time 约在 `10^6 ns = 1 ms` 的量级，虽略有下降，却没有随 CPU 同步缩短。[00:42:51–00:43:17] [课件: 11-memory-hierarchy.pptx p.41]
- 老师由图得出问题陈述：CPU 与 DRAM、SSD、disk 之间存在巨大差距，有些差距还随时间扩大。程序必须访问数据，而数据保存在 memory 和 disk 中；若计算变快而存储访问相对不变或更慢，那么程序性能会被取数时间限制，CPU 的增长无法自动转化为程序加速。[00:43:17–00:44:05] [课件: 11-memory-hierarchy.pptx p.41]

### 4. 用 locality 作为跨越鸿沟的程序性质

- 老师随后给出解决问题的关键：CPU 与 memory 之间的差距可以利用程序的一项基本、持久性质来弥合，这项性质叫 **locality**；随后议程页把讲授焦点从存储技术转到 locality of reference。[00:44:05–00:44:26] [课件: 11-memory-hierarchy.pptx p.42] [课件: 11-memory-hierarchy.pptx p.43]
- 局部性原则的准确表述是：程序倾向于使用其地址与最近使用过的地址相同或相近的数据和指令。换言之，访问某个数据项后，程序在不久的将来很可能再次访问它，或访问地址邻近的数据项。[00:44:26–00:45:19] [课件: 11-memory-hierarchy.pptx p.44]

### 5. 时间局部性与空间局部性

- **Temporal locality（时间局部性）**：最近引用过的 item 很可能在不久的将来再次被引用。老师的直接例子是循环中的累加变量：每次迭代都要再次访问同一个变量。[00:45:20–00:45:47] [课件: 11-memory-hierarchy.pptx p.44]
- **Spatial locality（空间局部性）**：若程序访问一个 item，便很可能在相近时间访问地址邻近的 items。这里“邻近”指地址接近，而不是变量名称或源码位置看起来接近。[00:45:49–00:46:08] [课件: 11-memory-hierarchy.pptx p.44]

### 6. 一维数组求和：同时检查数据与指令引用

课件代码为：[00:46:08–00:46:25] [课件: 11-memory-hierarchy.pptx p.45]

```c
sum = 0;
for (i = 0; i < n; i++)
    sum += a[i];
return sum;
```

- 老师先把 reference 分成两类：CPU 从内存取出并执行 **instructions**，这些 instructions 又产生对 **data** 的访问。局部性分析必须同时覆盖两者。[00:46:15–00:46:25]
- 对 data references 而言，`i` 每次加 1，程序依次访问 `a[i]`。老师把索引每次增加的量称为 **stride**，因此这是 **stride-1 reference pattern**；相邻数组元素的地址相近，所以它体现空间局部性。[00:46:27–00:47:05] [课件: 11-memory-hierarchy.pptx p.45]
- `sum` 在每次 loop iteration 中都被引用，连续迭代重复使用同一数据项，因此体现时间局部性。[00:47:05–00:47:17] [课件: 11-memory-hierarchy.pptx p.45]
- 对 instruction references 而言，一次迭代内按顺序执行一串相邻指令，体现空间局部性；循环随后回到同一段 loop body，下一次迭代再次执行上一轮的那些指令，体现时间局部性。简单例子中的 loop body 可能只有一条关键指令，但同一判断也适用于含多条指令的循环体。[00:47:17–00:48:08] [课件: 11-memory-hierarchy.pptx p.45]

### 7. 把“看代码判断局部性”提升为程序员技能

- 老师把定性判断 locality 称为专业程序员的关键技能，也是本课程的主要训练目标之一。理由将在后续缓存设计中展开：现代系统把良好局部性转化为良好性能，因此看到代码时应能区分“局部性很好”和“局部性很差”，并避免后者。[00:48:08–00:48:57] [课件: 11-memory-hierarchy.pptx p.46]
- 接着引入二维数组例子：`a` 有 `M` 行、`N` 列，双重循环对所有元素求和。操作本身很简单，但老师预告，若把访问顺序写成局部性差的形式，程序可能慢一个数量级；本段停在“当前写法对 `a` 的局部性好还是坏”的课堂提问，答案与对比留到下一段。[00:48:57–00:49:43] [课件: 11-memory-hierarchy.pptx p.46]

## 概念、符号与推导

### 有效周期时间

老师在趋势图中采用的定性指标是：[00:41:12–00:41:29] [课件: 11-memory-hierarchy.pptx p.66]

$$
T_{effective}=\frac{T_{cycle}}{N_{cores}}.
$$

- `T_cycle`：一个 core 的实际 cycle time。
- `N_cores`：可并行工作的 processor cores 数。
- `T_effective`：用“周期时间除以核数”表达并行后单位有效工作量的趋势。

这个量是老师为趋势图采用的 effective cycle time，不等于任意程序都能获得 `N_cores` 倍加速；课堂在此只说独立 threads/programs 可以并行执行，没有给出更一般的并行加速公式。[00:41:21–00:41:39]

### CPU–存储鸿沟的推理链

1. CPU cycle time 曾快速下降，2003 年后单纯提频受 power wall 限制。[00:39:54–00:42:06]
2. SRAM 尚能大体跟随 CPU，但 DRAM、SSD、disk 的 access time 明显更长，disk 约处于毫秒量级。[00:42:15–00:43:17]
3. 程序必须从这些设备取得 data；因此 storage latency 会限制程序性能。[00:43:17–00:44:05]
4. 程序并非均匀随机地访问所有地址，而倾向于重用近期 item 或访问邻近 item，即具有 locality。[00:44:05–00:45:19]

本段只提出利用 locality 跨越鸿沟，尚未给出 cache 命中时间、miss penalty 或平均访问时间公式。

### 局部性与步长

- **Temporal locality**：近期引用的 item 在近期再次引用。
- **Spatial locality**：地址相近的 items 在时间上相近地被引用。
- **Stride**：相邻两次数组引用之间索引增加的量；`a[0], a[1], a[2], ...` 是 stride-1。老师本段只定义索引层面的 stride，没有在这里推导 byte-address 差值。[00:45:20–00:47:05]

## 例子与课堂提示

- **800 W 与巨大散热器**：把功耗趋势转化为可感知的热设计问题，服务于“为什么 2003 年后不能继续只靠提频”。[00:40:00–00:40:37]
- **双核运行两个独立执行流**：解释为什么 core 数增加能让 effective cycle time 继续下降；前提是工作彼此独立、能够并行。[00:41:21–00:41:39]
- **`10^6 ns = 1 ms`**：老师现场换算 disk 曲线的纵轴，帮助学生在对数图上识别 disk 与 CPU/DRAM 的量级差距。[00:42:55–00:43:08] [课件: 11-memory-hierarchy.pptx p.41]
- **循环累加变量 `sum`**：同一个源代码片段同时展示四种判断：数组数据的空间局部性、`sum` 的时间局部性、顺序指令的空间局部性、循环指令的时间局部性。[00:46:08–00:48:08] [课件: 11-memory-hierarchy.pptx p.45]
- **二维数组悬念**：老师先不回答，而是让学生判断一个看似无害的双循环；它服务于下一段“循环顺序会改变 stride，并可能造成数量级性能差异”。[00:48:57–00:49:43] [课件: 11-memory-hierarchy.pptx p.46]

## 易错点

- `T_effective = T_cycle/N_cores` 是趋势图的有效工作指标，不能据此断言所有单线程程序都随核数线性加速。[00:41:12–00:41:39]
- SRAM “跟得上 CPU 趋势”不等于 SRAM 与 CPU 同速；老师仍称它约慢一个数量级。[00:42:15–00:42:33]
- 局部性同时适用于 **data** 与 **instructions**。只检查数组下标而忽略循环体指令，会漏掉本例的一半分析。[00:46:15–00:48:08]
- 时间局部性是重复引用同一 item；空间局部性是引用地址邻近的不同 items。`sum` 与 `a[i]` 在本例中分别承担这两个最直接的角色。[课件: 11-memory-hierarchy.pptx p.44–45]
- Stride-1 描述索引每次加 1；本段尚未讨论多维数组的内存布局，因此二维例题不能只看“两个下标都加 1”便下结论。[00:46:27–00:46:55] [00:48:57–00:49:43]

# 第 6 段：从数组访问顺序到内存层次

> 时间范围：00:49:43–00:59:38  
> 对应课件：11-memory-hierarchy.pptx p.46–52

## 本段在整讲中的作用

上一段以二维数组求和的课堂提问收尾，本段立即用 C 的 row-major layout 回答：相同计算只因循环嵌套顺序不同，就会形成 stride-1 或 stride-`N` 的访问模式。老师再把这套判断推广到三维数组，给出“让最右侧下标变化最快”的源码审查规则。完成 locality 的程序侧证据后，他回收前半讲的存储技术结论，将“快设备贵且小、CPU–存储差距大、程序有局部性”三件事合并，导出 **memory hierarchy**；最后定义 cache，并用主存缓存磁盘及背包类比说明“先把可能重用的数据放近一些”的基本直觉。[00:49:43–00:59:38] [课件: 11-memory-hierarchy.pptx p.46–52]

## 教学展开

### 1. 按行扫描二维数组：stride-1 是最佳空间局部性

课件中的第一版程序是：[00:49:43–00:50:24] [课件: 11-memory-hierarchy.pptx p.46]

```c
int sum_array_rows(int a[M][N])
{
    int i, j, sum = 0;

    for (i = 0; i < M; i++)
        for (j = 0; j < N; j++)
            sum += a[i][j];
    return sum;
}
```

- 老师先给出判断所需的布局事实：C 以 **row-wise（row-major）** 顺序存放二维数组，即第一行全部元素之后紧接第二行全部元素，再接第三行，以此类推。[00:49:54–00:50:16]
- 程序让 `j` 在 inner loop 中变化最快：固定 `i` 后依次访问第 `i` 行的所有 columns，完成一行才增加 `i` 并进入下一行。[00:50:16–00:50:49]
- 因此 `a[i][j]` 的引用地址按内存布局顺序前进，形成 stride-1 access，顺序遍历整个数组。老师把它评价为非常好的空间局部性，“这是能做到的最好情况”。[00:50:49–00:51:30] [课件: 11-memory-hierarchy.pptx p.46]

### 2. 交换循环次序：同一求和变为 stride-`N`

第二版仅交换两层循环：[00:51:32–00:51:52] [课件: 11-memory-hierarchy.pptx p.47]

```c
int sum_array_cols(int a[M][N])
{
    int i, j, sum = 0;

    for (j = 0; j < N; j++)
        for (i = 0; i < M; i++)
            sum += a[i][j];
    return sum;
}
```

- 现在 outer loop 固定 `j`，inner loop 改变 `i`，于是程序依次访问每一行的第 `j` 个元素，而不是同一行中的相邻元素。[00:52:09–00:52:23]
- 每行有 `N` 个 elements，从 `a[i][j]` 到 `a[i+1][j]` 会跨过一整行，在元素索引尺度上形成 stride-`N`。完成这一列后 `j` 才加 1，再从下一列重复同样的跨行扫描。[00:52:20–00:52:39]
- 老师把它称为 terrible、甚至 worst spatial locality，并要求学生看到这种写法时应立即警觉。这里的重点是：计算结果与循环体未变，访问顺序本身就足以改变 locality。[00:51:52–00:52:43] [课件: 11-memory-hierarchy.pptx p.47]

### 3. 三维数组：按下标从右向左安排变化速度

原课件程序为：[00:52:43–00:53:19] [课件: 11-memory-hierarchy.pptx p.48]

```c
int sum_array_3d(int a[M][N][N])
{
    int i, j, k, sum = 0;

    for (i = 0; i < M; i++)
        for (j = 0; j < N; j++)
            for (k = 0; k < N; k++)
                sum += a[k][i][j];
    return sum;
}
```

- 老师问：在保持访问表达式 `a[k][i][j]` 的前提下，怎样重排 loop indices 才能得到 stride-1？课堂答案是循环顺序 `k–i–j`，也就是 `k` 最外、`i` 居中、`j` 最内。[00:52:54–00:53:19]
- 推理规则是按数组下标 **从右向左** 安排变化速度：最右的 `j` 变化最快，因此在固定 `k`、`i` 时遍历所有 `j`；随后增加 `i`，再次遍历所有 `j`；最后才增加最左的 `k`。[00:53:19–00:53:58] [课件: 11-memory-hierarchy.pptx p.48]

按老师给出的顺序，循环结构可写成：

```c
for (k = 0; k < N; k++)
    for (i = 0; i < M; i++)
        for (j = 0; j < N; j++)
            sum += a[k][i][j];
```

该改写只是把课件已有的三个 loops 按课堂答案重排，没有引入额外算法。

### 4. 三条持久性质共同导出 memory hierarchy

- 老师先回收 storage technologies 的性质：更快的存储每 byte 更贵，因而实际容量更小；较大、较高容量的存储更便宜，但更慢。课件还把较快设备的更高功耗/发热列为同一组约束。[00:53:58–00:54:20] [课件: 11-memory-hierarchy.pptx p.49]
- 第二条性质是 CPU 与 storage devices 之间存在速度 gap；第三条是程序表现出 locality。硬件的速度/容量/成本约束与软件的访问规律彼此补足，提示了 storage system 的组织方式，即 **memory hierarchy**。[00:54:20–00:55:02] [课件: 11-memory-hierarchy.pptx p.49]
- 议程随后从 locality of reference 转入 caching in the memory hierarchy。[00:54:59–00:55:05] [课件: 11-memory-hierarchy.pptx p.50]

### 5. 从上到下排列：越近越快、越小、越贵

- Memory hierarchy 不再把存储看成 flat system，而把性质不同的设备分层。顶端是更小、更快、每 byte 更昂贵的设备；越向下则越大、越慢、每 byte 越便宜。[00:55:02–00:55:28] [课件: 11-memory-hierarchy.pptx p.51]
- 最顶端是 registers，可在一个 instruction 的执行过程中读写，访问约在一个 cycle 内；但它们使用 processor 的 custom silicon，制造昂贵且数量很少。老师以当时架构的 16 个 registers 强调顶层容量之小。[00:55:22–00:55:57]
- Registers 之下是一层或多层由 SRAM 构成、位于 processor chip 上的 cache memories。它们比 registers 大，但仍约为 megabytes；再下方是由 DRAM 构成、可达 gigabytes 或 tens of gigabytes 的 main memory。[00:55:57–00:56:44] [课件: 11-memory-hierarchy.pptx p.51]
- 更低层是 local disks；还可继续把远端 Web servers 纳入层次，例如存放在 Google 远端系统中的数据也可视为层次底部的一部分。[00:56:44–00:57:01] [课件: 11-memory-hierarchy.pptx p.51]

课件给出的完整示意从上到下为：`L0 registers → L1 cache → L2 cache → L3 cache → L4 main memory → L5 local secondary storage → L6 remote secondary storage`。[课件: 11-memory-hierarchy.pptx p.51]

### 6. 相邻层之间保存“从下一层取回的数据”

- 层次结构的关键关系是：每一层保存从下一层取回的数据。Registers 保存从 L1 cache 取来的 words；L1 保存从 L2 取来的 cache lines；L2 保存从 L3 取来的 cache lines；L3 保存从 main memory 取来的 cache lines；main memory 保存从 local disk 取来的 disk blocks。[00:57:01–00:57:40] [课件: 11-memory-hierarchy.pptx p.51]
- 老师先给出这一组织的目标效果：一般情况下，希望以层次顶部最快设备的速度访问数据，同时让整体存储的成本接近层次底部设备。[00:57:40–00:58:09]

### 7. Cache 是较快层中的 staging area

- **Cache** 的定义是：较小、较快的 storage device，充当较大、较慢设备中一部分数据的 **staging area**。[00:58:09–00:58:28] [课件: 11-memory-hierarchy.pptx p.52]
- 老师先用 main memory 与 disk 说明：从 disk 读出的数据放入 main memory 后，后续访问直接从更快的 memory 完成，不必每次再去 disk。相同思想沿层次一路向上重复。[00:58:28–00:59:00]
- 接着开始背包类比：住处离学校较远，早晨先从家中挑选物品放进 backpack；到学校需要这些物品时可直接从背包取，而不用每次走回家。本段在类比尚未总结完的 00:59:38 结束，下一段接着说明它为何普遍而有效。[00:59:00–00:59:38]

## 概念、符号与推导

### 二维数组的步长判断

前提来自老师口述：C 二维数组按行连续存放，每行有 `N` 个 elements。[00:49:54–00:50:16]

- 固定 `i`、改变 `j`：`a[i][0], a[i][1], ..., a[i][N-1]`，相邻引用在元素序列中前进 1，故为 stride-1。[00:50:24–00:51:12]
- 固定 `j`、改变 `i`：`a[0][j], a[1][j], ..., a[M-1][j]`，相邻引用跨过一行的 `N` 个元素，故为 stride-`N`。[00:52:09–00:52:30]

本段没有给出元素 byte size，因此不把 stride-`N` 进一步改写为字节地址差。

### 三维循环重排规则

对表达式 `a[k][i][j]`，最右侧 `j` 对应连续方向，故变化次序应满足：[00:53:19–00:53:58]

$$
\text{变化速度：}j\;\text{最快},\quad i\;\text{其次},\quad k\;\text{最慢}.
$$

所以 nesting order 为 `k → i → j`（从 outer 到 inner）。这是老师依据 row-major layout 给出的定性推导；本段未写出三维地址计算公式。

### 层次层级与缓存关系

- Level 编号越小，位置越靠上；本段课件以 `L0` registers 为顶端，以 `L6` remote storage 为底端。[课件: 11-memory-hierarchy.pptx p.51]
- 对相邻两层，较上层保存较下层数据的一个子集；本段以 words、cache lines、disk blocks 展示 transfer unit 随层次不同而变化。[课件: 11-memory-hierarchy.pptx p.51]
- 本段给出 cache 的定义和目标效果，但“为何 locality 能让它有效”的完整因果链从下一段 00:59:38 展开。

## 例子与课堂提示

- **只换循环次序**：`sum_array_rows` 与 `sum_array_cols` 计算相同、循环体相同，却分别产生 stride-1 与 stride-`N`。它服务于“源代码访问顺序能造成巨大性能差异”。[00:49:43–00:52:43] [课件: 11-memory-hierarchy.pptx p.46–47]
- **“看到列扫描应感到不适”**：老师用强烈措辞要求形成代码审查直觉；判断依据不是审美，而是 row-major layout 与 inner-loop index 的组合。[00:51:52–00:52:43]
- **下标从右向左**：三维例子把二维经验推广成规则，看到 `a[k][i][j]` 时先让 `j` 在最内层变化，再安排 `i`、`k`。[00:52:43–00:53:58] [课件: 11-memory-hierarchy.pptx p.48]
- **主存作为磁盘 cache**：展示 cache 不是 CPU 芯片专属术语；只要较快设备保存较慢设备的一部分数据，就符合这一抽象。[00:58:28–00:58:52]

## 易错点

- C 的二维数组在本讲模型中按 row-major 存放；“按列写在源码里看起来整齐”不意味着地址连续。[00:49:54–00:50:16]
- Stride-`N` 的 `N` 来自每行的元素数，不是外层循环次数 `M`。[00:52:20–00:52:30]
- 三维循环的课堂答案 `k–i–j` 指从 outer loop 到 inner loop 的 nesting order；“最右下标变化最快”意味着 `j` 必须在最内层。[00:53:19–00:53:58]
- Memory hierarchy 顶部是 level number 较小的 `L0`，不是编号最大的层；越往下编号才越大。[课件: 11-memory-hierarchy.pptx p.51]
- “以最快设备速度、以最慢设备成本/容量提供存储”是层次结构要达到的总体效果，不表示每次访问都必然命中最上层；hit/miss 从下一段定义。[00:57:40–00:58:09]

# 第 7 段：通用缓存模型、命中与缺失

> 时间范围：00:59:38–01:09:35  
> 对应课件：11-memory-hierarchy.pptx p.52–56

## 本段在整讲中的作用

上一段用背包说明 staging area 的直觉，本段把类比提升为可跨越整个 memory hierarchy 的统一模型。老师先形式化相邻层关系，并用 locality 解释为何把数据从 `k+1` 层搬到 `k` 层后值得保留；随后把较慢 memory 划为固定大小 blocks，说明 cache 只保存其子集，并沿具体请求依次定义 **hit**、**miss**、placement policy 与 replacement policy。最后开始分类 miss：先讲无法避免的 cold/compulsory miss，再用 working set 超过 cache 容量定义 capacity miss，并在提出 conflict miss 的放置限制处进入下一段。[00:59:38–01:09:35] [课件: 11-memory-hierarchy.pptx p.52–56]

## 教学展开

### 1. 从背包类比回到相邻层的正式关系

- 老师先总结上一段尚未说完的类比：缓存看似是熟悉而简单的想法，却非常有力，并出现在计算机系统的各个部分。[00:59:38–00:59:53]
- 对 hierarchy 中任意 level `k`，第 `k` 层较快、较小的设备充当第 `k+1` 层较大、较慢设备的 cache。[00:59:53–01:00:07] [课件: 11-memory-hierarchy.pptx p.52]
- 编号方向必须先固定：`L0` 位于 hierarchy 最上方；level number 增加意味着向下走。因此“上层/下层”的空间说法与数字大小相反：较小的编号对应更高、更快的一层。[01:00:00–01:00:14]

### 2. Locality 使搬到上层的数据能够被重复利用

- 为什么 hierarchy 有效？老师给出的根因是 locality：程序访问第 `k` 层已有数据的频率，倾向于高于访问第 `k+1` 层数据的频率。[01:00:14–01:00:38] [课件: 11-memory-hierarchy.pptx p.52]
- 当程序第一次需要第 `k+1` 层的 item 时，可以把它搬到第 `k` 层；由于 locality，它很可能再次被访问。之后对该 item 的多次访问便以第 `k` 层的较快速度进行，而不是每次支付第 `k+1` 层的较慢访问时间。[01:00:38–01:01:07]
- 因为程序不常直接触达第 `k+1` 层，该层允许使用更慢、因而更便宜的 storage technology，并可做得更大。[01:01:07–01:01:24]
- 老师据此概括 memory hierarchy 的总体效果：形成一个容量大致接近最低层、但通常能以最高层速度向程序提供数据的大 storage pool；课件同时强调其成本接近底部便宜存储。[01:01:24–01:01:37] [课件: 11-memory-hierarchy.pptx p.52]

### 3. 通用缓存把下层数据划分为传输单位

- 老师说明本节只讲一般 caching；下一次课才会具体展开 hardware cache memories。通用缓存原则适用于 hierarchy 的各层。[01:01:37–01:01:57]
- 示例中，上层 cache 可容纳 4 个 blocks；下层较大、较慢、较便宜的 memory 被切分成一组固定大小 blocks。[01:01:57–01:02:29] [课件: 11-memory-hierarchy.pptx p.53]
- 在 hierarchy 较上方，数据通常以等长 byte blocks 组织；在较下方，例如访问 Web server，transfer unit 也可能是 files。老师当前把下层假定为 main memory，并把它划为等 byte 数的 blocks。[01:02:29–01:03:09]
- 相邻层之间以 **整个 block** 为单位搬运：cache 若需要下层某处数据，不只取一个 word，而是取回包含它的整块。任一时刻，cache 保存的只是下层 memory blocks 的一个 subset。[01:03:09–01:03:28] [课件: 11-memory-hierarchy.pptx p.53]
- Cache 更快，因而单位存储更昂贵，所以容量更小；这解释了为何它不能保存下层的全部 blocks，只能选择一个子集。[01:03:28–01:03:49]

### 4. 请求 block 4 与 10：先付出搬运和驱逐成本

- 课件示例的下层 memory 有 blocks `0–15`，初始 cache 图中保存 `8, 9, 14, 3`。[课件: 11-memory-hierarchy.pptx p.53]
- CPU 需要 block 4 中的数据时，cache 检查后发现它不在上层，于是向 memory 请求整个 block 4；block 4 被复制进 cache，并在图示中覆盖原有 block 8。[01:03:49–01:04:24]
- 随后请求 block 10 时也要把 block 10 搬入并覆盖一个已有 block。老师强调，慢速搬运已经付出时间，保留 block 的目的就是希望正在运行的程序随后重用这些刚取回的 blocks。[01:04:24–01:04:58]

### 5. Hit：所需 block 已在 cache

- CPU 接着需要原本位于 memory block 14 的 word。Cache 查找后发现 block 14 已在上层，这称为 **cache hit**。[01:04:58–01:05:27] [课件: 11-memory-hierarchy.pptx p.54]
- Hit 是理想情况：cache 可直接向 CPU 返回数据；在该例中，上层 SRAM 比下层 DRAM 快，因此 CPU 获得 block 14 中数据的速度明显高于一路访问 main memory。[01:05:27–01:05:50]

### 6. Miss：从下层取块，并决定放在哪里、替换谁

- Hit 的相反情况是 **cache miss**。当 CPU 请求 block 12 而 cache 中没有它时，cache 必须向 DRAM 请求整个 block 12，等它复制到 cache 后才能把数据返回 CPU。[01:05:50–01:06:22] [课件: 11-memory-hierarchy.pptx p.55]
- 因为 CPU 必须等待较慢的 memory fetch，miss 慢；老师用最直接的判断总结：“hits are good because they are fast; misses are bad because they are slow”。[01:06:17–01:06:28]
- 课件把 miss 后的两个决定明确命名：**placement policy** 决定新 block `b` 放入 cache 的哪个位置；若目标位置需要腾空，**replacement policy** 决定驱逐哪个现有 block，该被驱逐项称为 victim。[课件: 11-memory-hierarchy.pptx p.55]

### 7. Cold/compulsory miss：cache 尚未装入任何内容

- 第一类 miss 是 **cold miss**，也叫 **compulsory miss**。初始 cache 为空，不包含 blocks，所以最初访问必然 miss；这类缺失没有办法通过已有 cache 内容避免。[01:06:28–01:07:06] [课件: 11-memory-hierarchy.pptx p.56]
- 随着从下一层取回的 blocks 逐渐填入 cache，hit 的可能性上升。老师把这个过程称为 **warming up the cache**：从 cold 状态逐步加入 items，直到后续访问更可能命中。[01:06:44–01:07:16]

### 8. Capacity miss：working set 大于 cache

- 第二类是 **capacity miss**，根因是 cache 只有有限容量。示例 cache 只有 4 blocks；若程序一段时间内反复访问的数据涉及 8 blocks，例如一个循环正在访问跨 8 blocks 的数组，那么 4-block cache 无法同时保存它们。[01:07:16–01:08:08] [课件: 11-memory-hierarchy.pptx p.56]
- 若 cache 足够大、能保存所有这些 blocks，便可利用程序的 spatial 和 temporal locality 获得较好的 hit rate；但当前容量不足，部分所需 blocks 必须不断进出。[01:08:08–01:08:23]
- 老师把程序在某一时刻反复使用的一组 blocks 称为 **working set**。Working set 会随执行阶段改变，例如从一个 loop 进入另一个 loop，或从一个 function 进入另一个 function；它描述当前阶段希望留在 cache 中的 blocks。[01:08:23–01:08:54]
- 当 working-set size 超过 cache size 时，就产生 capacity misses。[01:08:54–01:09:00] [课件: 11-memory-hierarchy.pptx p.56]

### 9. Conflict miss 的问题起点：block 不能放在任意位置

- 老师最后引出较特殊的 **conflict miss**。尤其是 hardware caches，为保持实现简单，通常会限制一个下层 block 只能放入 cache 的一小组位置，有时甚至只有一个位置。[01:09:00–01:09:29] [课件: 11-memory-hierarchy.pptx p.56]
- 本段停在“block `i` 只能被放到……”的规则开头；具体 `i mod cache_size` 映射及其冲突序列从下一段 01:09:35 继续。[01:09:29–01:09:35]

## 概念、符号与推导

### 相邻层缓存关系

对每个 hierarchy level `k`：[00:59:53–01:00:38] [课件: 11-memory-hierarchy.pptx p.52]

$$
L_k\ \text{是}\ L_{k+1}\ \text{的 cache}.
$$

- `L_k`：较高、较快、较小、每 bit 更昂贵。
- `L_{k+1}`：较低、较慢、较大、每 bit 更便宜。
- 数据第一次从 `L_{k+1}` 上移到 `L_k` 后，locality 提高它在 `L_k` 被再次访问的概率。[01:00:24–01:01:24]

课堂没有在这里给出“最高层速度、最低层容量/成本”的数值公式；这是由 locality 支撑的设计目标，而不是每次访问的硬保证。

### Block 模型

- 下层 memory 被分成 fixed-size blocks；上层 cache 可容纳更少 blocks。[01:01:57–01:03:09]
- Transfer unit 是完整 block；cache state 是下层 block 集合的一个 subset。[01:03:09–01:03:28]
- **Hit**：包含所需数据的 block 已在 cache，可由较快层服务。[01:04:58–01:05:50]
- **Miss**：所需 block 不在 cache，必须从下层 fetch，随后按 placement/replacement policy 更新 cache。[01:05:50–01:06:28] [课件: 11-memory-hierarchy.pptx p.55]

### Miss 分类条件

| Miss 类型 | 本段给出的触发条件 | 能否仅靠已有空闲总容量解释 |
|---|---|---|
| Cold / compulsory | Cache 初始为空，目标 block 从未装入 | 是初次访问条件，不取决于已有内容能否重排 |
| Capacity | `working-set size > cache size` | 是，容量本身不足 |
| Conflict | Block placement 被限制，多项竞争同一位置 | 否；下一段将展示总容量够却仍 miss |

本段对 capacity miss 的条件可写为：[01:08:23–01:09:00]

$$
|W|>C\quad\Longrightarrow\quad\text{capacity misses},
$$

其中 `W` 是当前 working set 的 blocks 集合，`C` 是 cache 可容纳的 block 数。符号写法只是对老师口述条件的紧凑表达；课堂未进一步给出 miss count 或 hit-rate 推导。

## 例子与课堂提示

- **背包类比的结论**：把远处较大集合中的常用子集带在身边，展示 caching 的思想与具体硬件无关。[00:59:38–00:59:53]
- **Block 4、10 的搬入**：先展示 cache 为重用机会付出的 fetch 与 overwrite 成本，再讲 hit；这样 hit 的收益不会被误解为“数据天然就在快设备里”。[01:03:49–01:04:58] [课件: 11-memory-hierarchy.pptx p.53]
- **Block 14 hit / block 12 miss**：同一张 4-block cache 上的相邻请求建立 hit 与 miss 的操作差异。[01:04:58–01:06:28] [课件: 11-memory-hierarchy.pptx p.54–55]
- **Cache warming**：不是提高硬件温度，而是逐步装入 blocks，让后续请求更可能 hit。[01:06:36–01:07:16]
- **4-block cache 对 8-block working set**：说明 locality 本身不够；若需要反复保留的集合超过容量，cache 仍不能充分利用重用。[01:07:27–01:08:23]

## 易错点

- `L0` 是 hierarchy 的最高层；数字增加才表示向下。不要把“level 0”误读为最底层或最慢层。[01:00:00–01:00:14]
- Cache 保存的是下层数据的 **subset**，数据通常以整 block 搬运，而不是每次只搬 CPU 请求的单个 byte/word。[01:02:54–01:03:28]
- Hit/miss 判断针对“包含所需数据的 block 是否在 cache”，不是只比较请求数字是否等于某个 cache slot 编号。[01:04:58–01:06:10]
- Cold miss 与 capacity miss 原因不同：前者来自初始为空，后者来自当前 working set 确实装不下。[01:06:28–01:09:00]
- Working set 会随 loop/function 阶段变化，不是程序从开始到结束访问过的所有 blocks 的永久全集。[01:08:23–01:08:54]

## 本段掌握检查

1. **问：对相邻层 `k` 和 `k+1`，cache 关系与层号方向分别是什么？**  
   **答：** 较快、较小的 `L_k` 缓存较慢、较大的 `L_{k+1}`；`L0` 在最上方，编号增加表示向下。[00:59:53–01:00:14]
2. **问：locality 为什么能让从 `L_{k+1}` 搬到 `L_k` 的成本值得支付？**  
   **答：** 搬上来的 item 很可能很快被再次访问，后续多次访问可按较快的 `L_k` 速度完成，而不必每次访问 `L_{k+1}`。[01:00:24–01:01:07]
3. **问：通用 block cache 中 hit 和 miss 的操作差异是什么？**  
   **答：** Hit 时目标 block 已在 cache，可直接由快层返回；miss 时必须从下层 fetch 整块、放入 cache，必要时驱逐 victim，然后才能返回。[01:04:58–01:06:28] [课件: 11-memory-hierarchy.pptx p.54–55]
4. **问：placement policy 与 replacement policy 各决定什么？**  
   **答：** Placement 决定新 block 放到哪里；replacement 决定空间冲突时驱逐哪个现有 block，即选择 victim。[课件: 11-memory-hierarchy.pptx p.55]
5. **问：cold miss 与 capacity miss 如何区分，working set 在其中扮演什么角色？**  
   **答：** Cold miss 因 cache 初始为空而发生；capacity miss 因当前反复使用的 blocks 集合即 working set 大于 cache 容量而发生。[01:06:28–01:09:00]

# 第 8 段：冲突缺失、全层次缓存实例与总结

> 时间范围：01:09:35–01:15:34.100  
> 对应课件：11-memory-hierarchy.pptx p.56–58

## 本段在整讲中的作用

上一段在“hardware cache 会限制 block 的可放置位置”处停下，本段补完 conflict miss 的取模映射和逐步驱逐过程，从而完成 cold、capacity、conflict 三类 miss 的区分。老师随后不再只看 SRAM cache，而按“缓存什么、存在哪里、访问多慢、由谁管理”巡视 registers、TLB、L1/L2、OS buffer cache、network cache 与 browser cache，证明 caching 是贯穿整个 memory hierarchy 的共同原则。最后用三句话回收整讲：速度鸿沟扩大、良好程序有 locality、利用 locality 的 caching hierarchy 弥合鸿沟，并在最终 cue 预告下一讲专门研究 hardware cache memories。[01:09:35–01:15:34.100] [课件: 11-memory-hierarchy.pptx p.56–58]

## 教学展开

### 1. 直接映射规则：memory block `i` 只能去一个 cache slot

- 本段接续上一句，给出最简单的 placement model：memory block `i` 只能放到编号为 `i mod cache_size` 的 cache block/slot。[01:09:35–01:09:48] [课件: 11-memory-hierarchy.pptx p.56]
- 对上一段的 4-block cache，映射位置为 `i mod 4`。因此 memory blocks 0、4、8 都只能放进 cache slot 0；block 9 则放进 slot 1。[01:09:40–01:10:11]

### 2. 容量足够仍不断 miss：这才是 conflict

- 老师让访问模式涉及 blocks 0、4、8。它们一共只有 3 blocks，而 cache 有 4 个 slots，所以从总容量看完全装得下。[01:10:11–01:10:38]
- 问题在 placement：三者都映射到 slot 0。装入 block 4 会覆盖 slot 0 中的 block 0，装入 block 8 又会覆盖同一位置；当访问模式继续回到先前 block 时，它已被驱逐，于是再次 miss。[01:10:38–01:11:12]
- 因此 **conflict miss** 不是 cache 总容量太小，而是 reference pattern 与 placement algorithm 共同造成的竞争：其他 slots 即使空闲或可用，这几个 blocks 也不能放过去，反复访问便会每次 miss。[01:10:55–01:11:19] [课件: 11-memory-hierarchy.pptx p.56]
- 课件给出的同类最小序列是 `0, 8, 0, 8, ...`：二者都映射到 `0 mod 4`，所以交替覆盖。老师说下一讲研究具体 caches 时会详细解释 conflict misses。[01:11:19–01:11:25] [课件: 11-memory-hierarchy.pptx p.56]

### 3. 用四个问题巡视每一种 cache

- 老师把视角扩到整条 memory hierarchy：各层都可视为某种 cache，只是实现不同。[01:11:25–01:11:46] [课件: 11-memory-hierarchy.pptx p.57]
- 对每一类 cache，课堂实际沿四个问题组织：**缓存什么（what is cached）**、**缓存在哪里（where is it cached）**、**latency 是多少**、**由谁管理（managed by）**。管理意味着：下层 item 被请求并装入上层时，某个机制必须决定怎样处理以及放到哪里。[01:11:46–01:12:13]

### 4. Registers：由 compiler 管理的 word cache

- Registers 可视为 cache，保存 `4` 或 `8` byte words；缓存位置就在 CPU core 上。[01:11:36–01:11:55] [课件: 11-memory-hierarchy.pptx p.57]
- 老师把 latency 描述为在一条 instruction 内完成；课件表将其记为 `0 cycles`，表达它相对于表中其他层几乎即时，而不是另行推导物理零时间。[01:11:50–01:11:59] [课件: 11-memory-hierarchy.pptx p.57]
- 这类 cache 由 **compiler** 管理：编译 C code 时，compiler 决定哪些来自 memory 的 data items 放入哪些 registers。[01:11:59–01:12:24]

### 5. TLB、L1 与 L2：专用硬件缓存

- 老师简短指出 **TLB** 是 virtual memory 使用的 cache。课件表补充：它缓存 address translations，位于 on-chip TLB，由 hardware MMU 管理。[01:12:25–01:12:33] [课件: 11-memory-hierarchy.pptx p.57]
- L1、L2 是 hardware caches；在老师所述的 modern Intel systems 上，它们保存 `64-byte blocks`，位于 CPU chip 内、由芯片上的 SRAM 构成。[01:12:33–01:12:50] [课件: 11-memory-hierarchy.pptx p.57]
- 以课堂的 Core i7 例子，L1 latency 为 `4 cycles`，L2 为 `10 cycles`；两者由 hardware 管理。[01:12:50–01:13:05]
- CPU 从 L1 取 item 时，hardware 查找它；若 L1 miss、block 从 L2 装入，L1 hardware 决定放置位置。整个查找和放置路径不要求程序显式发出 cache-management 操作。[01:13:05–01:13:24]

### 6. OS buffer cache：用 main memory 缓存文件内容

- 接着转到 operating-system-maintained **buffer cache**：缓存对象是 files 的 portions，缓存位置是 main memory，课堂给出的 latency 约 `100 cycles`，由 OS 管理。[01:13:24–01:13:46] [课件: 11-memory-hierarchy.pptx p.57]
- OS 会保留一部分 main memory 存放已经加载的文件。若程序读入一个 file 后继续引用其中 bytes，OS 利用 locality 从 file cache 服务这些访问，而不必再次访问 disk。[01:13:46–01:14:10]

### 7. Network 与 browser caches：把远端内容留在 local disk

- NFS、AFS 等 network systems 会在 local disk 维护 caches，把原本来自 network/remote storage 的内容留在本地。[01:14:10–01:14:18] [课件: 11-memory-hierarchy.pptx p.57]
- Web browser 获取 server 上的 files 后，也把它们存到 local disk；再次引用相同 Web pages 时，可由 local disk 提供，而不必再次跨 network 获取。[01:14:18–01:14:32]
- 课件表还把 browser cache、network buffer cache、web cache、disk cache、virtual memory 等放在同一张表中，用不同 transfer objects、locations、latencies 与 managers 展示相同抽象。老师的总结是：caches 到处存在，依据相同 principles，只是 implementation 不同。[01:14:32–01:14:44] [课件: 11-memory-hierarchy.pptx p.57]

### 8. 整讲三点总结与下一讲预告

- 第一，CPU 与 storage devices 之间的 speed gap 持续扩大。[01:14:44–01:14:57] [课件: 11-memory-hierarchy.pptx p.58]
- 第二，well-written programs 表现出称为 locality 的性质。[01:14:57–01:15:04.920] [课件: 11-memory-hierarchy.pptx p.58]
- 第三，caching 利用程序 locality 构造 memory hierarchy，使系统通常能以最快设备的速率提供数据，同时具有最低层设备的成本与容量特征。[01:15:04.920–01:15:26.300] [课件: 11-memory-hierarchy.pptx p.58]
- 结尾先预告 Thursday 将研究 hierarchy 中一个非常具体的部分，[01:15:26.420–01:15:31.300] 最终转录 cue 补完其名称：**cache memories**。[01:15:31.300–01:15:34.100]

## 概念、符号与推导

### Conflict mapping 的完整推导

令 cache 可容纳 `C` 个 slots，最简单的受限放置规则是：[01:09:35–01:10:23]

$$
\operatorname{slot}(i)=i\bmod C.
$$

课堂令 `C=4`，因此：

$$
0\bmod4=0,\qquad4\bmod4=0,\qquad8\bmod4=0,\qquad9\bmod4=1.
$$

对于 working set `{0,4,8}`：

1. Working-set size 为 3，而 cache capacity 为 4，故不是“3 个 blocks 总体装不进 4 个 slots”的 capacity 问题。[01:10:23–01:10:38]
2. 三个 block 的 placement result 都是 slot 0，故它们不能同时驻留。[01:10:38–01:10:55]
3. 若访问在 0、4、8 之间反复，每次新 block 都覆盖 slot 0 的旧 block；回访旧 block 时便 miss。[01:10:55–01:11:19]

由此得到区分条件：

$$
|W|\le C\ \text{但多个 active blocks 映射到同一受限位置}
\quad\Longrightarrow\quad\text{conflict misses}.
$$

该条件与上一段的 `|W| > C → capacity misses` 形成对照；课堂尚未给出 associativity 或更复杂 placement policy，因此不在这里扩展。

### 不同 cache 的统一描述维度

| Cache type | What is cached | Where cached | Latency（课件/口述） | Managed by |
|---|---|---|---:|---|
| Registers | `4–8 byte` words | CPU core | `0 cycles` / instruction 内 | Compiler |
| TLB | Address translations | On-chip TLB | `0 cycles`（课件表） | Hardware MMU |
| L1 cache | `64-byte` blocks | On-chip L1 | `4 cycles` | Hardware |
| L2 cache | `64-byte` blocks | On-chip L2 | `10 cycles` | Hardware |
| Virtual memory | `4-KB` pages | Main memory | `100 cycles` | Hardware + OS |
| Buffer cache | Parts of files | Main memory | `100 cycles` | OS |
| Disk cache | Disk sectors | Disk controller | `100,000 cycles` | Disk firmware |
| Network buffer cache | Parts of files | Local disk | `10,000,000 cycles` | NFS client |
| Browser cache | Web pages | Local disk | `10,000,000 cycles` | Web browser |
| Web cache | Web pages | Remote server disks | `1,000,000,000 cycles` | Web proxy server |

表中项目和数值来自课件 p.57；老师在口述中重点展开 registers、TLB、L1/L2、OS buffer、network 与 browser rows，没有逐项讲解其余 rows。[课件: 11-memory-hierarchy.pptx p.57]

## 例子与课堂提示

- **0、4、8 争 slot 0**：用“容量有 4、工作集只有 3，却仍每次 miss”隔离 conflict 与 capacity 两种原因。[01:10:23–01:11:19]
- **课件的 0/8 交替序列**：把同一冲突压缩到两个 blocks，说明只要 placement 相同，甚至很小的 working set 也可持续 miss。[课件: 11-memory-hierarchy.pptx p.56]
- **Registers 也算 cache**：打破“cache 只指 L1/L2 SRAM”的狭义理解，并展示管理者可以是 compiler。[01:11:36–01:12:24]
- **OS file cache**：再次读取已加载 file 的 bytes 时从 main memory 返回，服务于 locality 跨软件层仍然成立。[01:13:24–01:14:10]
- **Browser cache**：local disk 相对 remote network server 是较近、较快的一层，说明同一 cache abstraction 可跨越数百万乃至十亿 cycle 的 latency 层级。[01:14:18–01:14:44] [课件: 11-memory-hierarchy.pptx p.57]

## 易错点

- Blocks 0、4、8 都映射到 slot 0，不是因为它们编号“接近”，而是因为除以 4 的余数相同。[01:09:35–01:10:23]
- Conflict miss 的判据不是 cache 已满；该例总容量足够，失败来自 placement restriction。[01:10:23–01:11:19]
- “Managed by” 不只指硬件：register cache 由 compiler 管理，buffer cache 由 OS 管理，browser cache 由 browser 管理。[01:11:59–01:14:32]
- 课件表中的 latency 单位是 cycles，而且属于课堂所用层次示例；不要把 `4`、`10`、`100` 等数字当成所有机器的永恒常数。[课件: 11-memory-hierarchy.pptx p.57]
- 课件 p.59–66 是 supplemental slides；本讲转录在 p.58 总结与下一讲预告处结束，没有在 008 中把 supplemental DRAM 内容冒充为老师本段讲授。[01:14:44–01:15:34.100]
