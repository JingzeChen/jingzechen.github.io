## 学习目标

完成本讲后，应能：

1. 解释程序优化的两层路线：先消除跨机器普遍存在的低效与编译器阻塞，再依据现代处理器结构暴露指令级并行。
2. 说明优化编译器为什么必须保持程序行为，并据此判断过程调用副作用、分离编译和内存别名为何会阻止转换。
3. 从源码和生成代码中识别代码移动、强度削减、公共子表达式、重复过程调用和重复内存读写。
4. 用 `lower`/`strlen` 例子推导隐藏的二次复杂度，用 `sum_rows` 例子构造内存别名反例。
5. 使用 CPE（cycles per element）比较线性向量程序，并区分固定开销与每元素增量成本。
6. 区分操作延迟（latency）与发射间隔（cycles/issue），解释超标量、乱序执行和流水线如何利用独立操作。
7. 从归约计算的依赖图推导延迟界限，说明普通循环展开为何可能无效，以及重关联、多累加器为何能缩短关键路径。
8. 说明展开因子 $L$、并行累加器数 $K$、吞吐界限之间的关系，并读懂本讲的标量性能表。
9. 说明 YMM/AVX2 如何用 SIMD 同时处理多个数据元素，以及它相对标量代码的性能与可移植性边界。
10. 解释分支预测、推测执行、误预测失效、寄存器重命名和流水线重新装填之间的因果链。

## 先修知识

本讲直接承接此前的机器代码内容，默认能够：

- 阅读基本 x86-64 汇编，理解加载、存储、整数/浮点算术、比较与条件跳转。
- 理解 C 的数组、指针、指针算术、过程调用、局部变量和空字符结尾字符串。
- 理解行主序二维数组索引 $i n+j$。
- 使用渐近复杂度分析循环和函数调用的组合成本。
- 区分源代码表达式、编译器转换和机器实际执行这三个层次。
- 理解浮点运算会发生舍入；本讲据此说明浮点加法和乘法不能默认按严格结合律重排。

## 教学主线与概念依赖

本讲的依赖链按老师实际展开顺序如下：

```text
读懂机器代码
  -> 检查编译器实际生成了什么
  -> 理解编译器必须保持行为、遇疑保守
  -> 写编译器友好的代码
       -> 代码移动 / 强度削减 / 公共子表达式
       -> 消除循环中的重复过程调用
       -> 用局部累加器解除内存别名阻塞
  -> 得到干净的 combine4 基准
  -> 用 CPE 测量剩余成本
  -> 建立现代 CPU 的超标量、乱序、流水线模型
  -> 区分 latency 与 cycles/issue
  -> 从单累加器依赖链得到 latency bound
  -> 循环展开只减控制开销
  -> 重关联 / multiple accumulators 暴露 ILP
  -> 增大 L、K，逼近 throughput bound
  -> AVX2/SIMD 进一步利用数据级并行
  -> 分支预测维持前端供给
  -> 误预测失效、回滚并重新装填流水线
```

其中有三条必须贯穿全讲的判断线：

1. **语义线：** 转换是否对所有允许的输入、指针关系和副作用保持行为？
2. **依赖线：** 下一项运算是否必须等待上一项结果，还是存在可并行的独立工作？
3. **测量线：** 当前性能受软件开销、操作延迟，还是功能单元/加载吞吐限制？

## 总课堂笔记：严格按老师顺序

### 1. 从机器代码素养到性能优化 `00:00:00-00:02:59`（课件 p.1-p.3）

老师从“已经学会读机器代码”出发，提出本讲问题：算法已经确定、程序已经能够运行后，怎样让它更快。完整教材内容占一章，本课只用一讲，因此重点不是穷举技巧，而是建立分析路线。

优化分两层：

1. 先避免会让程序在很多机器上都变慢的写法，使代码更“编译器友好”。
2. 再依据目标机器的乱序执行、流水线、功能单元和向量能力做更具体的调优。

课件 p.3 提醒，性能不仅是渐近复杂度；算法和数据表示最重要，但过程、循环和常数因子也可能造成约 `10:1` 的差距。优化还必须兼顾模块性、通用性和可读性。

### 2. 编译器优化的职责与根本限制 `00:03:01-00:05:57`（课件 p.4-p.5）

现代程序默认由编译器生成机器代码，而不是由程序员手写汇编。程序员的任务是理解编译器擅长和不擅长什么，并用汇编检查实际结果。

编译器可以改善寄存器分配、指令选择与调度、死代码消除以及程序到机器的映射，但有一个不可绕过的约束：**优化后的程序必须保持标准允许的程序行为。** 因此：

- 静态分析看不到运行时输入的全部性质。
- 多数分析局限于过程内；分离编译时，被调过程的最终实现可能不可见。
- 指针可能别名，过程可能有副作用。
- 即使只有病态条件会产生不同结果，也可能禁止转换。

结论是课件 p.5 的原则：有疑问就保守，不做该优化。程序员可以先看生成代码；预期的优化若没有发生，再回到高级语言中重写以提供更清楚的语义，但不应把代码改到不可读。

### 3. 代码移动：把循环不变量移出热点循环 `00:05:57-00:08:38`（课件 p.6-p.7）

行主序二维数组位置 `(i,j)` 的线性索引为：

$$
\operatorname{index}(i,j)=ni+j.
$$

设置固定第 `i` 行时，内层循环只改变 `j`，所以 `n*i` 是循环不变量：

```c
for (j = 0; j < n; j++)
    a[n*i + j] = b[j];
```

可表达为：

```c
long ni = n * i;
for (j = 0; j < n; j++)
    a[ni + j] = b[j];
```

课件 p.7 的 `-O1` 汇编把唯一一次 `imulq` 放在循环标签之前，证明 GCC 已完成代码移动，并把行首地址变成逐项递增的指针。判断是否优化不能只看源码中仍写着乘法，而应看生成代码里乘法位于哪里。

### 4. 强度削减：用递推替代重复乘法 `00:08:38-00:09:56`（课件 p.8）

课件先给出常数乘法例子：

$$
16x\longrightarrow x\ll4.
$$

对逐行处理，外层第 `i` 次的行首为 $ni=i n$，下一行满足：

$$
ni_{i+1}=(i+1)n=ni_i+n.
$$

所以可以从 `ni=0` 开始，每行结束后执行 `ni += n`，以加法递推替代每轮乘法。老师同时提醒，收益依赖机器；课件以整数乘法约 3 周期为背景，不能把“乘法永远昂贵”当成脱离处理器的绝对规则。口述中“乘法或除法转为移位和加法”的句子有重复断裂，精确例子采用 p.8，其他措辞 `[需回听 00:08:38]`。

### 5. 共享公共子表达式：四邻域地址 `00:09:56-00:12:03`（课件 p.9）

二维图像像素 `(i,j)` 的上、下、左、右四邻域自然写法会分别形成 `i*n`、`(i-1)*n`、`(i+1)*n`，共 3 次乘法。先计算中心索引：

$$
inj=in+j,
$$

再得到：

```c
up    = val[inj - n];
down  = val[inj + n];
left  = val[inj - 1];
right = val[inj + 1];
```

乘法由 3 次降为 1 次。这个例子说明，程序员可重写表达方式，让共享部分更明显。学生问代码体积时，老师指出许多优化会以体积换速度，但此例指令反而更少；具体权衡必须看具体转换。

### 6. `lower` 与 `strlen`：隐藏的二次算法 `00:12:57-00:17:59`（课件 p.10-p.15）

原始程序在循环测试中调用 `strlen(s)`：

```c
for (i = 0; i < strlen(s); i++)
    if (s[i] >= 'A' && s[i] <= 'Z')
        s[i] -= ('A' - 'a');
```

把 `for` 展开成 `goto` 控制流后可见，测试每轮都会执行。`strlen` 又必须扫描到 `\0`，单次为 $\Theta(N)$；外层有 $\Theta(N)$ 次测试，所以：

$$
T(N)=\Theta(N)\cdot\Theta(N)=\Theta(N^2).
$$

课件列出 $N+(N-1)+\cdots+1=\Theta(N^2)$；但展示源码始终传入同一个 `s`，且转换不移动指针、不改终止符，因此逐次扫描更直接地可看成约 $N\times N$。两种计数都导出二次结论，细节 `[需回听 00:17:01]`。

实测中，字符串从 `100000` 增到 `200000`，时间约从 `9.55 s` 墏到 `38.20 s`；`500000` 时约 `238.81 s`。小输入会掩盖这一增长。

把长度预先保存：

```c
size_t len = strlen(s);
for (i = 0; i < len; i++)
    /* 转换 s[i] */;
```

现在一次长度扫描加一次字符遍历：

$$
T(N)=\Theta(N)+\Theta(N)=\Theta(N).
$$

### 7. Procedure calls：为什么编译器不自动移动 `strlen` `00:18:00-00:20:43`（课件 p.16）

程序员知道大小写转换不改变字符串长度，但编译器需要证明这一点。它还面对分离编译与潜在替换实现：最终链接的 `strlen` 可能不可见，也可能像课件示例那样更新全局 `lencnt`。若把 $N$ 次调用改成 1 次，副作用次数改变，程序行为就不同。

因此未知过程调用近似黑盒；同样实参不等于编译器可以默认“相同返回值且无其他效果”。可见且安全时，内联可能提供更多分析机会；否则由程序员显式把不变调用移出循环。

### 8. Memory aliasing：为什么 `b[i]` 必须每轮读写 `00:20:43-00:26:22`（课件 p.17-p.20）

原始行求和写法：

```c
for (i = 0; i < n; i++) {
    b[i] = 0;
    for (j = 0; j < n; j++)
        b[i] += a[i*n + j];
}
```

生成的内层循环对每个元素执行：读 `b[i]`、加 `a[...]`、写回 `b[i]`。编译器不能默认 `a` 与 `b` 不重叠；若 `b[i]` 与稍后读取的某个 `a[k]` 同址，中间写回会改变后续输入。

课件意图让 `B` 指向 `A+3`。按展示矩阵与逐次存储语义，第二行求和中的反馈路径为：

$$
0\xrightarrow{+A[3]=3}3
\xrightarrow{+A[4]=3}6
\xrightarrow{+A[5]=16}22.
$$

这里 `B[1]` 与 `A[4]` 同址，第一次部分和写回后，下一次读取 `A[4]` 读到刚写入的 `3`。所以删除中间存储会改变合法调用的可观察结果。

用局部累加器改写：

```c
double val = 0;
for (j = 0; j < n; j++)
    val += a[i*n + j];
b[i] = val;
```

源程序现在明确规定中间和只在局部变量中，整行结束才写 `b[i]`；编译器可令 `val` 常驻寄存器。这不是对所有别名调用都等价的幕后优化，而是程序员明确选择的新语义。

课件 p.18 的声明显示为 `double B[3] = A+3;`，学生现场报告 GCC 4.9 不接受；老师承认课件有误并表示核对，但未当场给出最终修正版。只能确认“让 `B` 与 `A+3` 别名”的意图，精确声明及个别结果 `[需回听 00:27:39]`、`[需回听 00:30:36]`。

### 9. 进入机器相关优化：向量归约基准 `00:31:20-00:34:57`（课件 p.21-p.23）

老师结束“简单优化”，开始利用现代通用处理器普遍具备的乱序执行能力。基准向量对象保存长度和数据指针，访问器每次做边界检查。`data_t` 可替换为 `int`、`long`、`float`、`double`；`OP/IDENT` 选择加法/0 或乘法/1。

最直观的 `combine1` 每轮：

1. 调用 `vec_length(v)`；
2. 调用 `get_vec_element` 并检查边界；
3. 从 `*dest` 读累计值，执行 `OP`，再写回。

统一基准让控制结构保持不变，只改变类型和运算，从而观察不同机器运算的性能。

### 10. CPE：用斜率表达每元素成本 `00:34:57-00:36:54`（课件 p.24）

对长度为 $n$ 的线性处理程序：

$$
T(n)=\mathrm{CPE}\cdot n+\mathrm{Overhead}.
$$

- `Overhead` 是与长度无关的固定成本，对应截距。
- CPE 是运行周期关于元素数的斜率，表示增加一个元素带来的周期增量。
- 本基准每元素做一次 `OP`，所以也可理解为 cycles per operation。

周期比秒更直接地连接代码结构和处理器内部工作；CPU 频率决定每周期时长，而 CPE 描述每元素需要多少周期。课堂没有展开拟合算法或误差分析。

### 11. 从 `combine1` 到 `combine4`：先移除非本质开销 `00:36:54-00:39:50`（课件 p.25-p.27）

课件数据：

| 方法 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| `combine1` 未优化 | 22.68 | 20.02 | 19.98 | 20.18 |
| `combine1 -O1` | 10.12 | 10.12 | 10.17 | 11.14 |
| `combine4` | 1.27 | 3.01 | 3.01 | 5.01 |

`combine4` 做三项基础变换：

1. 把 `vec_length(v)` 移出循环。
2. 直接取得底层数据指针，避免逐元素访问器和重复边界检查。
3. 用局部变量 `t` 累加，最后才写 `*dest`，解除潜在别名造成的内存往返。

明显的软件开销移除后，不同运算仍出现 `1.27/3.01/3.01/5.01 CPE`。这组数字成为新问题：剩余限制来自哪里？

### 12. 超标量乱序执行与指令级并行 `00:39:50-00:44:52`（课件 p.28-p.29）

现代 CPU 不是严格“取一条、完成一条、再取下一条”。超标量乱序处理器会：

1. 从顺序指令流中尽量多取入并解码操作；
2. 跟踪数据依赖和输入就绪状态；
3. 把相互独立的操作动态发射到多个功能单元；
4. 通过退休等机制，使内部乱序对外仍呈现正确的程序状态。

线性指令流背后更像一片计算“森林”：有真依赖边的节点必须等待，无依赖且资源可用的节点可以重叠。这里讨论的是单个核心内部的 ILP，不是多核并行。

老师还把寄存器名解释为生产者与消费者之间的值标签：结果可直接转发给依赖者，不一定先写入架构寄存器文件再读出。

### 13. Pipeline：延迟大于 1，不等于每隔多周期才能启动 `00:44:52-00:49:48`（课件 p.30-p.31）

功能单元可分成多个流水阶段。操作离开阶段 1 进入阶段 2 后，阶段 1 就能接收下一项独立操作。因此必须区分：

- **Latency：** 一项操作从开始到结果可被依赖者使用的周期数。
- **Cycles/Issue：** 相邻独立同类操作最短隔多少周期可启动。

三级乘法流水线例子：

```c
long p1 = a * b;
long p2 = a * c;
long p3 = p1 * p2;
```

`p1` 与 `p2` 独立，可相隔 1 周期进入流水线；`p3` 必须等待二者结果。三个延迟均为 3 周期的乘法因此共需 7 周期，而非完全串行的 9 周期。

课件 p.31 的 Haswell 表：

| 指令类别 | 延迟 | Cycles/Issue |
|---|---:|---:|
| Load / Store | 4 | 1 |
| Integer Multiply | 3 | 1 |
| Integer / Long Divide | 3-30 | 3-30 |
| Single / Double FP Multiply | 5 | 1 |
| Single / Double FP Add | 3 | 1 |
| Single / Double FP Divide | 3-15 | 3-15 |

多数乘加运算虽然结果需多个周期，却能每周期启动独立操作；除法既慢，又没有充分做到每周期发射。p.31 列出的加载、存储、整数和浮点能力有物理单元共享，不能把数量直接相加成同周期可全部兑现的操作数。

### 14. `combine4` 的 latency bound：单累加器制造串行链 `00:50:01-00:51:36`（课件 p.32-p.33）

`combine4` 的更新为：

$$
x_{i+1}=x_i\ \mathrm{OP}\ d_i.
$$

下一次运算必须读取上一次刚产生的 `x`，形成长度约为 $N$ 的真依赖链。若 `OP` 延迟为 $D$：

$$
T(N)\approx ND,\qquad \mathrm{CPE}\approx D.
$$

所以整数乘测得 `3.01` 对应延迟 3，双精度加 `3.01` 对应延迟 3，双精度乘 `5.01` 对应延迟 5。功能单元即使可以每周期发射独立操作，这条程序依赖链也没有独立操作可供它使用。

### 15. Loop unrolling 2×1：减少控制开销，但不缩短依赖链 `00:51:36-00:53:24`（课件 p.34-p.35）

2×1 表示每轮处理 2 个元素、仍只有 1 个累加器：

```c
x = (x OP d[i]) OP d[i+1];
```

主循环步长改为 2，尾部循环处理不能整除的剩余元素。循环比较与跳转约减半，但两个 `OP` 仍串行，下一轮仍依赖本轮最终的 `x`。

| 方法 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| `combine4` | 1.27 | 3.01 | 3.01 | 5.01 |
| Unroll 2×1 | 1.01 | 3.01 | 3.01 | 5.01 |

只有整数加从 `1.27` 降到 `1.01`，因为它原本接近 1 周期，控制开销仍可见；其余三列完全不变。结论：**展开减少循环开销，不自动创造 ILP。**

### 16. Reassociation 2×1a：移动括号，把关键路径减半 `00:53:24-00:56:45`（课件 p.36-p.38）

把：

```c
x = (x OP d[i]) OP d[i+1];
```

改为：

```c
x = x OP (d[i] OP d[i+1]);
```

每对输入可先独立计算：

$$
p_k=d_{2k}\ \mathrm{OP}\ d_{2k+1},
$$

串行的 `x` 链只剩约 $N/2$ 个节点：

$$
T(N)\approx\left(\frac{N}{2}+1\right)D,
\qquad
\mathrm{CPE}\to\frac{D}{2}.
$$

实测整数乘、双精度加、双精度乘分别达到 `1.51/1.51/2.51`，与 $3/2,3/2,5/2$ 吻合。老师先口误说关键路径缩短十倍，随即改正为两倍。

语义边界同样重要：课堂模型下的固定字长整数加法/乘法可按模运算重排；浮点运算有舍入和溢出，不满足严格结合律。程序员可依据应用容差决定是否接受，保守编译器不能默认自动改变浮点组合顺序。

### 17. Multiple accumulators 2×2：建立两条独立归约流 `00:56:45-00:59:57`（课件 p.37、p.39-p.41）

吞吐界限来自有限的执行和加载资源。2×2 用两个累加器分别处理偶数位与奇数位：

```c
x0 = x0 OP d[i];
x1 = x1 OP d[i+1];
```

两条链彼此独立，最后执行 `x0 OP x1`。每条链长度约 $N/2$，所以同样得到：

$$
T(N)\approx\left(\frac{N}{2}+1\right)D,
\qquad
\mathrm{CPE}\to\frac{D}{2}.
$$

| 方法/界限 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| Unroll 2×1 | 1.01 | 3.01 | 3.01 | 5.01 |
| Unroll 2×1a | 1.01 | 1.51 | 1.51 | 2.51 |
| Unroll 2×2 | 0.81 | 1.51 | 1.51 | 2.51 |
| Latency bound | 1.00 | 3.00 | 3.00 | 5.00 |
| Throughput bound | 0.50 | 1.00 | 1.00 | 0.50 |

整数加还能从 `1.01` 降到 `0.81`，因为独立流能更好利用两个加载能力。Latency bound 是某条依赖链的限制，不是不可突破的总体硬件极限；增加独立链后，瓶颈转向 throughput bound。

### 18. 一般化为 $L\times K$：用足够多独立链逼近吞吐界 `00:59:57-01:01:16`（课件 p.42-p.45）

- $L$：每轮展开处理的元素数。
- $K$：并行维护的累加器数。
- 课堂实现要求 $L$ 是 $K$ 的倍数，以均匀分配元素。

延迟侧的近似为：

$$
\mathrm{CPE}_{\text{latency}}\approx\frac{D}{K}.
$$

连同资源限制，可写成课堂模型：

$$
\mathrm{CPE}\gtrsim
\max\left(\frac{D}{K},\ \mathrm{ThroughputBound}\right).
$$

这不是所有长度上的精确等式；短向量固定开销、尾部处理和调度会造成偏差。增加 $K$ 也不能无限加速：达到功能单元或加载吞吐后收益停止。

双精度乘法中，$K=1$ 时无论 $L$ 多大都保持约 `5.01`；沿 $K=L$ 增加独立流后，`K=10,L=10` 达到 `0.51`，几乎贴住 `0.50` 吞吐界。整数加较早受每元素一次加载限制，最佳约 `0.54`。

课件 p.45 的最佳标量结果：

| 指标 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| 最佳实测 | 0.54 | 1.01 | 1.01 | 0.52 |
| Latency bound | 1.00 | 3.00 | 3.00 | 5.00 |
| Throughput bound | 0.50 | 1.00 | 1.00 | 0.50 |

最高 `42×` 来自未优化整数加与最佳标量整数加：

$$
\frac{22.68}{0.54}=42.
$$

它是编译选项、消除通用阻塞和重构依赖链共同带来的端到端改善，不是单一展开技巧的收益。

课件 p.44 左上仍标 `FP *`，老师明确说本页实际是整数加；同页又写吞吐界 `1.00`，与 p.40、p.45 和约 `0.54` 的结果冲突。概念主线采用跨页一致的 `0.50`，源错误保留 `[需回听 01:00:37]`。

### 19. AVX2/YMM 与 SIMD `01:01:16-01:06:08`（课件 p.46-p.48）

Haswell 有 16 个 YMM 寄存器，每个 32 字节（256 位），可解释为：

- 32 个 8 位整数；
- 16 个 16 位整数；
- 8 个 32 位整数；
- 8 个单精度浮点数；
- 4 个双精度浮点数。

向量指令对多个 lane 执行相同操作，将标量之外的数据级并行交给硬件。老师提到 AVX-512 时先把 512 位误说成 256 字节，随后修正为 64 字节。

课件 p.48：

| 指标 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| 最佳标量 | 0.54 | 1.01 | 1.01 | 0.52 |
| 最佳向量 | 0.06 | 0.24 | 0.25 | 0.16 |
| 向量吞吐界 | 0.06 | 0.12 | 0.25 | 0.12 |

整数加的 `0.06` 应理解为约 $0.0625=1/16$ CPE。向量版本并非每列都达到理论界，但均显著快于最佳标量版本。

老师将 SIMD 的典型动机放在视频、图像、信号处理和游戏图形等大量同构数据操作。显式向量扩展更依赖机器和编译器；课堂对 2015 年 Intel 编译器与 GCC 自动向量化能力的评价只能作为当时语境，不能外推为今天的结论。p.48 的整数加 `Latency Bound=0.50` 与 p.45 的 `1.00` 冲突，概念主线采用前文推导与 p.45，原表冲突 `[需回听]`。

### 20. 分支预测：让取指前端持续供给执行单元 `01:06:08-01:09:42`（课件 p.49-p.54）

乱序执行要保持功能单元忙碌，指令控制单元必须提前生成足够多操作。遇到条件分支时，真实方向要等分支/整数单元计算后才知道；若前端停等，执行单元会断粮。

处理器因此预测 taken 或 not taken，从预测地址继续取指并推测执行。预测正确时确认工作；预测错误时，错误路径的结果必须可撤销，不能提前成为不可逆的架构状态。

循环尾部通常连续预测 taken：前 $N-1$ 次正确，把短循环在前端拼成长指令流；退出时会错一次。课件以长度 100 的双精度乘法循环示意，错误方向上的 `i=100/101` 指令可能已取入，部分可能已执行，但尚未提交。

### 21. 误预测恢复与寄存器重命名 `01:09:42-01:12:28`（课件 p.54-p.55）

预测错误后，处理器取消错误路径上已取入甚至已执行的指令。概念上，它维护：

- 已确认、可作为恢复点的寄存器状态；
- 尚待提交的推测寄存器更新。

寄存器重命名单元可为同一个架构寄存器名保留旧值和连续多个待定版本。老师用“数百个内部寄存器”的量级描述这种版本存储，但没有指定为某个处理器的固定参数。误预测时丢弃错误路径版本，恢复最近的确定映射，从正确地址重新取指、解码并填充流水线。

因此误预测成本不只是丢掉几条指令，还包括重定向和重新达到满速的多个周期；课堂未给统一固定罚时。条件移动不改变取指方向，因而在合适场景下可避免这种控制流中断，但老师并未把它说成总优于分支。

课件 p.52 说推测执行“不实际修改寄存器或内存数据”，口述又说保留多个推测寄存器更新；可按“不会修改已提交架构状态，但会写内部待定版本”理解，字面冲突保留 `[需回听]`。

### 22. 全讲收束 `01:12:28-01:13:28`（课件 p.56）

第一层是写编译器友好的代码：

1. 使用合适的编译器和优化选项。
2. 警惕 `strlen` 一类隐藏算法低效。
3. 识别过程调用副作用与内存别名这两类优化阻塞。
4. 重点检查承担大部分工作的最内层循环。

第二层是按现代机器结构调优：

1. 暴露指令级并行，缩短串行依赖链。
2. 在语义允许时使用重关联和多个累加器。
3. 利用适当的数据并行能力。
4. 避免不可预测分支。

课件还列出 cache-friendly，但明确留到后续课程，本讲没有教授具体缓存优化方法，不能在这里补写。老师指出 ARM 手机处理器、x86 笔记本和课程 Shark 机器都具有相似的乱序、流水或并行执行思想；具体 $L,K$ 和向量 ISA 会变化，但“给硬件足够多独立工作”的原则较通用。

## 关键比较表

### 编译器阻塞与程序员动作

| 阻塞 | 编译器为什么不能直接优化 | 本讲中的程序员动作 |
|---|---|---|
| 未知过程调用 | 可能有副作用，最终实现可能在当前编译单元不可见 | 把不变调用显式移出循环；可见且安全时让分析有机会内联 |
| 内存别名 | 两个不同引用可能同址，中间写入可能改变后续读取 | 用局部变量累计，最后一次写回，明确改变源级可观察性 |
| 浮点重关联 | 舍入和溢出使不同结合顺序可能产生不同结果 | 由了解应用容差的程序员决定是否接受 |

### 三种展开/归约结构

| 结构 | 每轮元素 | 累加器 | 关键效果 |
|---|---:|---:|---|
| 2×1 普通展开 | 2 | 1 | 减少循环控制，不缩短串行依赖链 |
| 2×1a 重关联 | 2 | 1 | 每对输入先独立组合，串行链约减半 |
| 2×2 多累加器 | 2 | 2 | 建立两条独立归约流，最后合并 |

## 易错点总表

1. **只看大 O，不看常数和热点循环。** 本讲既强调算法，也用 CPE 解释相同算法下的巨大常数差异。
2. **只看源码，不看生成代码。** 源码中的乘法可能已被移出循环；要检查汇编中的实际位置。
3. **认为编译器足够聪明就会做所有数学等价变换。** 它必须证明语言语义下的行为等价，而不是只看程序员意图。
4. **把函数调用当成常数成本。** `strlen` 的线性扫描嵌入线性循环会产生二次工作。
5. **认为参数名不同就不会别名。** 运行时地址关系不由变量名保证。
6. **把局部累加器当成纯粹幕后优化。** 在别名反例中，它改变了中间状态的可观察性，必须由程序员承担语义意图。
7. **把 CPE 当成一次运行的总秒数。** CPE 是周期数关于元素数的斜率。
8. **把 latency 与 cycles/issue 混为一谈。** 依赖链受延迟限制；独立流可利用较短发射间隔。
9. **认为流水线等于复制多个完整功能单元。** 流水线让同一功能单元的不同阶段同时处理不同操作。
10. **认为循环展开必然加速。** 若仍只有一条依赖链，普通展开可能只减少跳转。
11. **把 latency bound 当成不可突破的总体极限。** 增加独立链可越过单链延迟界，直到受 throughput bound 限制。
12. **忽略展开后的尾部。** 长度不能整除 $L$ 时必须处理剩余元素。
13. **认为整数与浮点都可任意重关联。** 本讲明确把浮点结果变化作为编译器保守的理由。
14. **认为 $L$ 与 $K$ 是同一个参数。** $L$ 控制每轮元素数，$K$ 控制独立依赖链数；只增 $L$ 可能无效。
15. **认为 $K$ 越大就无限加速。** 达到执行或加载吞吐界后收益停止，短输入开销还会增加。
16. **把 42× 归因于一个技巧或 SIMD。** 42× 是未优化源码到最佳标量版本的端到端比值，向量化在其后。
17. **把 YMM 的 32 字节误写成 32 位。** 32 字节等于 256 位。
18. **把课件 p.44、p.48 的冲突数字静默修正。** 必须保留源错误与 `[需回听]`，并说明采用哪条跨页一致主线。
19. **认为错误路径已执行就不可撤销。** 推测结果未提交，可通过版本失效回滚。
20. **给分支误预测填写固定罚时。** 本讲只说多个周期且可能主导性能，没有统一数值。
21. **把缓存优化当成本讲内容。** p.56 只预告后续覆盖。

# 第一段：从机器代码素养到编译器友好的优化

> 时间范围：`00:00:00-00:09:56`  
> 主要课件：10-optimization.pptx p.1-p.8  
> 来源：课堂转录、课件；以下内容按老师实际讲授顺序整理。

## 本段在整讲中的作用

本段把前几讲的机器代码知识转化为一个新的实践问题：程序已经选定算法并能够运行之后，怎样利用对编译、机器指令和处理器的理解，让它运行得更快。老师先给出整讲的两层路线：第一层是消除跨机器普遍存在的低效写法，使源代码更“编译器友好”；第二层才是根据一类处理器的实现能力做机器相关调优 `[00:00:00-00:02:59]`（课件 p.1-p.3）。本段随后解释编译器为什么必须保守，并依次引入代码移动与强度削减，为下一段的公共子表达式、过程调用阻塞以及后半讲的指令级并行奠定共同前提。

## 教学展开

### 1. 从“能读机器代码”转向“能优化程序” `[00:00:00-00:00:53]`

老师先承接已经结束的机器代码系列：理解汇编并不是终点，而是让学生能够检查编译器究竟生成了什么。本讲对应教材第 5 章的程序性能优化，但课堂只安排一讲，也没有专门实验；相关内容通常只以少量旧考试题出现。这里的课堂目标不是发明新算法，而是在“算法已知、程序已工作”的前提下追问如何让程序更快（课件 p.1）。

### 2. 性能优化分层进行 `[00:00:53-00:02:59]`

老师把优化分成两层。

1. **先消除普遍低效。** 写代码时避免那些会让程序在多种机器上都变慢的结构，使代码更容易被编译器优化。这类习惯要求程序员知道编译器擅长什么、不擅长什么 `[00:01:06-00:01:53]`。
2. **再适配机器能力。** 清掉本不该存在的开销后，再考虑目标机器能提供什么，例如后文的乱序执行、流水线和向量指令 `[00:01:53-00:02:23]`。
3. **控制机器特化程度。** 即使都属于 x86，不同型号也会并存并持续演化。过度针对某一型号调优，迁移后可能失效；不过本讲稍后使用的若干一般方法可覆盖相当广的一类机器 `[00:02:23-00:02:59]`。

课件 p.2 把这条路线展开为：一般有用的优化（代码移动/预计算、强度削减、共享公共子表达式、删除不必要的过程调用），优化阻塞因素（过程调用、内存别名），指令级并行，以及条件分支。课件 p.3 进一步强调：性能不只有渐近复杂度，常数因子也可能因写法产生约 `10:1` 的差距；优化需要同时看算法、数据表示、过程和循环，并理解编译、执行、处理器、内存系统和测量方法。

### 3. 为什么默认依靠编译器，而不是手写汇编 `[00:03:01-00:03:56]`

老师否定“想快就必须写汇编”的旧观念。除资源极受限的小型嵌入式系统等例外，现代程序应假定由编译器生成机器代码。本课使用 GCC，因为它普遍可得且“足够好”；老师同时指出，当时 Intel 的商业编译器在某些优化上更强。这一比较的作用不是推荐某个产品，而是明确后续讨论的对象：程序员与优化编译器怎样协作，而不是程序员取代编译器。

### 4. 编译器优化的根本边界：必须保持程序行为 `[00:03:56-00:05:18]`

老师先从编译器难以推断的信息讲起：变量虽然声明为 `int`，运行时取值范围也许小得多；内存引用模式和过程调用的影响也常常难以静态判断。编译器有一套优化策略，会尝试寄存器分配、指令选择与调度、死代码消除等转换，但一旦不能确信转换保持语义，就退回较直接的实现 `[00:04:27-00:05:07]`（课件 p.4-p.5）。

课件 p.5 把保守性的依据写得更精确：

- 优化不得改变标准程序行为；即使变化只会在病态条件下出现，也可能禁止转换。
- 对程序员显然的事实可能被语言和写法遮蔽。
- 多数分析局限在过程内；全程序分析通常成本过高。当时较新的 GCC 可在单个文件内做过程间分析，但不能据此假定跨文件调用无副作用。
- 编译器主要拥有静态信息，难以预知运行时输入。
- 因而原则是：**有疑问就保守，不做该优化。**

这也解释了课件 p.4 的职责边界：编译器通常改善程序到机器的映射和常数开销，却不会替程序员选择渐近复杂度更优的总体算法；大 O 的改进通常更重要，但常数因子同样值得处理。

### 5. 用汇编结果反查源代码 `[00:05:19-00:05:57]`

机器代码知识在这里成为诊断工具：先让编译器生成代码，查看它实际做了哪些优化；若预期中的转换没有发生，就回到源代码寻找阻塞原因，并在同一种高级语言中重写，使意图更容易证明。老师明确认为这种调优合理，但约束是不能为了速度把程序改得完全不可读。

### 6. 一般优化之一：代码移动/预计算 `[00:05:57-00:08:38]`

老师用行主序二维数组说明。若一行有 `n` 列，位置 `(i,j)` 在线性存储中的索引为：

$$
\operatorname{index}(i,j)=n i+j.
$$

设置第 `i` 行时，内层循环只有 `j` 改变，`n*i` 对所有迭代都相同。原始写法在循环体中表达为（课件 p.6）：

```c
void set_row(double *a, double *b, long i, long n)
{
    long j;
    for (j = 0; j < n; j++)
        a[n*i+j] = b[j];
}
```

代码移动把循环不变量提前计算：

```c
long ni = n * i;
for (j = 0; j < n; j++)
    a[ni + j] = b[j];
```

其正确性前提是被移出的表达式在循环中始终产生同一结果。GCC 在 `-O1` 及以上通常能识别这种数组访问。课件 p.7 的生成代码只在进入循环前执行一次 `imulq %rcx, %rdx`，再计算行首地址；循环内只按元素步进、加载 `b[j]` 并写入目标。老师还指出，编译结果等价于进一步把行首变成指针并逐项递增：

```c
long ni = n * i;
double *rowp = a + ni;
for (j = 0; j < n; j++)
    *rowp++ = b[j];
```

这里不是要求手写指针，而是用汇编证明乘法已被移出热点循环。

### 7. 一般优化之二：强度削减 `[00:08:38-00:09:56]`

老师先提醒，编译器可把某些常数乘除转换为移位与加法，例如课件 p.8 的：

$$
16x \longrightarrow x \ll 4.
$$

随后把 `set_row` 扩展到所有行。即使内层循环已把 `n*i` 移出，外层每次仍重新乘一次。因为相邻行的基址满足：

$$
ni_0=0,\qquad ni_{i+1}=ni_i+n,
$$

所以可以把乘法序列改成加法递推：

```c
int ni = 0;
for (i = 0; i < n; i++) {
    for (j = 0; j < n; j++)
        a[ni + j] = b[j];
    ni += n;
}
```

老师把这种“以更简单、通常更便宜的运算替代昂贵运算”称为 **reduction in strength（强度削减）**。收益依赖机器：课件以 Intel Nehalem 的整数乘法约 3 个周期为例，因此不能脱离目标处理器把“乘法一定很昂贵”当作永恒结论。下一段将从 `[00:09:56]` 起继续共享公共子表达式的图像邻域例子。

## 概念、符号与推导

### 性能优化的两级模型

- **编译器友好的通用优化：** 消除不必要的计算、调用和内存往返，通常跨机器有效。
- **机器相关调优：** 根据执行单元、流水线等能力组织计算；收益更高，但可移植性风险更大。
- **评价优先级：** 先考虑算法的渐近复杂度，再处理常数因子；课件同时提醒常数差异可达到约 `10:1`（课件 p.3-p.4）。

### 编译器保守性

若转换前程序为 $P$、转换后为 $P'$，优化器必须能确信对语言标准允许的输入和状态，二者可观察行为相同。课堂没有把它写成形式化公式；本段实际使用的判断规则是：无法排除别名、副作用或异常边界时，编译器宁可保留原写法（课件 p.5）。

### 行主序索引与代码移动

1. 行 `i` 前有 `i` 行，每行 `n` 个元素，所以行首偏移为 $ni$。
2. 列 `j` 再增加偏移 $j$，得到 $ni+j$。
3. 固定 `i,n`、只改变 `j` 时，$ni$ 是循环不变量。
4. 因此把一次/迭代的乘法降为一次/循环的预计算（课件 p.6-p.7）。

### 强度削减

1. 原外层第 `i` 次使用 $ni=i\cdot n$。
2. 下一次为 $(i+1)n=in+n$。
3. 维护递推变量即可用一次加法替代每轮乘法。
4. 这是操作成本的替换，不改变 $ni$ 的数学值（课件 p.8）。

## 例子与课堂提示

- **二维数组作为统一例子** `[00:06:07-00:06:18]`：索引公式直观，既能显示循环不变量，也能在汇编中看见乘法是否仍在内层循环；服务于“从源代码意图检查生成代码”。
- **GCC `-O1` 实验** `[00:07:42-00:08:38]`：老师不是只宣称编译器会优化，而是用 `imulq` 的位置验证代码移动；服务于“以生成代码为证据”。
- **手写汇编并非默认答案** `[00:03:01-00:03:30]`：现代编译器通常应承担指令生成；服务于建立优化工作的正确层次。
- **可读性约束** `[00:05:34-00:05:57]`：允许重写高级语言代码，但不能把代码调到不可维护；服务于课件 p.3 所说“不破坏模块性和通用性”。
- **机器相关成本** `[00:08:38-00:09:56]`：移位替代常数乘法、加法替代乘法的价值取决于具体指令成本；服务于避免机械套用优化口诀。

## 易错点

1. **把性能只等同于大 O。** 大 O 很重要，但算法相同的程序仍可能有显著常数差距；本讲两者都讨论（课件 p.3-p.4）。
2. **认为编译器“足够聪明”就会做所有等价变换。** 编译器首先要证明行为不变；不能证明时不优化并不是缺陷，而是正确的保守选择。
3. **看到源码中的 `n*i` 就断定每轮都会乘。** 必须查看优化后的生成代码；课件 p.7 表明 `-O1` 已把乘法移出循环。
4. **把强度削减理解成永远用加法/移位替代乘法。** 是否更快依赖处理器，且这里还有明确的序列关系作为正确性依据。
5. **过早针对单一 CPU 型号特化。** x86 内部也有型号差异；应先做广泛有效的代码整理，再根据测量进入机器调优。

# 第二段：公共子表达式与过程调用造成的优化阻塞

> 时间范围：`00:09:56-00:19:53`  
> 主要课件：10-optimization.pptx p.9-p.16  
> 来源：课堂转录、课件；p.11 的原始图表数据经 PPTX 图表对象核对。以下内容按老师实际讲授顺序整理。

## 本段在整讲中的作用

上一段已经说明编译器可自动完成代码移动和强度削减。本段先用二维图像邻域计算补齐第三种一般优化：共享公共子表达式；随后故意转向一个“看起来完全正常”的字符串小写转换程序，揭示隐藏在循环条件中的 `strlen` 会把线性工作变成二次工作。老师再追问为什么编译器不自动把调用移出循环，由此引出本讲第一个核心优化阻塞因素：**过程调用可能有副作用，而且在分离编译下对优化器近似黑盒**。

## 教学展开

### 1. 共享公共子表达式：二维图像四邻域 `[00:09:56-00:12:03]`

老师延续二维数组索引，设图像按行主序存成一维数组 `val`，希望取得像素 `(i,j)` 的上、下、左、右四个邻居并求和。自然写法分别计算四个地址（课件 p.9）：

```c
up    = val[(i-1)*n + j];
down  = val[(i+1)*n + j];
left  = val[i*n + j-1];
right = val[i*n + j+1];
sum = up + down + left + right;
```

直接看表达式，会出现 `i*n`、`(i-1)*n`、`(i+1)*n` 三个乘法。关键观察是四个地址都可由中心索引

$$
inj=i n+j
$$

导出：

```c
long inj = i*n + j;
up    = val[inj - n];
down  = val[inj + n];
left  = val[inj - 1];
right = val[inj + 1];
sum = up + down + left + right;
```

于是乘法数由 3 个降为 1 个；其余位置通过加减偏移得到。课件 p.9 同时给出对应汇编对比：原式有三条 `imulq`，重写后只有 `imulq %rcx, %rsi` 计算 `i*n`，再用 `subq`、`leaq` 等形成邻居地址。老师把这作为“程序员重写表达方式，让编译器更容易识别共享部分”的例子。虽然现代乘法约需 3 个周期，不再像早期机器那样极昂贵，但能把 3 次乘法降到 1 次仍通常有利 `[00:11:47-00:11:58]`。

### 2. 课堂问答：速度与代码体积是否冲突 `[00:12:03-00:12:57]`

学生问如果目标是节省空间怎么办。老师承认很多优化会用更大代码换取速度，但这个例子反而生成更少的指令，因此速度和体积并不冲突。他以早期 IBM PC 最大配置约 640 KB 内存说明代码体积过去更敏感；现代程序中，代码通常只占整体存储的一小部分。不过他仍把“优化空间”视为有效问题，而不是一概忽略。

### 3. 从编译器擅长的低层优化转向隐藏算法低效 `[00:12:57-00:13:46]`

老师总结：代码写得合理时，编译器通常擅长上述低层转换；但有些问题即使最先进的编译器也未必能修复。为说明这一点，他展示 1998 年第一次开设 15-213 时从学生实验中发现的代码：老师、助教以及许多有经验的 C 程序员第一眼都没有看出问题（课件 p.10）。这个铺垫强调后面的错误不是语法错误，而是非常容易漏掉的性能错误。

### 4. `lower` 的表面意图与实测异常 `[00:13:46-00:15:25]`

程序逐字符扫描字符串，把 `'A'` 到 `'Z'` 范围内的字符改为小写：

```c
void lower(char *s)
{
    size_t i;
    for (i = 0; i < strlen(s); i++)
        if (s[i] >= 'A' && s[i] <= 'Z')
            s[i] -= ('A' - 'a');
}
```

从业务意图看，它只需访问每个字符一次，理应是线性工作。但实测曲线随字符串长度呈二次增长：课件 p.11 的原始散点数据中，`N=100000` 时约 `9.552553 s`，`N=200000` 时约 `38.204385 s`，`N=500000` 时约 `238.807323 s`。长度翻倍，时间约变为 4 倍；老师口述半百万字符约需 240 秒，即约 4 分钟 `[00:14:17-00:14:52]`。

这类问题的危险在于小规模测试会掩盖它：若只测试不超过一万字符，绝对时间仍可能很小，直到真实输入触发坏情况才突然暴露 `[00:14:53-00:15:20]`。

### 5. 把 `for` 展开成控制流，发现 `strlen` 每轮调用 `[00:15:25-00:16:38]`

问题位于循环测试 `i < strlen(s)`。初始化只执行一次，但测试和更新会在每次迭代执行。课件 p.12 用 `goto` 形式把这一点显式化：

```c
size_t i = 0;
if (i >= strlen(s))
    goto done;
loop:
if (s[i] >= 'A' && s[i] <= 'Z')
    s[i] -= ('A' - 'a');
i++;
if (i < strlen(s))
    goto loop;
done:
```

因此，对长度为 $N$ 的字符串，循环测试会反复调用 `strlen`，调用次数与 $N$ 同阶。

### 6. `strlen` 本身线性，嵌套后得到二次复杂度 `[00:16:38-00:17:13]`

课件 p.13 给出简化实现：

```c
size_t strlen(const char *s)
{
    size_t length = 0;
    while (*s != '\0') {
        s++;
        length++;
    }
    return length;
}
```

以空字符结尾的 C 字符串没有单独保存长度，`strlen` 只能从传入地址扫描到 `\0`，单次代价为 $\Theta(N)$。外层又执行 $\Theta(N)$ 次测试，因此总体为：

$$
T(N)=\Theta(N)\cdot\Theta(N)=\Theta(N^2).
$$

课件文字把扫描工作列为 $N,N-1,N-2,\ldots,1$，对应：

$$
N+(N-1)+\cdots+1=\frac{N(N+1)}{2}=\Theta(N^2).
$$

但展示的源码每次都调用 `strlen(s)`，且只改字符、不移动 `s`、不改结尾空字符，因此每次实际都从同一地址扫描整串，更直接的计数是约 $N\times N$。两种计数不影响二次结论，但源中的细节差异列入待核对项。

### 7. 手工代码移动：预先保存长度 `[00:17:14-00:17:59]`

字符串长度在大小写转换期间不变，因此把调用移出循环（课件 p.14）：

```c
void lower(char *s)
{
    size_t i;
    size_t len = strlen(s);
    for (i = 0; i < len; i++)
        if (s[i] >= 'A' && s[i] <= 'Z')
            s[i] -= ('A' - 'a');
}
```

现在只有一次 $\Theta(N)$ 的长度扫描，加上一次 $\Theta(N)$ 的转换循环：

$$
T_{\text{lower2}}(N)=\Theta(N)+\Theta(N)=\Theta(N).
$$

课件 p.15 把新版本标为线性性能，并注明字符串长度翻倍时运行时间翻倍。老师口述说新版本短到在前一张二次曲线的尺度上几乎看不见，处理约一百万字符“也许一秒” `[00:17:34-00:17:44]`。p.15 在 PPTX 中是静态图形，没有可读取的原始数值系列，因此这里不把图上位置解释成额外的精确测量点。

### 8. 为什么编译器不能放心自动移动 `strlen` `[00:18:00-00:19:53]`

老师最后把性能修复转成编译器正确性问题。

1. 循环体正在修改 `s` 指向的内容。程序员知道只改变字母大小、不改变 `\0`，但编译器必须证明修改不会改变 `strlen(s)` 的结果 `[00:18:29-00:18:54]`。
2. C 文件通常分别编译，之后才链接，部分绑定甚至在程序启动后完成。编译当前文件时，优化器未必知道最终链接的是哪一个 `strlen` 实现 `[00:19:04-00:19:36]`。
3. 被调用过程可能有副作用。课件 p.16 给出的自定义版本除返回长度外，还执行 `lencnt += length`。若把 $N$ 次调用改成 1 次，全局状态就不同，程序行为被改变。

因此，过程调用周围的优化较弱：编译器必须把未知调用视为黑盒，不能凭“标准库函数通常如此”擅自假定无副作用。课件 p.16 给出的补救方向是：在可见且安全时使用内联（当时 GCC `-O1` 可在单个文件内做一些处理），或者由程序员自己完成代码移动。

## 概念、符号与推导

### 公共子表达式

- 公共中心：$inj=in+j$。
- 四邻域：上 `inj-n`，下 `inj+n`，左 `inj-1`，右 `inj+1`。
- 成本变化：索引形成中的乘法由 3 次降为 1 次（课件 p.9）。
- 正确性前提：数组确实按每行 `n` 个元素的行主序布局，且所访问邻居处于合法范围；本段聚焦地址复用，没有展开边界处理。

### `lower1` 的复杂度

- 外层转换循环执行 $N$ 次量级。
- `strlen` 每次从字符指针扫描到空字符，单次为 $\Theta(N)$。
- 因而总复杂度为 $\Theta(N^2)$；长度翻倍时主导项约扩大 4 倍（课件 p.11-p.13）。

### `lower2` 的复杂度

- 预计算 `strlen`：$\Theta(N)$。
- 转换每个字符：$\Theta(N)$。
- 总计仍为 $\Theta(N)$；长度翻倍时主导时间约扩大 2 倍（课件 p.14-p.15）。

### 过程调用阻塞

“相同实参的调用会返回相同值且没有其他效果”并不是 C 编译器可默认采用的前提。若调用可能读写全局状态、修改参数可达内存，或最终链接实现未知，则把调用移出循环可能改变返回值序列或副作用次数（课件 p.16）。

## 易错点

1. **只看循环体，忽略 `for` 的测试表达式。** `strlen(s)` 位于测试中，所以不是只执行一次。
2. **把函数调用当成常数时间语法。** 调用成本由被调函数决定；`strlen` 必须扫描字符串。
3. **看到每个字符只改一次，就断定整体为 $O(N)$。** 每轮隐藏的 $O(N)$ 测试使总工作变成 $O(N^2)$。
4. **认为标准函数名足以让编译器假定无副作用。** 分离编译和链接替换意味着最终实现未必在当前优化单元中可见。
5. **把“程序员知道长度不变”与“编译器能证明长度不变”混为一谈。** 循环体修改了同一块内存，证明必须覆盖所有可能行为。
6. **机械采用课件的 $N,N-1,\ldots,1$ 扫描次数解释展示源码。** 该源码始终传 `s`，更自然的逐次扫描长度都是 $N$；两者都导出二次复杂度，但细节不可混写。

3. **问：把 `strlen` 结果保存到 `len` 后，复杂度怎样变化？**

# 第三段：内存别名为何迫使编译器保留读写

> 时间范围：`00:19:53-00:29:53`  
> 主要课件：10-optimization.pptx p.16-p.21  
> 来源：课堂转录、课件；以下内容按老师实际讲授顺序整理。

## 本段在整讲中的作用

本段先完成上一段的过程调用结论：未知函数可能有副作用，所以编译器不能把 `strlen` 调用擅自移出循环。随后老师用 `sum_rows1` 展示第二类优化阻塞因素：两个不同的 C 指针可能指向同一内存位置，即 **memory aliasing（内存别名）**。别名可能让写 `b[i]` 同时改变稍后读取的 `a[...]`，因此编译器必须在每轮真实地读写内存。程序员通过局部累加器把中间状态放入寄存器，既明确了意图，也解除这项约束。段末的课堂问答又暴露课件示例声明本身有疑点，老师没有当场完成核验，必须标为 `[需回听 00:27:39]`，不能替源修正成已确认事实。

## 教学展开

### 1. 过程调用阻塞的最终结论 `[00:19:53-00:20:43]`

老师承接自定义 `strlen`：如果函数除计算长度外还修改全局计数器，那么把循环内的多次调用改为一次会产生不同的程序结果。由于当前编译单元未必能看到最终实现，编译器必须把调用当成可能执行任意副作用的黑盒，不能作“它只返回字符串长度”的假设。因此，即使换到更好的编译器或另一台机器，这个缺少可证明前提的转换仍不会自动发生（课件 p.16）。老师指出自己因长期接触此类问题而容易发现它，但很多程序员不会自然注意到。

### 2. 行求和的直观写法 `[00:20:43-00:21:40]`

新例子要把 $n\times n$ 矩阵 `a` 的每一行求和，写入向量 `b`：

```c
void sum_rows1(double *a, double *b, long n) {
    long i, j;
    for (i = 0; i < n; i++) {
        b[i] = 0;
        for (j = 0; j < n; j++)
            b[i] += a[i*n + j];
    }
}
```

老师明确说这里不是要再次讨论把 `i*n` 移出循环，而是观察 `b[i] += ...` 在机器代码中怎样实现（课件 p.17）。

### 3. 为什么内层循环每次都读写 `b[i]` `[00:21:40-00:22:45]`

课件 p.17 给出的内层汇编为：

```asm
.L4:
    movsd   (%rsi,%rax,8), %xmm0  # 读取 b[i]
    addsd   (%rdi), %xmm0         # 加 a[i*n+j]
    movsd   %xmm0, (%rsi,%rax,8)  # 写回 b[i]
    addq    $8, %rdi
    cmpq    %rcx, %rdi
    jne     .L4
```

每次迭代除了读取一个 `a` 元素，还把同一个 `b[i]` 从内存读入 XMM 寄存器、相加、再写回。表面上，上一次写出的值正是下一次要读的值，似乎完全可以一直留在寄存器中。但编译器若没有额外信息，不能证明 `a` 与 `b` 的存储区域互不重叠。

### 4. 内存别名的定义与反例 `[00:22:45-00:24:41]`

老师把 **aliasing** 定义为：程序中两个看似不同的内存引用实际指定同一个位置。C 允许地址运算并直接操作存储结构，因此这种情况合法且常见，静态别名分析虽会尽量排除不可能的重叠，但一般情况下仍必须假定重叠可能发生（课件 p.18、p.20）。

课件 p.18 意图让 `B` 指向 `A` 从索引 3 开始的位置，即让结果向量覆盖矩阵第二行。按幻灯片展示的初始矩阵：

$$
A=[0,1,2,4,8,16,32,64,128],\qquad B\text{ 指向 }A+3.
$$

如果按 `sum_rows1(A,B,3)` 的逐次存储语义追踪：

1. 初始 `B=[4,8,16]`。
2. `i=0`：先令 `B[0]=0`，它同时把 `A[3]` 改为 0；但第 0 行仍是 `0,1,2`，累加后 `B[0]=3`，所以 `B=[3,8,16]`。
3. `i=1`：先令 `B[1]=0`，即把 `A[4]` 改为 0。随后第 1 行当前为 `3,0,16`。由于每轮都把部分和写回 `B[1]`，而 `B[1]` 本身就是 `A[4]`，读到中间元素时会把已经累积的值再次作为矩阵元素加入。逐步为 `0+3=3`，再 `3+A[4](=3)=6`，再 `6+16=22`，故 `B=[3,22,16]`。
4. `i=2`：先令 `B[2]=0`，即把 `A[5]` 改为 0；第 2 行是 `32,64,128`，不与该写入位置重叠，最后得到 `224`，故 `B=[3,22,224]`。

这组看似奇怪但可观察的结果正是编译器不能省略每轮存储的理由：若把 `b[i]` 私自留在寄存器中，`i=1` 时就不会通过 `A[4]` 读到中间和，结果将改变。

### 5. 用局部累加器明确“中间值不应暴露” `[00:24:41-00:25:17]`

程序员可以主动改写为（课件 p.19）：

```c
void sum_rows2(double *a, double *b, long n) {
    long i, j;
    for (i = 0; i < n; i++) {
        double val = 0;
        for (j = 0; j < n; j++)
            val += a[i*n + j];
        b[i] = val;
    }
}
```

现在源程序语义本身规定：中间和只存在于局部变量 `val`，整行完成后才写 `b[i]`。编译器可把 `val` 分配到寄存器，内层循环简化为一次内存操作数加法和循环控制：

```asm
.L10:
    addsd   (%rdi), %xmm0  # 读取 a 元素并加到寄存器 val
    addq    $8, %rdi
    cmpq    %rax, %rdi
    jne     .L10
```

它不再每轮读写 `b[i]`。老师预告内存访问本身会成为性能限制，因此这种改写会显著更快。

### 6. 编程习惯：用局部变量消除两类阻塞 `[00:25:17-00:26:22]`

老师把前两个例子合并成一个习惯：不要在热点循环中重复调用结果不变的函数，也不要反复读写同一个内存位置；把不变结果或中间累计值显式存入局部变量。局部变量通常会被分配到寄存器，这等于向编译器提供更强的语义保证。至此，两大通用优化阻塞因素被点明：

- 过程调用及其未知副作用；
- 内存引用可能发生别名。

课件 p.20 的措辞是，局部累加器是程序员告诉编译器“不必为这个中间值检查别名”的方式。课件 p.21 随后预告下一阶段：利用现代处理器可并行执行多条指令的能力，但性能仍受数据依赖约束。

### 7. 关于课件别名声明的课堂争议 `[00:26:22-00:27:47]`

学生质疑幻灯片上的 C 声明。课件 p.18 抽取出的文字为：

```c
double B[3] = A+3;
```

老师起初坚持这是合法 C，并从“一维数组 `A`、`A+3` 指向第 4 个元素、数组名在表达式中可当作只读地址值”解释 `[00:26:50-00:27:36]`。随后学生报告 GCC 4.9 对“这段完全相同的代码”报错，老师答应再核对 `[00:27:39-00:27:47]`。因此课堂并未在本段确认声明的正确形式；只能确认示例**意图**是让 `B` 与 `A+3` 别名。

### 8. 旁支问答：为什么 C 使用空字符结尾字符串 `[00:27:48-00:29:53]`

老师认为 C 的这一决定可能有多种缺点，但把它放回语言设计目标理解：C 由长期写汇编的系统程序员设计，目标是在机器级编程之上提供最薄、可移植的抽象，而不是提供尽可能丰富的高层数据结构。因此 C 数组本身不携带边界和长度，也不默认做边界检查；空字符结尾字符串符合这种“最小机制”取向 `[00:28:09-00:29:11]`。

随后有人比较 Pascal。老师强调 Pascal 是 Niklaus Wirth 为教学设计的语言，而 C 面向专业系统程序员、尽量不妨碍其操作机器；两者设计哲学不同 `[00:29:16-00:29:49]`。这一问答不改变别名结论，但帮助解释为何 C 的指针、数组和字符串表示会把更多正确性与性能责任交给程序员。

## 概念、符号与推导

### 内存别名

若两个表达式 `p` 与 `q` 在运行时满足：

$$
\operatorname{addr}(p)=\operatorname{addr}(q),
$$

则经由一个引用的写入会影响经由另一个引用的读取。课堂没有引入形式化别名集合；实际判断是：`a`、`b` 都由外部指针传入，编译器不能默认它们指向不相交区域（课件 p.18-p.20）。

### `sum_rows1` 的可观察中间状态

原循环每次都执行：

$$
b_i\leftarrow b_i+a_{in+j}.
$$

如果 `b_i` 与某个尚未读取的 $a_k$ 是同一位置，则本轮写入改变后续输入。故将多次存储合并成一次并非对所有合法指针关系都等价。

### `sum_rows2` 的语义变化

改写后是：

$$
val\leftarrow\sum_{j=0}^{n-1}a_{in+j},\qquad b_i\leftarrow val.
$$

这不只是编译器在背后做的临时优化，而是程序员明确选择“中间和不可通过 `b[i]` 被观察”的源程序语义。若调用者故意依赖 `sum_rows1` 的别名反馈行为，两版本结果可能不同；老师把该反馈行为视为通常无用，但它仍是合法语义约束。

### 别名反例中 `22` 的来源

`i=1` 时 `B[1]` 与 `A[4]` 同址：

$$
0\xrightarrow{+A[3]=3}3
\xrightarrow{+A[4]=3}6
\xrightarrow{+A[5]=16}22.
$$

第二步读到的 `A[4]=3` 正是第一步刚写入 `B[1]` 的部分和。这一反馈路径证明逐次存储不可被通用编译器删除。

## 易错点

1. **认为两个参数名不同就不会重叠。** `a` 和 `b` 是运行时传入的地址，名字不构成不相交保证。
2. **把寄存器累加当作编译器必然会做的局部改写。** 对 `sum_rows1`，该改写会在别名情况下改变可观察行为，编译器不能通用地执行。
3. **认为内存读写只是多余开销，没有语义。** 在反例中，每次写回会改变后续的 `a` 输入，正是程序结果的一部分。
4. **认为 `sum_rows1` 与 `sum_rows2` 对所有调用都等价。** 它们只在结果区域不以相关方式覆盖输入等前提下等价；改写是程序员承担该意图。
5. **把课件的 `double B[3] = A+3;` 当作已验证代码。** 课堂现场有人报告编译失败，老师只答应核对；必须标疑，而不是自行洗掉争议。
6. **把数组名“可衰减为指针”误推成“可用一个指针初始化数组对象”。** 这是课堂争议的核心，源并未在此给出确认结论。

## 教学展开

### 1. 继续核对别名示例中的课件错误 `[00:29:53-00:31:20]`

老师回应学生，承认幻灯片 p.18 “那里有一个错误”，但仍认为示例的运算逻辑可能正确；若声明有误，他口头提出可把 `B` 写成指向 `A+3` 的形式 `[00:30:11-00:30:24]`。另一位学生认为某个结果应为 `28`，老师没有现场手算，而是约定课后共同检查 `[00:30:24-00:30:52]`。有人问数组分配在栈上是否影响结论，老师明确回答分配位置与这里的别名行为无关 `[00:30:56-00:31:10]`。

### 2. 从“简单优化”转向机器相关优化 `[00:31:20-00:32:28]`

老师总结：代码移动、避免重复调用、局部累加等方法本身简单，难点是养成习惯。接下来进入更“高级”、更依赖系统的部分：除最原始的微控制器外，现代处理器普遍具有某种乱序执行能力，因此将要展示的总体方法仍能跨多种机器工作 `[00:31:38-00:32:12]`（课件 p.21）。

教学方法是从低效代码出发，一步步重写并测量，最终获得约 40 倍加速 `[00:32:13-00:32:23]`。课件 p.21 提前给出核心因果链：硬件能够并行执行多条指令，但实际性能受数据依赖限制；简单源代码变换可暴露指令级并行，而浮点不满足结合律/分配律等事实会阻止编译器自动执行某些变换。

### 3. 建立带长度信息的向量抽象 `[00:32:28-00:33:59]`

老师构造一种类似 Pascal 数组的抽象：对象同时保存长度与数据地址，访问器负责边界检查（课件 p.22）：

```c
typedef struct {
    size_t len;
    data_t *data;
} vec;

int get_vec_element(vec_ptr v, size_t idx, data_t *val)
{
    if (idx >= v->len)
        return 0;
    *val = v->data[idx];
    return 1;
}
```

调用者传入向量、索引和输出地址；访问成功返回 `1`，越界返回 `0`。`data_t` 是可替换类型，分别编译为 `int`、`long`、`float`、`double`，用来观察不同数据类型的性能特征。

### 4. 统一的归约基准：加法或乘法 `[00:33:59-00:34:57]`

基准任务是把向量全部元素组合起来，或者求和，或者求积。老师使用两个宏参数（课件 p.23）：

- 加法：`OP` 为 `+`，单位元 `IDENT` 为 `0`；
- 乘法：`OP` 为 `*`，单位元 `IDENT` 为 `1`。

四种数据类型乘两种运算，共 8 种配置。最直观的 `combine1` 为：

```c
void combine1(vec_ptr v, data_t *dest)
{
    long i;
    *dest = IDENT;
    for (i = 0; i < vec_length(v); i++) {
        data_t val;
        get_vec_element(v, i, &val);
        *dest = *dest OP val;
    }
}
```

每轮都调用 `vec_length`、通过访问器取元素并做边界检查，再从 `*dest` 读取累计值、执行运算并写回。

### 5. 定义 CPE：把固定开销与每元素成本分离 `[00:34:57-00:36:54]`

老师引入 **CPE（cycles per element，每元素周期数）**。对长度为 $n$ 的线性向量处理程序，运行周期可近似表示为（课件 p.24）：

$$
T(n)=\mathrm{CPE}\cdot n+\mathrm{Overhead}.
$$

- `Overhead` 是函数调用、循环建立等与 $n$ 无关的固定成本，即直线截距。
- `CPE` 是直线斜率，表示再增加一个元素所增加的周期数；本基准每个元素做一次 `OP`，所以也可理解为 cycles per operation。

老师解释为何用周期而不是秒或纳秒：程序员无法控制目标 CPU 恰好运行在 2 GHz 还是 2.3 GHz，但可以通过代码结构影响一项工作需要多少内部时钟周期。CPE 因而更直接地连接代码与微体系结构。课件 p.24 用两个前缀和版本示例说明斜率，分别标为 `9.0` 与 `6.0`。

### 6. `combine1` 基线：编译选项先带来约 2 倍改善 `[00:36:54-00:37:41]`

老师先比较同一份 `combine1` 源码在未优化与 `-O1` 下的结果。课件 p.25 的完整 CPE 表为：

| 方法 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| `combine1`，未优化 | 22.68 | 20.02 | 19.98 | 20.18 |
| `combine1 -O1` | 10.12 | 10.12 | 10.17 | 11.14 |

因此口述中的“约 20 CPE 降到约 10 CPE”不是抽象估计，而是四种配置的共同量级。仅启用第一个实质优化级别，就大致把时间减半；但循环仍保留访问抽象和大量冗余。

### 7. `combine4`：先移除循环内的非本质开销 `[00:37:41-00:39:07]`

老师不逐个展示中间版本，而是直接给出基础优化后的 `combine4`（课件 p.26）：

```c
void combine4(vec_ptr v, data_t *dest)
{
    long i;
    long length = vec_length(v);
    data_t *d = get_vec_start(v);
    data_t t = IDENT;
    for (i = 0; i < length; i++)
        t = t OP d[i];
    *dest = t;
}
```

变换按课堂顺序包含三项：

1. 把 `vec_length(v)` 移出循环，只计算一次长度。
2. 直接取得底层数据指针 `d`，不再每个元素调用访问器和重复边界检查；循环上界已由同一个 `length` 控制。
3. 用局部变量 `t` 累加，最后才写 `*dest`，避免潜在别名迫使每轮读写目的内存。

所有后续结果都使用 `-O1`。课件 p.27 给出的 CPE 为：

| 方法 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| `combine1 -O1` | 10.12 | 10.12 | 10.17 | 11.14 |
| `combine4` | 1.27 | 3.01 | 3.01 | 5.01 |

这说明通用优化已经消掉循环内的大部分软件开销，但四种运算不再具有相同成本。

### 8. 新问题：`1.27`、`3.01`、`5.01` 从哪里来 `[00:39:07-00:39:50]`

老师不满足于“已经快很多”，而是追问这些数字是否反映程序的根本限制。整数乘约 `3.01 CPE`，双精度乘约 `5.01 CPE`，整数加约 `1.27 CPE`；它们与具体硬件能力存在明显联系。要判断还能否继续优化，就必须理解底层处理器。老师提到更高阶体系结构课程会完整讲处理器设计，但本讲只需要一个足以解释性能界限的简化模型（课件 p.28）。

## 概念、符号与推导

### 参数化归约

对向量 $d[0],\ldots,d[n-1]$，`combine1/combine4` 计算：

$$
x=\mathrm{IDENT}\ \mathrm{OP}\ d[0]\ \mathrm{OP}\ d[1]\cdots \mathrm{OP}\ d[n-1].
$$

其中加法单位元为 0，乘法单位元为 1。相同控制结构配合 4 种 `data_t` 和 2 种 `OP`，得到 8 个实验实例（课件 p.22-p.23）。

### CPE 的斜率含义

取两个足够大的长度 $n_1,n_2$，线性模型下：

$$
\mathrm{CPE}\approx\frac{T(n_2)-T(n_1)}{n_2-n_1}.
$$

固定开销在差分中抵消。课堂强调的是斜率解释；没有在本段展示拟合算法或测量误差分析。

### 基础优化的量级

以双精度乘为例：

$$
\frac{11.14}{5.01}\approx2.22
$$

表示从 `combine1 -O1` 到 `combine4` 又约快 2.22 倍；相对未优化基线：

$$
\frac{20.18}{5.01}\approx4.03.
$$

整数加的基础优化更显著：

$$
\frac{22.68}{1.27}\approx17.86.
$$

这些比值只基于课件 p.25、p.27 同一组 CPE；老师本段口述主要使用“20→10→约 1 到 5”的量级，没有逐项报出上述比值。

### 基础优化后的待解释界限

`combine4` 已把大部分函数、边界和内存累计开销移走。剩余 CPE 随运算变化，形成可检验假设：热点循环可能受运算本身的延迟或处理器执行资源约束。下一段将用超标量乱序执行和流水线区分“完成一项运算需多久”与“能多密集地启动运算”。

## 易错点

1. **用一次短输入的总秒数代替 CPE。** 总时间混入固定开销；CPE 是随 $n$ 增长的斜率。
2. **认为 CPU 频率就是代码效率。** 频率决定每周期多长，而 CPE 描述完成每个元素需要多少周期；二者角色不同。
3. **把 8 种实验误认为 8 份不同算法。** 它们共享同一归约结构，只改变 4 种类型和 2 种运算。
4. **把边界检查全部视为无价值。** `combine4` 能绕过它，是因为循环由同一向量长度控制；这是基准中的特定安全理由，不是普遍删除检查的许可。
5. **只启用 `-O1` 就认为优化完成。** `combine1 -O1` 仍约 10 CPE；源级消除重复调用、检查和内存累计后才到 `1.27-5.01 CPE`。
6. **看到 `combine4` 的差异就直接归因于“指令条数”。** 后文会证明串行数据依赖和功能单元延迟才是多个值的主因。

# 第五段：超标量乱序执行、流水线与两种硬件速率

> 时间范围：`00:39:50-00:49:48`  
> 主要课件：10-optimization.pptx p.28-p.31  
> 来源：对应 `summary-input.jsonl` 切片、课堂逐字稿、`materials/10-optimization.pptx` 及 p.31 原始渲染；以下内容按老师实际讲授顺序整理。

## 本段在整讲中的作用

上一段把 `combine4` 压缩到一个加载、一次归约运算和循环控制，却仍测得不同运算对应 `1.27-5.01 CPE`。本段提供解释这些数字所需的最小处理器模型。老师先纠正“CPU 严格逐条完成指令”的直觉，说明现代单核会从顺序指令流中动态发现独立操作并乱序执行；再解释功能单元内部的流水线，使“一个运算从头到尾需若干周期”与“相邻运算可以每隔多久启动”成为两个不同指标。Haswell 表把这两个指标量化，下一段将据此证明：`combine4` 不是缺少流水硬件，而是源程序的数据依赖链把它锁在延迟界限上。

## 教学展开

### 1. 只取足够解释性能的处理器模型 `[00:39:50-00:40:32]`

老师说完整处理器设计需要多门先修课，细节庞大且实现困难；本讲不尝试设计处理器，只介绍一个自约 1995 年以来普遍适用的简化模型。这个取舍服务于程序优化：学生只需理解哪些操作可并行、哪些依赖会阻止并行，就能解释和改善 CPE（课件 p.28）。

### 2. 顺序执行直觉是错误的 `[00:40:32-00:40:58]`

朴素模型是“取一条指令、完成它，再取下一条”。老师明确说现代程序实际并非如此执行。处理器投入大量硬件，让执行速度远高于严格一次一条；核心机制是 **superscalar out-of-order execution（超标量乱序执行）**。

### 3. 从线性指令流中抽取指令级并行 `[00:40:58-00:41:50]`

程序的机器指令在文本上是线性序列，但处理器会尽可能多地取入指令，拆成较低层操作，并判断依赖关系。如果较后的操作不依赖当前操作，就可提前开始。这种从顺序程序中发现的并行称为 **instruction-level parallelism（ILP，指令级并行）**。

老师用“森林”描述真实计算结构：表面是一条指令链，内部却是多棵计算树；有些节点依赖前驱，有些彼此独立。处理器的任务不是任意重排，而是在满足依赖的前提下把独立操作分配给空闲硬件。

### 4. 简化数据通路：前端、执行单元与退休 `[00:41:50-00:43:58]`

课件 p.28 的图按信息流可整理为：

1. **取指与控制。** 指令高速缓存向前端供给指令，控制逻辑取指、预测控制流并解码。
2. **操作调度。** 解码后形成操作，硬件跟踪哪些输入已就绪、哪些操作依赖其他结果。
3. **执行功能单元。** 多个算术、分支、加载和存储单元并行工作；数据高速缓存提供部分内存数据的高速副本。
4. **结果与退休。** 操作结果被传递给依赖者，最终按可确认的程序状态更新寄存器/内存；退休单元负责让乱序执行对外仍呈现正确的顺序语义。

老师特别重塑了“寄存器”的直觉：在乱序核心内部，寄存器名更像数据依赖标签，表示某条操作产生的值将被哪些后续操作消费。结果可直接从生产者转发给消费者，不一定先写入架构寄存器文件再读出；状态稳定后才落实为架构可见寄存器值 `[00:43:12-00:43:53]`。

### 5. 超标量的定义与历史定位 `[00:43:58-00:44:52]`

课件 p.29 定义：超标量处理器可在一个周期内发射并执行多条指令；指令来自顺序流，通常动态调度。其收益是程序员无需显式创建线程，硬件就能利用程序中已有的 ILP。

老师举 Intel 历史为定位：1993 年的第一代 Pentium 已可同时处理两条指令；稍后的 Pentium Pro 奠定现代处理器乱序执行模型的基础。这里讨论的是**单个处理器核心内部**的并行，不是多核并行。

### 6. 功能单元也可以流水化 `[00:44:52-00:45:44]`

流水线的前提是把一项运算拆成连续阶段，每个阶段有相应硬件。某个操作从阶段 $i$ 前进到 $i+1$ 后，阶段 $i$ 即可接收下一个操作。于是单项运算的总延迟可以大于 1 周期，同时仍能高频率地启动新运算（课件 p.30）。

老师先用“先乘再加”的简单组合说明分阶段，又强调乘法内部本身也可拆成更细步骤。流水线不是复制整个乘法器，而是让不同操作同时占据同一功能单元的不同阶段。

### 7. 三级乘法流水线：3 个乘法只需 7 周期 `[00:45:44-00:47:20]`

示例代码为（课件 p.30）：

```c
long mult_eg(long a, long b, long c) {
    long p1 = a * b;
    long p2 = a * c;
    long p3 = p1 * p2;
    return p3;
}
```

假设乘法器有 3 个阶段，每个乘法延迟 3 周期：

- 周期 1：`p1=a*b` 进入阶段 1。
- 周期 2：`p1` 进入阶段 2；因阶段 1 空闲，独立的 `p2=a*c` 进入阶段 1。
- 周期 3：`p1` 进入阶段 3，`p2` 进入阶段 2。
- 周期 4：`p1` 完成，`p2` 进入阶段 3。
- 周期 5：`p2` 完成；此时依赖二者的 `p3=p1*p2` 才能进入阶段 1。
- 周期 6、7：`p3` 依次通过阶段 2、3并完成。

若把三个乘法完全串行，需 $3+3+3=9$ 周期；利用前两个乘法的独立性和流水重叠，总共 7 周期。这个例子同时展示两类约束：`p1` 与 `p2` 可重叠，`p3` 因真数据依赖不能提前。

### 8. 流水线并行与多执行单元、多核的区别 `[00:47:20-00:48:30]`

学生问如果有多个乘法器能否让前两个乘法完全同时执行，老师回答可以。随后明确：当前全部讨论发生在单个核心中，是比多核更低层的并行。除最低端、低功耗嵌入式处理器外，某种形式的这种机制普遍存在，而多数程序并没有充分使用硬件。

老师对流水线作总结：它像并行，但不要求多份完整资源；同一份硬件被分成阶段，让操作流以很近的间隔连续进入。

### 9. Haswell 的功能单元资源 `[00:48:30-00:49:20]`

老师以 Intel Haswell 为例。课件 p.31 标注 8 个总功能单元，同时列出它们可提供的能力：

- 2 个加载能力，含地址计算；
- 1 个存储能力，含地址计算；
- 4 个整数运算能力；
- 2 个浮点乘法能力；
- 1 个浮点加法能力；
- 1 个浮点除法能力。

这些数字不能简单相加成可同周期全部执行的操作数，因为部分能力共享同一物理功能单元；老师当场提醒“它们不能全都同时发生”。重点是单核内部存在大量可并行工作的设备。

### 10. 两个必须分开的指标：Latency 与 Cycles/Issue `[00:49:20-00:49:48]`

老师定义一项操作的两种时间特征：

- **Latency（延迟）**：从该操作开始到结果可供依赖者使用，需要多少周期。
- **Cycles/Issue（发射间隔）**：同类独立操作之间最短可以隔多少周期启动；流水化后可远小于延迟。

课件 p.31 的表为：

| 指令类别 | 延迟（周期） | Cycles/Issue |
|---|---:|---:|
| Load / Store | 4 | 1 |
| Integer Multiply | 3 | 1 |
| Integer / Long Divide | 3-30 | 3-30 |
| Single / Double FP Multiply | 5 | 1 |
| Single / Double FP Add | 3 | 1 |
| Single / Double FP Divide | 3-15 | 3-15 |

例如浮点乘法的单项结果要 5 周期才完成，但独立乘法可每周期发射一个。`[00:49:37-00:49:48]` 老师只来得及概括多数运算虽需多个周期却可按 1 周期间隔流水发射；除法为何不同留到下一段开头。

## 概念、符号与推导

### 指令级并行与数据依赖

若操作 $B$ 需要操作 $A$ 的结果，则有真依赖边 $A\to B$，$B$ 不可在结果就绪前开始。若两操作之间无依赖且资源可用，乱序核心可重叠执行。ILP 就是依赖图中可同时推进的操作量，而不是源代码中显式线程的数量。

### 流水线总时间

对深度 $D=3$、发射间隔 $I=1$ 的流水乘法器，若有 $m$ 个彼此独立的乘法连续进入，完成时间理想为：

$$
T_{\text{independent}}=D+(m-1)I.
$$

前两个独立乘法用 $3+(2-1)\cdot1=4$ 周期完成到最后一个结果。第三个乘法依赖两者，只能在其后启动，再付 3 周期，总计 7 周期（课件 p.30）。

### 延迟与吞吐的区别

若某运算延迟为 $L$，发射间隔为 $I$：

- 一条依赖链上的下一项必须等待约 $L$ 周期；
- 多条独立运算流在资源允许时可按约 $I$ 周期启动；
- 当 $L>I$ 时，暴露独立操作才能填满流水线。

Haswell 的整数乘为 $(L,I)=(3,1)$，双精度浮点乘为 $(5,1)$；这正为后续“为什么 `combine4` 测到约 3 和 5 CPE”提供候选解释。

### 多种并行的层次

- **多个功能单元：** 多份或多类硬件可在同一周期工作。
- **流水线：** 单个功能单元的不同阶段同时处理不同操作。
- **乱序执行：** 动态调度独立操作去使用这些资源。
- **多核：** 多个核心并行，本段明确不讨论这一层。

## 易错点

1. **认为乱序执行会违反程序语义。** 它只在依赖允许时重排内部操作，并通过退休机制维持架构可见的正确状态。
2. **把源代码顺序等同于硬件完成顺序。** 后面的独立操作可先开始，关键约束是依赖图而非文本位置。
3. **把流水线理解成多个完整乘法器。** 流水线共享一套分阶段硬件；多个完整单元是另一种并行来源。
4. **看到延迟 5 就断定最多每 5 周期做一次浮点乘。** Haswell 浮点乘 `Cycles/Issue=1`；独立操作可每周期启动，只是各自结果 5 周期后才就绪。
5. **把 p.31 列出的能力全部相加，认为可同周期全部兑现。** 一些能力共享物理功能单元，老师明确否定这种相加。
6. **把本段并行归因于多核。** 全部例子都在单个核心内部。

# 第六段：突破延迟界限：展开、重关联与多累加器

> 时间范围：`00:49:48-00:59:44`  
> 主要课件：10-optimization.pptx p.31-p.41  
> 来源：对应 `summary-input.jsonl` 切片、课堂逐字稿、`materials/10-optimization.pptx` 及 p.35、p.37、p.40 原始渲染；以下内容按老师实际讲授顺序整理。

## 本段在整讲中的作用

上一段区分了运算延迟与发射间隔。本段把这两个量用于 `combine4`，解释为什么流水化乘法器仍没有自动带来高吞吐：单个累加变量制造了一条不可断开的真依赖链，CPE 因而贴着运算延迟。老师依次试验三种变换：普通 2×1 循环展开只减少循环控制；右重关联把每两个输入先独立组合，将关键路径减半；2×2 多累加器建立两条独立归约流。教学重点不只是“哪个版本更快”，而是从计算依赖图推导延迟界限和吞吐界限，并辨认浮点语义为何限制编译器自动重排。

## 教学展开

### 1. 除法是流水化表中的例外 `[00:49:48-00:50:01]`

老师先补完课件 p.31：整数/长整数除法的延迟与发射间隔都约为 `3-30` 周期，浮点除法约为 `3-15`；与乘加不同，除法既慢，也没有做到每周期启动一项的充分流水化。因此“延迟大”与“吞吐低”可能同时存在。后面的归约实验聚焦加法和乘法，不使用除法。

### 2. `combine4` 的单累加器形成串行链 `[00:50:01-00:51:36]`

以整数乘法为例，课件 p.32 给出内层汇编：

```asm
.L519:                         # Loop
    imull  (%rax,%rdx,4), %ecx # t = t * d[i]
    addq   $1, %rdx            # i++
    cmpq   %rdx, %rbp          # length:i
    jg     .L519
```

关键不是循环里有多少条指令，而是 `%ecx` 的下一次乘法必须读取上一次乘法刚产生的新 `%ecx`。对长度 8 的乘法归约，计算结构为（课件 p.33）：

$$
x=((((((((1\cdot d_0)\cdot d_1)\cdot d_2)\cdot d_3)\cdot d_4)\cdot d_5)\cdot d_6)\cdot d_7).
$$

每个乘法节点依赖前一个节点，无法把下一次乘法按 `Cycles/Issue=1` 提前送入流水线。若运算延迟为 $D$，长向量稳态下：

$$
T(N)\approx N D,\qquad \mathrm{CPE}\approx D.
$$

这就是 **latency bound（延迟界限）**。实测整数乘 `3.01 CPE` 对应延迟 3，双精度加 `3.01` 对应延迟 3，双精度乘 `5.01` 对应延迟 5。硬件有流水线，但程序自己的数据依赖迫使乘法串行。

### 3. 普通 2×1 循环展开 `[00:51:36-00:52:35]`

老师引入 **loop unrolling（循环展开）**：一次循环处理多个元素。2×1 表示每轮处理 2 个元素、仍使用 1 个累加器（课件 p.34）：

```c
void unroll2a_combine(vec_ptr v, data_t *dest)
{
    long length = vec_length(v);
    long limit = length - 1;
    data_t *d = get_vec_start(v);
    data_t x = IDENT;
    long i;

    for (i = 0; i < limit; i += 2)
        x = (x OP d[i]) OP d[i+1];

    for (; i < length; i++)
        x = x OP d[i];
    *dest = x;
}
```

主循环每轮做两倍有效工作，循环索引、比较和跳转次数约减半；第二个循环处理奇数长度剩下的 1 个元素。展开因子可以不止 2，但尾部处理不可遗漏。

### 4. 为什么普通展开只帮助整数加 `[00:52:35-00:53:24]`

课件 p.35 的结果为：

| 方法/界限 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| `combine4` | 1.27 | 3.01 | 3.01 | 5.01 |
| Unroll 2×1 | 1.01 | 3.01 | 3.01 | 5.01 |
| 延迟界限 | 1.00 | 3.00 | 3.00 | 5.00 |

整数加本来接近 1 周期，循环控制开销仍占可见比例；展开把它从 `1.27` 压到 `1.01`，达到 1 周期延迟界限。其余三列完全不改善，因为表达式仍是：

```c
x = (x OP d[i]) OP d[i+1];
```

每轮内部的第二个运算依赖第一个，下一轮又依赖本轮最终的 `x`；一条长串行链没有缩短。普通展开减少的是控制开销，不自动创造数据并行。

### 5. 只移动括号：2×1a 重关联 `[00:53:24-00:54:28]`

老师提出极小的源代码变化，把括号向右移动（课件 p.36）：

```c
/* 原 2x1 */
x = (x OP d[i]) OP d[i+1];

/* 2x1a：a 表示 associativity transformation */
x = x OP (d[i] OP d[i+1]);
```

完整版本仍每次前进 2 个元素并保留尾部循环，只改变组合顺序。实测（课件 p.37）：

| 方法/界限 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| `combine4` | 1.27 | 3.01 | 3.01 | 5.01 |
| Unroll 2×1 | 1.01 | 3.01 | 3.01 | 5.01 |
| Unroll 2×1a | 1.01 | 1.51 | 1.51 | 2.51 |
| 延迟界限 | 1.00 | 3.00 | 3.00 | 5.00 |
| 吞吐界限 | 0.50 | 1.00 | 1.00 | 0.50 |

整数乘、浮点加、浮点乘几乎恰好快 2 倍；整数加已经受其他资源约束，仍为 `1.01`。

### 6. 重关联为何把关键路径减半 `[00:54:28-00:55:24]`

新结构先计算每对输入：

$$
p_k=d_{2k}\ \mathrm{OP}\ d_{2k+1},
$$

再把各 $p_k$ 依次并入 `x`。不同 $p_k$ 之间互不依赖，可提前进入功能单元；只有 `x` 的累计链保持串行。对 $N$ 个元素、每项运算延迟 $D$，课件 p.38 给出的关键路径约为：

$$
T(N)\approx\left(\frac{N}{2}+1\right)D,
$$

因此：

$$
\mathrm{CPE}=\lim_{N\to\infty}\frac{T(N)}{N}=\frac{D}{2}.
$$

这对应整数乘 $3/2\approx1.5$、浮点加 $3/2\approx1.5$、浮点乘 $5/2\approx2.5$，与 `1.51/1.51/2.51` 实测吻合。老师口头一度说关键路径缩短“十倍”，随即改正为“两倍” `[00:55:05-00:55:08]`。

### 7. 正确性边界：整数可重关联，浮点可能改变结果 `[00:55:24-00:56:45]`

老师先给“好消息”：在固定字长二进制补码的课堂模型中，整数加法和乘法按模运算具有结合性、交换性，改变组合顺序得到相同位级结果。随后给“坏消息”：浮点加法和乘法会舍入，也可能涉及溢出，因此不满足严格结合律。一般地：

$$
(x\ \mathrm{OP}\ a)\ \mathrm{OP}\ b
\ne
x\ \mathrm{OP}\ (a\ \mathrm{OP}\ b)
$$

可能成立。

老师认为许多应用中差异未必实际影响最终用途，但仅“可能不同”就足以让保守编译器拒绝自动改变浮点结合顺序。是否允许该变换必须由了解数值容差的应用程序员判断。

### 8. 从延迟界限转向吞吐界限 `[00:56:45-00:58:30]`

重关联突破了单链延迟后，更根本的下限来自有限执行资源，即 **throughput bound（吞吐界限）**：单位时间最多能发射多少所需运算、加载多少元素。

课件 p.37 给出 Haswell 上本基准的界限：

- 整数加：`0.50 CPE`，最终受每周期 2 个加载等资源约束；
- 整数乘：`1.00 CPE`，受整数乘法吞吐约束；
- 双精度加：`1.00 CPE`，只有 1 个浮点加法吞吐；
- 双精度乘：`0.50 CPE`，有 2 个浮点乘法能力且每个元素需 1 次加载。

老师口述此处有一次自我纠正 `[00:57:13-00:57:58]`，最终要点与表一致：双精度乘可以因两个乘法能力而比双精度加更快，而任何标量版本每元素都要加载一次，两个加载单元给出 `0.5 CPE` 的硬下限。

### 9. 2×2 多累加器：建立两条独立运算流 `[00:58:30-00:59:44]`

另一种重关联方法是把偶数位和奇数位分别累计，最后合并（课件 p.39）：

```c
data_t x0 = IDENT;
data_t x1 = IDENT;

for (i = 0; i < limit; i += 2) {
    x0 = x0 OP d[i];
    x1 = x1 OP d[i+1];
}
for (; i < length; i++)
    x0 = x0 OP d[i];
*dest = x0 OP x1;
```

`x0` 与 `x1` 之间没有循环内依赖，硬件可交错推进两条链。课件 p.40 的结果是：

| 方法/界限 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| Unroll 2×1 | 1.01 | 3.01 | 3.01 | 5.01 |
| Unroll 2×1a | 1.01 | 1.51 | 1.51 | 2.51 |
| Unroll 2×2 | 0.81 | 1.51 | 1.51 | 2.51 |
| 延迟界限 | 1.00 | 3.00 | 3.00 | 5.00 |
| 吞吐界限 | 0.50 | 1.00 | 1.00 | 0.50 |

整数乘、浮点加、浮点乘相对普通 2×1 都约快 2 倍；整数加还从 `1.01` 降到 `0.81`，因为两条流能更好利用两个加载单元。课件 p.41 的依赖图和完整 $D/2$ 推导从下一段继续。

## 概念、符号与推导

### 串行归约的延迟界限

单累加器每次更新：

$$
x_{i+1}=x_i\ \mathrm{OP}\ d_i.
$$

存在逐元素依赖 $x_i\to x_{i+1}$。若 `OP` 延迟为 $D$，则关键路径含 $N$ 个串行操作，`CPE≈D`，不受 `Cycles/Issue=1` 的独立操作吞吐帮助。

### 普通展开不改变关键路径

2×1 每轮写成：

$$
x'=(x\ \mathrm{OP}\ d_i)\ \mathrm{OP}\ d_{i+1}.
$$

虽然循环迭代数减半，但每两个元素仍有两个串行 `OP`，总关键路径节点数仍约 $N$，所以乘法和浮点加法 CPE 不变。

### 右重关联的 $D/2$ 界限

每两元素中，内部 $d_i\ \mathrm{OP}\ d_{i+1}$ 不依赖旧 `x`，可与前后迭代重叠；串行累计链只剩约 $N/2$ 个节点，再加首尾常数项：

$$
T(N)=\left(\frac{N}{2}+1\right)D,\qquad \mathrm{CPE}\to\frac{D}{2}.
$$

### 双累加器的两条链

$$
x^{(0)}_{k+1}=x^{(0)}_k\ \mathrm{OP}\ d_{2k},\qquad
x^{(1)}_{k+1}=x^{(1)}_k\ \mathrm{OP}\ d_{2k+1}.
$$

每条链长度约 $N/2$，二者独立，最后再做一次合并。理想关键路径同样约 $(N/2+1)D$，所以预测 `CPE=D/2`。下一段用 p.41 图继续确认。

### 吞吐界限

若功能单元每周期最多完成/发射 $R$ 个本基准所需操作，则仅从该资源看：

$$
\mathrm{CPE}\ge\frac{1}{R}.
$$

此外每元素需一次加载，Haswell 最多约 2 次加载/周期，所以标量归约还有：

$$
\mathrm{CPE}\ge\frac{1}{2}=0.5.
$$

实际下限取所有必需资源下限中最严格者。

## 易错点

1. **认为有流水乘法器就自动达到 1 CPE。** 单累加器的下一次乘法必须等待上一结果，受延迟而非发射间隔限制。
2. **认为循环展开必然加速所有运算。** 2×1 只减少控制开销，没有改变依赖链；三列 CPE 完全不变。
3. **把右重关联看作“相同代码的编译技巧”。** 它改变运算结合顺序，尤其对浮点可能改变数值结果。
4. **认为整数和浮点都严格满足结合律。** 课堂只把固定字长补码整数视为安全；浮点舍入和溢出会破坏结合性。
5. **把 latency bound 当作不可突破的硬件极限。** 它是特定依赖链的下限；增加独立链可转向更低的 throughput bound。
6. **忽略尾部循环。** 展开因子不能整除长度时，必须处理剩余元素，否则功能错误。
7. **把整数加吞吐界误写成 1.0。** 课件 p.37/p.40 对本基准给的是 `0.50`；其最终瓶颈可来自每周期两个加载。

## 本段掌握检查

1. **问：为什么 `combine4` 的整数乘法约为 3 CPE，尽管乘法可每周期发射一次？**  
   **答：** 每次乘法依赖上一次累加结果，形成串行链；整数乘延迟为 3，因此 CPE 贴近延迟 3（课件 p.31-p.33）。

2. **问：普通 2×1 展开为什么只改善整数加法？**  
   **答：** 它减少循环控制开销，所以将本来接近 1 的整数加从 1.27 降到 1.01；其他运算仍有原长度的串行依赖链（课件 p.34-p.35）。

3. **问：右重关联为何把整数乘、浮点加和浮点乘 CPE 近似减半？**  
   **答：** 每对输入可先独立组合，串行 `x` 链只剩约 $N/2$ 个节点，关键路径给出 `CPE=D/2`（课件 p.36-p.38）。

4. **问：为什么编译器通常不自动对浮点做这种重关联？**  
   **答：** 浮点舍入和溢出使结合顺序可能改变结果；编译器必须保守地保持程序语义。

5. **问：2×2 多累加器相对 2×1 创造了什么？**  
   **答：** 它把偶数位和奇数位分成两条独立依赖链，允许硬件并行推进，理论和实测都接近 `D/2`（课件 p.39-p.41）。

## 本段在整讲中的作用

本段完成标量归约优化，再把数据级并行扩展到 SIMD，最后转向控制流。老师先用奇偶两条依赖链验证双累加器的 $D/2$ 预测，再推广为展开因子 $L$、并行累加器数 $K$，通过不同参数逐步逼近功能单元吞吐界限；最佳标量版本相对最初代码最高约快 42 倍。之后利用 256 位 YMM 寄存器一次处理多个元素，把每元素成本进一步降到 `0.06-0.25 CPE`。但要持续给执行单元供给操作，取指前端还必须穿越条件分支，于是课程进入分支预测和推测执行：预测正确可把循环看成一长串指令，预测错误则必须取消错误路径工作。本段停在错误被发现之处，下一段解释如何依靠寄存器重命名回滚并恢复流水线。

## 教学展开

### 1. 双累加器依赖图与 $D/2$ 预测 `[00:59:44-00:59:57]`

课件 p.41 把 2×2 版本画成两条链：一条组合偶数元素 `d0,d2,d4,d6`，另一条组合奇数元素 `d1,d3,d5,d7`，最后把 `x0` 与 `x1` 合并。两条链各有约 $N/2$ 个延迟为 $D$ 的操作，彼此可并行，尾部再付一次合并：

$$
T(N)\approx\left(\frac{N}{2}+1\right)D,
\qquad
\mathrm{CPE}\to\frac{D}{2}.
$$

这与前一段的实测吻合：整数乘和浮点加从约 `3.01` 到 `1.51`，浮点乘从 `5.01` 到 `2.51`。关键不是偶数/奇数本身，而是建立两个独立的累计状态。

### 2. 推广为 $L$ 路展开、$K$ 个并行累加器 `[00:59:57-01:00:16]`

老师把方法参数化（课件 p.42）：

- 每次主循环处理 $L$ 个元素，即展开因子为 $L$；
- 同时维护 $K$ 个独立累计结果；
- 课堂实现要求 $L$ 是 $K$ 的倍数，以便每轮把 $L$ 个元素均匀分配给 $K$ 条流。

理想情况下，每条依赖链只承担约 $N/K$ 个元素，因此延迟侧给出：

$$
\mathrm{CPE}_{\text{latency}}\approx\frac{D}{K}.
$$

但它不能无限下降：达到执行单元/加载单元吞吐界限后，再增大 $K$ 收益递减；较大的展开还会增加短向量的固定开销，不能整除的尾部仍需顺序处理（课件 p.42）。

### 5. 最佳标量性能与 42 倍改善 `[01:00:58-01:01:16]`

课件 p.45 汇总最佳标量结果：

| 指标 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| 最佳实测 | 0.54 | 1.01 | 1.01 | 0.52 |
| 延迟界限 | 1.00 | 3.00 | 3.00 | 5.00 |
| 吞吐界限 | 0.50 | 1.00 | 1.00 | 0.50 |

四列都已接近吞吐界，而显著低于单链延迟界。课件写“最高 42×”；该数字可由最初未优化整数加与最佳整数加得到：

$$
\frac{22.68}{0.54}=42.0.
$$

老师口述把路径概括为约 `20 CPE -> 10 CPE -> 1 CPE 或更低`。这不是某一个技巧单独带来的，而是编译优化、移除通用阻塞、重构依赖链共同作用。

### 6. YMM 寄存器与 SIMD 数据宽度 `[01:01:16-01:02:55]`

老师接着问标量吞吐是否已是终点，答案是否定的。Haswell 支持 AVX2 的 YMM 寄存器：共 16 个，每个 32 字节（256 位），是此前 Shark 机器上 XMM 宽度的两倍（课件 p.46）。同一个寄存器可解释为：

- 32 个 8 位整数；
- 16 个 16 位整数；
- 8 个 32 位整数；
- 8 个单精度浮点数；
- 4 个双精度浮点数。

普通标量浮点只使用寄存器低端 4 字节（`float`）或 8 字节（`double`）；向量指令则在多个 lane 上同时执行相同操作。课件 p.47 对应单精度一次 8 路、双精度一次 4 路的 SIMD 加/乘。

老师还提到当时即将出现的 AVX-512，先口误说 512 位是 256 字节，随即修正为 64 字节 `[01:01:41-01:02:12]`。

### 7. 向量指令的实测收益 `[01:02:55-01:04:18]`

老师强调向量硬件本来就在芯片上，但普通标量程序很少充分使用。课件 p.48 的结果原样如下；其中 `Latency Bound` 行的整数加 `0.50` 与 p.45 的 `1.00` 冲突，见“待核对项”：

| 指标 | 整数加 | 整数乘 | `double` 加 | `double` 乘 |
|---|---:|---:|---:|---:|
| 最佳标量 | 0.54 | 1.01 | 1.01 | 0.52 |
| 最佳向量 | 0.06 | 0.24 | 0.25 | 0.16 |
| 标量延迟界 | 0.50 | 3.00 | 3.00 | 5.00 |
| 标量吞吐界 | 0.50 | 1.00 | 1.00 | 0.50 |
| 向量吞吐界 | 0.06 | 0.12 | 0.25 | 0.12 |

整数加显示为 `0.06`，老师精确解释应理解为 `0.0625=1/16 CPE`，即约每周期 16 个 32 位整数操作 `[01:03:55-01:04:05]`。向量版本并非每列都达到理论界，例如整数乘 `0.24` 高于 `0.12`，双精度乘 `0.16` 高于 `0.12`；但都显著快于最佳标量版本。

### 8. 向量化的应用与可移植性代价 `[01:04:18-01:06:08]`

老师把 SIMD 的主要动机放在视频、图像、信号处理和游戏图形：这些任务对大量同构数据执行相同运算，显示、旋转和处理速度直接影响体验。熟练程序员会按可向量化方式组织代码。

他以 2015 年课堂语境比较编译器：当时 Intel 编译器能够自动完成部分向量化，而他认为 GCC 的自动尝试效果不佳；教材网站的 Web Aside `OPT:SIMD` 介绍了使用 GCC 扩展显式编程的方法，课件 p.48 也指向该材料。老师用这些扩展获得表中结果，但强调这已经非常机器相关，也绑定特定编译器接口；它展示“追求极限时能做到什么”，不是前半讲那种普遍编码习惯。该编译器能力评价只记录当堂历史说法，不外推到今天。

### 9. 新瓶颈：取指前端如何穿越分支 `[01:06:08-01:07:26]`

课程回到乱序模型。执行单元要保持忙碌，指令控制单元必须提前取入足够多操作；但实际程序常是很短的循环，而不是天然很长的直线指令序列。遇到条件跳转时，前端不能事先确定后续地址（课件 p.49-p.51）：

- **taken（跳转发生）**：转到分支目标；
- **not taken / fall through（不跳转）**：继续下一条顺序指令。

结果通常依赖运行时数据，直到分支/整数单元计算条件后才能确定。若前端停下来等结果，执行单元会缺少工作。

### 10. 分支预测与推测执行 `[01:07:26-01:08:43]`

现代处理器采用 **branch prediction（分支预测）**：猜测分支方向，从预测地址继续取指并执行（课件 p.52）。但推测结果不能造成不可撤销的架构状态；预测正确时确认这些工作，预测错误时必须能撤销。

老师用课件 p.50 的数据通路解释两处职责：上游预测/取指逻辑先猜并持续供给操作，下游分支单元稍后确认“预测正确，可以继续”或报告“此前方向错误，必须修复”。口述中的“way back 100 clock cycles ago”随后收回为“没有那么久，只是若干周期” `[01:08:08-01:08:17]`。

### 11. 循环预测：一直猜 taken，直到退出时猜错 `[01:08:43-01:09:42]`

对循环尾部跳转，预测“taken，回到循环开头”通常很好：前 $N-1$ 次都正确，预测器借此把许多次循环迭代拼成一条长指令流。课件 p.53 用双精度乘法循环说明：

```asm
401029: vmulsd (%rdx), %xmm0, %xmm0
40102d: add    $0x8, %rdx
401031: cmp    %rax, %rdx
401034: jne    401029
```

假设向量长度为 100，`i=98`、`i=99` 时预测 taken 正确；到退出点仍预测 taken，就会继续取入甚至执行 `i=100/101` 方向上的错误路径操作，图中示意读取无效位置。这里必须区分：错误路径指令可能已被 **fetched**，部分也可能已 **executed**，但尚不能作为最终程序状态提交。

课件 p.54 接着标出 **Invalidate**：当真实分支结果表明预测错误，错误方向上的在途操作需要失效。本段转录恰在老师说“what will happen is it will...”时结束，具体如何取消寄存器更新由下一段续讲。

## 概念、符号与推导

### $L\times K$ 展开/累加模型

- 每轮消费 $L$ 个元素。
- 维护 $K$ 条独立累加链。
- 若均匀分配，单链约含 $N/K$ 个运算。
- 延迟主导时：

$$
\mathrm{CPE}\approx\frac{D}{K}.
$$

- 总体受两侧共同约束：

$$
\mathrm{CPE}\gtrsim
\max\left(\frac{D}{K},\ \mathrm{ThroughputBound}\right).
$$

这里的 `≈/≳` 表示课堂性能模型，不是对所有长度的精确等式；尾部、循环控制等会造成偏差。

### 42 倍加速的来源

取课件 p.25 的未优化整数加 `22.68 CPE` 与 p.45 最佳标量整数加 `0.54 CPE`：

$$
S=\frac{22.68}{0.54}=42.
$$

这是同一基准从原始代码到最佳标量版本的端到端比值，不应归功于单独的循环展开。

### SIMD 每元素成本

若一条向量指令同时处理 $W$ 个元素，且向量操作可按每 $I$ 周期发射一次，仅从该资源看：

$$
\mathrm{CPE}_{\text{vector}}\ge\frac{I}{W}.
$$

例如课件给整数加向量吞吐界 `0.06≈1/16`；实际值还需同时满足加载、归约和其他功能单元限制。

### 分支预测的性能条件

预测本身不改变程序语义；它改变的是执行单元是否能持续获得工作。预测正确时，推测工作成为有效工作；预测错误时，错误路径工作被丢弃，并付出恢复流水线的成本。精确恢复代价留到下一段。

## 例子与课堂提示

- **$K=10,L=10` 的双精度乘 `0.51`**（课件 p.43）：服务于显示足够多独立链可把 5 周期延迟隐藏到 0.5 CPE 吞吐附近。

- **视频/图像/游戏** `[01:04:18-01:04:49]`：服务于说明 SIMD 最适合大量同构数据操作。

## 易错点

1. **认为 $K$ 越大 CPE 必然无限下降。** 达到吞吐界后收益停止，短长度和尾部开销还会变大。
2. **把 $L$ 与 $K$ 混为一谈。** $L$ 是每轮处理元素数，$K$ 是独立累计链数；只增 $L$ 不增 $K$ 可能完全不改善延迟链。
3. **照抄 p.44 的 “Throughput bound: 1.00”。** 它与同页测量及 p.40/p.45 冲突；整数加本基准的界限为 `0.50`，源错误需标记。
4. **把 42 倍理解为向量化收益。** p.45 的 42 倍是最佳标量对未优化源码；向量化是其后的额外提升。
5. **把 YMM 32 字节误写成 32 位。** 它是 256 位，可装 8 个 32 位值或 4 个 64 位双精度值。
6. **把 2015 年的 GCC/Intel 编译器评价当作当前能力结论。** 这里只能作为课堂历史语境记录。
7. **认为推测执行已经把错误路径写入最终内存。** 预测未确认前不能提交不可撤销状态；错误路径必须可失效。
8. **认为循环分支一直预测 taken 就永远正确。** 它在大多数迭代正确，但退出迭代会错一次。

## 本段掌握检查

1. **问：一般的 $L\times K$ 方法中，$L$ 与 $K$ 各表示什么，为什么要求 $L$ 是 $K$ 的倍数？**  
   **答：** $L$ 是每轮展开处理的元素数，$K$ 是独立累加器数；倍数关系让每轮元素均匀分配到各链（课件 p.42）。

2. **问：双精度乘从 `5.01` 降到 `0.51 CPE` 的关键是什么？**  
   **答：** 增加到约 10 条独立累加链，把每条链的延迟摊薄，直到接近 `0.50` 的功能单元吞吐界（课件 p.43）。

3. **问：课件的“最高 42×”怎样算出？**  
   **答：** 未优化整数加 `22.68 CPE` 除以最佳标量整数加 `0.54 CPE`，正好为 42（课件 p.25、p.45）。

4. **问：YMM 寄存器一次能装多少个 `float` 和 `double`？**  
   **答：** 32 字节可装 8 个 4 字节 `float` 或 4 个 8 字节 `double`（课件 p.46-p.47）。

5. **问：分支预测为什么是保持执行单元忙碌所必需的，又为什么必须支持撤销？**  
   **答：** 前端必须在分支结果确定前继续取指以形成足够长的操作流；猜测可能错误，所以推测状态不能提前提交，错误路径必须失效（课件 p.49-p.54）。

# 第八段：误预测回滚、寄存器重命名与全讲收束

> 时间范围：`01:09:42-01:13:28`  
> 主要课件：10-optimization.pptx p.54-p.56  
> 来源：对应 `summary-input.jsonl` 切片、课堂逐字稿与 `materials/10-optimization.pptx`；以下内容按老师实际讲授顺序整理。

## 本段在整讲中的作用

本段接续上一段恰好截断的“预测错误后怎么办”。老师解释，乱序核心不会把推测结果直接覆盖唯一一份寄存器状态，而是借助寄存器重命名保存已确认版本和多个待定版本；误预测时丢弃错误路径的待定更新，恢复到最近的确定状态，再从正确方向重新填充流水线。由此说明不可预测分支为何昂贵，以及条件移动为何在合适场景下更顺畅。最后老师把整讲压缩成两级行动原则：先消除隐藏算法低效和编译器阻塞，再依据现代处理器的共同结构暴露 ILP、减少不可预测分支，并为之后的缓存优化留下接口。

## 教学展开

### 1. 误预测后取消错误路径指令 `[01:09:42-01:10:16]`

老师接上课件 p.54 的 **Invalidate**：一旦分支单元确认此前方向预测错误，处理器会取消沿错误路径已经取入、甚至已经执行的指令。之所以能够取消，是因为这些操作尚未把结果作为不可撤销的架构状态提交。

老师把寄存器状态分为两类：

- **确定状态**：已经确认属于正确程序路径的寄存器值；
- **推测状态**：错误尚未排除、等待提交的寄存器更新。

回滚时丢弃错误分支之后的待定更新，重新采用分支之前的确定值。这里“取消已经执行的指令”不是让时间倒流，而是让其结果永远不成为程序可见状态。

### 2. 寄存器重命名保存多个版本 `[01:10:16-01:11:16]`

回答学生问题时，老师指出处理器中有一个大的 **register renaming unit（寄存器重命名单元）**。架构指令虽然反复使用有限的寄存器名，内部却可为这些名字分配许多物理/虚拟版本，例如：

- 某寄存器最后一个已确认的旧值；
- 第一次待定更新；
- 第二次待定更新；
- 第三次待定更新。

老师说现代设计通常有“数百个”这类内部寄存器来保存映射和待定值 `[01:10:31-01:10:45]`。处理器必须跟踪每个消费者应读哪个版本，并在提交或取消时维护一致性；概念上是版本化与回滚，实现上却非常复杂，因此不是一学期课程可以完整覆盖的设计。

### 3. 推测执行的概念模型 `[01:11:16-01:11:46]`

老师把复杂硬件归纳成简单模型：处理器沿预测方向快速前进，基于猜测完成大量工作；若猜对，就让这些结果依次成为正式状态；若猜错，就回退到好像只执行到某个已确认点的状态，然后沿正确方向继续。它之所以能“赌”，是因为内部保存了足够的历史和待定版本，而不是因为错误路径不会执行。

### 4. 条件移动与不可预测跳转的差别 `[01:11:46-01:12:28]`

老师回忆课程前面比较过 conditional move（条件移动）与 conditional jump（条件跳转）：

- 条件移动不改变取指方向，可留在现有流水中执行；
- 不可预测的条件跳转可能让前端沿错误方向取入并执行许多操作。

误预测的成本不仅是丢掉错误路径上已经做的工作。处理器转向正确路径后，还要重新取指、解码、建立依赖并填满内部缓冲和流水级，经过若干周期后才能重新达到满速。课件 p.55 因而把分支误预测恢复列为现代处理器上的多周期成本和潜在主要性能限制，并示意退出循环后重新装填流水线，最终执行：

```asm
401040: vmovsd %xmm0, (%r12)
```

课堂没有给出固定的误预测周期数；代价随处理器与上下文变化，结论仅是“多个周期，可能主导性能”。

### 5. 第一层总结：先写编译器友好的代码 `[01:12:28-01:12:52]`

老师用“don't do anything stupid”概括第一层，随即承认 “stupid” 太重：很多问题并不明显，重点是建立日常习惯。结合课件 p.56，这一层包括：

1. 使用合适的编译器和优化选项；
2. 警惕隐藏的算法低效，例如循环条件中的 `strlen` 把线性任务变成二次任务；
3. 写编译器友好的代码；
4. 识别过程调用副作用和内存别名两类优化阻塞；
5. 特别检查承担大部分工作的最内层循环。

这层目标是不依赖某一具体处理器型号，先移除本不应存在的工作。

### 6. 第二层总结：按现代机器结构暴露并行 `[01:12:52-01:13:23]`

在通用优化之后，再面向一类机器调优：利用指令级并行，缩短依赖链，并避免不可预测分支。课件 p.56 还把 cache-friendly（缓存友好）列为高性能要求，但注明将在课程后面覆盖，本讲没有展开。

老师强调这些方法虽称“机器调优”，并非只对一颗 Haswell 有效。ARM 手机处理器、x86 笔记本以及课程的 Shark 机器都具有相似的乱序、流水或并行执行结构，因此重关联、多累加器等一般思想可跨这些处理器类别使用。具体最佳 $L,K$ 或向量 ISA 可能变化，但“减少串行依赖、向硬件提供独立工作”的原则保持不变。

### 7. 结束课程 `[01:13:23-01:13:28]`

老师确认本讲到此结束并致谢。至此，教学链闭合：

$$

\rightarrow
\text{编译器阻塞}

\text{CPE 测量}

$$

## 概念、符号与推导

### 已确认状态与推测状态

- 架构寄存器名对程序可见，但处理器内部可映射到不同物理版本。
- 已退休/已确认版本构成可恢复检查点。
- 推测路径产生待定版本；只有控制流和前序状态确认后才可提交。
- 误预测时丢弃错误路径版本，恢复映射并从正确地址继续。

课堂只给概念模型，没有说明重排序缓冲区、提交宽度或精确异常等实现细节；不得从本段自行补全这些结构。

### 误预测成本的因果链

1. 前端预测分支并沿预测路径取指。
2. 部分错误路径指令可能已经解码、调度、执行。
3. 分支结果确定后发现预测错误。
4. 错误路径结果失效，寄存器映射回到确定版本。
5. 前端改从正确目标取指，重新填充缓冲和流水线。
6. 在重新达到稳态前损失多个周期（课件 p.54-p.55）。

### 本段公式说明

除上面的课堂主线结构化箭头外，本段没有数值公式推导；课件与口述都没有给出固定误预测罚时。不能把某个处理器常见数字补成本讲结论。

## 例子与课堂提示

- **多个寄存器版本** `[01:09:54-01:11:00]`：服务于解释已经执行的错误路径为何仍可取消。
- **“旧值、第一次更新、第二次更新……”** `[01:10:51-01:11:00]`：服务于把寄存器重命名理解成版本链，而非把一个值直接覆盖。
- **实现复杂、概念简单** `[01:11:00-01:11:43]`：服务于限定本课目标，只理解性能后果，不设计完整乱序核心。
- **条件移动对照条件跳转** `[01:11:46-01:12:23]`：服务于解释控制依赖如何打断流水供给。
- **老师缓和 “stupid” 措辞** `[01:12:28-01:12:47]`：服务于强调这些性能错误并不显眼，应该依靠方法和习惯发现，而不是归咎程序员粗心。
- **ARM、x86、Shark 对照** `[01:12:52-01:13:20]`：服务于区分可跨机器类别的方法与具体 ISA/参数特化。

## 易错点

1. **把“错误路径已执行”理解为程序状态已不可逆改变。** 执行结果先进入推测版本，未确认前不会成为正式状态。
2. **把寄存器重命名理解成给源码变量改名。** 它是处理器内部把有限架构寄存器名映射到更多物理版本的机制。
3. **认为误预测成本只有错误路径指令数。** 还包括取消、重定向取指和重新填满流水线的时间。
4. **认为条件移动总优于分支。** 老师这里只说明它不造成控制转移；是否合适仍取决于两侧计算成本和安全性，本讲前文已讨论条件移动的适用限制。
5. **给误预测罚时填写一个固定数字。** 本讲只说多个周期且可能很昂贵，没有提供统一数值。
6. **把机器调优理解成只对 Haswell 生效。** 具体参数依机器变化，但暴露 ILP、减少不可预测分支的原则覆盖多种现代处理器。
7. **把缓存友好当作本讲已详细教授。** p.56 只预告后续课程覆盖，不能在本讲笔记中补入缓存机制。

## 本段掌握检查

1. **问：处理器为什么能取消已经执行的错误路径指令？**  
   **答：** 结果仍保存在待定的推测寄存器版本中，尚未提交；误预测时可丢弃这些版本并恢复最近的确定状态 `[01:09:42-01:10:16]`。

2. **问：寄存器重命名单元在本段承担什么作用？**  
   **答：** 它为同一架构寄存器的连续更新维护多个内部版本和映射，让依赖跟踪、乱序执行、提交及回滚成为可能 `[01:10:16-01:11:16]`。

3. **问：不可预测条件跳转为什么可能成为主要性能限制？**  
   **答：** 猜错会浪费错误路径工作，随后还需重定向并重新填充处理器缓冲和流水线，损失多个周期（课件 p.55）。

4. **问：全讲的两级优化策略是什么？**  
   **答：** 先消除隐藏算法低效和过程调用/别名等编译器阻塞；再依据机器结构暴露 ILP、使用合适的数据并行并减少不可预测分支（课件 p.56）。

5. **问：哪些结论较通用，哪些更机器相关？**  
   **答：** 避免重复调用、局部累加、分析依赖链等原则较通用；最佳展开/累加参数、AVX2 指令和具体吞吐数值更依赖处理器与编译器。
