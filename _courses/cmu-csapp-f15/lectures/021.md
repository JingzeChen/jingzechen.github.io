## 本讲定位与学习目标

老师把网络编程称为完成此前低层系统内容后的“回报”：CPU、内存、I/O、进程和 Unix file abstraction 不再只是孤立主题，而会共同支撑 client-server application。课程并不试图替代完整的 computer networking 课程，而是采取 programmer's perspective，目标是让应用程序员理解并使用 C-level sockets API，并为最后一个实验做准备（00:00:04-00:01:11）。

完成本讲后，应能：

1. 以 **client-server model** 描述一次网络事务：client request，server 操作其管理的 resource，server response，client 处理结果；同时说明 client/server 是 process role，可以位于相同或不同 hosts，也可在不同交互中切换（00:01:32-00:03:49；[课件: 21-netprog1.pptx p.2]）。
2. 解释 network adapter/NIC 为什么对主机表现为 I/O device，以及 Unix 为什么让应用通过 file-descriptor-style read/write 来收发网络数据（00:03:49-00:05:15；[课件: 21-netprog1.pptx p.3]）。
3. 从 hub、bridge/switch、LAN、WAN、router 逐层构造小写 `internet`，并区分一般 internetwork 与大写 Global IP Internet（00:05:15-00:12:02；[课件: 21-netprog1.pptx p.4] [课件: 21-netprog1.pptx p.5] [课件: 21-netprog1.pptx p.6] [课件: 21-netprog1.pptx p.8]）。
4. 说明 internet protocol 如何用统一 naming scheme 与 packet delivery mechanism 抹平不兼容 networks，并追踪 data 在 `PH` 与逐 LAN `FH` 下的 encapsulation（00:12:02-00:16:06；[课件: 21-netprog1.pptx p.10] [课件: 21-netprog1.pptx p.11] [课件: 21-netprog1.pptx p.12]）。
5. 区分 IP、UDP、TCP：IP 是 host-to-host best-effort datagram；UDP 是 process-to-process unreliable datagram；TCP 在 IP 上提供可靠、有序、双向 process-to-process byte stream（00:16:06-00:19:46；[课件: 21-netprog1.pptx p.14]）。
6. 精确区分 IPv4 address 的三种层面：32-bit 数值本体、big-endian network-byte-order 内存/报文表示、四段 `0-255` 的 dotted-decimal presentation；并说明 IPv6 以 128-bit address 回应 IPv4 容量压力（00:20:39-00:27:51）。
7. 把 hierarchical domain name 与 DNS multi-mapping 联系起来：一名可多址、多名可一址、结果可随时间/地点变化、合法名称也可能没有 host address（00:27:59-00:37:03）。
8. 写出 socket endpoint 与 connection identity：`socket address = IP address:port`，完整 connection 由 client/server 两端 socket addresses 标识；区分 server well-known port 与 client ephemeral port（00:37:03-00:42:38）。
9. 解释 generic `sockaddr` 与 IPv4-specific `sockaddr_in` 的 C 接口关系，以及 port/address 为什么必须使用 network byte order（00:43:11-00:45:54）。
10. 按顺序复现 server `socket -> bind -> listen -> accept` 与 client `socket -> connect`；区分 listening descriptor 和 connected descriptor，并说明 client close 为什么在 server read 端表现为 EOF（00:45:54-01:04:13）。
11. 说明现代 `getaddrinfo` 为什么返回 null-terminated `addrinfo` linked list、怎样逐项尝试 socket address、怎样用 `freeaddrinfo` 释放，以及它相对旧 API 的 IPv4/IPv6 统一性和 thread-safety 优势（01:04:13-01:10:47）。
12. 逐行解释 `hostinfo.c` 的 `hints`、`AF_INET`、`SOCK_STREAM`、`getaddrinfo`、`NI_NUMERICHOST`、`getnameinfo`、list traversal 与 `freeaddrinfo`，并用 `localhost -> 127.0.0.1` 设计单机 client-server 测试（01:11:14-01:16:51.79；[课件: 21-netprog1.pptx p.38] [课件: 21-netprog1.pptx p.40] [课件: 21-netprog1.pptx p.41] [课件: 21-netprog1.pptx p.42]）。

## 先修知识

1. **Unix I/O 与 file descriptor**：理解 low-level `read`、`write`、`close`、EOF，以及 standard input/output/error 使用小整数 descriptors；本讲把 socket 纳入同一应用接口（00:04:19-00:05:15，00:42:18-00:43:11，00:52:49-00:53:20）。
2. **process 与 kernel**：client/server 首先是 application processes；kernel 负责按 connection/port 分派到进程，并实现 TCP/IP 与 socket system calls（00:19:46-00:20:39，00:40:47-00:41:28；[课件: 21-netprog1.pptx p.15]）。
3. **二进制、十六进制与 byte order**：需要能从 32 bits 分成四个 bytes，理解 big-endian/little-endian 与 most-significant byte（00:21:07-00:22:02，00:25:21-00:27:23）。
4. **C structures、pointers 与 casts**：socket API 形成于没有 `void *` 的早期 C，因而依赖 generic/specific structs、pointer casts 和 caller-managed storage（00:24:15-00:25:21，00:43:11-00:45:54）。
5. **linked list 与动态资源**：`getaddrinfo` 返回 null-terminated linked list，程序必须遍历候选并最终 `freeaddrinfo`（01:07:36-01:09:24，01:12:35-01:13:15）。

## 教师教学主线

### 1. 先用角色和 I/O 统一应用视角（00:00:00-00:05:15）

老师没有从协议字段开始，而是先用 Amazon 与电话建立 client/server role。紧接着把 NIC 放进主机 I/O 路径：network 在硬件上是 I/O device，在 Unix application 中像 file。这样后续所有 sockets calls 都能复用学生已有的 descriptor/read/write 心智模型。[课件: 21-netprog1.pptx p.2] [课件: 21-netprog1.pptx p.3]

### 2. 从共享介质逐层抽象成可互连网络（00:05:15-00:16:06）

地理范围先给出 SAN/LAN/WAN/internetwork；设备层再从 hub 广播过渡到 bridge/switch 学习式转发，最后由 router 连接异构 LAN/WAN。面对“不兼容网络如何合作”，老师才引入共同 protocol、uniform address 与 packet。`PH`/`FH` 封装图把“跨网统一”与“本地链路差异”同时保留下来。[课件: 21-netprog1.pptx p.4] [课件: 21-netprog1.pptx p.5] [课件: 21-netprog1.pptx p.6] [课件: 21-netprog1.pptx p.9] [课件: 21-netprog1.pptx p.12]

### 3. 把不可靠 packet 收束成应用可读写的 TCP stream（00:16:06-00:20:39）

IP 只做 best effort；UDP 允许应用直接接受 unreliable datagrams；TCP 则在 IP 上切包、重传、重排，为 process-to-process connection 提供可靠 byte stream。于是应用又回到“写 descriptor 发送、读 descriptor 接收”，不再直接观察 packet boundary。[课件: 21-netprog1.pptx p.14]

### 4. 沿“机器怎样被命名”推进到 DNS（00:20:39-00:37:03）

IPv4 address 从 32-bit 值展开为 dotted decimal 与 network byte order；IPv6 由容量压力引出。随后老师指出人不会靠数字访问 Google，于是进入 hierarchical domain names 和 DNS。`nslookup` 的 CMU、Stanford、Twitter 演示逐步推翻“一名一址”的直觉，并用 static/dynamic assignment 回答地址从哪里来。

### 5. 从 host 身份推进到 process endpoint（00:37:03-00:49:37）

IP/DNS 只确定 host，port 才区分 SSH、FTP、mail、Web 等 service；IP address 与 16-bit port 组成 socket endpoint。kernel 以两端 socket information 区分 connections，application 则把 endpoint 当 file descriptor。老师再用 `sockaddr`/`sockaddr_in` 解释历史 C 类型接口，最后展示 client-server 生命周期全图。[课件: 21-netprog1.pptx p.15] [课件: 21-netprog1.pptx p.16] [课件: 21-netprog1.pptx p.17]

### 6. 逐调用建立、使用并关闭 connection（00:49:37-01:04:13）

两端共有 `socket(AF_INET, SOCK_STREAM, 0)`；server 依次 `bind -> listen -> accept`，client 调 `connect`。一次 request 到达后，`accept` 返回新的 connected descriptor；老师现场纠正为 “same port, different file descriptors”。双方用 read/write 完成 session，client close 后 server read 得到 EOF；当前图示 server 再回到 `accept`，构成一次只服务一个 client 的 iterative loop。

### 7. 用现代转换 API 承接 DNS 多映射与协议独立性（01:04:13-01:16:51.79）

老师提前进入原定周四 slides。`getaddrinfo` 用 strings 与 `hints` 产生一列 socket-address candidates，统一 IPv4/IPv6 并避开旧接口静态缓冲区的线程问题。`addrinfo` 字段直接连接 `socket`、`connect`、`bind`；`getnameinfo` 执行反向 presentation conversion。`hostinfo.c` 把整条链跑通，最后用 `localhost` 展示单机开发模式。[课件: 21-netprog1.pptx p.38] [课件: 21-netprog1.pptx p.39] [课件: 21-netprog1.pptx p.40] [课件: 21-netprog1.pptx p.41] [课件: 21-netprog1.pptx p.42]

## 概念与能力依赖

### 网络构造链

1. host 通过 NIC/network adapter 接入通信设施。
2. hub 让一个 Ethernet segment 上所有 hosts 共享并看见传输 bits。
3. bridge/switch 学习 port reachability，选择性转发 frames。
4. 一个 LAN 可抽象成能直接通信的一组 hosts。
5. router 连接多个可能不兼容的 LAN/WAN，形成小写 `internet`。
6. internet protocol 用 uniform address 与 packet format 屏蔽底层差异。
7. Global IP Internet 以 TCP/IP family 实现该抽象。

[课件: 21-netprog1.pptx p.3] [课件: 21-netprog1.pptx p.5] [课件: 21-netprog1.pptx p.6] [课件: 21-netprog1.pptx p.8] [课件: 21-netprog1.pptx p.10] [课件: 21-netprog1.pptx p.14]

### 命名与端点链

```text
MAC address (local Ethernet adapter)
    -> IPv4 address (32-bit host identity in this lecture)
    -> dotted-decimal presentation
    <-> hierarchical domain name via DNS
    -> IP address + 16-bit port = socket address
    -> two socket addresses = one connection identity
```

MAC、IP、domain name、port 并非同一标识的不同拼法：它们处在不同层次，解决 local adapter、Internet host、人类命名与 host 内 process/service 的不同问题（00:08:04-00:10:49，00:20:39-00:39:39）。

### 数据传输与可靠性链

```text
application bytes
  -> Internet packet [PH | payload]
  -> LAN frame [FH | PH | payload]
  -> IP best-effort datagrams
  -> TCP retransmission/reordering
  -> reliable full-duplex byte stream
  -> application read/write on socket descriptor
```

[课件: 21-netprog1.pptx p.11] [课件: 21-netprog1.pptx p.12] [课件: 21-netprog1.pptx p.14]

### connection 生命周期链

```text
Server                                  Client
socket                                  socket
bind
listen
accept  <------ connection request ----- connect
  |                                         |
connected descriptor                  client descriptor
  |<----------- read/write session -------->|
  |<--------------- EOF ---------------- close
close
loop back to accept
```

当前讲解是 iterative server；后续 multithreading 才让 server 在处理一个 client 时同时接受另一个（01:03:30-01:03:57）。

### address representation 与 conversion 链

1. IPv4 semantic value：32 bits。
2. packet/memory network representation：big-endian network byte order。
3. human presentation：四个 decimal bytes，以 `.` 分隔。
4. naming presentation：hierarchical domain name。
5. `getaddrinfo`：host/service strings -> linked list of socket addresses。
6. `getnameinfo`：socket address -> host/service strings。
7. `addrinfo` fields 把 conversion output 直接送入 sockets calls。

(00:21:07-00:29:40，01:04:29-01:13:15；[课件: 21-netprog1.pptx p.38] [课件: 21-netprog1.pptx p.39])

## 关键例子与适用边界

1. **Amazon shopping**：展示 request/resource manipulation/response，但不能推出所有 distributed systems 都只有一台 server（00:01:50-00:03:49）。
2. **telephone**：用于 client/server role、connection 和 close 类比；packet network 并不真的为 TCP 保留传统电话式专用物理线路（00:02:24-00:03:07，00:13:28-00:13:57）。
3. **party line 与教室 Wi-Fi**：说明共享信道和冲突；老师给出的主机数量只是课堂量级估计，不是标准硬上限（00:08:30-00:09:38）。
4. **CMU `128.2`**：说明地址前缀与剩余 $2^{16}$ 组合；不应把课堂例子当作永久、完整的现代 CMU 地址清单（00:22:02-00:22:47）。
5. **Twitter 重复 DNS 查询**：说明多地址、顺序/集合变化和服务调度；不能据一次结果推导 API 排序保证（00:33:31-00:35:05，01:14:01-01:14:30）。
6. **Google/Amazon 多客户端**：说明同一 service port 需要多个 connected descriptors；老师已现场纠正为 “same port, different file descriptors”（01:01:20-01:02:10）。
7. **`localhost`**：固定指当前 machine 的 `127.0.0.1`，适合在一台主机上同时测试 client/server；它不测试外部路由或真实跨机网络（01:15:01-01:15:43；[课件: 21-netprog1.pptx p.42]）。

## 全讲易错点

1. **把 client/server 当机器类型**：它们是 process roles，可在相同或不同 hosts 上运行。[课件: 21-netprog1.pptx p.2]
2. **把 network-as-file 当硬件等价**：相同的是应用 read/write interface，NIC 与 disk controller 底层不同（00:42:27-00:43:08）。
3. **混淆 internet 与 Internet**：小写是互连网络的一般概念，大写是 Global IP Internet 具体实例（00:06:50-00:07:44）。
4. **混淆 frame 与 packet**：FH 服务当前 LAN，PH 属于跨 internet packet；router 跨网时链路层封装会改变。[课件: 21-netprog1.pptx p.12]
5. **认为 IP 保证交付**：IP 可静默丢包；TCP 才负责重传、重排并向应用提供可靠 stream（00:16:49-00:19:35）。
6. **把 dotted decimal 当地址本体**：它是 32-bit IPv4 value 的 presentation form；报文字节序仍是 big-endian network order（00:21:07-00:27:43）。
7. **把 DNS 当单值函数**：映射可一对多、多对一、随时间变化或为空（00:30:13-00:36:00）。
8. **把 socket 当 IP address**：endpoint 是 `IP address:port`；connection 由两端 endpoints 共同标识（00:37:35-00:41:59）。
9. **给每个 client 分配不同 server service port**：server port 相同，`accept` 为 sessions 返回不同 process-local descriptors（01:01:44-01:02:10）。
10. **硬编码 socket address length**：老师反复强调使用 `getaddrinfo` 返回的 address 与 length；00:53:53 的 “four” 需回听，不能直接抄为 `bind` 的结构长度。
11. **把 `AF_INET` 当 IPv6**：`hostinfo.c` 课件明确 `AF_INET /* IPv4 only */`；transcript 在 01:12:27 的 “IPv6” 与代码冲突，[课件: 21-netprog1.pptx p.40]。
12. **忘记释放 `getaddrinfo` result**：遍历后必须 `freeaddrinfo`，否则产生资源泄漏（01:13:01-01:13:15；[课件: 21-netprog1.pptx p.41]）。

## 复习路径与掌握标准

### 第一轮：画出抽象层次

不看笔记，依次画出 `host/NIC -> Ethernet LAN -> router/internet -> IP -> TCP -> socket descriptor -> client/server process`，并对每一箭头说出它屏蔽了什么差异。若把 MAC、IP、domain、port 混为一层，应回看 00:05:15-00:20:39 与 00:37:03-00:43:11。

### 第二轮：手工追踪一个 request

从 client 的 domain name 开始：DNS/`getaddrinfo` 得到候选 socket addresses；`socket/connect` 发 request；server `bind/listen/accept` 接收；双方 read/write；client close；server read EOF 并 close。必须能指出哪一步使用 listening descriptor、哪一步产生 connected descriptor。

### 第三轮：核对 representation boundary

给出任意 IPv4 dotted decimal，说明每段 byte 范围、32-bit 本体、network order 与 host order 的区别；再说明 `getaddrinfo`/`getnameinfo` 在 string 与 socket structure 哪个方向转换。重点不是背未在本段可靠展示的旧函数名，而是不能把 byte-order conversion、numeric presentation conversion 和 DNS naming conversion 混成一件事。

### 第四轮：解释 `hostinfo.c`

逐行说出 `memset(hints)`、`AF_INET`、`SOCK_STREAM`、`getaddrinfo` error code/result pointer、`for (p = listp; ...)`、`NI_NUMERICHOST`、`getnameinfo` 与 `freeaddrinfo`。能够解释 `localhost`、单地址与多地址三种运行输出，即达到本讲 API 层掌握标准。[课件: 21-netprog1.pptx p.40] [课件: 21-netprog1.pptx p.41] [课件: 21-netprog1.pptx p.42]

# 第 1 节：从程序员视角进入网络编程

- **时间范围**：00:00:00-00:09:53
- **证据范围**：本节 transcript；[课件: 21-netprog1.pptx p.1] 至 [课件: 21-netprog1.pptx p.4]

## 本段在整讲中的作用

本段完成从此前低层系统主题到网络编程的转场。老师先限定课程目标：这不是一门完整的计算机网络课程，而是要从程序员视角理解网络软件，并学会使用网络编程所需的 C 级 API；该主题也直接为课程最后一个实验做准备（00:00:04-00:01:11）。随后，老师依次建立三层认识：网络应用采用客户端-服务器模型；主机把网络适配器当作 I/O 设备；现实网络由不同地理尺度的网络互连而成。最后从 Ethernet 的共享通信方式切入最低层局域网，为下一节继续比较 hub 与 switch/bridge 做铺垫。

## 教学展开

### 1. 课程转场与范围限定（00:00:00-00:01:30）

1. 老师把网络编程称为学完此前低层内容后的“回报”：此前对系统底层的理解，现在将用于真正理解并熟练编写网络软件（00:00:04-00:00:25）。
2. 本讲不会覆盖网络学科的全部内容；CMU 另有完整的网络课程。这里仍沿用 15-213 的一贯立场，只取软件开发者需要的部分，重点是如何使用网络编程相关的 C 级 API（00:00:25-00:01:11）。
3. 这个主题既面向学生未来的工作，也与课程最后一个实验直接相关（00:00:30-00:00:47）。课件标题确认本讲是 *Network Programming: Part I*，[课件: 21-netprog1.pptx p.1]。
4. 00:01:24 左右老师短暂处理课件遥控/显示问题；00:01:30 后正式进入第一个模型。

### 2. 客户端-服务器模型（00:01:32-00:03:49）

1. **为什么先讲模型**：大多数网络应用都能先抽象成“某处有一项服务，客户向提供服务的一方提出请求”（00:01:32-00:01:50）。
2. **基本角色**：客户端进程发出请求；服务器进程管理某种资源，处理请求并返回响应。服务器通常由客户端请求激活，[课件: 21-netprog1.pptx p.2]。
3. **Amazon 例子**：浏览器联系 Amazon 的 Web 服务器；客户端请求商品、提交信息，服务器查询本地资源并返回商品图片、购物建议或信用卡交易确认（00:01:50-00:02:21，00:03:15-00:03:43）。这个例子展示了完整顺序：请求 -> 服务器本地处理/访问数据库 -> 响应 -> 客户端决定下一步。
4. **电话例子**：发起呼叫时，主叫方是客户端，被叫方的电话等待呼叫，扮演服务器；接通后双方交谈，任一方都可挂断（00:02:24-00:02:57）。老师借此强调角色并非设备的永久属性，同一参与方可在不同交互中切换客户端和服务器角色（00:02:57-00:03:07）。
5. **结论**：客户端-服务器不是某个网站专用的结构，而是组织网络系统的一种普遍思维方式（00:03:03-00:03:07）。课件进一步明确，客户端和服务器是运行在主机上的**进程**，可以位于相同或不同主机，[课件: 21-netprog1.pptx p.2]。

### 3. 网络是 I/O 设备，socket 将其呈现为文件（00:03:49-00:05:15）

1. 从硬件看，计算机通过 NIC（network interface card，网络接口卡）连接网络；尽管名称保留了 “card”，它如今不一定真是一块独立扩展卡（00:03:49-00:04:04）。课件把 network adapter 画在 I/O 总线一侧，与磁盘控制器、图形适配器和 USB 控制器并列，[课件: 21-netprog1.pptx p.3]。
2. 对本课程更关键的不是 NIC 电路，而是它在主机中表现为一个 **I/O 设备**（00:04:04-00:04:19）。
3. Unix 网络 API 进一步把网络抽象成“文件”：发送消息表现为向一个代表网络的虚拟文件写入数据，接收数据表现为从中读取数据（00:04:19-00:04:52）。
4. 这把本讲与此前 Unix I/O 讲座连接起来：磁盘和网络在物理实现上不同，但应用程序都可通过读写接口操作（00:04:27-00:05:01）。这一模型源于早期标准 Unix，后来也被 Windows 等操作系统采用（00:05:01-00:05:15）。

### 4. 从 LAN/WAN 到 internet/Internet（00:05:15-00:08:04）

1. 老师把网络概括为一组称为 **hosts（主机）** 的系统，它们通过某种通信设施彼此通信（00:05:24-00:05:41）。
2. 按地理范围可形成层次：LAN（local area network）覆盖较小区域；WAN（wide area network）覆盖城市或更大区域（00:05:41-00:05:56）。课件给出更完整的尺度：SAN 覆盖集群或机房，LAN 覆盖建筑或校园，WAN 覆盖国家或全球，[课件: 21-netprog1.pptx p.4]。
3. CMU 是现实层次结构的例子：教室里的无线基站连接校园网络基础设施；校园再经商业提供商（老师点名 AT&T）接入商业 Internet；超级计算中心的另一组连接则提供大学间通信使用的 Internet2（00:05:56-00:06:44）。
4. **internet（小写 i）** 是把多个网络连接成“网络的网络”的一般概念；例如把本教室基站提供的局部网络接到校园内及全球的其他网络（00:06:50-00:07:11）。
5. **Internet（大写 I）** 是这一概念最著名的具体实例，采用特定原则和协议；日常说 “the Internet” 通常就是指现存的全球网络结构（00:07:11-00:07:53）。课件也明确区分 Global IP Internet 与一般 internetwork，[课件: 21-netprog1.pptx p.4]。
6. 本课程只研究这套现实结构，不比较其他可能的网络设计（00:07:44-00:08:04）。

### 5. Ethernet、hub 与共享信道（00:08:04-00:09:53）

1. 老师从网络的最低层开始，指出大量低层联网由 Ethernet 支持；但 “Ethernet” 随时间演化很大，如今更像一组技术的品牌名，而非单一固定技术（00:08:04-00:08:15）。
2. 在熟悉的有线形式中，多台主机把线缆插入一个盒子。历史上的 **hub（集线器）** 只是中继器：任一主机送入的信息都会广播到所有连接主机（00:08:15-00:08:41）。
3. 老师用 **party line（合用线路）** 类比：所有参与者都能“听到”其他人发送的内容，因此这种方式只适合大约十几台机器（00:08:41-00:08:53）。最早的 Ethernet 甚至让所有主机直接共享一根以无线电信号承载数据的电缆（00:08:53-00:09:00）。
4. 教室无线网络与 hub 类似：所有主机共享同一无线频率/通信信道，协议必须检测同时发送造成的冲突与干扰（00:09:00-00:09:29）。由于共享信道，这种结构只能扩展到老师估计的至多约 100 台通信主机（00:09:29-00:09:38）。
5. 最后老师转回现代有线设备：从运营商获得、带多个端口的盒子“实际上叫 router 或……”（00:09:42-00:09:53）。句子在本节边界处未完，下一节从 “sometimes a switch” 续接，不能仅凭本段判定老师在这里对 router、switch 与 bridge 作了何种严格分类。

## 概念、符号与推导

### 客户端-服务器事务

- 参与者是服务器进程与一个或多个客户端进程，而非固定种类的机器，[课件: 21-netprog1.pptx p.2]。
- 按课堂顺序可表示为：客户端请求 -> 服务器操作其管理的资源 -> 服务器响应 -> 客户端处理响应（00:03:15-00:03:49）。
- 电话例子表明“客户端/服务器”描述一次交互中的角色，不是参与方永恒不变的身份（00:02:24-00:03:07）。

### 网络 I/O 抽象

- 硬件路径：主机通过 network adapter/NIC 接入网络；适配器位于 I/O 体系中，[课件: 21-netprog1.pptx p.3]。
- 应用视角：发送 = 写，接收 = 读（00:04:19-00:04:52）。
- 这里建立的是接口上的统一性，不等于网络和磁盘的硬件实现相同。

### 网络层次与术语

- `host`：接入通信系统并能与其他系统通信的主机（00:05:24-00:05:41）。
- `SAN`、`LAN`、`WAN`：按地理邻近程度组织的不同尺度网络，[课件: 21-netprog1.pptx p.4]。
- `internet`：互连的一组网络；`Internet`：采用特定协议体系的 Global IP Internet，[课件: 21-netprog1.pptx p.4]。
- 本段无公式推导。

### 共享 Ethernet 的扩展限制

- hub 会把输入广播给所有端口；无线主机也共享同一通信信道（00:08:30-00:09:23）。
- 多方共享信道会带来同时发送和干扰问题，因而限制可扩展规模（00:09:18-00:09:38）。
- 老师给出的“十几台”“至多约 100 台”是课堂中的量级说明，不应当作协议规定的硬上限。

- **电话呼叫**（00:02:24-00:03:07）：用于说明服务器等待请求、建立连接、双方通信及角色可切换。

- **party line 与教室 Wi-Fi**（00:08:41-00:09:29）：用于解释 hub 广播、共享通信介质及冲突。

## 常见误解与辨析

1. **误解：客户端和服务器一定是两类固定机器。** 实际上它们首先是进程角色，可在同一或不同主机运行；电话还展示了同一设备可切换角色，[课件: 21-netprog1.pptx p.2]，00:02:24-00:03:07。
2. **误解：网络被当作文件，说明网络硬件就是磁盘。** 文件只是应用可见的 Unix I/O 抽象；NIC 仍是独立的网络 I/O 设备（00:03:49-00:05:15）。
3. **误解：internet 与 Internet 完全同义。** 小写词表示网络互连的一般概念，大写词表示 Global IP Internet 这个具体实例（00:06:50-00:07:44）。
4. **误解：Ethernet 指从诞生至今完全不变的一种设备。** 老师明确说该名称随技术演化，已近似品牌名（00:08:04-00:08:15）。
5. **误解：hub 会判断目标后只转发给对应主机。** 本段讲的 hub 是盲目广播；有选择的转发在下一段才续讲（00:08:30-00:09:53）。

# 第 2 节：从交换式 Ethernet 到 TCP/IP 与 sockets

- **时间范围**：00:09:53-00:19:46
- **证据范围**：本节 transcript；[课件: 21-netprog1.pptx p.5] 至 [课件: 21-netprog1.pptx p.14]

## 本段在整讲中的作用

本段承接上一节末尾关于现代有线设备的未完句，先把共享式 Ethernet 提升为可选择转发的交换式 LAN，再说明 router 如何把不兼容的 LAN/WAN 组成小写 `internet`。老师随后追问：异构网络凭什么互通？答案是主机和路由器共同遵守 internet protocol。由此依次引出统一命名、packet、header/payload、跨网络封装，以及 Global IP Internet 中 IP、UDP、TCP 的分工。结尾把 TCP 的可靠双向字节流重新接回 Unix 文件 I/O，正式落到 sockets 编程接口。

## 教学展开

### 1. 从 hub 广播转向 switch/bridge 选择性转发（00:09:53-00:10:49）

1. 本节开头的 “or sometimes a switch” 与上一节末尾 “called a router or” 连成一句。老师强调现代盒子不再把每条消息广播给所有人，而会判断消息是否发往某台主机，并只向相应方向转发（00:09:53-00:10:13）。
2. 课件先给出被替代的最低层结构：Ethernet segment 由双绞线连接到 hub 的若干 host 构成；每个适配器有唯一 48-bit MAC address，数据以 frame 为单位发送，hub 则把每个端口收到的每一 bit 复制到所有其他端口，[课件: 21-netprog1.pptx p.5]。
3. bridge/switch 的改进是学习哪些 host 可从哪些 port 到达，再选择性地从端口到端口复制 frame；多个 segment 可由 bridge 连接，覆盖建筑或校园，[课件: 21-netprog1.pptx p.6]。
4. 老师说这些有线设备可按 hop 继续连接若干层，之后还可叠加更复杂的 switching（00:10:13-00:10:36）。尽管真实 Ethernet 结构复杂，在本讲的概念层面可以把 LAN 简化成“一组能够直接互相通信的 host”（00:10:36-00:10:49）；课件也把 hub、bridge 和 wires 折叠成 hosts 挂在一根逻辑 wire 上，[课件: 21-netprog1.pptx p.7]。

### 2. router 把 LAN 连接成 internet（00:10:49-00:12:02）

1. **构造方式**：用 router 把多个 local area networks 连接起来；router 根据目标地址并遵守特定 protocol 转发（00:10:49-00:11:04）。这些 LAN 可以采用完全不同且彼此不兼容的技术，如 Ethernet、Fibre Channel、802.11、T1 或 DSL，[课件: 21-netprog1.pptx p.8]。
2. **逻辑结果**：世界各处的 host 通过一系列 router hop 彼此可达。无论消息在校园内传输还是绕行全球，系统都依据目标 host 的已知地址选择下一步（00:11:04-00:11:45）。
3. internet 没有规定唯一拓扑，router 和 link 的容量也可能差异极大；packet 从源到目标逐网跳转，不同 packet 还可能走不同路线，[课件: 21-netprog1.pptx p.9]。
4. 老师明确划定程序员边界：路由如何实现、如何保证所需性质是一整门学科；本课先假设这些机制由网络系统处理，应用程序员的任务是让一台 host 与另一台 host 通信（00:11:45-00:12:02）。

### 3. 为什么异构网络需要共同协议（00:12:02-00:13:31）

1. 老师把问题提升到全球异构性：计算机来自不同厂商，运行于不同国家并受不同电信管理体系约束，怎样才能互操作（00:12:02-00:12:24）？
2. 答案是 **protocol**：各方必须共同遵守关于消息格式、发送方式、丢失处理和恢复方式的一组约定（00:12:24-00:12:40）。课件将其定义为 host 与 router 跨网络传输数据时的合作规则；它屏蔽不同底层网络之间的差异，[课件: 21-netprog1.pptx p.10]。
3. 协议至少提供两类能力：
   - **naming scheme**：用统一格式标识 host，使发送方能指定目标；每个 host/router 至少获得一个 internet address，[课件: 21-netprog1.pptx p.11]；
   - **delivery mechanism**：定义标准传输单位 packet，并让路由系统把数据送往命名目标（00:12:47-00:13:08）。
4. 数据被切成 packet，老师给出的典型量级约为 1,000-2,000 bytes；长消息被切分后，底层通信逐 packet 进行（00:13:08-00:13:28）。
5. 老师用传统电话系统作对照：历史电话是 connection-based 系统，通话期间有一组专用线路被预留；packet 网络并不为整段通信永久锁定同一物理线路（00:13:28-00:13:57）。

### 4. packet、header/payload 与封装（00:13:57-00:16:06）

1. 从 host A 向 host B 发送时，先有一段应用数据（00:13:57-00:14:09）。
2. 协议软件在数据前添加 header，作用类似信封正面的投递信息；沿途不同层使用不同格式的 header（00:14:09-00:14:32）。
3. 源主机先添加描述 internet routing 的 **PH（Internet packet header）**，再为当前 local network 添加 **FH（LAN frame header）**（00:14:32-00:15:07；[课件: 21-netprog1.pptx p.12]）。课件 p.11 进一步区分：header 可含 packet size、source address 与 destination address，payload 才是源主机要发送的数据 bits。
4. network adapter 把带有本地 frame header 的内容送入 LAN；跨越 router 和下一 LAN 时，本地 frame 包装随网络改变，而 internet packet 作为下一层 payload 被携带。到达 host B 后，相关 header 被剥离，应用最终看到发送的数据（00:15:11-00:15:46；[课件: 21-netprog1.pptx p.12]）。
5. 老师把“在已有 packet 前再附加一层 header，其余内容当作 bytes 传过该层”的做法称为 **encapsulation（封装）**（00:15:46-00:16:06）。
6. 老师没有在此展开不同最大 frame size、router 如何学习下一跳、拓扑变化和 packet loss 等问题；课件把它们列为 computer networking 要解决而本课略过的议题，[课件: 21-netprog1.pptx p.13]。

### 5. Global IP Internet 的 IP、UDP 与 TCP（00:16:06-00:19:46）

1. 大写 `Internet` 采用 TCP/IP protocol family（00:16:06-00:16:24；[课件: 21-netprog1.pptx p.14]）。
2. **IP（Internet Protocol）** 规定如何命名 Internet host、如何发送 packet；packet 在这里也称 datagram，即从 A 到 B 独立发送的单个实体（00:16:24-00:16:49）。IP 提供 host-to-host 的基本命名与**不可靠** datagram delivery，[课件: 21-netprog1.pptx p.14]。
3. IP 是 best effort：条件允许就继续转发；拥塞或无线干扰等情况下可以直接丢弃 packet，并不会向应用保证送达（00:16:49-00:17:28）。
4. **UDP** 是 IP 上的一层较薄软件，向 process-to-process 提供不可靠 datagram delivery。老师以游戏为例：若目标是尽快发送状态，偶尔丢失一份信息问题不大，就可能接受 UDP；本课不继续讲 UDP（00:17:28-00:18:01；[课件: 21-netprog1.pptx p.14]）。
5. **TCP（Transmission Control Protocol）** 建立在 IP 之上，为进程间连接提供可靠的双向 byte stream（00:18:02-00:18:33；[课件: 21-netprog1.pptx p.14]）。应用可以发送任意长度字节流，而不必自己按 packet 操作。
6. TCP 必须把字节流切成 datagrams；packet 丢失时重传，packet 经不同路线而乱序到达时重新排序（00:18:33-00:18:57）。老师让本课暂时把这些内部机制视为已经工作。
7. 因而应用看到的模型是：A 向 B 写一串 bytes，B 也可反向发送；写 socket 像写文件，读 socket 像读文件，packet 边界被接口隐藏（00:19:02-00:19:35）。这就是老师随后所说的 **sockets interface / socket programming**（00:19:35-00:19:46），也对应课件所说通过 Unix file I/O 与 sockets functions 访问 TCP/IP，[课件: 21-netprog1.pptx p.14]。

## 概念、符号与推导

### LAN 与 internet 的逐层抽象

- 物理 Ethernet segment：host + twisted pairs + hub；adapter 以 48-bit MAC address 标识，数据单位为 frame，[课件: 21-netprog1.pptx p.5]。
- bridged Ethernet：bridge 学习 port 可达性后选择性复制 frame，[课件: 21-netprog1.pptx p.6]。
- 概念 LAN：忽略内部 hub/bridge/wire，把它看成可直接通信的一组 hosts，[课件: 21-netprog1.pptx p.7]。
- internet：router 连接多个可能不兼容的 LAN/WAN，使 packet 按地址跨网络逐跳传输，[课件: 21-netprog1.pptx p.8] [课件: 21-netprog1.pptx p.9]。

### 协议的两项核心职责

1. 统一地址格式，解决“目标是谁”；
2. 统一 packet 及其 header/payload 结构，解决“如何传送”。

这不是数学推导，而是从异构互操作问题得到的功能分解（00:12:02-00:13:28；[课件: 21-netprog1.pptx p.10] [课件: 21-netprog1.pptx p.11]）。本段无数学公式推导。

### 封装关系

可按课堂图示记作：

```text
应用数据
  -> [PH | 应用数据]             Internet packet
  -> [FH_LAN1 | PH | 应用数据]   LAN1 frame
  -> router 跨网转发
  -> [FH_LAN2 | PH | 应用数据]   LAN2 frame
  -> 目标端逐层去除 header
```

这里的 `PH` 是跨 internet 使用的 packet header；`FH_LAN1` 与 `FH_LAN2` 属于各自 LAN 的 frame header，[课件: 21-netprog1.pptx p.12]。

### 可靠性与通信端点

| 层/协议 | 老师强调的服务 | 端点/数据视图 |
|---|---|---|
| IP | best-effort、不保证投递 | host-to-host datagram |
| UDP | IP 上的薄层，仍不保证投递 | process-to-process datagram |
| TCP | 重传、重排后提供可靠连接 | process-to-process byte stream |
| sockets | 把 TCP 字节流呈现为读写对象 | 应用使用 file-I/O 式接口 |

[课件: 21-netprog1.pptx p.14]

## 常见误解与辨析

1. **误解：switch 与 hub 都把 frame 发给所有 host。** hub 盲目复制；bridge/switch 学习可达端口后选择性复制，[课件: 21-netprog1.pptx p.5] [课件: 21-netprog1.pptx p.6]。
2. **误解：internet 要求所有底层网络采用 Ethernet。** router 的意义恰在于连接可能完全不兼容的 LAN/WAN，[课件: 21-netprog1.pptx p.8]。
3. **误解：一个长消息就是一个巨大 packet。** 老师先把长数据切成约 1,000-2,000-byte 的 packets，通信在 packet 层进行（00:13:08-00:13:28）。
4. **误解：IP 既命名目标又保证投递。** IP 提供地址与 best-effort datagram delivery，并不保证 packet 到达（00:16:24-00:17:28）。
5. **误解：TCP 不使用 packet。** TCP 的应用接口隐藏 packet，但内部仍把 byte stream 切成 IP datagrams，并负责丢失重传与乱序重排（00:18:33-00:19:35）。

## 本段掌握检查

### 1. 为什么 bridge/switch 比 hub 更适合扩展 Ethernet？

**答：** hub 把每一 bit 复制到所有端口；bridge/switch 学习 host 从哪个 port 可达，只向需要的端口复制 frame，从而减少无关广播，[课件: 21-netprog1.pptx p.5] [课件: 21-netprog1.pptx p.6]。

### 2. 多个底层技术不兼容的网络如何形成一个 internet？

**答：** router 物理连接不同 LAN/WAN，主机与路由器运行共同的 protocol software；协议统一地址和 packet 格式，屏蔽底层网络差异（00:10:49-00:12:40；[课件: 21-netprog1.pptx p.8] [课件: 21-netprog1.pptx p.10]）。

### 3. 封装时 PH 与 FH 各自服务于哪一层？

**答：** PH 是 Internet packet header，携带跨 internet 所需信息；FH 是当前 LAN 的 frame header。跨入另一 LAN 时本地 frame 包装可改变，而 IP packet 被继续承载，[课件: 21-netprog1.pptx p.12]。

### 4. IP、UDP、TCP 在可靠性和端点上如何区分？

**答：** IP 提供不可靠的 host-to-host datagram；UDP 在 IP 上提供不可靠的 process-to-process datagram；TCP 在 IP 上通过重传和重排提供可靠的 process-to-process byte stream，[课件: 21-netprog1.pptx p.14]。

### 5. 为什么 TCP socket 对应用看起来像文件？

**答：** TCP 隐藏 packet 的切分、重传和重排，让应用只看到有序字节流；应用向 descriptor 写 bytes 来发送、从 descriptor 读 bytes 来接收（00:18:33-00:19:46）。

## 概念、符号与推导

### IPv4 点分十进制的位数关系

IPv4 address 共 32 bits，分为四个 8-bit byte：

$$
32=4\times 8,\qquad 0\le b_i\le 2^8-1=255.
$$

因此 presentation 形式为：

```text
b0.b1.b2.b3
```

其中每个 `bi` 用十进制显示（00:21:07-00:21:46）。老师没有在本段推导任意实例的完整 32-bit 数值转换。

### 地址空间容量

- IPv4：$2^{32}$，老师近似为 4 billion（00:22:56-00:23:07）。
- 固定 `128.2` 两个 byte 后：剩余 $32-16=16$ bits，因此约有 $2^{16}$ 种后缀（00:22:02-00:22:47）。
- IPv6：128-bit address；本段未计算 $2^{128}$ 的十进制数量（00:22:47-00:23:51）。

### 三种不能混淆的表示

1. **语义对象**：一个 IPv4 address，是 32-bit 值。
2. **内存/报文整数表示**：network byte order，即 big-endian。
3. **presentation 表示**：四个 byte 的十进制值，以 `.` 分隔。

标准函数负责 host order 与 network order 的转换；另一组 API 调用负责 presentation text 与 32-bit address 之间的转换（00:25:28-00:27:43）。本段没有可靠说出函数名。

### 域名到地址的层次

人类使用 hierarchical domain name；DNS 将它映射到 IP address（00:27:59-00:29:30）。本段只建立问题与系统角色，映射是否一对一留到下一节。

## 例子与课堂提示

- **一人多设备**（00:23:07-00:23:32）：用于直观说明 $2^{32}$ 地址空间压力，并引出 IPv6。
- **早期 C 没有 `void *`**（00:24:36-00:25:08）：用于解释 socket API 中 `char *` 和大量结构体/类型技巧的历史来源。
- **`128` 等于 `0x80`**（00:26:47-00:27:08）：用于说明点分十进制首 byte 对应 32-bit 地址的 most significant byte。
- **Google 通常按域名访问**（00:27:51-00:28:17）：用于把数字表示转换自然过渡到 DNS。

## 常见误解与辨析

1. **误解：IPv4 地址就是四段字符串。** 地址本质是 32-bit 值；点分十进制只是 presentation form（00:21:07-00:21:46）。
2. **误解：`128.2` 已占 16 bits，所以 CMU 还剩 $2^{64}$ 个地址。** IPv4 总共 32 bits，剩余 16 bits，对应 $2^{16}$ 个组合；老师在现场也修正了幂次口误（00:22:02-00:22:47）。
3. **误解：network byte order 会随 host CPU 改变。** network order 固定为 big-endian；标准转换函数适配 host 自身字节序（00:25:28-00:26:13）。

1. 有时是一对一；
2. 有时多个 domain names 指向同一 address；

4. 有时名称合法，但没有关联 host/IP address。

（00:35:40-00:36:00）

1. 学生问自己创建 server 时“那个号码”怎样生成；老师把问题澄清为“怎样获得自己的 IP address”（00:36:00-00:36:13）。

3. 在 CMU，一部分地址是 **statically allocated**：固定分配给机器，可向 computing services 注册申请（00:36:17-00:36:33）。

### 6. TCP connection 与 socket endpoint（00:37:03-00:37:53）

1. 老师回到本课主要使用的 TCP：一台 host 与另一台 host 建立 connection 后，可以双向发送任意长的 byte streams（00:37:03-00:37:35）。
2. connection 的两个 endpoint 各称为一个 **socket**（00:37:35-00:37:43）。
3. 一个 socket address 由 **IP address + port number** 组成（00:37:43-00:37:53）。IP address 指定 host，port 进一步指定该 host 上参与通信的进程/服务。

### 7. 16-bit port 区分同一 host 上的服务与连接（00:37:53-00:39:39）

1. port 是 **16-bit integer**（00:37:53-00:38:01）。仅知道目标机器还不够，因为同一机器可以同时提供 SSH、FTP、mail、Web 等不同 services（00:38:01-00:38:23）。
2. server 上不同服务以不同 port numbers 区分；kernel 由此把到达同一 host 的数据交给正确服务进程（00:38:18-00:38:28）。
3. client 也可能同时连接几十台 host，例如浏览网页时有许多程序/连接并行运行；client 端同样以不同 ports 区分这些通信端点（00:38:28-00:38:48）。
4. 因而 port 的作用是标识 connection 任一端具体通信的 endpoint/process，而不是再次标识整台 host（00:38:48-00:39:00）。
5. client port 通常由系统动态分配，称为 **ephemeral port**，只在该 connection 持续期间占用（00:39:00-00:39:15）。
6. 要联系 server，DNS 只解决例如 `google.com` 的 IP address；client 还必须用 port 指定请求 Web 等哪项服务（00:39:15-00:39:39）。老师口述 Web 为 port 80，并说 HTTPS 使用不同 port，但句子在本段边界处未完；本段不补出未口述的编号。

## 概念、符号与推导

### DNS 应建模为关系而非单值函数

老师展示的映射可写成集合值关系：

$$
\operatorname{DNS}(name)=\{addr_1,addr_2,\ldots\}
$$

反向查询也可能返回多个名称：

$$
\operatorname{DNS}^{-1}(addr)=\{name_1,name_2,\ldots\}.
$$

这只是对老师 “one or more” 与 “multi-mapping” 的形式化记录，不是课堂新增算法（00:30:13-00:30:32，00:35:21-00:35:53）。集合还可能为空，对应合法 domain name 没有关联 IP address。

### TCP connection 的端点表示

本段先定义单个 socket address：

$$
\text{socket address}=\text{IP address}:\text{port}.
$$

- IP address：定位 host；
- port：16-bit integer，区分该 host 上的 endpoint/process/service（00:37:35-00:39:00）。

完整 connection 有两个 endpoints，因此后续会由一对 socket addresses 标识；本段尚未给出形式化 socket-pair 记号。

### 端口角色

- server：公开服务使用约定端口；Web 例为 port 80（00:39:15-00:39:39）。
- client：kernel 动态分配 ephemeral port，生命周期通常限于一次 connection（00:39:00-00:39:15）。

## 教学展开

### 1. 补完客户端 `connect`（00:59:35-01:00:03）

1. `connect` 接收目标的 address 与 port 组合，也就是 server socket address（00:59:35-00:59:40）。
2. 调用还需要 address length；老师再次说这一数值通常由 `getaddrinfo` 的结果填入，而不是应用硬编码（00:59:40-00:59:50）。

### 2. connection request 怎样到达 `accept`（01:00:03-01:01:20）

1. server 执行 `bind` 与 `listen` 后，已有一个 **listening port/socket**，专门等待 connection requests（01:00:03-01:00:27）。
2. client 的 `socket` 已给它一个 file descriptor；`connect` 使 request 穿过 network 到达 server（01:00:27-01:00:41）。
3. server kernel 根据目标 port，把 request 交给运行在该 port 的 server program；server 阻塞在 `accept` 的调用由此得到处理（01:00:41-01:01:06）。

### 3. 为什么一个 server 需要不同 descriptors（01:01:20-01:02:22）

1. server 通常需要服务多个 clients；老师用 Google/Amazon 举例，单个 host 应允许多个 clients 与它通信（01:01:20-01:01:44）。
2. listening descriptor 只负责听取新的 connection requests；每次 session 的双向通信使用 `accept` 产生的另一个 connected descriptor（01:01:44-01:02:04）。
3. 老师先说这些通信通过 server 侧“different ports”，随后立即纠正：**same port, different file descriptors**（01:01:52-01:02:10）。区别是 server 应用中的 descriptor，不是每接一个 client 就更换 well-known service port。
4. 这种分离让一个 service port 可对应多个具体 client connections；并发处理方式留到后续课程（01:01:20-01:02:22）。

### 4. session 的 read/write、close 与 EOF（01:02:22-01:03:12）

1. connection 建立后，双方按具体 application protocol 使用 reads 与 writes 发送/接收 messages（01:02:22-01:02:41）。
2. session 持续多久、消息如何组织，由应用层 protocol 决定（01:02:31-01:02:41）。
3. client 最终 close connection；在 server 端，这表现为对 connected descriptor 的一次 read 返回 **end-of-file (EOF)**（01:02:41-01:03:05）。
4. EOF 告诉 server 这个特定 connection 已结束，于是 server close 相应 connected descriptor（01:03:05-01:03:12）。

### 5. iterative server 循环与未来的并发 server（01:03:12-01:04:13）

1. 关闭一个 client connection 后，server 可以绕回去再次 `accept`，等待另一个 client（01:03:12-01:03:30）。
2. 当前图示是 **serial / iterative server**：一次只能管理一个 connection request，服务完当前 client 才接下一个（01:03:30-01:03:42）。
3. 课程后面讲 multithreading 后，可让 server 在处理一个 client 时同时回去接受另一 connection（01:03:42-01:03:57）。
4. 当前 iterative 循环的可见行为是：read -> EOF -> close connected descriptor -> 回到 `accept`（01:03:57-01:04:13）。

1. 老师明确说接下来跳到线上属于周四 lecture 的 slides，因为周四内容很多，今天先讲一部分（01:04:13-01:04:29）。这解释了本段为何从 connection 生命周期跳到 host/service conversion。

### 7. `getaddrinfo` 的输入、输出与配套函数（01:05:53-01:07:36）

### 8. 结果是 null-terminated linked list（01:07:36-01:09:31）

## 概念、符号与推导

### listening 与 connected descriptors

```text
service port P
    |
listening descriptor L  --accept(request from client C1)--> connected descriptor C1
                        --accept(request from client C2)--> connected descriptor C2
```

关键不变量是 **same server port, different file descriptors**（01:01:44-01:02:10）。`L` 接收新 request；`C1`、`C2` 各表示一个具体 connection。

### iterative server 控制流

```text
while (running):
    connected_fd = accept(listen_fd)
    exchange_data(connected_fd)
    read(...) -> EOF
    close(connected_fd)
```

这是对课堂流程的伪代码化整理，不是老师展示的完整 C 程序（01:02:22-01:04:13）。当前版本一次只处理一个 client。

### `getaddrinfo` 的抽象类型关系

```text
inputs:  host string + service string + hints
output:  result -> addrinfo -> addrinfo -> ... -> NULL
helpers: freeaddrinfo(result), gai_strerror(error_code)
```

list 的意义不是维持输入顺序的数学保证，而是返回当前可尝试的多个 socket addresses（01:07:36-01:09:24）。本段无数学公式推导。

## 概念、符号与推导

### `struct addrinfo` 的数据流角色

```c
struct addrinfo {
    int              ai_flags;
    int              ai_family;
    int              ai_socktype;
    int              ai_protocol;
    char            *ai_canonname;
    size_t           ai_addrlen;
    struct sockaddr *ai_addr;
    struct addrinfo *ai_next;
};
```

[课件: 21-netprog1.pptx p.38]

- `ai_family`, `ai_socktype`, `ai_protocol` -> `socket(...)`；
- `ai_addr`, `ai_addrlen` -> `connect(...)` 或 `bind(...)`；
- `ai_next` -> 下一候选；
- `ai_canonname` -> canonical host name（若请求/提供）。

### 正向与逆向转换

```text
getaddrinfo(host string, service string, hints)
    -> linked list of socket address candidates

getnameinfo(socket address)
    -> host/service presentation strings
```

`getnameinfo` 是方向上的 inverse，但多重 DNS 映射意味着它不是简单数学双射，[课件: 21-netprog1.pptx p.39]。

### `hostinfo` 的转换链

```text
argv[1]
  -> getaddrinfo(..., &listp)
  -> for each addrinfo p
       getnameinfo(p->ai_addr, p->ai_addrlen, NI_NUMERICHOST)
       print numeric host
  -> freeaddrinfo(listp)
```

[课件: 21-netprog1.pptx p.40] [课件: 21-netprog1.pptx p.41]

本段无数学公式推导；重点是结构体字段与 API 间的数据依赖。

## 常见误解与辨析

1. **误解：`addrinfo` 只保存一个 IP number。** 它还保存可直接供 socket API 使用的 family、type、protocol、address length/pointer、canonical name 和 next pointer，[课件: 21-netprog1.pptx p.38]。
2. **误解：`getnameinfo` 总会唯一恢复原 domain name。** DNS 可一址多名；它是转换方向的 inverse，不保证数学一一对应（01:10:47-01:11:03；[课件: 21-netprog1.pptx p.39]）。
3. **误解：本例通过 `AF_INET` 请求 IPv6。** 课件代码明确 `AF_INET /* IPv4 only */`；transcript 的 “IPv6” 与画面冲突，需回听（01:12:27；[课件: 21-netprog1.pptx p.40]）。
4. **误解：`hostinfo` 本例打印 domain names。** `NI_NUMERICHOST` 明确要求 numeric address，运行输出也是点分十进制，[课件: 21-netprog1.pptx p.41] [课件: 21-netprog1.pptx p.42]。
5. **误解：result list 可不释放。** `getaddrinfo` 分配的 linked list 必须由 `freeaddrinfo` 释放，否则产生内存资源问题（01:13:01-01:13:15）。

## 本段掌握检查

### 1. 哪些 `addrinfo` 字段可以直接传给 `socket`，哪些传给 `connect`/`bind`？

**答：** `ai_family`、`ai_socktype`、`ai_protocol` 对应 `socket` 三个参数；`ai_addr` 与 `ai_addrlen` 对应 `connect`/`bind` 的 address 及长度，[课件: 21-netprog1.pptx p.38]。

### 2. `getaddrinfo` 与 `getnameinfo` 的方向有何区别？

**答：** 前者从 host/service strings 得到 socket-address candidates；后者从 socket address 得到 host/service strings，但 DNS 多重映射使它们不是数学双射（01:10:47-01:11:14；[课件: 21-netprog1.pptx p.39]）。

### 3. `hostinfo.c` 为什么先清零 `hints`，又设置 `AF_INET` 与 `SOCK_STREAM`？

**答：** 清零使未使用 hints fields 有确定默认值；`AF_INET` 限定 IPv4，`SOCK_STREAM` 限定 connection/TCP stream candidates，[课件: 21-netprog1.pptx p.40]。

### 4. `NI_NUMERICHOST` 对 `hostinfo` 输出有什么影响？

**答：** 它要求 `getnameinfo` 输出 numeric host address 而非 domain name，所以程序逐项打印点分十进制地址，[课件: 21-netprog1.pptx p.41]。

### 5. `localhost` 为什么适合开发 client-server 程序？

**答：** 它固定指当前主机的 loopback address `127.0.0.1`，可在一台机器上同时运行 client 与 server 进行测试（01:15:01-01:15:43；[课件: 21-netprog1.pptx p.42]）。
