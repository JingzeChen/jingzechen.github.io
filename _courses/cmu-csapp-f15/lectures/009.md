## 学习目标

完成本讲后，应能够：

1. 从机器级程序员视角解释“内存是字节数组”的抽象，并区分名义 64 位地址与本讲机器实际使用的 47 位地址 [00:01:51–00:08:35；课件 p.3]。
2. 按地址高低辨认 x86-64 Linux 进程中的 text、data、heap、shared libraries 与 stack，并说明栈向低地址增长、典型限制为 8 MB [00:08:36–00:16:47；课件 p.3–5]。
3. 从 C 越界写、无界字符串函数、栈帧布局和返回地址破坏，逐步推导 buffer overflow 如何变成 code injection [00:16:48–00:37:50；课件 p.7–20]。
4. 解释 Morris Worm 与 AIM/MSN 案例分别如何利用缓冲区溢出，并区分 worm 与 virus [00:37:50–00:42:49；课件 p.21–25]。
5. 比较有界接口、ASLR、non-executable stack 与 stack canary 各自打断的攻击前提 [00:42:50–01:03:14；课件 p.26–33]。
6. 从 canary 设置/检查汇编说明 `%fs:0x28`、`8(%rsp)`、异或比较和 `__stack_chk_fail` 的控制路径 [00:54:40–01:02:22；课件 p.31–33]。
7. 定义 ROP gadget，解释 `0xC3`、函数尾部 gadget、从指令中间重新解码的 gadget，以及栈上地址链如何连接执行 [01:03:14–01:11:55；课件 p.34–37]。
8. 对比 array、struct 与 union 的存储语义，区分 union 位重解释与数值 cast，并从同一字节序列推导 IA32、Sun 和 x86-64 的输出 [01:12:46–01:18:36；课件 p.39–47]。

## 先修知识

- C 数组、指针、字符串终止符 `\0`，以及 `char`、`short`、`int`、`long`、`float`、`double` 等类型的机器表示。
- Struct 的字段布局、padding 与 alignment；本讲以此对照 union [01:13:15–01:13:49；课件 p.39、p.47]。
- x86-64 函数调用基础：`%rsp`、参数寄存器 `%rdi`、`callq` 保存返回地址、`retq` 从栈恢复控制流。
- 十六进制与二进制换算，例如一个十六进制位对应 4 bit，`0x18=24`。
- 能阅读 `objdump`/反汇编输出，并用 GDB 观察地址、寄存器与单步执行；这些工具也是 Attack Lab 的训练重点 [01:12:11–01:12:29]。
- Data Lab 中对浮点位模式的认识；老师用 union 连接到此前的浮点位级操作 [01:14:10–01:15:27；课件 p.40]。

4. **从控制流破坏走到远程利用** [00:32:49–00:42:49；课件 p.19–25]：exploit bytes + padding + buffer address，随后用 Morris Worm 和 IM War 说明现实后果。
5. **逐层部署防护** [00:42:50–01:03:14；课件 p.26–33]：有界 API、ASLR、NX stack、canary；每项针对不同攻击前提。
6. **攻击复用现有代码** [01:03:14–01:12:46；课件 p.34–38]：ROP 用 gadgets 和 `ret` 地址链应对随机化与不可执行栈，但本讲明确保留 canary 这一限制。

## 概念依赖

```text
字节地址空间
├─ 进程内存区域
│  ├─ stack 中的局部缓冲区
│  └─ stack 中保存的返回地址
├─ C 不做数组边界检查
│  └─ 无界字符串输入
│     └─ buffer overflow
│        ├─ 意外控制流破坏
│        └─ code injection
│           ├─ 依赖可预测的 stack 地址 → ASLR
│           ├─ 依赖 stack 可执行 → NX stack
│           └─ 必须越过关键栈状态 → stack canary
│              └─ ROP 复用现有代码，但本讲仍受 canary 限制
└─ 同一字节的多种解释
   ├─ array：同型连续元素
   ├─ struct：字段顺序分配并填充
   └─ union：字段重叠
      ├─ float/unsigned 位重解释
      └─ short/int/long 视图暴露 byte ordering
```

关键依赖关系如下：

- 不先知道 stack 与返回地址的邻接关系，就无法解释为什么字符串越界能改变控制流 [00:27:33–00:35:41；课件 p.13–19]。
- 不先区分“输入内容写到哪里”和“处理器能否执行那里”，就会混淆 ASLR 与 NX stack [00:45:21–00:51:33；课件 p.28–29]。
- 不先理解 `ret` 从栈取得地址，就无法理解 ROP 为何要求 gadget 以 `0xC3` 结束 [01:05:30–01:10:02；课件 p.34–37]。
- 不先理解 union 字段共享同一存储，就无法解释为何写 `c[8]` 后能从 `s/i/l` 看到组合值 [01:13:26–01:16:23；课件 p.39、p.42–43]。

## 关键推导与例子

### 1. 地址空间数量级

$$
2^{10}\approx10^3,
$$

$$
2^{64}=2^4\cdot2^{60}\approx16\times10^{18}\ \text{bytes},
$$

$$
2^{47}=2^7\cdot2^{40}=128\times2^{40}\ \text{bytes}\approx128\ \text{TB}.
$$

`0x7FFFFFFFFFFF` 中 `7` 提供 3 个有效位，11 个 `F` 提供 $11\times4=44$ 位，总计 47 位 [00:02:48–00:08:35；课件 p.3]。

### 2. 地址实例

- `local = 0x00007ffe4d3be87c`：stack。
- `main = 0x000000000040060c`、`useless = 0x0000000000400590`：text。
- `huge_array = 0x0000000000601060`、`big_array = 0x0000000080601060`：data。
- 大块 `malloc` 结果位于高地址侧，小块结果位于低地址侧；老师明确只把它作为当前系统观察，不给出普遍规则 [00:12:04–00:16:32；课件 p.4–5]。

### 3. `echo` 的溢出边界

反汇编 `sub $0x18,%rsp` 给出 24 字节栈区域：4 字节 `buf` + 20 字节未用空间，之后是返回地址 [00:25:29–00:28:18；课件 p.12–14]。

若输入有 $n$ 个字符，`gets` 共写 $n+1$ 字节：

- $n=23$：24 字节，越过 `buf[4]`，但未触及返回地址；
- $n=24$：终止符成为第 25 字节，把返回地址 `0x4006f6` 改为 `0x400600`；
- $n=25$：进一步破坏返回地址，演示 segmentation fault [00:28:35–00:32:48；课件 p.15–18]。

### 4. Code injection 布局

```text
[ exploit instruction bytes ][ padding ][ address B of buffer ]
```

`B` 覆盖原返回地址 `A`；`Q` 执行 `ret` 后跳到缓冲区中的注入指令 [00:33:35–00:36:05；课件 p.19]。

### 5. ASLR 的变化范围

五个变化的十六进制位对应：

$$
5\times4=20\ \text{bits},\qquad 2^{20}\approx1\ \text{MB}.
$$

演示中 stack local 和 heap 地址变化，而 global 与 code 地址保持不变 [00:45:21–00:49:59；课件 p.28]。

### 6. Canary 设置与检查

```asm
mov %fs:0x28,%rax
mov %rax,0x8(%rsp)
...
mov 0x8(%rsp),%rax
xor %fs:0x28,%rax
je  normal_exit
call __stack_chk_fail
```

若栈内副本 $C_s$ 与基准 $C_r$ 相同，则 $C_s\oplus C_r=0$，进入正常退出；否则失败 [00:54:40–00:57:39；课件 p.31–33]。最低字节原为 `0x00`，解释了 8 字符后的终止符覆盖为何没有改变比较结果 [00:59:42–01:02:22]。

### 7. 从现有字节中抽取 gadget

课件 p.36 的正常指令从 `0x4004d9` 开始：

```text
c7 07 d4 48 89 c7 c3
```

从 `0x4004dc=0x4004d9+3` 开始重新解码：

```asm
48 89 c7    movq %rax,%rdi
c3          retq
```

这说明 gadget 可从原指令中间开始，不必对应源代码中的完整操作 [01:07:13–01:08:24；课件 p.36]。

### 8. Union 与 endian 推导

把低地址到高地址写成 `f0 f1 f2 f3 f4 f5 f6 f7` [课件 p.43]：

- little-endian 的首个 short 为 `0xf1f0`，首个 int 为 `0xf3f2f1f0`；
- big-endian 的首个 short 为 `0xf0f1`，首个 int 为 `0xf0f1f2f3`；
- x86-64 的 64 位 long 为 `0xf7f6f5f4f3f2f1f0` [01:15:35–01:17:10；课件 p.44–46]。

## 易错点

- 64 位 ISA 不等于本讲机器已使用全部 64 位地址；本讲的有效范围是 47 位、约 128 TB [00:04:00–00:08:35]。
- 老师先口算出 256 TB，随后板书并重复修正为 128 TB；应采用后者 [00:04:10–00:06:21；00:08:02–00:08:09]。
- 地址位模式处于 47 位范围内，不代表该地址已被虚拟内存映射 [00:14:45–00:15:13]。
- `buf[4]` 只能安全保存 3 个普通字符加 `\0`；编译器额外留出 20 字节不扩大 C 数组合法边界 [00:24:31–00:29:18]。
- 返回地址被破坏不一定立即崩溃；错误跳转可能执行无关代码后再次返回 [00:31:52–00:32:48；课件 p.18]。
- ASLR、NX stack 与 canary 不等价：分别针对地址可预测性、数据区可执行性和越界破坏检测 [00:45:21–01:03:14；课件 p.28–33]。
- Canary 不阻止 `gets` 越界；它在函数返回前检测特殊值变化 [00:52:05–00:57:39]。
- ROP 栈中主要放 gadget 地址，不是在不可执行栈中运行新指令；真正执行的是已有代码 [01:04:16–01:10:02]。
- ROP 在本讲中不能绕过 canary；Attack Lab 必须关闭 canary 才能让地址链溢出成功 [01:10:29–01:11:55]。
- Union 位重解释不等于 cast；前者保留位，后者执行数值转换 [01:14:18–01:15:22；课件 p.40]。
- 单字节数组无法显示 endian 差异；必须观察 short/int/long 等多字节聚合 [课件 p.44–46]。
- IA32 与 x86-64 都是 little-endian，但本例 `long` 宽度不同，输出分别为 4 字节和 8 字节 [课件 p.44、p.46]。

## 全讲自测

1. **问：为什么本讲在 64 位架构上仍以 47 位地址、128 TB 为核心数字？**  
   **答：**x86-64 名义地址最长 64 位，但课堂所述当时硬件只实现 47 位；$2^{47}=128\times2^{40}$ 字节 [00:04:00–00:08:35]。

2. **问：为什么地址 `0x00007ffe...` 常提示 stack，而 `0x000000000040...` 常提示 text？**  
   **答：**本讲 Linux 布局把 stack 放在用户地址空间高端、text 放在约 `0x400000` 的低端；示例 `local` 与 `main()` 正好验证这一点 [00:08:36–00:16:04；课件 p.3–5]。

3. **问：`gets` 的接口为何从根本上缺少边界检查所需信息？**  
   **答：**它只有目标指针，没有目标容量；循环只依据 EOF 或换行停止 [00:19:46–00:21:12；课件 p.10]。

4. **问：24 字符输入怎样把 `0x4006f6` 改成 `0x400600`？**  
   **答：**前 24 字节填满 `echo` 分配区，第 25 个写入字节是 `\0`，落到返回地址最低地址字节，把低字节 `f6` 清为 `00` [00:30:40–00:32:16；课件 p.17–18]。

5. **问：经典 code injection 同时依赖哪两个系统性质？**  
   **答：**攻击者要能预测注入缓冲区地址，并且 stack 中的注入字节必须可执行 [00:33:35–00:37:50；00:48:39–00:51:33]。

6. **问：为什么 Morris Worm 能从一台机器继续传播？**  
   **答：**课件说明 `fingerd` 漏洞让 exploit code 在受害机器启动 root shell 并连接攻击者；进入机器后再扫描其他目标 [课件 p.21]。

7. **问：五次 ASLR 演示如何得到约 1 MB 的变化量？**  
   **答：**局部变量地址约有 5 个十六进制位变化，即 20 位，范围为 $2^{20}$，约 1 MB [00:47:56–00:48:25]。

8. **问：Canary 检查为何使用异或和 `je`？**  
   **答：**栈副本与基准值相等时异或为零，设置零标志，`je` 跳过 `__stack_chk_fail` 进入正常退出 [00:56:57–00:57:39；课件 p.31、p.33]。

9. **问：8 字符输入为何可能越界却未改变 canary？**  
   **答：**终止符写到 canary 最低字节，而该字节原本为零，所以写后值不变；第 9 个普通字符才会用非零值覆盖它 [00:59:51–01:02:22]。

10. **问：ROP 为什么不需要从 stack 执行指令？**  
    **答：**stack 保存的是已有可执行代码中 gadgets 的地址；每个 gadget 末尾 `ret` 取出下一个地址 [01:04:16–01:10:02；课件 p.34–37]。

11. **问：`0x4004dc` gadget 的功能和来源是什么？**  
    **答：**它从 `setval` 正常指令中间开始，把 `48 89 c7 c3` 解码为 `movq %rax,%rdi; retq` [01:07:13–01:08:24；课件 p.36]。

12. **问：为什么 union 可以把 unsigned 位模式当作 float 看，而 cast 不可以保持同一位串？**  
    **答：**union 字段重叠，写 `u` 后读 `f` 是对同一存储换类型解释；cast 做数值转换并改变表示 [01:14:18–01:15:22；课件 p.40]。

13. **问：字节 `f0 f1 f2 f3` 在 little-endian 与 big-endian 下分别形成什么 32 位值？**  
    **答：**little-endian 为 `0xf3f2f1f0`；big-endian 为 `0xf0f1f2f3` [课件 p.44–46]。

14. **问：数组、结构体、联合体的机器级寻址/分配核心分别是什么？**  
    **答：**数组是同型连续元素、常用缩放索引；结构体按声明顺序分配并用固定位移访问；联合体把字段重叠在同一位置、只按最大字段分配 [01:17:36–01:18:33；课件 p.47]。

# 第 1 段：课程定位、地址空间规模与栈的高地址布局

> 时间范围：00:00:00–00:09:53  
> 对应课件：09-machine-advanced.pptx p.1–3

## 本段在整讲中的作用

本段先把本讲定位为机器级编程系列的最后一讲。老师把标题中的 “Advanced Topics” 解释为若干彼此相关的补充主题，并把课堂内容与即将发布的 Attack Lab 连接起来：依次讨论 x86-64 程序运行时的内存布局、缓冲区溢出及其安全后果、最后再把此前学过的数组和结构体扩展到联合体（union）[00:00:00–00:01:50；课件 p.1–2]。

随后老师从机器级程序员看到的“内存是一大列字节”这一抽象出发，暂不展开其背后的虚拟内存实现，而是先回答本讲的第一个问题：x86-64 Linux 进程的地址空间有多大，栈放在哪里，又向哪个方向增长 [00:01:51–00:09:53；课件 p.3]。这为后面理解局部变量、返回地址和缓冲区溢出为何会在同一片栈内存中相互影响建立空间模型。

## 教学展开

### 1. 本讲与实验的衔接

- 老师提醒 Bomb Lab 当晚截止，而新的 Attack Lab 会在午夜发布；新实验与过去使用过的攻击实验相似，但做了显著更新。由于课程规模大、实验又是新版本，教师团队会密切观察问题，并鼓励学生尽早开始，以便尽早暴露实验基础设施中的故障 [00:00:11–00:01:08]。
- 本讲有三条内容线：运行 x86-64 程序时的内存形态；缓冲区溢出这一重要安全漏洞及 Attack Lab 对它的实际利用；联合体与已经学过的数组、结构体在组织方式上的差别 [00:01:09–00:01:50；课件 p.2]。

### 2. 从“字节数组”抽象进入地址空间

- 对机器级程序员而言，内存可概念化为一个很大的字节数组。这是程序可见的简化模型，不是硬件和操作系统的真实实现 [00:01:51–00:02:05]。
- 真实实现属于课程后续的虚拟内存主题，会协调磁盘、固态存储和 DRAM 等不同存储介质；本段只使用统一地址空间这一抽象 [00:02:06–00:02:35]。
- 老师明确 DRAM 是 dynamic RAM，也是通常为处理器购买的主存类型 [00:02:28–00:02:35]。

### 3. 估算 64 位地址空间

- x86-64 名义上允许地址最长为 64 位，因此完整地址数量是 $2^{64}$ [00:02:36–00:02:52]。
- 估算从 $2^{10}\approx 10^3$ 开始：
  1. $2^{60}=(2^{10})^6\approx(10^3)^6=10^{18}$；
  2. $2^{64}=2^4\cdot 2^{60}\approx16\times10^{18}$；
  3. 若每个地址对应一个字节，则名义空间约为 $16\times10^{18}$ 字节 [00:02:52–00:03:37]。
- 老师用“在 Amazon 上购买同等数量 DRAM 会非常昂贵”强调：可编码的地址空间远大于当时现实机器能配置的物理 DRAM [00:03:29–00:03:55]。

### 4. 从 64 位名义地址收缩到 47 位实际范围

- 老师说明当时的机器实际只使用 47 位地址，因此可寻址范围是 $2^{47}$ 字节；这一限制相对于现实机器的物理内存容量仍然很宽裕，未来处理器可随技术和成本变化逐步增加有效地址位数 [00:04:00–00:05:12]。
- 口述在第一次心算时说到 256 TB [00:04:10–00:04:22]，随后在板书中修正并确认：
  $$
  2^{47}=2^7\cdot2^{40}=128\times2^{40}\ \text{bytes}\approx128\ \text{TB}.
  $$
  因而本段应以老师后续板书和总结中的 128 TB 为准 [00:05:54–00:06:21；00:08:02–00:08:09]。
- 为建立数量级直觉，老师依次问到 petabyte（$10^{15}$）、exabyte（$10^{18}$）和 zettabyte（$10^{21}$），并用大型互联网企业总存储、每日新增数据以及全球年度数字内容作类比。这些数字只是课堂中的粗略量级示例，老师明确说自己不知道企业的准确内部数字 [00:06:21–00:08:01]。

### 5. 从 47 位推到最高用户地址的十六进制写法

- 老师把最高端地址写成 `0x00007FFFFFFFFFFF`，即有效部分为一个十六进制 `7` 后接 11 个 `F` [00:05:13–00:05:35；课件 p.3]。
- 位数解释为：11 个 `F` 各贡献 4 个二进制 1，共 44 位；`7` 的二进制是 `111`，再贡献 3 位，因此一共是 47 个有效的 1，即 $44+3=47$ [00:08:10–00:08:35]。
- 这一地址是课件内存图的高端边界。图中还标出低地址端、约 `0x400000` 的代码区域，以及栈、共享库、堆、数据和文本等区域；老师在本段只开始详细解释最上方的栈 [课件 p.3]。

### 6. 栈位于高地址并向低地址增长

- Linux 把栈放在地址空间顶部附近。压栈时地址减小，所以栈从高地址向低地址增长 [00:08:36–00:09:16；课件 p.3]。
- 老师特别提醒课件图完全不按比例绘制，而且惯常的栈图方向还会让视觉上的“上下”与地址增减关系显得相反；判断增长方向应看地址值，而不是只看纸面方向 [00:08:47–00:09:16；课件 p.3]。
- 典型系统将运行时栈限制为 8 MB。老师用 Linux 的 limit 命令输出说明 `8192 KB = 8 MB`，并开始解释超出这段栈范围访问内存会发生什么；这一句在下一段继续 [00:09:17–00:09:53；课件 p.3]。

## 概念、符号与推导

### 关键概念

- **机器级内存抽象**：程序把内存看作按地址索引的大型字节数组；虚拟内存如何用多层存储实现这一抽象留待后续课程 [00:01:51–00:02:35]。
- **名义地址宽度与已实现地址宽度**：x86-64 名义地址最长 64 位，但本讲所述机器实际使用 47 位地址 [00:02:36–00:04:10]。
- **地址空间**：47 位地址对应 $2^{47}$ 个逐字节位置，课堂最终采用约 128 TB 的量级 [00:05:54–00:06:21]。
- **栈**：课件将局部变量所在的运行时栈放在用户地址空间高端，典型限制为 8 MB，并向较小地址增长 [00:08:36–00:09:53；课件 p.3]。

### 推导链

1. $2^{10}\approx10^3$ [00:02:58–00:03:06]。
2. $2^{60}=(2^{10})^6\approx10^{18}$ [00:03:06–00:03:28]。
3. $2^{64}=2^4\cdot2^{60}\approx16\times10^{18}$ 字节 [00:03:13–00:03:37]。
4. $2^{47}=2^7\cdot2^{40}=128\times2^{40}$ 字节，即约 128 TB [00:05:54–00:06:21]。
5. `0x7FFFFFFFFFFF` 的有效 1 位数为 $3+11\times4=47$，与 47 位地址上界相对应 [00:08:10–00:08:35]。

- **数据量单位问答**：petabyte、exabyte、zettabyte 的课堂问答用于训练数量级直觉，而不是给出精确行业统计 [00:06:21–00:08:01]。
- **十六进制拆位**：`7 + 11 个 F` 的位数计算把抽象的 47 位限制与调试器中实际看到的高地址形式联系起来 [00:08:10–00:08:40；课件 p.3]。
- **栈图方向提示**：课件图不按比例，栈图的视觉方向也不能替代地址算术；压栈对应地址减小 [00:08:47–00:09:16]。

## 易错点

- 不要把“64 位体系结构”误解成当时硬件已经实现全部 $2^{64}$ 字节地址范围；老师在本讲使用的是 47 位有效地址、约 128 TB [00:04:00–00:06:21]。
- 不要沿用老师第一次口算中的“256 TB”。老师随后板书修正为 128 TB，并在 00:08:02 再次确认 [00:04:10–00:04:22；00:05:54–00:06:21；00:08:02–00:08:09]。
- 不要把地址空间容量等同于物理 DRAM 容量；前者是程序可用地址的范围，后者是机器实际配置的存储资源 [00:03:29–00:04:58]。
- 不要根据课件图的纸面“向下”直接判断栈地址变化；本讲明确给出栈从高地址向低地址增长 [00:08:47–00:09:16；课件 p.3]。
- `0x00007FFFFFFFFFFF` 中的 `7` 只贡献 3 个有效二进制位，11 个 `F` 才各贡献 4 位 [00:08:10–00:08:35]。

# 第 2 段：进程内存区域、实际地址与缓冲区溢出入口

> 时间范围：00:09:53–00:19:46  
> 对应课件：09-machine-advanced.pptx p.3–10

## 本段在整讲中的作用

本段承接上一段对 47 位地址空间顶部栈区域的说明，补完 x86-64 Linux 进程的主要内存区域，并用一个包含全局数组、局部变量、函数和多次 `malloc` 的程序，把抽象布局落实到实际十六进制地址 [00:09:53–00:16:47；课件 p.3–5]。老师的目标不是让学生记住某一轮运行的地址，而是让学生在 GDB 和反汇编中看到地址时，能粗略判断它属于栈、代码、静态数据还是动态分配区。

完成内存布局后，老师转入本讲第二条主线：C 程序允许越界访问，而越界写若受到外部输入控制，就可能从普通程序错误升级为安全漏洞 [00:16:48–00:19:46；课件 p.6–10]。这个过渡直接为下一段分析 `gets`、栈帧和返回地址破坏奠定基础。

## 教学展开

### 1. 栈边界之外会发生什么

- 上一段已给出典型 8 MB 栈限制；老师在本段补完结论：若通过栈指针访问超出这 8 MB 栈范围的内存，程序会发生 segmentation fault [00:09:53–00:10:10；课件 p.3]。
- 这里强调的是“地址位模式看起来合法”并不足以保证访问成功；该地址还必须处于进程实际建立的可访问区域。老师稍后用地址空间中部的空洞再次说明这一点 [00:14:45–00:15:13]。

### 2. 从低地址向上辨认 text、data、heap 与共享库

- **Text segment**：可执行文件中的机器指令位于较低地址区域，传统上称为 text segment。老师说稍后的 linking 主题会进一步解释可执行文件中的各区域 [00:10:10–00:10:40；课件 p.3]。
- **Data segment**：程序启动时就已分配的数据位于 data 区，例如全局变量；课件还列出静态变量和字符串常量 [00:10:40–00:10:56；课件 p.3]。
- **Heap**：由 `malloc` 及相关函数按需分配。它起初很小；若持续分配而不释放，已用范围会朝更大地址扩展 [00:10:56–00:11:25；课件 p.3]。
- **Shared libraries**：`printf`、`malloc` 等库函数的代码存放在磁盘上，程序启动时通过动态链接带入进程地址空间；其具体位置会随系统而异 [00:11:25–00:11:51；课件 p.3]。
- 老师先给出总体观察：运行中的有效分配往往聚集在地址空间的低端和高端，而不是均匀铺满整个 47 位范围 [00:11:51–00:12:03；课件 p.3]。

### 3. 用分配程序把对象映射到地址区域

- 课件中的示例声明两个全局字符数组：`big_array[1L<<24]` 为 16 MB，`huge_array[1L<<31]` 为 2 GB；另有全局变量 `global`、函数 `useless()` 和 `main()` 内的局部变量 `local` [00:12:04–00:12:59；课件 p.4]。
- `main()` 还执行四次动态分配：`p1` 为 256 MB、`p2` 为 256 B、`p3` 为 4 GB、`p4` 为 256 B。老师说明若把某些数组再增大，示例程序就无法运行 [00:12:19–00:13:09；课件 p.4]。
- 这些对象故意覆盖多种来源：局部变量测试栈；函数测试 text；程序内全局声明测试 data；大小不同的 `malloc` 测试动态分配 [00:12:45–00:13:15；课件 p.4]。

### 4. 读取一轮实际地址输出

课件给出一轮运行的地址 [课件 p.5]：

| 对象 | 地址 | 老师据此辨认的区域 |
|---|---:|---|
| `local` | `0x00007ffe4d3be87c` | 栈，高地址端 |
| `p1` | `0x00007f7262a1e010` | 大块动态分配，高地址端附近 |
| `p3` | `0x00007f7162a1d010` | 大块动态分配，高地址端附近 |
| `p4` | `0x000000008359d120` | 小块动态分配，低地址侧 heap |
| `p2` | `0x000000008359d010` | 小块动态分配，低地址侧 heap |
| `big_array` | `0x0000000080601060` | 静态数据；受前一大数组占用影响而处于较高的 data 地址 |
| `huge_array` | `0x0000000000601060` | 静态数据 |
| `main()` | `0x000000000040060c` | text |
| `useless()` | `0x0000000000400590` | text |

- 老师先看 `local`：前缀中出现 `0x00007ff...`，符合高地址栈区的形态 [00:13:16–00:13:29；课件 p.5]。
- 再看 `main()` 与 `useless()`：它们处在约 `0x400000` 的低地址 text 区 [00:13:29–00:13:47；课件 p.5]。
- 两个编译进程序的全局数组位于 data 区；`huge_array` 本身占 2 GB，因此相邻静态对象的地址可以被推到明显更高的位置 [00:13:47–00:14:09；课件 p.4–5]。
- 这一轮运行中，两块 256 B 小分配 `p2/p4` 位于低地址侧，而 256 MB 与 4 GB 大分配 `p1/p3` 位于高地址侧、接近栈所在范围 [00:14:09–00:14:44；课件 p.4–5]。

### 5. 地址空间空洞与分配边界

- 低端与高端已映射区域之间存在大片空洞。访问其中某个地址会 segmentation fault：它的 47 位表示可能有效，但虚拟内存系统没有为该位置建立分配或映射 [00:14:45–00:15:13；课件 p.5]。
- 随着继续 `malloc`，已映射范围的边界可向中部推进。老师用概念图说明：若内存请求最终使两侧范围相遇，`malloc` 会返回 0；但在 128 TB 地址范围下，这种由地址范围直接耗尽导致的相遇很不容易发生 [00:15:14–00:15:42]。
- 课堂提问“为什么 heap 不只朝一个方向推进”时，老师明确回答自己不知道这个实现选择的确切原因，只观察到该运行把大对象与小对象交给了不同位置，并推测两类对象采用了略有不同的管理策略 [00:16:04–00:16:32]。因此不能把这次观察提升为所有系统必须遵循的固定规则。
- 实用结论是：在 GDB 中看到大量前导零、随后约为 `4...` 的地址，往往是在看代码；看到 `7` 和若干 `f` 开头的高地址，往往是在看栈。老师把这作为调试时的方向感，而非严格地址分类算法 [00:15:43–00:16:47]。

### 6. 从内存布局转向越界写

- 老师切换到 Buffer Overflow 主题，并回顾第一讲的 `struct_t` 示例：结构体中有 `int a[2]` 和 `double d`，函数先令 `d=3.14`，再执行 `s.a[i]=1073741824`。当 `i` 越过数组边界时，写入位置可能落入 `d` 或其他内存 [00:16:48–00:17:48；课件 p.6–8]。
- 课件记录的系统特定结果为：`fun(0)`、`fun(1)` 返回 `3.14`；`fun(2)` 返回 `3.1399998664856`；`fun(3)` 返回 `2.00000061035156`；`fun(4)` 又表现为 `3.14`；`fun(6)` 发生 segmentation fault [课件 p.7–8]。这组结果说明越界写的后果并不随索引平滑变化，也不保证立刻崩溃。
- 老师由此抽象出 C 的风险：程序很容易引用意图之外的内存。若索引来自程序内部且已知有界，风险较低；若来自外部输入，攻击者就可能故意提供越界值，使程序崩溃或改变其状态 [00:17:48–00:18:47]。
- 课件把“超过数组所分配内存大小”概括为 buffer overflow，并指出常见形式是没有检查字符串输入长度，尤其是栈上的定长字符数组，因此也称 stack smashing [课件 p.9]。
- 老师进一步聚焦到字符串：消息中的字符串长度若事先未知，就可能大于目标缓冲区；某些库函数甚至没有参数可表达目标上限。`gets` 被作为最典型的入口，它从终端读取字符串；具体循环在下一段展开 [00:18:48–00:19:46；课件 p.10]。

## 概念、符号与推导

### 内存区域与对象来源

- `local`：函数局部变量，示例中位于栈 [00:12:53–00:13:29；课件 p.4–5]。
- `main()`、`useless()`：函数机器指令，示例中位于 text [00:13:29–00:13:47；课件 p.5]。
- `global`、`big_array`、`huge_array`：程序启动时已有的全局数据，位于 data [00:10:40–00:10:56；00:13:47–00:14:09；课件 p.3–5]。
- `p1`–`p4` 所指对象：由 `malloc` 动态分配；这一轮运行把大块放在高地址侧、小块放在低地址侧 [00:13:00–00:14:44；课件 p.4–5]。

### 容量换算

$$
1\text{L}\ll24=2^{24}\ \text{bytes}=16\ \text{MB}
$$

$$
1\text{L}\ll31=2^{31}\ \text{bytes}=2\ \text{GB}
$$

课件还直接标注 `1L<<28` 为 256 MB、`1L<<8` 为 256 B、`1L<<32` 为 4 GB [00:12:19–00:12:36；课件 p.4]。

### 从普通错误到安全漏洞的条件链

1. C 允许按计算出的地址执行存取，没有自动数组边界检查 [00:16:53–00:17:54；课件 p.7–9]。
2. 越界写可覆盖同一结构体中的 `double`、其他对象或未映射内存 [00:17:07–00:17:47；课件 p.7–8]。
3. 若决定索引或字符串长度的值可由外部提供，外部人员便可能主动触发越界 [00:18:03–00:18:47]。
4. 对定长字符缓冲区，缺少长度参数的输入/复制函数构成常见触发路径 [00:18:48–00:19:46；课件 p.9–10]。

## 例子与课堂提示

- **地址打印程序**服务于区域辨认：同一轮输出同时放入代码、静态数据、栈和大小不同的动态分配，以便从地址前缀形成直觉 [00:12:04–00:16:47；课件 p.4–5]。
- **中部空洞**服务于“位模式合法不等于已映射”：不能仅凭地址在 47 位范围内就认为可访问 [00:14:45–00:15:13]。
- **学生提问**保留了实现边界：老师没有为大小分配位置给出确定机制，只把它作为当前系统的一次观察 [00:16:04–00:16:32]。
- **`struct_t` 反例**服务于说明未定义后果的非局部性：有的索引改变 `d`，有的似乎无影响，还有的直接崩溃 [00:16:53–00:17:48；课件 p.7–8]。
- **信任边界提示**：写代码时要问输入值是否由程序内部可靠地产生，还是来自外部、可能被刻意构造 [00:18:29–00:18:47]。

## 易错点

- 不要把 text segment 理解成文本字符串区；老师这里指可执行机器指令所在区域 [00:10:27–00:10:40；课件 p.3]。
- 不要认为所有合法 47 位地址都能访问；未被虚拟内存系统建立映射的中部地址仍会 segmentation fault [00:14:45–00:15:13]。

- 不要用“程序没有立刻崩溃”证明越界写无害。`fun(4)` 看似仍返回 `3.14`，但这只说明该次可见结果没有暴露破坏 [课件 p.7–8]。
- 不要只检查内部计算得到的索引而忽略外部字符串长度；老师把不受限字符串输入列为最常见的缓冲区溢出形式 [00:18:03–00:19:46；课件 p.9–10]。

# 第 3 段：无界字符串输入与 `echo` 栈帧溢出

> 时间范围：00:19:46–00:29:41  
> 对应课件：09-machine-advanced.pptx p.10–16

## 本段在整讲中的作用

上一段已经说明“外部可控的越界写”会把普通内存错误变成安全漏洞。本段沿着这一因果链深入两个层次：先从近似的 `gets` 源码说明为什么某些 C 字符串函数根本没有足够信息实施边界检查；再把一个只有 `char buf[4]` 的 `echo` 函数编译成汇编，逐字节追踪输入如何越过数组、穿过编译器留出的栈空间并接近返回地址 [00:19:46–00:29:41；课件 p.10–16]。

本段的关键教学转换是从“源代码中数组太小”转到“机器代码实际分配多少字节、返回地址具体在哪里”。这使下一段能够解释为什么破坏返回地址有时崩溃、有时表面正常，并最终发展为代码注入攻击。

## 教学展开

### 1. `gets` 如何读取一行

- 老师从 `gets` 的近似实现开始：它只接收一个参数 `dest`，即结果写入位置；没有接收目标缓冲区容量 [00:19:46–00:20:20；课件 p.10]。
- 函数用 `getchar()` 每次读取一个字符，从 `dest` 开始顺序写入。它只在遇到 EOF 或换行符 `\n` 时停止；换行字符编码为十六进制 `0x0A` [00:19:46–00:20:33；课件 p.10]。
- 循环退出后，函数在当前位置写入字符串终止符 `\0`，再返回 `dest`。课件中的核心结构是 [课件 p.10]：

```c
char *gets(char *dest)
{
    int c = getchar();
    char *p = dest;
    while (c != EOF && c != '\n') {
        *p++ = c;
        c = getchar();
    }
    *p = '\0';
    return dest;
}
```

- 因为参数中没有容量，函数无法知道何时到达调用者所分配缓冲区的末尾；在遇到 EOF 或换行前，它会继续向后写 [00:20:33–00:21:12]。
- 老师指出现代编译器在使用 `gets` 时会给出强烈警告，因为该函数来自早期 Unix 时代，当时的代码往往假设调用者已经分配“足够大”的缓冲区，而没有把恶意输入作为设计前提 [00:21:12–00:21:47]。

### 2. 同类字符串库风险

- `strcpy(dest, src)` 从源字符串逐字符复制，到源端 `\0` 才停止；它同样不知道 `dest` 的容量，因此源字符串可能越过目标边界 [00:21:48–00:22:31；课件 p.10]。
- `strcat` 把字符串连接到目标位置，也可能在没有目标容量信息的情况下持续写入 [00:22:25–00:22:41；课件 p.10]。
- `scanf`、`fscanf`、`sscanf` 的 `%s` 转换会读入并存储字符串；若格式中没有限制长度，也不知道目标位置可容纳多少字节 [00:22:32–00:23:05；课件 p.10]。
- 老师暂不在这里展开替代写法，只先得出结论：这些函数的原始、无长度限制用法是真实漏洞来源，稍后再讨论程序员如何写得更安全 [00:23:06–00:23:23]。

### 3. 构造最小的脆弱 `echo` 程序

- 示例函数只做“读入一行，再原样输出”：声明 `char buf[4]`，调用 `gets(buf)`，随后调用 `puts(buf)`；外层 `call_echo()` 调用 `echo()` [00:23:24–00:24:00；课件 p.11]。
- `buf[4]` 只有 4 字节，而合法 C 字符串还必须保留一个 `\0`，所以按源语言对象本身计算，最多只能容纳 3 个普通字符和 1 个终止符 [00:24:31–00:24:54；课件 p.11]。
- 演示程序名为 `bufdemo-nsp`，其中 `nsp` 表示没有 stack protector；stack protector 的机制留到后面讲 [00:24:21–00:24:31]。
- 课件演示了反直觉现象：输入 `012345678901234567890123`（24 个字符）仍打印原串，而再多一个字符的 `0123456789012345678901234`（25 个字符）发生 segmentation fault [课件 p.11]。这说明源代码的 4 字节声明并不能直接预测何时出现可见崩溃，必须看编译后的栈帧。

### 4. 从反汇编读出实际栈帧大小

- `echo` 的第一条关键指令是 `sub $0x18,%rsp`。`0x18=24`，所以函数把栈指针下移 24 字节，为当前调用建立 24 字节区域 [00:25:29–00:26:55；课件 p.12]。
- 随后的 `mov %rsp,%rdi` 把这一区域的起始地址放入第一个参数寄存器 `%rdi`，再调用 `gets`；因此 `gets` 从当前 `%rsp` 开始写 [00:26:48–00:27:18；课件 p.12]。
- `puts` 也以 `%rsp` 为参数；函数结束前执行 `add $0x18,%rsp` 恢复栈指针，再执行 `retq` [课件 p.12]。
- 外层 `call_echo` 在地址 `0x4006f1` 执行 `callq 0x4006cf <echo>`，正常返回位置是紧随其后的 `0x4006f6`。`callq` 保存的这个返回地址位于 `echo` 的 24 字节区域之后，是后续分析的关键状态 [00:27:25–00:28:18；课件 p.12–14]。

### 5. 源语言对象与栈帧之间的 20 字节空隙

- 虽然 C 源码只声明 4 字节 `buf`，该编译结果为 `echo` 留出 24 字节。因此课件把 `%rsp` 开始的前 4 字节标为 `buf[0]`–`buf[3]`，其后 20 字节标为 unused，24 字节区域之后才是 8 字节返回地址 [00:27:51–00:28:18；课件 p.13–14]。
- 老师没有在此给出编译器为何选择 24 字节的通用规则；本段只使用反汇编中已经观察到的事实，不能据此推导所有 `char buf[4]` 都有同样布局。

### 6. 逐步逼近返回地址

- **23 个输入字符**：`gets` 还要写 1 个 `\0`，总写入 24 字节，恰好填满编译器分配区域。它早已越过源语言中的 4 字节 `buf`，但尚未写入返回地址，因此演示仍正常输出 [00:28:35–00:29:18；课件 p.15]。
- **24 个输入字符**：再加终止符一共写 25 字节；结合本段给出的 24 字节分配区和紧随其后的返回地址可知，第 25 个字节会落到返回地址的最低地址字节上。课件 p.11 已展示该长度可能“看起来仍能运行”，老师在下一段才完整解释原因 [课件 p.11、p.13–16]。
- **25 个输入字符**：再加终止符一共写 26 字节，会进一步破坏返回地址。课件 p.16 把这一输入对应为 segmentation fault；本段在 00:29:41 截止时正讲到输入越过“23 个字符加终止符”后开始损坏返回地址 [00:29:19–00:29:41；课件 p.16]。

## 概念、符号与推导

### `gets` 缺失的边界信息

`gets` 只有目标指针：

```c
char *gets(char *dest);
```

由转录和课件能得到的停止条件只有：

$$
c=\mathrm{EOF}\quad\text{或}\quad c='\backslash n'.
$$

其中不存在“已写字符数等于目标容量”这一条件，所以调用者无法通过该接口把 `buf` 的大小传给函数 [00:19:46–00:21:12；课件 p.10]。

### 栈帧字节关系

由反汇编直接得到：

$$
0x18=1\times16+8=24\ \text{bytes}.
$$

对这次特定编译结果：

$$
24\ \text{bytes}=4\ \text{bytes of }buf+20\ \text{unused bytes}.
$$

返回地址紧随这 24 字节之后 [00:26:20–00:28:18；课件 p.12–14]。

### 输入长度与写入范围

设输入含 $n$ 个非换行字符，`gets` 还会写一个 `\0`，因此总写入字节数为：

$$
n+1.
$$

- $n=23$：写 24 字节，填满分配区，不触及返回地址 [00:28:35–00:29:18；课件 p.15]。
- $n=24$：写 25 字节，终止符开始改写返回地址的第一个字节 [课件 p.11、p.13–16；下一段口述详解]。
- $n=25$：写 26 字节，输入和终止符会改写返回地址的更多字节，演示发生 segmentation fault [课件 p.16；下一段口述详解]。

## 例子与课堂提示

- **近似 `gets` 实现**服务于接口级解释：问题不是某次循环“忘了检查”，而是函数签名根本没有目标容量可检查 [00:19:46–00:21:12；课件 p.10]。
- **1970 年代 Unix 背景**说明危险接口为何会存在：早期设计假设输入不会超过预留空间，安全威胁模型与后来不同 [00:21:19–00:21:47]。
- **`echo` 示例**故意选择功能极简单的程序，使所有异常都能归因于输入写入和栈布局，而不是业务逻辑 [00:23:24–00:24:21；课件 p.11]。
- **反汇编问答**中老师让学生把 `0x18` 换算为 24，用机器指令回答“为什么不是输入第 4 个字符就立刻崩溃” [00:25:29–00:26:55；课件 p.12]。
- **23 字符边界例子**区分“已经越过 C 数组边界”与“已经破坏控制状态”：前者在第 4 个普通字符之后就发生，后者在这次布局中要写过 24 字节才发生 [00:28:35–00:29:18；课件 p.15]。

## 易错点

- 不要把 `buf[4]` 理解为可存 4 个普通字符的 C 字符串；还必须为 `\0` 留 1 字节，因此对象本身只能安全容纳 3 个字符 [00:24:31–00:24:54]。
- 不要认为编译器分配了 24 字节就把 `buf` 的合法容量扩大到 24。4 字节之后仍是越界写，只是前 20 字节暂未覆盖演示中的返回地址 [00:27:51–00:29:18；课件 p.13–15]。
- 不要把 `gets` 遇到换行停止误写成把换行也存入目标字符串；课件近似代码在退出循环后写的是 `\0` [课件 p.10]。
- 不要混淆“输入字符数”和“总写入字节数”。长度为 $n$ 的输入会额外写入终止符，总计 $n+1$ 字节 [00:28:35–00:29:41]。
- 不要把 23/24/25 的演示阈值推广到其他编译结果；老师明确通过当前反汇编才得到 24 字节栈分配 [00:25:29–00:27:18]。

3. **问：`sub $0x18,%rsp` 和 `mov %rsp,%rdi` 联合说明什么？**  
   **答：**`echo` 先在栈上留出 24 字节，再把这一区域起始地址作为 `gets` 的第一个参数 [00:25:59–00:27:18；课件 p.12]。

4. **问：为什么 23 个字符已经溢出 `buf[4]`，却没有改写返回地址？**  
   **答：**23 个字符加 `\0` 共 24 字节，填满了这次编译分配的 4 字节 `buf` 加 20 字节空隙，刚好停在返回地址之前 [00:27:51–00:29:18；课件 p.13–15]。

5. **问：本例中 24 个输入字符为什么比 23 个多出关键影响？**  
   **答：**24 个字符加 `\0` 共 25 字节，第 25 字节开始覆盖紧随 24 字节区域之后的返回地址 [00:29:19–00:29:41；课件 p.11、p.13–16]。

# 第 4 段：返回地址破坏、代码注入与 Morris Worm

> 时间范围：00:29:41–00:39:39  
> 对应课件：09-machine-advanced.pptx p.16–21

## 本段在整讲中的作用

本段接着上一段停在返回地址边界处的 `echo` 示例，先说明控制状态被破坏后的结果为何不确定：它可能立即 segmentation fault，也可能跳入无关代码、执行一串指令后又返回，看起来像是什么都没发生 [00:29:41–00:32:48；课件 p.16–18]。老师借此把“程序错误”推进到“攻击能力”：既然输入能改写保存的返回地址，攻击者就可以把输入的一部分布置为机器指令，再让 `ret` 跳到这些指令，从而形成 code injection attack [00:32:49–00:37:50；课件 p.19–20]。

最后，老师用 1988 年 Morris Worm 说明该路径不是假想：早期 `fingerd` 使用 `gets` 读取远程请求，攻击者可通过一条构造输入在受害机器执行代码并继续传播 [00:37:50–00:39:39；课件 p.20–21]。这一历史案例为后面讨论即时通信案例和防护技术提供现实动机。

## 教学展开

### 1. 越过 24 字节后开始改写返回地址

- 上一段已确定 `echo` 在 `%rsp` 处留出 24 字节，随后是保存的返回地址。本段开头明确：输入继续增长时，写入会破坏返回地址的字节表示，使 `ret` 不再回到 `call_echo` 中原定位置 [00:29:41–00:30:12；课件 p.16–17]。
- 老师重新核对演示字符串：第一串实际有 24 个字符，再加 `\0`，会改写返回地址的低位一个字节；第二串有 25 个字符，再加 `\0`，会严重改写返回地址的两个字节 [00:30:13–00:31:08；课件 p.16–17]。
- 25 字符示例发生 segmentation fault，但老师强调具体原因不能仅凭结果精确断定：错误地址可能让处理器落入某段无关代码，执行随机的有效指令，随后才在某处失败。越界后的行为“不漂亮且不可预测” [00:31:17–00:31:37；课件 p.16]。

### 2. 24 字符示例为何表面成功

- 正常返回地址是 `0x4006f6`；24 个字符后的终止字节把其低位字节清零，使返回目标变为 `0x400600` [00:31:52–00:32:16；课件 p.17–18]。
- `0x400600` 恰好落在无关函数 `register_tm_clones` 的一段代码中。课件列出从 `0x400600` 开始的若干指令，并显示该路径最终在 `0x400613` 执行 `retq`，回到 `main` [00:32:16–00:32:33；课件 p.18]。
- 因为这段误执行没有破坏演示所依赖的关键状态，程序表面上仍完成输出。老师用它强调：内存错误存在并不保证程序立刻崩溃；程序可能已经做了未知的额外工作，而使用者毫不知情 [00:32:26–00:32:48；课件 p.17–18]。

### 3. 从“意外跳转”转成“有意注入”

- 如果问题只导致崩溃，危害程度仍取决于软件用途；老师用起搏器与作业程序作对比，说明同一崩溃在不同系统中的后果不同 [00:32:49–00:33:07]。
- 更严重的路径是攻击者主动安排跳转目标。老师将其定义为 code injection attack：利用外部输入把可执行机器指令的字节放进受害程序内存，再控制程序去执行它们 [00:33:07–00:33:35；课件 p.19]。
- 输入字符串的布局按构造顺序是：
  1. 代表 exploit code 的机器指令字节；
  2. 为填到返回地址位置而加入的 padding；
  3. 用缓冲区起始地址 `B` 覆盖原保存返回地址 `A` [00:33:35–00:34:49；课件 p.19]。
- 在课件模型中，`P()` 调用含 `char buf[64]` 和 `gets(buf)` 的 `Q()`。当 `Q` 执行 `ret` 时，它不再取回原地址 `A`，而是取出被改写的 `B`；程序计数器因此跳到缓冲区开头并执行注入字节 [00:34:30–00:36:05；课件 p.19]。
- 老师现场指出课件口述中的调用关系笔误：应是 **P calls Q**，不是 “bar” 调用 Q [00:35:02–00:35:17；课件 p.19]。
- Attack Lab 的一部分会让学生亲自实施这种攻击，以具体理解字节编码、栈布局和控制转移 [00:36:09–00:36:27；课件 p.20]。

### 4. 覆盖位置并非完全靠猜

- 学生问如何确保新返回地址恰好落到保存返回地址的位置。老师回答：攻击者需要掌握二进制布局，但在当前例子中，反汇编已显示缓冲区到返回地址之间是 24 字节，因此只需令 exploit code 与 padding 合计 24 字节，接下来的字节就会覆盖返回地址 [00:36:27–00:37:21]。
- 远程攻击并非对任意未知程序都自动成功。攻击者需要足够了解远端运行环境，例如操作系统是 Linux、GCC 倾向生成怎样的栈帧，并以某种方式获得或推测目标代码信息 [00:37:21–00:37:50]。
- 这也解释了为什么后面引入地址随机化：只要攻击依赖可预测的缓冲区位置 `B`，让地址在每次运行间变化就能破坏这条假设。

### 5. Morris Worm：早期互联网中的实际利用

- 老师把 1988 年 Morris Worm 作为早期大规模互联网攻击。互联网当时规模较小，该蠕虫使很大比例的联网机器受到影响；CMU 因已修补相应漏洞而未中招 [00:37:50–00:38:30；课件 p.20–21]。
- 课件说明早期 finger server（`fingerd`）用 `gets()` 读取客户端发来的参数。正常请求形如 `finger droh@cs.cmu.edu`；攻击请求则把参数换成“exploit code + padding + new return address” [00:39:20–00:39:39；课件 p.21]。
- 课件进一步给出这段 exploit code 的目标：在受害机器启动 root shell，并建立直接到攻击者的 TCP 连接；成功进入一台机器后继续扫描其他目标并传播 [课件 p.21]。
- 课件记录约 6000 台计算机在数小时内被侵入，约占当时互联网的 10%；作者后来被起诉，CERT 也在此次事件后成立并设于 CMU [课件 p.21]。老师口述同样指出 CMU Software Engineering Institute 运行的 Computer Emergency Response Team 是对此次攻击的响应 [00:38:30–00:38:47]。
- 老师在本段结尾刚开始说明 `fingerd` 会接收远程消息并回复；`gets` 如何读取该参数的口述延续到下一段 [00:39:20–00:39:39]。

## 概念、符号与推导

### 返回地址的逐字节破坏

本例已有：

$$
d_{\mathrm{buffer\rightarrow return}}=24\ \mathrm{bytes}.
$$

设输入含 $n$ 个字符，则 `gets` 写入 $n+1$ 字节。于是：

- $n=24$ 时，第 25 个写入字节 `\0` 覆盖返回地址最低地址处的第一个字节；课堂演示中 `0x4006f6` 因此变为 `0x400600` [00:30:40–00:32:16；课件 p.17–18]。
- $n=25$ 时，字符与终止符继续覆盖返回地址的两个字节，演示最终 segmentation fault [00:30:59–00:31:37；课件 p.16]。

本段不把“改写多少字节”推广为固定崩溃规则；老师的结论恰恰是控制流落点及后果不可预测 [00:31:17–00:32:48]。

### 代码注入的数据布局

课件用 `A` 表示原返回地址、用 `B` 表示缓冲区/注入代码起始地址 [课件 p.19]：

```text
低地址                                                    高地址
[ exploit instruction bytes ][ padding to 24 bytes ][ B replaces A ]
                ^ B
```

控制转移链为：

$$
P\ \text{calls}\ Q
\rightarrow Q\ \text{executes}\ \texttt{ret}
\rightarrow \texttt{ret}\ \text{loads}\ B
\rightarrow \text{execute injected bytes at}\ B.
$$

该链条同时依赖两个可预测量：保存返回地址相对缓冲区的偏移，以及缓冲区的运行时地址 [00:33:35–00:37:50；课件 p.19]。

## 例子与课堂提示

- **`0x4006f6 → 0x400600`** 是“错误未必立刻显现”的反例：错误跳转进入现存有效代码，最终又执行 `retq`，使程序表面正常 [00:31:52–00:32:48；课件 p.18]。
- **起搏器与作业**用于区分同一崩溃的场景风险；老师随后强调安全问题不止是崩溃，而是攻击者可以选择被执行的代码 [00:32:49–00:33:35]。
- **24 字节 exploit code + padding**回答学生关于精确覆盖位置的问题：偏移可以从目标二进制的反汇编和编译布局中获得 [00:36:27–00:37:21]。
- **远程环境知识**说明经典注入并非魔法：攻击者要知道或推断操作系统、编译器和代码布局 [00:37:21–00:37:50]。
- **Morris Worm / `fingerd`**把 `gets`、远程输入、返回地址覆盖、执行代码和自传播串成一个现实案例 [00:37:50–00:39:39；课件 p.21]。

## 易错点

- 不要认为返回地址一旦被改写就必然立即 segmentation fault；`0x400600` 恰好是可执行代码，错误路径最终还能返回 [00:31:52–00:32:48；课件 p.18]。
- 不要把“程序给出了正确输出”当作内存安全证明；24 字符示例已经改变控制流，只是关键可见状态没有被破坏 [00:32:16–00:32:48]。
- 不要把注入代码理解为源代码字符串；输入中放的是机器指令的字节表示，正如 `objdump` 展示的 instruction bytes [00:33:35–00:34:12]。
- 不要混淆 `A` 与 `B`：`A` 是原保存返回地址，攻击者用 `B` 覆盖它，而 `B` 指向缓冲区内注入代码的开头 [00:34:20–00:35:41；课件 p.19]。
- 不要遗漏 padding 的作用：它不是待执行逻辑，而是把新返回地址精确推到保存返回地址槽位 [00:34:12–00:34:30；00:36:54–00:37:18]。
- 不要把本段的远程利用理解为在完全不知道目标二进制时仍可可靠工作；老师明确要求攻击者拥有足够的系统与代码布局知识 [00:37:21–00:37:50]。

## 本段掌握检查

1. **问：为什么 24 字符输入可能不崩溃，却仍已经破坏程序？**  
   **答：**终止符把返回地址从 `0x4006f6` 改成 `0x400600`；该地址碰巧落在有效代码中，执行若干无关指令后又返回，所以外部表现可能正常 [00:31:52–00:32:48；课件 p.17–18]。

2. **问：经典代码注入输入依次包含哪三部分？**  
   **答：**可执行指令字节、把长度补到返回地址槽位的 padding、指向缓冲区开头的地址 `B` [00:33:35–00:34:49；课件 p.19]。

3. **问：`Q` 执行 `ret` 后为什么会进入攻击代码？**  
   **答：**保存的原返回地址 `A` 已被 `B` 覆盖；`ret` 从栈取出 `B` 作为下一条指令地址，而 `B` 正指向注入字节 [00:34:30–00:36:05；课件 p.19]。

4. **问：攻击者如何知道 padding 应有多长？**  
   **答：**需要了解目标二进制；在 `echo` 例中，反汇编直接显示缓冲区起点到返回地址之间为 24 字节 [00:36:27–00:37:21]。

5. **问：Morris Worm 的 `fingerd` 路径如何对应本段的通用攻击布局？**  
   **答：**早期 `fingerd` 用 `gets` 读远程参数；伪造参数包含 exploit code、padding 和新返回地址，从而在受害机器执行 root shell 代码并继续传播 [00:39:20–00:39:39；课件 p.21]。

# 第 5 段：现实案例、安全接口与地址空间随机化

> 时间范围：00:39:39–00:49:33  
> 对应课件：09-machine-advanced.pptx p.21–28

## 本段在整讲中的作用

本段先收完 Morris Worm 的输入路径，再用 1999 年 AOL 与 Microsoft 的即时通信冲突说明缓冲区溢出甚至可能被软件提供方主动用来识别客户端 [00:39:39–00:42:21；课件 p.21–24]。老师随后区分 worm 与 virus，至此结束“漏洞是什么、怎样被利用、现实中发生过什么”的部分 [00:42:22–00:42:49；课件 p.25]。

从 [00:42:50] 起，课堂转入防护。老师按三层路线展开：应用代码避免无界写、系统提供地址随机化与不可执行区域、编译器插入 stack canary [课件 p.26]。本段完成第一层，并开始第二层中的 ASLR：它不修复越界，却破坏代码注入必须准确预测缓冲区地址这一前提 [00:42:50–00:49:33；课件 p.26–28]。

## 教学展开

### 1. 补完 `fingerd` 的远程输入路径

- `finger` 请求会向远程位置发送消息并等待响应；早期 `fingerd` 实现调用 `gets` 读取客户端发来的输入字符串 [00:39:39–00:39:51；课件 p.21]。
- 这与上一段的通用布局完全对应：远程输入中可依次携带 exploit code、padding 和新返回地址。课件说明注入代码会在受害机器启动 root shell，并建立指向攻击者的 TCP 连接，之后蠕虫继续扫描其他机器 [课件 p.21]。

### 2. IM War：利用自家客户端漏洞识别竞争者

- 老师先补背景：AOL 当时运营流行的互联网与即时通信服务；Microsoft 发布自己的 MSN Messenger 客户端，但让它接入 AOL 的 AIM 服务器 [00:39:51–00:40:49；课件 p.22]。
- Microsoft 客户端起初能够正常通信，随后突然被阻断；Microsoft 修改客户端后可暂时恢复，AOL 再改变服务端策略，如此反复。课件记录双方至少经历 13 次这样的交锋 [00:40:50–00:41:21；课件 p.23]。
- 真正机制是 AOL 发现自己 AIM 客户端中的缓冲区溢出漏洞，并主动利用它在客户端机器执行代码、查看某位置的内容，以判断运行的是 AOL 客户端还是“外来”客户端 [00:41:21–00:41:54；课件 p.23]。
- 课件把机制具体化为：exploit code 从客户端某位置取回 4 字节 signature 并送回服务器；Microsoft 修改代码去匹配签名后，AOL 再更换签名位置 [课件 p.23]。
- 事件由署名 Phil Bucking 的邮件披露；课件保留邮件主题 “AOL exploiting buffer overrun bug in their own software!” 并注明邮件后来被判定来自 Microsoft 内部 [00:41:55–00:42:21；课件 p.24]。

### 3. Worm 与 virus 的区分

- **Worm**：能够独立运行，并把一个完整可工作的自身版本传播到其他计算机 [00:42:22–00:42:35；课件 p.25]。
- **Virus**：不能独立运行，而是把自身代码加入其他程序、借被感染程序改变行为 [00:42:35–00:42:49；课件 p.25]。
- 课件补充两者通常都以传播并造成破坏为目的；老师同时指出日常说法经常没有严格区分二者 [00:42:22–00:42:49；课件 p.25]。

### 4. 防护路线一：先不要写出溢出漏洞

- 老师首先把责任放回应用或服务器端代码作者：使用能表达最大长度的接口 [00:42:50–00:43:16；课件 p.26–27]。
- 用 `fgets(buf, 4, stdin)` 替代 `gets(buf)`。本讲强调 `fgets` 接收最大读取字节数；若输入更长，就按该限制截断，而不是继续越过缓冲区 [00:43:17–00:43:43；课件 p.27]。
- 用能给出限制的 `strncpy` 替代无界 `strcpy` [00:43:43–00:43:53；课件 p.27]。
- 不直接使用无宽度的 `scanf("%s", ...)`；可以先用 `fgets` 读取，或在格式串中写 `%ns`，其中 `n` 是适当的最大长度 [00:43:53–00:44:06；课件 p.27]。
- 老师把系统性检查和修补旧代码称为 hardening。它工作量很大，因为真实程序中有许多字符串复制位置，Unicode 与字节等字符编码转换还会引入细微的长度问题；开发工具能帮助发现部分漏洞，但不能据此认为风险已经消失 [00:44:07–00:44:51]。

### 5. 防护路线二的起点：ASLR

- 除了修代码，还可在系统中加入保障，使前面展示的利用更难成功。第一个机制是 stack randomization，更一般的名称是 **ASLR（address space layout randomization）** [00:44:51–00:45:21；课件 p.28]。
- 目标是让程序每次运行时的地址发生变化，使攻击者不能可靠预知对象位置 [00:45:21–00:45:39；课件 p.28]。
- 老师给出的实现模型是：在 `main` 执行前，启动代码先在栈上分配一个随机大小的空间，量级约为 1 MB；这会让本次运行中的所有栈位置整体平移 [00:45:39–00:46:21；课件 p.28]。

### 6. 五次运行的地址观察

- 演示程序基于此前的内存定位程序，打印四类地址：栈上的局部变量、全局变量、`malloc` 返回的 heap 地址和函数 `useless` 的代码地址 [00:46:33–00:47:28]。
- 五次执行中，全局变量地址保持 `0x60102c`，代码地址保持 `0x400590` [00:47:28–00:47:56]。
- 局部变量的栈地址在较低的约 5 个十六进制位上变化。老师先口误为 5 bytes，随即修正为 5 hex digits；$5\times4=20$ 位，因此变化范围约为 $2^{20}$，即约 1 MB [00:47:56–00:48:25]。
- `malloc` 得到的 heap 地址也随运行变化，说明这次系统的动态分配中同样包含随机性 [00:48:25–00:48:38]。

### 7. ASLR 正好打断代码注入的哪一步

- 经典注入攻击不仅要把机器指令写进缓冲区，还必须把缓冲区起始地址编码到覆盖返回地址的位置，使 `ret` 跳回注入代码 [00:48:39–00:49:25]。
- ASLR 让这个缓冲区地址在约一百万种位置范围内变化。老师强调，即使攻击者有完全相同的代码副本、也能在同类系统上运行，仍不能提前预测目标进程下一次运行的具体栈位置 [00:49:25–00:49:33，本句延续至下一段；课件 p.28]。
- 因而 ASLR 的作用不是阻止写越界，也不是删掉注入字节，而是降低“新返回地址准确指向注入代码”的可靠性。

## 概念、符号与推导

### 三层防护框架

课件先列出三类措施 [课件 p.26]：

1. 避免产生 overflow vulnerability；
2. 使用 system-level protections；
3. 让编译器使用 stack canary。

本段展开第 1 类和第 2 类中的地址随机化；不可执行栈与 canary 在后续段落展开。

### 有界接口所增加的信息

- `gets(buf)`：只有目标地址，没有容量；本段在替代方案中再次展示这一调用 [课件 p.27]。
- `fgets(buf, 4, stdin)`：额外提供最大读取量 `4` [00:43:17–00:43:43；课件 p.27]。
- `%ns`：在格式串中用整数 `n` 表达字符串最大长度 [00:43:53–00:44:06；课件 p.27]。

本段的逻辑不是“换函数名自然安全”，而是让执行复制的代码获得并遵守边界值。

### ASLR 变化位数

老师观察到约 5 个十六进制数字变化：

$$
5\ \text{hex digits}\times4\ \text{bits/digit}=20\ \text{bits},
$$

$$
2^{20}\approx1\ \text{MB}.
$$

这与课前启动阶段随机分配约 1 MB 栈空间的讲解相呼应 [00:45:39–00:46:21；00:47:56–00:48:25]。

### 被 ASLR 破坏的攻击前提

原攻击需要：

$$
A_{\mathrm{return}}=A_{\mathrm{injected\ buffer}}.
$$

当右侧地址每次运行改变，攻击者即使知道返回地址槽位相对缓冲区的偏移，也无法稳定填入正确的绝对目标地址 [00:48:39–00:49:33；课件 p.28]。

# 第 6 段：不可执行栈与 stack canary 的汇编机制

> 时间范围：00:49:33–00:59:18  
> 对应课件：09-machine-advanced.pptx p.28–33

## 本段在整讲中的作用

本段先收束 ASLR：即使攻击者拥有相同代码并能在同类系统上运行，也无法提前知道下一次运行时注入缓冲区的准确位置 [00:49:33–00:49:59；课件 p.28]。然后老师继续系统级防护路径，依次讲不可执行栈和 stack canary [00:49:59–00:59:18；课件 p.29–33]。

两种机制打断的环节不同：不可执行栈阻止处理器把栈中的输入字节当指令执行；canary 则在函数返回前检测缓冲区到控制状态之间的栈区域是否被改写。老师通过同一个脆弱 `echo` 函数说明，即使源代码仍使用 `gets`，编译器也能插入检测逻辑，但这不等于源代码漏洞已经消失。

## 教学展开

### 1. ASLR 的结论

- 栈位置在约一百万种取值范围内变化，因此攻击者无法从一次运行推知下一次运行的缓冲区地址。老师据此说随机化会挫败前面那种需要返回到注入缓冲区的攻击 [00:49:33–00:49:59；课件 p.28]。
- 这里的限定词是“这种攻击”：地址随机化针对的是目标地址可预测性，不是直接禁止越界写。

### 2. 为什么栈不应默认执行代码

- 老师提出直接问题：正常代码应位于 text segment，为什么栈中的数据也能被当作代码执行 [00:49:59–00:50:23；课件 p.29]？
- 传统 x86 对内存区域区分可写与可读；老师说明当时“可读”也被解释为“可执行”，即任何可读区域都可取指执行 [00:50:23–00:51:02；课件 p.29]。
- 后来的硬件先由 AMD、再由 Intel 增加独立 execute permission，使读、写、执行成为可分别控制的权限，类似 Unix 文件权限 [00:51:02–00:51:22；课件 p.29]。
- 系统把栈标为 non-executable 后，即使攻击者通过 `gets` 把机器指令字节写入栈，处理器尝试从那里执行也会失败 [00:51:22–00:51:33；课件 p.29]。

### 3. 同一脆弱源码，加入 stack protector

- 第三个机制是放在栈中的 canary。老师说部分学生在 Bomb Lab 反汇编中已经见过这类代码，因为 GCC 的 stack protection 在当时已默认启用 [00:51:33–00:52:05；00:54:01–00:54:40；课件 p.30]。
- 新演示程序 `bufdemo-sp` 与之前源码相同，只是使用 stack protector 编译；`sp` 与先前 `nsp` 形成对照 [00:52:05–00:52:22]。
- 现场口述结果是 8 个字符尚不报错，9 个字符触发表示 “stack smashing detected” 的退出信息 [00:52:22–00:53:10]。课件 p.30 的静态示例则显示 7 个字符成功、8 个字符触发；这一差异在待核对项保留。
- 老师由错误信息说明 buffer overflow 也常称为 stack smashing。尽管源码仍然使用过小缓冲区和 `gets`，编译器生成的代码在函数返回前识别了破坏 [00:52:35–00:53:15；课件 p.30]。

### 4. “Canary” 名称表达的是预警作用

- 老师用旧时煤矿中的 canary 作类比：在可靠气体测量手段不足时，矿工观察对甲烷敏感的 canary；它出现异常就是环境危险的预警 [00:53:19–00:54:01]。
- 栈 canary 同样不是阻止越界发生的墙，而是放在关键状态之前的特殊值；如果它改变，就说明有数据从缓冲区方向越界写过来 [00:53:53–00:54:18；课件 p.30]。

### 5. 受保护 `echo` 的完整汇编骨架

课件 p.31 给出的关键指令按执行顺序为：

```asm
40072f: sub    $0x18,%rsp
400733: mov    %fs:0x28,%rax
40073c: mov    %rax,0x8(%rsp)
400741: xor    %eax,%eax
400743: mov    %rsp,%rdi
400746: callq  4006e0 <gets>
40074b: mov    %rsp,%rdi
40074e: callq  400570 <puts@plt>
400753: mov    0x8(%rsp),%rax
400758: xor    %fs:0x28,%rax
400761: je     400768 <echo+0x39>
400763: callq  400580 <__stack_chk_fail@plt>
400768: add    $0x18,%rsp
40076c: retq
```

- 和未保护版本一样，函数先用 `sub $0x18,%rsp` 分配 24 字节 [00:54:40–00:54:49；课件 p.31]。
- 新增设置步骤把 `%fs:0x28`（十进制偏移 40）处的 8 字节值读入 `%rax`，再存到 `8(%rsp)`；课件 p.32 将其概括为 “Get canary” 与 “Place on stack” [00:54:49–00:55:01；课件 p.31–32]。
- `xor %eax,%eax` 将 `%eax` 清零。老师只说接着把该寄存器清掉，没有在本段为此给出进一步目的，故不额外推断 [00:55:01–00:55:06；课件 p.31–32]。
- 原有主体仍把 `%rsp` 传给 `gets`，再传给 `puts` [00:55:06–00:55:23；课件 p.31]。
- 返回前，代码从 `8(%rsp)` 取回当前栈上值，与 `%fs:0x28` 的基准值做异或比较。相等时异或结果为 0，`je` 跳过失败调用；不等时调用 `__stack_chk_fail`，不进入正常 `retq` [00:55:23–00:57:39；课件 p.31、p.33]。

### 6. Canary 在栈上的位置与数据来源

- canary 是 8 字节值，放在 `%rsp+8`，位于从 `%rsp` 开始写入的缓冲区与更高地址的返回控制状态之间 [00:55:45–00:56:00；课件 p.32–33]。
- 老师把 `%fs` 追溯到原始 8086 的寄存器机制，并说它为了向后兼容仍然存在；在此代码中，`%fs:40` 用来取得一组普通程序不直接访问的值 [00:55:59–00:56:32]。
- 老师同时明确承认自己没有找到令他完全满意的相关文档，因此课堂能确认的是指令行为与 canary 用途，不应在笔记中凭常识补写更具体的运行时实现 [00:56:10–00:56:32]。

### 7. 检测时机与现场单步

- 对 7 字符输入，连同终止符在内的写入尚未改变演示中的 canary。`gets` 与 `puts` 返回后，函数在退出前重新读取并比较 canary [00:56:40–00:57:47；课件 p.33]。
- 若 canary 任一受检查字节被改变，比较失败即表示缓冲区越界可能已威胁栈中其他状态；这就是“煤矿预警”的机器级对应 [00:57:05–00:57:39]。
- 老师注意到现场 8 字符输入仍然成功，于是开始通过调试器单步核对：先定位 `sub 24`，再准备执行读取 canary 的指令；本段在地址 `0x40072f` 附近结束，具体 canary 值与最低字节在下一段继续 [00:57:39–00:59:18；课件 p.31]。

## 概念、符号与推导

### 两种机制的保护对象

| 机制 | 被破坏的攻击前提 | 本讲所述动作 |
|---|---|---|
| Non-executable stack | 注入栈中的字节必须能被取指执行 | 为内存增加独立 execute permission，并把 stack 标为不可执行 [00:49:59–00:51:33；课件 p.29] |
| Stack canary | 攻击者必须越过缓冲区去改写返回控制状态 | 在缓冲区之后放特殊值，返回前检查是否改变 [00:51:33–00:57:39；课件 p.30–33] |

### Canary 地址与宽度

由指令：

```asm
mov %fs:0x28,%rax
mov %rax,0x8(%rsp)
```

可直接读出：

$$
0x28=40,
$$

基准值从 `%fs:40` 取得，栈内副本从 `%rsp+8` 开始；`movq`/64 位寄存器与课件图共同表明副本宽度为 8 字节 [00:54:49–00:56:00；课件 p.31–32]。

### 异或比较

设栈内副本为 $C_s$，基准值为 $C_r$：

$$
C_s\oplus C_r=0\iff C_s=C_r.
$$

因此 `je` 走正常退出路径表示两值相等；否则调用 `__stack_chk_fail` [00:56:57–00:57:39；课件 p.31、p.33]。

- **相同源码、不同编译**说明 canary 是编译器插入的保护：开发者没有改掉 `gets`，但生成代码多出设置与检查路径 [00:52:05–00:53:15；课件 p.30–31]。

## 易错点

- 不要把 non-executable stack 说成栈不可读或不可写；本讲只说它不能作为指令来源执行 [00:50:23–00:51:33；课件 p.29]。
- 不要把 canary 当作边界检查。`gets` 仍可越界；canary 是在返回前发现邻近状态可能被覆盖 [00:52:53–00:57:39]。
- 不要漏掉检查失败路径：比较不相等时调用 `__stack_chk_fail`，而不是继续恢复 `%rsp` 并 `retq` [课件 p.31、p.33]。
- 不要把 `%fs:0x28` 与 `0x8(%rsp)` 混为同一地址：前者是取得基准 canary 的来源，后者是当前栈帧中的副本位置 [课件 p.31–33]。
- 不要根据老师关于 `%fs` 的简短描述补写未在 transcript/PPT 中出现的线程或内核实现细节；老师自己保留了文档不确定性 [00:55:59–00:56:32]。
- 不要忽略课件 p.30 与现场演示的字符阈值不同；应保留差异，而不是强行合并成一个无来源的数字。

## 本段掌握检查

1. **问：不可执行栈打断代码注入的哪一步？**  
   **答：**输入字节仍可能写入栈，但处理器不能从标为 non-executable 的栈区域执行这些字节 [00:49:59–00:51:33；课件 p.29]。

2. **问：stack canary 放在哪里、在什么时候检查？**  
   **答：**本例把 8 字节 canary 放在 `%rsp+8`、缓冲区之后；在 `gets` 和 `puts` 返回后、函数正常 `retq` 前检查 [00:54:40–00:57:39；课件 p.31–33]。

3. **问：汇编怎样取得并保存 canary？**  
   **答：**`mov %fs:0x28,%rax` 取得基准值，`mov %rax,0x8(%rsp)` 把副本放进当前栈帧 [课件 p.31–32]。

4. **问：为什么 `xor %fs:0x28,%rax` 后可以用 `je` 判断 canary 未变？**  
   **答：**从栈取回的值与基准值相等时异或结果为 0，零标志使 `je` 跳到正常退出路径；不等则调用失败函数 [00:56:57–00:57:39；课件 p.31、p.33]。

5. **问：为什么说加入 stack protector 没有修复源代码漏洞？**  
   **答：**源码仍是小缓冲区加 `gets`，越界仍能发生；编译器只是插入 canary，在返回前检测到破坏并终止正常返回 [00:52:05–00:53:15；课件 p.30–31]。

# 第 7 段：Canary 最低字节与 ROP gadget 链

> 时间范围：00:59:18–01:09:15  
> 对应课件：09-machine-advanced.pptx p.31–37

## 本段在整讲中的作用

本段先完成上一段的调试器单步，用实际 canary 值解释为什么现场输入 8 个字符仍未触发检查：canary 每次运行变化，但最低字节固定为 `0x00`，因此字符串终止符覆盖该字节时值没有改变；再多一个非零字符才会造成可检测差异 [00:59:18–01:02:22；课件 p.31–33]。

老师随后总结四条防护路线，并提出攻击者对 ASLR 与不可执行栈的回应：return-oriented programming（ROP）。ROP 不在栈上执行新注入的机器指令，而是寻找程序中已经存在、以 `ret` 结束的短指令片段（gadgets），再把它们的地址排在栈上形成执行链 [01:02:22–01:09:15；课件 p.34–37]。这段从“防护怎样工作”转到“防护覆盖边界在哪里”，并直接对应 Attack Lab 的第二类攻击。

## 教学展开

### 1. 现场读出 canary 的两个性质

- 老师在受保护 `echo` 的第一条指令附近继续单步，执行读取 canary 的指令并查看其值 [00:59:18–00:59:42；课件 p.31]。
- 第一个性质是**每次运行的值不同**，因此攻击者不能预先可靠知道完整 canary [00:59:42–00:59:51]。
- 第二个性质是**最低字节为零** [00:59:51–00:59:56]。

### 2. 最低字节为零与字符串 off-by-one

- 老师把这一设计与常见字符串错误联系起来：程序员可能只为可见字符分配空间，忘记额外的 null terminator，从而发生差一个字节的越界 [00:59:56–01:00:12]。
- 在本例中，8 个字符写入偏移 0–7，随后 `gets` 把 `\0` 写到偏移 8，也就是 canary 的最低地址字节。由于那里原本就是 `0x00`，写入后 canary 数值不变，比较仍通过 [01:00:11–01:00:28；课件 p.31–33]。
- 再输入第 9 个普通字符时，偏移 8 被非零字符覆盖，canary 改变；老师现场在“9 还是 10 个字符”之间有一次口误并花时间寻找调试位置，但最终总结是：8 个字符加终止符可以通过，更多字符会被检测 [01:00:28–01:02:22]。
- 这不是说 8 字符输入没有越界，而是该特定最低字节设计没有把终止 `\0` 的这一次改写视为 canary 变化。

### 3. 汇总四条防护路线

老师先说“三种”，随即修正为总共四条 [01:02:22–01:03:14]：

1. 写更好的代码，避免无界输入；
2. 随机化栈位置，使注入代码起始地址难以预测；
3. 把栈设为不可执行，使栈中注入字节不能直接运行；
4. 使用 stack canary 等机制，在源头附近检测可能的栈缓冲区溢出。

前三段防护内容到此形成闭环，老师紧接着问：如果随机化和不可执行栈阻断经典代码注入，攻击者还能怎样利用已经被改写的控制流？

### 4. ROP 的目标与边界

- Return-oriented programming 是针对部分防护发展出的攻击方式，Attack Lab 会同时包含 code injection 和 ROP，而旧实验只包含前者 [01:03:14–01:03:46；课件 p.34]。
- 按老师本讲的表述，ROP 不能解决 canary：只要溢出先改坏 canary，函数就会在正常 `ret` 前检测到。老师说自己没有见过绕过 stack canary 的例子；这应理解为本讲中的经验判断，不扩大成材料之外的普遍定理 [01:03:48–01:04:12；课件 p.34]。
- ROP 针对另外两项：即使不知道随机化后的 stack 地址、也不能从 stack 执行代码，攻击者仍可利用地址保持固定且本来就可执行的现有代码 [01:04:12–01:04:55；课件 p.34]。
- 单个现有函数通常不会恰好完成攻击者所需的全部工作，因此策略是寻找很多短片段并把它们串起来 [01:04:55–01:05:30；课件 p.34]。

### 5. Gadget 的定义

- Gadget 是现有可执行代码中的一段指令序列，最后以 `ret` 结束 [01:05:30–01:05:45；课件 p.34]。
- 在 x86 的 IA32 与 x86-64 编码中，`ret` 的单字节编码是十六进制 `0xC3` [01:05:35–01:05:59；课件 p.34]。
- 课件概括 gadget 的三个利用条件：代码位置在运行间固定、所在区域可执行、末尾 `ret` 能把控制权交给下一个栈上地址 [课件 p.34]。

### 6. Gadget 示例 1：使用函数尾部

- 原 C 函数 `ab_plus_c(a,b,c)` 计算 `a*b+c`；但攻击者不必从函数开头执行，可以只取末尾本来就存在的有用指令 [01:05:59–01:06:29；课件 p.35]。
- 老师说明该 5 字节片段包含一条执行加法效果的 `lea` 和结尾 `ret`。若事先把值放入 `%rdi` 与 `%rdx`，它会把两者之和放入 `%rax`，随后返回 [01:06:17–01:06:43]。
- 课件给出的 gadget 起始地址是 `0x4004d4` [课件 p.35]。这个例子中的操作与原函数机器代码本来要做的计算有关，因此是较直观的 gadget 来源。

### 7. Gadget 示例 2：从一条指令中间重新解码

- 第二个例子来自看似与寄存器搬运无关的函数：

```c
void setval(unsigned *p) {
    *p = 3347663060u;
}
```

  其正常反汇编包含 [课件 p.36]：

```asm
4004d9: c7 07 d4 48 89 c7    movl $0xc78948d4,(%rdi)
4004df: c3                   retq
```

- x86 指令是按字节、可变长度解码的。若不从 `0x4004d9` 开始，而从其中第 4 个字节地址 `0x4004dc` 开始，字节序列 `48 89 c7 c3` 被重新解释为 `movq %rax,%rdi; retq` [01:07:13–01:08:24；课件 p.36]。
- 该 gadget 实现 `%rdi ← %rax`，而这并不是原 C 函数的源级意图。老师借此强调，寻找 gadget 不限于函数边界或编译器原本划分的指令边界 [01:07:13–01:08:24；课件 p.36]。

### 8. 为什么每个 gadget 都要以 `ret` 结束

- 攻击者不再把可执行代码放进缓冲区，而是把一系列 gadget 地址放到栈上 [01:08:26–01:08:42；课件 p.37]。
- 先触发一次 `ret`：它从栈取出一个地址，并开始执行第一个 gadget [01:08:42–01:09:15；课件 p.37]。
- 第一个 gadget 末尾的 `0xC3` 又执行 `ret`，将从栈取得下一个地址。完整的逐 gadget 执行过程在下一段继续。

## 概念、符号与推导

### 8 字符输入为何不改变 canary

本例的栈内 canary 从偏移 8 开始 [课件 p.31–33]。对 8 个普通字符：

$$
\begin{aligned}
\mathrm{characters} &\rightarrow \mathrm{offsets}\ 0,1,\ldots,7,\\
\mathtt{'\backslash0'} &\rightarrow \mathrm{offset}\ 8.
\end{aligned}
$$

又因 canary 在偏移 8 的原字节是 `0x00`：

$$
0x00\rightarrow0x00,
$$

所以比较看不到变化。第 9 个普通字符落在偏移 8，若它非零，则 canary 改变 [00:59:51–01:02:22]。

### Gadget 2 的地址与字节推导

原指令从 `0x4004d9` 开始；跳过前三个字节 `c7 07 d4`：

$$
0x4004d9+3=0x4004dc.
$$

从新地址开始的字节为：

```text
48 89 c7 | c3
movq %rax,%rdi | retq
```

这就是课件给出的 gadget 地址与操作 [课件 p.36]。

### ROP 地址链

栈中放置：

```text
[ address of gadget 1 ][ address of gadget 2 ][ address of gadget 3 ] ...
```

执行关系为：

$$
\mathtt{ret}\rightarrow G_1\rightarrow\mathtt{ret}\rightarrow G_2
\rightarrow\texttt{ret}\rightarrow G_3\rightarrow\cdots
$$

其中每个 $G_i$ 是现有可执行代码，栈中保存的是地址而不是待执行的新指令字节 [01:08:26–01:09:15；课件 p.34、p.37]。

## 例子与课堂提示

- **Canary 最低字节**解释了现场演示，而不是否认越界：终止符确实写到 canary 位置，只是写入值与原值相同 [00:59:51–01:02:22]。
- **四项防护总结**把程序员责任与系统/编译器机制放在同一框架中，便于判断每项分别打断哪一个攻击前提 [01:02:22–01:03:14]。
- **Gadget 1**展示“函数尾部本来就有用”的直观来源 [01:05:59–01:07:13；课件 p.35]。
- **Gadget 2**展示更反直觉的来源：从已有指令中间开始，得到原 C 代码没有表达过的寄存器搬运 [01:07:13–01:08:24；课件 p.36]。
- **Attack Lab 新旧对比**说明教学安排：新实验让学生同时实践 code injection 与 ROP [01:03:21–01:03:46]。

## 易错点

- 不要把最低字节为零理解成整个 canary 为零；老师明确说完整值每次运行变化且不可预测 [00:59:42–00:59:56]。
- 不要说 8 字符输入“没有越界”；终止符已经写到 canary 的最低字节，只是没有改变该字节 [01:00:04–01:00:28]。
- 不要把 ROP 说成绕过本讲全部三项系统保护。老师明确说它可应对 stack randomization 与 non-executable stack，但不解决 canary [01:03:48–01:04:16；课件 p.34]。
- 不要认为 gadget 必须是完整函数或从合法指令边界开始；`0x4004dc` 示例就是从原指令内部重新解码 [01:07:13–01:08:24；课件 p.36]。
- 不要把栈中的 gadget 地址误当作在栈上执行的机器代码；真正执行的是 text/library 中已有、可执行的指令 [01:04:16–01:05:25；01:08:26–01:09:15]。
- 不要忽略 `0xC3` 的作用：它不只是 gadget 的结尾标记，也是从当前片段转到栈上下一地址的控制机制 [01:05:35–01:05:59；01:08:26–01:09:15]。

# 第 8 段：ROP 执行、Union 重叠存储与字节序

> 时间范围：01:09:15–01:18:36  
> 对应课件：09-machine-advanced.pptx p.37–47

## 本段在整讲中的作用

本段先完成 ROP 的执行链：每个 gadget 末尾的 `ret` 从栈取出下一个 gadget 地址，于是原本由顺序程序计数器组织的执行，被改造成由栈上地址序列组织的执行 [01:09:15–01:10:29；课件 p.37]。老师同时明确 ROP 仍无法消除 canary 检测，并解释 Attack Lab 为教学目的分别启用或关闭哪些保护 [01:10:29–01:12:46；课件 p.37–38]。

随后课堂进入本讲最后一条主线 union。老师先把 union 与 struct 的分配方式对比，再展示 union 如何在不改变比特的情况下以不同类型观察同一存储，最后借一个 8 字节 union 重访 little-endian 与 big-endian，并总结数组、结构体、联合体三种 C 复合类型 [01:12:46–01:18:36；课件 p.39–47]。

## 教学展开

### 1. ROP 如何从一个 gadget 转到下一个

- 初始 `ret` 从栈弹出第一个 gadget 地址并开始执行；第一个 gadget 到达末尾字节 `0xC3` 后再次执行 `ret`，从栈弹出第二个地址 [01:09:15–01:09:32；课件 p.37]。
- 如此重复，相当于把散落在现有代码中的片段连接起来。正常程序常由程序计数器按代码布局推进，而这里利用 x86 `ret` 的栈行为来决定下一段代码 [01:09:32–01:10:21；课件 p.37]。
- 老师说这种方法在其他处理器上也可能实现，但 x86 特别适合寻找和连接这些片段；Attack Lab 会让学生自己找 gadgets 并组合功能 [01:10:02–01:10:29]。

### 2. ROP 的剩余限制与实验配置

- 老师再次指出 stack canary 仍能相当有效地发现为了植入 gadget 地址而发生的 buffer overflow；本讲的 ROP 并不绕过 canary [01:10:29–01:10:51；课件 p.37]。
- Attack Lab 的目标程序经过有意编译和配置，保留可利用漏洞，否则实验会困难得多 [01:10:52–01:11:20]。
- **Code injection 部分**：关闭 stack randomization，并让 stack 可执行，从而允许学生把指令字节放进栈并跳过去执行 [01:11:20–01:11:33]。
- **ROP 部分**：重新启用随机化和不可执行栈，但关闭 stack canary，使学生仍能溢出缓冲区、写入 gadget 地址并建立地址链 [01:11:33–01:11:55]。
- 这组配置不是生产系统建议，而是为了分别隔离并练习两种攻击机制。

### 3. 为什么课程要让学生实践攻击

- 第一层教学目标是机器级程序执行：栈如何工作、指令如何按字节编码，以及如何更深入使用 GDB、`objdump` 等工具 [01:11:57–01:12:29]。
- 第二层目标是防御理解：课程假定学生会把知识用于正当目的，但要有效防御，也必须理解攻击者具体会做什么 [01:12:30–01:12:46]。

### 4. Union 与 struct 看起来相似、分配语义不同

- Union 的声明形式像 struct：都有命名字段，字段可有不同类型，也都可以定义相应指针 [01:12:46–01:13:14；课件 p.39]。
- Struct 为所有字段同时存在分配足够空间，并可能加入 padding 以满足对齐 [01:13:15–01:13:26；课件 p.39]。
- Union 只按最大字段分配一块空间，并假定任一时刻只使用一个字段；所有字段从同一位置重叠存放 [01:13:26–01:13:49；课件 p.39]。
- 课件对比：

```c
union U1 {
    char c;
    int i[2];
    double v;
} *up;

struct S1 {
    char c;
    int i[2];
    double v;
} *sp;
```

  `U1` 只需容纳其最大成员，而 `S1` 要让三个成员同时共存 [课件 p.39]。
- 若把 union 当作可同时保存多个独立值的结构，写一个字段会覆盖另一个字段的同一批字节。它适用于“多个表示中只用一个”，也可故意创建别名，以不同类型观察同一内存 [01:13:37–01:14:10]。

### 5. 用 union 访问浮点位模式

课件定义 [课件 p.40]：

```c
typedef union {
    float f;
    unsigned u;
} bit_float_t;

float bit2float(unsigned u) {
    bit_float_t arg;
    arg.u = u;
    return arg.f;
}

unsigned float2bit(float f) {
    bit_float_t arg;
    arg.f = f;
    return arg.u;
}
```

- `arg.u` 与 `arg.f` 覆盖同一 4 字节存储。先写 `unsigned` 再读 `float`，得到的是同一批位按浮点类型解释的结果；反向操作同理 [01:14:10–01:14:48；课件 p.40]。
- 这与 `(float)u` 或 `(unsigned)f` 的数值 cast 根本不同。老师说明 cast 会改变位表示，产生与原数值相对应或最接近的目标类型数值；union 方式不改变位，只改变查看这些位所用的类型，因此所得数值可能相差很大 [01:14:48–01:15:27；课件 p.40]。
- 老师把它称为越过类型系统、直接取得位表示的一种技巧 [01:15:10–01:15:27；课件 p.40]。

### 6. 一个 8 字节 union 的四种视图

课件接着定义 [课件 p.42]：

```c
union {
    unsigned char  c[8];
    unsigned short s[4];
    unsigned int   i[2];
    unsigned long  l[1];
} dw;
```

- 同一块 8 字节存储可被看成 8 个 byte、4 个 short、2 个 int，或在本讲所示 64 位机器上看成 1 个 64 位 long [01:15:27–01:16:08；课件 p.42]。
- 这种重叠视图会暴露 byte ordering：同样的连续字节，在不同机器上聚合成 short、int、long 时可能得到不同打印结果 [01:16:08–01:16:23；课件 p.41–42]。

### 7. 字节序定义

- 多字节 short/long/quad word 在内存中占连续 2/4/8 字节，问题在于最低地址对应最高有效字节还是最低有效字节 [课件 p.41]。
- **Big-endian**：最高有效字节位于最低地址；课件举 Sparc 为例 [课件 p.41]。
- **Little-endian**：最低有效字节位于最低地址；课件列出 Intel x86，以及 ARM Android 和 iOS [课件 p.41]。
- **Bi-endian**：可配置为任一种；课件列 ARM [课件 p.41]。
- 不同字节序机器交换二进制数据时，这种差异可能造成问题 [课件 p.41]。

### 8. 先逐字节写入，再从宽类型读取

示例先执行 [课件 p.43]：

```c
for (j = 0; j < 8; j++)
    dw.c[j] = 0xf0 + j;
```

因此地址从低到高依次存入：

```text
f0 f1 f2 f3 f4 f5 f6 f7
```

随后程序分别打印 `c[0..7]`、`s[0..3]`、`i[0..1]` 和 `l[0]` [课件 p.43]。

### 9. 三类机器上的输出

**IA32，little-endian，`long` 为 32 位** [01:16:23–01:16:36；课件 p.44]：

```text
Characters 0-7 == [0xf0,0xf1,0xf2,0xf3,0xf4,0xf5,0xf6,0xf7]
Shorts     0-3 == [0xf1f0,0xf3f2,0xf5f4,0xf7f6]
Ints       0-1 == [0xf3f2f1f0,0xf7f6f5f4]
Long       0   == [0xf3f2f1f0]
```

**Sun，big-endian，课件输出中的 `long` 为 32 位** [01:16:36–01:16:46；课件 p.45]：

```text
Characters 0-7 == [0xf0,0xf1,0xf2,0xf3,0xf4,0xf5,0xf6,0xf7]
Shorts     0-3 == [0xf0f1,0xf2f3,0xf4f5,0xf6f7]
Ints       0-1 == [0xf0f1f2f3,0xf4f5f6f7]
Long       0   == [0xf0f1f2f3]
```

**x86-64，little-endian，`long` 为 64 位** [01:16:46–01:17:10；课件 p.46]：

```text
Characters 0-7 == [0xf0,0xf1,0xf2,0xf3,0xf4,0xf5,0xf6,0xf7]
Shorts     0-3 == [0xf1f0,0xf3f2,0xf5f4,0xf7f6]
Ints       0-1 == [0xf3f2f1f0,0xf7f6f5f4]
Long       0   == [0xf7f6f5f4f3f2f1f0]
```

- 字符数组输出在三者上相同，因为每次只读取一个字节。多字节视图才体现字节序 [课件 p.44–46]。
- x86-64 的第一个低地址字节是 `0xF0`，而它成为 64 位 long 的最低有效字节，所以可据此判断 little-endian [01:16:58–01:17:10；课件 p.46]。

### 10. Union 的力量与可移植性风险

- Union 能直接接近低层字节，但等价于告诉 C 编译器“相信我知道自己在做什么”，绕过通常的类型抽象 [01:17:10–01:17:26；课件 p.47]。
- 若代码暗中依赖某种 byte ordering，同一 union 技巧可能在另一种机器上得到不同结果，造成不可移植行为 [01:17:26–01:17:36；课件 p.41、p.44–46]。

### 11. 三种 C 复合类型总结

- **Array**：相同类型元素连续存放，以数字位置索引；机器级访问通常形成按元素大小缩放的地址计算。课件还总结：满足元素对齐、数组表达式关联到首元素指针、没有边界检查 [01:17:36–01:18:01；课件 p.47]。
- **Struct**：固定数量、可为不同类型的命名字段按声明顺序分配；为满足对齐可在中间和末尾填充，字段访问通常变为相对结构起点的固定位移 [01:18:01–01:18:15；课件 p.47]。
- **Union**：多个声明重叠在同一位置，只按最大字段分配空间，不能让所有字段作为独立值同时存在；它提供绕过类型系统、以不同类型观察同一字节的能力 [01:18:15–01:18:33；课件 p.47]。
- 老师在 [01:18:33–01:18:36] 结束本讲。

## 概念、符号与推导

### ROP 的控制序列

若栈上依次保存 gadget 地址 $A_1,A_2,\ldots,A_n$，则每个 gadget 的末尾 `ret` 取出下一个地址：

$$
\mathtt{ret}\to A_1\to G_1\to\mathtt{ret}\to A_2\to G_2\to\cdots.
$$

这里栈提供“下一段在哪里”，真正的指令仍来自已有可执行代码 [01:09:15–01:10:29；课件 p.37]。

### Union 分配规则

对字段大小分别为 $s_1,s_2,\ldots,s_n$ 的 union，本讲给出的规则是按最大字段分配：

$$
S_{union}=\max(s_1,s_2,\ldots,s_n),
$$

并让所有字段从同一存储位置重叠。老师没有在本段给 `U1` 算具体总字节数，故不额外加入对齐后的精确大小 [01:13:15–01:13:49；课件 p.39]。

### 位重解释与数值转换

- Union 路径：写 `arg.u` 后读 `arg.f`，保留同一位串 $B$，只把解释函数从 unsigned 改为 float。
- Cast 路径：将 unsigned 的数值转换为目标 float 数值，老师明确说位串会改变 [01:14:18–01:15:22；课件 p.40]。

因此：

$$
\operatorname{reinterpret}_{float}(B)\ne\operatorname{float\_cast}(\operatorname{unsigned}(B))
$$

通常不能把 `bit2float(u)` 写成 `(float)u` 并期待相同含义。

### 从地址顺序推导整数打印顺序

内存低地址到高地址是 `f0 f1 f2 f3 ...` [课件 p.43]。

- Little-endian 的 16 位 `s[0]`：低地址 `f0` 是最低有效字节，高地址 `f1` 是最高有效字节，所以打印 `0xf1f0` [课件 p.44、p.46]。
- Big-endian 的 16 位 `s[0]`：低地址 `f0` 是最高有效字节，所以打印 `0xf0f1` [课件 p.45]。
- 同理，x86-64 的 8 字节 long 从数值最高位到最低位打印为 `f7 f6 f5 f4 f3 f2 f1 f0`，即 `0xf7f6f5f4f3f2f1f0` [课件 p.46]。

## 例子与课堂提示

- **实验保护开关**服务于区分攻击机制：code injection 需要可预测且可执行的 stack；ROP 允许 stack 随机且不可执行，但为了教学关闭 canary [01:11:20–01:11:55]。
- **`bit_float_t`**服务于区分“同一位串的不同解释”和“数值类型转换” [01:14:10–01:15:27；课件 p.40]。
- **`dw` 四视图**把 union 的重叠存储变成可观察实验：只写 `char` 数组，再从 short/int/long 读取 [01:15:35–01:16:23；课件 p.42–43]。
- **IA32 与 x86-64 对比**同时暴露两个变量：两者都是 little-endian，但本讲示例中的 `long` 宽度分别为 32 位和 64 位 [01:16:23–01:17:10；课件 p.44、p.46]。
- **Sun 对比**隔离字节序差异：相同地址字节在 big-endian 上按相反有效位方向聚合 [01:16:35–01:16:46；课件 p.45]。

## 易错点

- 不要认为 ROP 使 stack canary 失效；本讲明确说实验必须关闭 canary 才能让学生写入 gadget 地址链 [01:10:29–01:11:55]。
- 不要把 Attack Lab 的保护配置当作普通系统默认配置；它们是为了让每种攻击在受控条件下可实践 [01:10:52–01:11:55]。
- 不要把 union 当成节省空间的 struct 后仍同时保存全部字段；union 字段重叠，写一个会占用其他字段的同一存储 [01:13:15–01:14:10；课件 p.39]。
- 不要把 union 位重解释与 cast 混淆；前者保留位，后者按数值转换并改变位 [01:14:18–01:15:22；课件 p.40]。
- 不要只凭字符数组输出判断 endian；单字节视图在三台示例机器上相同，差异出现在 short/int/long 聚合 [课件 p.44–46]。
- 不要忽略数据模型差异：IA32 与 x86-64 都是 little-endian，但示例 `long` 分别打印 4 字节和 8 字节 [课件 p.44、p.46]。
- 不要假定依赖 union 字节视图的代码天然可移植；老师明确警告 byte-ordering 差异会使代码在某些机器上失效 [01:17:10–01:17:36]。

## 本段掌握检查

1. **问：ROP 链怎样从 gadget 1 转到 gadget 2？**  
   **答：**gadget 1 末尾执行 `ret`，从栈弹出 gadget 2 的地址并把控制转移过去 [01:09:15–01:09:47；课件 p.37]。

2. **问：Attack Lab 的 code injection 与 ROP 部分分别怎样配置保护？**  
   **答：**code injection 关闭 stack randomization 并让 stack 可执行；ROP 重新启用随机化和不可执行栈，同时关闭 canary [01:11:20–01:11:55]。

3. **问：Union 与 struct 的核心分配差别是什么？**  
   **答：**struct 为所有字段同时存在分配空间并可能加 padding；union 只按最大字段分配一块重叠存储，假定一次使用一个字段 [01:13:15–01:13:49；课件 p.39]。

4. **问：`bit2float(u)` 为什么不等同于 `(float)u`？**  
   **答：**`bit2float` 通过 union 保留 `u` 的位并按 float 解读；cast 做数值转换，会改变位以表示对应浮点数 [01:14:18–01:15:22；课件 p.40]。

5. **问：内存字节为 `f0 f1 f2 f3` 时，little-endian 与 big-endian 的第一个 32 位 int 分别是什么？**  
   **答：**little-endian 为 `0xf3f2f1f0`，big-endian 为 `0xf0f1f2f3` [课件 p.44–46]。
