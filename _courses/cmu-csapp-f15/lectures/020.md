### 2. 从扫描所有块改为只链接空闲块（`00:06:36-00:38:58`）

显式链表把双向指针放进 free block 的旧 payload，搜索规模从全部 blocks 缩到 free blocks；代价是最小块更大、splice 更复杂。[00:07:44-00:09:51] [00:17:27-00:18:29] [00:38:00-00:38:34] 学生提问驱动老师补齐 locality、未来 workload hint、专用 fixed-size pool、payload 连续性和 coalescing invariant。[00:09:51-00:22:27] 随后老师才按 allocation、free insertion policy 和四种邻块状态逐图追踪指针更新。[00:22:33-00:36:18]

### 3. 用 size classes 同时争取时间与空间（`00:38:58-00:45:50`）

课件先用重复的 “Today” 议程页标记从 explicit free lists 转入 segregated free lists。[课件: 20-malloc-advanced.pptx p.14] 一条 explicit list 仍可能过长，因而按 block size 拆成多条链。seglist 缩小每次搜索集合，又让局部 first fit 近似全局 best fit；`sbrk` 则展示一次多申请以摊销 syscall 和过度扩堆压低 utilization 的直接冲突。[00:38:58-00:44:38] 老师以 Knuth 1973 和 Wilson et al. 1995 的资料结束 allocator 组织部分。[00:45:13-00:45:46] [课件: 20-malloc-advanced.pptx p.18]

## 概念与能力依赖

### Allocator 组织链

1. $U_k$、throughput 与 fragmentation 提供评价标准。
2. implicit list 暴露“allocate 扫描所有 blocks”的成本。
3. explicit list 只链接 free blocks，因此需要块内 `prev`/`next`。
4. 块内链指针提高最小块尺寸；物理邻接仍由 boundary tags 支持。
5. `free` 必须同时完成 physical coalescing 与 free-list splicing。
6. 单条 explicit list 仍为 $O(F)$ 搜索，于是按 size class 拆成 segregated lists。
7. size class 缩短链并近似 best fit，因此 throughput 和 utilization 可以同时改善。

[00:05:03-00:05:28] [00:07:44-00:09:51] [00:14:22-00:18:29] [00:28:01-00:38:34] [00:38:58-00:43:38]

### Garbage collection 推导链

1. 应用不再持有 pointer 的 allocated block 提供 garbage 例子。
2. 不能预测未来控制流，但可用“从 roots 是否存在 path”判定 reachability。
3. reachability 需要明确 root、heap node 和 block 内 pointer edge。
4. Mark 设置所有 reachable blocks 的位；marked 检查同时避免重复与环上无限递归。
5. Sweep 用 block lengths 遍历 heap，清 reachable marks，释放 allocated/unmarked blocks。
6. 精确算法要求 pointer 可辨、指向块首且不可隐藏；C 不满足。
7. C conservative GC 用 allocated-block interval tree 接受内部 pointer，代价是把某些 integers 当 pointer、保留实际 garbage。

[00:45:50-00:50:16] [00:50:54-01:01:57] [课件: 20-malloc-advanced.pptx p.20] [课件: 20-malloc-advanced.pptx p.27]

### Memory bug 调试链

1. `()`/`[]` 与 `*` 的 precedence 决定声明含义，也决定 `*size--` 的结合。
2. pointer 的类型、生命周期和 ownership 决定地址是否可读写。
3. 错误 write 常不立即失败，症状会远离根因。
4. 复杂结构不能只靠崩溃点；必须先写 invariants。
5. 静默 checker 把结构合法性变成 probe 信号，再沿时间位置做 binary search。

## 关键例子与适用边界

1. **Peak-utilization 现场纠错**：最大值必须遍历 $P_i$；这是本讲第一个“不要静默修字幕/板书”的证据点。[00:05:29-00:06:19]
2. **Fixed-size object pool**：同尺寸 AST nodes 可由大 chunk 切出并用 bit vector 标记，还能获得 contiguous access；它依赖专用 workload，不是通用 `malloc` 接口承诺。[00:18:29-00:20:27]
3. **Payload 不能分段拼接**：allocator 必须返回应用请求大小的 contiguous block，交付后不能把自己的链接写入 payload。[00:21:24-00:22:27]
4. **LIFO 与 address order**：LIFO 表头插入为常数时间但研究提示 fragmentation 较高；address order 要搜索但研究提示 fragmentation 较低。[00:23:51-00:25:07] [课件: 20-malloc-advanced.pptx p.7]
5. **四种 coalescing**：Case 1 不摘旧节点；单侧合并摘一个；双侧合并摘两个。Case 2/3 的字幕称谓与课件页标题存在冲突，不能只靠文本确定老师当时指图方向。[00:28:30-00:36:18] [课件: 20-malloc-advanced.pptx p.8] [课件: 20-malloc-advanced.pptx p.11]
6. **Seglist remainder**：split 后余块大小可能跨 class，必须重新分类；当前类失败后先查更大类，最后才 `sbrk`。[00:40:07-00:41:54]
7. **`sbrk` chunk**：较大 chunk 摊销昂贵 syscall，但扩大 $H_k$、压低 utilization；本讲不给最优 chunk 公式。[00:43:39-00:44:38]
8. **`foo` 的 128-byte garbage**：它说明“对象还占内存”与“应用仍能到达对象”是两件事。[00:46:33-00:47:20] [课件: 20-malloc-advanced.pptx p.20]
9. **Mark 图中的 edges**：是应用放入 allocated payload 的 pointers，不是 explicit free-list 的 `prev`/`next`。[00:55:48-00:56:03]
10. **C conservative 边界**：整数落入 allocated interval 会造成 false reachability；老师描述的是漏收垃圾，不是释放仍可达块。[01:00:18-01:01:57]

## 全讲易错点与证据边界

- 不要把 $U_k$ 写成当前 $P_k/H_k$；分子是截至 $k$ 的 payload high-water mark。[00:02:50-00:06:19]
- 不要把 free-list `next` 当成物理 successor；显式链表默认可按任意地址顺序链接。[00:09:01-00:09:51] [00:29:40-00:30:18]
- 不要以为 `prev`/`next` 存在后就不需要 footer/boundary tag；两套字段服务于不同邻接关系。[00:17:01-00:17:19] [课件: 20-malloc-advanced.pptx p.4]
- 不要把链指针视为“免费”；它们占旧 payload 并提高 minimum block size。[00:17:27-00:18:29]
- 不要把 isolated free block 与 adjacent free blocks 混同；前者可存在，后者必须 coalesce。[00:14:22-00:15:09]
- 不要因为 balanced tree 渐近复杂度好就断言它实际最快；老师强调与低常数 seglists 竞争时的维护成本。[00:25:18-00:26:28]
- 不要在 seglist 当前类失败后立刻 `sbrk`；应逐级搜索更大 classes。[00:41:07-00:41:54]
- 不要把 Mark 与 Sweep 混在一起；Mark 不释放，Sweep 才处理 allocated/unmarked blocks。[00:54:15-00:55:13]
- 不要把“无直接 root edge”误作 garbage 判据；只要存在 root 出发的多跳 path 就 reachable。[00:52:11-00:53:14]
- 不要把 C conservative GC 说成能收走全部垃圾；不确定值按 pointer 处理会保留一部分不可达块。[01:01:16-01:01:57]
- 不要把 `int *p[13]` 与 `int (*p)[13]`、`int *f()` 与 `int (*f)()` 混同；必须从变量名按括号和 precedence 向外读。[01:06:40-01:12:35] [课件: 20-malloc-advanced.pptx p.31]
- 不要把 `p += sizeof(int)` 当成移动一个 `int`；typed pointer arithmetic 已经按 `sizeof(*p)` 缩放。[01:15:30-01:16:27]
- 不要把 `*size--` 当成 `(*size)--`；老师的错误代码实际改变 pointer。[01:17:35-01:18:28]
- 不要认为保留一个旧地址就保留了对象 ownership；局部对象返回后、heap block free 后，该地址都可能失效或被复用。[01:18:28-01:19:27]
- 不要把 segfault 行当成根因行；memory corruption 往往在更早的错误 write 发生。[01:02:36-01:03:16] [01:19:39-01:19:58]
- 不要让 checker 正常时输出大量噪声；老师要求静默，只有 invariant violation 才报告。[01:21:24-01:21:36]

# 第 1 段：峰值内存利用率回顾与显式空闲链表引入

> 时间范围：`00:00:00-00:09:51`  
> 主要课件：[课件: 20-malloc-advanced.pptx p.1] [课件: 20-malloc-advanced.pptx p.2] [课件: 20-malloc-advanced.pptx p.3] [课件: 20-malloc-advanced.pptx p.4] [课件: 20-malloc-advanced.pptx p.5]

## 本段在整讲中的作用

老师先补正上一讲没有解释清楚的峰值内存利用率，再给出本讲路线，随后从上一讲的隐式空闲链表过渡到显式空闲链表。教学链条是：先明确评价分配器的空间指标，再开始讨论为了提高搜索效率而改变空闲块组织方式的办法。[00:00:08-00:00:17] [00:06:36-00:07:29] 课件列出的本讲主题依次是显式空闲链表、分离空闲链表、垃圾回收和内存相关错误。[课件: 20-malloc-advanced.pptx p.2]

## 教学展开

### 1. 为什么重新解释峰值内存利用率

老师说明，上一讲对 peak memory utilization 的解释不够清楚，而它又是重要概念，因此先回到请求序列本身。[00:00:08-00:00:24]

设程序依次执行请求

$$
R_0,R_1,\ldots,R_k,\ldots,R_{n-1}.
$$

执行完前 $k+1$ 个请求后：

- $H_k$ 是此时堆的大小；[00:00:33-00:01:01]
- $P_k$ 是此时所有已分配块的 payload 之和，即 aggregate payload。[00:01:01-00:01:38]

随着请求执行，`malloc` 使 aggregate payload 增加，`free` 使它减少，所以 $P_k$ 会随时间上下变化。[00:01:38-00:02:12] 老师把它解释成一个极端理想的基准：分配器没有任何元数据开销，而且还允许压紧块；因此当前 payload 总和代表容纳这些已分配 payload 所需的最少字节数。这个基准非常激进，实际无法达到，但可以作为 best case。[00:02:17-00:02:50]

### 2. 从瞬时 payload 得到峰值利用率

老师定义执行完前 $k+1$ 个请求后的峰值内存利用率：

$$
U_k=\frac{\max_{0\le i\le k}P_i}{H_k}.
$$

[00:02:50-00:03:42]

推导含义按老师的解释分两步：

1. 分子保留截至时刻 $k$ 的 payload “高水位线”，即此前出现过的最大 aggregate payload；[00:03:42-00:04:08]
2. 再除以执行到当前请求后的总堆大小 $H_k$，得到效率指标。[00:04:08-00:04:24]

课堂提问促使老师在板书中纠正下标：最大值内部必须遍历 $i\le k$，所以应写 $P_i$，不能仍写 $P_k$。[00:05:29-00:06:19] 这项纠正决定了公式是否真的表示“记住此前的高水位线”。

分母由分配器记录。每次调用 `sbrk` 扩展堆时，分配器把新增大小累计进 $H_k$；本课当前假设堆只增长。即使允许缩小，只要堆大小由分配器控制，它仍可跟踪。[00:04:25-00:05:03]

老师最后强调：$U_k$ 越高越好。对同一请求序列，$\max_{0\le i\le k}P_i$ 不随分配器实现改变；真正反映分配器空间效率的是 $H_k$。[00:05:03-00:05:28]

### 3. 本讲路线

在澄清指标后，老师回顾上一讲介绍了动态存储分配器的基础，本讲要考察更复杂的数据结构来保存空闲链表；之后简要考察一种垃圾回收器，最后列举动态分配存储可能引发的错误。[00:06:36-00:07:29] 这一安排与课件总览一致。[课件: 20-malloc-advanced.pptx p.2]

### 4. 从隐式链表到显式链表

上一讲的隐式形式通过遍历整个堆来访问空闲块。老师提出改进：只把空闲块组织成双向链表，这就是 explicit free list。[00:07:44-00:08:10] 课件把几种组织方式并列：隐式链表以块长度串起所有块；显式链表用指针只串起空闲块；后续还会讲按大小类别分开的链表以及以块大小为键的平衡树。[课件: 20-malloc-advanced.pptx p.3]

指针存放位置来自分配器接口约束：

- 已分配块仍由 header、可选的 boundary-tag footer、payload 和 padding 构成；分配器不得改动应用拥有的 payload。[00:08:25-00:08:50]
- 空闲块无人使用，因此可以把双向链表的 `next` 和 `prev` 指针放进原 payload 区。[00:08:50-00:09:08] [课件: 20-malloc-advanced.pptx p.4]
- boundary tag 仍然需要用于合并相邻空闲块，`next`/`prev` 不能替代它。[课件: 20-malloc-advanced.pptx p.4]

逻辑上它是一条普通双向链表；物理上，各空闲块可以散落在任意内存地址，链表前后关系不等于地址先后关系。老师用一个大小为 6 的块说明：它的 forward pointer 可以指向别处，而 backward pointer 甚至可以指向地址更高的块。[00:09:01-00:09:51] [课件: 20-malloc-advanced.pptx p.5]

## 概念、符号与推导

### 请求与利用率符号

| 符号 | 老师给出的含义 | 时间证据 |
|---|---|---|
| $R_i$ | 请求序列中的第 $i$ 个请求 | [00:00:24-00:00:50] |
| $H_k$ | 执行完前 $k+1$ 个请求后的堆大小 | [00:00:50-00:01:01] |
| $P_k$ | 同一时刻所有已分配 payload 的总和 | [00:01:01-00:01:38] |
| $\max_{0\le i\le k}P_i$ | 截至请求 $k$ 的 aggregate-payload 高水位线 | [00:03:42-00:04:08] |
| $U_k$ | 高水位 payload 与当前堆大小之比；越高越好 | [00:02:50-00:03:42] [00:05:03-00:05:10] |

### 显式空闲链表的不变量与代价

- 链表只包含空闲块，不包含已分配块。[00:07:44-00:08:10] [课件: 20-malloc-advanced.pptx p.4]
- 空闲块至少需要容纳前向、后向两个链指针；本段尚未量化由此产生的最小块大小。[00:08:10-00:09:08]
- 内存相邻关系与链表相邻关系是两套关系；本段只引出差异，具体释放和合并操作留到后文。[00:09:08-00:09:51]

## 例子与课堂提示

1. **理想分配器基准**：把 payload 总和想成无元数据开销且允许压紧的完美分配器所需空间，用来解释为什么它只能做不可达到的 best case。[00:02:17-00:02:50]
2. **高水位线**：即使当前 payload 已下降，分子仍记住过去的峰值；这个类比服务于最大值算子的理解。[00:03:42-00:04:08]
3. **跟踪堆大小**：每次 `sbrk` 扩堆都更新堆大小，说明 $H_k$ 对分配器是可观测量。[00:04:25-00:05:03]

## 本段掌握检查

### Q1. 为什么 $P_k$ 可以充当理想空间需求的基准？

**答：** 它只统计仍已分配的 payload，不含分配器开销；老师还假想允许压紧块，所以它表示这些 payload 所需的最少字节数，但现实分配器无法达到。[00:02:17-00:02:50]

### Q2. $U_k$ 的分子为什么要取 $\max_{0\le i\le k}P_i$？

**答：** aggregate payload 会随分配和释放上下变化，最大值用于记住截至当前的高水位线。[00:01:38-00:02:12] [00:03:42-00:04:08]

### Q3. 对同一请求序列，什么量不变，什么量体现不同分配器的差异？

**答：** payload 高水位 $\max_{0\le i\le k}P_i$ 不变；堆大小 $H_k$ 取决于分配器使用堆空间的效率。[00:05:03-00:05:28]

### Q4. 显式空闲链表为什么能把链指针放在块内？

**答：** 它只链接空闲块；空闲块的旧 payload 当前不属于应用，可供分配器存放 `next` 和 `prev`。已分配块的 payload 则不可触碰。[00:08:10-00:09:08]

### Q5. 显式链表中的前后关系和物理地址顺序有什么关系？

**答：** 默认没有必然关系；除非额外维持地址有序，逻辑相邻的空闲块可散落在任意地址。[00:09:01-00:09:51] [课件: 20-malloc-advanced.pptx p.5]

# 第 2 段：显式空闲链表的局部性、接口边界与块开销

> 时间范围：`00:09:51-00:19:49`  
> 主要课件：[课件: 20-malloc-advanced.pptx p.4] [课件: 20-malloc-advanced.pptx p.5] [课件: 20-malloc-advanced.pptx p.6] [课件: 20-malloc-advanced.pptx p.12]

## 本段在整讲中的作用

本段紧接显式空闲链表的物理布局，通过一连串学生提问补齐设计约束：合并、局部性、是否可给分配器提示、必须维持的不变量、双向指针的必要性、boundary tag 是否仍需保留，以及链指针对最小块大小的影响。末尾转向固定大小对象的专用分配器，为下一段的 workload-aware 设计铺垫。[00:09:51-00:19:49]

## 教学展开

### 1. 任意时刻的链表状态与合并问题

老师澄清，图中的布局是经过不定次数 `malloc` 和 `free` 后的某个状态，空闲块可以出现在任意内存位置。[00:09:51-00:10:12] [课件: 20-malloc-advanced.pptx p.5] 学生马上问：若释放的块夹在两个空闲块中间怎么办？老师回答必须 coalesce，并预告具体指针操作稍后展示；难点不在“是否合并”，而在合并后还要维护显式链表。[00:10:12-00:10:24]

### 2. 显式链表与局部性

学生问显式链表会怎样影响 locality。老师先说块本身仍然连续，因此仍有 block locality；若程序要扫描一组已分配块，把它们彼此连续地放置会更好，但维持这种布局存在取舍。[00:10:24-00:11:06]

老师随后修正自己“无需关心空闲块局部性”的初步说法：分配器遍历空闲链表时，访问一个空闲块会带入整个页；若同一页里包含更多后续链表节点，遍历也会受益。因此两侧都可能需要局部性：应用访问已分配块，分配器访问空闲块。[00:11:06-00:11:41]

### 3. 应用提示和历史预测

学生提出：若应用知道接下来会分配许多相同小对象，能否把这一信息传给分配器以改善性能或利用率？老师回答“完全可以”，但标准 `malloc` 接口没有这种参数；一旦依赖这类应用知识，就不再是这里讨论的通用分配器。[00:11:43-00:12:40]

### 4. 合并不变量和双向链表的理由

### 5. 元数据怎样影响利用率和最小块大小

`next`/`prev` 不能取代 boundary tag；老师明确说仍然需要，具体原因将在释放与合并时显现。[00:17:01-00:17:19] 课件也写明显式链表 “Still need boundary tags for coalescing”。[课件: 20-malloc-advanced.pptx p.4]

对于小请求，header、footer、`prev`、`next` 共同施加最小块大小。老师逐项列出四个 one-word 字段，并说明即使请求的 payload 为 0，也不能分配比最小块更小的块；看似“免费”使用旧 payload 的链指针其实会提高最小块门槛。[00:17:27-00:18:29] 课件总结为每个空闲块的 links 需要额外两个 words。[课件: 20-malloc-advanced.pptx p.12]

学生提出先申请一个大块再自行切分。老师认为，若请求对象大小相同，这是很好的专用策略；编译器构造抽象语法树时会动态分配许多相同大小的节点，就是这种 workload 的例子。[00:18:29-00:19:49] 具体实现效果在下一段继续展开。

# 第 3 段：专用分配、显式链表分配与释放策略

> 时间范围：`00:19:49-00:29:40`  
> 主要课件：[课件: 20-malloc-advanced.pptx p.6] [课件: 20-malloc-advanced.pptx p.7] [课件: 20-malloc-advanced.pptx p.8] [课件: 20-malloc-advanced.pptx p.13] [课件: 20-malloc-advanced.pptx p.17]

## 本段在整讲中的作用

本段先完成固定大小对象专用分配器的讨论，再回到通用分配器的接口边界；随后正式讲显式空闲链表上的 allocation、两种 free insertion policy，以及 LIFO 下第一个合并案例。中间穿插了老师对平衡树、分离链表、常数因子和“过早优化”的工程判断。[00:19:49-00:29:40]

## 教学展开

### 1. 固定大小对象：大 chunk、位向量和连续布局

若已知对象大小一致，可以先申请一个大 chunk，再从中切出所有对象。老师说这种方法非常高效：甚至不需要为每个对象保存链指针，只需一个 bit vector 标记各 chunk 已分配还是空闲。[00:19:49-00:20:07] 另一个副作用是对象可以连续放置；若这些对象组成程序将遍历的链表，按顺序连续分配会改善访问布局。[00:20:07-00:20:27]

对不知道未来请求的通用分配器，仍可对程序行为作一般假设、运行 traces，或在 malloc lab 中观察给定 traces 的模式。允许针对 workload 的一般规律优化，但不能写死“若大小依次为 42、24，就认定是某条测试 trace”的条件分支。[00:20:27-00:21:21]

### 2. 分配器必须返回连续且不可侵占的 payload

学生问能否把一个 payload 拆成不同堆区域，再用指针连接。老师先反复确认问题，随后给出接口约束：应用期望一个指定大小的连续块；allocator 只能返回这个连续块，返回后不得在 payload 中放自己的指针或再改动它。[00:21:24-00:22:27]

### 3. 从显式空闲链表中分配

老师以空闲链表中间的一个块为例。选中它并按需要切分后，分配器调整前后相邻空闲节点的 forward/back pointers，使它们连接到切分后留下的新空闲块。[00:22:33-00:23:20] 课件用 before/after 图表示 “malloc with splitting”。[课件: 20-malloc-advanced.pptx p.6]

老师按图数出一共更新六个指针；这里是图示操作次数，不是所有实现、所有边界情形都固定更新六次。[00:23:08-00:23:20]

### 4. 释放后的插入位置：LIFO 与地址有序

释放比分配更难，因为必须同时处理 coalescing。原来已分配的块不在 free list 中；一旦释放，就必须决定把它插到哪里。[00:23:20-00:23:51]

第一种是 LIFO：总把新释放块放到表头。最后释放且大小合适的块会最先被再次分配。它简单、每次做固定的少量指针更新，因此为常数时间；研究结果则提示它的碎片可能比地址有序策略更差。[00:23:51-00:24:25] [课件: 20-malloc-advanced.pptx p.7]

第二种是地址有序：插入后维持

$$
\operatorname{addr}(\text{prev}) < \operatorname{addr}(\text{curr}) < \operatorname{addr}(\text{next}).
$$

这通常要求搜索正确插入点，但研究提示其碎片低于 LIFO。[00:24:25-00:25:07] [课件: 20-malloc-advanced.pptx p.7]

### 5. 为什么老师不建议一开始就上平衡树

可以用平衡树加速按地址或大小的搜索；课件也把“以长度为键、块内存树指针的红黑树”列为第四种空闲块组织法。[00:25:07-00:25:28] [课件: 20-malloc-advanced.pptx p.13] 但老师提醒，malloc lab 中平衡树要与常数因子很小的分离链表竞争。即使渐近搜索好，维护树的常数开销也可能吞掉收益。[00:25:28-00:26:07]

随着 size classes 增多，分离链表的搜索趋近常数时间；按二次幂范围分级时，老师说搜索降为对数时间。课件同样把 power-of-two classes 的优势写为 log time。[00:26:07-00:26:28] [课件: 20-malloc-advanced.pptx p.17]

由此老师给出工程顺序：面对 allocator 这样大的设计空间，先实现简单版本，观察真正的慢点和低效点，再逐项优化。上一讲提到的“去掉已分配块 footer”就是应当延后的优化；一开始堆叠所有技巧属于 premature optimization。[00:26:33-00:27:53]

### 6. LIFO 释放：Case 1

老师回到释放时必须维持“不能有两个相邻空闲块”的不变量，并准备复习四种邻居状态。[00:28:01-00:28:30]

Case 1 中，待释放的黄色块的物理前驱和物理后继都已分配，因此无需合并。采用 LIFO 时：

1. 让 free-list root 指向新释放块；
2. 让新块的 forward/next 指针指向原来的表头；
3. 相应更新原表头的 back/prev 关系。

[00:28:30-00:29:40] 课件将其概括为 “Insert the freed block at the root of the list”。[课件: 20-malloc-advanced.pptx p.8]

## 概念、符号与推导

### 地址有序不变量

$$
\operatorname{addr}(\text{prev}) < \operatorname{addr}(\text{curr}) < \operatorname{addr}(\text{next}).
$$

此处 `prev`、`curr`、`next` 指链表顺序；该策略特意让链表顺序与块起始地址顺序一致。[00:24:29-00:24:50] [课件: 20-malloc-advanced.pptx p.7]

### 老师给出的复杂度比较

- LIFO 表头插入：常数时间。[00:23:51-00:24:19]
- 地址有序插入：通常要搜索插入位置。[00:24:29-00:25:07]
- 分离链表：类别足够细时搜索趋近常数；二次幂范围类别对应对数级类别搜索。[00:26:07-00:26:28]

关于平衡树更新复杂度，字幕在 [00:25:44] 记为 “N-log-N”，而上下文讨论单次树操作；本笔记不据常识替换老师原话，列入待核对。

# 第 4 段：显式链表的四种合并与分离链表引入

## 教学展开

### 1. 两套邻接关系必须分开命名

对于当前块，老师用 **predecessor/successor** 表示内存中物理相邻的前块和后块；它们可能已分配，也可能空闲，因而未必在 free list 中。用 **prev/next** 表示显式空闲链表中的前后节点。[00:29:40-00:30:18] 这是理解后续 splice 的前提：合并依据物理邻接，摘链和插链依据链表邻接。

### 2. 第一种单侧合并图示

从 [00:30:18] 开始，字幕把口述状态记作“predecessor free、successor allocated”，但紧接着又把 “successor block” 称为 free-list 节点，术语内部不一致。[00:30:18-00:30:50] 老师实际展示的操作链条是清楚的：

1. 将新释放块和唯一的空闲物理邻块合并成一个大空闲块；
2. 用该旧空闲节点的 `prev` 与 `next` 互连，把它从原 free-list 位置 splice out；
3. 让 root 指向合并块；
4. 让原表头的 `prev` 回指新表头。

[00:31:02-00:32:16]

课件把 Case 2 定义为摘除 successor 后合并两块并插到 root，把 Case 3 定义为摘除 predecessor 后做同样操作。[课件: 20-malloc-advanced.pptx p.9] [课件: 20-malloc-advanced.pptx p.10] 因口述字幕与页上编号不一致，本笔记保留“第一种单侧合并图示”这一中性描述，并在待核对项列出差异。

学生问 root 是否为全局变量。老师回答可以是全局标量，也可以把 root 做成具有与普通节点相同 `prev`/`next` 字段的结构；后者有时能统一链表操作、简化实现。[00:32:16-00:32:52]

### 3. 单侧合并的局部优化

对于合并后起始地址不变的那种单侧情形，老师指出可以让扩大的空闲节点留在原 free-list 位置，不必先摘除再按 LIFO 插到表头；这样可免去 free-list 操作。当前图示仍坚持 LIFO，老师把“留在原位”明确称为一种后续优化。[00:33:02-00:33:42]

### 4. 对称的另一种单侧合并

字幕在 [00:33:42] 把下一情形称作 Case 3，并记为 predecessor allocated、successor free。操作仍是：将新释放块与空闲 successor 合并，摘除旧空闲节点，再把合并块放到表头，更新原表头的回指。[00:33:42-00:34:40]

它在逻辑上与前一情形对称，但如果想让节点留在原处，由于合并块的起始地址发生变化，原有链指针都要改为指向新块起点；更新量并不会减少。因此老师认为这里没有同样的性能优化收益。[00:34:40-00:35:18]

### 5. 两侧都空闲：三块合并

Case 4 中，物理 predecessor 和 successor 都空闲。老师要求：

1. 把 predecessor、当前释放块、successor 合成一个空闲块；
2. 分别从 free list 的两个位置摘除两个旧空闲邻块；
3. 把新的三块合并结果插到表头。

[00:35:18-00:36:18] 课件同样写明 “Splice out predecessor and successor blocks, coalesce all 3 memory blocks and insert the new block at the root”。[课件: 20-malloc-advanced.pptx p.11]

### 6. 实现为何比图更难，以及怎样分层实现

老师警告，这部分图上简单、代码却可能是学生写过最难的约 200 行代码之一：指针位于任意块内部，需要大量显式类型转换，几乎得不到 C 类型系统保护。[00:36:18-00:36:53]

他的实现建议是：

1. 从书中的隐式链表 allocator 开始，尽管它太慢、拿不到性能分；
2. 抽象出 `insert_block` 和 `remove_block`；
3. 先把隐式链表转换成显式链表。

这样可把一个约 “F” 的 allocator 提升到约 “B-”；要达到约 “A”，还需要稍后讲的 segregated lists。[00:36:53-00:38:00]

### 7. 显式链表总结并转入分离链表

显式链表的 allocation 时间与空闲块数量线性相关，而隐式链表与堆中全部块数量线性相关；当大多数内存已分配时，前者快得多。[00:38:00-00:38:15] 代价是分配/释放要 splice，代码更复杂；每块还要给链指针留额外空间，提高最小块大小。[00:38:15-00:38:34] [课件: 20-malloc-advanced.pptx p.12]

单条显式链表通常还不足以成为高效通用 allocator，但适合作为分离链表的一部分：维护多条 free lists，每条对应一个 size class。[00:38:34-00:39:20] 一个类别可以只含单一尺寸，也可以覆盖尺寸范围；对高频小尺寸可单独设类，对较大尺寸可用范围。[00:39:20-00:39:37] [课件: 20-malloc-advanced.pptx p.15]

# 第 5 段：分离链表的组织、性能与垃圾回收动机

> 时间范围：`00:39:37-00:49:34`  
> 主要课件：[课件: 20-malloc-advanced.pptx p.15] [课件: 20-malloc-advanced.pptx p.16] [课件: 20-malloc-advanced.pptx p.17] [课件: 20-malloc-advanced.pptx p.18] [课件: 20-malloc-advanced.pptx p.20] [课件: 20-malloc-advanced.pptx p.21]

## 本段在整讲中的作用

本段完成 allocator 组织方式的最高一层：用多个 size classes 同时改善搜索吞吐量和近似 best fit 的空间利用率。老师随后讨论 `sbrk` 的时间/空间权衡和链表头数组的存放位置，再从“应用负责 `free`”切换到“系统自动识别垃圾”的隐式内存管理，并在结尾提出实现 GC 所需而 C 不具备的指针假设。[00:39:37-00:49:34]

## 教学展开

### 1. 怎样划分 size classes

如果 workload 中有大量很小的块，可以为若干小尺寸分别维护 free list；更大的尺寸则常按二次幂范围分组。老师口头举出 `5-8` 这一范围，再设一个类别容纳其余大小。[00:39:37-00:40:07] 课件给出的完整示意类别是 `1-2`、`3`、`4`、`5-8`、`9-inf`，用来说明“小尺寸可单独分、较大尺寸按范围分”，而不是规定唯一划分。[课件: 20-malloc-advanced.pptx p.15]

### 2. Seglist 的分配流程

给定 free-list 数组，每个元素对应一个 size class。请求大小为 $n$ 时，老师按以下顺序讲解：[00:40:07-00:41:54]

1. 定位唯一覆盖 $n$ 的类别；
2. 在该 free list 中搜索大小为 $m$ 且 $m>n$ 的块；
3. 找到后放置请求块并切分；
4. 把切出的剩余空闲块放进它自己的合适类别，因为余块大小可能已不属于当前类别；
5. 当前类找不到时，依次尝试更大的类别；
6. 一直搜索到覆盖所有剩余大尺寸的最后一类；仍找不到则调用 `sbrk` 向系统申请更多堆内存。

课件补充：从新内存中分出 $n$ 字节后，把余部作为单个空闲块放入最大 size class；split 本身标为 optional。[课件: 20-malloc-advanced.pptx p.16]

释放流程较直接：先按此前规则 coalesce，再把合并结果放到覆盖其新大小的 free list。每条表内部仍可选择地址有序，也可简单地采用 LIFO 表头插入。[00:41:54-00:42:17]

### 3. 为什么同时提高吞吐量与利用率

老师称 segregated lists 是目前这些方法中“到目前为止最好”的类型，因为它同时改善两项指标：[00:42:07-00:43:38]

- **吞吐量更高**：每个类别的链表比一条巨型 free list 短，而且候选块大小本来就接近请求，通常更快找到可用块。[00:42:17-00:43:04]
- **利用率更好**：单链表上的 best fit 必须搜索整条表；size classes 让 first fit 在局部类别内近似全堆 best fit，而不承担完整 best-fit 搜索代价。[00:43:04-00:43:38] [课件: 20-malloc-advanced.pptx p.17]

课件给出极端边界：若每个块大小都有自己的类别，就等价于 best fit。老师没有在口述中继续推导这个极端情形。[课件: 20-malloc-advanced.pptx p.17]

### 4. `sbrk` 成本与扩堆粒度

学生问 `sbrk` 是否为常数时间。老师回答：是常数时间，但非常昂贵，因为它是 system call，要从用户空间进入内核并改变执行上下文和栈；老师给出的数量级说法是数百微秒。[00:43:39-00:44:20]

因此不应每次只扩恰好所需大小，而应一次申请较大的 chunk 来摊销 `sbrk` 成本；但 chunk 太大会扩大 $H_k$、降低内存利用率。这又是一个 space-time trade-off。[00:44:20-00:44:38]

### 5. free-list 数组放在哪里

学生问多条链表的头指针数组存在哪里。老师回答放在堆开头，malloc lab 也要求这样做。理由是数组本身占空间，大小会影响利用率评估，因此必须算进堆。[00:44:41-00:45:02]

老师随后给出进一步阅读：Knuth 1973 年的经典文本，以及 Wilson 等人在 1995 年发表的综合调查；后者可从 CS:APP 学生网站获得，并可能为 lab 提供思路。[00:45:13-00:45:46] [课件: 20-malloc-advanced.pptx p.18]

### 6. 从显式释放转向隐式内存管理

此前一直假设应用同时负责分配和释放。implicit memory manager 则让应用只申请，不必主动释放；系统自动识别再也无法引用的内存区域，即 garbage，并回收这些块。[00:45:50-00:46:33]

老师的例子是：函数 `foo` 执行 `malloc(128)`，把地址放在栈上的局部指针 `p` 中；函数返回后 `p` 消失，程序再也无法取得该块，它便成为垃圾。[00:46:33-00:47:05]

```c
void foo() {
   int *p = malloc(128);
   return; /* p block is now garbage */
}
```

[课件: 20-malloc-advanced.pptx p.20]

回收仍可调用此前讨论过的同一个 `free`，区别只在调用者从 application 变为 garbage collector。[00:47:05-00:47:20] GC 常见于多种动态语言；C/C++ 也有 conservative variants，但不能保证收走所有垃圾，有疑问时会保留块。[00:47:20-00:48:05] [课件: 20-malloc-advanced.pptx p.20]

### 7. 判定垃圾需要哪些假设

一般无法预测未来控制流会不会再次使用某块；但若内存中不存在到该块的任何指针，就能判断它不可能再被访问。[00:48:05-00:48:59] 为利用这一点，内存管理器需要扫描内存、识别所有指针，再判断哪些块被指向。

困难首先是区分 pointer 与 non-pointer。C 中一个 8-byte 整数值既可能是地址，也可能只是大整数，运行时无法仅看比特确定。[00:49:00-00:49:31] 第二个困难在本段末尾刚开始提出：即使识别出指针，还希望它指向块起点；C 指针却可以指向块内部。[00:49:31-00:49:34] [课件: 20-malloc-advanced.pptx p.21]

## 概念、符号与推导

### Seglist 搜索关系

对请求 $n$，在覆盖 $n$ 的类别中寻找 $m>n$ 的空闲块；未找到就按类别大小递增搜索。[00:40:07-00:41:54] 课件使用同一 $n,m$ 记号。[课件: 20-malloc-advanced.pptx p.16]

### First fit 近似 best fit 的逻辑

老师的推导链为：

1. size class 已限制候选块大小接近请求；
2. 因而该类别内较早遇到的可用块，通常也接近全堆最佳尺寸；
3. 所以局部 first fit 近似全局 best fit，同时避免扫描整个 free list。

[00:42:37-00:43:38] [课件: 20-malloc-advanced.pptx p.17]

### 扩堆的空间/时间权衡

老师没有给出摊销公式，只给出方向关系：扩堆 chunk 较大，`sbrk` 次数减少、调用成本更易摊销；但额外堆空间增加，使利用率下降。[00:44:20-00:44:38]

## 例子与课堂提示

1. **`1-2, 3, 4, 5-8, 9-inf`**：说明类别可以混用 singleton 与 range，而非要求全部按同一种宽度。[课件: 20-malloc-advanced.pptx p.15]

- **误解：split 后的 remainder 留在原 size class 即可。** 余块大小改变，必须按新大小重新归类。[00:40:32-00:40:59]

# 第 6 段：内存图与 Mark-and-Sweep 的标记阶段

> 时间范围：`00:49:34-00:59:31`  
> 主要课件：[课件: 20-malloc-advanced.pptx p.21] [课件: 20-malloc-advanced.pptx p.22] [课件: 20-malloc-advanced.pptx p.23] [课件: 20-malloc-advanced.pptx p.24] [课件: 20-malloc-advanced.pptx p.25] [课件: 20-malloc-advanced.pptx p.26]

## 本段在整讲中的作用

## 教学展开

### 1. 简单 GC 的指针假设为何不适用于 C

上一段已指出要区分指针与非指针。老师继续列出另外两项要求：[00:49:34-00:50:16]

- 指针必须指向块起点，这样才能从它前一 word 的 header 得到块大小；若指向块内部，就不知道起点和尺寸。[00:49:34-00:49:58]
- 指针不能被隐藏；“是指针”必须是稳定、静态可辨认的属性，不能通过转换等方式暂时消失。[00:49:58-00:50:16]

这些正是课件列出的三个假设：可区分 pointer/non-pointer、所有指针指向块起点、不能隐藏指针。[课件: 20-malloc-advanced.pptx p.21]

垃圾回收研究从 1960 年前后延续至今，并在并行、多线程程序中仍是研究主题。本课只讲较简单的 Mark-and-Sweep，其余算法不展开。[00:50:16-00:50:54]

课件列出了但老师本段没有展开的其他经典方法：reference counting、copying collection、generational collectors；课件还注明 Mark-and-Sweep 默认不移动块，除非另做 compact。[课件: 20-malloc-advanced.pptx p.22]

### 2. 把内存视为有向图

老师建立图模型：[00:50:54-00:52:11]

- 每个 node 对应一个已分配 heap block；
- 每条 edge 对应该块中保存的、指向另一块的应用指针；
- root nodes 位于堆外但含有指向堆的指针，例如栈和寄存器中的位置；课件还列出全局变量。[00:51:31-00:52:11] [课件: 20-malloc-advanced.pptx p.23]

一个块 **reachable**，当且仅当存在一条从任意 root 到它的路径。老师把图中的 reachable blocks 标成绿色；从 root 沿若干指针即可到达。[00:52:11-00:52:34]

不可达节点就是 garbage：未来应用没有从任何 root 出发的路径能取得它们，因此可以确定释放。[00:52:34-00:53:14] 回收后，这些节点从图中移除。[00:53:14-00:53:23] [课件: 20-malloc-advanced.pptx p.23]

### 3. 在 `malloc/free` 上构造收集器

应用仍像以前一样调用 `malloc`，allocator 也照常分配，直到“run out of space”。这可以指达到自定的最大 heap size，也可以指 OS 不再提供虚拟内存。[00:53:23-00:53:57]

每个块 header 增加一个 mark bit。老师指出 header 因对齐往往已有三四个 spare bits，可取其中一位。[00:53:57-00:54:15]

回收分两阶段：[00:54:15-00:55:13]

1. **Mark**：从所有 roots 出发遍历可达节点，并设置每个 reachable block 的 mark bit；
2. **Sweep**：从堆起点扫描全部块，查找 allocated 但 unmarked 的块；未标记意味着不可达，因此调用 `free`。

[课件: 20-malloc-advanced.pptx p.24]

### 4. 课堂图示中的边是什么

图中一个 root 指向中心块，中心块及后续块里的若干应用指针形成可达子图。约定指针指向 payload 起点，header 位于前一 word。[00:55:13-00:55:48]

老师特意澄清：图中的 edges 是应用放在 payload 内的指针，不是 allocator 维护的 free-list `prev`/`next`。Mark 后，所有可达块的 mark bit 被设为图中的粉色；未标记的 allocated blocks 可释放并回到 free list。[00:55:48-00:56:43]

### 5. 简化实现所提供的接口

老师定义一个便于说明的抽象机器：[00:56:43-00:57:38]

- `new(n)`：返回含 $n$ 个位置且全部清零的新块；
- `read(b,i)`：读取块 $b$ 的位置 $i$；
- `write(b,i,v)`：向块 $b$ 的位置 $i$ 写值 $v$；
- header 位于 `b[-1]`；
- `is_ptr(p)`：判断 $p$ 是否为指针；
- `length(b)`：返回不含 header 的块长度；
- `get_roots()`：返回全部 roots。

[课件: 20-malloc-advanced.pptx p.25]

### 6. `mark`：带两个终止条件的深度优先遍历

课件伪代码为：[课件: 20-malloc-advanced.pptx p.26]

```c
ptr mark(ptr p) {
   if (!is_ptr(p)) return;
   if (markBitSet(p)) return;
   setMarkBit(p);
   for (i=0; i < length(p); i++)
     mark(p[i]);
   return;
}
```

老师按执行顺序解释：[00:57:38-00:59:17]

1. 输入最初是 root 中的值；不是 pointer 就立即返回；
2. 若块已经 marked，也立即返回，因为从它可达的区域此前已处理；这个条件也阻止循环图无限递归；
3. 否则先设置当前块的 mark bit；
4. 扫描块内每个 word，递归调用 `mark(p[i])`；
5. 非指针 word 会在第一条判断返回，指针 word 则继续深度优先搜索。

老师把它归结为熟悉的 depth-first graph traversal。[00:59:04-00:59:17]

最后开始介绍 `sweep(p,end)`：参数分别指向第一个 heap block 和堆末尾，具体循环在下一段继续。[00:59:17-00:59:31]

## 概念、符号与推导

### Reachability 的形式化定义

令有向图 $G=(V,E)$，roots 构成集合 $R$。老师的定义可记为：

$$
b\ \text{is reachable}
\iff
\exists r\in R,\ \exists\text{ path }r\leadsto b.
$$

若不存在这样的 root-to-block path，则 $b$ 是 garbage。[00:52:11-00:53:14] [课件: 20-malloc-advanced.pptx p.23]

### Mark 的递归不变量

每次真正展开 `mark(p)` 前先把 $p$ 标记；若再次沿环回到 $p$，`markBitSet(p)` 立即终止。因此每个 reachable block 至多进入一次“扫描所有 words”的主体。[00:58:23-00:59:08]

本段没有给出 Mark-and-Sweep 总时间或空间复杂度公式。

## 例子与课堂提示

2. **root 示例**：栈、寄存器以及课件所列全局变量是应用当前可直接取得堆对象的入口。[00:51:31-00:51:57] [课件: 20-malloc-advanced.pptx p.23]

4. **应用边与 allocator 边**：GC 图只跟踪应用对象之间的指针，不能把 free-list 链指针混进可达性图。[00:55:48-00:56:03]

## 易错点与辨析

# 第 7 段：Sweep、C 的保守回收与指针声明解析

> 时间范围：`00:59:31-01:09:31`  
> 主要课件：[课件: 20-malloc-advanced.pptx p.26] [课件: 20-malloc-advanced.pptx p.27] [课件: 20-malloc-advanced.pptx p.28] [课件: 20-malloc-advanced.pptx p.29] [课件: 20-malloc-advanced.pptx p.30] [课件: 20-malloc-advanced.pptx p.31]

## 本段在整讲中的作用

老师先完成 Sweep 伪代码，再说明如何在不满足精确指针假设的 C 中做 conservative Mark-and-Sweep，以及为何它会保留部分实际垃圾。随后课程进入最后主题：内存错误。老师先解释这类错误为何在空间和时间上远离根因，再从 C 运算符优先级建立一套机械解析指针声明的方法，并完成前两个声明例子。[00:59:31-01:09:31]

## 教学展开

### 1. Sweep 顺序扫描整个堆

`sweep` 从首块走到 `end`。老师按循环说明：[00:59:31-01:00:05]

1. 若当前块 mark bit 已设置，说明它 reachable；清除 mark bit，为下次 GC 做准备；
2. 否则，若块仍标为 allocated，则它不可达，调用 `free(p)`；
3. 计算下一块地址并继续，直到堆末尾。

课件伪代码为：[课件: 20-malloc-advanced.pptx p.26]

```c
ptr sweep(ptr p, ptr end) {
   while (p < end) {
      if markBitSet(p)
         clearMarkBit();
      else if (allocateBitSet(p))
         free(p);
      p += length(p);
   }
}
```

这里保留课件抽取出的写法；老师只说明利用块长度取得下一块，没有在本段推导 header/步长的单位细节。[00:59:50-01:00:05]

### 2. 在 C 中保守地判断“这个 word 像不像指针”

C 中无法区分 pointer/non-pointer，指针又可落在块内部。[01:00:05-01:00:46] 老师提出一种保守方案：

1. 把扫描到的每个 word 都当作潜在 pointer；
2. 用平衡树记录所有 allocated blocks；
3. 对候选值查树，判断它是否落在某个已分配块的起止地址范围内；
4. 若落在范围内，就把它当成指向该块的 pointer，并把该块视为 reachable。

[01:00:46-01:01:26]

课件说明平衡树以 block start 为 key，左右链接可存进 header，需要额外两个 words；左子树地址较小，右子树地址较大。[课件: 20-malloc-advanced.pptx p.27]

“Conservative”的原因是候选值可能只是恰好落入该地址范围的大整数。此时系统会把本来不可达的块误判为 reachable，因而留下一些 garbage；它宁可漏收，也不冒险释放可能仍被引用的块。[01:01:16-01:01:57]

### 3. 为什么内存错误特别难找

课程切到 memory-related perils and pitfalls。[01:01:57-01:02:24] [课件: 20-malloc-advanced.pptx p.28] 老师说内存错误是最难调试的一类，因为根因和表现同时在 **space** 与 **time** 上分离：

- 错误 write 可能先悄悄破坏某个数据结构，不会立即报错；
- 很久以后，另一函数、另一模块读取那一位置时才失败；
- 因而崩溃点可能距离写坏位置很多代码行，也可能晚很多执行时间。

[01:02:24-01:03:16]

另一个主要来源是误解或误用 pointers，包括未正确初始化的 pointer。老师以自己的学习经历说明，仅靠模式匹配记住几种声明，并不等于理解指针。[01:03:24-01:04:40] 课件列出的错误类别包括坏指针解引用、未初始化读取、越界覆盖、不存在变量、多次释放、释放后引用和未释放。[课件: 20-malloc-advanced.pptx p.29]

### 4. 解析声明前先掌握运算符优先级

C 用运算符写声明，因此必须先知道 precedence。老师引用 K&R p.53，建议把该页作为随手参考。[01:04:40-01:05:10]

本段强调的相对顺序是：

1. function `()`、array `[]` 以及结构访问运算符具有高优先级；
2. 随后是 unary operators，包括 dereference `*` 与 address-of `&`；
3. arithmetic 的 binary forms 更低。

[01:05:10-01:06:00] [课件: 20-malloc-advanced.pptx p.30]

老师把记忆点压缩为：**function and array are higher than star**。[01:05:50-01:06:00]

### 5. 从变量名向外读声明的算法

老师给出一套构造英文解释的算法，并引用 K&R §5.12：[01:06:00-01:06:40] [课件: 20-malloc-advanced.pptx p.31]

1. 从 variable name 开始；
2. 查看名字左右两侧的 operators；
3. 按 parentheses 和 precedence 选择下一项；
4. 一层层向外读；
5. 最后落到基础 type。

第一个例子：

```c
int *p;
```

从 `p` 开始，右边无运算符，左边是 `*`，所以 “p is a pointer”；最后读到 `int`，完整解释是 **p is a pointer to int**。[01:06:45-01:07:50] [课件: 20-malloc-advanced.pptx p.31]

第二个例子：

## 概念、符号与推导

### Sweep 的分类表

| mark bit | allocate bit | 动作 |
|---|---|---|
| set | allocated | 清 mark bit，保留块 |
| clear | allocated | `free(p)` |
| clear | free | 不调用 `free`，前进到下一块 |

第三行来自伪代码 `else if (allocateBitSet(p))` 的控制流；老师没有单独展开它。[00:59:31-01:00:05] [课件: 20-malloc-advanced.pptx p.26]

### 保守回收的误判方向

$$
\text{integer value falls in allocated interval}
\Longrightarrow
\text{treated as pointer}
\Longrightarrow
\text{block retained}.
$$

因此会出现“垃圾被保留”的 false reachability；本段没有讲“仍可达块被错误释放”的路径。[01:01:16-01:01:57]

### 声明解析的优先级核心

$$
(),\ []\quad >\quad *\ \text{(declarator)}.
$$

所以 `int *p[13]` 先与 `[]` 结合，是 pointer 数组；若括号改变结合方式，含义也随之改变。[01:05:10-01:08:52]

## 易错点与辨析

## 教学展开

### 1. 括号可以显式固定声明的结合方式

本段从上一段尚未讲完的声明继续。老师先处理：

```c
int *(p[13]);
```

括号要求先看 `p[13]`，所以仍读作 **p is an array[13] of pointers to int**；它与 `int *p[13]` 含义相同，只是把原本由优先级决定的结合显式写出来。老师称这种显式写法是 good practice。[01:09:31-01:09:47] [课件: 20-malloc-advanced.pptx p.31]

接着课件给出：

```c
int **p;
```

应从 `p` 向左逐层读两个 `*`：**p is a pointer to a pointer to an int**。[01:09:47-01:10:37] [课件: 20-malloc-advanced.pptx p.31] 字幕在这里一度转成三个 `*`、又回到两个层次；声明文本和老师最后的解释以课件可见内容为准，歧义保留在待核对项。

### 2. 数组指针、返回指针的函数与复杂声明

下一个声明是：

```c
int (*p)[13];
```

括号迫使 `*` 先与 `p` 结合，因此先读 “p is a pointer”，再读右侧 `[13]`，最后读基础类型：**p is a pointer to an array[13] of int**。[01:10:42-01:10:54] [课件: 20-malloc-advanced.pptx p.31] 它与 `int *p[13]` 的区别完全来自括号改变结合顺序。

老师随后让全班判断：

```c
int *f();
```

因为 `()` 优先于左侧 `*`，`f` 首先是 function，再向外读返回类型：**f is a function returning a pointer to int**。[01:11:01-01:11:41] [课件: 20-malloc-advanced.pptx p.31]

出于时间考虑，老师跳过课件中间的若干声明，直接选最复杂的最后一个来证明算法仍然机械可用：[01:11:50-01:12:02]

```c
int (*(*x[3])())[5];
```

课件给出的完整读法是：**x is an array[3] of pointers to functions returning pointers to array[5] of ints**。[课件: 20-malloc-advanced.pptx p.31] 老师口头依次读出 array、pointers、functions、returning pointers、array five、ints，并警告实际代码若写成如此复杂的类型，“shame on you”；例子的目的只是验证解析算法，而不是鼓励这种接口。[01:12:02-01:12:23]

老师由此收束：从变量名出发、按括号与优先级向外读，任何声明都能转成确定的句子；K&R p.53 是运算符参考。[01:12:23-01:12:35]

### 3. 坏指针解引用：`scanf` 少传地址

老师进入内存错误案例，第一项是经典 `scanf` bug：[01:12:35-01:13:06]

```c
int val;

...

scanf("%d", val);
```

[课件: 20-malloc-advanced.pptx p.32]

`scanf` 需要一个可写入结果的位置；代码却传入 `val` 的值，没有传变量地址。老师把错误概括为忘记传 address，因此 `scanf` 不知道应把输入数据写到哪里。[01:12:45-01:13:06]

### 4. 读取未初始化 heap 数据

第二个案例计算矩阵-向量乘积：[课件: 20-malloc-advanced.pptx p.33]

```c
/* return y = Ax */
int *matvec(int **A, int *x) { 
   int *y = malloc(N*sizeof(int));
   int i, j;

   for (i=0; i<N; i++)
      for (j=0; j<N; j++)
         y[i] += A[i][j]*x[j];
   return y;
}
```

代码在第一次执行 `y[i] += ...` 时就读取 `y[i]` 的旧值，但 `malloc` 返回的 heap 数据不能假定全为 0。错误链是：只分配 `y` -> 未初始化元素 -> 用 `+=` 先读后写 -> 结果依赖不确定旧内容。[01:13:06-01:13:38]

### 5. 为二维数组分配了错误的元素尺寸

老师要创建含 $N$ 个 `int *` 的顶层数组，再为每个元素申请 $M$ 个 `int`：[01:13:43-01:14:21]

```c
int **p;

p = malloc(N*sizeof(int));

for (i=0; i<N; i++) {
   p[i] = malloc(M*sizeof(int));
}
```

[课件: 20-malloc-advanced.pptx p.34]

课堂判断的 bug 在第一次 `malloc`：顶层数组的元素是 `int *`，却按 `int` 的大小分配。老师明确指出应按 `sizeof(int *)` 计量。把 int 与 pointer 假定为同尺寸在 32-bit 代码中可能成立，在 64-bit 中不成立，因此旧代码迁移到 64-bit 时常在这里暴露。[01:14:21-01:14:51]

### 6. Off-by-one：分配 $N$ 项却写 $N+1$ 项

接着顶层分配尺寸已改对，但循环边界写成 `i<=N`：[课件: 20-malloc-advanced.pptx p.35]

```c
int **p;

p = malloc(N*sizeof(int *));

for (i=0; i<=N; i++) {
   p[i] = malloc(M*sizeof(int));
}
```

数组只有索引范围内的 $N$ 个位置，循环却执行 $N+1$ 次并访问 `p[N]`。老师将其称为经典 off-by-one bug。[01:14:51-01:15:13]

### 7. 不检查字符串最大长度

老师把 attack lab 中的代码注入联系到未检查 buffer 大小：[01:15:14-01:15:29]

```c
char s[8];
int i;

gets(s);  /* reads "123456789" from stdin */
```

[课件: 20-malloc-advanced.pptx p.36]

课件明确标注这是经典 buffer-overflow attacks 的基础：`gets` 没有在这里获得最大长度，而示例输入超过 `s[8]` 可容纳的范围。[课件: 20-malloc-advanced.pptx p.36]

### 8. 指针算术已经按元素尺寸缩放

老师强调，pointer 增加 1，不是机械地把地址增加 1 byte，而是增加所指对象的大小；`int *` 增加 1，在课堂假设下地址增加 4 bytes。[01:15:30-01:16:01]

错误代码是：[课件: 20-malloc-advanced.pptx p.37]

```c
int *search(int *p, int val) {
   
   while (*p && *p != val)
      p += sizeof(int);

   return p;
}
```

程序员想前进到下一个 `int`，却又显式加上 `sizeof(int)`。由于 `p` 已是 `int *`，课堂按 `sizeof(int)=4` 解释：`p += sizeof(int)` 前进 4 个 `int`，即 16 bytes，而不是预期的 4 bytes。[01:16:01-01:16:27]

### 9. `*size--` 修改的是指针，不是所指对象

老师用自己写过的 heap 数据结构删除代码说明优先级错误：[01:16:27-01:18:28]

```c
int *BinheapDelete(int **binheap, int *size) {
   int *packet;
   packet = binheap[0];
   binheap[0] = binheap[*size - 1];
   *size--;
   Heapify(binheap, *size, 0);
   return(packet);
}
```

[课件: 20-malloc-advanced.pptx p.38]

老师按意图逐行追踪：保存 heap 首元素；把最后一个元素移到首位；删除后应把调用者的 heap size 减 1；再用更新后的 size 重新 heapify。[01:16:42-01:17:44]

但 `--` 与 `size` 的结合优先于左侧 `*`，所以 `*size--` 按 `*(size--)` 解析：被递减的是 pointer `size`，随后代码会从错误位置解引用，而不是把 `size` 指向的整数减 1。老师给出的修复意图是显式写括号，使先解引用、再递减：`(*size)--`。[01:17:44-01:18:28] 这正是课件标题所说的“引用 pointer，而不是它指向的 object”。[课件: 20-malloc-advanced.pptx p.38]

### 10. 返回已经不存在的局部变量

老师提醒 local variables 会在函数返回时消失：[01:18:28-01:18:50]

```c
int *foo () {
   int val;

   return &val;
}
```

[课件: 20-malloc-advanced.pptx p.39]

返回后该地址不再代表仍存活的 `val`。它可能暂时看起来可用，直到另一函数复用相同 stack 空间；那里可能存放别的局部变量或 return address。[01:18:33-01:18:50]

### 11. Double free 会再次改写 allocator 元数据

课件代码先释放 `x`，随后分配并使用 `y`，最后又错误地 `free(x)`：[课件: 20-malloc-advanced.pptx p.40]

```c
x = malloc(N*sizeof(int));
        <manipulate x>
free(x);

y = malloc(M*sizeof(int));
        <manipulate y>
free(x);
```

老师把它称为非常严重的错误。此前的 allocator 结构已经说明 `free` 不是无操作：它会写 heap、coalesce、改链指针和块大小。对已释放块再次执行这些操作会破坏当前 heap 状态。[01:18:50-01:19:14]

### 12. 释放后仍引用原块

最后一个跨到分段边界前的错误是 use-after-free：[01:19:14-01:19:27]

```c
x = malloc(N*sizeof(int));
  <manipulate x>
free(x);
   ...
y = malloc(M*sizeof(int));
for (i=0; i<M; i++)
   y[i] = x[i]++;
```

[课件: 20-malloc-advanced.pptx p.41]

`x` 所指块已经归还 allocator，却仍在右侧通过 `x[i]++` 被读写；中间的 `malloc` 还可能让 `y` 使用被回收的空间。老师在本段只指出“忘记已经 free，随后又 reference”，下一段立即转入 memory leak。[01:19:14-01:19:27]

### 三条直接决定地址或尺寸的关系

指针算术按所指类型缩放：

$$
\operatorname{addr}(p+k)=\operatorname{addr}(p)+k\times\operatorname{sizeof}(*p).
$$

因此课堂例中 `int *p` 的 `p += sizeof(int)`，在 `sizeof(int)=4` 的讲解假设下移动 $4\times4=16$ bytes。[01:15:30-01:16:27]

二维数组顶层保存的是 pointers，所需字节数应随 pointer size 计算；错误代码却使用：

$$
N\times\operatorname{sizeof}(int)
$$

而老师指出目标是：

$$
N\times\operatorname{sizeof}(int *).
$$

[01:13:43-01:14:40]

优先级导致：

$$
*size--\equiv *(size--),
$$

而老师想表达的是：

$$
(*size)--.
$$

[01:17:35-01:18:28]

本段没有其他公式推导。

### 1. Memory leak：函数返回后块永久留在 heap

紧接上一段的 use-after-free，老师提出另一个大问题：failing to free blocks。[01:19:27-01:19:32] 课堂例子是在函数中申请一块内存，随后直接返回：

```c
foo() {
   int *x = malloc(N*sizeof(int));
   ...

}
```

[课件: 20-malloc-advanced.pptx p.42]

局部 pointer 消失后，该块成为 garbage，却没有被 `free`，所以会一直占在 heap 中；课件把这种错误称为 “Slow, long-term killer!”。[01:19:27-01:19:38] [课件: 20-malloc-advanced.pptx p.42]

```c
   int val;

};

foo() {
   struct list *head = malloc(sizeof(struct list));
   head->val = 0;
   head->next = NULL;
   <create and manipulate the rest of the list>
    ...

   return;
}
```

### 2. `gdb` 能指出 fault，却未必指出先前的错误 write

### 3. 先写出数据结构必须始终维持的 invariants

老师给出的更有效方法是：对任何复杂数据结构，先识别它在所有合法状态下都必须保持的 invariants；再写一个函数遍历该结构，逐项验证这些 invariants。[01:20:10-01:20:28]

allocator 的第一个课堂 invariant 是：

> heap 中绝不能存在两个 contiguous free blocks。

因此 consistency checker 应扫描 heap，确认没有一对物理相邻的空闲块。[01:20:28-01:20:44]

第二个 invariant 是：

> every free block should be in a free list somewhere。

老师给出的检查办法是先扫描 heap，统计 free blocks；再扫描 free list，统计链表中的 blocks；两边数量必须相同。[01:20:44-01:21:04]

## 概念、符号与推导

### Memory leak 的课堂判据

本段的 leak 因果链是：

$$
\texttt{malloc}\ \longrightarrow\ \text{失去最后一个可用 pointer}\ \longrightarrow\
\text{block 成为 garbage 但未被 free}\ \longrightarrow\ \text{heap 空间持续占用}.
$$

[01:19:27-01:19:38] [课件: 20-malloc-advanced.pptx p.42]

### Allocator consistency checks

老师给出的两个检查条件可写为：

$$
\nexists\ (b_i,b_{i+1})\quad
\text{s.t. }b_i\text{ 与 }b_{i+1}\text{ 物理相邻且二者均 free},
$$

[01:20:28-01:20:44]

以及计数检查：

$$
F_{\mathrm{heap}}=F_{\mathrm{free\ lists}}.
$$

其中前者来自扫描整个 heap，后者来自扫描 free list。[01:20:44-01:21:04] 老师在本段没有给出更复杂的 checker 公式或证明。

### Probe 二分的判定信号

checker 在某点静默表示此前尚未检测到 invariant violation；输出错误表示结构在该点已经非法。老师利用这个二值信号在“最后一次正常”和“第一次异常”之间反复缩小范围。[01:21:24-01:22:13]
