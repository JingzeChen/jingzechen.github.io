### 核心概念与依赖关系

- `P/V 原子语义` -> `mutex 互斥` 与 `counting semaphore 状态计数` -> `sbuf` 的等待/通知协议。
- `sbuf` -> `主线程投递 connfd / worker 取 connfd` -> `预线程化服务器摊销线程创建成本`。
- `读操作不修改对象` + `写操作必须独占` -> `读者—写者约束` -> `首读者 P(w) / 末读者 V(w)` -> `读者优先及写者饥饿风险`。
- `并发调用仍必须正确` -> `四类线程不安全来源` -> `加锁、状态参数化、lock-and-copy、替换不安全被调函数`。
- `不访问共享变量` -> `可重入` -> `无需同步`；反向不成立，因为加锁访问共享变量的函数可线程安全但不可重入。[01:00:37–01:02:19] [课件: 25-sync-advanced.pptx p.25]
- `意外共享地址` + `未规定事件顺序` -> `race`；`独立参数块` -> `取消该共享依赖`。
- `阻塞 P` + `相反锁获取顺序` -> `循环等待` -> `deadlock region`；`统一获取全序` -> `消除该区域`。

### 关键推导、例子与结论边界

- **`sbuf` 的两条精确序列：** 插入为 `P(slots) -> P(mutex) -> 写 rear -> V(mutex) -> V(items)`；移除为 `P(items) -> P(mutex) -> 读 front -> V(mutex) -> V(slots)`。等待/通知 semaphore 不替代保护 `front/rear/buf` 的 mutex。[00:09:31–00:12:16] [课件: 25-sync-advanced.pptx p.9] [课件: 25-sync-advanced.pptx p.10]
- **第一类读写者方案：** 入口为 `P(mutex); readcnt++; if (readcnt == 1) P(w); V(mutex)`；出口为 `P(mutex); readcnt--; if (readcnt == 0) V(w); V(mutex)`。它偏向读者，可能使写者饥饿；写者优先版本只作为思考题，没有在本讲给出实现。[00:16:32–00:25:37] [课件: 25-sync-advanced.pptx p.12] [课件: 25-sync-advanced.pptx p.13]
- **服务器职责分离：** master 只 `Accept` 和投递，worker 分离自身后反复取描述符、服务、关闭；`echo_cnt` 只是可替换的业务函数。[00:31:20–00:35:16] [课件: 25-sync-advanced.pptx p.15] [课件: 25-sync-advanced.pptx p.16]
- **`rand` 与 `rand_r`：** 算术递推不变，状态位置从共享 `next` 变为调用者的 `*nextp`；代价是调用者必须维护 seed。[00:47:19–00:51:57] [课件: 25-sync-advanced.pptx p.21] [课件: 25-sync-advanced.pptx p.22]
- **`ctime` 的 lock-and-copy：** mutex 必须覆盖原始 `ctime` 调用和 `strcpy(privatep, sharedp)` 两步，复制结束后才可解锁；复杂返回结构可能需要困难的 deep copy。[00:52:02–01:00:13] [课件: 25-sync-advanced.pptx p.23]
- **race 实验证据：** 无竞态时 0–99 各一次；共享 `&i` 会造成重复/缺失。单核通过抢占也会发生，多核结果更严重；精确柱数只能回看课件图。[01:03:39–01:09:27] [课件: 25-sync-advanced.pptx p.27]–[课件: 25-sync-advanced.pptx p.30]
- **死锁顺序：** 错误版本为 thread 0 获取 `s0 -> s1`、thread 1 获取 `s1 -> s0`；正确版本让二者都获取 `s0 -> s1`。老师明确说释放顺序无关，而不是要求获取与释放都同序。[01:13:54–01:20:13] [课件: 25-sync-advanced.pptx p.33]–[课件: 25-sync-advanced.pptx p.36]

# 第 1 段：信号量复习与有界生产者—消费者模型

## 本段在整讲中的作用

本段先把上一讲的信号量语义和互斥用法重新固定下来，再把信号量从“保护共享变量”推进到“记录资源状态并在线程间通知事件”。老师用生产者—消费者问题建立这一新用法，并逐步落到有界循环缓冲区 `sbuf` 的数据结构、初始化和插入操作的第一步。它既是后续读者—写者问题的概念准备，也是稍后预线程化并发服务器中“主线程生产连接描述符、工作线程消费描述符”的直接基础。[00:00:09–00:00:17] [00:02:35–00:03:18] [00:06:25–00:07:04] [课件: 25-sync-advanced.pptx p.1] [课件: 25-sync-advanced.pptx p.4] [课件: 25-sync-advanced.pptx p.6]

## 教学展开

1. **说明本讲目标并回顾信号量。** 老师先说明本讲继续讨论线程程序的同步问题，然后回顾：信号量 `s` 是一个非负的全局整数同步变量，只能通过 `P`、`V` 操作操纵。[00:00:09–00:00:31] [课件: 25-sync-advanced.pptx p.1] [课件: 25-sync-advanced.pptx p.2]
2. **按阻塞条件解释 `P(s)`。** 若 `s` 非零，`P` 将其减 1 并立即返回；若 `s` 为 0，调用线程挂起，直到某次 `V` 使 `s` 非零并重新启动该线程。线程恢复后，尚须由这个 `P` 把 `s` 减 1，才返回调用者。[00:00:31–00:01:09] [课件: 25-sync-advanced.pptx p.2]
3. **解释永不阻塞的 `V(s)`。** `V` 先把 `s` 加 1；若已有线程阻塞在等待 `s` 非零的 `P` 中，则只重新启动其中恰好一个。选择哪一个等待者的准则没有规定。P/V 的语义维持不变量 `s >= 0`。[00:01:10–00:01:44] [课件: 25-sync-advanced.pptx p.2]
4. **回顾互斥保护。** 对一个共享变量或一组相关共享变量关联唯一的 `mutex`，初值设为 1；访问共享状态前执行 `P(mutex)`，访问结束后执行 `V(mutex)`。两者之间是需要互斥执行的临界区。[00:01:56–00:02:31] [课件: 25-sync-advanced.pptx p.3]
5. **把信号量用途从“锁”扩展为“状态计数与通知”。** 老师对比两种用途：互斥量保护共享资源；计数信号量则记录资源状态，并用一次信号量操作通知其他线程某个条件已经成立。资源本身的并发更新仍需要 `mutex` 保护。[00:02:35–00:03:18] [课件: 25-sync-advanced.pptx p.4]

## 概念、符号与推导

- **信号量不变量：** `s >= 0`。`P` 在可用计数上消耗一个单位，`V` 增加一个单位；不能把阻塞中的 `P` 理解成先把 `s` 减成负数。[00:00:31–00:01:44] [课件: 25-sync-advanced.pptx p.2]
- **互斥模板：** `mutex = 1; P(mutex); /* 临界区 */ V(mutex);`。唯一的 `mutex` 对应一个共享变量或一组必须一起保持一致的共享变量。[00:01:56–00:02:31] [课件: 25-sync-advanced.pptx p.3]
- **资源状态：** `slots` 的值表示当前空槽数，初值为 `n`；`items` 的值表示当前项目数，初值为 0；`mutex` 的初值为 1。老师在本段没有进一步给出三者之间的代数不变量。[00:06:34–00:07:04] [00:09:04–00:09:23] [课件: 25-sync-advanced.pptx p.6] [课件: 25-sync-advanced.pptx p.8]
- **循环缓冲区索引约定：** 声明中写明 `buf[(front+1)%n]` 是首项，`buf[rear%n]` 是末项；因此实现会在访问前推进相应位置，再对 `n` 取模。[00:07:25–00:07:51] [课件: 25-sync-advanced.pptx p.7]
- **初始状态推导：** 新缓冲区没有项目，所以 `items = 0`；全部 `n` 个位置都空，所以 `slots = n`；尚无线程占有缓冲区，所以 `mutex = 1`。这些初值使消费者一开始会等待项目，而生产者可以开始插入。[00:08:31–00:09:23] [课件: 25-sync-advanced.pptx p.8]

# 第 2 段：`sbuf` 完整操作与读者—写者问题的两种偏好

> 时间范围：`00:09:59–00:19:58`

## 本段在整讲中的作用

本段先完成上一段尚未讲完的 `sbuf_insert`，再用对称方式推导 `sbuf_remove`，把“计数信号量负责等待/通知、互斥量负责保护结构更新”的协议落实为完整代码。随后老师从普通互斥过于保守这一问题出发，引入允许并发读、要求独占写的读者—写者问题，精确定义读者优先与写者优先两种经典变体及各自的饥饿风险，最后开始讲第一类（读者优先）方案。[00:09:59–00:14:00] [00:14:00–00:19:58] [课件: 25-sync-advanced.pptx p.9] [课件: 25-sync-advanced.pptx p.10] [课件: 25-sync-advanced.pptx p.11] [课件: 25-sync-advanced.pptx p.12] [课件: 25-sync-advanced.pptx p.13]

## 教学展开

1. **完成生产者的插入路径。** 在上一段的 `P(&sp->slots)` 成功后，线程已经占到一个空槽；接着执行 `P(&sp->mutex)` 锁住缓冲区，把 `rear` 预增后对 `n` 取模，并把 `item` 写入所得位置。随后先 `V(&sp->mutex)` 释放结构，再 `V(&sp->items)` 宣告多了一个可消费项目。[00:09:59–00:11:09] [课件: 25-sync-advanced.pptx p.9]
2. **强调最后一次 `V(items)` 的通知意义。** 老师把它类比为 signal：生产者并非只是在改一个计数，而是在通知可能阻塞的消费者“系统中发生了项目可用这一事件”。[00:10:55–00:11:09] [课件: 25-sync-advanced.pptx p.9]
3. **对称推导消费者的移除路径。** 消费者先 `P(&sp->items)` 等待并占用一个项目，再 `P(&sp->mutex)` 锁缓冲区；将 `front` 预增后对 `n` 取模，读出项目到线程局部变量 `item`。然后先解锁缓冲区，再 `V(&sp->slots)` 通知生产者新空槽已经出现，最后返回 `item`。[00:11:18–00:12:16] [课件: 25-sync-advanced.pptx p.10]
4. **讨论多生产者、多消费者同时操作。** 两个核心上的消费者即使“同时”对同一个 `items` 执行 `P`，内核也会把这两个 `P` 串行化并原子执行。哪一个先成功没有保证，但先执行者先减少计数；后执行者再根据更新后的 `items` 是 0 还是非零决定继续或阻塞。老师把它称为一种受控的竞争。[00:12:20–00:13:55]
5. **指出普通互斥在只读场景中过于保守。** 若多个线程只读共享对象且没有写者，读操作不会改变对象，没有必要让所有读者彼此互斥；因此可允许任意多个读者同时访问。只有写者要修改对象时，才必须获得对对象的独占访问。[00:14:00–00:15:30] [课件: 25-sync-advanced.pptx p.11]
6. **用真实系统说明读写区分。** 在线机票预订系统中，多个客户可以同时查询数据库，但一次预订会更新数据库，必须独占；在多线程缓存 Web 代理中，多个线程可以同时读取缓存，但加入新页面是写操作，必须互斥进行。[00:15:30–00:16:32] [课件: 25-sync-advanced.pptx p.11]
7. **定义第一类读者—写者问题：偏向读者。** 除非写者已经获准使用对象，否则读者不应等待。特别地，若写者只是在等待，而此时又到达一个读者，新读者仍优先于该写者。若读者持续到达，写者可能无限等待，即写者饥饿。[00:16:32–00:18:03] [课件: 25-sync-advanced.pptx p.12]
8. **定义第二类读者—写者问题：偏向写者。** 一旦写者准备写，就应尽快执行；在写者到达之后再到达的读者必须等待，即使该写者本身仍在等待。若多个写者持续到达，读者可能饥饿。老师说明还有处理饥饿问题的其他变体，但本讲不展开。[00:18:07–00:18:42] [课件: 25-sync-advanced.pptx p.12]
9. **只选择第一类方案展开。** 在简化模型中，一个线程要么是读者，要么是写者。写者路径很直接：对信号量 `w` 执行 `P`，独占完成写临界区，再执行 `V`；这保证至多一个写者处于写临界区。[00:18:42–00:19:34] [课件: 25-sync-advanced.pptx p.13]
10. **引出读者侧的两个共享控制量。** 全局变量 `readcnt` 用来跟踪读者群体；信号量 `mutex` 保护对 `readcnt` 的访问和更新，而 `w` 控制写者对被保护对象的访问。读者侧的具体进入/退出协议在下一段继续。[00:19:34–00:19:58] [课件: 25-sync-advanced.pptx p.13]

## 概念、符号与推导

- **插入顺序：** `P(slots) -> P(mutex) -> buf[(++rear)%n] = item -> V(mutex) -> V(items)`。先取得资源资格，再锁住结构；先完成结构更新并解锁，最后才公布新项目。[00:09:59–00:11:09] [课件: 25-sync-advanced.pptx p.9]
- **移除顺序：** `P(items) -> P(mutex) -> item = buf[(++front)%n] -> V(mutex) -> V(slots) -> return item`。它与插入在资源计数上对称，但等待的是 `items`，通知的是 `slots`。[00:11:18–00:12:16] [课件: 25-sync-advanced.pptx p.10]
- **原子 `P` 的结果：** 对同一信号量的并发 `P` 不会共同读取同一个旧值后都成功；内核确定某个串行次序，每个操作观察前一个操作留下的状态。老师未规定获胜线程的选择策略。[00:12:44–00:13:55]
- **读者—写者访问约束：** 同时读者数可以不受该协议限制；写者必须独占，即写者不能与其他写者或读者同时访问被保护对象。[00:14:29–00:15:30] [课件: 25-sync-advanced.pptx p.11]
- **第一类优先级：** “已获准的写者”能挡住读者；“仅等待的写者”不能阻止后来读者插队。因此持续的读者流可能使写者饥饿。[00:16:49–00:18:03] [课件: 25-sync-advanced.pptx p.12]
- **第二类优先级：** 写者一旦就绪，后来读者即等待；持续的写者流可能使读者饥饿。[00:18:07–00:18:39] [课件: 25-sync-advanced.pptx p.12]
- **第一类方案初始状态与写者路径：** `readcnt = 0`，`mutex = 1`，`w = 1`；写者循环执行 `P(w)`、写临界区、`V(w)`。[00:18:42–00:19:58] [课件: 25-sync-advanced.pptx p.13]

## 例子与课堂提示

- **双核上的两个消费者：** 老师故意设定两个线程在两个核心上同时调用 `P(items)`，用它说明应用代码看似并发，信号量操作本身仍由内核原子地串行化；该例服务于理解为何多个消费者不会凭同一个计数同时取得同一份资格。[00:12:26–00:13:55]

## 常见误解与辨析

- **误解：`V(items)` 可以在写入数组之前执行。** 这会先向消费者宣布项目可用；课堂代码明确先在互斥区完成写入并解锁，再通知消费者。[00:10:13–00:11:09] [课件: 25-sync-advanced.pptx p.9]

- **误解：读者—写者协议意味着读者和写者各自内部都可无限并发。** 只有读者之间可并发；写者必须对所有访问者独占。[00:14:29–00:15:30] [课件: 25-sync-advanced.pptx p.11]
- **误解：读者优先意味着任何时候读者都能越过写者。** 若写者已经获得对象许可，后来读者仍须等待；优先规则针对的是尚在等待的写者。[00:16:49–00:17:34] [课件: 25-sync-advanced.pptx p.12]

# 第 3 段：首读者/末读者协议与预线程化服务器架构

> 时间范围：`00:19:58–00:29:57`  
> 证据范围：课堂实录；承接 [课件: 25-sync-advanced.pptx p.13]，进入 [课件: 25-sync-advanced.pptx p.14]

## 本段在整讲中的作用

本段完成第一类读者—写者方案：老师逐行说明 `mutex` 只保护 `readcnt`，而读者群体通过“第一个进入者锁住 `w`、最后一个离开者释放 `w`”把写者挡在外面，从而同时满足多读者并发和写者独占。课堂问答进一步消除“一个 mutex 怎么允许多个读者”的误解。随后老师把前半讲的生产者—消费者模型用于服务器设计，提出由主线程接收连接、共享缓冲区传递连接描述符、固定 worker 池反复服务客户的预线程化并发服务器。[00:19:58–00:26:48] [00:26:55–00:29:57] [课件: 25-sync-advanced.pptx p.13] [课件: 25-sync-advanced.pptx p.14]

## 教学展开

1. **重申两个信号量的对象及初值。** `mutex` 保护对共享 `readcnt` 的读写，`w` 保护写者的临界区；二者初值都为 1，`readcnt` 初值为 0。[00:19:58–00:20:17] [课件: 25-sync-advanced.pptx p.13]
2. **读者进入时先串行更新计数。** 每次循环，读者先执行 `P(&mutex)`，进入针对 `readcnt` 的临界区，再执行 `readcnt++`。这一把锁只让读者们对计数的更新串行，不是把实际读取对象的整个过程串行化。[00:20:17–00:20:55] [课件: 25-sync-advanced.pptx p.13]
3. **首读者代表整个读者群体获取 `w`。** 若加 1 后 `readcnt == 1`，当前线程是第一个读者，于是执行 `P(&w)`。若已有写者持有 `w`，首读者在此等待；若没有写者，`w` 从 1 减至 0，从此阻挡后来写者。[00:20:55–00:21:53] [课件: 25-sync-advanced.pptx p.13]
4. **释放计数锁，让其他读者加入。** 首读者取得 `w` 后执行 `V(&mutex)`；后续读者只需短暂锁住 `readcnt`、增加计数，因为它们看到 `readcnt > 1`，不会再次执行 `P(w)`。因此多个读者可同时进入实际读取区域，而写者仍因 `w == 0` 被排除。[00:21:53–00:22:52] [课件: 25-sync-advanced.pptx p.13]
5. **读者退出时判断自己是否是末读者。** 读完后，线程再次 `P(&mutex)`，执行 `readcnt--`；若结果为 0，说明读者群体已经清空，由这个最后离开的读者执行 `V(&w)`，让等待写者有机会进入。最后执行 `V(&mutex)`。[00:22:53–00:23:37] [课件: 25-sync-advanced.pptx p.13]
6. **把写者优先版本留作思考。** 老师没有给出第二类方案代码，只请学生思考如何改写成偏向写者的版本；因此本讲实际推导和展示的实现仅是第一类读者优先方案。[00:23:43–00:23:56]
7. **回答“mutex 是否允许多个读者”。** 老师明确否定：`mutex` 本身不允许多人同时持有。之所以多个读者能并行，是因为它只包围 `readcnt` 的更新，实际读取区不在它保护之下；`w` 则由读者群体持有，用来排除写者。[00:24:00–00:25:37] [课件: 25-sync-advanced.pptx p.13]
8. **回答阻塞的代价。** 阻塞至少涉及进入内核、跨越系统调用边界的开销，并且线程会等待到某个线程执行 `V`，所以等待时间可能任意长。随后老师口头提到内核采用某种公平机制，使阻塞的 `P` 不会永远留在队列中。[00:25:37–00:26:48]
9. **从按请求创建线程转向预先创建 worker 池。** 旧模型每到一个连接请求就创建线程或进程，服务结束后再销毁；创建和销毁都有开销。新模型提前创建固定的一组 worker（线程时称 prethreaded，进程时称 preforked），让它们常驻并反复接活。[00:26:55–00:28:24] [课件: 25-sync-advanced.pptx p.14]
10. **主线程成为连接描述符的生产者。** 主线程循环调用 `accept` 等待客户；每次成功后得到代表该客户连接的 connected file descriptor，并把这个小整数插入共享缓冲区。线程共享同一个描述符表，因此描述符可以在线程间传递。[00:28:24–00:29:30] [课件: 25-sync-advanced.pptx p.14]
11. **worker 成为连接描述符的消费者。** 所有 worker 等待缓冲区出现项目；有描述符可用时，其中一个 worker 取走它，并以该描述符与对应客户交互。本段在“该描述符对应客户—服务器连接”处结束，服务完成后的复用在下一段继续。[00:29:30–00:29:57] [课件: 25-sync-advanced.pptx p.14]

## 概念、符号与推导

- **入口协议：** `P(mutex); readcnt++; if (readcnt == 1) P(w); V(mutex);`。条件只在 `0 -> 1` 的转变上成立，所以只有首读者替读者群体获取 `w`。[00:20:17–00:22:01] [课件: 25-sync-advanced.pptx p.13]
- **并发读取：** 入口协议结束后没有任何读者专属 mutex 包围“Reading happens”。只要已有至少一个读者使 `w` 保持为 0，后续读者可增加 `readcnt` 后直接读取，而写者的 `P(w)` 会阻塞。[00:22:01–00:22:52] [00:24:09–00:25:37] [课件: 25-sync-advanced.pptx p.13]
- **出口协议：** `P(mutex); readcnt--; if (readcnt == 0) V(w); V(mutex);`。条件只在 `1 -> 0` 的转变上成立，所以只有末读者替群体释放 `w`。[00:22:53–00:23:37] [课件: 25-sync-advanced.pptx p.13]
- **读者优先从何而来：** 只要读者群体尚未清空，`w` 一直为 0；新读者只更新 `readcnt`，不在 `w` 上排到等待写者之后。因此持续到达的新读者可以延长群体寿命，让写者继续等待。[00:21:53–00:22:52] [00:24:33–00:25:27] [课件: 25-sync-advanced.pptx p.13]
- **写者独占：** 写者执行 `P(w)` 后，其他写者也阻塞在 `w`；此时下一个首读者同样阻塞在 `P(w)`。所以写者在写临界区内不与任何读者或写者并发。[00:21:15–00:21:53] [00:24:49–00:25:27] [课件: 25-sync-advanced.pptx p.13]
- **服务器中的生产者—消费者映射：** 主线程是生产者，项目是 `accept` 返回的 connected file descriptor，共享缓冲区是有界 `sbuf`，worker 是消费者；并发性来自多个 worker 同时服务不同客户。[00:27:08–00:29:57] [课件: 25-sync-advanced.pptx p.14]

# 第 6 段：把状态移给调用者与 `ctime` 的 lock-and-copy

> 时间范围：`00:49:50–00:59:30`  
> 证据范围：课堂实录；承接 [课件: 25-sync-advanced.pptx p.21]，进入 [课件: 25-sync-advanced.pptx p.22]–[课件: 25-sync-advanced.pptx p.24]

## 本段在整讲中的作用

本段回答上一段留下的并发 `rand` 问题，并给出 class 2 的接口级修复：把持久状态作为参数交给调用者，使每个线程维护自己的种子。随后老师完整分析 class 3：`ctime` 返回同一静态字符串地址时，线程 A 的结果可被线程 B 覆盖；修复先考虑改写原函数，再选择不改 libc 的 lock-and-copy 包装器。本段由此展示两种通用策略：消除共享状态，或在锁内把共享结果复制到调用者私有存储。[00:49:50–00:51:57] [00:52:02–00:59:30] [课件: 25-sync-advanced.pptx p.22] [课件: 25-sync-advanced.pptx p.23]

## 教学展开

1. **说明共享 `next` 如何破坏每线程伪随机序列。** 多个线程交错调用原始 `rand` 时，一个线程本次得到的状态不只取决于它上次调用留下的 seed，还取决于其他线程在中间对同一个 `next` 做了多少次更新。因此同一线程多次调用时，可能不再看到原本可重现的序列。[00:49:50–00:50:44] [课件: 25-sync-advanced.pptx p.21]
2. **界定“错误”的含义。** 老师强调这不一定表现为程序崩溃；若程序依赖伪随机序列的可重复性质，跨线程干扰就使结果不正确。[00:50:44–00:51:02]
3. **把状态移入调用线程。** 新函数 `rand_r` 要求调用者维护 `next`，并把其地址传入。每个线程可在自己的栈上保存独立副本；函数通过 `nextp` 更新该线程的状态，不再访问一个全局 `next`。[00:51:02–00:51:37] [课件: 25-sync-advanced.pptx p.22]
4. **说明 `_r` 与接口代价。** 名称后缀 `_r` 表示 reentrant，这个性质稍后定义。代价是程序员不能只调用无参 `rand()`，而要负责保存和传递自己的 seed。[00:51:37–00:51:57] [课件: 25-sync-advanced.pptx p.22]
5. **转入 class 3：返回同一静态对象地址。** 这类函数每次返回相同地址，地址所指内容却会被每次调用重写。老师把它与先前把同一个 connected descriptor 变量地址传给 worker 的竞态联系起来。[00:52:02–00:52:34] [课件: 25-sync-advanced.pptx p.23]
6. **用线程 A/B 展开 `ctime` 竞态。** A 用时间结构调用 `ctime`，拿到指向日期时间 ASCII 字符串的指针；若 A 使用字符串之前，B 又调用 `ctime`，B 会覆盖同一静态位置。A 随后通过旧指针读到的是 B 的时间字符串。只有 A 在 B 覆盖前完成读取时，结果才碰巧正确。[00:52:34–00:54:21]
7. **评估修复 1：重写函数接口。** 可以让调用者分配结果空间并把地址传给 `ctime`，由函数直接写调用者私有缓冲区。但这要求同时修改调用者和被调函数；系统 libc 源码在本机上不可直接修改，而且改变既有接口会破坏其他调用程序，所以老师判定该路径不可行。[00:54:22–00:55:18] [课件: 25-sync-advanced.pptx p.23]
8. **选择修复 2：自建 `ctime_ts` 包装器。** 新函数保留 `timep` 参数，并增加调用者私有结果缓冲区 `privatep`。包装器内部另有局部指针 `sharedp`，用于暂存原始 `ctime` 返回的共享地址。[00:55:18–00:56:24] [课件: 25-sync-advanced.pptx p.23]
9. **执行 lock-and-copy。** 先 `P(&mutex)`，保证当前线程独占这一包装临界区；在锁内调用原始 `ctime(timep)` 得到 `sharedp`，并立即用 `strcpy(privatep, sharedp)` 把字符串复制到该线程的私有缓冲区。复制完成后才 `V(&mutex)`，最后返回 `privatep`。[00:56:24–00:57:19] [课件: 25-sync-advanced.pptx p.23]
10. **说明包装器对程序的改动。** 不需要修改 libc 的 `ctime`，但程序中原来的调用点要改成 `ctime_ts`，并准备一个私有字符串缓冲区。返回 `privatep` 保持了“调用时间转换函数会得到一个字符串指针”的使用习惯。[00:57:19–00:58:03] [课件: 25-sync-advanced.pptx p.23]
11. **回答为什么问题集中在指针返回。** 学生问题的字幕严重损坏；老师的回答主线是：这类函数更新某个数据结构并返回指向它的指针，所以调用者继续共享同一对象。若返回的是标量值，值通过 `EAX/RAX` 返回，调用者得到的是该值，不会因另一次调用改写原对象而通过同一指针看到变化。[00:58:03–00:59:30]

## 概念、符号与推导

- **原始共享状态的依赖：** 对线程 A 而言，若两次调用之间插入线程 B 的调用，则 A 的第二次输入状态已经被 B 改写；所以 A 的序列是全局调用交错的函数，而不再只是 A 自己调用历史的函数。[00:49:50–00:50:44]
- **`rand_r` 的状态递推：**

  ```c
  *nextp = *nextp * 1103515245 + 12345;
  return (unsigned int)(*nextp / 65536) % 32768;
  ```

  算式与原始版本相同，关键变化是状态位置由全局 `next` 变为调用者传入的 `*nextp`。[00:51:02–00:51:37] [课件: 25-sync-advanced.pptx p.22]
- **每线程状态隔离：** 若每个线程在自己的栈上保存一个 `next` 并传其地址，线程之间更新的是不同存储位置，因此一个线程的下一状态只延续自己的上一状态。[00:51:15–00:51:37] [课件: 25-sync-advanced.pptx p.22]
- **`ctime` 的竞态条件：** A 得到 `p = ctime(tA)` 后，正确性取决于 A 读取 `*p` 是否先于 B 的 `ctime(tB)` 重写同一静态对象；这正是执行先后决定正确性的竞态。[00:53:22–00:54:13]
- **lock-and-copy 的临界区边界：** 锁必须同时覆盖“调用不安全函数取得共享地址”和“把共享内容复制到私有缓冲区”。若在 `ctime` 返回后、`strcpy` 前解锁，另一线程仍可覆盖 `sharedp` 所指内容。[00:56:24–00:57:19] [课件: 25-sync-advanced.pptx p.23]
- **共享与私有指针：** `sharedp` 指向 `ctime` 的共享静态字符串；`privatep` 指向调用者准备的私有结果空间。返回的是后者。[00:55:44–00:57:19] [课件: 25-sync-advanced.pptx p.23]

## 例子与课堂提示

- **“不崩溃也可能错”：** 并发 `rand` 仍会返回整数，但失去调用者所依赖的可重复序列。该提示服务于线程安全定义中的“正确结果”，而非只观察运行是否终止。[00:50:31–00:51:02]
- **connected descriptor 地址类比：** class 3 与之前向 worker 传共享局部变量地址的错误同样危险：调用者持有一个地址，但生产该地址内容的一方可以在使用前再次改写它。[00:52:23–00:52:34]
- **A/B 时间字符串：** 老师明确分出两种调度：A 先读则正常，B 先覆盖则 A 读错；这个例子服务于识别看似普通库调用中的时序依赖。[00:53:22–00:54:21]
- **包装而非修改 libc：** `ctime_ts` 展示如何在无法改变第三方不安全函数时，通过一个受控的调用入口恢复线程安全。[00:55:03–00:57:48] [课件: 25-sync-advanced.pptx p.23]

## 常见误解与辨析

- **误解：并发 `rand` 的唯一风险是对 `next` 的某次算术更新丢失。** 老师本段强调的是更广的语义问题：每线程序列混入其他线程的调用历史，破坏可重复性。[00:49:50–00:51:02]

# 第 7 段：可重入函数、库函数安全性与 `&i` 竞态实验

> 时间范围：`00:59:30–01:09:27`  
> 证据范围：课堂实录；承接 [课件: 25-sync-advanced.pptx p.23]，进入 [课件: 25-sync-advanced.pptx p.24]–[课件: 25-sync-advanced.pptx p.31]

## 本段在整讲中的作用

本段先收束四类线程不安全函数：补充 lock-and-copy 面对复杂结构时的深拷贝代价，并给出 class 4 的传播规则。随后老师定义线程安全函数中的重要子集“可重入函数”，说明它为何无需同步，并列出标准库/Unix 接口中的安全性与 `_r` 替代项。后半段转向另一类并发风险 race：用主线程把同一个循环变量 `i` 的地址传给 100 个线程的实验，证明竞态既可在单核发生，在多核还会大量发生。[00:59:30–01:03:39] [01:03:39–01:09:27] [课件: 25-sync-advanced.pptx p.23] [课件: 25-sync-advanced.pptx p.24] [课件: 25-sync-advanced.pptx p.25] [课件: 25-sync-advanced.pptx p.26] [课件: 25-sync-advanced.pptx p.27] [课件: 25-sync-advanced.pptx p.28] [课件: 25-sync-advanced.pptx p.29] [课件: 25-sync-advanced.pptx p.30]

## 教学展开

1. **补充 lock-and-copy 的主要缺点。** 对字符串，复制只需 `strcpy`；若不安全函数返回的是嵌套结构，其中还有结构、指针和数组，私有化结果就需要 deep copy，可能非常复杂。[00:59:30–01:00:13] [课件: 25-sync-advanced.pptx p.23]
2. **class 4：调用不安全函数会传播不安全性。** 一个函数只要调用线程不安全函数，整体就线程不安全；修复方向是修改它，使其只调用线程安全函数。[01:00:17–01:00:33] [课件: 25-sync-advanced.pptx p.24]
3. **定义可重入函数。** 若函数在被多个线程调用时不访问任何共享变量，它就是 reentrant。老师用“所访问变量都声明为函数局部变量并位于该线程栈上”解释这种隔离：每个线程有独立栈，多个实例可独立运行。[01:00:37–01:01:40] [课件: 25-sync-advanced.pptx p.25]
4. **推出无需同步与性能优势。** 因为没有共享变量访问，就没有需要协调的共享状态，所以不需要 P/V 或其他同步。同步本身昂贵，完全避免同步使可重入函数更高效。[01:01:08–01:01:51] [课件: 25-sync-advanced.pptx p.25]
5. **说明集合关系。** 所有可重入函数都是线程安全函数，但线程安全函数不全可重入。访问共享变量的函数可以用 mutex 变得线程安全，却仍因访问共享变量而不是可重入函数。课件同时指出，class 2 函数要线程安全，需改成可重入形式，例子是 `rand_r`。[01:01:52–01:02:19] [课件: 25-sync-advanced.pptx p.25]
6. **给出库函数的课堂结论。** 老师说 K&R 书后所列的标准 C 库函数都是线程安全的，但不一定可重入；大多数 Unix 系统调用也是线程安全的，只有少量例外。所列例外不是完整清单。[01:02:19–01:02:51] [课件: 25-sync-advanced.pptx p.26]
7. **逐项说明 `_r` 替代。** class 3 的 `asctime`、`ctime`、`gethostbyaddr`、`gethostbyname`、`localtime` 分别有 `asctime_r`、`ctime_r`、`gethostbyaddr_r`、`gethostbyname_r`、`localtime_r`；class 2 的 `rand` 有 `rand_r`。这些可重入版本通常参数不同。`inet_ntoa` 被列为 class 3，但没有 `_r` 版本；老师说已有其他替代调用。[01:02:39–01:03:39] [课件: 25-sync-advanced.pptx p.26]
8. **定义 race 并指出常见根源。** race 是指：程序正确性取决于某线程先到达点 `x`，还是另一线程先到达点 `y`。老师称它是线程程序中的棘手问题，并说它通常涉及意外共享。[01:03:39–01:03:55] [课件: 25-sync-advanced.pptx p.27]
9. **重访把 `&i` 传给线程的错误。** 主线程在循环中以 `&i` 作为每个新线程的参数；所有线程共享主线程栈上的同一个循环变量。peer routine 一开始执行 `myid = *((int *)vargp)`，试图保存自己的 ID。[01:03:55–01:04:53] [课件: 25-sync-advanced.pptx p.27]
10. **定位两个竞争事件。** 竞争发生在主线程递增 `i` 与 peer 解引用 `&i` 之间。以 thread 0 为例：若 peer 在主线程把 `i` 从 0 增到 1 前解引用，得到 0；若主线程先递增，peer 得到 1，即错误 ID。[01:04:53–01:05:31] [课件: 25-sync-advanced.pptx p.28]
11. **设计 100 线程实验。** 主线程创建 100 个线程，每次仍传同一个 `&i`；peer 分离自己、解引用并调用 `save_value(i)` 保存结果。若无竞态，结果集合恰含 0 到 99 各一次，直方图每个柱高都为 1；若竞态发生，会出现重复值，并相应缺少某些值。[01:05:31–01:07:34] [课件: 25-sync-advanced.pptx p.29]
12. **读实验图。** 无竞态结果中，横轴是 0–99，纵轴是出现次数，每项恰一次。在单核笔记本上，老师数到约七次竞态表现：线程可在解引用前被抢占。多核服务器上竞态出现得很多，口述称大多数时候都拿不到正确 `myid`。[01:07:37–01:09:04] [课件: 25-sync-advanced.pptx p.30]

## 概念、符号与推导

- **深拷贝：** 若共享结果包含指向其他存储的指针，只复制最外层对象不足以隔离线程；老师只指出需要 deep copy 及其复杂性，没有在本段给出具体算法。[00:59:30–01:00:13]
- **可重入判据：** 多线程调用时不访问共享变量，因此每次调用只操作所属线程的局部状态；结论是无需同步。[01:00:37–01:01:40] [课件: 25-sync-advanced.pptx p.25]
- **集合关系：** `可重入函数 ⊂ 线程安全函数 ⊂ 全部函数`；线程不安全函数位于线程安全集合之外。一个“访问共享变量但正确加锁”的函数证明前一个包含关系通常不是等号。[01:01:52–01:02:19] [课件: 25-sync-advanced.pptx p.25]
- **class 2 的修复约束：** 课件明确写出，class 2 跨调用状态函数要变得线程安全，需要把它改成可重入形式，例如把 seed 作为参数状态的 `rand_r`。[课件: 25-sync-advanced.pptx p.25]
- **课堂列出的接口表：**

- **race 的形式：** 正确性依赖事件顺序 `x < y`；这里 `x = peer 解引用 &i`，`y = main 递增 i`。要求 thread 0 正确时必须有 `x < y`，但调度器没有提供该先后保证。[01:03:39–01:05:31] [课件: 25-sync-advanced.pptx p.27] [课件: 25-sync-advanced.pptx p.28]

## 常见误解与辨析

- **误解：线程安全与可重入是同义词。** 可重入要求完全不访问共享变量；线程安全函数可以访问共享变量，只要同步后始终正确。[01:01:52–01:02:19] [课件: 25-sync-advanced.pptx p.25]
- **误解：函数只用“局部名字”就一定可重入。** 判据是实际不访问共享变量；若局部指针指向共享对象，不能仅凭变量声明位置下结论。本段课堂定义以“无共享变量访问”为准。[01:00:45–01:01:31] [课件: 25-sync-advanced.pptx p.25]
- **误解：所有 `_r` 版本与原函数参数完全相同。** 老师明确说它们通常有不同参数，正如 `rand_r` 要接收状态地址。[01:02:51–01:03:08] [课件: 25-sync-advanced.pptx p.26]
- **误解：`tid[i]` 数组造成这个 race。** 被所有线程意外共享并在创建循环中变化的是 `i`；`tid[i]` 用于保存各线程句柄，不是本例错误 ID 的竞争对象。[01:03:55–01:05:31] [课件: 25-sync-advanced.pptx p.27]
- **误解：单核机器不会发生线程竞态。** 实验在单核笔记本上仍出现多次异常，因为线程可在关键解引用前被抢占。[01:08:15–01:08:51] [课件: 25-sync-advanced.pptx p.30]
- **误解：跑很多次没出错就证明没有 race。** 本例结果取决于调度，观察到无竞态的一次运行只代表那一次交错恰好满足先后关系。[01:05:31–01:09:11]

# 第 8 段：消除参数竞态与用进度图定位死锁

> 时间范围：`01:09:27–01:19:17`  
> 证据范围：课堂实录；承接 [课件: 25-sync-advanced.pptx p.31]，进入 [课件: 25-sync-advanced.pptx p.32]–[课件: 25-sync-advanced.pptx p.36]

## 本段在整讲中的作用

本段先完成上一段的 race 修复：不再让所有线程共享主线程的循环变量地址，而是为每个线程分配唯一存储并传递其地址。随后老师引入死锁，先以两个线程各占一个资源、再等待另一个资源说明循环等待，再用一段获取顺序相反的双信号量程序构造真实死锁。最后回到进度图，把 forbidden region、deadlock region、deadlock state、不可达状态和调度轨迹联系起来，并提出“所有线程按同一顺序获取锁”的避免规则。[01:09:27–01:09:51] [01:09:51–01:19:17] [课件: 25-sync-advanced.pptx p.31] [课件: 25-sync-advanced.pptx p.32] [课件: 25-sync-advanced.pptx p.33] [课件: 25-sync-advanced.pptx p.34] [课件: 25-sync-advanced.pptx p.35]

## 教学展开

1. **完成 `&i` 竞态的消除。** 主线程为每个新线程在堆上分配一个独立整数块，把该线程的 ID 写入，再把唯一块的地址传给线程。这样各线程不再竞争同一个循环变量地址。课件中的 peer 先把值复制到局部 `myid`，再 `Free(vargp)`，随后使用 `myid`。[01:09:27–01:09:51] [课件: 25-sync-advanced.pptx p.31]
2. **定义死锁。** 一个程序/进程若在等待某个永远不会成立的条件，就是 deadlocked。老师指出 `P` 是典型风险点，因为它会阻塞，等待相应信号量变成非零；若多个 `P` 相互阻止了产生这些条件的 `V`，等待就永远无法结束。[01:09:51–01:10:50] [课件: 25-sync-advanced.pptx p.32]
3. **构造两个资源的典型场景。** 两个线程都必须取得资源 A 和 B 才能继续。线程 1 先取得 A 后被抢占，线程 2 先取得 B；随后线程 1 等 B，而线程 2 等 A。每个线程都持有对方需要的锁，又都无法走到释放自己所持锁的步骤，因此二者永久等待。[01:10:50–01:12:46] [课件: 25-sync-advanced.pptx p.32]
4. **指出根因是获取次序不一致。** 老师称这里的细小错误看似无害：两个线程按不同顺序取得共同需要的资源。代码表面并不会很显眼地暴露问题，体现并发错误的隐蔽性。[01:12:46–01:13:18]
5. **建立双信号量示例。** `main` 把 `mutex[0]`、`mutex[1]` 都初始化为 1，创建 ID 分别为 0、1 的两个线程并等待它们结束。线程 ID 被直接转换成 `void *` 参数；老师说这种写法略奇怪，但在本例中可用。[01:13:18–01:13:54] [课件: 25-sync-advanced.pptx p.33]
6. **展开相反的获取序列。** 每个 `count` 线程循环执行 `P(&mutex[id]); P(&mutex[1-id]); cnt++; V(&mutex[id]); V(&mutex[1-id]);`。因此 thread 0 的序列是 `P(s0) -> P(s1) -> cnt++ -> V(s0) -> V(s1)`；thread 1 是 `P(s1) -> P(s0) -> cnt++ -> V(s1) -> V(s0)`。[01:13:54–01:15:06] [课件: 25-sync-advanced.pptx p.33]
7. **用进度图画出 `s1` 的 forbidden region。** 在每条线程轴上标出该线程从 `P(s1)` 成功到 `V(s1)` 之间持有 `s1` 的区间；两个区间的笛卡尔交集表示两线程同时持有同一个二元信号量的状态，这些状态因互斥不可能出现，形成 `s1` 的 forbidden region。[01:15:06–01:15:56] [课件: 25-sync-advanced.pptx p.34]
8. **同样画出 `s0` 的 forbidden region。** 分别找出 thread 0 和 thread 1 持有 `s0` 的区间，取其交集，得到另一个禁止区域。两块禁止区域的相对位置由两个线程相反的获取顺序造成。[01:15:56–01:16:20] [课件: 25-sync-advanced.pptx p.34]
9. **识别 deadlock region 和 deadlock state。** 若轨迹进入两块禁止区域之间的 deadlock region，时间不能倒退，轨迹只能沿线程继续执行的方向前进；无论怎样调度，最终都会到达被两块禁止区域夹住的 deadlock state。此时 thread 0 持有 `s0`、等待 `s1`，thread 1 持有 `s1`、等待 `s0`，两个信号量都不会被释放。[01:16:20–01:17:05] [课件: 25-sync-advanced.pptx p.34]
10. **区分不可达状态。** 老师指出两块 forbidden region 尾端后方还有一片状态，因为任何合法单调轨迹都无法到达，所以是 unreachable states；它与“进入后会走向死锁”的 deadlock region 不是同一个概念。[01:17:05–01:17:28] [课件: 25-sync-advanced.pptx p.34]
11. **说明死锁的非确定性。** 某些调度轨迹幸运地绕过 deadlock region，程序正常完成；另一些轨迹进入该区后死锁。程序可能运行一百万次都绕过，第 1,000,001 次才因调度进入，因此测试成功不能证明没有死锁。[01:17:34–01:18:51] [课件: 25-sync-advanced.pptx p.34]
12. **提出统一获取次序。** 避免本例死锁的方法是：所有需要多个共享资源的线程都按同一顺序获取它们。课件给出的改写让两个线程都执行 `P(&mutex[0]); P(&mutex[1]);`，而释放代码仍可按线程 ID 所决定的次序执行。本段在老师准备具体说明“先 0 后 1”的地方结束。[01:18:55–01:19:17] [课件: 25-sync-advanced.pptx p.35]

## 概念、符号与推导

- **race 修复的不共享原则：** 原程序的实参地址恒为 `&i`；修复后第 `i` 个线程得到自己的 `ptr_i`，并且在读取后释放 `ptr_i`。不同线程不再通过参数指针访问同一存储块。[01:09:27–01:09:51] [课件: 25-sync-advanced.pptx p.31]
- **死锁条件链：** thread 0 已完成 `P(s0)`，只有完成 `P(s1)` 后才能走到 `V(s0)`；thread 1 已完成 `P(s1)`，只有完成 `P(s0)` 后才能走到 `V(s1)`。但 `s1` 由 thread 1 持有且不会先释放，`s0` 由 thread 0 持有且不会先释放，于是双方等待条件都永远不成立。[01:11:14–01:12:46] [01:14:20–01:15:06] [课件: 25-sync-advanced.pptx p.33]
- **原程序的精确获取/释放顺序：**

  | 线程 | 获取 | 临界操作 | 释放 |
  | --- | --- | --- | --- |
  | thread 0 | `P(s0) -> P(s1)` | `cnt++` | `V(s0) -> V(s1)` |
  | thread 1 | `P(s1) -> P(s0)` | `cnt++` | `V(s1) -> V(s0)` |

  [01:13:54–01:15:06] [课件: 25-sync-advanced.pptx p.33]
- **进度图状态：** 一个点表示两个线程各自执行到某个位置的联合状态；合法轨迹不能后退，也不能进入任一 semaphore 的 forbidden region。[01:15:06–01:16:39] [课件: 25-sync-advanced.pptx p.34]
- **deadlock region 的推导：** 相反的获取顺序把两块禁止区域排成一个可进入却无出口的通道；轨迹一旦进入，只能走向两线程都卡在第二次 `P` 的 deadlock state。[01:16:20–01:17:05] [课件: 25-sync-advanced.pptx p.34]
- **避免规则：** 对所有线程规定同一个全序，并按该顺序获取所需锁。本例具体重写为所有线程都先 `P(s0)`、再 `P(s1)`；其如何消除 deadlock region 由下一段口述完成。[01:18:55–01:19:17] [课件: 25-sync-advanced.pptx p.35]

## 例子与课堂提示

- **A/B 两资源类比：** 它把抽象的两个 semaphore 解释为两个任务都必须拥有的资源，服务于看清“持有一个、等待另一个”的循环。[01:10:50–01:12:46] [课件: 25-sync-advanced.pptx p.32]
- **故意简化的 `cnt++`：** 老师称示例“totally bogus”，表示业务操作只是为了把两个锁包围的临界区可视化；重点是锁顺序，不是计数任务本身。[01:14:34–01:14:48]
- **“一百万次正常”提示：** 非确定死锁可能被绝大多数测试调度绕过，因此复现概率低不是正确性证据。[01:17:34–01:18:51]
- **进度图的价值：** 代码中的相反次序不易一眼识别；图上两块 forbidden region 与被夹住的 deadlock state 则把风险直接显现出来。[01:13:09–01:13:18] [01:15:06–01:17:05]

## 常见误解与辨析

- **误解：给 `cnt++` 加了两个 mutex，所以程序一定比只用一个锁更安全。** 多锁引入获取顺序问题；保护了临界区并不自动排除死锁。[01:13:54–01:15:06] [课件: 25-sync-advanced.pptx p.33]
- **误解：双方都只是在等一个普通的 `P`，总会有一个先醒来。** 能唤醒它们的 `V` 位于各自第二次 `P` 之后；双方都无法到达对应 `V`，等待条件永远不会成立。[01:10:16–01:12:46]
- **误解：deadlock region 与 forbidden region 相同。** forbidden region 表示互斥语义下不可能合法进入的状态；deadlock region 可以进入，但进入后的轨迹最终被困住。[01:15:06–01:17:28] [课件: 25-sync-advanced.pptx p.34]
- **误解：不可达区域就是已经死锁的区域。** 不可达状态根本没有合法轨迹能到达；deadlock state 则可由不幸的合法调度到达。[01:16:20–01:17:28]
- **误解：只要压力测试一直通过，就能排除死锁。** 是否进入 deadlock region 取决于调度；老师明确给出“第 1,000,001 次才失败”的情形。[01:17:34–01:18:51]
