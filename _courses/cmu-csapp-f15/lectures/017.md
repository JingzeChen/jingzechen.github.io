## 前置知识

1. **存储层次与 cache**：block、hit/miss、miss penalty、direct-mapped/set-associative/fully associative、tag/index/offset、write-through/write-back。
2. **局部性**：时间局部性与空间局部性；本讲用它们解释 working set、TLB 命中和 VM 的可行性。
3. **异常控制流**：硬件异常如何把控制交给内核 handler；page fault 是可恢复异常，handler 返回时重启 faulting instruction。
4. **进程地址空间**：代码、数据、堆、共享映射、用户栈、内核区域的基本布局，以及进程具有独立上下文这一事实。
5. **链接与加载**：ELF、`.text`、`.data`、全局引用 relocation、`execve` 的基本角色；本讲关注 VM 如何简化它们。
6. **二进制位运算**：$2^p$ 个位置需要 $p$ 位；低位作为块/页内 offset，高位作为 tag 或 page number；数组地址为 `base + index × element size`。
7. **内存保护与 Attack Lab 背景**：用户态/内核态、读写执行权限、代码注入与 return-oriented programming 的课堂关联。

## 概念依赖

```text
资源虚拟化 / interposition
  ↓
CPU 产生 VA → MMU → PA → DRAM
  ↓
虚拟/物理地址空间 + 页 P=2^p
  ↓
DRAM 缓存 VP：cached / uncached / unallocated
  ↓
每进程页表与 PTE
  ├─ valid/PPN/磁盘后备 → hit / page fault / demand paging
  ├─ 权限位 → READ / WRITE / EXEC / SUP 检查
  └─ 独立映射 → 任意放置 / 迁移 / 共享 / 固定 VA 布局
  ↓
VA=[VPN|VPO]，PA=[PPN|PPO]，PPO=VPO
  ↓
page-table lookup 的额外访问
  ↓
TLB=[TLBT|TLBI] 缓存 PTE
  ↓
单级页表过大
  ↓
VPN=[VPN1|...|VPNk] 的多级 page walk
```

依赖关系中有两次使用 locality：第一次让活跃 **data pages** 留在 DRAM，第二次让活跃 **translations/PTEs** 留在 TLB。缺少前者会 thrash，缺少后者则频繁 page walk。[00:22:24–00:23:46] [00:47:45–00:48:49]

## 关键推导

### 1. 地址空间与页数

$$
N=2^n,\qquad M=2^m,\qquad P=2^p\ \text{bytes}
$$

$$
\#VP=\frac{N}{P}=2^{n-p},\qquad
\#PP=\frac{M}{P}=2^{m-p}
$$

[课件: 17-vm-concepts.pptx p.5] [课件: 17-vm-concepts.pptx p.8]

### 2. 工作集与 thrashing 边界

对单进程：

$$
|WS_i|<C
\Longrightarrow
\text{compulsory misses 后可稳定获得良好性能}
$$

对多进程：

$$
\sum_i|WS_i|>C
\Longrightarrow
\text{thrashing：页面持续换入换出}
$$

其中 $C$ 为主存可容纳的页面容量。[课件: 17-vm-concepts.pptx p.18]

### 3. 地址翻译函数

$$
MAP:V\rightarrow P\cup\{\varnothing\}
$$

$$
MAP(a)=
\begin{cases}
a', & a\text{ 的数据当前位于物理地址 }a'\\
\varnothing, & a\text{ 的数据当前不在物理内存}
\end{cases}
$$

[课件: 17-vm-concepts.pptx p.26]

### 4. 单级页表翻译

$$
VA=[VPN\mid VPO],\qquad PA=[PPN\mid PPO]
$$

$$
PTEA=PTBR+VPN\times sizeof(PTE)
$$

$$
PPN=PTE[VPN].PPN,\qquad PPO=VPO
$$

等价整数形式：

$$
VPN=\left\lfloor\frac{VA}{2^p}\right\rfloor,\qquad
VPO=VA\bmod2^p,\qquad
PA=PPN\cdot2^p+VPO
$$

[课件: 17-vm-concepts.pptx p.28]

### 5. TLB 位切分

若 TLB 有 $T=2^t$ 个 set：

$$
VA=[TLBT\mid TLBI\mid VPO]
$$

$$
VPN=[TLBT\mid TLBI],\qquad |TLBI|=t
$$

TLBI 选 set，TLBT 在该 set 内确认 VPN；VPO 不参与翻译缓存查询。[课件: 17-vm-concepts.pptx p.33]

### 6. 512 GiB 单级页表

48 位 VA、4 KB $=2^{12}$ B 页、8 B $=2^3$ B PTE：

$$
\#PTE=2^{48-12}=2^{36}
$$

$$
\text{size}=2^{36}\times2^3=2^{39}\ \text{bytes}=512\ \text{GiB}
$$

[课件: 17-vm-concepts.pptx p.36]

### 7. $k$ 级页表

$$
VA=[VPN_1\mid VPN_2\mid\cdots\mid VPN_k\mid VPO]
$$

设 $B_1=PTBR$：

$$
PTEA_i=B_i+VPN_i\times sizeof(PTE)
$$

对 $i<k$：

$$
B_{i+1}=PTE_i.\text{next-table-base}
$$

末级：

$$
PPN=PTE_k.PPN,\qquad PA=[PPN\mid VPO]
$$

[课件: 17-vm-concepts.pptx p.38]

## 关键边界

1. **地址空间不是数据集合**：它是地址的集合；某页是否分配、在磁盘还是在 DRAM 是映射状态。[00:05:27–00:05:40]
2. **通常 $N>M$，不是定义要求**：老师明确说物理空间理论上也可大于虚拟空间。[00:36:09–00:36:34]
3. **valid=0 不等于一种唯一状态**：它可能表示合法但不驻留、文件/磁盘后备、未分配或非法；本讲没有给出区分所有状态的真实 PTE 位布局。
4. **TLB miss 不等于 page fault**：前者只是翻译缓存未命中；从内存页表取回的 PTE 仍可能 valid=1。[课件: 17-vm-concepts.pptx p.35]
5. **page hit 不等于普通 cache hit**：页已在 DRAM 后，PTE 和目标数据各自在普通 cache 层次仍可能 hit/miss。[课件: 17-vm-concepts.pptx p.31]
6. **多级页表不是逐项压缩**：顶层表完整存在，已创建下级表仍是定长数组；只对整片未使用区域省掉整张下级表。[00:59:37–01:02:30]
7. **segmentation 是历史旁支**：老师没有给出可可靠复原的精确公式，并明确不在本讲深入；不能用它替代分页主线。[01:06:22–01:09:39]
8. **真实 Intel/Linux 实现不在本讲**：老师将其留到下一讲；不得补入真实页表位布局或 Linux 内核 handler 细节。[01:10:54–01:11:01.71]
9. **课件 p.39 未被逐条口述**：其 programmer/system 双视角是屏幕总结，不应标成老师同步讲解。[课件: 17-vm-concepts.pptx p.39]

## 全讲复习

### 一句话主线

虚拟内存通过 MMU 在每次地址访问上插入映射，把每进程私有线性 VA 转成可任意放置和共享的 PA；页表同时承载驻留与权限信息，局部性让 DRAM page cache 和 TLB translation cache 都保持高命中，多级页表则让稀疏 VA 空间的映射元数据可承受。

### 核心术语对照

| 术语 | 本讲含义 | 不能混淆为 |
|---|---|---|
| VA / PA | CPU/MMU 前的虚拟地址 / DRAM-cache 前的物理地址 | 同一个数值或同一地址空间 |
| VP / PP | 虚拟页 / 物理页 | 编号固定相等的页 |
| PTE | 某 VP 的映射、驻留和权限信息 | 页面数据本身 |
| page hit | 目标 VP 已在 DRAM | 目标数据一定在 L1 cache |
| page fault | 目标 VP 不在 DRAM而触发异常 | TLB miss |
| working set | 某时刻活跃虚拟页集合 | 程序历史上访问过的所有页 |
| TLB | MMU 内缓存 PTE/translation 的小型硬件 cache | 缓存程序数据的普通 L1 |
| PTBR / CR3 | 当前进程页表的物理基址 | 某个最终 PPN |
| non-leaf PTE | 下一层页表的 base | 最终数据页 PPN |
| VPN2 | level-2 table 内的 index | level-2 table pointer |

### 三条性能因果链

1. **磁盘 miss penalty 巨大** → 大页、全相联、复杂替换、write-back。[课件: 17-vm-concepts.pptx p.9]
2. **程序有 locality** → working set 可驻留 DRAM；若总工作集超出主存则 thrashing。[课件: 17-vm-concepts.pptx p.18]
3. **翻译也有 locality** → TLB 缓存近期 PTE；hit 消除一次 PTE memory access。[课件: 17-vm-concepts.pptx p.32]–[课件: 17-vm-concepts.pptx p.35]

### 三条正确控制流

**Page hit（无 TLB 简化路径）**：

```text
CPU VA → MMU → PTEA → cache/memory 返回 PTE
       → MMU 拼 PA → cache/memory 返回 data → CPU
```

**Page fault**：

```text
CPU VA → MMU 读 PTE → valid=0 → exception
       → kernel 选 victim → dirty 时写回 → page in → 更新 PTE
       → 返回并重启 faulting instruction → page hit
```

**TLB miss 但 page hit**：

```text
MMU 查 TLB miss → 从内存页表取 valid PTE → 填 TLB
                → 拼 PA → 访问数据
```

# 第 1 段：从物理寻址到虚拟内存的三项动机

- **时间范围**：00:00:00–00:09:54.68
- **转录覆盖**：开场、物理寻址、虚拟化与 MMU、地址空间、虚拟内存三项动机，至页面概念的首次引入
- **课件范围**：[课件: 17-vm-concepts.pptx p.1]–[课件: 17-vm-concepts.pptx p.8]

## 本段在整讲中的作用

本段先推翻此前默认的“CPU 地址就是 DRAM 字节下标”模型，再建立本讲的总抽象：现代系统让 CPU 产生虚拟地址，由 MMU 截获每次内存访问并把它翻译为物理地址。老师不是直接罗列页表机制，而是先用磁盘控制器的逻辑块视图解释“虚拟化 = 在资源访问路径上插入一层映射”，为后续所有页表查询、权限检查与缺页处理提供共同起点。[00:00:19–00:05:08] [课件: 17-vm-concepts.pptx p.3] [课件: 17-vm-concepts.pptx p.4]

随后老师定义虚拟与物理地址空间，并用“缓存、内存管理、隔离保护”三项动机回答为什么值得承担这层间接访问。段末进入第一条主线：把 DRAM 看成磁盘上虚拟地址空间的缓存，块在虚拟内存中称为页。[00:05:20–00:09:54] [课件: 17-vm-concepts.pptx p.5]–[课件: 17-vm-concepts.pptx p.8]

## 教学展开

### 1. 从课程此前的物理内存模型起步 [00:00:00–00:01:29]

1. 老师宣布本讲主题是计算机科学中的重要概念 virtual memory（虚拟内存）。[00:00:06]
2. 此前可以把主存想成连续的物理字节数组；地址就是某个字节相对数组起点的偏移。[00:00:19–00:00:37]
3. 在物理寻址系统中，CPU 执行 `mov` 一类指令，产生的有效地址就是物理地址。课件例子中 CPU 产生地址 4，内存按该下标取回数据字并送回 CPU。[00:00:37–00:01:10] [课件: 17-vm-concepts.pptx p.3]
4. 这种直接模型用于汽车、电梯、数码相框等设备中的简单微控制器，但不是手机、桌面机和服务器等现代通用系统的常规模型。[00:01:15–00:01:29] [课件: 17-vm-concepts.pptx p.3] [课件: 17-vm-concepts.pptx p.4]

### 2. 先定义虚拟化，再把它应用到内存 [00:01:29–00:04:20]

老师把虚拟化解释为两步：[00:01:35–00:02:40]

1. 向资源使用者呈现与物理资源不同的抽象视图。
2. 在使用者访问资源时进行拦截（interpose/intercept）；一旦掌握访问路径，中间层就能重新解释或转换请求。

他先回忆对 `malloc` 做 wrapper/interposition 的例子，再用磁盘说明这种结构。物理磁盘有柱面、磁道、扇区、盘面等几何属性，但控制器不要求内核按这些物理坐标发请求，而是呈现连续逻辑块序列。控制器截获内核给出的逻辑块号，并转换成真正的物理位置。[00:02:19–00:03:35]

内存也是关键系统资源，因此采用相同思想。差别只是拦截者变成硬件 **MMU（Memory Management Unit，内存管理单元）**：它位于 CPU 发出地址和主存接收物理地址之间。[00:03:44–00:04:20] [课件: 17-vm-concepts.pptx p.4]

### 3. 用 `VA 4100 → PA 4` 展示地址翻译 [00:04:20–00:05:08]

1. CPU 执行 `mov` 等指令并产生有效地址；在虚拟寻址系统中，这个有效地址是虚拟地址（VA）。[00:04:20–00:04:32]
2. CPU 把 VA 送给 MMU。
3. MMU 执行 address translation（地址翻译）。课件示意把 VA 4100 转成 PA 4。[00:04:32–00:04:56] [课件: 17-vm-concepts.pptx p.4]
4. 主存只看到翻译后的 PA，并返回该物理位置的数据字。[00:04:56–00:05:08]

这里建立了本讲最重要的边界：程序和 CPU 指令使用 VA；DRAM 最终按 PA 访问；MMU 是两者之间的硬件中介。翻译细节此时尚未展开，老师明确留到讲末。[00:04:39–00:04:43] [00:08:39–00:08:59]

### 4. 定义三种地址空间 [00:05:08–00:06:31]

老师先强调：**地址空间是地址的集合，不是这些地址指向的数据字节集合。**[00:05:20–00:05:40]

1. **线性地址空间**：连续非负整数构成的有序集合，例如 $\{0,1,2,3,\ldots\}$。[00:05:40–00:05:55] [课件: 17-vm-concepts.pptx p.5]
2. **虚拟地址空间**：包含 $N=2^n$ 个虚拟地址，范围为 $\{0,1,\ldots,N-1\}$。[00:05:55–00:06:01] [课件: 17-vm-concepts.pptx p.5]
3. **物理地址空间**：包含 $M=2^m$ 个物理地址，范围为 $\{0,1,\ldots,M-1\}$。[00:06:01–00:06:10] [课件: 17-vm-concepts.pptx p.5]

通常 $N$ 大于 $M$。物理地址空间受系统实际 DRAM 容量约束；同一系统上的各进程则使用相同规模、相似布局的虚拟地址空间。[00:06:10–00:06:31]

### 5. 用三项收益回答“为什么要多一层 MMU” [00:06:31–00:08:39]

#### 5.1 高效使用主存：DRAM 作为磁盘数据的缓存 [00:06:44–00:07:31]

虚拟内存只把虚拟地址空间中当前需要的部分放进物理内存，因此 DRAM 可以被视为磁盘数据的缓存。和此前缓存、局部性的思路一样，不必让全部虚拟空间同时占用稀缺 DRAM。[课件: 17-vm-concepts.pptx p.6]

#### 5.2 简化内存管理：给每个进程统一视图 [00:07:31–00:08:14]

每个进程都看到相似的线性空间：代码和数据从固定位置开始，用户栈位于用户可见空间顶部；实际承载这些地址的物理页却可散布在主存各处。统一 VA 视图隐藏了物理放置的复杂性。[课件: 17-vm-concepts.pptx p.6]

#### 5.3 隔离和保护：建立私有地址空间 [00:08:14–00:08:39]

每个进程得到彼此分离、受保护的私有地址空间，因此一个进程不能任意破坏另一个进程的内存，用户程序也不能直接访问特权内核代码和数据。[课件: 17-vm-concepts.pptx p.6]

老师据此给出全讲路线：依次深入缓存、内存管理、保护，最后再落实地址翻译细节。[00:08:39–00:08:59] [课件: 17-vm-concepts.pptx p.2] [课件: 17-vm-concepts.pptx p.7]

### 6. 开始把 VM 具体化为页面缓存 [00:09:05–00:09:54.68]

1. 概念上，虚拟内存是一段存放在磁盘上的连续字节数组，共有 $N$ 个字节。[00:09:05–00:09:20] [课件: 17-vm-concepts.pptx p.8]
2. 这段磁盘内容的部分副本缓存在 DRAM 中，所以物理内存扮演 DRAM cache。[00:09:20–00:09:35]
3. 和任何缓存一样，数据按块搬运；虚拟内存系统把这种块称为 **page（页）**，页大小写作 $P=2^p$ 字节。[00:09:35–00:09:54.68] [课件: 17-vm-concepts.pptx p.8]
4. 老师在本段末只指出页比此前讨论的 SRAM cache block 大得多；具体 4 KB 对 64 B 的比较从下一段开始。[00:09:47–00:09:54.68]

## 概念、符号与推导

### 1. 两级视图与翻译关系

```text
指令产生有效地址
        ↓
虚拟地址 VA
        ↓  MMU 截获并翻译
物理地址 PA
        ↓
DRAM 返回数据
```

[00:04:20–00:05:08] [课件: 17-vm-concepts.pptx p.4]

老师此处只建立关系，没有给出页表索引算法；不能提前把后半讲的 VPN、PTE 或 TLB 步骤写成本段已经推导的内容。

### 2. 地址空间参数

$$
V=\{0,1,\ldots,N-1\},\qquad N=2^n
$$

$$
P_{\text{addr}}=\{0,1,\ldots,M-1\},\qquad M=2^m
$$

这里用 $P_{\text{addr}}$ 仅在笔记中区分“物理地址集合”和稍后表示页大小的 $P$；课件本页直接称其为 physical address space，并未引入 $P_{\text{addr}}$ 这个课堂符号。[课件: 17-vm-concepts.pptx p.5]

由定义可知，$n$ 位 VA 可编码 $2^n$ 个虚拟字节地址，$m$ 位 PA 可编码 $2^m$ 个物理字节地址。老师给出的经验关系是通常 $N>M$，但本段没有宣称这是数学必然。[00:06:10–00:06:19]

### 3. 页大小

$$
P=2^p\ \text{bytes}
$$

因此磁盘上的虚拟字节数组按等大 virtual pages（VPs）划分，DRAM 按等大的 physical pages（PPs）承载其中一部分。[课件: 17-vm-concepts.pptx p.8] 本段只定义页；虚拟页数和物理页数的具体指数形式留待后续页表讨论。

### 4. 三项动机之间的共同机制

三项收益都依赖同一个“interposition point”：MMU 已经截获每次内存访问，因此它既能改变物理放置、只缓存活跃页，也能在翻译时检查访问者和权限。[00:01:46–00:02:40] [00:06:31–00:08:39]

# 第 2 段：DRAM 页缓存、页表与首次缺页

- **时间范围**：00:09:54.68–00:19:54.28
- **转录覆盖**：页大小比较、DRAM cache 组织、页表与 PTE、page hit、page fault，至选中 VP 4 为牺牲页并开始更新映射
- **课件范围**：[课件: 17-vm-concepts.pptx p.8]–[课件: 17-vm-concepts.pptx p.15]

## 本段在整讲中的作用

上一段刚把虚拟内存描述成“磁盘字节数组在 DRAM 中的缓存”。本段把这个类比落实为可运行机制：为什么 DRAM cache 必须采用大页、全相联、复杂软件替换和写回策略；内核又如何用每进程页表记录 VP 在 DRAM 或磁盘中的位置。[00:09:55–00:17:27] [课件: 17-vm-concepts.pptx p.8]–[课件: 17-vm-concepts.pptx p.10]

在数据结构建立后，老师依次演示 page hit 与 page fault。段末停在缺页处理的中间状态：VP 3 未命中，硬件触发异常，内核选择 VP 4 作为牺牲页并把 VP 3 调入；脏页写回、PTE 完整更新和故障指令重启由下一段接续。[00:17:27–00:19:54.28] [课件: 17-vm-concepts.pptx p.11]–[课件: 17-vm-concepts.pptx p.15]

## 教学展开

### 1. 明确虚拟页、物理页与三种虚拟页状态 [00:09:54.68–00:11:21]

1. 虚拟内存页通常为 4 KB，而此前研究的 SRAM cache block 典型为 64 B；页是更大的缓存块。[00:09:55–00:10:03] [课件: 17-vm-concepts.pptx p.8]
2. 概念模型中，磁盘保存按编号排列的虚拟页 VP 0、VP 1、……；任一时刻只有其中一部分缓存在 DRAM 的物理页中。[00:10:03–00:10:34]
3. VP 编号与承载它的 PP 编号没有固定数值关系。映射函数可以把某个 VP 放到任意 PP。[00:10:34–00:10:50]
4. 图中虚拟页有三种状态：[00:10:50–00:11:21] [课件: 17-vm-concepts.pptx p.8]
   - **cached**：当前副本在 DRAM；
   - **uncached**：已分配但当前只在磁盘；
   - **unallocated**：尚未分配，连磁盘内容也不存在。

大部分巨大虚拟地址空间必须保持未分配；例如有效地址规模可达 $2^{48}$ 字节，不可能预先为每个虚拟页在磁盘上建立真实内容。[00:11:00–00:11:21]

### 2. 从巨大未命中代价推导 DRAM cache 的组织 [00:11:21–00:15:16]

老师把设计原因归结为磁盘访问代价：课件给出的数量级是 DRAM 约比 SRAM 慢 10 倍，而磁盘约比 DRAM 慢 10,000 倍。因此一次 DRAM cache miss 的代价压倒其他局部开销。[课件: 17-vm-concepts.pptx p.9]

由此依次得到四项设计选择：

1. **大块**：块要足够大，才能把一次昂贵磁盘读取摊薄。典型页为 4 KB，x86 还可使用 4 MB 页；此前 cache block 的例子为 64 B。[00:12:01–00:12:41]
2. **全相联**：任意 VP 都可放入任意 PP。相联度越高，冲突不命中的概率越低；只有一个 set 的 fully associative 组织消除了这类放置冲突。[00:12:41–00:13:16]
3. **复杂的软件替换**：选错牺牲页、很快又访问它，会付出一次磁盘 I/O。因而系统值得花较长的软件时间做精细选择；具体算法留给操作系统课程。[00:13:57–00:15:04]
4. **write-back**：虚拟内存不使用每次写都落盘的 write-through，而尽量推迟磁盘写入。[00:15:04–00:15:16]

全相联也带来新问题：不能像小型 SRAM cache 那样在一个小 set 内用硬件并行比较所有 tag。系统需要一个可直接定位映射的大数据结构。[00:13:16–00:13:57]

### 3. 引入每进程页表与 PTE [00:15:16–00:17:27]

1. **页表（page table）** 是内核维护在 DRAM 中的数据结构，属于进程上下文；每个进程各有一张。[00:15:16–00:15:49] [课件: 17-vm-concepts.pptx p.10]
2. 页表是 **页表项（PTE）** 的数组。索引 $k$ 的 PTE 对应虚拟页 VP $k$，记录该虚拟页当前映射到哪里。[00:15:49–00:16:42]
3. 若页在 DRAM，PTE 记录物理页号；示例中 VP 1 映射 PP 0，VP 2 映射 PP 1。[00:16:31–00:16:55]
4. 若页已分配但不在 DRAM，PTE 可记录它在磁盘上的位置，可把它理解为磁盘逻辑块号。[00:16:57–00:17:18]
5. 若页未分配，图中 PTE 是 null。[00:17:18–00:17:27]

课件用 valid bit 区分“当前在内存”与“不在内存”：valid 为 1 时，其余位给出 PPN；valid 为 0 时，页可能在磁盘，也可能尚未分配，二者还需结合其余状态判断。[课件: 17-vm-concepts.pptx p.10]

### 4. 演示 page hit：VP 2 已在 DRAM [00:17:27–00:18:53]

1. CPU 执行 `mov` 并产生落在 VP 2 内的 VA。[00:17:47–00:18:09]
2. MMU 选择 PTE 2。
3. PTE 2 表明 VP 2 已映射到 DRAM 中的 PP 1，因此这是 **page hit / DRAM cache hit**。[00:18:09–00:18:34] [课件: 17-vm-concepts.pptx p.11]
4. MMU 据映射形成物理地址，随后内存系统返回目标数据。[00:18:34–00:18:53]

本处只说明高层命中逻辑；VA 如何切成 VPN/VPO、怎样构造 PA，要到讲后半才展开。

### 5. 演示 page fault：VP 3 当前在磁盘 [00:18:53–00:19:54.28]

1. CPU 引用的字位于 VP 3，但 VP 3 没有缓存在 DRAM，因此发生 DRAM cache miss。[00:18:53–00:19:13] [课件: 17-vm-concepts.pptx p.12]
2. 硬件触发 **page fault exception（缺页异常）**，控制转移给内核 page fault handler。[00:19:13–00:19:27] [课件: 17-vm-concepts.pptx p.13]
3. handler 选择 VP 4 所在物理页作为 victim，准备驱逐 VP 4。[00:19:27–00:19:38] [课件: 17-vm-concepts.pptx p.14]
4. handler 从磁盘读取 VP 3，把它放入刚腾出的物理页，并开始更新页表，使映射反映“VP 4 已被换出、VP 3 已被换入”。[00:19:38–00:19:54.28] [课件: 17-vm-concepts.pptx p.15]

段末恰好切在句子中间；若 VP 4 被修改过，是否写回磁盘以及怎样重启指令在下一段说明。

## 概念、符号与推导

### 1. 页数与编号范围

由虚拟空间 $N=2^n$ 字节、物理空间 $M=2^m$ 字节和页大小 $P=2^p$ 字节，可得到：[课件: 17-vm-concepts.pptx p.8]

$$
\#VP=\frac{N}{P}=2^{n-p},\qquad VP\in\{0,\ldots,2^{n-p}-1\}
$$

$$
\#PP=\frac{M}{P}=2^{m-p},\qquad PP\in\{0,\ldots,2^{m-p}-1\}
$$

这里的推导只用课件 p.8 已给出的三个幂次参数；它解释图中最高 VP 为 $2^{n-p}-1$、最高 PP 为 $2^{m-p}-1$。

### 2. 失效代价到设计决策的因果链

```text
磁盘约比 DRAM 慢 10,000 倍
  ├─→ 大页：摊薄一次磁盘访问
  ├─→ 全相联：避免放置冲突造成额外 miss
  ├─→ 软件精细替换：宁可多算，也不要选错 victim
  └─→ write-back：避免每次写都访问磁盘
```

[课件: 17-vm-concepts.pptx p.9]

这不是四条互不相关的记忆项；它们都由同一项前提“miss penalty 极大”推出。[00:11:21–00:15:16]

### 3. PTE 的三态解释

| VP 状态 | valid bit | PTE 其余信息 | 访问结果 |
|---|---:|---|---|
| 已缓存在 DRAM | 1 | PPN | page hit |
| 已分配、当前在磁盘 | 0 | 磁盘位置/相关定位信息 | page fault |
| 未分配 | 0 | null | 不是“可直接从磁盘换入”的普通命中状态 |

[00:16:31–00:17:27] [课件: 17-vm-concepts.pptx p.10]

valid 为 0 不能单独证明“页面一定在磁盘”；它也可能是 unallocated。这一区分在后续分配页面时会再次出现。

## 例子与课堂提示

### 例子

- **4 MB x86 选项**：老师用大页选项进一步说明页面尺寸由高 miss penalty 驱动，但没有在本段讨论选择大页的其他代价。[00:12:29–00:12:41]

- **VP 3 替换 VP 4**：展示 miss 不只是“再查一次表”，而是硬件异常、内核选择 victim、磁盘搬运和 PTE 更新组成的长路径。[00:18:53–00:19:54.28]

## 教学展开

### 1. 完成 page fault：写回、换入、重启 [00:19:54.28–00:20:55]

1. VP 4 已被选为 victim；若它曾被修改，就必须先把内容写回磁盘。[00:19:55–00:20:01]
2. handler 把 VP 3 从磁盘复制到腾出的物理页，并更新 PTE。[00:20:06–00:20:15]
3. page fault handler 返回时，不是跳过出错操作，而是回到 **faulting instruction** 重新执行。[00:20:15–00:20:24]
4. 同一 VA 再次交给 MMU 时，对应 PTE 已表明页面在 DRAM，所以第二次执行成为 page hit，指令可继续取得目标字。[00:20:24–00:20:38] [课件: 17-vm-concepts.pptx p.16]

等到 miss 才把页复制进 DRAM，称为 **demand paging（按需分页）**。[课件: 17-vm-concepts.pptx p.16]

### 2. 区分“分配虚拟页”和“把页带入 DRAM” [00:20:55–00:21:58]

老师接着讨论图中尚未分配的 VP 5：[课件: 17-vm-concepts.pptx p.17]

1. 程序通过 `malloc` 请求很大的虚拟地址区间，其中某些页可能尚未分配。[00:20:55–00:21:18]
2. `malloc` 可通过老师口述为 “s-break” 的 `sbrk` 一类机制向内核扩展可用虚拟空间，建立页面分配状态。[00:21:18–00:21:36]
3. 老师随即自我修正：单纯分配并不意味着页面已经进入 DRAM；此时主要改变页表/虚拟映射状态。[00:21:36–00:21:52]
4. 只有页面后来真正被触碰，才按需进入 DRAM cache。[00:21:44–00:21:58]

因此“allocated”与“cached”是两个独立维度：已分配页仍可尚未驻留物理内存。

### 3. 用局部性回答“这个机制为什么没有慢到不可用” [00:21:58–00:23:46]

老师坦言初学时觉得这一机制“低效得可怕”：每条访存指令似乎都要查表，缺页还要来回复制。[00:21:58–00:22:24] 随后给出关键答案：程序具有时间局部性和空间局部性，在任一时刻倾向于反复访问一组活跃虚拟页，称为 **working set（工作集）**。[00:22:24–00:22:56] [课件: 17-vm-concepts.pptx p.18]

老师给出两种容量关系：

1. 对单个进程，若工作集小于主存容量，当前活跃页可全部驻留；经历 compulsory misses 后，性能良好。[00:22:56–00:23:10]
2. 多进程系统中，若各进程工作集大小之和超过主存容量，就没有进程能让完整工作集稳定驻留，页面持续换入换出，形成 **thrashing（抖动）** 和性能崩溃。[00:23:10–00:23:31]

老师还预告 TLB：它会进一步利用局部性，减少地址翻译自身的查表开销。[00:23:31–00:23:46]

课件随后再次显示全讲目录，标记课堂从“VM as a tool for caching”转入“VM as a tool for memory management”。[课件: 17-vm-concepts.pptx p.19]

### 4. 每进程页表把统一 VA 视图映射到分散 PP [00:23:46–00:25:28]

1. 每个进程有自己的虚拟地址空间；内核把该进程的页表作为进程上下文的一部分保存。[00:23:59–00:24:23]
2. 该页表只解释这个进程的 VA，因此不同进程的同一个 VPN 可以得到不同 PPN。[00:24:23–00:24:55]
3. 课上例子：进程 1 的 VP 1 映射 PP 2，进程 2 的 VP 1 映射 PP 8。[00:24:55–00:25:07] [课件: 17-vm-concepts.pptx p.20]
4. 每个进程仍看到同样大小、相似布局、代码和数据起点一致的线性空间；真实物理页则可散布在整个 DRAM。[00:25:07–00:25:28]

### 5. 用“给 50 个进程切物理分区”的反例说明管理收益 [00:25:28–00:27:16]

老师让学生设想没有 VM 时管理 50 个进程：[00:25:28–00:26:11]

1. 可以把物理地址空间切块，每个进程占一块。
2. 但新进程随时可能出现，系统必须预留空间，固定分区难以有效适配不同需求。[00:26:11–00:26:27]
3. 程序在链接时又不知道最终会落在哪个物理块；加载时必须重定位所有全局符号引用，或强制所有指令使用相对地址。[00:26:27–00:27:10]

这些复杂性由 VM 统一解决：链接器面向稳定 VA，内核/MMU 再自由决定物理放置。[00:27:10–00:27:16]

### 6. 任意放置、迁移和共享带来调度自由 [00:27:16–00:29:26]

老师依次扩展同一映射思想：[课件: 17-vm-concepts.pptx p.21]

1. 每个 VP 可映射到任意 PP，物理内存不必为一个进程保持连续。[00:27:16–00:27:30]
2. 同一个 VP 在不同时刻可位于不同 PP：被换出后再次换入，不必回到原位置。[00:27:30–00:27:51]
3. 多个进程的 PTE 可指向同一个 PP，从而共享代码或数据。[00:28:04–00:28:30]
4. 示例中两进程的 VP 2 都指向 PP 6。共享库 `libc` 只需在物理内存保留一份，各进程却都在自己的 VA 空间中看到它。[00:28:30–00:29:18]

这不是破坏“私有地址空间”，而是内核有意建立的共享映射。

### 7. 由统一 VA 布局引出链接简化 [00:29:26–00:29:45.52]

由于每个程序都可在相同虚拟位置放置代码、数据和堆，链接器能提前知道各区域地址并解析、重定位引用，不必等待程序被塞进某个不可预测的物理分区。[00:29:26–00:29:45.52] [课件: 17-vm-concepts.pptx p.22]

## 概念、符号与推导

### 1. 缺页恢复的不变量

```text
故障前：PTE(VP 3) 表示不在 DRAM
   ↓ page fault handler
必要时写回 dirty VP 4
   ↓
VP 3 → victim 所在 PP，更新相关 PTE
   ↓ restart
同一条指令、同一 VA 再执行，此时命中
```

[00:19:54–00:20:38] [课件: 17-vm-concepts.pptx p.16]

重启之所以可行，是因为 handler 修复了导致 fault 的页驻留状态，而程序语义仍从原指令开始；老师本段没有讨论不可恢复的非法访问。

### 2. 工作集容量条件

令进程 $i$ 当前活跃虚拟页集合为 $WS_i$，主存可容纳的页数为 $C$。按老师和课件给出的条件：[课件: 17-vm-concepts.pptx p.18]

$$
|WS_i|<C
\quad\Longrightarrow\quad
\text{compulsory misses 后可获得良好性能}
$$

多进程时：

$$
\sum_i |WS_i|>C
\quad\Longrightarrow\quad
\text{thrashing：页面持续换入换出}
$$

若按字节计量，可把两边同时乘页大小 $P$；课堂和课件使用的是 working set size 与 main memory size 的直接比较，没有在这里规定固定观测窗口算法。

### 3. 每进程映射函数

可以把每个进程的映射记成独立函数：

$$
MAP_i(VP)=PP
$$

因此完全允许：

$$
MAP_1(VP_1)=PP_2,\qquad MAP_2(VP_1)=PP_8
$$

也允许有意共享：

$$
MAP_1(VP_2)=MAP_2(VP_2)=PP_6
$$

[00:24:46–00:25:07] [00:28:20–00:28:41] [课件: 17-vm-concepts.pptx p.20] [课件: 17-vm-concepts.pptx p.21]

上述写法是对课堂映射图的形式化转写，不代表老师在本段引入了 `MAP_i` 这个符号；正式 `MAP` 定义在后续地址翻译部分。

## 教学展开

### 1. `execve` 先建虚拟映射，不先复制完整程序 [00:29:49.08–00:31:40]

1. loader `execve` 读取 ELF 可执行文件，识别代码和数据区段大小。[00:29:49–00:30:13]
2. 它从约定的固定 VA 开始，为 `.text`、`.data` 等区段分配虚拟页面并建立 PTE。[00:30:13–00:30:25] [课件: 17-vm-concepts.pptx p.22]
3. 这些 PTE 初始标为 invalid，因此 MMU 首次遇到相应页面时会触发 page fault。[00:30:21–00:31:00]
4. 内核在 fault handler 中把所需文件页复制进物理内存；程序和数据并非在 `execve` 时一次性全部搬入。[00:31:00–00:31:31]
5. 页面内某个字节第一次被访问才发生复制，这就是 demand paging；它与普通 cache “访问块内某个字才装入块”的原则相同。[00:31:31–00:31:53]

课件给出的典型虚拟布局从低到高包括只读 `.init/.text/.rodata`、可读写 `.data/.bss`、运行时堆、共享库映射区、用户栈以及用户不可见的内核虚拟内存。[课件: 17-vm-concepts.pptx p.22] 老师本段重点是固定布局和按需装页，并未逐一区段解释增长方向。

### 2. 用巨大数组说明按需加载为何节省 DRAM [00:31:56–00:32:44]

程序可能声明或映射一个巨大数组，却只访问其中一小部分。demand paging 只把被触碰页面带入 DRAM，未访问部分不占同量物理页，因此加载既延迟工作，也避免浪费稀缺主存。[00:31:56–00:32:32]

这让前一段“allocated 不等于 cached”在 ELF/大数组场景中变成具体收益。[00:32:32–00:32:44]

课件目录页在此标记从“VM as a tool for memory management”转入第三项动机“VM as a tool for memory protection”。[课件: 17-vm-concepts.pptx p.23]

### 3. 把保护信息加入 PTE [00:32:44–00:35:56]

老师从进程地址空间中的不同访问要求开始：[00:32:44–00:34:31]

1. 代码页可设为只读；某些地址只能由内核执行/访问。
2. x86-64 指针和寄存器宽度为 64 位，但老师所讲系统实际使用 48 位虚拟地址；高位按规则全为 0 或全为 1。[00:33:22–00:33:53]
3. 高位全 1 的区域用于内核代码/数据，高位全 0 的区域用于用户地址。[00:33:53–00:34:17]

页表项可扩展权限位，例如：[课件: 17-vm-concepts.pptx p.24]

- **SUP**：是否需要 supervisor/kernel mode；
- **READ**：是否允许读取；
- **WRITE**：是否允许写入；
- **EXEC**：是否允许从该页取指执行。

MMU 每次访问都检查这些位。若操作与权限不符，例如向不可写页写入，硬件触发异常交给内核处理。[00:34:17–00:35:56]

老师特别把不可执行页与 Attack Lab 相连：x86-64 的 execute control 可阻止从数据页装入指令，抬高代码注入攻击难度，也促使攻击方式转向复用现有代码的 return-oriented programming。[00:34:42–00:35:23]

保护用途讲完后，课件目录页把焦点切到最后一项“Address translation”，对应老师从高层用途转入位级机制。[课件: 17-vm-concepts.pptx p.25]

### 4. 形式化定义地址翻译函数 [00:35:56–00:37:15]

老师结束高层用途介绍，开始精确机制。给定虚拟地址空间：

$$
V=\{0,1,\ldots,N-1\}
$$

以及物理地址空间：

$$
P=\{0,1,\ldots,M-1\}
$$

定义：[课件: 17-vm-concepts.pptx p.26]

$$
MAP:V\rightarrow P\cup\{\varnothing\}
$$

对虚拟地址 $a$：

$$
MAP(a)=
\begin{cases}
a', & \text{若 }a\text{ 的数据当前位于物理地址 }a'\\
\varnothing, & \text{若该数据不在物理内存}
\end{cases}
$$

空映射可能表示页面无效或当前存于磁盘。老师也提醒，通常 $N>M$，但并非定义上必须如此；$M$ 理论上也可以大于 $N$。[00:36:09–00:37:15]

### 5. 列出后续翻译所需符号 [00:37:15–00:37:35]

| 参数/字段 | 含义 |
|---|---|
| $N=2^n$ | 虚拟地址数 |
| $M=2^m$ | 物理地址数 |
| $P=2^p$ | 页大小（字节） |
| VPN | virtual page number |
| VPO | virtual page offset |
| PPN | physical page number |
| PPO | physical page offset，和 VPO 相同 |
| TLBI / TLBT | TLB index / TLB tag，稍后使用 |

### 6. 把 VA 分成 VPO 与 VPN [00:37:35–00:38:41]

1. VA 共 $n$ 位，页大小为 $2^p$ 字节，因此低 $p$ 位选择页内字节，称为 **VPO**。[00:37:35–00:38:10]
2. 余下高 $n-p$ 位唯一标识虚拟页，称为 **VPN**。[00:38:10–00:38:41]
3. 老师用此前 cache 地址位切分作类比：VPO 类似 block offset；VM 的 DRAM cache 全相联、只有一个 set，所以 offset 以上的位都像 tag，完整 VPN 唯一识别页面。[00:37:58–00:38:41]

### 7. PTBR/CR3 给出页表基址，VPN 选择 PTE [00:38:41–00:39:46.28]

1. **PTBR（page table base register）** 保存当前进程页表在物理内存中的基地址；Intel 把相应控制寄存器称为 `CR3`。[00:38:41–00:39:00] [课件: 17-vm-concepts.pptx p.28]
2. MMU 收到 VA 后，以 VPN 作为页表索引，定位对应 PTE。[00:39:06–00:39:31]
3. 若页面在内存，PTE 提供相应物理页号 PPN。[00:39:20–00:39:40]
4. 地址翻译的目标是从给定 VA 构造对应 PA；具体“PPN 来自 PTE、PPO 复制 VPO”的拼接从下一段开头继续。[00:39:31–00:39:46.28]

## 概念、符号与推导

### 1. Demand paging 的加载链

```text
execve 读取 ELF 元数据
  ↓
为文件区段建立固定 VA 范围与 invalid PTE
  ↓ 首次触碰某页
MMU 发现 valid=0，触发 page fault
  ↓
内核从 ELF 对应位置调入该页并更新 PTE
  ↓
重启访问
```

[00:29:49–00:31:53] [课件: 17-vm-concepts.pptx p.22]

关键不是“无映射”，而是已建立可按需解析的虚拟区段，但当前页面尚未驻留。转录对 invalid PTE 内其余字段的口述有矛盾，不能据此断言它已经包含一个有效 PPN。

### 2. 地址位数与页面字段宽度

VA 宽 $n$ 位、页大小 $2^p$ 字节：

$$
VA=[VPN\mid VPO]
$$

$$
|VPO|=p,\qquad |VPN|=n-p
$$

[00:37:35–00:38:41] [课件: 17-vm-concepts.pptx p.28]

页表索引可以写成：

$$
PTEA=PTBR+VPN\times sizeof(PTE)
$$

本段老师明确说 VPN 是索引、PTBR 是物理基址，但没有在口述中写出这条算式；它是对数组寻址关系的直接表达。末段将对多级页表明确口述同型的“base + index × PTE size”。

### 3. 映射与保护的共同检查点

PTE 不只回答“VP 在哪个 PP”，还携带 SUP/READ/WRITE/EXEC 等权限。MMU 已经必须读取 PTE，因此可在每次翻译时同时验证访问类型；不合法访问触发异常，而不是生成一个可继续使用的 PA。[00:34:17–00:35:56] [课件: 17-vm-concepts.pptx p.24]

## 教学展开

### 1. 完成 PA 的拼接：PPN 来自 PTE，PPO 复制 VPO [00:39:46.28–00:40:21]

老师先接上上一段未说完的结论：[课件: 17-vm-concepts.pptx p.28]

1. MMU 用 VPN 定位页表中的 PTE。
2. 若 PTE 有效，PTE 给出目标物理页号 **PPN**。
3. 物理地址中的页内偏移 **PPO** 不需要翻译，直接取自虚拟地址的 **VPO**；两组位完全相同。[00:39:46–00:40:06]
4. 原因是虚拟页和物理页大小相同。某字节在虚拟页内距离页首多少字节，映射到物理页后仍距物理页首同样多字节。[00:40:06–00:40:21]

所以地址翻译改变“在哪一页”，不改变“页内哪个字节”。

### 2. 用地址逐一递增解释 VPN/VPO 边界 [00:40:21–00:41:50]

老师要求学生自行说服自己 VPN 为什么可以直接作为页号，并从全 0 地址开始演示：[00:40:21–00:41:50]

1. VA 全为 0 时，VPN 为 0，VPO 也为 0，即 VP 0 的第 0 个字节。
2. VA 加 1 后，仍在 VP 0，只是 VPO 从 0 变为 1。
3. 持续递增，直到 VPO 的全部 $p$ 位都为 1；此时到达 VP 0 的最后一个字节，而 VPN 仍为 0。
4. 再加 1，低 $p$ 位发生进位：VPO 回到 0，进位进入 VPN，因而来到 VP 1 的第 0 个字节。

这个过程说明低 $p$ 位自然编码页内偏移，高位自然随每跨过一个完整页面递增一次，因此高位唯一标识虚拟页。[课件: 17-vm-concepts.pptx p.28]

### 3. 按五步走完 page hit [00:41:52–00:42:55]

CPU 执行 `mov`、`call`、`ret` 或其他控制转移时都可能产生需要翻译的 VA。命中路径如下：[00:41:52–00:42:46] [课件: 17-vm-concepts.pptx p.29]

1. CPU 把 VA 送到 MMU。
2. MMU 根据 PTBR 与 VPN 形成 PTE 地址（PTEA），向内存层次请求该 PTE。
3. 页表位于内存中，PTE 返回 MMU。
4. MMU 从 PTE 取得 PPN，与 VPO 拼成 PA，再把 PA 送往 cache/memory。
5. cache/memory 按 PA 返回目标数据字给 CPU。

老师特意指出：**page hit 并不等于不访问内存层次。** 即使目标虚拟页已经在 DRAM，MMU 仍须先取得 PTE；若没有后续优化，一次程序数据访问会先多出一次页表项访问。[00:42:47–00:42:55]

### 4. 按七步走完 page fault [00:42:55–00:44:21]

缺页开始时，前半路径与命中相同：[课件: 17-vm-concepts.pptx p.30]

1. CPU 把 VA 送给 MMU。
2. MMU 读取相应 PTE。
3. MMU 发现 valid bit 为 0，或该项表明页面当前在磁盘，因此触发 page fault exception。[00:42:55–00:43:32]
4. 异常把控制转交内核 page fault handler。
5. handler 选择 victim；若 victim 为 dirty，则先把它写回磁盘。[00:43:32–00:43:50]
6. handler 从磁盘调入所需新页，并更新内存中的 PTE。[00:43:50–00:43:57]
7. handler 返回原进程，重新执行 faulting instruction；这次相同 VA 对应有效驻留页，于是成为 page hit。[00:43:59–00:44:21]

因此 page fault 是可恢复异常路径，而不是“返回一个失败值”；恢复点是原指令，不是下一条指令。

### 5. 把页表访问与普通 cache 串起来 [00:44:21–00:45:15]

老师接着回答“cache 在哪里”：[课件: 17-vm-concepts.pptx p.31]

1. 页表本身在物理内存中，PTEA 也是一个物理地址；MMU 对 PTE 的请求先进入普通 cache。
2. 若 PTEA 在 cache 中命中，PTE 直接返回 MMU；若未命中，再到 DRAM 取 PTE，并把它带回 cache。
3. MMU 得到 PTE 后构造目标 PA。
4. 目标 PA 再进入同一个 cache/memory 层次；PA 可能命中 cache，也可能继续访问 DRAM，最终数据返回 CPU。

本课程此前讨论的 cache 使用物理地址，老师同时说明也可以构造使用虚拟地址的 cache，但此处不展开。[00:44:34–00:45:15]

### 6. 课堂问答：磁盘上的“虚拟字节数组”并非逐页实存 [00:45:27–00:47:07]

有学生追问虚拟地址空间在磁盘上究竟如何实现。老师修正此前便于理解的抽象模型：实际系统比“先在磁盘完整放一个巨大数组”更节省空间。[00:45:27–00:45:40]

1. **全零页**：分配时可声明一页初始全为 0。系统不必真的在磁盘保存一页 0；需要时在内存中构造即可。[00:45:40–00:46:08]
2. **文件映射页**：页面可以映射到用户文件。例如 ELF 的代码页以可执行文件中的相应字节为后备，首次缺页时从 ELF 取入。[00:46:08–00:46:36]
3. **匿名页**：页面也可以不映射任何用户文件。老师说明这类页面需要磁盘后备时使用 swap area/swap file。[00:46:36–00:47:07]
4. **写回去向**：按课堂口述，文件映射页被写回其映射文件；没有文件映射的页面写入 swap 区。[00:46:46–00:47:07]

这段问答限定了本讲的“VM 在磁盘上”说法：它是概念模型，实际后备可能是零填充规则、可执行文件/普通文件或 swap，并非每个可能的 VP 都预占磁盘块。

### 7. 课堂问答：调入一页后仍经过普通 cache hierarchy [00:47:08–00:47:45]

第二个问题是：从磁盘调入 DRAM 的页是否也进入片上 cache 层次？老师回答“是”，并沿用本讲数字说明：一个页面会按 64 B cache block 划分，内存数据访问继续经过 cache hierarchy。[00:47:08–00:47:45]

这里要同时保留两种粒度：磁盘与 DRAM 之间以页（典型 4 KB）搬运；DRAM 与片上 cache 之间以 cache block（课堂例子 64 B）组织。[课件: 17-vm-concepts.pptx p.9] [课件: 17-vm-concepts.pptx p.31]

### 8. 从“命中仍要查 PTE”推出 TLB [00:47:45–00:48:49]

局部性让活跃数据页常驻 DRAM，但若每次翻译仍需到普通内存层次取 PTE，开销仍然过大。老师因此引入 **TLB（Translation Lookaside Buffer）**：[00:47:45–00:48:49] [课件: 17-vm-concepts.pptx p.32]

- TLB 是位于 MMU 内的小型、组相联硬件 cache。
- 它专门缓存少量完整 PTE，也就是近期使用的 VPN 到 PPN/权限信息映射。
- 普通 L1 也能像缓存其他内存字一样缓存 PTE，但 PTE 会与程序数据竞争并被驱逐，而且即使 L1 命中仍有一小段访问延迟；TLB 把翻译所需映射放到 MMU 内直接查询。

### 9. 用 VPN 访问 TLB：TLBI 选组，TLBT 准备判同一项 [00:48:49–00:49:40.07]

一页内所有地址共享同一个 PTE，所以 TLB 查询不需要 VPO，只使用 VPN。[00:48:49–00:49:09] [课件: 17-vm-concepts.pptx p.33]

1. 若 TLB 有 $T=2^t$ 个 set，从 VPN 中取 $t$ 位作为 **TLBI（TLB index）**。
2. TLBI 选择一个 set。
3. VPN 的其余高位作为 **TLBT（TLB tag）**，用于区分映射到同一 set 的不同 VPN。[00:49:09–00:49:40.07]

本段恰好结束在老师说“TLBI 映射到这个 set”之后；TLBT 如何确认目标 PTE、TLB hit/miss 的完整流程由第 6 段接续。

## 概念、符号与推导

### 1. VA 到 PA 的字段关系

页大小为 $P=2^p$ 字节时：[课件: 17-vm-concepts.pptx p.28]

$$
VA=[VPN\mid VPO],\qquad PA=[PPN\mid PPO]
$$

$$
PPN=PTE[VPN].PPN,\qquad PPO=VPO
$$

若把地址写成整数：

$$
VPN=\left\lfloor\frac{VA}{2^p}\right\rfloor,
\qquad
VPO=VA\bmod 2^p
$$

$$
PA=PPN\cdot 2^p+VPO
$$

推导前提是 VP 与 PP 采用相同页大小；因此翻译只替换页号字段，偏移字段无需改变。[00:39:54–00:40:21]

### 2. 单级页表项地址

PTBR 保存页表物理基址，VPN 是数组索引，因此：

$$
PTEA=PTBR+VPN\times sizeof(PTE)
$$

老师在上一段明确给出 PTBR 和 VPN 的职责；本段用课件数据通路名称 PTEA 表示结果。[课件: 17-vm-concepts.pptx p.28] [课件: 17-vm-concepts.pptx p.29]

### 3. 地址进位的边界

VP 0 的地址范围为：

$$
0\le VA\le 2^p-1
$$

在最后一个字节上：

$$
VPN=0,\qquad VPO=2^p-1
$$

再加 1：

$$
VA=2^p\Longrightarrow VPN=1,\quad VPO=0
$$

这正是老师从“全 0 地址”逐步加到跨页进位的课堂推导。[00:40:36–00:41:50]

### 4. TLB 的地址位切分

对 $T=2^t$ 个 set 的 TLB：[课件: 17-vm-concepts.pptx p.33]

$$
VA=[TLBT\mid TLBI\mid VPO]
$$

$$
VPN=[TLBT\mid TLBI],\qquad |TLBI|=t
$$

VPO 不参与 TLB 项选择，因为同一 VP 内的所有字节共享同一个 PTE；TLBI 选 set，TLBT 在该 set 内判定是否为所需 VPN。

## 教学展开

### 1. TLBI 选 set 后，TLBT 确认是不是所需 PTE [00:49:40.07–00:49:59]

上一段已经说明 VPN 的低 $t$ 个相关位作为 TLBI，选择 $T=2^t$ 个 TLB set 中的一组。本段开头补完第二步：把 VPN 剩余高位 TLBT 与该 set 中各有效项的 tag 比较，判断缓存项是否真是当前 VPN 的 PTE。[00:49:40–00:49:59] [课件: 17-vm-concepts.pptx p.33]

因此“索引相同”只说明候选项位于同一组；只有 valid 且 tag 匹配才构成 TLB hit。

### 2. TLB hit：直接得到 PTE，省掉一次内存访问 [00:49:59–00:50:40]

老师按数据通路讲解命中：[课件: 17-vm-concepts.pptx p.34]

1. CPU 产生 VA 并送入 MMU。
2. MMU 先以 VPN 查询 TLB，而不是立即按 PTBR 去内存取页表项。
3. 若 TLB 命中，它直接返回该 VPN 的完整 PTE。
4. MMU 从 PTE 取得 PPN，与 VPO 拼成 PA。
5. PA 送到 cache/memory，目标数据最终返回 CPU。[00:49:59–00:50:40]

核心收益是课件写出的 **“A TLB hit eliminates a memory access”**：消除的是取 PTE 的那次访问，不是目标数据本身的 cache/memory 访问。[课件: 17-vm-concepts.pptx p.34]

### 3. TLB miss：回到页表取 PTE，再填入 TLB [00:50:40–00:51:21]

未命中路径如下：[课件: 17-vm-concepts.pptx p.35]

1. MMU 用 VPN 查 TLB，未找到匹配项。
2. MMU 按常规路径到内存层次读取相应 PTE；因此相对 TLB hit 多一次 PTE 访问。[00:50:40–00:50:53]
3. PTE 返回 MMU，MMU 把它缓存到 TLB 中。[00:50:53–00:50:59]
4. 若需要替换已有 TLB 项，则按 cache 规则处理被替换项；老师口述还提到修改过的 PTE 需要写回。[00:50:59–00:51:12]
5. MMU 用新取得的 PTE 构造 PA，随后访问目标数据。[00:51:16–00:51:21]

TLB miss 不等同于 page fault：前者表示翻译不在 TLB，仍可从驻留内存的页表取得有效 PTE；后者表示 PTE 说明目标虚拟页不在物理内存。[课件: 17-vm-concepts.pptx p.30] [课件: 17-vm-concepts.pptx p.35]

### 4. 计算单级页表为什么不可接受 [00:51:21–00:52:32]

老师让学生关注页表规模，并给出参数：[00:51:21–00:52:20] [课件: 17-vm-concepts.pptx p.36]

- 有效虚拟地址空间为 48 位，即 $2^{48}$ 字节；
- 页大小为 4 KB，即 $2^{12}$ 字节；
- 每个 PTE 为 8 B，即 $2^3$ 字节。

单级页表需要为每一个可能的 VP 放一个 PTE：

$$
\#PTE=\frac{2^{48}}{2^{12}}=2^{36}
$$

$$
\text{page-table bytes}=2^{36}\times 2^3=2^{39}\ \text{bytes}=512\ \text{GiB}
$$

老师口头概括为“几乎一 TB 的 DRAM 只用来放页表”，并立即判断这种实现不可行。[00:51:58–00:52:32] 课件给出的精确结果是 512 GB（公式写作 $2^{48}\times2^{-12}\times2^3=2^{39}$ bytes）。[课件: 17-vm-concepts.pptx p.36]

### 5. 用层次页表把“有没有下级表”也编码进映射 [00:52:32–00:53:36]

常用解法是 **multi-level page table（多级页表）**。老师先用两级结构说明：[课件: 17-vm-concepts.pptx p.36]

1. 顶层是 level-1 page table，始终驻留内存，不被换出。[00:52:38–00:52:55]
2. level-1 的每个 PTE 保存某张 level-2 page table 的物理基址；第一个一级项指向第一张二级表，第二个一级项指向第二张，依此类推。[00:52:55–00:53:20]
3. level-2 的项才指向最终虚拟页；课件注明二级页表本身可以像其他数据一样分页进出。[课件: 17-vm-concepts.pptx p.36]
4. 因为绝大多数 VA 未使用，对未覆盖任何已分配页的大片区域，不必创建对应 level-2 table。[00:53:20–00:53:36]

空间节省来自“整张缺席的下级表”，而不是让已经创建的二级表内部每个 PTE 变成可变长。

### 6. 两级示例：2K 代码/数据页、6K 空洞与栈顶一页 [00:53:38–00:55:25]

课件示例参数是 32 位地址、4 KB 页、4 B PTE，因此一张 4 KB 页表可放：

$$
\frac{4096\ \text{B}}{4\ \text{B/PTE}}=1024\ \text{PTE}
$$

即每张二级表覆盖 1024 个 VP。[课件: 17-vm-concepts.pptx p.37]

老师按地址从低到高描述进程布局：[00:53:38–00:54:30]

1. 代码和数据共分配 2K 个虚拟页。
2. 随后是 6K 个未分配页形成的 gap。
3. 高处有一个大小为 1024 页的栈区域，但老师现场修正说法：并非 1024 页都已分配，只有栈顶的一页实际分配，其余 1023 页未分配。[00:53:58–00:54:30]

由此只需三张 level-2 table：[00:54:30–00:55:12]

- 第一张覆盖代码/数据的前 1024 页；
- 第二张覆盖代码/数据的后 1024 页；
- 第三张覆盖高地址栈区域，其中只有最后一个 PTE 有效。

再加一张 level-1 table 指向这三张二级表，总计四张页表就描述了整个稀疏虚拟空间。中间 6K 页 gap 不需要六张空的二级表。[00:55:12–00:55:25] [课件: 17-vm-concepts.pptx p.37]

### 7. 把 VPN 拆成 $k$ 段，逐级找到最终 PPN [00:55:25–00:57:26]

老师把两级结构推广到 $k$ 级：[课件: 17-vm-concepts.pptx p.38]

1. VA 的低 $p$ 位仍是 VPO；高位 VPN 被拆成 $VPN_1,VPN_2,\ldots,VPN_k$。[00:55:25–00:55:54]
2. 在课堂简化图中，这些子 VPN 取相同宽度；$VPN_1$ 是 VPN 的最高位部分。[00:55:54–00:56:05]
3. PTBR 给出 level-1 table 基址，$VPN_1$ 是其中的索引。[00:56:05–00:56:21]
4. 选中的一级 PTE 给出某张 level-2 table 的物理基址；$VPN_2$ 再索引这张二级表。[00:56:21–00:56:46]
5. 依此类推，前一层选中的 PTE 给出下一层表基址；$VPN_k$ 最终索引 level-$k$ table，取得包含目标 PPN 的末级 PTE。[00:56:46–00:57:12]
6. 最终 PPN 进入 PA 高位，VPO 仍不变地复制为 PPO。[00:57:12–00:57:26]

多级结构改变的是“找到末级 PTE 要走几张表”，不改变最终地址仍为 $[PPN\mid PPO]$。

## 概念、符号与推导

### 1. TLB hit 与 page hit 是两个不同判断

```text
TLB lookup(VPN)
  ├─ hit  → 直接得到 PTE
  └─ miss → 从内存页表读取 PTE，并填入 TLB
                         ↓
                   检查 PTE valid
                     ├─ 1 → page hit，形成 PA
                     └─ 0 → page fault，进入内核
```

[00:49:59–00:51:21] [课件: 17-vm-concepts.pptx p.34] [课件: 17-vm-concepts.pptx p.35]

因此完全可能出现 **TLB miss + page hit**：翻译缓存里没有 PTE，但内存页表中的 PTE 有效，目标页已在 DRAM。

### 2. 单级页表通用规模

对 $n$ 位虚拟地址、$2^p$ 字节页、每项 $E$ 字节：

$$
\#VP=2^{n-p}
$$

$$
\text{single-level page-table size}=2^{n-p}E\ \text{bytes}
$$

代入课堂参数 $n=48,p=12,E=8=2^3$：

$$
2^{48-12+3}=2^{39}\ \text{bytes}=512\ \text{GiB}
$$

[00:51:38–00:52:20] [课件: 17-vm-concepts.pptx p.36]

### 3. 两级示例的覆盖粒度

课件 p.37 中一张页表占 4 KB、PTE 为 4 B：

$$
\#PTE_{table}=2^{12}/2^2=2^{10}=1024
$$

每个 level-1 PTE 对应一张 level-2 table，每张 level-2 table 覆盖 1024 个 VP。若页也为 4 KB，则一张二级表所描述的 VA 范围为：

$$
1024\times4\ \text{KB}=4\ \text{MiB}
$$

老师的 2K code/data 因而恰需两张二级表；栈所在的另一个 1024 页区域需第三张，但其中仅一个末级 PTE 有效。[00:54:30–00:55:18] [课件: 17-vm-concepts.pptx p.37]

### 4. $k$ 级页表的地址链

$$
VA=[VPN_1\mid VPN_2\mid\cdots\mid VPN_k\mid VPO]
$$

设 $B_1=PTBR$，第 $i$ 级索引得到的 PTE 地址为：

$$
PTEA_i=B_i+VPN_i\times sizeof(PTE)
$$

对 $i<k$：

$$
B_{i+1}=PTE_i.\text{next-table-base}
$$

末级给出：

$$
PPN=PTE_k.PPN,
\qquad
PA=[PPN\mid VPO]
$$

该算式是对老师“每个子 VPN 是本级表索引，前一层 PTE 指向下一层基址”的直接形式化。[00:55:25–00:57:26] [课件: 17-vm-concepts.pptx p.38]

### 例子

- **512 GB 页表**：把 48 位 VA、4 KB 页、8 B PTE 代入，服务于证明单级结构不是“小有浪费”，而是根本不可部署。[00:51:38–00:52:27]

### 易错点与边界

- **误区：TLB miss 就是 page fault。** TLB miss 只要求去内存页表取 PTE；只有取回 PTE 后发现页面不驻留，才发生 page fault。
- **误区：TLB hit 后不再访问 cache/memory。** 它省去 PTE 访问，但目标数据仍按 PA 访问 cache/memory。[课件: 17-vm-concepts.pptx p.34]
- **误区：512 GB 是虚拟页面内容大小。** 它是为 $2^{36}$ 个可能 VP 各放 8 B PTE 得到的单进程单级页表大小。[课件: 17-vm-concepts.pptx p.36]
- **误区：多级页表把每个 null PTE 都压缩掉。** 已创建的二级表仍是定长数组，内部可以有大量 null PTE；主要节省来自未使用大片区域根本不创建二级表。[00:53:20–00:55:25]
- **误区：level-1 PTE 直接给最终 PPN。** 在多级结构中，非末级 PTE 给下一层页表基址；只有末级 PTE 给目标物理页号。[00:55:54–00:57:20]
- **误区：VPO 会被拆进多级索引。** 只有 VPN 被分成多个子 VPN；VPO 始终保留并最终复制成 PPO。[00:55:35–00:57:26]
- **边界：关于“最多六级”的问答不够清晰。** 可确认 Intel 四级和 4 KB 页对应 12 位 offset，不能从残缺字幕推出普适的六级上限。

## 教学展开

### 1. 单级表的浪费来自“无论使用与否都要有 PTE” [00:59:37.46–01:00:25]

老师延续上一段最后一句重新说明：[00:59:37–01:00:25]

1. 对 48 位虚拟地址空间，单级页表要为其中每一个虚拟页提供一个 PTE。
2. 是否真正分配、访问过该页，不影响这个数组槽位必须存在。
3. 但如此大的 VA 空间中，绝大多数页面永远不会使用。
4. 因而浪费不是页面内容本身，而是为了表示大量“未使用”页面仍预留了海量页表项。

这正是前一段 512 GiB 计算的结构原因，而非某个 PTE 字段选择不当。[课件: 17-vm-concepts.pptx p.36]

### 2. 多级表按已用区域创建下级表 [01:00:25–01:00:58]

两级结构把大 VA 空间分成许多由 level-1 PTE 覆盖的区域：[01:00:25–01:00:54]

- 若某个区域含有正在使用的虚拟页，就创建相应 level-2 table。
- 若整个区域都未使用，例如课件中 code/data 与 stack 之间的 6K-page gap，就让对应 level-1 项为空，不创建下级表。
- 因此只需足够多的 level-2 tables 覆盖实际使用部分。

这里的粒度是“一整张下级表”：只要区域中有一个页面需要映射，就必须创建覆盖该区域的整张二级表；只有整片区域都不用时才能省掉它。[课件: 17-vm-concepts.pptx p.37]

### 3. 节省并非没有代价：顶层完整存在，已建下级表仍为定长 [01:00:58–01:02:37]

老师面对仍不确信的学生，逐项澄清：[01:00:58–01:02:37]

1. 在 p.37 的示例里，4 KB 页表和 4 B PTE 使一张表有 1K 个 PTE。
2. level-1 table 仍然必须存在并保留这 1K 个槽位，因为系统要能表示哪一个 VA 区域以后可能需要下级表。[01:01:04–01:01:53]
3. 代码/数据区域的前两张 level-2 tables 覆盖的页面都在使用，因此其中各 PTE 都要初始化和使用。[01:01:55–01:02:14]
4. 栈区域的第三张 level-2 table 一旦创建，也必须为 1K 个槽位分配空间；只是除栈顶一项外，大部分 PTE 为 null。[01:02:14–01:02:30]

## 概念、符号与推导

### 1. 单级与两级示例的空间对比

课件 p.37 参数为 32 位地址、4 KB 页、4 B PTE。单级页表需要：

$$
\#VP=\frac{2^{32}}{2^{12}}=2^{20}
$$

$$
\text{single-level size}=2^{20}\times 4\ \text{B}=4\ \text{MiB}
$$

两级示例实际创建一张 level-1 table 和三张 level-2 tables，共四张 4 KB 表：

$$
\text{allocated page-table bytes}=4\times4\ \text{KiB}=16\ \text{KiB}
$$

这是按课件参数与老师“总共四张表”的直接计算。[00:55:12–00:55:25] [课件: 17-vm-concepts.pptx p.37] 它不表示所有进程都固定只需 16 KiB；需要多少下级表取决于实际使用区域。

### 2. 节省空间的判定单位

对某个 level-1 entry $L1[j]$ 覆盖的 VA 区域：

$$
L1[j]=null
\Longrightarrow
\text{不分配对应 level-2 table}
$$

若区域中至少有一个页面需要表示：

$$
L1[j]\ne null
\Longrightarrow
\text{分配完整 level-2 table}
$$

完整下级表内其余未使用页面仍由 null PTE 表示。[01:00:25–01:02:30]

### 3. 多级 page walk 的潜在访存数

老师没有给出周期数，但给出结构关系：没有可用 TLB translation 时，$k$ 级页表需要逐级取得 PTE，最后才能访问目标数据。因此基本路径可概括为：

$$
k\ \text{次页表项访问}+1\ \text{次目标数据访问}
$$

这是不计各次访问在普通 cache 中命中的结构上限描述；有 TLB hit 时，TLB 可直接提供最终翻译，从而避免 page walk。[01:04:39–01:05:55]

### 4. 位编号与遍历方向

对 $n$ 位 VA：

$$
VA[n-1:0]=[VPN_1\mid VPN_2\mid\cdots\mid VPN_k\mid VPO]
$$

右端 bit 0 是 LSB，左端 bit $n-1$ 是 MSB；page walk 则先用高位 $VPN_1$ 索引 level 1，再逐级使用后续字段。[01:03:37–01:04:35] [课件: 17-vm-concepts.pptx p.38]

## 概念、符号与推导

### 1. 二级索引的基址与偏移来源

$$
PTE_1=Mem[PTBR+VPN_1\times E]
$$

$$
Base_{L2}=PTE_1.\text{next-table-base}
$$

$$
PTEA_2=Base_{L2}+VPN_2\times E
$$

其中 $E=sizeof(PTE)$。第一式是前段已建立的一级数组索引；第二、三式对应本段老师明确区分的“一级 PTE 给二级基址、VPN2 给表内 offset”。[01:09:43–01:10:35] [课件: 17-vm-concepts.pptx p.38]

### 2. 为什么必须乘 PTE size

$VPN_2$ 的值是第几个 PTE，而内存按字节寻址。若每项大小为 $E$ 字节，则第 $j$ 项距离表首：

$$
offset_{bytes}=jE
$$

令 $j=VPN_2$，即可得到老师口述公式。直接做 `base + VPN2` 只有在每项恰为 1 B 时才成立；本讲示例 PTE 为 4 B 或 8 B，因此必须缩放索引。[课件: 17-vm-concepts.pptx p.36] [课件: 17-vm-concepts.pptx p.37]

上一级 PTE → 下一层表的 base
当前 VPN_i → 下一层表中的 index

### 易错点与边界

- **误区：VPN2 本身存放二级表地址。** 二级表基址来自一级 PTE；VPN2 只选择表内某项。[01:09:43–01:10:35]
- **误区：PTE 地址是 `base + VPN2`。** VPN2 是元素下标，必须乘 PTE 的字节大小再加 base。
- **误区：设置线性地址模式意味着旧 segmentation 硬件不存在。** 老师刚说明 Intel 保留向后兼容机制；mode 选择与物理移除不是一回事。[01:09:16–01:09:39]
- **误区：p.39 每条 bullet 都由老师在结尾口述。** transcript 没有逐条朗读，只能标为课件总结。[课件: 17-vm-concepts.pptx p.39]
- **边界：真实 Intel/Linux 实现尚未讲。** 老师明确把它留到下一讲；本节不能添加真实页表位布局、Linux fault handler 或内核数据结构。[01:10:54–01:11:01.71]

## 本段掌握检查

1. **问：level-2 table 的基址由谁给出？VPN2 又给出什么？**  
   **答：** 由 $VPN_1$ 选中的 level-1 PTE 给出二级表物理基址；VPN2 是该表中的 entry index/offset。[01:09:43–01:10:27]
2. **问：如何计算目标 level-2 PTE 的地址？**  
   **答：** $PTEA_2=Base_{L2}+VPN_2\times sizeof(PTE)$。[01:10:28–01:10:35]
3. **问：为什么 VPN2 必须乘 PTE size？**  
   **答：** VPN2 以“项”为单位编号，而物理地址以字节为单位；乘每项字节数才能得到相对表首的字节偏移。
4. **问：课件最终从哪两个视角总结 VM？各自重点是什么？**  
   **答：** 程序员视角是每进程私有线性地址空间和进程间隔离；系统视角是页面缓存/局部性、简化管理与编程、在中介点检查权限。[课件: 17-vm-concepts.pptx p.39]
5. **问：老师把哪些内容明确留到下一讲？**  
   **答：** virtual memory 在真实系统以及 Linux 中的具体实现。[01:10:54–01:11:01.71]
