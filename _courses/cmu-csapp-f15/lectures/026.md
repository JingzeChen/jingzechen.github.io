## 核心概念与依赖关系

1. **硬件可用性不等于应用可加速。** 有多个 core/hardware thread，只表示潜在执行资源存在；程序还要把工作拆成足够独立、粒度合适的 task。[00:02:37-00:04:10]
2. **任务独立性决定同步粒度。** 求和区间可一次划成 $K$ 份；quicksort 通过 partition 递归产生独立左右区间。若 inner loop 仍共享一个热变量，并行结构会被同步重新串行化。[00:12:22-00:16:00] [00:33:14-00:38:40] [课件: 26-parallelism.pptx p.38]
3. **单线程基线先决定 speedup 是否可信。** 把累加放入 register、使用较强 sequential implementation 后，才有资格用 absolute speedup 衡量并行本身的收益。[00:19:04-00:24:48] [课件: 26-parallelism.pptx p.17]
4. **Speedup/efficiency 描述实测，Amdahl 描述结构上限。** 前者量化在 $p$ 个 core 上实际快多少及损失多少；后者指出未加速路径无论增加多少资源都不会消失。[00:21:26-00:28:28]
5. **Task granularity 连接 parallelism 与 overhead。** 阈值过早转串行会缺少 task；拆分过深又让 queue/thread/control overhead 超过工作本身。宽谷底意味着应实验扫描，而不是假设某一点普遍最佳。[00:37:02-00:45:31]
6. **Memory consistency 依赖 cache coherence mechanism。** Program order 约束只有在 private cache 之间能找到最新副本、正确降级/失效状态时才能成为 multicore 的可观察行为；这套机制本身又有性能和扩展成本。[00:52:37-01:02:04]

## 关键推导、例子与结论边界

### Parallel summation

求和目标与检查公式为

$$
\sum_{i=0}^{n-1}i=\frac{(n-1)n}{2}.
$$

在 $t\mid n$ 的简化前提下，thread $j$ 处理

$$
start=j\frac{n}{t},\qquad end=start+\frac{n}{t},
$$

即半开区间 $[start,end)$。[00:11:55-00:14:08] [课件: 26-parallelism.pptx p.8] [课件: 26-parallelism.pptx p.11]

- `psum-mutex`：单线程口述约 51 秒，但老师稍后回忆为 58 秒；1→2 thread 约慢 9 倍，说明每次加法同步和 cache-line ownership transfer 压倒计算。[00:14:24-00:16:00] [需回听 00:14:28] [需回听 00:18:18] [课件: 26-parallelism.pptx p.12]
- `psum-array`：单线程口述约 5 秒，相比 mutex 版快约一个数量级；到 16 thread 仍有改善，但相邻槽位可能共享 cache line。[00:17:11-00:19:04] [课件: 26-parallelism.pptx p.13] [课件: 26-parallelism.pptx p.14]
- `psum-local`：循环只做 local/register accumulation，8 thread 达到最好，16 thread 退化；8 core 上最好约 6×、约 75% efficiency。结论只针对 Shark 与该工作负载。[00:19:04-00:24:48] [课件: 26-parallelism.pptx p.15] [课件: 26-parallelism.pptx p.16] [课件: 26-parallelism.pptx p.18]

### Speedup、efficiency 与 Amdahl

若 $T_p$ 是使用 $p$ 个 core 的运行时间：

$$
S_p=\frac{T_1}{T_p},\qquad E_p=\frac{S_p}{p}=\frac{T_1}{pT_p}.
$$

Relative speedup 的 $T_1$ 来自并行代码的单线程版本；absolute speedup 的 $T_1$ 来自最佳 sequential algorithm/implementation，老师认为后者更真实。[00:21:26-00:24:09] [课件: 26-parallelism.pptx p.17]

若原时间为 $T$，比例 $p$ 可加速 $k$ 倍：

$$
T_k=\frac{pT}{k}+(1-p)T.
$$

令 $k\to\infty$：

$$
T_\infty=(1-p)T,\qquad S_\infty=\frac{1}{1-p}.
$$

课件例子 $T=10,p=0.9,k=9$ 得 $T_9=2$，所以 speedup 为 5；极限时间为 1、极限 speedup 为 10。[00:26:10-00:28:06] [课件: 26-parallelism.pptx p.19] [课件: 26-parallelism.pptx p.20]

**结论边界：** 老师口述一度把 $T_9=2$ 说成“2x performance improvement”，并把 $1-p$ 说成“best speedup”；课件公式与后续例子分别表明 2 是运行时间、$1-p$ 是极限时间比例。[需回听 00:27:12] [需回听 00:27:43]

### Parallel quicksort 与测量

- 顶层 partition 完全串行；第二层最多 2 路、第三层最多 4 路，课件把第 $k$ 层上界写为 $2^{k-1}$。因此要递归若干层才可能填满全部 core。[00:45:54-00:46:47] [课件: 26-parallelism.pptx p.35]
- 实验必须看 elapsed runtime；输入为 $2^{27}=134{,}217{,}728$ 个随机值，best speedup 为 6.84×。老师先误读成 $2^{37}$，随即用数量级发现错误。[00:42:00-00:45:54] [需回听 00:42:06] [课件: 26-parallelism.pptx p.33]
- Serial fraction 从 1 降低时先增加 parallelism；继续拆得过细后，thread/task overhead 使时间回升。近似从 $2^5$ 到 $2^{12}$ 的阈值范围性能相近，跨度约 128 倍。[00:43:09-00:45:31] [需回听 00:44:56]
- Parallel partition 的 local scan 很快，但 copy/reassemble 增加原 in-place 算法没有的工作，最终没有 overall speedup。[00:47:20-00:49:44] [课件: 26-parallelism.pptx p.36] [课件: 26-parallelism.pptx p.37]

### Sequential consistency 与 snoopy cache

两个线程约束为

$$
W_a<R_b,\qquad W_b<R_a.
$$

同时读到旧值还要求 $R_b<W_b$ 与 $R_a<W_a$，合并成

$$
W_a<R_b<W_b<R_a<W_a,
$$

形成有向环，所以 `100,1` 与 `1,100` 不可能出现在 sequentially consistent execution 中。[00:52:46-00:56:18] [课件: 26-parallelism.pptx p.39] [课件: 26-parallelism.pptx p.40]

无协调 write-back cache 却会让新值只留在 writer cache，另一个 core 从 memory 读到 stale value。Snoopy protocol 让持有 E-tagged 最新值的 cache 响应 read miss，并使原持有者 $E\to S$、请求者取得 $S$；后续 writer 必须重获 Exclusive 并 invalidate 其他副本。[00:56:18-01:01:16] [课件: 26-parallelism.pptx p.41] [课件: 26-parallelism.pptx p.42] [课件: 26-parallelism.pptx p.43]

## 易错点与待核对项

- **把 hardware thread 当完整 core：** SMT 共享 functional unit，`psum-local` 和 quicksort 都显示 8→16 thread 没有额外收益。[00:19:54-00:20:40] [00:45:31-00:45:54]
- **用弱基线制造漂亮 speedup：** 应优先报告 absolute speedup，并先优化 sequential version。[00:20:42-00:23:17]

## 概念、符号与推导

- **Multicore：** 单个芯片上放置多个独立 CPU/core；各 core 有私有 cache 部分，也通过共享 cache 和主存看到一致的内存视图。[00:04:37-00:05:24] [课件: 26-parallelism.pptx p.4]
- **外部并发与内部并行：** 前者用多个线程分别处理多个 client，目标是隐藏或隔离 I/O 延迟；后者把一个大任务拆成并行子任务，目标是缩短该任务的完成时间。[00:02:57-00:03:36] [课件: 26-parallelism.pptx p.3]
- **Out-of-order execution：** instruction control 把程序动态转为操作流，并依据依赖关系把操作映射到多个 functional unit；它不是汇编表面上的严格逐条执行。[00:06:27-00:08:08] [课件: 26-parallelism.pptx p.5]
- **Hyperthreading / SMT 的结构：** 对 $K$ 条 instruction stream，复制足够的控制状态以及 $K$ 份寄存器状态，而 functional unit 和 cache 等核心执行资源仍共享。这里的 $K$ 表示同一 core 可同时维护的硬件线程上下文数，不等于增加了 $K$ 个完整 core。[00:08:22-00:09:59] [课件: 26-parallelism.pptx p.6]
- **推导链：** 单线程常因依赖或 cache miss 不能占满功能单元；若只复制相对便宜的控制/状态部分，就可在一个线程停顿时从另一线程取得可执行操作；因此 hyperthreading 的目标是提高单 core 内既有资源利用率，而不是复制完整执行引擎。[00:09:02-00:09:50] [课件: 26-parallelism.pptx p.6]

## 教学展开

1. **补全 hyperthreading 的名称与经验边界。** Intel 称这种技术为 hyperthreading，也常称 SMT（simultaneous multithreading）。老师的经验是它通常不会带来很大差异，但由于加入该功能相对便宜，x86 processor 普遍提供 two-way hyperthreading。[00:09:59-00:10:34] [课件: 26-parallelism.pptx p.6]

2. **固定实验机器。** Shark 是约 2010 年的 server-class machine，采用 2.27 GHz Intel Xeon E5520（Nehalem），有 8 个 core，每核支持 two-way hyperthreading。因此理论上最多可同时维持 16 个独立线程；老师随即加上条件：只有程序能让各部分持续工作且不发生不良干扰，才可能接近“16-way parallelism”。[00:10:35-00:11:48] [课件: 26-parallelism.pptx p.7]

3. **选择刻意简单、可验证的任务。** 任务是求 $0,\ldots,n-1$ 的和。虽然可直接用闭式公式计算，所以作为实际应用“很笨”，但公式恰好可作为正确性检查。把范围划成 $t$ 段，每个线程负责一段，最后合并局部结果；课件为简化假设 $n$ 是 $t$ 的倍数。[00:11:55-00:12:48] [课件: 26-parallelism.pptx p.8]

4. **第一次尝试：所有线程更新同一个受保护的全局和。** `psum-mutex` 维护全局 `gsum`、每线程元素数 `nelems_per_thread` 和 semaphore `mutex`。主线程建立各 peer thread 并 `join`；工作线程从 `myid` 算出自己的半开区间 `[start,end)`，对每个 `i` 都执行 `P(&mutex)`、`gsum += i`、`V(&mutex)`。[00:12:48-00:14:19] [课件: 26-parallelism.pptx p.9] [课件: 26-parallelism.pptx p.10] [课件: 26-parallelism.pptx p.11]

5. **先看正确性，再看灾难性的性能。** mutex 使 `gsum` 更新在功能上正确，但在 $n=2^{31}$ 的测试上，单线程口述约需 51 秒；若单线程不做 lock/unlock，只需几秒。线程从 1 增至 2 时，时间反而约增为 9 倍；增加到 8 个线程才开始有所回落，16 个线程又变差。[00:14:24-00:14:58] [课件: 26-parallelism.pptx p.12]

6. **解释失败原因。** 每次循环都同步本身已有巨大开销；多个 core 还反复争抢包含同一内存地址的 cache line，使其所有权在 core 间来回移动。于是计算被串行化，cache 行为恶劣，semaphore 开销又叠加其上。由此得到第一条实践规则：低层并行的 inner loop 中不能使用这种 fine-grained locking。[00:14:58-00:16:00]

8. **从 8 到 16 的退化判断 hyperthreading。** 该实现 8 线程到 16 线程变慢，说明在这一工作负载上 16 个 hardware thread 没有额外价值。老师同时强调，此时整个算法本身已经很差，不能把局部线程数曲线误当成成功的并行方案。[00:16:44-00:17:05]

9. **第二次尝试：每线程一个数组槽位。** `psum-array` 让 thread $i$ 只更新全局数组 `psum[i]`，主线程在所有 worker 完成后再合并数组。这样消除了 mutex 和对同一标量的直接竞争；但相邻数组元素通常仍处于同一 cache line，所以线程仍会在 cache-line 粒度发生干扰。[00:17:11-00:18:13] [课件: 26-parallelism.pptx p.13]

## 概念、符号与推导

- **SMT / two-way hyperthreading：** 同一物理 core 维持两个 hardware-thread context。8 个 core 因此暴露最多 16 个可运行线程位置，但不等价于 16 个完整 core。[00:09:59-00:11:48] [课件: 26-parallelism.pptx p.7]
- **求和目标：**

  $$
  \sum_{i=0}^{n-1} i=\frac{(n-1)n}{2}.
  $$

  闭式结果在这里主要用于检查并行程序是否算对，而不是作为实验所采用的求和算法。[00:12:02-00:12:16] [课件: 26-parallelism.pptx p.8]

- **区间划分：** 使用 $t$ 个线程，在假设 $t\mid n$ 时，每个线程处理 $n/t$ 个值。对 `myid = j` 的线程：

  $$
  start=j\cdot(n/t),\qquad end=start+n/t,
  $$

  循环覆盖半开区间 $[start,end)$；各区间不重叠且合起来覆盖 $0,\ldots,n-1$。[00:12:22-00:12:43] [00:13:46-00:14:08] [课件: 26-parallelism.pptx p.8] [课件: 26-parallelism.pptx p.11]

- **`psum-mutex` 的粒度：** 每次加法都位于一个 critical section 内。保护的是逻辑上的共享标量 `gsum`，但硬件转移和失效发生在包含它的 cache line 上。[00:13:08-00:14:19] [00:15:06-00:15:39]
- **`psum-array` 的 reduction：** worker $j$ 只生成 `psum[j]`，所有线程完成后由主线程求这些局部和。它消除同一变量上的互斥，却没有保证不同槽位位于不同 cache line。[00:17:11-00:18:13] [课件: 26-parallelism.pptx p.13]
- **`psum-local` 的 reduction：** worker 先执行 `sum += i` 的 register/local accumulation，再把最终值写入 `psum[myid]` 一次。变化的不是数学分区，而是 inner loop 的存储位置和访问次数。[00:19:04-00:19:47] [课件: 26-parallelism.pptx p.15]
- **理想加速的初步口径：** 若使用 $N$ 个 core，理想情况是相对单 core 快 $N$ 倍；正式的 speedup 定义在下一节给出。[00:18:45-00:19:04]

   $$
   W_a<R_b,\qquad W_b<R_a.
   $$

    | --- | --- |
    | $W_a,R_b,W_b,R_a$ | `100, 2` |
    | $W_a,W_b,R_b,R_a$ | `200, 2` |
    | $W_a,W_b,R_a,R_b$ | `2, 200` |
    | $W_b,R_a,W_a,R_b$ | `1, 200` |

    | $W_b,W_a,R_b,R_a$ | `200, 2` |

    六种是 event ordering 的数量；因某些交错打印相同值，distinct value sequence 少于六种。打印 `b` 还是 `a` 先出现，也取决于线程交错。[00:54:46-00:55:15]

    W_a<R_b<W_b<R_a<W_a,

## 概念、符号与推导

- **两种 parallelization strategy：** independent partitioning 把工作一次分成 $K$ 份；divide-and-conquer 递归产生可并发子问题。两者都要求尽量避免共享热状态。[00:50:26-00:50:55] [课件: 26-parallelism.pptx p.38]
- **Shared memory model：** 线程共享一个 virtual address space 中的 global/heap state，同时各有 private stack；共享地址可被不同 core 的 cache 同时保存副本。[00:51:55-00:52:37]
- **Memory consistency model：** 对 concurrent read/write 的可观察顺序给出抽象约束；它回答哪些打印结果是硬件/语言模型允许的。[00:52:37-00:53:16] [课件: 26-parallelism.pptx p.39]
- **Sequential consistency：** 存在一个包含所有 memory event 的全局 interleaving；该 interleaving 对每个 thread 的投影保持 program order。这里必须满足 $W_a<R_b$ 与 $W_b<R_a$。[00:53:16-00:54:12]
- **不可能性推导：** 同时读到两个旧值还需 $R_b<W_b$ 与 $R_a<W_a$；四条约束构成有向环，因此不存在满足它们的 total order。[00:55:15-00:56:18] [课件: 26-parallelism.pptx p.40]
- **Write-back coherence 风险：** modified value 可暂留 private cache 而不立即更新 main memory；若别的 cache 不知道这个副本，便可能从 memory 取到 stale value。[00:56:39-00:57:52] [课件: 26-parallelism.pptx p.41]
- **Snoopy 状态：** Invalid = 不可用；Shared = 可读副本；Exclusive = 单一 cache 可写副本。状态作用于 cache line，而不是源代码变量的抽象边界。[00:58:37-00:59:40] [课件: 26-parallelism.pptx p.42]

## 本段在整讲中的作用

本段承接上一节在句中截断的 snoopy cache 场景，完成一次 write-back multicore 中的读写状态转换：写者先持有 Exclusive 副本；另一 core 读取时在共享通信介质上发出请求，由持有最新值的 cache 响应，双方转为 Shared；任一方以后再写，都必须重新取得 Exclusive 并使其他副本失效。[00:59:40-01:01:16] [课件: 26-parallelism.pptx p.41] [课件: 26-parallelism.pptx p.42] [课件: 26-parallelism.pptx p.43]

## 教学展开

1. **补完第二个 writer 的前置条件。** 上一节已经说明 Thread 1 写 `a` 前必须获得其 Exclusive copy；本节从半句继续：Thread 2 要写 `b`，同样必须先获得 `b` 的 Exclusive copy。此时最新的 `a=2` 与 `b=200` 可以分别只存在于两个 private cache 中，main memory 尚未必更新。[00:59:40-00:59:51] [课件: 26-parallelism.pptx p.41] [课件: 26-parallelism.pptx p.42]

2. **Thread 2 读取 `a` 时产生 cache miss。** 请求通过 bus，也就是 cores/caches 共享的 communication medium 广播“我要读 `a`”。关键点是不能让 main memory 返回旧的 `a=1`；持有 `a` 最新 Exclusive copy 的 Thread 1 cache 侦听到请求并提供值 `a=2`。[00:59:51-01:00:14] [课件: 26-parallelism.pptx p.43]

3. **由 Exclusive 降级为 Shared。** 原持有者不能在别的 reader 已取得副本后继续保有独占可写权，因此其 cache-line state 从 Exclusive 变为 Shared；请求者也得到一个 Shared、只读的最新副本。这样 Thread 2 正确读到 `a=2`，而不是 main memory 中可能仍然陈旧的值。[01:00:05-01:00:48] [课件: 26-parallelism.pptx p.43]

4. **说明 write-back memory 未必立刻更新。** 老师提醒，main memory 此时可能仍未更新，因为整个系统遵循此前讲过的 write-back protocol；不同实现有不同细节，有时会更新 memory。本讲只要求理解 cache-to-cache 供值与状态变化，不展开所有变体。[01:00:14-01:00:29]

5. **解释 “snoopy” 名称。** Cache 会侦听共享介质上的请求，并让请求方取得另一 cache 所保存的最新信息；这里 Thread 2 实际“窥探”到 Thread 1 cache 中的 `a`。对 `b` 也对称发生：Thread 1 通过 snoop 得到 Thread 2 cache 中的最新 `b=200`。[01:00:29-01:00:58] [课件: 26-parallelism.pptx p.43]

6. **确定两边读取后的状态。** 相关 cache line 现在都标为 Shared，可以被多个 cache 读取。若任一 core 接下来想写，必须重新取得 Exclusive access，并使其他位置的 Shared copy 失效，避免其继续读取旧值。[01:00:58-01:01:16] [课件: 26-parallelism.pptx p.42] [课件: 26-parallelism.pptx p.43]

7. **从状态机复杂度推到 core scaling 限制。** 真正的 coherence protocol 比这三个状态的课堂简图复杂得多，但已经成为 multicore hardware 的常规组成。它必须在 cache access 的时间尺度内快速维护跨 cache 一致性；让协议在 8、10、16 个 core 上正确且高效地扩展并不简单，因此 coherence hardware 是限制单芯片 core count 的因素之一。[01:01:16-01:02:04]

8. **给程序员的抽象承诺。** 在多数现代系统上，程序员可假设硬件支持某种可供编程的 memory consistency model。老师把刚才讨论的这种“可序列化”模型称为最容易理解的一种，同时提醒还存在更细致的模型，但本讲不展开。[01:02:04-01:02:29]

9. **开始整讲收束：multithreading 不容易自动变快。** 为获得性能，往往需要重写 application、重新思考 algorithm，还要处理 debugging。Shell lab 和 proxy lab 已展示 concurrency 的难点：事件顺序不可预测，使 bug 更难复现和定位。[01:02:45-01:03:16]

10. **必须理解底层机制及其 performance implication。** Programmer 不能只会调用 thread API；还要知道 cache 与 synchronization 如何工作，才能判断哪里可能快、哪里可能慢、错误可能出现在哪里。[01:03:16-01:03:29]

11. **把 snoopy ownership 回扣到 `psum-mutex`。** 最初求和版本让所有线程争抢一个 global sum。每个 core 都尽可能快地获得该 cache line 的 Exclusive copy、写入、释放；下一 core 随即再次索取。于是 ownership 和 lock 在 caches 间来回“飞”，正是其性能很差的硬件原因。[01:03:29-01:04:18]

12. **再叠加 software synchronization cost。** Application programmer 还在执行 semaphore call；老师指出这会进入 OS kernel，本身也有成本。因而该实现同时承受 cache-line ownership transfer、serialization、lock protocol 和 kernel transition 等不利因素。[01:04:18-01:04:43]

13. **以统一挑战结束。** Parallel programming 的挑战不是有没有并行硬件，而是怎样使用它，同时不被各种 control mechanism 的成本拖住。Programmer 需要在足够深的层次理解这些机制，才有能力判断性能快慢和潜在错误；本讲只是这一更大主题的入门。[01:04:43-01:05:19]

## 概念、符号与推导

- **初始缓存状态：** Thread 1 cache 以 Exclusive 保存最新 `a=2`，Thread 2 cache 以 Exclusive 保存最新 `b=200`；write-back 允许 main memory 暂时仍为 `a=1,b=100`。[00:59:40-01:00:29] [课件: 26-parallelism.pptx p.41] [课件: 26-parallelism.pptx p.42]
- **Read snoop 状态转换：** 若 cache A 对某 line 持有 Exclusive 最新副本，cache B 发出 read request，则 A 直接 supply value；A 的状态 $E\to S$，B 取得 $S$ 副本。课件明确写为 “When cache sees request for one of its E-tagged blocks: Supply value from cache; Set tag to S.”[00:59:51-01:00:48] [课件: 26-parallelism.pptx p.43]
- **对称读取：** Thread 2 读 `a` 得 2，Thread 1 读 `b` 得 200；两次都不能依赖可能仍陈旧的 main memory，而应从持有 modified/exclusive 最新值的 peer cache 获得数据。[01:00:29-01:00:58]
- **后续写入：** Shared 副本只读。任一 cache 要重新写该 line，必须先获得 Exclusive ownership，并 invalidate 其他 cache 中的副本。[01:00:58-01:01:16]
- **Coherence scaling cost：** core 越多，需要侦听、传递和失效的参与者越多；老师没有给出定量公式，只指出该逻辑必须按 cache-rate 运行，使 8、10、16 core 的正确高效扩展很难。[01:01:16-01:02:04]
- **求和争用路径：** `psum-mutex` 每次更新都需要对同一 line 获得 exclusive copy、write、release；多个 core 重复这一过程，使 cache ownership transfer 与同步成为串行瓶颈。[01:03:29-01:04:18]

本段无公式推导；核心是 Exclusive/Shared 状态转换和由该机制解释的性能因果链。
